## Revision list

1. **[SHARPENING] State (or enforce) that `claims_on` assumes Supersedes links are schema‑conforming.** ASN‑0125 EL11(b) defines `in/out` over **Ŝ^Σ** (schema‑conforming claims), introducing Ŝ^Σ in EL4 precisely because S^Σ may contain non‑conformers. `claims_on` computes over `type_slice(Supersedes)` = **S^Σ** with no conformance filter. This coincides with ASN‑0125 only when Ŝ^Σ = S^Σ — which the *assembled* system guarantees (supersession flows only through `assert_sup`/`editlink`, which M7 enforces; `makelink` can't produce a Supersedes type since its `ty` resolves to the content subspace; no component raw‑`emit`s Supersedes). Note this reliance explicitly (it's what makes M8's `in/out` faithful and what justifies reading endpoints), or add a defensive conformance check (`readlink(old).is_some() && readlink(new).is_some()`) alongside the existing residence gate. As written the dependence on edit‑discipline is silent.

2. **[SHARPENING] Make the `stab(empty)` handling consistent in `delete_orphans`.** `findlinks_v`/`discoverable_from` short‑circuit empty queries to "keep the empty‑query reliance off M7's `stab` surface," but `delete_orphans` does not: when `retained` is empty (delete‑everything from a link‑free document) `surv = stab_union(Endset::from_spans([]), …)` calls `stab(i, &empty, Active)` — exactly the reliance the design otherwise avoids. Either short‑circuit empty `retained` (`surv = OrdSet::new()`), or establish that `stab(∅)=∅` is safe and demote the other short‑circuits to optimizations. (`cand` is always non‑empty given the bounds check, so this is the only such site.)

3. **[SHARPENING] Enumerate `delete_orphans` in the active‑filter divergence, and note the ASN‑0117 gap.** `delete_orphans` is active‑filtered (`stab_union(…, View::Active)`), so it realizes orphans over the active view, diverging from ASN‑0117's `D(d,Σ) = {a ∈ dom(Σ.L) : …}` (over **dom(L)** — a nullified link that loses its last witness is not reported). Conflict #8 covers this via "every present‑state primitive uniformly," but the explicit invariant list names only `findlinks_v`/`count_v`/`window_v`/`discoverable_from`. Add `delete_orphans` to that list with the ASN‑0117 note so the divergence is documented like the others.

4. **[SHARPENING] Don't make the default code depend on the unconfirmed `View: Copy`.** M7's interface derives `Copy` on `Shape`/`Behavior` but **not** on `View`, so `stab_union`'s loop and `claims_on`'s two probes won't compile as written. `stab_union` is *always* called with `View::Active`, so drop its `v` parameter and use the `View::Active` literal in the loop (no `Copy` needed); in `claims_on` rebind `v` locally (fieldless‑enum match) for the second use. This keeps M8 buildable against M7 as given rather than pushing a derive request upstream — the existing flag/fallback can stay as a note.

5. **[SHARPENING] Attribute `window_ftt` to ASN‑0108 too.** ASN‑0108 ("findnextnlinks**fromtothree**") is the windowed FTT query; the design labels `window_v` "ASN‑0108" (defensible via Match = `findlinks_V`) but leaves `window_ftt` unattributed. State that ASN‑0108's windowing mechanism is instantiated over *both* Match readings (`findlinks_V` and `findlinks_FTT`).

6. **[SHARPENING] Sharpen `project`'s link‑subspace redirect.** The doc‑comment says "link‑side reverse discovery is M7's BH3," but BH3 (`sources_to`/`target_of`) is typed reverse *lookup* (target→sources), not the positional projection (a slot's V‑positions in `d`'s link subspace) that ASN‑0098 `project` would give. The accurate path for that case is the scoped‑out contextual EL11a (→ M5/M6 listing, §7); point there instead of BH3.

7. **[SHARPENING] Soften "M8 does essentially no span algebra itself."** `retrieve_endsets`'s `touches` uses M1 `classify_spans`. It's safe and correct (a pure, level‑gate‑free order relation — distinct from the `intersect_sets`/`difference_sets` the design rightly avoids) and is disclosed in the dependency list, but the prose claim should acknowledge the per‑span classification it does perform.
