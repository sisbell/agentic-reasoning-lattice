## Review of M8 — Link Query & Discovery (detailed design)

I checked the design against the upstream interfaces (M1/M2/M3/M5/M7) and the source notes (ASN-0098/0127/0121/0108/0132/0131/0117/0125). The composition is, on the whole, careful and faithful — the FTT/region split, the address-key windowing, the active-filter conflict (#8), the FROM/TO flip, and the last-witness set identity for `delete_orphans` are all correct and well-argued. One algorithm, however, computes the wrong set due to an `im`-crate API footgun, and that is load-bearing.

### Revision list

1. **`[DEFECT]` `delete_orphans_on` computes the wrong set: `cand.difference(surv)` is a *symmetric* difference, not the relative complement the algorithm needs.** In the `im` crate, `OrdSet::difference(self, other)` is an alias for `symmetric_difference` — it returns `(cand \ surv) ∪ (surv \ cand)`, **not** `cand \ surv`. The derivation in §6 is correct (orphaned = `findlinks(A_del) \ findlinks(retained)`, cleanly via F-UDIST), but the code emits the symmetric difference, so the report adds the `surv \ cand` half — every link reaching the *retained* range but not the deleted range, i.e. links that plainly **survive** the delete. For a small deletion against a large document this floods the "orphaned" report with most of the document's links — the exact opposite of the intended set. A builder will copy this verbatim and ship a silently inverted survival check. **Fix:** use `cand.relative_complement(surv)` (the `im` method for `self \ other`). Note the same footgun applies anywhere a relative complement is wanted; the design's `union`/`intersection` uses elsewhere are correct, so only this call site is affected.

2. **`[SHARPENING]` Pin the `View: Copy` assumption — it may not compile against the interface as given.** `stab_union` passes `v: View` by value three times in a loop and `claims_on` passes it twice; both rely on `View` being `Copy`. M7's interface shows explicit `#[derive(…, Copy, …)]` on `Shape`/`Behavior` but **no** derive line on `View` — so as written this consumes `v` on first use and fails to typecheck. Either confirm M7 derives `Copy` for `View` (and state the dependency in the seam list), or rebind/clone locally. Trivial, but it's a latent compile dependency the spec should nail down.

3. **`[SHARPENING]` `in_claims`/`out_claims` silently over-match on a non-link key.** Correctness of `match_links(slot, enc([key])) ∩ type_slice(Supersedes)` ⟺ "claim names `key`" rests on `key ∈ dom(L)` and the prefix-antichain (EL4 + R0a). The design documents this as a caller precondition, but because these return `Vec` (not `Result`), a non-link `key` (e.g. a document prefix) yields `enc([key])` coverage `{t : key ≼ t}` that over-matches every claim under that prefix — a wrong, *silent* answer. Consider an internal `readlink(key).is_some()` residence gate that returns `[]` (or switch the return to `Result<_, NotALink>`), rather than leaving a wrong-result trap behind a comment.

4. **`[SHARPENING]` `discoverable_from` shadows a named foundational predicate with different semantics.** It is documented (extensively) as "reachable AND active," not LP12, and `project` is left as the raw retraction-blind tool — internally consistent. But a method literally named `discoverable_from` returning `Ok(false)` for a nullified-but-reachable link, while LP12's `discoverable_from` would say true, is an easy mis-read. Lead the doc-comment with "NOT pure LP12 — active-filtered" (or rename, e.g. `discoverable_active`), so a builder composing against the LP12 name isn't surprised.

5. **`[SHARPENING]` `retrieve_endsets` leaks `im::HashSet` across the public boundary.** Everywhere else M8 deliberately converts M7's `im` containers to `Vec`/`usize` at the output boundary ("converted to `Vec<Address>` only at the output boundary"); `retrieve_endsets` instead returns `im::HashSet<(usize, Endset)>` directly, coupling M10 to `im`. Either convert to `Vec<(usize, Endset)>`/`std::collections::HashSet` at the seam for consistency, or state the `im` coupling explicitly as intentional.

VERDICT: REVISE
