## Revision list

1. **[DEFECT] Reconcile the uniform `View::Active` filter with the unfiltered foundations and the contradicted invariant.** `findlinks_v`/`count_v`/`window_v`/`discoverable_from` are derived from ASN‑0127/0108/0098, whose `findlinks_V`/`Match`/`discoverable_from` range over **all of `dom(Σ.L)`** — ASN‑0121 FL‑DEF *explicitly* calls ASN‑0127's findlinks "slot‑agnostic, unfiltered" and "**not a restriction**" of the addressable `findlinks_FTT`. The design applies `View::Active` (= `dom(L)\nullified`) to *all* of them, which is the right user‑facing behavior but is (a) mislabeled — calling `findlinks_v` "the disjunctive ASN‑0127 findlinks" is inaccurate, it is that ∩ active; and (b) self‑contradicting the Invariant *"Result‑drop = present unreachability, not deletion"* (cited to D‑ZERO/LP13, which are over unfiltered `dom(L)`): under Active, a **retracted‑but‑arrangement‑reachable** link also drops, so a missing link does **not** uniquely assert present unreachability. Fix: add the addressability reconciliation to *Conflicts resolved* (foundations‑unfiltered vs ops‑addressable; `retrieve_endsets`/`findlinks_ftt`/`count_ftt` are already note‑faithful since RE‑DEF/FL‑DEF/CN‑DEF use `addressable`), correct the label, and refine the invariant to "unreachable **or** retracted."

2. **[DEFECT] The §7 contextual‑discovery refinement is unbuildable and self‑contradictory.** `!m5.project(d, followlink(claim, FROM)).is_empty()` calls `.is_empty()` on a `SpanSet` — which M1 does **not** provide and which §5 *itself* flags ("avoids the opaque, **no‑is_empty** SpanSet test by reducing to membership") — and `followlink` returns `Result<SpanSet, Invalid>`, not a `SpanSet`. Either rewrite it with the membership reduction §5 already uses (or M1 `equiv(&proj, &SpanSet::empty())?`), or drop the "one‑line refinement" claim. (EL11a is out of M8's decomposed scope, which is archival `in/out`=EL11b — so dropping it is acceptable; shipping it as written is not.)

3. **[SHARPENING] Thread the operation's single snapshot through internal composition.** The pseudo‑code's `let img = self.image(d, region)?` inside `findlinks_v`/`count_v`/`retrieve_endsets`/`delete_orphans` re‑enters `self.kernel.snapshot()`, opening a **second** snapshot and breaking the stated one‑snapshot `(L,M)`‑coherence invariant (ASN‑0127). In the canonical `foo_on(snap,…)` twins, compose via `image_on(snap,…)` / read off the one `w = snap.world()`, never `self.image`. Show the pseudo‑code in threaded form.

4. **[SHARPENING] `project`'s scope and opacity.** Note that `project` is content‑subspace‑only (M5's tool), so `project(a,i,d) ≠ ∅` is a *content‑only* discoverability witness, strictly weaker than `discoverable_from` (which spans both subspaces via `link_runs`); LP12's biconditional therefore holds only within the content subspace, and a link discoverable solely through the link subspace has empty `project` yet true `discoverable_from`. Also flag that `project` returns an opaque `SpanSet` the caller cannot enumerate or test for emptiness via M1 — give the `equiv(&·,&empty())` / pointwise‑`denotes` recipe, or build an enumerable `VPos` result via `point`+`denotes` over `1..=content_count`.

5. **[SHARPENING] `QueryError::BadRegion` is declared but never produced.** Every malformed region is silently clipped by `resolve`, so no method emits it. Either wire it (validate that `region` is content‑subspace depth‑2 V‑spans and reject otherwise) or remove the variant.

6. **[SHARPENING] `delete_orphans` ignores `p.subspace` and clips an out‑of‑bounds width.** It hardcodes `s_C` in `vspan(s_C, np, width)` and lets `resolve` clip when `np+width > nc`, so it silently previews a *different* (coerced, clipped) delete than requested. Mirror DELETE's preconditions (reject non‑`s_C` `p` / out‑of‑bounds via `BadRegion`) or document the coercion explicitly.

7. **[SHARPENING] Align non‑link handling.** `discoverable_from(a,d)` returns `Ok(false)` for `a ∉ dom(L)` (bare set‑membership), whereas `project` returns `Err(NotALink)` via `followlink`. Pick one convention for "a is not a link."

8. **[SHARPENING] Pseudo‑code/interface precision.** `validate` consumes its `Tumbler`, but `range(...)`/`into_iter()` over `OrdSet<Tumbler>` yield `&Tumbler` — clone before `validate`, and `unwrap` it (infallible by M3's mint, per M7's §G→§F note); `project` uses `followlink(a, i)` where the param is `slot`; the `next` cursor's `.map(/* Address */)` is identity noise; `image` may emit duplicate `Run`s for overlapping region spans (dedup or note it's set‑idempotent downstream). List the public `foo_on(snap,…)` twin signatures (or state the exact `&self`→`snap` transform once).

9. **[SHARPENING] Restate the arity‑3 invariant crisply.** The `{FROM,TO,TYPE}` disjunction in `findlinks_v`/`retrieve_endsets` is exact only because *every v1 link‑creation path* (`makelink`/`emit`/`assert_sup`/`editlink`/`nullify`) yields arity‑3 links — assert that v1 invariant directly, and pin the needed M7 `stab_any`/max‑arity extension for any future arity‑>3 content‑reaching slot (already flagged as an Open decision; tie it to the invariant).
