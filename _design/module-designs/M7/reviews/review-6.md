## Review of M7 — Link & Relation Store

This is a strong, unusually thorough design. The core architecture — one append-only `links` map with everything else a recomputable hint, two write surfaces (`MAKELINK` open / `Emit_K` managed) over one `emit_core`, spanfilade+matcher co-located with the writer — is faithful, internally consistent, and (with the brute-force `stab` bootstrap) buildable. I verified the load-bearing claims: MAKELINK's `iextent`-of-runs endsets are coverage-exact to ML1 (because `⋃[a_k,a_{k+1}) = ⋃subtree(a_k)`); `coverage_class` is total because `⊕` preserves start-length so each `#start`-partition has equal-length endpoints; `age = home_count[origin] − ordinal = J_d − j` matches BH4; the P-tgt self-emitter `incʰᵒᵐᵉᶜᵒᵘⁿᵗ([d.0.s_L.1],0)` equals `mint_link` by FrontierUnification; the editlink claim's fresh-successor key makes its dedup vacuous/lock-free. Upstream calls (`mint_link`/`link_lock_key`/`is_registered_document`, `resolve`/`Run::iextent`/`stage_seat_link`, `transact`/`snapshot`/`Staging`) all match the given interfaces, and the M2-seam's stale illustrative names (`ArrRec::SeatLink`, `m5_next_link_vpos`) are correctly superseded by M5's real `M5Rec::LinkSeat`/`stage_seat_link`.

One material correctness gap remains.

### Revision list

1. **[DEFECT] Specify that the BH3 reverse family reads the *active typed* slice; the §7 prose under-specifies it and the one view it names is wrong.** `sources_to`/`target_of`/`targets_keyed` (§F) carry a `ty` argument but **no `View`**, and §7 describes them as `stab(2|1, enc(·), Audit)` + an exact `denotes`/`addrs` filter — **never composing `type_slice(ty, Active)`**. So the prose (a) leaves the `ty` argument unused (no type-restriction stated) and (b) names only `Audit`. ASN-0128 requires these over `A_K` (active, type-K). A builder following §7 literally ships a cross-type, audit-view reverse lookup: `sources_to` returns sources from other types *and from nullified tuples*; `target_of` returns `⊥` spuriously whenever a nullified or other-type tuple shares the source (violating "exactly one **active** K-tuple"). The document contains no general "BH3 reads active" statement to recover from — and the asymmetry is conspicuous: BH2's `succs` explicitly filters `∉ nullified`, and `is_k`/`members`/`targets_of`/`observe` all name the active view, so a builder reasonably reads BH3's explicit `Audit` as deliberate. **Fix:** state that the BH3 family operates over `type_slice(ty, Active)` (typed + active), with `stab(·, Audit)` used *only* as an overlap prefilter and the exact-filter restricting to active type-K tuples — mirroring `observe`'s §6 construction (`candidates = type_slice(K, view)`, stab-Audit prefilter, exact `denotes`).

2. **[SHARPENING] Flag the `assert_sup` idem⊤ refinement of ASN-0125 EL6/EL8b.** §4 + the `[K_sup]` idem⊤ registration correctly make supersession claims dedup, but the design never draws the consequence: a duplicate identical bare `assert_sup(home, old, new)` (notably from a *different* home, same `(old,new)`) is a hit returning the incumbent — refining ASN-0125 EL6(i)'s raw-Emit "exactly one fresh address" and subsuming the second asserter's EL8(b) attribution. Add a Conflict entry noting this is per ASN-0128 S2 and that `editlink` forks are unaffected (fresh successors ⇒ distinct keys ⇒ no dedup).

3. **[SHARPENING] Spell out `current`'s per-sink inbound-claim collection.** §5 says `CurrentMember.claims` = "operative `[K_sup]` claims whose `new` endpoint is this sink," but not how `current` obtains them. State the mechanism: during the `reach_o(y)` closure over `succs`/`sup_fwd`, collect for each reached node the operative inbound edges (equivalently, operative `out(sink)`), then filter to sinks — buildable from `sup_fwd` + `nullified` with no new structure.

4. **[SHARPENING] Expose or explicitly defer BH2 `is_in_chain(addr, target)`.** ASN-0128 lists it as a BH2 primitive; §F provides `succs`/`chain`/`tip` but not `is_in_chain`. Either add it or state it is caller-derivable as `chain(ty, addr).contains(target)`.

5. **[SHARPENING] State the `match_links` constraint convention.** Document that `constraints` lists **only constrained slots** — an unconstrained slot is omitted, never passed as an empty `Endset` (since `stab(i,&empty,_) = ∅` would empty the AND). Mirror the empty-pattern handling already given for `observe`.

6. **[SHARPENING] Make `coverage_class`'s infallibility argument explicit.** It is declared total (`-> CoverageClass`, called from the total `apply_link`), but a builder may fear `canonical_key` faults on the `Extents` branch. Add the one-line justification: `⊕` never extends, so `#reach = #start`, hence each `#start`-partition has uniformly length-`#start` endpoints and `canonical_key` cannot `LevelMismatch`.

7. **[SHARPENING] Close the trivial type-bridge gaps in the pseudocode.** `LinkRec::Emit.addr` is `Tumbler` while `emit_core` holds an `Address` (needs `.tumbler().clone()`); `enc(&[from])` for `from: &Address` needs `slice::from_ref(from)`/clone against `enc(&[Address])`; `age`/`stale`/`retract_stale` narrow `ordinal: &Nat` to `u64` (state the `to_u64` boundary); and `emit`'s lock decision for an **unregistered** type is unstated (take `[link_lock_key(home)]` only and let `emit_core` reject with `NotRegistered`).

VERDICT: REVISE
