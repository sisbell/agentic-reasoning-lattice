Reviewing M7 against buildability, upstream fidelity, source-note faithfulness, boundary discipline, conflict resolution, altitude, and internal consistency. This is a strong, careful spec — the two-surface architecture, the readable-`Endset`-vs-opaque-`SpanSet` decision, the per-level-class coverage partition, the `home_count`-derived BH4 frontier (no upward M3 read), and the disclosed slot-direction/home-on-hit divergences are all sound and well-reasoned. The defect I found is localized but lands on the central index primitive.

## Revision list

1. **[DEFECT] `stab` is missing its `&self` receiver.** In §G, `pub fn stab(i: usize, query: &Endset, v: View) -> im::OrdSet<Tumbler>` is declared as an *associated function* (no receiver), while its siblings `match_links`/`type_slice` take `&self`. But §6 specifies `stab` as the one shared spanfilade probe that reads `self.hints.spanfilade` (or brute-force-scans `self.links`) and applies the `View` filter against `self.hints.nullified` — all of which require `self`. As written it cannot reach the store, and every caller breaks: `match_links` ("OR `stab`-union … then AND"), `observe` (prefilter), and BH3 `sources_to`/`target_of` all call it from `&self` methods, and **M8 builds its entire discovery against `LinkState::stab` across the `M8→M7` edge** — M8's `link_state.stab(…)` method-call won't resolve against a receiver-less impl. Fix: `pub fn stab(&self, i: usize, query: &Endset, v: View) -> im::OrdSet<Tumbler>`.

2. **[SHARPENING] Name the `coverage_class(&Endset) -> CoverageClass` helper.** The pseudocode uses `CoverageClass(value.type_slot())` / `CoverageClass(ty)` / `CoverageClass(reserved(Retraction))` pervasively (emit_core gate, dedup key, `apply_link` hint folds, DC guard), but `CoverageClass` is an enum — it isn't callable. The *algorithm* is fully specified in Core data model (address-denoting → `Addrs` ≼-minimal antichain; general → per-`#start` `Extents`), so this is buildable, but promote it to an explicit internal `fn coverage_class(&Endset) -> CoverageClass` and call it by name throughout.

3. **[SHARPENING] `targets_keyed`'s `CoverageClass` key is awkward to consume at the M9 seam.** `targets_keyed(source) -> im::HashMap<CoverageClass, Address>` hands M9 a map M9 can iterate but cannot easily *query by type*: constructing a `CoverageClass::Addrs` is possible only for types whose key addresses M9 already knows (the reserved classes), not arbitrary app BH3 types, and `coverage_class` is internal. Either key by the type `Endset`, or expose `coverage_class` publicly, or document that M9 looks up reserved BH3 types via `Addrs({reserved.addr})`.

4. **[SHARPENING] Give `emit_core`'s concrete signature and the error conversions.** `emit_core` is only ever shown in pseudocode; pin its real form (`fn emit_core<W>(stg: &mut Staging<W>, home: &Address, value: Link, gate: Gate) -> Result<Address, EmitCoreError> where W: WorldState + HasLinks + HasM3, W::Record: From<LinkRec> + From<M3Rec>`). The per-op mapping of `EmitCoreError` is described in prose, but the pseudocode's bare `?` on `emit_core(…)?`, `mint_link(…)?`, `stage_seat_link(…)?` implies `From`/`map_err` impls (e.g. `EmptyType→EmptyTypeResolution`, `SeatError→Seat`) that aren't written — state them so the propagation typechecks.

5. **[SHARPENING] Resolve the editlink lock set when `d_s == d_a`.** ASN-0125 permits same-home edit, so `transact([link_lock_key(d_s), link_lock_key(d_a)])` collapses to `[k, k]`. M2's `transact(keys)` contract doesn't state duplicate-key handling; either dedupe the key vec in `editlink` before the transact, or note that M2 sorts-and-dedupes (it must, for deadlock-free multi-key acquisition).

6. **[SHARPENING] State the `View` for the `observe`/BH3 `stab` prefilters.** §6/§7 use `stab(1, &enc(F̂))` as a *prefilter* but don't name the view. Any superset is sound (the exact `denotes` filter and the `type_slice(K, view)` intersection carry the view), so specify `Audit` (or "the candidate view") to remove the ambiguity.

7. **[SHARPENING] Mark which hint costs are v1 vs target.** The cost table claims the spanfilade costs "O(log n) insert per slot-span on apply," but the v1 bootstrap "leaves it empty and `stab` scans `links` directly" — so v1 has *no* spanfilade insert and an O(n) `stab`. Annotate the table (or `apply_link`'s spanfilade step) so a builder doesn't think the index is populated in v1.

8. **[SHARPENING] Tighten the "M8 composes BH3 for in/out" framing.** ASN-0125's `in(y)/out(x)` enumerate *claim tuples*, but BH3's `sources_to`/`target_of` return *endpoint* addresses; M8 must get claim addresses from `match_links([(slot, enc({y}))])` ∩ `type_slice(K_sup)` + `readlink` (BH3 is for the endpoint-projection variant). M7 exposes all the needed primitives, so this is no hole — just clarify the seam so M8's builder doesn't reach for BH3 alone.

(Observation, not actionable: the strict arity-3 store backed by `emit_core`'s `assert(value.arity()==3)` does close off ASN-0043 L4's "n-sets in storage and search" capacity beyond a type floor — but since no digested operation produces N>3 and this matches Gregory's N=3 implementation, it is a faithful altitude choice and the design defends it explicitly.)
