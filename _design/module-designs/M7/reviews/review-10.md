I found two material problems, both closable with small, local changes.

**Revision list**

1. **[DEFECT] Public `emit` does not fence the supersession class — the Df-LAY/EL-DM discipline commitment is dropped on that path.** ASN-0125 Df-LAY commits that *every* `[K_sup]` emission routes through `assert_sup` or `editlink` (under DC); Df-DISC(ii)'s schema (both endpoints resident links, `x ≠ y`) is what EL-DM, EL4's accessors, and the design's own walk family (`succs`/`chain`/`tip`/`current`) rely on. The design implements the exactly parallel `[R]` fence ("Public `emit` rejects `K ~ R` … so `nullify` is the *sole* `[R]`-writer") but leaves `emit(home, reserved(Supersedes), x, [y])` admissible: it passes the Managed gate (registered, Binary shape, `K ≁ R`) with no residence or irreflexivity check, depositing a schema-violating claim — `sup_fwd` then carries edges to non-resident or self-referential endpoints, and `chain`/`tip`/`current` can report non-link "sinks." This is also an internal inconsistency: the Invariants section lists "Supersession schema (Df-DISC)" under *by active enforcement*, but a public write path bypasses the enforcement, and the ASN-0125-vs-0128 tension (0128's `Emit_K` fences only `[R]`; 0125's layer demands `[K_sup]` routing too) is never surfaced in Conflicts. Fix: reject `ty ~ [K_sup]` in the **public** `emit` (new `EmitError` variant, checked alongside `NonAddressDenotingType`, so `assert_sup`/`editlink`'s internal `emit_core` path is unaffected), and record the resolution in Conflicts; alternatively, state explicitly why an off-surface `[K_sup]` emit's degradation is acceptable and strike the schema line from active enforcement — but the one-line fence is the sound choice.

2. **[DEFECT] The registry admits behavior declarations the build silently does not serve.** `TypeRegistry::build` validates app `TypeDecl`s per R-C0 and accepts `Walk` on any Binary type and `ReadFilter` on any Unary type, but §5 serves the walk family only for the shipped `Supersedes` class (`succs`/`chain`/`tip` return *empty* for any other registered BH2 type), and §7's type-less `is_filtered`/`Default` rewrite is "correct only while exactly one BH1 type is registered." So a genesis configuration the module itself validates yields registered behaviors whose ASN-0128-defined semantics (BH2 Provides; BH1's `J ≠ K'` rewrite scope) silently malfunction — an inconsistency between the module's validation surface and its serving surface that no error ever reports. Deferring the *general* implementations is a legitimate Open decision; accepting the declarations meanwhile is not. Fix: in v1, `TypeRegistry::build` rejects app-declared `Walk` and any second `ReadFilter` registration (new typed `RegistryError` variants), lifting the rejection when the parameterized paths in the Open decisions land — or implement the general BH2 scan path already sketched there.

3. **[SHARPENING] Pin `CurrentMember.claims` to one of the two readings the text gives.** The §F doc and §5 define `claims` as the operative `[K_sup]` claims whose `new` endpoint *is* the sink (i.e., full operative `out(sink)`), but the mechanism sentence says the closure "accumulates … as it goes," which yields only walk-traversed inbound edges — the two differ when an operative claim targets the sink from a node outside `reach_o(y)`. State which one is meant (full `out(sink)` matches EL14d's disclosure intent; note it is computed via the `match_links(TO, enc({sink}))` ∩ `type_slice` composition, not walk accumulation).

4. **[SHARPENING] Provide `is_in_chain(ty, addr, target)` as a method.** The derivation `chain(ty, addr).contains(target)` is documented at the M9 seam, but ASN-0128 lists it as a BH2-provided atom and the decomposition hands "all four behavior atoms" to M9; the one-line method closes the PL atom surface without caveats.

5. **[SHARPENING] Record (or remove) the pattern-domain narrowing on `observe`/`is_k`.** ASN-0086's `Observe_K` patterns and ASN-0128's membership-predicate arguments range over `T` (any tumbler); the design's `&[Address]`/`&Address` restrict to T4-valid tumblers. The `denotes` test is total over `Tumbler`, so widening is free; otherwise state the narrowing as a deliberate divergence next to the ghost-address note.

6. **[SHARPENING] State that derived `Eq`/`Hash` on `Endset`/`Link` is structural (span-order- and decomposition-sensitive), not the model's L6 equality over set-valued endsets**, and that no seam may use it for link-value identity (identity is the address; type/dedup identity is `coverage_class`). The Open-decisions bullet gestures at this for span order; make it a stated contract so a consumer never keys on the derived impls.

7. **[SHARPENING] Specify `coverage_class`'s failure mode on contract-violating input.** It is `pub` (M9 keys `targets_keyed` with it) and "total on level-uniform input," but a hand-built non-level-uniform span would hit M1's `LevelMismatch` inside — say whether that is a panic, a `debug_assert`, or a skipped span, so the public function's behavior is defined even off-contract.
