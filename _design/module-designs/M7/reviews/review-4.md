Reviewing M7 against the source notes, upstream interfaces, and the decomposition. I worked through the write surfaces, the dedup/lock seam, the BH4/P-tgt frontier arithmetic, the coverage-class machinery, and the spanfilade matcher. The module is largely buildable and faithful — the two-surface split, the append-only `links`-map-plus-genesis-config data model, `rebuild_derived`'s registry-before-replay ordering, and the conflict resolutions (§§1–8) are sound. One material defect, then sharpenings.

## Revision list

**1. [DEFECT] Fix the spanfilade overlap predicate — `Adjacent` is coverage-*disjoint*, not overlap.** §6, the Dependencies note, and `stab`'s contract all say the spanfilade computes coverage **overlap** via `classify_spans` with "**Separated ⟹ none**" as the exclusion. That is wrong: M1's `SpanRel::Adjacent` denotes *abutting, coverage-disjoint* spans — confirmed by M1's own `merge` ("= 1 when overlap/**adjacent**", i.e. it fuses `[a,b)`+`[b,c)` into one *contiguous* span) and `intersect` ("disjoint ⇒ `Ok(None)`", which returns `None` for adjacent spans because they share no tumbler). So `coverage([a,b)) ∩ coverage([b,c)) = ∅`. As written, `stab` (and therefore `match_links`, and therefore M8's `findlinks`, which the design routes *through* `match_links` with **no** downstream exact-filter — observe/BH3 exact-filter, but match_links is stated as "findlinks' core" with only stab+combine) returns **false positives** for every link whose slot coverage merely abuts the query region (query `[5,11)` wrongly matches a link covering `[11,15)`). This is also internally inconsistent with stab's stated "OVERLAPS" contract. Fix: define overlap as `matches!(rel, ProperOverlap | Containment | Equal)` — exclude **both** `Separated` and `Adjacent` — everywhere the spanfilade (brute-force scan and the deferred index) decides overlap.

**2. [SHARPENING] State that the `observe` per-slot prefilter is applied only for a *non-empty* pattern.** §6 prefilters candidates by `stab(1, &enc(F̂))`/`stab(2, &enc(Ĝ))` ("optionally"), then exact-filters by `denotes`. But `enc(∅)` is the empty endset and `stab(i, &empty)` returns `∅` (no query spans to overlap), so a builder who applies the prefilter unconditionally breaks the common enumerate-a-type query `observe(K, [], [], Active)` (it should return all of `A_K`, not `∅`). Make explicit: skip the slot's prefilter when that pattern is empty (an empty pattern is no constraint); the `denotes` exact-filter is authoritative.

**3. [SHARPENING] Add a defensive `value.arity() == 3` assertion in `emit_core`.** The design relies on "the store holds only arity-3 links" to let `type_class`/`type_slice`/`observe` satisfy ASN-0086's `|Σ.L(a)| = 3` restriction *without an explicit arity filter*, and to make the 3-slot `spanfilade` exhaustive. But `Link::new` admits arity ≥ 3 and `emit_core` "carries no arity guard," resting the invariant on every caller. A future `Managed`/`Open` caller (or bug) depositing an N>3 link via `Link::new` + `emit_core` would land it in `type_class` (no arity filter) in violation of ASN-0086's arity-3 restriction, and leave slots 4+ outside the spanfilade. Enforce the store invariant locally with one assertion rather than caller-by-caller.

**4. [SHARPENING] Make the public ops' pre-transact registry read explicit.** `emit`/`assert_sup`/`nullify` must know `idem(K)` to choose the lock set (`[dedup_key, link_lock_key]` vs `[link_lock_key]`) and to compute the `DedupKey` *before* opening the transact, but `TypeRegistry::registration` is marked "internal lookup." Spell out that the public op reads the genesis-fixed (P1/P2-immutable) registration off a snapshot (or a construction-time cache) — the registry is stable, so this read is race-free — so a builder doesn't conclude the lock-set choice has no legal source for the `idem` flag.

(Non-issues confirmed: the BH4 `age = home_count[origin(a)] − ordinal(a)` formula correctly equals ASN-0128's `f_d − 1 − j`; `nullify`'s self-emit `inc^{home_count}([d.0.s_L.1],0)` matches `a_emit`; the `subspace(u_j)=s_C` wf check correctly uses `start.get(1)` not M1's `Address::subspace()`; storing `iextent` run-spans is coverage-equal to ML1's canonical spans and admissible per ML2; the `Adjacent` bug does *not* affect `observe`/BH3/`is_k`/in-out, which exact-filter; the hoisted home-check-on-hit divergence is disclosed and sound; arity-3 restriction, slot convention §2, and `e₃≠∅`-at-write-boundary §3 are all faithful.)
