Reviewing M7 against the upstream interfaces (M1/M2/M3/M5), the source notes (ASN‑0043/0093/0120/0111/0114/0086/0126/0128/0125), and the decomposition. The architecture (one append‑only `links` map + recomputable hints; two write surfaces sharing `emit_core`; seat staged by MAKELINK; BH4 frontier from M7's own `home_count`; the conflict resolutions) is mostly sound and faithful. One root‑cause problem makes the bulk of the module unbuildable against M1 as given.

# Revision list

1. **[DEFECT] M7 cannot read the spans/addresses out of a stored or passed `Endset`, but nearly every owned capability requires it.** The design sets `pub type Endset = SpanSet` (M1's type) and stores `Link { slots: im::Vector<Endset> }`, but M1's `SpanSet` is read‑opaque: its only public surface is `empty`/`singleton`/`normalize`/`is_normalized`/`denotes` plus the set‑algebra free functions (`union`/`intersect_sets`/`difference_sets`/`equiv`/`canonical_key`). There is **no span iterator, no `len`, no `addrs`, no field access** (the `im::Vector<Span>` is private to `skep-address`). Yet M7's design pervasively needs to enumerate an endset's constituent `Span`s / unit‑depth starts:
   - `apply_link`'s incremental hint fold — `spanfilade` per‑slot extents, `type_class` via `CoverageClass(e₃)`, the `[R]` to‑root into `nullified`, `sup_fwd` old/new, the `dedup` key — every hint is computed from the `value: Link`'s endsets;
   - the enumerated reads `members`/`targets_of`/`sources_to`/`target_of`/`addrs` (all return *denoted addresses*, not membership answers);
   - `CoverageClass(·)` for `TypeRegistry::build`'s `KeyCollision`/`ReservedClassClash`/`NonAddressDenotingKey` checks, for the registration lookup `registration(CoverageClass(ty))`, and for the dedup `LockKey`;
   - `stab`/`match_links` — overlap needs per‑`Span` `classify_spans` against a *query* `SpanSet` that is itself opaque to M7 (so even the "trivially correct brute‑force bootstrap" can't read the endsets it scans).

   `LinkRec::Emit{addr, value}` carries no structured sidecar, so there is no escape route at apply time. (`readlink`/`followlink` and `observe`'s `denotes`‑filter survive, since they need no enumeration.) **Fix:** make M7's `Endset` a representation M7 controls and can iterate — `Span` exposes `start()/width()/reach()/contains()` publicly, so a newtype over `im::Vector<Span>` is fully readable — with a `→ SpanSet` conversion (fold `singleton`+`union`) only at the M1‑call boundary (`canonical_key`/`normalize`/`equiv`). Build managed endsets via `enc` (already readable `subtree_of` spans) and MAKELINK endsets from M5's `resolve` (`Vec<Run>`) + `Run::iextent()` (readable spans) instead of the opaque `resolve_coverage`; implement `addrs`/overlap/`CoverageClass`/`denotes` over those spans with `Span::contains`/`classify_spans`/`is_prefix`. Carry the `stab`/`match_links` query arguments in the same readable form across the M8 seam. As written, M7 cannot maintain a single hint or answer a single enumerated read.

2. **[SHARPENING] "Home‑registration even on a dedup hit" is listed under *active enforcement* but the implementation is branch‑local (skips the check on a hit).** `emit_core` short‑circuits at the dedup hit *before* `mint_link` (the only home‑existence check), so an unregistered‑home hit is not rejected. Either reword it as a documented caller precondition (not an M7‑enforced guard) and move it out of the enforcement list, or hoist `is_registered_document(home)` ahead of the dedup short‑circuit if you actually want it enforced. As stated, the invariants table claims enforcement the code does not provide.

3. **[SHARPENING] State the exact‑membership filter for the BH3 reverse family (`sources_to`/`target_of`), mirroring `observe`.** The text "the spanfilade *is* the reverse index — no separate structure" reads as `stab`‑alone, which contradicts the explicit `observe` treatment ("`stab` is only a prefilter and the membership test is authoritative"). For element‑level antichain targets `stab` overlap *does* equal `target ∈ coverage(G)`, but a coarse (document‑level/ghost) argument over‑matches. Add the `G.denotes(target)` / `source ∈ addrs(F)` exact‑filter after the `stab` prefilter so the contract is right for all arguments.

4. **[SHARPENING] Gate the `dedup`‑hint insert in `apply_link` on `registry.registration(class).idem`.** As written, every deposit (including idem⊥ MAKELINK content links, whose dedup is never consulted) computes and stores a `DedupKey`, forcing the expensive multi‑span `Extents` partition for content endsets that no dedup check ever reads. Compute the dedup key only for idem⊤ types.

5. **[SHARPENING] Pin what `CurrentMember.claims` contains.** EL14 owes "each member with its supporting claims," but the field is described only as "the supporting `[K_sup]` claim addresses." Specify it (e.g., the operative claims whose `new` is the sink) so the disclosure is deterministic across builders.

6. **[SHARPENING] Document the `editlink` successor‑construction path.** `editlink` takes a pre‑built `successor: Link` (faithful to ASN‑0125's `editlink(a, ℓ', …)`), so editing a *content* link requires the caller (M10) to resolve V‑specs via M5's `resolve` + M7's public `enc` + `Link::new`. Note this path explicitly — and that the resolution may be taken off a prior snapshot since recorded I‑addresses are permanent (ML8/EL0) — so M10's builder isn't left guessing how to form a content successor.

7. **[SHARPENING] Tighten the `e₃ = ∅` attribution in Conflict §3.** It is ASN‑0043's `Endset` definition that admits `∅`; ASN‑0111 affirms L3's *non‑empty* type slot for the read (RL1(a)/(c)). The resolution (arity floor in `Link::new`, `e₃ ≠ ∅` at the write boundary) is correct; just credit the right note.

VERDICT: REVISE
