# Review of M7 — Link & Relation Store

This is a strong, unusually thorough design. The two-surface split (MAKELINK vs Emit_K), the append-only `links` map with recomputable hints, the `Endset`-newtype justification, the spanfilade/matcher co-location, and the conflict resolutions (§1–§9) are all sound and well-reasoned. The upstream calls (`mint_link`, `is_registered_document`, `resolve` + `Run::iextent`, `stage_seat_link`, `transact`/`snapshot`) typecheck against the given interfaces, and the ML1 recovery-equation realization via `iextent` is correct. The age formula `home_count − ordinal` correctly reduces to ASN-0128's `f_d − 1 − j`. I found one material totality gap.

## Revision list

**1. [DEFECT] `coverage_class` is not total — it faults (panics) on any endset containing a `#width > #start` span, and the design installs no guard against such spans on the managed type-endset paths.** (Core data model, the `coverage_class` paragraph; §1 `apply_link`; §2 `emit_core` gate; §B `TypeRegistry::build`.)

The totality argument rests on a **factually false claim about M1**: *"M1's `⊕` never extends its left operand's length."* It does — M1's own `displacement` round-trip `a ⊕ (b⊖a) = b` holds under `#a ≤ #b`, so reach can be longer than start. Concretely, T12 (M1 `Span::new`) bounds only `actionPoint(width) ≤ #start`, **not** `#width ≤ #start`: `Span::new([5,3], [0,2,7])` is T12-valid, with `reach = [5,5,7]` (`#reach = 3 ≠ #start = 2`). Such a span lands in the `#start = 2` partition, whose endpoints then mix lengths 2 and 3, so `canonical_key` returns `Err(LevelMismatch)` and `coverage_class`'s unwrap panics.

This is reachable, not theoretical: stored *from/to* endsets are always level-uniform (`enc`/`iextent`), and MAKELINK's *type* endset is level-uniform (`iextent`) — but the **managed type endset is caller-supplied and unconstrained**. `emit(home, ty: &Endset, …)` accepts any `Endset` and computes `coverage_class(ty)` in the gate *before* the registration check; and `TypeRegistry::build` constrains only **idem⊤** keys to be address-denoting (`NonAddressDenotingKey`) — a non-level-uniform **idem⊥** `TypeDecl.key` reaches `coverage_class` during C0 key-uniqueness. Both panic instead of cleanly rejecting, and the design explicitly advertises `coverage_class` as "TOTAL — never faults," on which `apply_link`'s M2-required totality depends.

Fix: (a) add a **level-uniformity** precondition (recommended: **address-denoting**, matching ASN-0128 AD's canonical-encoding intent for the managed surface) on *every* type endset that reaches `coverage_class` — validate `emit`'s `ty` (new `EmitError` variant, checked before `coverage_class`) and **every** `TypeDecl.key` (extend the idem⊤-only `NonAddressDenotingKey` check to all keys), so `coverage_class` only ever sees level-uniform input (MAKELINK's `iextent` already satisfies this); and (b) re-justify `coverage_class`'s totality on that level-uniformity invariant and **delete the false `⊕`-never-extends claim**. (Consider also: `emit` taking a registered type *handle* rather than a raw `&Endset`, which closes the runtime-`ty` fault surface entirely and is closer to ASN-0128's K-indexed `Emit_K`.)

**2. [SHARPENING] Define the `View` domain for `stab`/`match_links`.** The `View` comment scopes `Default` (active∖filtered) to `members`/`targets_of` and says `observe` coerces `Default→Active`, but `stab(i, q, v)` and `match_links(constraints, v)` take a `View` with no stated meaning for `Default` (BH1 filtering is result-side, undefined for a raw index probe). State that `stab`/`match_links` accept only `{Audit, Active}` (or coerce `Default→Active`), so M8's findlinks has an unambiguous contract.

**3. [SHARPENING] Prefer the construction-time registration cache over a per-`emit` snapshot.** §3 step 1 reads `Registration` via `self.k.snapshot().world().links()` to pick the lock set on every `emit`/`assert_sup`. Since the registry is genesis-immutable (P1/P2/R1/R2), recommend the "construction-time cache" alternative as the default to avoid taking a full `Snapshot` purely to read invariant config on the write hot path.

**4. [SHARPENING] Provide `is_in_chain` (BH2) or confirm the derivation contract with M9.** ASN-0128 lists `is_in_chain(addr, target)` among the BH2 atoms; the design omits it as a method ("caller-derive: `chain(ty, addr).contains(target)`"). Either expose it for PL-surface completeness or explicitly note in the M9 seam that M9 derives it, so the "full BH1–BH4 read surface" claim is unambiguous.

**5. [SHARPENING] State the BH4 type expectation on `age`/`stale`/`retract_stale`.** These are dormant in v1 (no shipped BH4 type) and don't verify the queried type is BH4-registered/idem⊥; `age` on an idem⊤ tuple returns a chain-distance with no renewal-reset semantics (the reason ASN-0128 R-C0 forces BH4⇒idem⊥). Document that these methods are for app idem⊥ BH4 types (or gate them on registration), and confirm `stale(ty, h)` restricts to the type-`ty` active slice.

VERDICT: REVISE
