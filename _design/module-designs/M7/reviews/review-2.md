Reviewing M7 against buildability, upstream fidelity, source-note faithfulness, boundary discipline, conflict resolution, altitude, and internal consistency.

## Revision list

**1. [DEFECT] `emit_core` cannot be the shared choke point as written — its `seat` branch requires `HasM5`/`From<M5Rec>`, which the §D ops do not have.** §C's MAKELINK block is `W: …+HasM5, W::Record: …+From<M5Rec>`; §D's block (`emit`/`nullify`/`assert_sup`/`editlink`/`retract_stale`) is only `W: WorldState+HasLinks+HasM3, W::Record: From<LinkRec>+From<M3Rec>`. But `emit_core`'s body does `if seat: stg.push(stage_seat_link(stg.working().m5(), …)?.into())`, which statically needs `HasM5 + From<M5Rec>` regardless of the runtime `seat` flag. So the §D ops cannot call `emit_core` — it won't compile. Restructure: give `emit_core` bounds `W: WorldState+HasLinks+HasM3` only (gate + `mint_link` + deposit `LinkRec`), drop the `seat` parameter, and have **MAKELINK** (the sole `HasM5` caller) stage the seat itself after `emit_core` returns the address.

**2. [DEFECT] The link-arity contract is incoherent, with an unmapped error path and a dropped ASN-0086 restriction.** `emit_core`'s Open gate `require value.arity()==3` (a) has **no `EmitCoreError` variant** for an arity≠3 failure, and (b) contradicts `editlink`'s precondition `require successor.arity() ≥ 3`, `Link::new`'s `arity < 3` floor (admits ≥3), and the spanfilade's "higher-slot search is deferred" (implies arity>3 exists). An arity-4 `editlink` successor passes editlink's `≥3` check, then hits the Open gate's `==3` with nowhere to go. Pick one story: **either** M7 stores only arity-3 (tighten editlink's precondition to `==3`→`IllFormedSuccessor`, drop/footnote the "higher-slot" and `Link::new ≥3` language, and state explicitly that ASN-0043 L3's N≥3 is a type *capacity* no creation op realizes), **or** M7 admits N≥3 (Open gate `≥3`) — in which case `type_class`/`observe`/`type_slice`/`members`/`targets_of` **must restrict their slices to arity-3 links**, since ASN-0086 `TypedRelation` defines `L_K` with the `|Σ.L(a)| = 3` conjunct and the design currently indexes by `e₃`-coverage at any arity (so `observe` would return arity>3 tuples ASN-0086 excludes).

**3. [SHARPENING] `stab`'s overlap test must use the fault-free `classify_spans`, not `intersect`.** §6 says "classify_spans/`intersect` decide overlap," but `resolve_coverage` output (the spanfilade's content) is explicitly "possibly mixed-length," and M1's `intersect` gates on level and returns `Err(LevelMismatch)` on unequal-length endpoints — the common case. `classify_spans` is "pure order, no level gate" and decides overlap (`Separated` ⟹ none) without faulting. Drop `intersect` from the overlap path.

**4. [SHARPENING] Spell out MAKELINK's `wf` check concretely; `subspace(u_j)`/`ordinal-disp(σ_j)` are not M1 functions.** ASN-0120's `subspace(u_j)=s_C` is the V-position's *first component* (`span.start().get(1) == s_C`), **not** M1's `Address::subspace()` (which needs `zeros=3` and returns `None` for a depth-2 V-position — a naïve builder would reject every spec). State the wf as the concrete component tests (`#start==2`, `start.get(1)==s_C`, width is `δ(n,2)` i.e. `#width==2 ∧ width.get(1)==0`), mirroring M5's `resolve` precondition, since these must produce `IllFormedSpec` rejections rather than the silent ⟨⟩ `resolve_coverage` returns.

**5. [SHARPENING] State the `ReservedAddrs ∉ s_C ∪ s_L` precondition and correct the Extents/Addrs prose.** The data-model claim "only MAKELINK content-type grouping touches `Extents`" is false: a MAKELINK type resolving to a single content address yields a unit-depth span → `CoverageClass::Addrs`. The real no-collision guarantee (Conflict §1's "different subspace") rests on reserved type addresses lying **outside s_C/s_L**; otherwise a content-typed link could be classified into a reserved class (e.g. an `[R]`-class misread → spurious `nullified` insert). Make this an explicit, `genesis`/`build`-checked precondition on `ReservedAddrs`, and fix the prose to "address-denoting endsets → `Addrs`; only multi-/mixed-length content extents → `Extents`."

**6. [SHARPENING] Separate the dedup *check* (in `emit_core`) from the dedup *lock* (the public op's `transact` keys).** §3 step 1 ("`emit_core` … passes [the lock] to `transact`") is impossible: `emit_core` runs *inside* an already-open `transact`. State that each public op computes the `DedupKey` from its arguments **before** the transact and supplies `[dedup_key, link_lock_key(home)]` to `transact`; `emit_core` performs only the active-view check against `stg.working()`. (This is also what makes editlink's claim correctly lock-free — the check runs, finds the fresh successor unmatched, and no dedup key is needed.)

**7. [SHARPENING] Constrain registered idem⊤ type keys to address-denoting, or the dedup `LockKey` is unserializable.** The dedup `LockKey` encodes `DedupKey.ty = CoverageClass(ty)`. For an app-registered idem⊤ type whose `key` is a multi-/mixed-length content endset, that class is `Extents(OrdMap<usize, CanonicalForm>)`, and `CanonicalForm` is **not** `Serialize` — so no `LockKey` bytes exist. The design assumes "managed surface always lands in `Addrs`" but `TypeRegistry::build` checks only C0/R-C0/R-C1, none requiring address-denoting keys. Add that constraint to `build`.

**8. [SHARPENING] `sup_fwd` is `[K_sup]`-specific, but `succs`/`chain`/`tip`/`current` take a general `ty`.** `sup_fwd: HashMap<Tumbler, OrdSet<(Tumbler,Tumbler)>>` carries no type dimension and is described as fed only by `[K_sup]` applies. A second BH2 Binary type would be conflated or unindexed. Either note v1 supports only the shipped `Supersedes` for the walk family (and validate `ty`), or specify the general path (`succs(ty,x)` scans `type_class[ty]` active, with `sup_fwd` as the `[K_sup]` accelerator) — symmetric to the multi-BH1 Open decision.

**9. [SHARPENING] Buildability/perf nits.** (a) `#[serde(skip)] registry: Arc<TypeRegistry>` requires `TypeRegistry: Default` (serde seeds skipped fields via `Default`) — add the impl or a `serde(default=…)`; (b) note M7 needs the `im` crate's `serde` feature and `Link: Serialize` for `OrdMap<Tumbler,Link>` to checkpoint; (c) `apply` clone-and-modify clones `LinkState` on *every* record system-wide (via `..self.clone()`), so `decls: Vec<TypeDecl>` makes each fold O(|decls|) — wrap `decls`/`reserved` in `Arc`.

**10. [SHARPENING] Residual clarity gaps.** Move editlink's `require`/`DC` checks *inside* the closure against `stg.base()` (the pseudocode shows them before `transact`, but `DC`'s "witnesses ∈ base links" is a base-state read); the M1 dependency list cites a nonexistent `coverage` function — it's `denotes`/`contains`/`subtree_of`; specify how `nullify` computes its own would-be emitter for the P-tgt self-emit branch (`chain_{d_retr}(home_count[d_retr])` via M1 arithmetic, since M7 reads no M3 frontier); and flag that `PredDef`/`PredStable` shipped registrations (`Unary/⊤/{}`) are M9-coordinated assumptions, not pinned by any digested note.
