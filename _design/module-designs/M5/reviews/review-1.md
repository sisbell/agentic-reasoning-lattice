Reviewed M5 against the decomposition, the engine-composition contract, the M1–M4 interfaces, and the ASN source statements. The operation modeling (INSERT/DELETE/COPY/REARRANGE/VERSION as effect-level deltas), the implicit-position run-list, the eager I-adjacency coalesce, the single-`(M,R)`-fold co-location, the value-blind reorder, the trusting link-seating seam, and the conflict resolutions are mostly sound and faithful. Two material problems block a correct build, plus several sharpenings.

## Revision list

1. **[DEFECT] Fix the I-extent span construction — it is malformed wherever a `Run` is turned into a `Span`.** In the `ContentPlace` and `VersionSnapshot` folds' R-append (`Span(r.i_start, [0, r.width])`), in `project` (`Span(i_start, [0,width])`), and in `content_image` (and hence transitively in the spans `ever_placed` returns), `i_start` is an **element-level** address (`zeros = 3`, depth ≈ 8, last component = ordinal), but `[0, width]` is a **depth-2** displacement. `Span::new(i_start, [0,width])` makes `add` advance `i_start` at component 2 (a field separator), producing a garbage reach, and the span is **not level-uniform** (`#start = 8 ≠ #width = 2`) — so the downstream `intersect` / `difference_sets` / `normalize` calls return `LevelMismatch`, breaking R-append, SHOWDELETIONS, FINDDOCSCONTAINING, and footprint projection. Construct the I-extent with a last-component displacement: `Span::from_endpoints(i_start.tumbler().clone(), M1::shift(i_start.tumbler(), &width))` (level-uniform by construction). The design already uses `M1::shift` correctly for run splitting and coalescing — use the same primitive here.

2. **[DEFECT] `im::OrdMap<Address, …>` / `im::OrdSet<Address>` do not compile against M1 as given.** M1's `Address` derives `Clone/PartialEq/Eq/Hash/Serialize/Deserialize` but **not** `Ord`/`PartialOrd` (only `Tumbler` carries the manual `Ord`), and M5 cannot add `Ord` to a foreign type. So `arrangements`, `prov_by_doc`, and the **public** `docs_containing(...) -> im::OrdSet<Address>` won't build. Key the maps by `Tumbler` (`im::OrdMap<Tumbler, DocArrangement>`, converting with `doc.tumbler().clone()`) and return `im::OrdSet<Tumbler>` (or `Vec<Address>`) from `docs_containing`; or switch to `im::HashMap`/`im::HashSet` (`Address: Hash` is available). Pick one and update the seam type M6 builds against.

3. **[SHARPENING] COPY silently drops ASN-0118's per-spec admissibility clause "source subspace non-empty" (`V_{subspace(s)}(d_s) ≠ ∅`).** A spec from a registered source whose content subspace is empty resolves to ∅ and is dropped; only aggregate emptiness raises `EmptyResult`, so ASN-0118 would reject the COPY while this design proceeds. Either add the per-spec check (new `CopyError` variant) or record this as a deliberate accept-and-intersect relaxation in "Conflicts resolved."

4. **[SHARPENING] The "`M5Rec` fields private ⇒ `stage_*` are the only constructors" guarantee is unachievable as stated.** A public enum's variant fields cannot be private in Rust, so anyone can build `M5Rec::ContentPlace{…}` and bypass the M/R-coupling invariant. Specify the real mechanism — `#[non_exhaustive]` on each variant, or variants wrapping a private-typed payload struct (as M4 does for the `ContentWrite` struct).

5. **[SHARPENING] Two signatures in the pseudocode don't typecheck.** `point` returns `Some(M1::validate(...))` but `validate` returns `Result` (use `.expect("T4-valid by construction")` or `.ok()`); VERSION's `principal_prefix(principal)?` applies `?` to an `Option` in a `Result`-returning function (use `.ok_or(VersionError::NotAPrincipal)?`).

6. **[SHARPENING] Reconcile reverse-provenance index ownership with the decomposition.** The decomposition assigns "the reverse-index hint over R" to M6, but M6 sees only M5's pure `docs_containing` surface and cannot iterate R to build one — so the hint, if built, must live in M5 (as Open decision #3 already contemplates). State this explicitly: M5 owns R and any index over it; M6 owns only the FINDDOCSCONTAINING query that composes `docs_containing` + `content_image`.

VERDICT: REVISE
