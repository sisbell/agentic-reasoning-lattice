**Revision list**

1. **[SHARPENING] Type‑enforce the `width ≥ 1` Run invariant.** The folds' panic‑freedom and `iextent`'s totality both rest on "every Run has width ≥ 1," but `Run` has **public fields** and is **not** `#[non_exhaustive]`, so any crate can build `Run{ i_start, width: 0 }` by struct literal and the public `iextent` will panic on it — "read‑only ergonomics" mischaracterizes public read‑write fields. Make the fields private with `i_start()`/`width()` accessors (or mark `Run` `#[non_exhaustive]`) so `new` is the sole external constructor and the invariant is enforced like the `M5Rec` variants. (In v1 the assembled system never hands `iextent` a 0, so the module is correct as built — this closes the latent gap the design's own justification leaves open.)

2. **[SHARPENING] Validate the COPY source‑span form explicitly.** COPY leans on `resolve`'s defensive `[]` for a malformed/non‑ordinal span; a span that passes the `get(1)==s_C` `NotContentSubspace` check but isn't ordinal‑level depth‑2 then resolves to nothing and surfaces as `EmptyResult`, indistinguishable from an empty range. Add an explicit guard (`#start==2 ∧ #width==2 ∧ width.get(1)==0`) and a typed `CopyError::BadSpan`, so M10 gets a clear rejection rather than a confusing empty result.

3. **[SHARPENING] Name `Span::contains` in `project`'s fallback; tighten `resolve`'s start check.** §2 says "fall back to `SpanSet::denotes` membership" while iterating *per coverage span* — the per‑span test is `Span::contains` (or `denotes` on a singleton). Name `Span::contains` so a builder doesn't wrap each span. Separately, `resolve` rejects `#start < 2` but not `#start > 2`; with m=2 it's unreachable, but `#start==2 ∧ #width==2` is the complete defensive guard.

4. **[SHARPENING] Specify the append boundary of `locate`/`splice_in`.** The RunList contract leaves `locate(ord)`/`splice_in(ord,·)` at `ord = total_width+1` (the INSERT/COPY append case `J=N+1`) implicit. State that `locate` at `total_width+1` returns the end boundary (prefix = all, suffix = empty) so the append splices at the tail; otherwise a builder may mis‑handle or special‑case it.

5. **[SHARPENING] Add the REARRANGE cut lower bound (CS5).** The enumerated R‑PRE checks omit ASN‑0084 CS5's `ord ≥ 1`; a `VPos{s_C, 0}` passes subspace/depth/ascent/upper‑bound. Because the fold *tiles by placement* (split‑at‑0 and split‑at‑1 coincide), `ord=0` is harmless — but add the explicit `cut‑ordinal ≥ 1` check (or fold it into `OutOfBounds`) so the validation list is self‑complete against the cited R‑PRE.

6. **[SHARPENING] Justify or wrap the raw `shift` in address synthesis.** M5 uses raw `M1::shift` on `Run.i_start`, which M1 flags as the text→link hazard for subspace bases; it's safe here *only* because `i_start` is always a full element position (ordinal as last component). Either route synthesis through M1's subspace‑safe `shift_ordinal`/`elem_addr`, or add one line asserting `i_start` is a full element address so the raw shift sits in M1's stated safe window.
