## Review of M5 — Arrangements & Editing (Vstream)

I checked the design against the four upstream interfaces (M1/M2/M3/M4), the ten source notes, the decomposition's ownership/seams, and the Engine Composition Contract. The core is unusually solid, so I'll record where I expected defects and found none, then the genuine improvements.

**What I verified holds (and would be the usual failure points):**
- **The implicit-position run-list** is the right Lampson-cheapest structure: D-SEQ★/D-CTG★/D-MIN★/S2 fall out by construction, INSERT/DELETE suffix-shift is free, and the K.μ⁻/K.μ⁺ "gapped bridge" of ASN-0116/0082 collapses to one `splice_in` while reproducing the exact post-state (I-SHIFT/I-LEFT/I-DOM/I-NEW). Faithful at the *effect* level, which is what `apply_m5` must be.
- **The level-class discipline is real and necessary, not over-engineering.** Element addresses genuinely vary in length (#content = #d+3, and a version's own inserts are #d+4 while its shared content is #d+3 — so even one document's `content_image` is mixed-length). M1's gate confirms `intersect`/`difference_sets`/`normalize`/`canonical_key` fault on mixed length; the per-endpoint-length partition + `union`, with `classify_spans`/`contains`/`denotes` for the un-gated overlap/membership paths, is the correct minimal treatment, and it's applied consistently (`project`, `deletions`, `docs_containing`).
- **Single (M,R) snapshot** via co-located fold (one `M5State` → one root) correctly discharges ASN-0075's atomic root-swap without a cross-store protocol.
- **VERSION** copies the *map* not the range (V2 multiplicity preserved), shares O(1) via `im`, reads source at apply-time deterministically (journal order), records dual provenance (V9w/V13), and routes node-tier cross-owner to an explicit `NodeTierCrossOwner` before any mint (P-tier).
- **Upstream calls typecheck and are faithful**: `mint_content`/`mint_version`/`mint_document` with the matching `*_lock_key` held before the closure (held-key == advanced-frontier-key); `stage_write`/`contains`; `shift`/`validate`/`from_endpoints`/`document_of`/`zeros` on full element I-starts only (M1's stated safe window); `transact`/`snapshot`/`working`/`push`. The pre-read of stable ω off a snapshot is exactly what M3's interface prescribes.
- **Conflict resolutions** (1–6) are all stated and sound — including the I-adjacency coalesce guard (vacuously false across origin-lengths, so M16/M14-safe) and the M5-owns-R-and-its-index resolution of the decomposition's mis-placement of the reverse index under M6.

### Revision list

1. **[SHARPENING]** Add the standalone `seat_link<W>(k: &Kernel<W>, doc, link) -> Result<(_, Seq), TxnError<SeatError>>` transact-wrapped form alongside `stage_seat_link`. The Engine Composition Contract requires *both* forms for any primitive that appears as a step in another store's composite — `stage_seat_link` is exactly such a primitive (M7's MAKELINK). Mark it `#[doc(hidden)]` / isolation-test-only, mirroring M4's `write`. (Non-load-bearing: production correctly composes the *pure* `stage_seat_link`, which is present and correct; only the test/contract-parity affordance is missing.)

2. **[SHARPENING]** Resolve `content_image`'s public exposure. Its sole stated role — the SHOWDELETIONS operand — is consumed *internally* by `deletions`, and FINDDOCSCONTAINING is explicitly routed through `project`, so per the design's own seam descriptions no downstream module (M6/M7/M8/M9/M10) reads `content_image`. Either privatize it (keep `deletions` as the only external SHOWDELETIONS surface) or name the external consumer that needs the raw, mixed-length current-image cover; as written it muddies the interface with a method that carries a "consume under the level-class discipline" hazard but has no caller.

3. **[SHARPENING]** Harden `Run::new` to also reject a non-element-level `i_start` (e.g. `zeros(i_start) ≠ 3`), not only `width == 0`. `iextent`'s raw-`shift` safety and the `from_endpoints` totality argument both rest on every `Run.i_start` being a full element position; v1 has no external `Run` producer so this is latent, but `Run::new` is precisely the documented seam guard for a future one, and the width-only check leaves the text→link mis-shift constructible through it.

Nothing in the data model / interface / invariants / seams contradicts another part, no upstream API is invented or misused, no owned capability is dropped, and no neighbor's material is designed here (the `deletions` and `docs_containing` placements are sound, explicitly-stated conflict resolutions, not overreach). The m=2 commitment narrows ASN-0116's `m ≥ 2`, but it is the integrating note's practical depth (ASN-0047 `m_S = 2`), drops no exercised capability, and is flagged with its exact trade-off in Open decision #6 — handled at the right altitude. A competent Rust engineer can build this module from this document.
