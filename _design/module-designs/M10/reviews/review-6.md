# Revision list

1. **[SHARPENING] Correct the `Stores` test-double rationale.** The prose twice claims "a mock `Stores` exercises the whole lifecycle with **no real kernel**." But `Kernel<W>`, `Namespace<W>`, `Vstream<'_,W>`, `LinkStore<'_,W>` are all concrete (non-trait) types, and the three drivers are kernel-bound — a `Stores` test double *must* wrap a real `Durability::InMemory` `Kernel`, not zero kernel. Reword to "an in-memory-kernel-backed `Stores` (no disk/recovery)." The actual decoupling benefit (M10 constructs no driver itself, names only the `Stores` trait) is real and stands; only the "no kernel" phrasing overstates it.

2. **[SHARPENING] Reconcile `Op::PrincipalPrefix { id }` with M3's seam.** M3's seam motivates this read as resolving *"a bound session's prefix"*, but the design takes an explicit wire `id`. A fresh client authenticated to principal π holds a `SessionId`, not necessarily π's `PrincipalId` value, so it cannot fill `id` for its own account. Either add a session-relative form (resolve `sessions[s] → principal_prefix(..)`, no `id` arg) or state explicitly that the (open) transport surfaces the client's `PrincipalId` at session-open and that arbitrary-id lookup of (public) prefixes is the deliberate shape. (The common account-creation flow is unaffected — `Op::Delegate` already returns the new account `Address`.)

3. **[SHARPENING] State the nested-error `Lower` rule explicitly.** "Mechanical lowering" is unambiguous for flat enums but several store errors wrap inner enums: `*Error::Mint(MintError)` (8 enums), `InsertError::Content(ContentError)`, `MakeLinkError::Seat(SeatError)`, `OpError::Mint(MintError)`. Specify that a wrapper variant lowers by matching its inner enum to the same-named leaf `RejectCode` (`MintError::Gate → RejectCode::Gate`, `SeatError::AlreadySeated → RejectCode::AlreadySeated`, …), so the ~15 `Lower` impls are fully determined for a builder.

4. **[SHARPENING] Clarify `editlink`'s `TypeArg`.** Note that `Addrs` builds an address-denoting (managed-relation) type slot while `Resolve` builds a content-resolved one (mirroring `makelink`, which offers only content `Vec<VSpec>`); both feed M7's type-slot gate (`IllFormedSuccessor` on empty/non-level-uniform, `DcViolation` on retraction- or claim-schema), so M10's helper pre-checks only VSpec content-well-formedness and lets M7 gate the slot.

5. **[SHARPENING] Flag the `ContentError` collapse.** `InsertError::Content(ContentError)` lowers to a single `RejectCode::Content` (defaulting to `Permanent`), discarding M4's error structure. Note this is best-effort pending M4's (out-of-scope) interface, and that a *transient* ContentError would be misclassified `Permanent` — a refinement to revisit if/when M4's edge is ratified.
