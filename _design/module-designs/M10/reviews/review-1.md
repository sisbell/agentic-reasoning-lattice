Reviewing M10 against the upstream interfaces (M1–M3, M5–M8), the source note (ASN-0134), the decomposition, and the composition contract. The design is fundamentally sound — a thin lifecycle wrapper that gets commit-before-ack structurally right, reads ASN-0134 faithfully, and resolves the cross-family-composite open question soundly (zero v1 occupants, mechanism retained). The defects are localized to the idempotency cache and the disposition table.

## Revision list

1. **[DEFECT] The idempotency cache over-caches: gate `idem_put` to committed-write responses only.** `execute` step (d) caches *every* `resp` keyed by `ReqId`, including `Response::Rejected` and read responses. The cache's stated purpose (ASN-0134 §A7/§SAFE(b)(iii)) is to defeat the *lost-acknowledgment duplicate* — which only exists after a **successful commit**. Caching a rejection defeats no duplicate and actively breaks the retry semantics the design itself promises: a `Nullify` rejected `{code: BadTarget, disposition: Reorder}` is cached, so when the client (heeding the Reorder hint) reissues the same logical op after the target appears, step (a) returns the *stale cached rejection* without re-executing — the nullify never happens. Same failure for `Durability`/`Retry`. Fix: in step (d), only memoize responses that represent a committed write (`Ack`/`AckAddr`/`AckEdit`); never cache `Rejected` (or at minimum never cache `Reorder`/`Retry`/`Halt`), and don't cache reads (a cached read replays a stale snapshot).

2. **[DEFECT] Disposition table classifies permanently-unsatisfiable codes as `Reorder`, contradicting upstream invariants.** The `Reorder` row asserts "a *future* committed state may satisfy the precondition." That is **factually false** for two listed codes: `NotRegistered`(type) can never become satisfiable because M7's type registry is genesis-immutable (`RegistryInvariance`, W4 — no runtime type registration; M9 writes only *tuples* of already-registered types) — reclassify it `Permanent`. `NotFresh` is op-dependent: for `register_node` the supplied address is already registered and allocations are append-only/permanent (M3), so it is `Permanent`; only `delegate`'s NotFresh is recoverable (by re-deriving the next prefix). A flat `code → disposition` table cannot honor that split — either move `NotFresh` to `Permanent` (and let `delegate` callers re-derive), or key disposition by `(OpKind, code)`.

3. **[SHARPENING] Relocate the poison latch out of the free function `map_txn`.** `map_txn` is declared as a free function, yet its `TxnError::Poisoned` arm carries `/* set self.poisoned */` — it has no `self`, so the latch is unimplemented and the "Poisoned halt … enforced in execute step (c)" invariant is unbacked as written (step (c) reads a flag nothing sets). Safety survives via the slow path (a poisoned write still gets `TxnError::Poisoned` from `transact` → `Halt`), so this is non-load-bearing, but make `map_txn` a `&self` method (closures become `|e| self.map_txn(op, e)`) or latch in `execute` upon observing a `Poisoned` response, so the fast-path actually fires.

4. **[SHARPENING] Conflict #4: commit to one M4-type resolution and reconcile it with the DAG.** M10 must *name* `Val`/`ContentWrite`/`HasContent` and carry `W: HasContent`, `W::Record: From<ContentWrite>` to call `Vstream::insert`. The "preferred" path (M5 re-exports these) is not promised by M5's interface as given — it names them as "M4's" but lists no re-export in its seams. Either secure that re-export in M5's surface, or adopt the type-only `M10 → M4` edge **and add it to the module DAG** (which currently omits it). Don't leave it bistable in "Conflicts resolved."

5. **[SHARPENING] Specify `endset_from_vspecs`'s error path.** It is called with `?` (fallible), but its only described work is `M5State::resolve` (which "cannot fault — no `Result`") + `Run::iextent` + `Endset::from_spans`. State what the `?` propagates — presumably an M10-side VSpec well-formedness check (content-subspace, depth-2) producing `IllFormedSpec` — or make the helper infallible (letting M7's `editlink` catch the empty/ill-formed type slot) and drop the `?`.

6. **[SHARPENING] Make the RejectCode union buildable without reverse-engineering it.** `RejectCode` is a comment ("deduped union of every store error variant + …"); the `From<StoreError>` impls are called "mechanical," but the variant set is only implied by the disposition table. Either enumerate the union explicitly or adopt the `(category, store_code)` shape (the design's own Open decision #6) so a builder can write the `From` impls and the `classified` lookup from one place. Note also that variant-carried localization (`MalformedSpec{index, fault}`, `NotContentSubspace{operand, region, index}`) must survive into the `Rejection` (via `detail` or a structured payload), or the client loses the fault site.

7. **[SHARPENING] Note the assumed upstream constructors.** The design calls `Vstream::new(&kernel)`, `LinkStore::new(&kernel, registry)`, and (implicitly) `Namespace::new(kernel.clone())`, none of which appear in M3/M5/M7's published interfaces (only "holds `… Kernel<W>`" prose). State the assumption (or request those `::new` constructors upstream) so the dispatch arms compile.

8. **[SHARPENING] Fix the latent-composite sketch's lock-before-mint.** §10's hypothetical passes `M3State::content_lock_key(&d)` in `transact`'s `keys` while `d` is minted *inside* the closure — `d` isn't known when the keys are taken. Note that the content lock for a freshly-minted document is moot (no concurrent writer knows the new address), or defer the content-key acquisition design to when the path is actually populated. Low priority (no v1 occupant), but the sketch as drawn is incoherent.

VERDICT: REVISE
