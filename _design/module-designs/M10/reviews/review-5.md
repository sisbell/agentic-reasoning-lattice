## Revision list

1. **`[SHARPENING]` State the SessionId non-forgeability contract the security model rests on.** §7/item-4 asserts the per-session idem key "closes the pre-auth cross-principal replay hazard" because "no other connection can present a colliding key" — but `SessionId` is a *sequential, guessable* `u64` (`next_session.fetch_add`), so that conclusion holds only if the transport binds `SessionId` to the connection and never accepts a wire-supplied one. Make this an explicit transport contract: *the `SessionId` is a per-connection credential injected by the transport from the connection binding, never client-supplied* (and consider an unguessable id as defense-in-depth). Note that this same non-forgeability already underpins the *write-authorization* model (step (b) trusts the `SessionId→principal` binding), so it is not cache-specific — phrase it once as a global precondition rather than letting §7 assert the conclusion.

2. **`[SHARPENING]` Make `execute`'s `Total` (panic-free) contract locally evident instead of resting on a non-local invariant.** `SessionCtx::principal()`'s `.expect(...)` is panic-free only because step (b) gates unbound writes *and* exactly the write arms (and no read arm) call `principal()` — a correspondence enforced nowhere locally. Produce a proven-bound value at step (b) (e.g. dispatch writes with a `WriteCtx { principal: PrincipalId }` and reads with a separate anon path) so the write arms receive a `PrincipalId` directly and the `expect`/`Option` disappears; a future mis-categorized op then cannot reach a panic and silently break totality.

3. **`[SHARPENING]` Pin the scope of the never-silent invariant across the parse boundary.** The decomposition lists "request parse" as an M10 component and "never a silent skip" as a contract, but `execute` takes an already-parsed `Request` and the parse-failure → `OpKind::Unparseable` rejection is *built by the transport*, outside M10's exhaustive-dispatch enforcement. Either (a) give M10 a raw-frame entry that invokes `Codec::parse` and constructs the `Unparseable` rejection itself, bringing parse failures under M10's enforced never-silent, or (b) explicitly scope the invariant to "post-parse operations" and document that frame-level parse surfacing is a transport obligation discharged with M10's `Rejection` type — so the boundary of the guarantee is unambiguous.

4. **`[SHARPENING]` Reword "ratifies amending the DAG" (Conflicts resolved #4/#3).** A single module design doesn't have authority to ratify a decomposition change; the substance (M5's public `insert` leaks `Val`/`ContentWrite`/`ContentError`/`HasContent`, forcing a behavior-free type-only `M10→M4` edge the DAG omits, collapsible to `M10→M5` if M5 re-exports the four types as it does `VPos`) is correct and well-argued — phrase it as *flagging a required decomposition amendment*, matching the honest framing already used for the #6 constructor amendment.
