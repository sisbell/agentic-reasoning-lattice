Reviewing M10 against the decomposition, the composition contract, ASN-0134, and the M1–M8 interfaces as given. The module is unusually well-built — the trait-bound union matches the exact union of every store op's bounds, `Response` deliberately avoids a transitive `Clone`, the poison latch is `&self` via `AtomicBool` so `map_txn` doesn't collide with the `Vstream` borrow, commit-before-ack is genuinely structural, and the RejectCode union appears complete against every upstream error enum. But there is one material hole.

## Revision list

**1. [DEFECT] Expose M3's `next_account_prefix(parent)` (and `principal_prefix(id)`) as read operations, with a `Response` shape carrying `Option<Address>` + `as_of`.** As written, M10 ships `Op::Delegate { new_prefix, new_id }` — the *only* path from the genesis bootstrap node to any account, hence essential — but provides no operation through which a client can obtain the next-form prefix `delegate` demands. M3 requires `new_prefix == next_in(namespace(new_prefix))` (`NotNextForm`) and warns "obtain via `next_account_prefix(parent)` to avoid guess-and-retry"; that value is M3-internal frontier state a client cannot compute, and the design classes both `NotNextForm` and `NotFresh` as **`Permanent`**, so retry cannot recover. §5's own disposition narrative says a delegate client "recovers … by re-deriving a fresh prefix via `next_account_prefix` — a *different request*" — a request that does not exist in the `Op`/`Response` model. The result: account creation is impossible past the first guessable prefix, and the design references a client capability it never exposes (internal inconsistency). M10 already has `HasM3`, so `snap.world().m3().next_account_prefix(&parent)` is one snapshot read away; the gap is only the missing `Op` and single-`Option<Address>` `Response` variant. Expose `principal_prefix` the same way, since a client also needs its own account `Address` to drive `CreateNewDocument`.

**2. [SHARPENING] Get the engine-facing store-driver constructors actually ratified into M3/M5/M7's published interfaces.** Conflicts-resolved #6 correctly observes that `Namespace`/`Vstream`/`LinkStore` have *no* published constructor and that the binary has no construction privilege M10 lacks — so the write path is unassemblable *by anyone* until `Namespace::new(Arc<Kernel<W>>)`, `Vstream::new(&Kernel<W>)`, `LinkStore::new(&Kernel<W>, Arc<TypeRegistry>)` exist. The design only *asserts* this precondition; flag it as a required upstream interface amendment (it is trivially satisfiable — the constructors mirror the documented fields — but it is load-bearing for system assembly, not just for M10).

**3. [SHARPENING] Ratify the `M10 → M4` type-only edge against the decomposition.** The decomposition's DAG is `M10 → M1, M2, M3, M5, M6, M7, M8` (no M4), but `Vstream::insert`'s public signature (`Vec<Val>`, `W: HasContent`, `W::Record: From<ContentWrite>`, `InsertError::Content(ContentError)`) genuinely forces M10 to name M4's types, and M5 publishes no re-export. The design's resolution (a behavior-free type/trait edge) is correct, but it *adds* an edge the decomposition omits — either ratify the DAG amendment or have M5 re-export the four M4 types (collapsing the edge into `M10 → M5`).

**4. [SHARPENING] Close the pre-auth idempotency replay / scope the cache per-session.** `execute` runs `idem_get` (step a) *before* the session check (step b), so a request bearing a cached `ReqId` returns the cached committed-write ack (Seq + minted `Address`) with no authentication. With the global cache the design currently sketches, a second principal replaying another's `ReqId` learns that commit's coordinate and address — a cross-principal disclosure. The design flags cache *scope* as open (§Open 3) but does not connect it to this auth bypass; key the cache on `(SessionId, ReqId)` (or move the idem check after step b for writes) and say so.

**5. [SHARPENING] Resolve `register_node` against the write-auth gate.** `register_node` takes no principal (it is "supplied by provisioning") yet `execute` step (b) rejects every write on an unbound session as `Unauthenticated`. This is not broken (provisioning can use `bootstrap_session()`), but the coupling is non-obvious — state explicitly that node provisioning runs under the bootstrap session, or exempt `register_node` from the principal gate.

**6. [SHARPENING] Engage M3's "M5 wires the shared content separately" in the Fork dispatch.** `Op::Fork → namespace().fork()` returns an *empty* account-tier document (M3's `fork` reduces to `create_new_document`), while the content-sharing copy-on-write fork is M5's atomic `version` (exposed as `Op::Version`). The design is faithful, but its "no v1 cross-family composite" claim brushes against M3's note that fork's content-wiring is M5's; one line distinguishing `Op::Fork` (empty identity) from `Op::Version` (content-sharing, atomic, M5-owned) would forestall a builder expecting `Fork` to share content.

**7. [SHARPENING] Make `is_content_vspan` and the ~30 unshown dispatch arms unambiguous.** `is_content_vspan` appears only as a comment; spell it out and order the conjuncts length-check-before-`get(i)` (M1's `Tumbler::get` panics on out-of-range, and `execute` is contracted `Total`). The four arm-shapes plus the full Op→method (Dependencies) and Response-consolidation comments make the remaining arms mechanically derivable — but a complete Op→method→Response table would remove all judgment from filling them. (Trivia: §5's "M6/M5's variant-carried localization" is M6-only — M5's errors carry no `index`/`operand`.)

VERDICT: REVISE
