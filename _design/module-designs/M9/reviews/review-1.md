I reviewed M9 against M1–M7 (as given) and the ASN-0128/0129/0130/0133 statements. The PL AST, the dynamics analyzer, the quiescence theory, and the conflict resolutions are mostly faithful and well-reasoned — but the term-construction/evaluation path has two real holes, and several upstream calls don't match the interfaces as written.

## Revision list

1. **[DEFECT] Make the parameter context Γ_D a first-class input to `type_check`/`define_predicate`.** `type_check(&self, term: Term) -> Result<TypedTerm, TypeError>` takes no context, and §1 says Γ "maps *bound* VarId → Sort." A parameterized def body (k>0, ASN-0130 SignedTerm) has *free* parameter `Var` nodes with no binder, so they cannot be typed — ASN-0129 WT is a Γ-parameterized **checking** judgment. Consequently no parameterized `TypedTerm` can be produced to hand to `define_predicate(d, term: TypedTerm)`, and the ordered list Γ_D that `evaluate_def(start, args, …)` binds positionally and `Signature.params`/PR5 ST⁺ ("every Γ_D-instantiation") require has no defined source. Parameterized definitions are core to ASN-0130, so this is unbuildable as specified. Fix: pass the ordered Γ_D into `type_check`/`define_predicate` (and have `TypedTerm` carry it), or state the convention that fixes free-var sorts *and order*.

2. **[DEFECT] Resolve the `eval`/`Ref`/`type_check` inconsistency.** `eval` is documented "INFALLIBLE on a TypedTerm (well-typed + **ref-free** post-expansion)" with no `Ref` row in its dispatch table, but `type_check` expands only `Reg`-quantifiers (§1) — it *types* `Ref` via WT-ref and leaves it in place — and `define_predicate(d, term: TypedTerm)` must receive ref-bearing `TypedTerm`s (a def may reference other defs, PR-SIG). The same `type_check` therefore yields ref-bearing terms, and nothing stops one reaching `eval` or `TriggerRef::Inline`, where it is unhandled. `eval` cannot resolve a `Ref` inline either: resolution is an M4 content read, which would break the structural-reads-only denotation (PC4) the design leans on. Fix: make ref-freeness an enforced/checkable precondition of `eval` and `TriggerRef::Inline`, and route *all* ref-bearing terms exclusively through `define_predicate → evaluate_def` (the separate resolve-then-denote passes), keeping `eval`'s denotation content-free.

3. **[DEFECT] Fix the `from` argument on every M7 `emit` call.** M7's interface is `emit(&self, home: &Address, ty: &Endset, from: &Address, to: &[Address])` — `from` is a single `&Address` ("|from|=1 forced"). The design passes a slice everywhere: `emit(d, reserved(PredDef), &[start], &[])`, `emit(d, reserved(Supersedes), &[old], &[new])`, and the fire's `emit(home, ty, &[x], &[])`. `&[start]` is `&[…;1]`, not `&Address`; none compile. Pass the single address (`emit(d, reserved_type(PredDef), start, &[])`, etc.). The slice form is correct only for `observe`'s `from_pat: &[Address]`, which the design also uses — don't conflate the two.

4. **[DEFECT] Correct the false statement that nullify-actions "require M7 to expose a pure `stage_emit`"** (Open build decisions). M7 already exposes `nullify(home, target) -> Result<(Address, Seq), …>`, a complete atomic transact-wrapped retraction; a single-`nullify` `FireAction` is buildable today in exactly one transaction (H-ATOM/H-FIN satisfied, parallel to the Marker emit) and needs no new M7 surface. Only *multi-deposit* fires (multi-emit, or emit-and-nullify composed atomically in one fire) need `stage_emit`. The real reason to defer nullify-rules from v1 is that their active-state triggers aren't SF-certifiable (outside the certified-terminating regime) — state that instead.

5. **[SHARPENING] Compute `L_dom` from M9's sanctioned surface.** The dispatch table builds `L_dom = ⋃_{K∈catalog} type_slice(K, Audit)`, but M7's interface partitions `type_slice` to the M8 seam and lists M9's surface as Observe + BH1–BH4 + is_k/members/targets_of. `⋃_K observe(K, &[], &[], Audit).map(|t| t.addr)` gives the same `dom(Σ.L)` inside the declared surface (or add `type_slice` to the M7→M9 seam explicitly).

6. **[SHARPENING] Tighten the `register_pred` two-transaction soundness argument (§4).** Validate-at-σ / emit-at-σ′ means *only* endorsement (iv) can regress (parse/typing are content-fixed; ever-registration is monotone). Say plainly that this weakens PR1(iv)'s *deposit-time* guarantee to a *validation-time* one, and that the regression is harmless because evaluation keys on ever-registration, never endorsement currency — rather than calling it "exactly the state the no-cascade behavior already tolerates," which conflates a *post-deposit* de-registration (PR1-permitted) with a *pre-deposit* one (technically off PR-DISC).

7. **[SHARPENING] Specify the error/outcome enums the public interface names.** At minimum the load-bearing variants of `TypeError` (`BehaviorMissing`, `DanglingReference`, plus the missing-context and ref-in-inline cases from items 1–2), `DefineError`/`RegisterError`/`CertifyError`/`RetractError`/`EvalError`/`FireError`, and the shapes of `FireOutcome`, `StepOutcome`, `Enabled`, `RuleCertification`, `Dynamics`, `Env`, `Lit`, `Prim`. Include the `From<TxnError<InsertError>>`/`From<TxnError<EmitError>>` conversions the `?` in `define_predicate`/`register_pred` needs, and pin which `Seq` `define_predicate` returns (the `pdef` emit's commit, not the insert's).

8. **[SHARPENING] Guard `retract_pred`.** `observe(pdef, &[start], &[], Active)[0].addr` panics when `start` is not actively registered; use `.first().ok_or(RetractError::NotActive)?` (or check `is_active_pred` first).

9. **[SHARPENING] Validate a `TypeKey` endset before `coverage_class`.** `coverage_class` is total only on level-uniform/address-denoting input (M7); a user-built `TypeKey(arbitrary_endset)` reaching it can panic. Look the key up in the cached `TypeCatalog` and reject a non-address-denoting/unregistered `TypeKey` with a `TypeError` before the coverage-class computation.

10. **[SHARPENING] Minor:** (a) `signature(start)` takes no snapshot — state it answers from the immutable `DefMemo`, snapshotting internally only on a miss (sound: content immutable, ever-registration monotone); (b) drop or justify `effective_owner` in the M3 dependency list — no algorithm uses it; (c) reword "T1-extrema are per-home-scoped" — PC2a defines `max_{T1}/min_{T1}` as *global* T1-extrema over an address-valued domain; the per-home ordinal-time caution belongs to BH4 `age`/`stale`, not T1-extrema.

VERDICT: REVISE
