**Revision list**

1. `[SHARPENING]` **Guard (or explicitly disclaim) `supersede`'s `old_start`.** PR4 presupposes the superseded address *is* a definition, but `supersede(d, old_start, new_term)` performs no check on `old_start` — a typo silently emits a `supersedes` edge from a non-def address, seeding a garbage lineage that `current_version` will happily walk. Add a cheap `is_ever_pred(old_start, snap)` gate before the third transaction (with a typed rejection), or add one sentence stating that `supersede` trusts the caller on `old_start`. While there, state which `Seq` the returned pair carries (presumably the `supersedes` emit's commit `Seq`, by analogy with `define_predicate`'s "the `pdef` emit's, not the insert's").

2. `[SHARPENING]` **Reconcile the divergence monitor's "count > 1 certifies misbehavior" with its own documented over-count routes, and pin the journal-attribution rule.** §8 states count > 1 for an SF/Marker rule *certifies* misbehavior (Q-EXT), but §Internal 5 concedes a gap-deposited witness can be misclassified `Fired` ("at worst… miscounted as a real fire"), and the journal-replay recompute must attribute raw `LinkRec::Emit` deposits to a `(ρ, x)` — presumably by `(ty, home, F-coverage)` match — which collides when two rules share `(ty, home)` or when a non-rule writer emits the same type (e.g. re-emission after an environment nullify: two genuine deposits, zero rule misbehavior). Both routes err toward false alarms, which is safe for a backstop, but the word "certifies" invites a builder to wire an automated kill on count > 1. Soften the claim (flag-for-investigation, exact only in the race-free single-writer regime) and state the replay attribution key and its collision cases in the `FireCounters` row.

3. `[SHARPENING]` **State the snapshot-freshness contract for rule-engine entry points with `TriggerRef::Def` triggers.** `quiescent`/`quiescent_scoped`/`next_enabled`/`step` take a caller-supplied `Snapshot`, and a `Def` trigger evaluates through `evaluate_def`, whose precondition is ever-registration *at that snapshot*. Registration-time validation (`signature` = `Some`) plus monotonicity make the `Err` unreachable only for snapshots taken at-or-after the def's registration commit; a stale snapshot predating it yields `EvalError::NotEverRegistered` inside a method that returns a bare `bool`/`StepOutcome`, with no stated policy. Add one line: either the precondition (snapshots passed to rule-engine entry points must not predate any registered `Def` trigger's registration; violation panics like `decide`) or a defined error path.

4. `[SHARPENING]` **Pin the `CertifyError` mapping for a poisoned (undisciplined) start.** CVALID(0) fails whenever `signature(start)` is `None`, but the enum offers only `NotEverRegistered` and `NotBoolean` — neither is accurate for an ever-registered start with a permanent poisoned memo entry (PR-DISC breach). Reachable only off-discipline, but a builder must pick a variant; either document that the poisoned case surfaces as `NotEverRegistered` (accepting the imprecise name) or add an `UndisciplinedDef`-style variant mirroring `EvalError`'s.

5. `[SHARPENING]` **Pin the flat-`expand` traversal order.** The certification-path flat build claims cross-evaluator determinism ("two evaluators thus obtain the same concrete term") via the content-deterministic counter, but the design restates only the counter discipline, not the traversal order the counter advances along (the note fixes bottom-up, siblings left-to-right, parameters before binding sites). Any fixed order suffices; since the builder works from this document alone, add the one clause fixing it so the determinism claim is implementable as stated rather than by convention.
