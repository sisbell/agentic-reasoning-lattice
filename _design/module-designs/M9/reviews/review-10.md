This design is close — the seam analysis (audit-honoring `observe`, UV self-exclusion, engine-injected registry, the two-transaction soundness arguments) is unusually careful. But I found one internal contradiction in the type system, two soundness/contract gaps, and one admit-vs-serve mismatch against M7's given interface, so it does not converge this round.

**Revision list**

1. **[DEFECT] Resolve the contradictory typing rules for `MapGet(TargetsKeyed(s), Concrete(K))`.** §Internal 1's atom-typing paragraph gates the indexed lookup on `K` being BH3/Binary (`BehaviorMissing{ty: K, needs: ReverseLookup}`), but the same section's `Reg`-expansion paragraph names `MapGet(TargetsKeyed(s), ClassVar(cvar))` as "the one survivor... well-typed whenever *some* class attaches BH3." These cannot both hold: instance-wise expansion necessarily produces the `Concrete(R)` instance (retraction is mandatory with `behaviors = ∅`), so under the BH3 guard every `Reg`-quantified `targets_keyed` join dies as `RegInstanceIllTyped` and no survivor exists. The BH3 guard is also unfaithful to ASN-0129: V-PRIM defines `·[K]` as "Map lookup **per registered class**... an absent key reading ⊥," and V-STAT adds the lookup for *every* newly registered K, not just BH3 ones. Fix: `MapGet`'s `TypeRef` guard is cataloged-only (`UnregisteredType` if absent), with no behavior requirement; a non-BH3 or key-absent lookup denotes ⊥, which the evaluator's absent-key handling already produces. Keep `NoReverseLookupClass` on the bare `Atom::TargetsKeyed` only.

2. **[DEFECT] Restore PD0's argument proviso on the atom-level ST rules in §3.** PD0 places `is_doc(d)` and audit `is_K(addr)` in ST only when "its argument a literal or already-bound address." §3 carries this condition for the membership/`targets_of` forms ("at a literal/bound `t`") but drops it for `is_doc` and audit `is_K`. As written, a builder classifies `IsDoc(e)` as ST for an arbitrary Addr-sorted, state-reading argument `e` (e.g. an `IfSome`-narrowed value), whose value can change across steps and flip the verdict ⊤→⊥ — over-certification, violating the module's own "never over-certify" invariant and feeding false `pd_stable` certificates and `CertifiedTerminating` verdicts. Fix: the atom-level ST verdict applies only when the address argument is step-constant (a Γ- or binder-bound `Var`, a literal, or a bound-tuple V-TUP projection — equivalently, a subterm with empty footprint); otherwise the node lands in `Neither`.

3. **[DEFECT] `step`'s outcome type cannot represent a fire failure.** `step(&mut self, snap) -> StepOutcome` offers only `Fired`/`Deduped`/`NoOp`/`Quiescent`, yet `fire` returns `Result<_, FireError>` and the design itself documents recurring failures in admitted configurations: an `Addr`-over-`M_K` Nullify rule trips `FireError::Nullify(Rejected(BadTarget))` on *every* fire (a documented contract, not a registration check), and `HomeNotRegistered` is promised to be "never a silent skip." As typed, the default driver must swallow the error — a silent skip at exactly the layer the design forbids it — and gives no rotation policy for a persistently failing enabled occurrence (it never discharges, muddying the weak-fairness account). Fix: add a failure arm (`StepOutcome::Failed { rule, arg, err: FireError }`, or return `Result<StepOutcome, FireError>`) and state the rotation policy for a failing occurrence (e.g. rotate past, surface to the caller for deregistration).

4. **[DEFECT] BH2 admit/serve mismatch for app-declared Walk classes.** M7's given interface serves `succs`/`chain`/`tip` only for the shipped `Supersedes` class in v1 ("empty/trivial for any other `ty`"), but M9's behavior guard admits BH2 atoms on *any* cataloged class whose registration attaches Walk — and nothing stops an app `TypeDecl` from attaching Walk at genesis. Following the dispatch table verbatim, PL then silently denotes `succs(K_app, x) = ∅` and `chain = []` at every state for admissible terms — contradicting ASN-0128's BH2 semantics without any signal. This is exactly the class of seam trap the design catches elsewhere (aggregate `is_filtered`, audit-honoring `observe`) and misses here. Fix (M9-local, cheapest): in v1 the catalog guard admits BH2 atoms only at the Supersedes key, rejecting others with a typed error naming the v1 limitation; alternatively, document the propagated limitation and bar Walk in app decls as a named assembly obligation.

5. **[SHARPENING] Re-check domain membership in `fire`, or state the trigger-only contract.** ASN-0133 defines a fire of `(ρ, x)` only at states with `x ∈ [D_ρ]_Σ`; M9's `fire` re-evaluates the trigger off its own snapshot but not membership, so an argument removed from the domain in the peek→fire gap can still deposit. This is benign under idem⊤ (and the design's Deduped analysis covers the converse race), but it fires outside the note's fire relation and blurs fairness's "removed" discharge. Either re-check `x ∈ [D_ρ]` at the fire snapshot (NoOp if out) or document the deviation and its benignity explicitly.

6. **[SHARPENING] Fix the `Reg`-expansion phrasing "emit the And/Or of the well-typed instances."** It reads as filtering ill-typed instances out, while the following sentence (and V-IDX) requires any ill-typed instance to reject the whole term via `RegInstanceIllTyped`. Reword to "the And/Or of the instances — each of which must be well-typed, else the term is rejected."

7. **[SHARPENING] State the Tumbler→Address lift at its real sites.** `Value::AddrSet` holds `im::OrdSet<Tumbler>` while quantifier/fold binding produces `Value::Addr(Address)` and extrema produce `OptAddr`; the evaluator lifts set elements via M1's `validate` (infallible on store-minted addresses). The Dependencies section attributes the `validate` lift to lifting "a §G Tumbler," but M9 never calls M7's §G — repoint the note to the set-element binding sites.

8. **[SHARPENING] Have `define_predicate` reject a `Tup`-parameter `TypedTerm` up front.** A term built via `type_check_trigger` can carry a `Tup` parameter; today it is caught only at `register_pred`'s re-check — after committing orphan content. Reject before the insert, and specify that the def codec refuses to encode `Sort::Tup` in a parameter context (parameter sorts are Codom-only per ASN-0130's SignedTerm), making the invariant hold at encode time as well as at registration.

VERDICT: REVISE
