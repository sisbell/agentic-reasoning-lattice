ameter, but `Signature.params` are Codom-only (`type_check` rejects `Tup` with `TupParameter`), so the def-escape is unavailable — leaving the consumer stuck between two rejections (`RefBearingInlineTrigger` and `TupParameter`) with contradictory advice. State explicitly that ref-bearing triggers are persistable-as-def *only* for Codom-parametrized (non-`Tup`) triggers; a tuple-domained trigger must be ref-free `Inline` (inline the helper). M9's *behavior* is correct (both rejections fire); only the stated remediation is incomplete.

2. **[SHARPENING] Validate (or explicitly constrain) a `FireAction::Nullify` rule's domain at `register_rule`.** `nullify(home, a)` requires `a` to be a resident link (M7 `BadTarget` otherwise). For a tuple-domained rule `a = t.addr` (a resident link — fine), but for an `Addr`-domained rule over `M_K` the bound argument is a *from-side member address*, not a link tuple, so every fire fails late with `FireError::Nullify(Rejected(BadTarget))`. Either reject a `Nullify` rule whose domain element sort/shape cannot yield link addresses at registration, or document that `Nullify` rules must be tuple-domained (or address-over-`L_dom`) so the late `BadTarget` is not a surprise.

3. **[SHARPENING] Note the engine-injection dependency on M5/M7 exposing engine-visible handle constructors.** `Coordinator::new`'s `mk_vstream`/`mk_link_store` factories are the correct way for M9 to avoid naming `Vstream::new`/`LinkStore::new` (absent from the "for dependents" interfaces). But the factory *bodies* the engine supplies require those constructors to exist publicly to `skep-engine`; the M5/M7 interfaces as given show no such constructor (a gap shared with M10). Add one line: M9's instantiation presupposes the engine can construct `Vstream`/`LinkStore` from `&Kernel<W>` — an upstream/assembly obligation, not an M9-local one.

4. **[SHARPENING] Reconcile the `Address`-vs-`Value` typing for tuple-domained fire bookkeeping.** `Enabled.arg: Value` admits `Value::Tuple`, but `fire_count(rule, x: &Address)` and `StepOutcome::{Fired,Deduped}{ arg: Address }` are `Address`-typed. Specify that for a `Tup` domain the bookkeeping key/report is `t.addr` (tuples are address-identified, so this is total and collision-free), or widen these to carry the projected address explicitly.

5. **[SHARPENING] Enumerate which formers reject `Dom::Reg`.** The design states `Reg` is "quantification-only" plus the `Count(Reg) → Lit` exception and the `Reflect(Reg)` rejection, but does not explicitly say `BigUnion(Reg)`/`MaxT1(Reg)`/`MinT1(Reg)`/`SetTerm` over `Reg` are rejected (PC2a "Reg excluded"; extrema need address-valued). Add the explicit list: `Reg` is admissible only under `Forall`/`Exists` (expanded by `type_check`) and `Count` (folds to `Lit`); every other `Dom`-accepting former rejects it at the element-sort check.

6. **[SHARPENING] Specify `RwLock` (not `RefCell`) for the `DefMemo` interior mutability.** A `Coordinator<W>` over the `Send + Sync` factories and `Arc<Kernel<W>>` is naturally `Sync`; `RefCell` is not `Sync` and won't compile across the `&self` `signature`/`define_predicate`/`register_pred` API if the Coordinator is shared. State `RwLock`/concurrent-map (the idempotent-`Some`-fill argument already justifies the benign race).

7. **[SHARPENING] Use `slice::from_ref` for single-`&Address` slice arguments, and `value_at(start.tumbler())`.** Throughout, `observe(pdef, &[start], …)` / `&[x]` / `&[r]` is written where the M7 reads want `&[Address]` (a literal `&[start]` is `&[&Address]`); the `supersede` body already shows the correct `slice::from_ref(&new_start)`. Likewise `value_at` takes `&Tumbler`, so M9 passes `start.tumbler()`. Pseudocode hygiene — the intent is unambiguous, but make the slice form consistent so a builder copies it verbatim.

8. **[SHARPENING] Soften the "byte-identical to M7's `reserved_type`" claim to coverage-equality, and state PR-ENC injectivity.** (a) M9's correctness needs only that its own `reserved_type(ShippedType) = enc(&[reserved.X])` endsets are *coverage-equal* to M7's types — M7's `emit`/typed reads identify by coverage (I0), so a non-`enc` stored key would still accept M9's endsets; the byte-identity is a happy assumption, not a requirement. (b) §Encoding says "deterministic, decidable, prefix-free, self-delimiting" but not *injective*; PR-ENC requires injectivity (and it follows from `decode∘encode = id`) — state it, since identity-by-start and `register_pred` dedup lean on it.

9. **[SHARPENING] Reserve an explicit `VarId(u32)` range for PR-ENC expansion names.** §Internal 4's certification flat-`expand` draws fresh names "from PR-ENC's reserved supply"; since all vars are `VarId(u32)`, the design should carve out the reserved sub-range so the body-binder-disjointness PR-ENC mandates ("no recorded parameter name and no body binder may inhabit") is structurally enforced, not just intended.
