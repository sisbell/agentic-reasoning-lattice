Reviewing M9 against the source notes (ASN-0129/0130/0133/0128), the upstream interfaces, and the decomposition. This is a strong, self-aware design — most conflicts are resolved soundly and explicitly (the two-transaction `register_pred` weakening, the `dom(Σ.M)`→M3 residence mapping, the UV `K_queried` self-exclusion, the Unary-`pdef`/re-parse resolution). The defects below are the load-bearing ones.

## Revision list

**1. [DEFECT] The AST cannot represent QD-refl's reflection of `L_dom` or any *filtered* domain as a set-valued term, so the "denotationally complete" claim is false and the value-returning-def interface is unbacked.** §Internal 1 / Core data model keep only the *unfiltered* `M_K` reflection (`Atom::Members`); there is no `Dom→Term` former for `L_dom` or a `Filter`, and there is no singleton-set former, so `BigUnion{dom: Filter{LinkDom,P}, …, body: {x}}` cannot be spelled either. Consequently a perfectly valid ASN-0129/0130 def body such as `f() : ℘_fin(T) := {x ∈ L_dom : is_doc(x)}` (an address-valued filtered domain reflected to a term, in `PL` by PC6/QD-refl) is **unrepresentable**, while the public interface explicitly admits it (`Signature.result : Sort` any COD sort; `evaluate_def → Value`; `define_predicate(term: TypedTerm)` of any sort). Boolean uses survive (membership/emptiness via `∃`/`¬∃`), but value positions do not. **Fix:** either add a value-reflection former for address-valued domains (e.g. `Term::Reflect(ArcDom)` typing at `℘_fin(T)`, directly mirroring QD-refl), or scope the completeness claim to *Boolean predicates* and restrict/document the value-returning-def surface to set-bodies that are atom- or fold-derived (no reflected `L_dom`/filtered domain).

**2. [DEFECT] The BH4 `age(K,a)` / `stale` dispatch guard is wrong against ASN-0129's totalization.** §2's table and the matching invariant both specify `is_active(a) ∧ is_k(K,a) ? M7::age(a) : ⊥`. ASN-0129 says `age(a) = ⊥` exactly when `a` is *not the address of an active K-tuple* — a tuple-identity test. `is_k(K,a)` is coverage-of-`F` membership (content addresses denoted by some K-tuple's from-set), not "the tuple at link-address `a` has type K." For a real active K-tuple at link-address `a`, `is_k(K,a)` is false, so the guard makes `age` **always `⊥`**. Even though BH4 is dormant in v1, the row is concretely mis-specified. **Fix:** test active-K-tuple-address identity, e.g. `observe(K,&[],&[],Active).iter().any(|t| t.addr == a)` before `M7::age(a)`; correct both the §2 dispatch and the §Invariants "BH4 totalization" line.

**3. [SHARPENING] `classify` under-specifies which domains are grow-only.** §3 names the stability lattice and the `ST`/`SF` leaf rules but cites "grow-only domain" without enumerating the forms (`L_K`, `L_dom`, audit-view `M_K`, a filter over a grow-only domain with an `ST` body, step-constant domains). A conservative omission stays *sound* (errs to not-certified) but loses completeness silently. Transcribe PD0's grow-only closure so the classifier's certification reach is buildable from this doc alone.

**4. [SHARPENING] State where the catalog's *shipped-type registrations* come from.** The `TypeCatalog: HashMap<TypeKey,(CoverageClass,Registration)>` is "built from (reserved, decls) plus the five ShippedType endsets," but the behavior guards (e.g. `Succs ⇒ Binary/BH2`) need the shipped `Registration`s (`retired=Unary/{BH1}`, `supersedes=Binary/{BH2}`, `retraction=Binary/{}`, `pred_def`/`pred_stable=Unary/{}`). Make explicit that these are sourced from `TypeRegistry::build`'s seeded shipped set / the PredLayer agreement / M7's shipped-type table, not from the `decls`.

**5. [SHARPENING] `type_check` should reject `TargetsKeyed`/`MapGet` when no registered class attaches BH3.** Per V-atom, `targets_keyed` is in the vocabulary *iff some class attaches BH3*; in v1 no shipped type is BH3, so an accepted `TargetsKeyed` evaluates to an always-empty map (harmless but outside ASN-0129's vocabulary). Add the "∃ BH3 class" guard at the class-unindexed atom.

**6. [SHARPENING] Extend the named Audit-reliance flag to `members(pdef, Audit)`.** §2 flags only `observe(·, Audit)` as relying on M7 honoring `View::Audit`, but ever-registration (`register_pred` (iii), `signature`/`evaluate_def`, the hints table) is read via `members(pdef, Audit)`. M7's `members` contract foregrounds only `Default`/`Active`; name this audit dependency at the seam so an M7 build that ignored `Audit` on `members` is caught.

**7. [SHARPENING] Pin the rule-domain enumeration view to `rule.view`.** The trigger is stated to evaluate "at `rule.view`," but `[D_ρ]_snap` for a view-parameterized domain (`M_K`) has no view pinned. For a `default`-view rule over `M_K`, enumerating at `active` over-includes filtered args (spurious fires). State that the domain is enumerated at `rule.view`.

**8. [SHARPENING] Name the `LinkStore<W>`/`Vstream<W>` constructors M9 depends on.** M9 "constructs its `Vstream<W>` … and the internal `LinkStore<W>`," but neither M5 nor M7 publishes a constructor in its interface (only the struct + ops). The intent is unambiguous, but M9 (and M10) cannot build without it — surface the required constructor signatures (e.g. `LinkStore::new(&Kernel<W>, Arc<TypeRegistry>)`, `Vstream::new(&Kernel<W>)`) as an upstream dependency.

VERDICT: REVISE
