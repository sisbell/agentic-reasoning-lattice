Reviewing M9 against the upstream interfaces (M1–M7), the source notes (ASN-0128/0129/0130/0133), and the decomposition. The design is unusually careful — the two-transaction `register_pred` soundness argument, the `is_doc → is_registered_document` mapping, the structural-reads-only/resolution split, and all six conflict resolutions are stated and sound. Two real problems remain, plus polish.

# Revision list

**1. [DEFECT] `register_rule` (with the `Rule`/`RuleError` types) under-specifies validation, so malformed rules are accepted and fail late as eval-time panics rather than typed rejections.** `Rule.domain: Dom` is a *raw, un-type-checked* QD expression, and the trigger is type-checked independently of it (`type_check` only ever sees standalone `Term`s, never a bare `Dom`). Nothing reconciles the trigger's parameter with the domain. A caller can build `Rule{ domain: ActiveSlice(K) /*Tup*/, trigger: Inline(TypedTerm with an Addr param), … }`; `register_rule` checks only ref-freeness and accepts it; at fire/quiescence the domain enumerates `Tuple`s, binds a `Tuple` to the trigger's `Addr` parameter, and the atom dispatch panics. Specify that `register_rule` must (a) validate `rule.domain` as a QD domain expression (cataloged `TypeRef`s, well-typed `Filter` bodies, behavior-compatible atoms, element sort `Addr` or `Tup`, no bare `Reg`), reusing the WT domain judgment; (b) require the trigger to be a one-parameter `Bool`-codomain predicate whose single parameter sort equals the domain element sort — for `Inline` check the carried `Γ_D`, for `Def` check `signature(addr)` is ever-registered, Boolean, and single-param of the domain sort; (c) add `RuleError` variants (`IllFormedDomain(TypeError)`, `DomainTriggerSortMismatch{expected,found}`, `TriggerNotBoolean`, `DefTriggerUnregistered`, `BadTriggerArity`). Today only `RefBearingInlineTrigger` exists.

**2. [DEFECT] The default-view denotation of `members(K, default)` diverges from ASN-0129 UV when `K` is itself the BH1 filter type.** The atom dispatch delegates `members(K, default)` to M7's `members(K, Default)` (= active ∖ aggregate-`is_filtered`). For `K = retired` that yields ∅, but ASN-0129 UV's `K_queried` self-exclusion requires `members(retired, default) = members(retired, active)` — a type never filters its own members (this is the *settled* OQ1, a locked commitment). The conflict-3 note frames the aggregate-`is_filtered` limitation as mattering only for "a second BH1 type," which misses this single-BH1 self-query. Fix: for `members(K, default)`, compute `members(K, active)` filtered by the BH1 types *other than* `K` instead of blindly delegating — in v1 that returns `members(retired, active)` unfiltered for `K = retired` and delegates only for `K ≠ retired`. (Unary `retired` makes `targets_of(retired,·)` ∅ regardless, so in v1 only `members` is affected; correct the note's scoping accordingly.)

**3. [SHARPENING] `next_enabled(&self)` cannot itself be "fair."** It is described as "round-robin/FIFO over the agenda," but `&self` cannot advance a rotation cursor. State that `next_enabled` *peeks* a candidate and the `&mut self` `step` driver owns the rotation, so the weak-fairness guarantee (Q6 regime-ii-grow-only) is a property of the `step` loop, not a single `next_enabled` call.

**4. [SHARPENING] The `Atom::Age(TypeRef,_)` dispatch (`age → M7::age(a)`) drops ASN-0129's BH4 totalization.** ASN-0129 makes `age_K(a) = ⊥` unless `a` is an active `K`-tuple, whereas M7's type-agnostic `age(a)` returns `Some(distance)` for any homed address. Guard the dispatch with `is_active(a) ∧ is_k(K,a)` before returning `M7::age`. Dormant in v1 (no BH4 type is cataloged, so `Age` atoms can't even type-check), but it ships latent for the first BH4 activation; likewise note the `Nat → u64` narrowing when forwarding a `stale` horizon.

**5. [SHARPENING] `quiescent_scoped(scope, body, snap)` applies one `ScopeBody` to the whole registry, but per-emitter/target/source need tuple-domained rules and per-address needs address-domained rules** — a mixed-sort registry has no single valid body. Specify either that the body applies per-rule only where sort-compatible (others left unscoped) or that the registry must be sort-homogeneous, and state `scope`'s contract (a one-`Addr`-parameter `Bool` predicate), validated up front.

**6. [SHARPENING] Validate `FireAction::Marker.ty` shape at registration.** A non-Unary `ty` currently fails only at fire time (`FireError::Emit(ShapeViolation)` from `emit(home, ty, a, &[])`). Checking at `register_rule`/`certify_rule` that `Marker.ty` is a cataloged Unary type converts a statically-detectable error into a registration-time typed rejection.

**7. [SHARPENING] `supersede` is three non-atomic transactions, and a lost-ack retry branches the lineage.** A retry re-inserts a fresh successor and emits a second `old→new'` edge, so `current_version` returns `Indeterminate` — worse than `define_predicate`'s harmless-orphan retry outcome. Note this and that retry-dedup is M10's idempotency responsibility (as already stated for `create_new_document`).

**8. [SHARPENING] State the encoding of `L_dom` set-operations and its PD0-precision pitfall.** Only `M_K` gets a term twin (`Atom::Members`); `L_dom`/slices/filters reach term position only through `Dom`-accepting formers. This is denotationally complete, but make explicit (where §Internal 1 gestures at it) that `t ∈ L_dom` / `L_dom = ∅` are spelled `Exists`/`¬Exists`/`Count` over `Dom::LinkDom`, and that emptiness must be `¬∃` (or `count ≤ 0`), *not* `count = 0`, since PD0 puts `count = c` in neither stability class — otherwise certification precision is silently lost.

**9. [SHARPENING] Name the interior-mutability requirement.** `signature`/`define_predicate`/`register_pred` are `&self` yet update recomputable hint caches (`DefMemo`); state these are interior-mutable, and that `FireCounters` are authoritative-via-journal-replay so a direct `&self` `fire` that does not touch the cached counter is still covered by the divergence monitor's recompute.

VERDICT: REVISE
