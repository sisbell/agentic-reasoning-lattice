Picking up from the seam-by-seam check — most of M9's calls into M1/M2/M3/M4/M5/M7 typecheck against the interfaces as given, the Unary-`pdef` and content-address-`supersedes` conflict resolutions are sound, the two-transaction `register_pred` weakening of PR1(iv) is correctly argued, and `is_doc → is_registered_document` is faithful to the decomposition's `dom(Σ.M)`=registry realization. The construction-by-engine-injection (factories + shared `Arc<TypeRegistry>`) is the right boundary discipline and dodges naming unpublished upstream constructors. One material problem remains, plus several sharpenings.

## Revision list

1. **[DEFECT] `type_check`'s blanket `TupParameter` rejection makes ASN-0133's tuple-domained rules unbuildable — contradicting `register_rule`'s own Tup-domain support.** `type_check` "rejects any `Γ_D` parameter whose sort is not a codomain — a Tup-sorted parameter (`TupParameter`)" (citing ASN-0130 SignedTerm). But `register_rule` explicitly requires, for a `Tup`-domained rule (`ActiveSlice(K)`/`AuditSlice(K)`), "a Tup-parameter trigger" (and emits `DomainTriggerSortMismatch{expected: Tup, …}` to enforce it). An `Inline` trigger's `Γ_D` *comes from* `type_check`, so a one-`Tup`-parameter trigger can never be constructed; a `Def` trigger is a stored def, whose signature is also Codom-only — so **no trigger of either kind can take the `Tup` argument a tuple-domained rule binds.** ASN-0133's `ρ_R` (the retraction rule over `L_cmt`) is exactly such a rule and is the note's central scoped-rule example (Q7 "covers tuple-domained rules — `ρ_R` among them, whose `dom(Tup)` restriction"), so this is not a corner case. The justification is also over-broad: ASN-0129 WT *admits* `Tup`-sorted context variables, and `eval` already binds `Value::Tuple` (`Enabled.arg`) and dispatches the V-TUP atoms (`TupAddr`/`TupAddrsF`/`TupAddrsG`/`InCoverageF`/`InCoverageG`) on it — the Codom-only restriction is real only for the *stored-def* path (where `evaluate_def` binds value `args`). **Fix:** split the parameter-sort policy by use — keep `TupParameter` for `define_predicate`'s `Γ_D`, but permit exactly one `Tup`-sorted parameter when checking a rule trigger (a flag or a second `type_check_trigger` entry). Correspondingly, state that `Def` triggers (Codom-only sigs) cannot serve `Tup` domains, and have `register_rule` reject a `Def`+`Tup`-domain pairing (or document that `Tup`-domained rules require an `Inline` trigger).

2. **[SHARPENING] Consolidate the audit-slice reliance onto one named, ASN-0086-justified primitive.** Ever-registration (the backbone of `register_pred (iii)`/`signature`/`evaluate_def`/the hints) reads `members(pdef, Audit)`, but M7's `members` contract documents only D1/Active/Default and is silent on `Audit` — the design itself concedes "M7's `members` contract foregrounds only Default/Active." M9 *already* relies on `observe(_, Audit)` returning the audit slice (for `is_K@audit`, `L_K`, `L_dom`), and `observe`'s Audit-capability is the same assumption (and is mandated by ASN-0086's two-selectable-slice `Observe`, which M7 explicitly realizes elsewhere via `type_slice`'s "L_K (Audit)"). Route ever-registration through `observe(pdef, &[start], &[], Audit)` (= `is_K(pdef, start)@audit`) so the whole audit surface rests on the single `observe`-honors-`Audit` seam, and state that one requirement once at the boundary rather than asserting a separate, less-documented `members`-Audit dependency.

3. **[SHARPENING] Make `quiescent_scoped`'s exact-vs-approximate behavior a caller contract, not just prose.** ASN-0133 Q7's `quiescent_{R,S}` uses each rule's *declared* scoping body; M9 takes one `ScopeBody` per call, applies it only to sort-compatible rules, and leaves the rest unscoped. The design correctly notes this is safe-direction (never false quiescence) and exact for sort-homogeneous registries — but a consumer needs the *contract* on the method: "exact for a registry whose scoped rules share this body's sort; a strict over-approximation of remaining work (never false quiescence) otherwise; exact per-rule scoping deferred (Open) pending a per-rule scope-body field on `Rule`." Promote that from §Internal 6 into the `quiescent_scoped` caller contract.

4. **[SHARPENING] Encode the pre-`Reg`-expansion compact body, not the expanded `TypedTerm`.** Because `define_predicate` takes a post-type-check, post-`Reg`-expansion `TypedTerm`, the stored `Val` is the *expanded* body (`body × |classes|` for any `∀K∈Reg`), diverging from ASN-0130 PR-ENC's canonical encoding of the compact signed syntactic term (ASN-0129's grammar *includes* `Reg`-quantifiers). It round-trips and re-derives an identical `sig`/denotation, so it is not load-bearing — but retain the original syntactic body in `TypedTerm` and encode that, to match the note's canonical form and avoid per-def storage blowup.

5. **[SHARPENING] State `fire`'s trigger-check / emit as two transactions and its benign resolution.** `fire` evaluates `T_ρ(x)` against its own snapshot, then runs `emit`/`nullify` as M7's separate `transact` (M9 cannot nest). A trigger can flip between the check and the commit; the design relies on this being harmless but never says why. Make it explicit: idem=⊤ dedup absorbs the race (a Marker emit dedup-hits the now-present witness; a `nullify` dedups the already-retracted target), so the gap is benign — and distinguish a dedup-hit `FireOutcome` from a real deposit (today both report `Fired{effect, seq}`, which over-counts in `FireCounters` for the divergence monitor).

6. **[SHARPENING] Note `define_predicate`'s insert-position TOCTOU.** `at = VPos{ s_C, n_C+1 }` is computed off a snapshot read of `content_count(d)`, then `insert` revalidates against committed state: a concurrent INSERT lands the def mid-document (harmless — identity is the returned start address), a concurrent DELETE shrinking `n_C` yields a clean `Insert(Rejected(BadPosition))` (retryable). State both outcomes so a builder doesn't treat the rejection as a logic error, and note the orphan-content-on-`register_pred`-failure is the same benign pattern as `create_new_document`'s orphan.
