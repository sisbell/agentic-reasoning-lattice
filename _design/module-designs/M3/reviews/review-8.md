## Revision list

**1. [SHARPENING] Add the serde derives to M3's *own* persisted types.** `M3State`, `M3Rec`, `NsKey`, `Principal`, and `PrincipalId` all sit inside checkpointed slice state or journaled records, so M2's `WorldState`/`XRec` contract requires `Clone + Serialize + Deserialize` on each. But the design shows `#[derive(Clone, PartialEq, Eq, Hash)]` on `NsKey`, `#[derive(Clone)]` on `Principal`, a derive-less `M3State`, and *no* derive line on `M3Rec`. The design is meticulous about this for M1's types ("Tumbler/Address/… derive Serialize+Deserialize") — mirror it here: `M3State`/`M3Rec`/`NsKey`/`Principal` → add `Serialize, Deserialize`, `PrincipalId` → add `Serialize, Deserialize`. State explicitly that `frontiers`/`nodes`/`principals` are normal (non-`#[serde(skip)]`) fields, so the "needs no `rebuild_derived` override" claim is airtight (they are checkpointed, not replay-rebuilt).

**2. [SHARPENING] Spell out the (iv) top-down range bound in `delegate`.** "OrdMap range scan" is correct but terse; give the concrete form: `principals.range(new_prefix.tumbler().clone()..)`, take the first key `k`, reject `NotTopDown` iff `is_prefix(new_prefix.tumbler(), k) && k != new_prefix.tumbler()` — a single probe suffices because the extensions of `new_prefix` are a contiguous block under tumbler order (T5). Apply the same concretization to `effective_owner`'s optional `OrdMap` descending-range upgrade.

**3. [SHARPENING] Rename the fold from `apply` to the engine-composition convention** (`apply_ns`/`apply_m3`). The composition contract names the per-store fold `apply_x` (`self.ns.apply_ns(x)`); naming M3's `fn apply(&self, r: &M3Rec) -> M3State` collides conceptually with `WorldState::apply` and obscures that this *is* the dispatch target. Rename and note that the engine's `World::apply` routes the `Record::Ns` variant here.

**4. [SHARPENING] Fix the `Space`-enum placement wording and reconcile the three-tag use.** The text calls it "the engine's single central `Space` enum," which read literally would put it in the assembler crate and *cycle*; per the M2 contract it lives in `skep-kernel`, below every store. Say that, and note that M3 draws *three* tags (`Namespace`/`Principals`/`Nodes`) from that one central enum — a deliberate (and fine) deviation from the contract's "each store is assigned one tag" guidance, since M3 genuinely owns three serialization domains; flag it so the assembler reserves all three.

**5. [SHARPENING] Make the ω-authorization comparisons explicit about `None`.** `effective_owner(account).id == caller` is written informally against an `Option<Principal>`; render it as `matches!(self.effective_owner(account), Some(p) if p.id == caller)` (→ `NotOwner` otherwise) at the prose sites, matching the behavior the design already states.
