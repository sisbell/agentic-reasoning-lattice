The allocation core is genuinely strong: the closed-form `next_in` (count → `c_{m+1}` via `shift`), the `(parent, g)` keying that makes document/version/content/link frontiers separate by construction (the ASN-0123 fix), the byte-identical lock-key/frontier-key mirroring, and the P8 parent-registration gate in `delegate` (conflict 5) are all correct and faithful. ## Revision list

1. **[DEFECT] Enforce (or explicitly delegate) `PrincipalId` injectivity — `delegate` accepts an unchecked `new_id`, but `principal_by_id`/`principal_prefix` and the `effective_owner(account).id == caller` authorization gate all assume one id ↦ one principal.** The data model keys `principals` by *prefix* and treats `PrincipalId` as an opaque caller-supplied field with no freshness check; the design enforces *prefix* injectivity (delegate condition (v) `!is_allocated(new_prefix)`, O1b) but introduces a second identity axis used as the auth/lookup key with no corresponding guarantee. If M10 ever reuses an id (a fixed "admin" id, `id = hash(user)`, or simply `PrincipalId(0)` = `BOOTSTRAP_PRINCIPAL`), `principal_by_id` returns an arbitrary match, so `fork`/cross-owner `VERSION` mint under the wrong account and `create_new_document`'s ω-gate mis-authorizes — an O8/O5 violation. Fix: either (a) add an id-freshness gate to `delegate` — reject `principal_by_id(new_id).is_some()` with a new `DelegateError::DuplicateId`, mirroring the prefix-freshness check — **or** (b) state as an M3 *requirement* that M10 supply globally-unique, never-reused `PrincipalId`s and that `principal_by_id`/`principal_prefix`/the ω-gate are well-defined only under that obligation. As written, the data model permits what the auth layer forbids.

2. **[SHARPENING] Define the `namespace(addr) -> NsKey` helper.** It is used in `delegate`'s next-form check (`new_prefix == next_in(namespace(new_prefix))`, §6) and in the `delegate` lock acquisition (`namespace(new_prefix)`, §8) but never defined; only `decompose` exists. Add `fn namespace(addr: &Tumbler) -> NsKey { let (p, g, _) = decompose(addr); NsKey{parent: p, g} }` (or have `delegate` call `decompose` directly) so the next-form check and the held lock key are visibly the same key the staged `Allocate` will advance.

3. **[SHARPENING] Write out the `is_allocated` body.** It is only described ("the same probe without the `zeros ≤ 2` restriction"). Show it explicitly: it must keep `entity_level`'s `Level::Node => nodes.contains(..)` case and replace the `Level::Element => None` arm with the general decompose-and-compare branch (parent/`g`/`ordinal ≤ m`), since this is the content/link referential-integrity oracle M5 (COPY transclusion) and M7 depend on.

4. **[SHARPENING] Specify how `transact` closures and snapshot reads reach the `M3State` slice of `W`.** Methods are written as `impl M3State` (`stg.working().mint_document(..)`, `snapshot.world().is_allocated(..)`), but `Staging::working()`/`Snapshot::world()` return `&W` (the composite engine state), of which `M3State` is "M3's slice." Name the accessor (`W::m3(&self) -> &M3State`, per M2's "read your store's slice off this" contract) so a builder isn't left to assume `W == M3State`.

5. **[SHARPENING] Tighten the error enums and their mapping.** Several loose ends: `OpError::NotAnAccount` duplicates `OpError::Mint(MintError::NotAnAccount)` — pick one surfacing path for `create_new_document`/`fork`; `OpError::NotRegistered` appears unused (an unregistered account is caught as `NotAnAccount` by `mint_document`) — remove or justify it; `delegate`'s next-form check calls `next_in`, which can return `GateViolation`, but `DelegateError` has no mapping for it (fold into `NotNextForm` or add a variant); `fork`'s unknown-caller path returns before any transaction yet must produce `Result<_, TxnError<OpError>>` — state that it constructs `TxnError::Rejected(OpError::NotOwner)` directly; and `mint_version`'s `SourceNotRegistered` also fires for a *registered non-document* source (`!= Some(Document)`), so the name is slightly misleading — clarify it covers "source is not a registered document."
