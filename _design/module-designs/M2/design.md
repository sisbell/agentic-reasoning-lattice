# M2 — Transaction, Journal & Concurrency Kernel — Detailed Design

## Purpose & boundary

M2 is the engine's **generic transactional substrate**: it turns every state change into one atomic, totally-ordered, durable, recoverable step (or a composite committed as one), serves consistent snapshots of committed state, and serializes writers — *knowing nothing about what any change means*. It is a WAL + atomic-install + keyed-serialization + snapshot engine that the stores plug into, dependency-inverted: M2 defines the fold (`WorldState::apply`), the engine implements it, and M2 only calls down through that trait. **One thing well: make the spec's single sequential, atomic-step order real and durable for a plural, concurrent world — over an opaque payload and opaque keys.**

It does **not**: compute addresses, frontiers, or coverage-classes (M1/M3/M7 supply keys and do the math — M2 has no address algebra); enforce store permanence P0–P3 or the J-couplings (the stores enforce those at their composite boundaries *through* M2, never by it — see ASN-0047); interpret record semantics; own the request lifecycle, the parse/dispatch table, or the acknowledgment-to-client (M10 — M2 keeps only the commit-gate *mechanism*); own derived hints (the stores do; M2 journals only authoritative deltas); or bundle a caller-separate *multi-step* (`m ≥ 2`) batch (`retract_stale`, a multi-step rule firing) into one atomic unit — it offers only the per-`transact` atomic unit, so a store honors A5's intended partial visibility by issuing the batch as *separate* `transact`s. Whether committing such a batch as *one* `transact` is a sound over-satisfaction of A5 turns on whether any *modeled read witnesses its interior*: for an **unwitnessed** batch — a **content run** (m × K.α), whose mid-batch states A5 itself classes as witnessed by no read the notes model — collapsing to one `transact` is harmless and is exactly how W2 contiguity is delivered (§4); for a **witnessed** batch — a link-store `retract_stale`, whose every interior `Nullify_Binary` *is* visible to an `Observe_K` over the active slice `A_K` (A5) — collapsing it *suppresses* that intended partial visibility, a real observable-behavior change, so the recommended default stays *separate* `transact`s and one-`transact` is **not** a free over-satisfaction. M2 neither forces nor forbids the granularity, but the store must choose by this witnessed/unwitnessed criterion (ASN-0134 A5's principle that a multi-step batch's atomicity is the caller's to build above the substrate, not the kernel's — a paraphrase, not a literal A5 clause). A *single-step* (`m = 1`) fire, by contrast, **is** one atomic `transact` — indivisible by A0, exactly the "atomic fires" M9 leans on — so only `m ≥ 2` fires are the A5 batches left above the substrate.

## Public interface

The kernel is `Kernel<W>` for an engine-supplied `W: WorldState`. Keys are opaque bytes; payloads are the engine's `Record` enum (`W::Record`). All write paths return only after their commit is installed and (under the durable mode) durable — commit-before-acknowledge. The **v1 concurrency realization is the single applier** (§8); the `transact`/`snapshot` method signatures and the `LockKey` seam are invariant across concurrency realizations, so the deferred per-key/CAS realizations slot in later as a pure internal change.

```rust
// ---- The engine's contract to M2 (dependency-inverted) ----
pub trait WorldState: Clone + Serialize + DeserializeOwned + Send + Sync + 'static {
    type Record: Serialize + DeserializeOwned + Clone + Send + Sync + 'static;
    /// The ONE deterministic, total, side-effect-free fold step — drives both live
    /// commit and replay. Folds authoritative deltas AND maintains every derived hint
    /// incrementally; a hint NOT folded here is stale after every live write and after
    /// replay (rebuild_derived runs only at load — see below). Deterministic so replay
    /// reproduces committed state exactly; NOT required to be idempotent — recovery
    /// applies each committed record exactly once (the checkpoint embodies Seq ≤ s,
    /// replay covers Seq > s; §6/§7).
    fn apply(&self, record: &Self::Record) -> Self;
    /// Seed derived hints from authoritative state. Runs ONCE at load, BEFORE replay,
    /// and NEVER on a live commit — so it cannot keep any hint current by itself.
    /// Incremental hint maintenance MUST live in `apply` (which runs on every live
    /// commit AND every replay step); `rebuild_derived` exists solely to reconstruct
    /// hints a checkpoint skip-serialized (`#[serde(skip)]`). Default identity (hints
    /// folded by `apply` and serialized in the checkpoint); override iff hints are skipped.
    ///
    /// CONSISTENCY OBLIGATION: an override MUST seed exactly the hint state that folding
    /// every record with Seq ≤ S through `apply` would produce (S = the loaded checkpoint's
    /// seq). Recovery runs `rebuild_derived` (to seed hints for Seq ≤ S) THEN replays
    /// Seq > S through `apply`; if this seed disagrees with the `apply`-fold of the ≤ S
    /// prefix it stands in for, the recovered hint diverges from the live-maintained one
    /// and reads go wrong. The two hint-maintenance paths must produce identical hints.
    fn rebuild_derived(self) -> Self { self }
}

/// Opaque serialization key — the documented serialization seam M3/M7 code against
/// (clauses 2/5/7). M2 only Eq/Hash/Ord-s the bytes (Ord is bytewise, NOT tumbler order;
/// the `derive` below supplies exactly those traits, dormant under the single applier — §4/§8).
/// Callers prefix a 1-byte space tag so distinct key spaces (e.g. (home,subspace) vs
/// coverage-class) never collide. These tags are drawn from a SINGLE CENTRAL ENUM defined in
/// M2's OWN crate (`skep-kernel`) — it names only `LockKey` and 1-byte constants, no store
/// types, so it sits BELOW every store (never the engine crate, which already depends on every
/// store and would thus CYCLE — §Dependencies & seams) — and never chosen per-store, which is
/// what guarantees CROSS-STORE uniqueness — without it two stores could both pick 0x01 and
/// silently alias M3's (home,subspace) keys with M7's class_keys. Under the single applier the
/// global lock subsumes the keys (§4); they remain the seam so a per-key realization slots in
/// without changing any caller's call shape.
#[derive(Clone, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct LockKey(pub Vec<u8>);

#[derive(Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Debug)]
pub struct Seq(pub u64);  // M2's per-record linearization coordinate; monotone always — gap-free
                          // under BurnedSeqPolicy::Rollback (the default), monotone-only under
                          // TolerateGap (§1/Invariants).
                          // Copy, so seq()/current_seq() return it by value (§ergonomics).
                          // A REFINEMENT of ASN-0134's 𝔼, not an identity, and no caller derives
                          // idx(σ) from it. §2 states the full correspondence ONCE — which records
                          // carry a Seq, the →_sh subsequence's isomorphism to the finest 𝔼, and the
                          // install-order mapping M2 presents for over-satisfied content runs.
```

**Config & errors** — the knobs the Open-build-decisions section selects; carried on `KernelCfg`.

```rust
pub struct KernelCfg {
    pub journal_path: PathBuf,        // directory for journal segments + checkpoints (the in-memory mode ignores it)
    pub durability: Durability,       // per-commit Fsync (the canonical durable-before-visible barrier, with its
                                      //   burned-Seq policy) | InMemory (no journal/barrier/recovery — MIC-faithful)
    pub checkpoint: CheckpointPolicy, // auto-checkpoint trigger, evaluated by an ON-COMMIT check inside transact (§6):
                                      //   EveryN(u64) commits | Interval(Duration) wall-clock-since-last |
                                      //   JournalBytes(u64) | Manual (no auto-trigger — caller drives checkpoint()).
                                      //   No background timer.
    pub retain_checkpoints: usize,    // N ≥ 1 most-recent checkpoints kept; the journal is reclaimed only BELOW the
                                      //   OLDEST retained one, so BadCheckpoint can fall back to an older retained
                                      //   base. N = 1 ⇒ newest is the sole base, no fallback (§6/§7).
}

pub enum Durability {
    Fsync { burned_seq: BurnedSeqPolicy }, // the ONE ordering — durable-before-visible (§1): append records → marker →
                                           //   barrier (one records+marker fsync) → install. burned_seq governs the
                                           //   durability-failure rollback (§1).
    InMemory,                              // fully in-memory: no journal, no barrier, no recovery (MIC-faithful —
                                           //   ASN-0134 is silent on durability; atomicity/isolation intact). checkpoint()
                                           //   and flush() are then no-ops (§6/Lifecycle).
}
pub enum BurnedSeqPolicy { Rollback, TolerateGap }  // gap-free (default) | monotone-only — durability-failure rollback (§1)
pub enum CheckpointPolicy { EveryN(u64), Interval(Duration), JournalBytes(u64), Manual }  // evaluated on-commit (§6); no timer thread

pub enum OpenError {
    Io(io::Error),
    BadCheckpoint,           // no retained checkpoint loads (each unreadable / failed its checksum) and genesis is
                             // unreachable (its covering journal reclaimed). Recovery internally falls back
                             // newest → next-older RETAINED checkpoint → genesis-while-reachable (§6/§7); this is
                             // returned only when that whole chain is exhausted.
    Corruption { at: Seq },  // A corrupt run whose INFERRED Seq MAX (= next-intact coordinate − 1, the CLASSIFIER;
                             // a record landing contributes its `seq`, a marker landing `last_seq + 1` — markers
                             // carry no Seq of their own; §7) falls in the GENUINELY-REPLAYED range (S_load, W] —
                             // W the last COMMITTED marker's seq (committed = intact + durable +
                             // records_checksum-valid; §1), derived in recovery's FIRST PASS (§7) — i.e. durable
                             // committed data the recovered state needs is corrupt; halt, never drop. `at` is only
                             // the PAYLOAD: the next-intact coordinate the magic-resync lands on (the run's own
                             // seqs are unreadable; at a marker landing, at = last_seq + 1). A run reaching EOF
                             // with no next intact frame classes as the tail (> W), so Corruption never carries an
                             // EOF payload (§7). Classifying by inferred MAX, not by `at`, keeps the boundary frame
                             // at `at = S_load + 1` HARMLESS (its run's max is S_load) rather than spuriously
                             // fatal. A run whose inferred max is ≤ S_load is NOT fatal — skipped (already
                             // embodied in the loaded checkpoint, discarded by the Seq > S_load filter); one whose
                             // max is beyond W is the un-acked / torn tail, discarded, not corruption (§7).
}
pub enum CheckpointError { Io(io::Error), Serialize, Poisoned }  // Poisoned: a prior barrier/truncation failure has
                             // halted the kernel (§1); no further checkpoint is taken.
```

**Lifecycle**

```rust
impl<W: WorldState> Kernel<W> {
    /// Recover (load the latest valid RETAINED checkpoint @S_load — on BadCheckpoint fall
    /// back to the next-older retained checkpoint, then to genesis while still reachable
    /// (§6/§7) → rebuild_derived → replay committed records with `S_load < Seq ≤ W`, where W
    /// is derived in recovery's FIRST PASS as the last COMMITTED marker's `last_seq`
    /// (committed = intact, durable, records_checksum-valid; §7); if no committed marker sits
    /// above S_load, W = S_load and replay folds nothing) or init from `genesis`
    /// (= Σ₀, with S_load = 0). Records present on disk beyond W are an un-acked / torn tail
    /// (no committed marker) and are discarded. Under `Durability::InMemory` there is no journal
    /// or checkpoint: `open()` IGNORES `journal_path`, runs no recovery, and initializes the
    /// root directly from `genesis` (S_load = 0).
    ///
    /// CALLER CONTRACT — `genesis` (= Σ₀) MUST be byte-identical on every `open()` of a given
    /// journal: recovery folds journaled DELTAS onto it (at first init, and on the BadCheckpoint
    /// fallback to genesis), NEVER onto a journaled root, so a `genesis` that drifts between opens
    /// silently mis-recovers (correct deltas land on the wrong base). M2 cannot check this; ASN-0047's
    /// fixed Σ₀ (n₀ = [1]; C₀ = L₀ = R₀ = ∅) satisfies it by construction (§7).
    pub fn open(cfg: KernelCfg, genesis: W) -> Result<Self, OpenError>;
    /// Persist a checkpoint embodying all records with `Seq ≤ s`, keep the most recent
    /// `retain_checkpoints` checkpoints, and reclaim journal segments lying wholly BELOW the
    /// OLDEST retained checkpoint (segment-granular — §6); recovery then replays exactly the
    /// records above whichever retained checkpoint it loads. Non-blocking to writers (it grabs
    /// a lock-free `Snapshot` and never takes the applier lock) and SERIALIZED AGAINST ITSELF by
    /// a dedicated checkpoint mutex (distinct from the applier lock — §6), so concurrent
    /// `checkpoint()` calls and the on-commit auto-trigger never race on the retention set or
    /// segment deletion. Cadence is governed by `cfg.checkpoint`: M2 evaluates that policy as an
    /// ON-COMMIT check inside `transact` and auto-runs `checkpoint()` when it is crossed
    /// (`Manual` disables the auto-trigger, leaving cadence to the caller's own loop — §6; there
    /// is no background timer; the trigger counters live in `transact`'s applier-locked state and
    /// are reset there, so `checkpoint()` itself never reads or resets them — §6). Returns the
    /// checkpointed seq `s`, or `CheckpointError::Poisoned` if a prior barrier failure has halted
    /// the kernel (§1). Under the in-memory durability mode (Durability::InMemory — no journal) it
    /// is a NO-OP returning `current_seq()` — nothing to persist or reclaim.
    pub fn checkpoint(&self) -> Result<Seq, CheckpointError>;
    /// Shutdown/checkpoint hook. Under per-commit `Fsync` every commit already fsyncs its
    /// records+marker barrier, so there is nothing pending and this is a no-op returning
    /// `Ok(())`; under the in-memory mode it is likewise a no-op. Retained as the slot-in
    /// point for the deferred group-commit (`FsyncBatch`) durability mode (Open build
    /// decisions), where it would flush the pending batch and advance the Clean watermark, so
    /// the API is invariant across durability modes. On a POISONED kernel it is a no-op
    /// returning `Ok`.
    pub fn flush(&self) -> Result<(), io::Error>;
}
```

**Writes (transactions / composites)** — discharge clauses 1, 2, 3, 5, 7.

```rust
impl<W: WorldState> Kernel<W> {
    /// Hold `keys` for the txn's duration, run `f` against a consistent base state, and —
    /// iff `f` returns Ok with ≥1 staged record — commit them atomically & durably under
    /// one commit marker, INSTALL the root, then return (A7). Returns `(T, Seq)`: the
    /// closure's value and the committed `last_seq` — a write's V1 retrospective coordinate
    /// (exact, unlike a post-hoc `current_seq()`).
    /// `f` returning Err → clean typed rejection, nothing committed, no dangling state.
    /// `f` returning Ok with zero records → zero-step op (A1: read-only / idem-hit /
    /// nullify-hit), no commit; the returned Seq is then the base `Committed`'s `seq` — the
    /// committed index the op evaluated against (V1). (`transact` retains the `Committed` it
    /// loaded via `root.load()` at txn start for exactly this `seq`; `Staging::base()` exposes
    /// only that `Committed`'s `&W`, which has no `seq()` — the two `base`s are distinct.)
    /// Under per-commit `Fsync` that base root is durable, so a zero-step op never waits.
    ///
    /// NON-REENTRANT: `f` MUST NOT call `transact` (or any kernel write path) — the applier
    /// lock / install serialization point is held, so a nested write DEADLOCKS. A composite
    /// composes neighbors' PURE math (e.g. M3's `recompute_max`/`inc` against `stg.working()`)
    /// inside ONE closure, never a transaction-within-a-transaction (§3).
    pub fn transact<T, E>(
        &self,
        keys: &[LockKey],
        f: impl FnOnce(&mut Staging<W>) -> Result<T, E>,
    ) -> Result<(T, Seq), TxnError<E>>;
}

pub struct Staging<W: WorldState> { /* base, working, records */ }
impl<W: WorldState> Staging<W> {
    pub fn base(&self) -> &W;            // Σ — the installed root at txn start
    pub fn working(&self) -> &W;         // Σᵢ — base folded with records so far (intra-composite checks)
    pub fn push(&mut self, r: W::Record); // fold into working, append to the txn's records
}

pub enum TxnError<E> {
    Rejected(E),            // f's typed precondition failure — surfaced verbatim to M10
    Durability(io::Error),  // the per-commit barrier (the single records+marker fsync) failed BEFORE install AND the
                            // txn's un-acked record+marker tail was durably truncated (Seqs burned per BurnedSeqPolicy),
                            // so nothing was installed and no durable marker survives → a TRUE no-op; caller may safely
                            // re-invoke. If the truncation ITSELF fails to complete durably the kernel POISONS and the
                            // call returns `Poisoned` INSTEAD — a surviving un-acked marker would let a successor collide
                            // on recovery (Seq reuse under Rollback, or a stale recorded deposit under TolerateGap; §1/§7).
    Poisoned,               // the kernel was halted by a prior UNRECOVERABLE failure (§1): a durability-failure
                            // truncation that itself failed to complete durably. Returned by the poisoning call ITSELF
                            // (in place of Durability) and by every later transact; reads (snapshot/current_seq) keep
                            // serving the last consistent root.
}
```

## Core data model

The **only durable, authoritative state M2 owns is the journal.** Everything in memory is a recoverable fold of it (Lampson: the log is the truth; in-memory structures are hints). Within the recovered `World`, the *store-level* distinction between authoritative slices (C, L, E, M, R) and derived hints (spanfilade, reverse indexes) belongs to M4/M5/M7 — to M2 the whole `World` is one fold.

| Structure | Shape | Authority | Why this shape |
|---|---|---|---|
| **Journal** | append-only segment file(s) — each carrying its `[firstSeq, lastSeq]` range (§1) — of magic-anchored, CRC-framed records + per-txn commit markers, every frame `txn`-tagged (so recovery groups a transaction's records to validate its marker's checksum even after a `magic`-resync skips a corrupt frame — §1/§7) | **authoritative, durable** | record-of-record; replay reconstructs everything; append-only makes immutability of committed steps free (ASN-0047 P0/P1/P2 at the log level); the per-frame magic word anchors recovery resync (§1/§7); **in v1 a committed marker (intact, durable, `records_checksum`-valid) *is* the commit ack** — in-order append + prefix-flushing fsync make a committed marker's presence at recovery == durably-committed (§1/§7) |
| **Root** | `arc_swap::ArcSwap<Committed<W>>`, `Committed { seq: Seq, world: W }` | recoverable materialization | lock-free reads; **atomic install = atomic, indivisible step (A0/A4)**; persistent `W` (im) ⇒ snapshot & install are O(1) and snapshots never tear |
| **Checkpoint** | serialized `W` @ `Seq` on disk (temp→fsync→rename, checksummed — §6), most recent `retain_checkpoints` kept | recoverable cache (a prefix-fold) | bounds replay time; optional; the oldest retained one is the journal-reclamation floor and the `BadCheckpoint` fallback base (§6); writing it + reclaiming the journal is serialized by a dedicated **checkpoint mutex** (separate from the applier lock, so writers never block — §6) |
| **Sequencer** | a single `Seq` high-water + the install serialization point (the applier `Mutex`) — **no separate `Txn` counter** (`Txn` is a transaction's first `Seq`) | volatile, recovered as `W` (the last committed marker's `last_seq` — §7), which restores `Txn` freshness for free | assigns the total order; **serializes journal-append + install** (`current_seq()` reports the installed *root*'s seq — §5) |

`W` is the engine's composition of all store slices, each an `im` persistent collection (`OrdMap` for address-keyed stores — gives prefix-range scans free — `HashMap`/`Vector` elsewhere). `W: Clone` is O(1) (Arc bumps); `W::apply` returns a structurally-shared successor touching only changed paths. This persistent-immutable representation is the **design's own mechanism, not an ASN-0134 mandate** — the note fixes the single-state and reader-snapshot *obligations* (A3, V0, V2; MIC-4/6) and flags clause 6's global-exclusion cost, but recommends no data structure — chosen because the root's identity *is* the version coordinate, making clauses 1/4/6 nearly free.

`Snapshot<W>` is the newtype `Snapshot<W>(Arc<Committed<W>>)` (not a bare `Arc`, so it can carry the inherent `seq()`/`world()` the orphan rule would forbid on `Arc` — §Public interface) — a cheap, pinned, consistent view carrying its own `seq` (so verdicts can be reported as retrospective statements about `Σ_r`, V1).

## Internal design

### 1. The journal & WAL discipline

**Frames.** `[u32 magic][u32 len][u32 crc][payload]`, where the fixed `magic` sync word anchors frame starts for recovery resynchronization (§7) and `crc` covers **both the `len` field and the `payload`** (so a corrupt length is *detected* rather than silently mis-delimiting the following frame). After a CRC failure the recovery scan (§7) seeks forward for the next `magic`, takes that as a candidate frame start, and accepts it only if it is **intact** — its `crc` validates over its framed `len`+payload; a `magic` that occurs by coincidence inside a payload fails this check and the scan continues. Payload is one of `LogRecord{ seq: Seq, txn: Txn, bytes }` (where `bytes` is the serialized `W::Record` — the frame struct is named `LogRecord` so it does not collide with the trait's `W::Record` enum) or `Marker{ txn: Txn, last_seq: Seq, records_checksum }` (`records_checksum` checksums the txn's *record frames* — distinct from the marker's own per-frame `crc`). **v1 has no separate ack record:** the marker, once committed, *is* the commit ack (below); the deferred group-commit mode (`FsyncBatch`, Open build decisions) reintroduces a `Clean{ through: Seq }` record to batch the ack across markers. Here **`Txn` is the transaction's *first* `Seq`** — `Txn(pub Seq)`, *not* a separate per-kernel counter: it is the `Seq` assigned to the transaction's first record, tagging every frame of that transaction (records and marker alike). Deriving the txn id from the first `Seq` rather than a standalone counter makes it **unique within any scanned journal region and recovered for free with the single `Seq` high-water** (§7) — because `Seq`s are globally monotone and continue across a crash/restart, no two transactions ever share a `txn`, *including across sessions*. (A standalone per-kernel counter, by contrast, resets on restart and reuses ids while `Seq`s march on, so a post-crash replay of a range spanning two sessions would merge two distinct transactions under one `txn` and fail the later marker's `records_checksum` — silently losing committed data or raising a spurious `Corruption` halt; the first-`Seq` derivation, *plus recovery restoring the single `Seq` high-water* (§7), forecloses that.) **Frames are matched to their marker by `txn`, not by file position:** recovery groups a transaction's record frames by their `txn` to validate that transaction's `records_checksum` — which is precisely what lets validation survive a `magic`-resync that skipped a corrupt frame, since file-contiguity ("the frames between the previous marker and this one") can no longer be trusted once a frame has been skipped (§7).

**Segments.** The journal is a sequence of append-only segment files; **each segment records its `Seq` range** — named by its `firstSeq` (or carrying a small header recording `[firstSeq, lastSeq]`) — so recovery can skip a whole segment whose `lastSeq ≤ S_load` without opening it (§7) and reclamation can drop a whole segment whose `lastSeq ≤ S_old` (§6), both by the recorded range alone. A segment that *straddles* a boundary is kept/opened whole; the `Seq`-filtered fold (§6/§7) handles whatever survives. (Segment-rotation must preserve the marker-as-ack property across the boundary — the rotation discipline of the Open build decisions.)

*(Canonical statement — §3, §7, Invariants & contracts, Conflicts #3, and Open build decisions cross-reference the commit-ack / barrier-failure discipline stated in the next two paragraphs rather than restating it.)* **The marker is the recovery contract — and in v1 the marker's own durability is its ack.** Two predicates, kept terminologically apart for the recovery classification (§7): a frame is **intact** iff its own per-frame `crc` validates; a marker is **committed** iff it is intact, durable (present at recovery — by definition on the disk recovery reads), **and** its `records_checksum` validates over the txn's records. A txn is committed iff its marker is. An *intact* marker whose `records_checksum` *fails* (a torn or bit-rotted txn) is **not** committed. There is **no separate clean-watermark conjunct in v1**: the only durable realization (the single applier) appends frames **in `Seq` order**, and fsync is **prefix-flushing** (it flushes the whole journal prefix), so a committed marker implies every earlier frame is durable too. A committed marker's presence at recovery therefore *equals* durably-committed, and recovery trusts an intact, `records_checksum`-valid marker directly. *(This holds within a journal segment; preserving it across a segment rotation requires the old segment durable before the new one is appended — the segment-rotation discipline of the Open build decisions.)* (The deferred `FsyncBatch` group-commit *does* need a separate watermark: one batched fsync there acks many markers, so marker-presence no longer implies durability and recovery must again bound trust by the highest durable `Clean{through}` = W; that is a `FsyncBatch` concern, not v1.) **W** — used below to classify recovery regions — is in v1 simply *the `last_seq` of the last committed marker* (the end of the committed prefix; derived by the recovery scan, §7), not a value read from any record.

**Commit ordering: durable-before-visible (per-commit `Fsync`).** This is the single applier's **one** ordering — there is no visible-before-durable alternative in v1 (the per-key/CAS realizations that would force install-before-barrier are deferred — §8). A txn commits in this order — *append records → append commit marker (terminal record frame) → durability barrier (ONE fsync of records+marker) → atomic install of the root → return `(v, last_seq)`*. Two properties, both load-bearing for sound failure handling:

- **A marker counts as committed iff its own barrier made it durable and its `records_checksum` validates** (and, read back at recovery, it is intact — §7). Nothing promotes a marker but its own durable landing. This closes the **phantom-commit hole** *via the truncate-and-poison discipline below*, not via a watermark: a barrier failure either removes the marker (truncate) or halts the kernel (poison), so no operation reported *cleanly failed* ever leaves a durable marker behind for a successor to race, and a same-`(d,S)` retried successor never double-deposits a colliding address.
- **Barrier failure is a true no-op — *conditional on the un-acked-tail truncation succeeding*.** If the durability barrier fails, the txn's record+marker frames are truncated (durably) from the journal tail, and the root is *not* installed — so no committed state and no durable marker reflect the txn. `transact` returns `TxnError::Durability` and the caller may safely re-invoke. The Seqs the txn had been assigned are **burned**; under `BurnedSeqPolicy::Rollback` (default) the serializer rolls the `Seq` high-water back to the last committed marker's `last_seq` before releasing, preserving the gap-free invariant (the alternative — `TolerateGap`, relaxing the invariant to monotone-only — is the open knob). **This no-op guarantee, and the truncate-then-reuse it permits, rests on the truncation *itself* completing durably.** If the truncation (or its fsync) fails, the failed records+marker survive on disk as a committed marker. Were the kernel to continue, a successor would collide on recovery: under `Rollback` it reuses the burned Seqs, so two frames carry the same `Seq` (a direct journal collision, and for a same-`(d,S)` allocation a colliding address); under `TolerateGap` it does not reuse them, but on recovery the surviving marker replays *first* (in `Seq` order) and advances the home's frontier *under* the successor's already-computed deposit, colliding the address. Either is the exact corruption this ordering exists to prevent. Therefore: **if the un-acked-tail truncation fails to durably complete, the kernel must poison (halt; subsequent calls fail), and the poisoning `transact` returns `TxnError::Poisoned`, *not* `TxnError::Durability` as a safe no-op.** The poison applies regardless of burned-Seq policy (the surviving marker is dangerous under either policy, as just shown). Poison halts the kernel so *no successor runs*; the surviving marker is then at most the journal tail. **No on-disk sentinel is needed for recovery:** on the next `open()`, that surviving marker — durable and intact — is, if its records also check out, simply the last committed marker (recovery replays it: a lost-ack / indeterminate outcome, correct per ASN-0134 SAFE(b)(iii) — the caller received `Poisoned`, never a clean failure) or, if torn (`records_checksum` fails), the discarded tail (§7). (Where the disk failure is so severe that even the *prior* committed state's durability is in doubt, the kernel stays poisoned in-memory and refuses further writes, the best it can do.)

**Only authoritative deltas are journaled.** Derived hints are *never* journaled — they are reconstructed by `apply` during replay (mandatory incremental maintenance — §6/§7), and seeded once at load by `rebuild_derived` if the checkpoint skip-serialized them. This is the structural answer to ASN-0134's divergence hazard (decision #10, multi-store atomicity): one logical step is exactly one journal record driving one `apply`, so there is nothing to diverge.

The durability config selects per-commit `Fsync` (the ordering above) vs `InMemory` (the fully in-memory realization — **MIC-faithful**, ASN-0134 being silent on durability — no journal, no barrier, no recovery; atomicity/isolation intact).

### 2. Sequencer & the linearization point

Each committed record receives the next `Seq` from a monotone counter, assigned inside the serialization point so the order is gap-free and a composite's records are **Seq-contiguous** (no foreign record interleaves a composite). Under the single applier this serialization point is also the journal-append point, so **file order == `Seq` order**. **`Seq` refines ASN-0134's `idx(σ)`, it is not identical to it:** every `→_sh` step (the ASN-0128 trio `K.σ`/`K.α`/`K.λ_sh`) receives a `Seq`, but so do the non-`→_sh` records a composite stages (`K.μ⁺`/`K.μ⁻`/`K.ρ`) **and the further ASN-0047 records M2 journals that the `→_sh` trio does not enumerate** — `K.δ` for node/account creation, `K.μ⁺_L` link-subspace extension. The two lists are *illustrative*, not the whole record vocabulary, and `K.δ`-for-documents is exactly ASN-0134's `K.σ`. **The link step is one operation at two layers, not two records:** ASN-0128's gated emission `K.λ_sh` (in the trio) *is* gate-check-then-`K.λ`-allocation, so the trio already enumerates the link allocation — as `K.λ_sh` — and the only thing journaled is its deposit, the single ASN-0047 record `K.λ` (`LinkRec::Emit`); a gated *operation* `K.λ_sh` ⇒ one allocation *record* `K.λ`, so no builder should infer a distinct second link-allocation record. **M2 acts on no record's `→_sh` classification** — it assigns a `Seq`, journals, and folds every record uniformly — so the partition is *descriptive* (it explains the correspondences below, nothing M2 branches on).

**Which `𝔼` the correspondence is against matters, because M2 over-satisfies clause 5 for content runs.** The subsequence of `Seq`s carrying `→_sh` records is order-isomorphic to the **finest** `𝔼` — the one whose atomic steps are the *individual* `K.σ`/`K.α`/`K.λ_sh` (the per-atom granularity at which ASN-0134 clause 5 reasons about a run); against *that* `𝔼` a `→_sh` record's `Seq` *corresponds positionally* to its `idx(σ)`, **not equal** to it (the counter has also advanced on the interleaved non-`→_sh` records). But for a multi-atom **content run** M2 *over-satisfies* clause 5 by collapsing the run's m × `K.α` into **one** externally-observable atomic install (§4), thereby *presenting* to readers the coarser **over-satisfy `𝔼`** in which the whole run is a single step — and against the `𝔼` M2 actually presents for runs it is the **install order** (one install per run), **not** the interior `→_sh` `Seq` order, that is order-isomorphic, the m interior Seqs being a *refinement* of that one presented step rather than an isomorphism with it. M2's full `Seq` order is finer still. Both build and V1 reporting key off the install coordinate (below), so the distinction never bites a caller; no caller derives `idx(σ)` from `Seq`.

A `→_sh` record's `Seq` assignment is its linearization point (A2); one `transact` = one operation = one linearization point (single-step op) or one contiguous composite boundary. **The interior `Seq` and the externally-observable coordinate must be kept apart.** For a *single-record* op the returned `Seq` is that record's own `Seq` and is its linearization point — directly observable. For a *multi-record composite*, the interior `→_sh` record's `Seq` (e.g. the K.α inside an INSERT) is **M2-internal and not separately observable**: the composite installs atomically at one boundary, so A2's "entire effect is one transition" maps to that single atomic install, never to the interior step. The coordinate `transact` returns is therefore the composite's terminal `last_seq` (the K.ρ, say) — the one boundary at which the whole composite becomes visible — and that, not the interior K.α `Seq`, is the V1 referent a caller reports against. M2 fixes both; M10 merely chooses to call `transact` once per operation. (`current_seq()` reports the installed *root*'s seq, not the in-flight high-water — §5.) Seq-contiguity is a property of M2's *internal* order; it is *not* what delivers W2 chain contiguity — that comes from holding `key(d,s_C)` across the run, which under the single applier is subsumed by the global lock serializing every write (§4).

### 3. The transaction / composite boundary

`transact(keys, f)` — the per-commit flow (durable-before-visible, the one ordering):

```
lock the applier (single global serializer)    // subsumes `keys` — serializes ALL writes (clauses 2/5/7); §4
base ← root.load()                             // the installed durable root
stg  ← Staging::new(base)
match f(&mut stg) {                            // store logic; f MUST NOT call transact (#NR — deadlock)
    Err(e)             → release applier lock; return Rejected(e)        // clean rejection; nothing journaled
    Ok(v) if stg empty → release applier lock; return Ok((v, base.seq()))  // zero-step (A1); V1 = base.seq()
    Ok(v) ⇒
        seqs ← alloc_seqs(stg.records.len())                       // linearization (burned+rolled back on failure)
        txn  ← Txn(seqs[0]); last_seq ← seqs.last()                // txn id = FIRST Seq (unique, recovered §1/§7)
        journal.append_records(txn, seqs, stg.records)            // PER-TXN, under applier lock
        journal.append_marker(txn, last_seq, records_checksum)    // PER-TXN — commit marker, terminal frame

        durability.barrier()                   // ONE fsync of records+marker; a committed marker IS the ack (§1)
            on Err → if truncate(seqs) durable: rollback_seq_hi(burned_seq); release; return Durability   // TRUE no-op
                     else: poison; release; return Poisoned       // surviving marker would let a successor collide (§1)
        root.store(Committed{ last_seq, stg.working })            // ATOMIC INSTALL, AFTER durability
        if checkpoint-trigger crossed: reset trigger counters    // §6 — UNDER the applier lock (no race with checkpoint())
        release applier lock
        if crossed: checkpoint()                                 // §6 — AFTER release, under the SEPARATE checkpoint mutex;
                                                                 //   its CheckpointError is logged+dropped (§6), never
                                                                 //   failing the already-committed txn
        return Ok((v, last_seq))                                  // commit-before-acknowledge (A7)
}
```

The barrier (the single records+marker fsync) and the subsequent install both sit *inside* the applier-locked region — the single applier runs on one core, so there is nothing to gain by releasing the lock, and the whole append→barrier→install→return sequence is serialized through the one point the Sequencer row promises. `base` is therefore always the installed durable root; there is no in-memory working tip and no wait. The barrier-failure handling (truncate-tail + Seq-rollback, or poison) is exactly the canonical-ordering bullets of §1. On a successful commit the committing thread evaluates the §6 on-commit checkpoint-trigger (`cfg.checkpoint`) **while still holding the applier lock**, and if its threshold is crossed **resets the trigger counters under that same lock**; it then releases the applier lock and, only afterward, performs `checkpoint()` under the *separate* checkpoint mutex, blocking only this one caller while every other writer proceeds (so the counter increment, the threshold test, and the reset all sit under the applier lock, never racing `checkpoint()` — §6). A `CheckpointError` from that auto-triggered call is **logged and dropped**: the transaction is already committed, durable, and installed, so there is no sound path for the error through `TxnError` — failing the return would un-acknowledge a real effect. Dropping it is safe by §6's own crash argument: a failed checkpoint leaves at most an ignored `.tmp` and an unreclaimed journal, and the next recovery simply replays more.

**Composites are one closure, not nested transactions.** A composite (M5's placement, e.g. K.α + K.μ⁺ + K.ρ — a span of m content atoms is m such `K.α`) is a *single* `transact` whose `f` stages each step's record and, where a step needs a neighbor's address math, calls that neighbor's **pure** function against the relevant *slice* of the staging view — reached through the store's `HasX` accessor, never the bare `&W`: **`stg.working().x()` for any frontier/allocation math** (the slice reflects the records already pushed in this same closure — equal to `stg.base().x()` only before the first push), `stg.base().x()` for the txn-start state. E.g. M5's content `K.α` reads the content frontier off **`stg.working().content()`** (via `HasContent`) and applies M1's `inc`, *inside this one closure*, so each atom of a multi-atom run mints at the frontier slot left by the prior atom (against the unchanging `base().content()` every atom would recompute the same max and *collide*; §4, M5 seam). It must **never** invoke a neighbor's allocation `transact` from within `f`: `transact` is non-reentrant (the applier lock is held), so a nested call deadlocks. The standalone seam examples (Dependencies & seams) show a *bare* allocation as its own `transact`; when that allocation is one step of a larger composite, the caller lifts its *pure* body into the composite's closure, not the transaction. (This is exactly what the *pure composable step surface* contract — Dependencies & seams (3) — exists to guarantee.)

`Staging.working` (= `base` folded with staged records, cheap over persistent `W`) is what lets the store check **intra-composite preconditions** at intermediate states (ASN-0047's "observable intermediate states," e.g. checking `K.μ⁺`'s own precondition `a ∈ dom(C)` — satisfied by the prior K.α — at the post-K.α/pre-K.μ⁺ intermediate; S3★ referential integrity is *not* the check here, holding *vacuously* at that intermediate since no V-position yet binds the new content `a`). Those intermediates are visible only to the executing closure — **never to external readers**, who see only the single atomic install. The J-couplings the closure may check at the boundary (`base`→`working`) are M5's to assert; M2 never does.

Install follows durability, so `TxnError::Durability` is a sound true no-op under §1's truncate-or-poison discipline (a failed truncation poisons instead, returning `Poisoned`, and recovery's scan finds any surviving marker only as the journal tail — §1/§7).

### 4. Keyed critical sections

One mechanism serves clauses 2, 5, 7; the key is always caller-supplied bytes — the documented serialization seam M3/M7 code against. **Under the single applier the global applier lock subsumes the keys:** because every write runs to completion under that one lock, all same-key (indeed all cross-key) writes are already serialized, so **read-decide-deposit is atomic for any keys by construction** — exactly what clause 7's idem dedup needs (the dedup-read of the global active set and the deposit are one action under the coverage-class key; cf. G2) and what clause 2 needs (frontier-read-and-deposit under the `(home,subspace)` key — the calling store does the `inc(max,·)` math over its population; M2 only serializes). The `keys` argument is therefore the **seam, not a live lock table in v1**: M3/M7 pass the keys they would need under a per-key realization, so the deferred per-key concurrency (§8, Open build decisions) slots in as a pure internal change without altering any caller's call shape.

**Run contiguity (W2) is delivered by committing a multi-atom content run inside one `transact([key(d,s_C)], …)`.** Under the single applier the whole run commits as one serialized, atomically-installed step, so no foreign `s_C`-allocation to `d` can interleave between the run's first and last atom — *that* is W2 (chain/address contiguity) — and no reader lands mid-run, *additionally* over-satisfying clause 5. **Within the run, each `K.α` must mint against `stg.working().content()`, not `stg.base().content()`** (§3): `working().content()` reflects the atoms already pushed, so the run deposits at consecutive frontier slots `φ, φ+1, …, φ+m−1`; reading the *unchanging* `base().content()` max for every atom would compute one address m times — a collision, not a contiguous block, and the `working().content()`-checked freshness precondition (`a ∉ dom(C)`) would then reject the second atom, so the whole multi-atom INSERT could never commit. (Equivalently, a batch allocator may hand back m consecutive addresses from one `base().content()` read plus the count m.) Seq-contiguity (§2) is a distinct, internal property and is not the source of W2.

The reader-visible-mid-run flavor of clause 5 (a run committed as *separate* inner commits with readers landing between them) is **not realizable under the single applier**, which serializes every write; it belongs to the deferred per-key realization (§8). In v1 **a run is simply one `transact`** (atomic, satisfying clause 5 by over-satisfaction).

### 5. Snapshot reads

`snapshot()` is one lock-free `ArcSwap::load_full` — an *owned* `Arc<Committed<W>>` (not `load`'s borrowed `Guard`, since the returned `Snapshot` outlives the call) — wrapped in the `Snapshot<W>` newtype. It is **infallible and stays available even on a poisoned kernel** — the poison path (§1) leaves the in-memory root a consistent committed state — so reads keep serving while writes/checkpoints fail with `Poisoned`. Per-call single-state (clause 4 / A3 / V0) is by construction. A multi-read verdict reads all `p` constituents off **one** `Snapshot` → clause 6 / V2 for free (persistent state dissolves the "global" cost ASN-0134 flags). This is the seam contract on M6/M8/M9: thread one `Snapshot` through every constituent of a verdict; do not issue them as separate `snapshot()` calls (the §8 pathology).

`current_seq()` returns the **currently installed root's seq** — equal, *at the instant of the call*, to a `snapshot()` taken at that same instant, but **not** a substitute for it across calls. Install is serialized through the single applier's lock, so this coordinate **never regresses**; it is a sound standalone "latest committed index" progress indicator. It is **not** the stamp for a verdict. A verdict's V1 coordinate is always `s.seq()` for the single `Snapshot s` its constituents were read off — and that is *not* interchangeable with a later `current_seq()`: a write can land between the `snapshot()` and the later `current_seq()`, so stamping a snapshot-computed verdict with `current_seq()` would assert it of a *later* committed state than it was actually read against, a V1 violation. So: read every verdict constituent off one `Snapshot`, and stamp the verdict with *that* `Snapshot`'s `seq()` (a retrospective statement about the real committed `Σ_r` it was read from — V1); reserve `current_seq()` for a bare "where is the log now?" query. (A write reports its own coordinate from the `last_seq` that `transact` returns — exact — never from a post-hoc `current_seq()`.)

### 6. Checkpoint & truncation

**The operation, and its self-serialization.** `checkpoint()` is **serialized against itself by a dedicated checkpoint mutex** — held for the whole persist+reclaim operation, *distinct from the applier lock* so it never blocks writers — because the API permits concurrent calls (an explicit caller call racing the on-commit auto-trigger below, or two callers), and that mutex is what keeps the retention-set update and segment deletion single-threaded. The body is otherwise non-blocking: grab a `Snapshot` `Committed{ seq: S, world }` (lock-free) — `world` is the fold of **exactly the records with `Seq ≤ S`**, and `S` is always a committed marker boundary (installs are atomic at commit). Serialize `world()` (authoritative; hints may `#[serde(skip)]`) to `checkpoint.tmp` **with a checksum over the serialized `W` bytes carried in the file's header**, fsync, atomic-rename to `checkpoint.<S>`, fsync dir. **That checksum is what load validates before trusting a base** — the check `OpenError::BadCheckpoint`'s "failed its checksum" names (§7): serde deserialization alone does not reliably detect bit-rot, and a silently-wrong checkpoint base would defeat the fallback chain, so the write path must supply what the read path checks.

**Auto-trigger (a fixed on-commit mechanism, not an open one).** `cfg.checkpoint` is evaluated by an **on-commit check inside `transact`'s post-install step** — the only moment new committed state appears. M2 keeps three counters **inside `transact`'s applier-locked state** — commits-since, journal-bytes-since, and wall-clock-of-last-checkpoint — advanced (and read) only under the applier lock. After a successful install, **still under the applier lock**, the applier compares them against the policy — `EveryN(n)`: commits-since ≥ n; `JournalBytes(b)`: bytes-since ≥ b; `Interval(d)`: now − last ≥ d; `Manual`: never — and, if crossed, **resets all three counters then and there (under the same applier lock)**, *then* releases the lock and **runs `checkpoint()` on the committing thread** (holding only the checkpoint mutex), so the one triggering `transact` pays the checkpoint's cost while every *other* writer proceeds unblocked; its `CheckpointError` is **logged and dropped, never surfaced through the already-committed `transact`** (§3 — a failed checkpoint leaves at most an ignored `.tmp` and an unreclaimed journal, the crash argument below). **The increment, the threshold test, and the reset all happen under the applier lock, and `checkpoint()` never reads or resets these counters** — so the trigger state never races against `checkpoint()` (which holds only the disjoint checkpoint mutex). A consequence to accept deliberately: a *caller-invoked* `checkpoint()` does **not** re-zero the cadence counters (it cannot touch them), so it does not reset the auto-trigger's progress — at worst a benign cadence imprecision, traded for a counter discipline with no data race. Evaluating `Interval` on-commit (rather than from a background timer) is deliberate: a kernel with no commits has nothing new to persist, so *not* firing while quiescent is correct, and it spares the kernel a timer thread and its shutdown coordination entirely. A zero-step op installs nothing, so it never advances a counter or trips the trigger. (Under `Durability::InMemory` the trigger still evaluates but `checkpoint()` is a no-op.)

**Retention & reclamation.** The kernel keeps the most recent `retain_checkpoints` (N ≥ 1) checkpoints; let `S_old` be the seq of the **oldest** retained one. Reclaim journal space only by **dropping whole journal segments all of whose frames have `Seq ≤ S_old`** (identified by the segment's recorded `[firstSeq, lastSeq]` range — §1, so the `Seq ≤ S_old` test needs no scan of the segment's contents) — *segment-granular* truncation, not an exact per-frame guarantee: a segment that *straddles* `S_old` is kept whole, so some `Seq ≤ S_old` frames may survive on disk. **Tying reclamation to the *oldest* retained checkpoint (not the just-written `S`) is what makes `BadCheckpoint`'s fallback real** — the journal back to `S_old` survives, so a corrupt newest checkpoint falls back to an older retained one (or to genesis only while nothing below it has yet been reclaimed — concretely, while the earliest surviving segment's `firstSeq` is still the first assigned `Seq`, §7) and replays from there (§7); with `N = 1`, `S_old = S`, the newest checkpoint is the **sole** recovery base, there is no fallback, and the write should be made redundant/verified. Truncation is therefore a space-reclamation optimization, **not** a correctness mechanism; correctness rests entirely on recovery (§7) replaying, from whichever checkpoint @`S_load` it loads, **exactly `S_load < Seq ≤ W`** (W the last committed marker's `last_seq`, §7) — its `Seq > S_load` filter discards any surviving `≤ S_load` frames *regardless of their integrity* (a corrupt `≤ S_load` frame is irrelevant — its effect is already in the loaded `world`). Each checkpoint @X thus *embodies* `Seq ≤ X`, and recovery from it replays *exactly the complement* `X < Seq ≤ W` — no overlap, no gap. This complementarity, enforced by that filter over a coarse segment-granular truncation, is essential because `apply` is **not** idempotent (a `Vector`-append record double-applies wrongly): every committed record must be folded into the recovered state exactly once. Writers run throughout — the snapshot's Arc keeps the checkpointed version alive while live installs advance the root. Crash mid-checkpoint leaves an ignored `.tmp` and an unreclaimed journal: always safe (the next recovery just replays more, the filter still bounding it to `S_load < Seq ≤ W`). **Cadence policy** (every-N / time / size — its *mechanism* fixed as the on-commit trigger above), **retention `N`**, and representation (full-World vs per-store/incremental) are open knobs.

Under the in-memory durability mode (`Durability::InMemory`) there is no journal: `checkpoint()` is a no-op returning `current_seq()` (nothing to persist or reclaim), and the in-memory realization simply has no recovery story to bound.

### 7. Recovery

**In-memory mode short-circuits recovery.** Under `Durability::InMemory` there is no journal or checkpoint: `open()` ignores `journal_path`, runs neither pass below, and initializes the root directly from `genesis` (`S_load = 0`). Everything that follows is the `Durability::Fsync` path.

`open` recovers in **two passes** — the first to locate the trustworthy boundary `W` and classify any damage, the second to fold — because a corrupt run cannot be classified until `W` is known, and `W` (the last committed marker) is found only by scanning to the end.

**Terminology (from §1).** A frame is **intact** iff its own per-frame `crc` validates; a marker is **committed** iff it is intact, durable (present on the disk recovery reads), and its `records_checksum` validates over its txn's record frames. An *intact-but-`records_checksum`-failing* marker (a torn or bit-rotted txn) is **not** committed.

**Load the base.** Load the latest valid **retained** checkpoint `checkpoint.<S_load>` — *valid* = its header checksum validates over the serialized `W` bytes (§6). On `OpenError::BadCheckpoint` fall back to the next-older *retained* checkpoint, then to `genesis` with `S_load = 0` only while nothing below it has been reclaimed — **concretely: genesis is still reachable iff the earliest surviving segment's recorded `firstSeq` (§1) is still the first assigned `Seq` (`Seq(1)` — the high-water starts at genesis's `S_load = 0`), a test the per-segment range metadata answers without opening a segment (a journal with no reclaimed segment, an empty first-init journal included, qualifies)**; the whole chain exhausted ⟹ surface `BadCheckpoint` (§6). Then call **`rebuild_derived`** (seeds, from authoritative state, the hints the checkpoint skip-serialized; `apply` then keeps them current across replay — and a store's `rebuild_derived` override **must** seed exactly the `apply`-fold of the `Seq ≤ S_load` prefix it stands in for, or the recovered hint diverges from the live-maintained one, a trait contract — §Public interface, §Dependencies & seams).

**Caller contract — `genesis` must be byte-stable across opens.** Every recovery folds journaled *deltas* onto the caller-supplied `genesis` — both at first init (`S_load = 0`) and on the `BadCheckpoint` fallback to genesis — and **never** onto a journaled root (M2 journals deltas only, never Σ₀ itself). So the *same* `genesis` value must be passed on every `open()` of a given journal; a `genesis` that differs byte-for-byte between opens silently mis-recovers, folding correct deltas onto the wrong base. ASN-0047's fixed initial state Σ₀ (the bootstrap node `n₀ = [1]`; `C₀ = L₀ = R₀ = ∅`, `M₀(d) = ∅`) satisfies this by construction, but the kernel *depends* on the caller honoring it and cannot check it.

**Pass 1 — find `W` and classify.** Scan the journal from the first segment whose recorded `lastSeq > S_load` (earlier whole segments, with `lastSeq ≤ S_load`, are skipped outright by that range metadata — §1, without opening them), **in file order, which is `Seq` order** — the single applier appends frames under the applier lock in `Seq` order. On a CRC failure the framed `len` cannot be trusted to find the next frame (the offset depended on the corrupt length), so recovery **seeks forward byte-by-byte for the next `magic` sync word** (§1), takes that as a candidate frame start, and accepts it only if it is **intact** (its `crc` validates over its `len`+payload — a coincidental `magic` inside a payload fails this and the scan continues). Group surviving frames by their `txn` id (a transaction's first `Seq`, unique across sessions — §1) — **not by file position**, because a `magic`-resync that skipped a corrupt frame breaks file-contiguity, so "the frames between the previous marker and this one" can no longer identify a transaction; a transaction missing a (skipped) record then *fails* its `records_checksum`. A transaction is **committed** iff its marker is committed (intact, durable, `records_checksum`-valid over its records). **`W` = the `last_seq` of the last committed marker** — the end of the committed prefix; everything after it is the torn/un-acked tail. (In-order append + prefix-flushing fsync make this sound: a committed marker implies every earlier frame is durable, so the committed prefix is a contiguous `Seq` prefix and a committed marker *is* the commit ack — §1. The deferred `FsyncBatch` mode instead reads `W` from the highest durable `Clean{through}` record.) **If the scan finds *no* committed marker above `S_load`** (every marker above it torn, or none present at all), then **`W = S_load`**: the committed prefix ends exactly at the loaded checkpoint, Pass 2 folds nothing, and the invariant `W ≥ S_load` holds at equality. For each **corrupt run** (a span the scan skipped via `magic`-resync), record two derived `Seq`s and keep them apart: its **inferred `Seq` max** = `next_intact − 1` is the **classifier**; `next_intact` itself is the **error payload** `at`. **`next_intact` is a coordinate defined per landing-frame kind** (the run's own `Seq`s being unreadable): a **record** landing contributes its own `seq`; a **marker** landing contributes **`last_seq + 1`** — equivalently, *a run ending at a marker has inferred max `= last_seq`* — because a `Marker` carries no `seq` field of its own (§1), sharing `last_seq` with its txn's *final record*, which may be exactly the corrupt frame the resync skipped. The naive reading `next_intact := last_seq` under-counts that record by one, with a real consequence at the boundary: rot the final record of an *interior committed* txn at `Seq = S_load + 1` and the resync lands on that txn's own intact marker (`last_seq = S_load + 1`); the naive inference gives max `= S_load` — harmless — so recovery proceeds, the txn (its `records_checksum` now failing) is not replayed while later txns are, and an *acked* effect is silently lost — the exact wrong recovery this classification exists to refuse. The marker rule gives max `= S_load + 1 ∈ (S_load, W]` — fatal, halted. A run reaching **end-of-journal with no next intact frame** has no coordinate and classifies as the **tail** (`> W`): sound, because the last committed marker is itself intact, so it precedes any EOF-reaching run, whose frames therefore all carry `Seq > W`; consequently `Corruption{ at }` never carries an EOF payload, and when `at` is reported off a marker landing it is that marker's `last_seq + 1`. `at` and the max differ by one at the `S_load` boundary, and classifying by the max rather than by `at` is exactly what stops a single boundary frame from being claimed by both the harmless and the fatal region (below).

**The inferred max is an *upper bound* — exact only under `BurnedSeqPolicy::Rollback`.** `next_intact − 1` presumes the run's `Seq`s run contiguously up to the landing coordinate; under `TolerateGap` a burned-`Seq` gap falling immediately *after* the run inflates `next_intact` above the run's true max, so the classifier can *overestimate*. The mis-classification is strictly one-directional and safe-side: a run whose true max is `≤ S_load` but whose inferred max a trailing gap pushes into `(S_load, W]` is conservatively **halted** as `Corruption{at}` — a recoverable kernel refused — and *never* the reverse: a genuinely-replayed corrupt frame (true `Seq` in `(S_load, W]`) is never under-classified down to harmless — the inferred max upper-bounds the run's true max at *both* landing kinds, the marker rule included (a skipped final record's `Seq` *is* the landing marker's `last_seq`, exactly what the rule infers) — nor out to the discarded tail, since the committed marker bounding `W` is itself an intact frame the resync must stop at or before: landing *on* it contributes `next_intact = W + 1`, i.e. inferred max `= W`, and any earlier landing contributes less, so a run holding any committed-range frame gets an inferred max inside `(S_load, W]` — halted, never tail-classed. This over-halt is the accepted cost of the never-silently-drop posture under `TolerateGap`; under the default `Rollback` the order is gap-free (§1) and the inferred max is the run's *exact* max at either landing kind (a record landing: `seq − 1`; a marker landing: the skipped final record's own `last_seq`), so no such over-halt arises.

**Classify each corrupt run by its inferred `Seq` max** (*not* by the payload `at`) — relative to the two boundaries `S_load` and `W`:

- **inferred max `≤ S_load`** (the *whole* corrupt run sits at or below `S_load` — frames surviving §6's segment-granular reclamation in a straddling segment): **harmless** — the `Seq > S_load` filter skips every one of them and the loaded checkpoint already embodies their effect; recovery resyncs past the run and continues. The boundary case `at = S_load + 1` lands here (its run's inferred max is `S_load`, under either landing kind — a record at `Seq = S_load + 1` or a marker with `last_seq = S_load`), so it stays harmless — classifying by `at` instead would spuriously halt on this exact frame. Halting here would needlessly refuse a recoverable kernel.
- **inferred max `∈ (S_load, W]`** (at least one corrupt frame falls inside the genuinely-replayed, committed range — *including a run that straddles `S_load`*, with some frames `≤ S_load` and some above: still **fatal**, because it holds a frame the recovered state needs): **corruption of durable committed data** → halt and report `OpenError::Corruption{ at }`, the payload `at` = `next_intact` (the run's own `Seq`s are unreadable; `last_seq + 1` at a marker landing); never silently drop it, because a silent discard would leave a `Seq` hole in the genuinely-replayed range that — `apply` being non-idempotent and `Seq`-ordered — recovers a *wrong* state.
- **inferred max `> W`** — the class an **EOF-terminated run** (no next intact frame, Pass 1) also lands in — (the run lies wholly past the last committed marker): the **un-acked / torn tail** → discard. It was never a committed marker (its barrier never completed, its records are incomplete, or its `records_checksum` fails), so loss is correct. A *committed marker* is by definition `≤ W` (it is, or precedes, the last committed marker, replayed below); a frame beyond `W` is therefore always an incomplete in-flight transaction. A *torn* surviving marker from a barrier-failure-then-truncation-failure that poisoned the kernel (§1) lands here too (no successor ran, so its frames are at most the journal tail); but an **intact, `records_checksum`-valid** such surviving marker is *not* beyond `W` — it **is** the last committed marker (`W` = its `last_seq`), found by the normal scan and replayed below as a lost-ack / indeterminate op (SAFE(b)(iii)), never discarded. "No successor ran" makes it the *last committed* marker when its records check out, a beyond-`W` tail only when it is torn.

**Pass 2 — fold.** Replay the committed records with `S_load < Seq ≤ W`, folded via `apply` **in `Seq` order** (a linear scan — in-order append) — exactly the complement of what the loaded checkpoint embodies (§6), no record applied twice or skipped (when `W = S_load`, the range is empty and nothing is folded). The `Seq > S_load` filter is load-bearing because `apply` is non-idempotent: a surviving `≤ S_load` frame, replayed, would double-apply. **No `Seq`-contiguity is required in the replayed range:** under `BurnedSeqPolicy::TolerateGap` it may legitimately contain burned-Seq gaps, which fold harmlessly (each *present* record applied exactly once, in order); a builder must **not** add a contiguity check that would falsely trip on such a gap — the only journal defect that is corruption is a **CRC failure with inferred max in `(S_load, W]`**, never a merely missing `Seq`. `apply` determinism guarantees a clean replay reproduces the exact committed state (A6: every journal prefix up to a committed marker is a canonical reachable state).

**Lost acks are the client's, not a phantom.** A *committed marker* at the tail that was never *acked* — a crash between its barrier and its return, or the surviving marker of a failed-truncation poison — is `≤ W` and is **replayed** as a committed operation. This is correct: the operation genuinely committed (it is durable); the caller, having received no ack (or `Poisoned`), is in the lost-ack / indeterminate case ASN-0134 SAFE(b)(iii) assigns to the client (idempotency keys for `idem=⊥`, dedup for `idem=⊤`), and a same-`(d,S)` retry after restart allocates fresh against the recovered (advanced) frontier. The phantom-commit hole is closed not by discarding committed markers but by the §1 truncate-and-poison discipline, which guarantees no operation *reported cleanly failed* ever leaves a committed marker for a successor to race. Only corruption *inside the replayed range* `(S_load, W]` is fatal; corruption already embodied in the loaded checkpoint (`≤ S_load`), or sitting in the discarded tail beyond `W`, is irrelevant.

**Known limitation — post-commit bit-rot of the *last* committed txn (out of scope).** The classification above is exhaustive for the *crash-atomicity* threat the durable-before-visible + truncate-or-poison discipline (§1) actually admits: there, an intact marker whose `records_checksum` fails arises only as a not-yet-acked torn/poison tail beyond `W`, correctly discarded. It has **one blind spot** for *post-commit* media decay, flagged here because it is the lone case where the "never silently drop committed data" posture does not hold. If a bit rots in a record frame of an *already-committed, already-acked* txn, that txn's marker stays intact while its `records_checksum` now fails — so recovery does not count it committed, `W` demotes to the *prior* committed marker, and the rotted txn, now *beyond* the demoted `W`, is **discarded as a torn tail, silently, with no `Corruption` signal** — a disposition the classifier arithmetic (Pass 1) reproduces: the rot's resync lands within the txn (a record landing) or on the txn's own intact marker (inferred max `= last_seq`), in either case above the demoted `W`, the tail class. This is exposed **only for the last committed txn**: identical rot in any *interior* committed txn lands inside the genuinely-replayed range `(S_load, W]` (a later txn still holds `W` above it) and *is* caught — halt with `OpenError::Corruption` — including at a marker landing, where the `last_seq` inference is precisely what keeps a rotted *final* record inside `(S_load, W]` instead of under-counting it out (Pass 1). Neither source note mandates post-commit-rot handling, so this is **out of scope for v1**; closing it would need a marker-level signal distinguishing "torn in flight" from "was committed, since decayed" (deferred).

**High-water rebuilt.** Recovery is single-threaded — the applier lock and the single `Seq` high-water are rebuilt fresh. The **`Seq` high-water** is restored to `W`, and that is the *whole* of it: there is **no separate `Txn` counter** to restore. `Txn` is a transaction's *first* `Seq` (`Txn(pub Seq)`, §1), not an independent id, so the next session's first transaction draws `Txn = W + 1`, automatically beyond every committed `Txn` (each `≤ W`). Restoring the one `Seq` high-water to `W` therefore *fully* restores `Txn` freshness — a new session can never reuse a committed `Txn` id, so the by-`Txn` frame grouping (§1) is safe across sessions for free. (This is exactly why `Txn` is derived from the first `Seq` rather than a standalone counter: a *reset* standalone counter would repeat ids while `Seq`s march on, merging two sessions' transactions under one `txn` and failing the later marker's `records_checksum` — the first-`Seq` derivation forecloses that with no second piece of recovered state. In v1 `W` is that committed boundary; the `Clean{through}` watermark `FsyncBatch` would bound it against is folded into the marker-as-ack model — §1.)

### 8. Concurrency realizations — the fault line

The v1 realization is the **single applier**. `f` runs under one global applier lock with `base == current root` (per-commit `Fsync`: append records+marker → barrier (the single records+marker fsync) → install, all inside the applier-locked region — §3); install always follows the barrier, so the ordering is unconditionally **durable-before-visible** (§1/§3) and every installed root is durable. The `keys` argument is subsumed by the global lock (every write is serialized), so clauses **1, 2, 4, 5, 7 are free**, leaving **clause 6** — which still needs the §5 one-`Snapshot` threading, since the read-drift pathology arises even with no write concurrency — and the **clause-3** commit-gate ordering to be handled explicitly. The durability config selects per-commit `Fsync` (with the truncate-tail + Seq-rollback / poison failure path of §1) vs `InMemory` (no journal/barrier/recovery). Bounded by one core. Because `f` always sees the live root, a store written against the single applier *can* read state outside its `keys` — but that liberty is **safe only under the single applier**, and it is exactly what the deferred per-key realization would break: the migration is "a pure internal change" only for stores whose every read is covered by a declared key, so a store that wants that guarantee must declare **every slice it reads** among its `keys` (already the stated intent of the seam — §4), treating out-of-key reads as a v1-only liberty taken at migration cost.

**Per-key-concurrent (merge-at-install) and optimistic-CAS write concurrency are deferred out of v1 scope** (Open build decisions). They are concurrent protocols whose crash/interleaving correctness a prose design cannot pin — to be developed against a `loom`/linearizability harness — and are the seam ASN-0134's G1 (per-home serialization suffices) ultimately blesses for throughput. The `transact`/`snapshot` method signatures and the `LockKey` seam are invariant across these realizations, so they slot in later as a pure internal change.

## Invariants & contracts

**By construction** (falls out of the data model above):
- **Total order, monotone `Seq`, refining `𝔼` — gap-free *only* under `BurnedSeqPolicy::Rollback`** — counter under the serializer (ASN-0134 A1/A2, SequentialTransitionAxiom; ASN-0047 same). The full `Seq`/`idx(σ)` correspondence — which records carry a `Seq`, the `→_sh` subsequence's isomorphism to the finest `𝔼`, the install-order mapping M2 presents for over-satisfied content runs, and that no caller derives `idx(σ)` from `Seq` — is stated once in §2; here only its *invariant* facts. The refinement relationship is **unconditional** (it survives gaps); only **gap-freeness** is policy-conditional — it holds under `Rollback`'s Seq-rollback on durability failure (§1) and relaxes to **monotone-only** under `TolerateGap`. For a single-record op the returned `Seq` is observable; for a multi-record composite the *observable* coordinate is the terminal `last_seq`, the interior `→_sh` `Seq` being internal (§2). File order == `Seq` order in the durable (`Fsync`) realization; the in-memory mode has no journal, so the question does not arise (§7/§8).
- **No torn read / per-call single-state** — immutable `Committed<W>` + atomic `ArcSwap` install + lock-free `load_full` (A0/A3/A4/V0, MIC-4). External readers see only the installed root, and `current_seq()` (that installed root's seq) never regresses because install is serialized (§5).
- **Reads available under poison** — the poison path leaves the in-memory root a consistent committed state (durable-before-visible: the failed txn's root was never installed, so it remains the last durable state), so `snapshot`/`current_seq` keep serving it and never fail; only write (`transact`) and `checkpoint` paths return `Poisoned` (§Public interface, §5).
- **Multi-read verdict single-state** — one `Snapshot` threaded through all reads (V2, MIC-6; caller contract, made trivial by persistent root).
- **Composite Seq-contiguity** — a composite's Seqs assigned as a unit; an *internal-order* property only — W2 chain contiguity comes from committing the run as one `transact` under the global lock, not from this (§2/§4).
- **Append-only journal; a committed frame (one belonging to a committed marker's txn — the marker intact, durable, `records_checksum`-valid) is immutable; every prefix up to a committed marker is a replayable canonical state** — magic-anchored, `txn`-tagged append-only file + terminal per-txn marker + `apply` determinism (ASN-0047 journaling; ASN-0134 A6).

**By active enforcement** (M2 must guard, named where):
- **Same-key serialization** — the single applier's global lock §4/§8 (ASN-0134 H2, MIC-2; the `keys` are the seam M3 builds frontier H0 atop).
- **Commit-before-acknowledge** — `transact` returns only post-durable+install; a zero-step op returns `base.seq()` against the durable installed root (under per-commit `Fsync` `base` is durable, no wait) (A7, MIC-3).
- **Composite atomicity (none-or-all to readers)** — single atomic install §3 + torn-tail recovery discard (everything after the last committed marker) §7 (ASN-0047).
- **Durability before ack, with a sound failure path** — the durable-before-visible ordering (append records+marker → barrier → install → return) and its truncate-or-poison failure path are stated canonically in §1; in summary: a committed marker *is* the commit ack (so v1 needs no second ack fsync), a barrier failure is a **true no-op** (`TxnError::Durability`) when its un-acked-tail truncation completes durably and a kernel **poison** (`TxnError::Poisoned`) when it does not, and no on-disk sentinel is needed (recovery finds any surviving marker at the journal tail — §1/§7) (ASN-0047, A7).
- **Recovery faithfulness** — load the latest valid *retained* checkpoint (*valid* = its header checksum validates — §6; falling back to an older retained one or genesis on `BadCheckpoint`, §6/§7; `genesis` is a caller-stable-across-opens contract — §7); in a **first pass**, scan in `Seq` order (== file order — in-order append), resynchronizing past interior bad frames via the per-frame `magic` word (accepting only *intact* frames) and grouping a transaction's records by `txn` (= its first `Seq`, unique across sessions, recovered for free — §1) rather than file position to validate its `records_checksum`, deriving **`W` = the last committed marker's `last_seq`** (or `W = S_load` if no committed marker sits above the loaded checkpoint — §7) and, for each corrupt run, its inferred `Seq` max (= next-intact coordinate − 1, a **record** landing contributing its `seq` and a **marker** landing `last_seq + 1` — markers carry no `Seq` of their own — with an EOF-terminated run classing as tail; the *classifier*, an **upper bound**: exact under `Rollback`, possibly conservative-over-halting under `TolerateGap` — §7) alongside that coordinate itself (the *payload* `at`); then in a **second pass** replay committed records **filtered to `S_load < Seq ≤ W`** (skipping any `≤ S_load` frames surviving §6's segment-granular reclamation; folding nothing when `W = S_load`), folded in `Seq` order (a linear scan) **without requiring Seq-contiguity** (a `TolerateGap` gap folds harmlessly). Rebuild the **single `Seq` high-water (= `W`)**; since `Txn` is a transaction's *first* `Seq` (not a separate counter), this alone sets the next session's first `Txn = W+1` beyond every committed `Txn`, so the by-`txn` grouping stays collision-free across sessions with no second piece of recovered state (§7). A corrupt run is classified **by its inferred `Seq` max**: one whose max is *beyond* `W` — the class an EOF-terminated run also lands in — is the un-acked/torn tail (discard — including a *torn* surviving marker from a failed-truncation poison; an **intact, `records_checksum`-valid** such marker is *not* here but is the last committed marker itself, `W` = its `last_seq`, replayed below as a lost-ack op (§1) — the one out-of-scope blind spot being post-commit bit-rot of the *last* committed txn, which demotes `W` and lands that txn here, discarded silently — §7); one whose max falls in the genuinely-replayed range **`(S_load, W]`** — *including a run straddling `S_load`, which holds a needed frame* — is corruption of durable committed data (halt, `OpenError::Corruption{ at }`, the payload `at` = the next-intact coordinate, `last_seq + 1` at a marker landing — never drop); one whose max is `≤ S_load` is **harmless** (the boundary case `at = S_load+1` has max `S_load`, so stays harmless not spuriously fatal; the `Seq > S_load` filter skips it; the checkpoint already embodies it). A *committed* but un-acked tail marker (lost ack) is `≤ W` and is replayed as a committed op — the client's case per ASN-0134 SAFE(b)(iii), not a phantom (A6; ASN-0047).
- **idem=⊤ dedup atomicity** — read-decide-deposit under the coverage-class key = one `transact`, serialized by the global lock §4 (I1a/I4/G2, MIC-7).
- **Run contiguity** — a run as one `transact([key(d,s_C)], …)`, each atom minting against `stg.working().content()`: under the single applier the serialized atomic install delivers W2 chain contiguity and over-satisfies clause 5 §4 (W2, MIC-5).
- **Checkpoint/reclamation single-threaded** — `checkpoint()` (caller-invoked or on-commit auto-triggered) is serialized against itself by a dedicated checkpoint mutex, distinct from the applier lock so it never blocks writers, keeping the retention-set update and segment deletion race-free even though the `&self` API permits concurrent calls; the cadence counters live in `transact`'s applier-locked state and are reset there (by the triggering `transact`, under the applier lock), so `checkpoint()` never touches them and the two never race; an auto-triggered `checkpoint()`'s error is logged and dropped, never failing the already-committed transaction (§3/§6).
- **Live derived-hint correctness** — incremental hint maintenance is folded by `apply` on every commit and every replay step; `rebuild_derived` only seeds skip-serialized hints at load (§1/§7). A store that maintains a hint via `rebuild_derived` alone leaves it stale after every live write — so hint folding in `apply` is mandatory; and a store that *does* override `rebuild_derived` must seed exactly the `apply`-fold of the `Seq ≤ S_load` prefix, else the recovered hint diverges from the live one (§7).

**Explicitly *not* M2's** (passes through M2, enforced by neighbors):
- store permanence P0–P3/L12 and the J-couplings J0/J1★ (stores' `apply`+API; M5's composite boundary — ASN-0047);
- frontier/address and coverage-class computation (M3, M1/M7);
- register-before-allocate ordering (a store precondition checked against the snapshot, then a clean `Rejected` if unmet);
- the request lifecycle and ack-to-client (M10);
- **multi-*step* (`m ≥ 2`) batch atomicity** — M2 offers only the per-`transact` atomic unit; a store honors A5's intended partial visibility by issuing the batch as *separate* `transact`s. Committing a batch as *one* `transact` over-satisfies A5 soundly **only for an unwitnessed interior** (the content run, delivering W2 — §4); a *witnessed* link batch (`retract_stale`, whose interior retractions an `Observe_K` sees) must stay *separate* `transact`s, since collapsing it suppresses modeled partial visibility (A5, paraphrased: a multi-step batch's atomicity is built above the substrate, not by it). M2 neither forces nor forbids the granularity; the store chooses by that criterion. A single-step `m = 1` fire **is** one atomic `transact`;
- durability *as a requirement* (not a MIC clause — the in-memory mode is faithful).

## Dependencies & seams

**Upstream: none.** M2 is a foundation (it carries no edge to M1 — keys and payloads are opaque, ordering of keys is plain bytewise, not tumbler order). Its only dependencies are crates: `im`, `arc_swap`, `serde`, `parking_lot`, a CRC32C lib.

**Composition seam (dependency-inverted).** The engine crate defines `World` (composing all store slices) and `Record` (the enum union of every store's record-types), implements `WorldState` for `World` by dispatching `apply` to the owning store's logic, and instantiates `Kernel<World>`. The **single central `LockKey` space-tag enum lives in M2's own crate (`skep-kernel`), *not* the engine crate** (item 4 / the Engine Composition Contract's crate graph: `skep-kernel (M2, + the central Space tag enum) ← every store`). It names only `LockKey` and 1-byte constants — no store types — so it sits *below* every store and M2 stays store-agnostic; placing it in `skep-engine` (which already depends on every store crate) would instead give *every store* a dependency on the engine crate and close a **compile-time crate cycle**, the exact failure the contract exists to forbid. Every store's key constructor draws its 1-byte prefix from this one M2-defined enum, which is what guarantees cross-store tag uniqueness — no store picks a tag locally, so M3's `(home,subspace)` keys and M7's `class_key`s can never alias. The shared `key(home, …) -> LockKey` *constructor* the seam examples below call is, however, a **different artifact** from that tag enum: it names *both* `Address` (M1) **and** `LockKey` (M2), so it **cannot** live in `skep-kernel` (which carries no M2→M1 edge) — it lives in the **shared base crate over `skep-address` + `skep-kernel`** (the Engine Composition Contract's crate graph), and every store building a namespace lock key calls *that one* constructor, so M3-alloc / M4-write / M5-placement keys are byte-identical by construction; a builder must not try to export `key(...)` from `skep-kernel`. "Stores register record-types" = a store contributes its **own** `XRec` record-type + its `apply_x` fold, which the **engine** lifts into a `Record` variant and an `apply` dispatch arm (a store never names the central `Record`); "index-rebuilders" = **mandatory** incremental hint maintenance inside `apply` (it runs on every live commit and every replay step — a hint not folded here is stale after every write), plus, optionally, `World::rebuild_derived` to seed hints the checkpoint skip-serialized (it runs once at load, before replay, never on a live commit, so it cannot keep a hint current on its own — and whatever it seeds must equal the `apply`-fold of the `Seq ≤ S_load` prefix it stands in for, §7). Three hard contracts on store code:

**(1)** stage only authoritative deltas, maintain hints incrementally in `apply`, and **never journal a hint**.

**(2)** if a store overrides `rebuild_derived` to reconstruct a skip-serialized hint, that override must seed exactly what folding the `Seq ≤ S_load` prefix through `apply` would produce — so the load-time seed and the live `apply`-fold can never disagree (§7); M2 cannot check this.

**(3) Pure composable step surface.** Because `transact` is **non-reentrant** (§3), a store primitive that appears as a *step inside another store's composite* — M3's allocation inside M5's placement, M1's address math, **M5's link-seating inside M7's MAKELINK** — **cannot** be invoked as a nested `transact` (that deadlocks on the held applier lock). So every such primitive MUST be exposed in **two** forms: its standalone `transact`-wrapped form (for direct callers) **and** a **pure** function over its own slice `&XState` — reached by the enclosing composite as `stg.base().x()` / `stg.working().x()` through the `HasX` accessor, never the bare `&W` — returning the primitive's **own** `XRec` (never the central `Record`), which the composite lifts with `.into()` and `stg.push`es into its closure. The composite composes neighbors' *pure* bodies and stages their records; it never nests their transactions, never names the concrete `World`/`Record`, and never field-accesses a slice. M2 cannot enforce this — it is a contract *among the stores*, forced by M2's non-reentrancy — so **M3/M5** must publish the pure surface (and their `XRec` variants) up front, not discover the constraint at wiring time. (M1's address math is already pure — it does no I/O and needs no `transact` form.)

**Downstream seams (what neighbors code against):**
- **M3 allocation** (entity frontier under the H0 discipline): `let (addr, _seq) = kernel.transact(&[key(home, subspace)], |stg| { let max = recompute_max(stg.working().ns(), home, subspace); let addr = inc(max, 0); stg.push(NsRec::Alloc{ addr, … }.into()); Ok(addr) })?`. M3 supplies the key bytes (1-byte central-enum space tag + tumbler bytes, via the shared base-crate `key(...)` constructor) and does the entity address math — here `inc(max, 0)` is ASN-0034's `inc(t, k)` at `k = 0`, the sibling-advance increment the H0 frontier discipline uses for a *subsequent* emission; the store's allocator itself picks the first-emission boundary `[d.0.S.1]` vs this sibling advance per ASN-0093, M2 only serializing — every sketch below writes the representative `k = 0` call. (The math reads M3's own slice through the `HasNamespace` accessor — `stg.working().ns()`, not the bare `&W`, never `stg.base()`; for a bare single allocation `working()` == `base()` — nothing is pushed yet — but reading `working()` is the uniform rule that keeps a *multi-atom run* correct, where each atom must see the prior atoms' deposits — §3/§4/M5 seam.) The push is M3's **own** `NsRec`, lifted via `From` — never the central `Record`. This standalone form is for a *bare* allocation; per contract (3), when the *same allocator discipline* is one step of a larger composite (M5's content placement), the caller does **not** invoke a `transact` from inside its own closure (that would deadlock — §3) but reuses the *pure* `recompute_max`/`inc` body directly against the step's own population slice (for M5's content step, `stg.working().content()`).
- **M5 placement composite** (INSERT/COPY/VERSION): one `transact([key(d, s_C)], …)` staging, for a span of m content atoms, m × K.α together with their K.μ⁺ mappings and K.ρ entries, returning `(_, last_seq)`; M5 checks S3★ on `stg.working()` and the J-couplings at the boundary; M2 commits atomically. **Each content `K.α` mints its address from the content frontier read off `stg.working().content()`** (the population H0 defines the frontier over, reached via the `HasContent` accessor) **plus M1's pure `inc` — reading `working().content()`, not `base().content()`** — *inside this one closure* (contract (3)): `working().content()` reflects the atoms already pushed (each K.α is a content write), so atom k mints at the slot left by atoms 1..k−1 and the run fills consecutive frontier slots. Reading the unchanging `base().content()` for every atom would recompute one max m times — colliding addresses, and the `working().content()`-checked freshness precondition would reject atom 2, so a multi-atom INSERT could never commit (the v1 W2 defect this avoids — §4). The first atom reads `working().content()` == `base().content()` (nothing pushed yet); equivalently a batch allocator may hand back m consecutive addresses from one `base().content()` read plus the count m. Each record is the *owning* store's own `XRec`, lifted via `.into()` — M4's `ContentWrite` for K.α, M5's `ArrRec` for K.μ⁺/K.ρ — never the central `Record`. Sketch:

  ```
  kernel.transact(&[key(d, s_C)], |stg| {
      for atom in span {                                            // m content atoms, one run
          let max = recompute_max(stg.working().content(), d, s_C); // content frontier; sees prior atoms' K.α
          let a   = inc(max, 0);                                    // M1 pure — k=0 sibling advance
          stg.push(ContentWrite::new(a, atom).into());             // K.α — M4's own record, via M4's pure ctor + From
          stg.push(ArrRec::Extend{ d, v, a }.into());              // K.μ⁺ — M5's own record
          stg.push(ArrRec::Provenance{ a, d }.into());             // K.ρ   (J1★ asserted at the boundary)
      }                                                            // S3★/D-SEQ★ checked on stg.working()
      Ok(())
  })?;
  ```

  It does **not** nest a call to an allocation `transact` (a nested `transact` deadlocks on the held applier lock — §3); the composite is one closure composing neighbors' pure functions and staging their records, never a transaction-within-a-transaction, and it names no concrete `World`/`Record` — every record is the owning store's `XRec` lifted by `.into()` (contract (3)). CREATENEWDOCUMENT (M3) is one `transact` registering the entity (returning its `Seq`) — it does *not* materialize an arrangement (M5 keeps that lazy).
- **M7 idem=⊤ emit** (and its link-seating — the `M7 → M5` no-return edge, shown as concretely as M5's content placement):

  ```
  kernel.transact(&[class_key, key(home, s_L)], |stg| {
      if m7_active_in_class(stg.working().links(), class).is_some() {
          Ok(Hit)                                                      // idem=⊤ dedup HIT — stages nothing (zero-step)
      } else {
          let max = recompute_max(stg.working().links(), home, s_L);  // link frontier (H0 population), via HasLinks
          let ℓ   = inc(max, 0);                                       // M1 pure — k=0 sibling advance; K.λ_sh deposit
          stg.push(LinkRec::Emit{ ℓ, tuple }.into());                // K.λ — M7's OWN record, via From
          let v_ℓ = m5_next_link_vpos(stg.working().arr(), home);     // M5's PURE seating math — K.μ⁺_L V-position
          stg.push(ArrRec::SeatLink{ d: home, v: v_ℓ, ℓ }.into());    // K.μ⁺_L — M5's OWN record (M7 → M5, no return edge)
          Ok(Deposited(ℓ))
      }
  }) // → (outcome, seq)
  ```

  The dedup read and the link-frontier read both reach M7's **own** slice through the `HasLinks` accessor (`stg.working().links()`); the dedup read precedes any push, so `base()` would suffice, but `working()` is the uniform rule (§4/M5 seam). The emit branch stages **two** records, each the *owning* store's own `XRec` lifted via `.into()`: M7's **`LinkRec::Emit`** (the K.λ deposit of the gated K.λ_sh operation — §2) and M5's **`ArrRec::SeatLink`** (the K.μ⁺_L link-subspace extension seating ℓ in home d's arrangement) — never the central `Record`. The seating reads M5's arrangement slice through `HasArrangement` (`stg.working().arr()`) and folds **M5's pure `m5_next_link_vpos` body** (M5 owns the arrangement), so MAKELINK never nests an M5 `transact` — the **M7 → M5** edge with no return edge, concretely mirroring how M5's content placement folds M4's pure frontier-max and M1's `inc` (the M5 seam above). Per ASN-0047 J-LV the link seating appends **no** provenance R (and link allocation is uncoupled from content allocation), so there is no K.ρ push here — unlike content placement. The `class_key` keys same-class emits (clause 7); the alloc key keys same-home allocation (clause 2) — under the single applier the global lock serializes both, the keys remaining the documented seam (§4). Nullify hit-branch = a `transact` that stages nothing (zero-step), returning `(Hit, base.seq())` against the durable installed root (under per-commit `Fsync` no wait). The spanfilade is M7's hint, maintained incrementally in `apply` (mandatory — never journaled) and seeded by `rebuild_derived` only if the checkpoint skip-serialized it — that seed obligated to equal the `apply`-fold of the `Seq ≤ S_load` prefix (§7). **M5's** seating primitive and its arrangement `XRec` variants are published per contract (3) (M5 owns the arrangement), which is what makes this `M7 → M5` fold legal at all.
- **M6/M8/M9 readers & verdicts**: `let s = kernel.snapshot();` then read every constituent off `s` (clause 6). M9 reports quiescence as "as of `s.seq()`" (V1 retrospective). M9 calls M2 **directly only for these snapshot verdicts**; its reactive rule *fires* do **not** call `transact` — they go through **M7's gated write path** (`Emit_K` → M2), per the `M9 → M7` edge, and its predicate-**definition content** creation rides **M5's placement composite** (`M9 → M5 → M2`, where J0 fires for predicate-def creation — covered by the M5 placement seam above), so M9 *does* reach the placement path, just never directly. A *single-step* (`m = 1`) fire is exactly one atomic `transact` *inside M7's emit* (the "atomic fires" M9 leans on), and M9 obtains the fire's index from the `Seq` **M7 returns** (exact, unlike a post-hoc `current_seq()`, which names only the installed root — §5); a *multi-step* (`m ≥ 2`) fire is an A5 batch M9 drives as several such M7 emits, sequenced above the substrate.
- **M10**: opens/commits each operation's transaction via `transact`, receiving `(result, last_seq)`; acknowledges to the external client only after it returns (commit-before-ack), may report `last_seq`, surfaces `TxnError::Rejected(E)` as a typed rejection (never a silent skip), and treats `TxnError::Poisoned` as a halt condition (do not re-invoke). On startup, `OpenError::Corruption`/`BadCheckpoint` are operator-intervention conditions, not retried automatically. (An operation returns only once *its own* effect is durable and installed — the single applier's durable-before-visible default closes even the window where an external read could reflect a not-yet-durable state — §1/Conflicts #3.)

## Conflicts resolved

**1. Composite atomicity (ASN-0047) vs "batches are not atomic" (ASN-0134 A5).** The two speak of different units. M2's atomic unit is the **transaction** (one `transact`) — externally none-or-all. ASN-0047's "observable intermediate states" of a composite are precisely `Staging.working`, visible *only to the executing closure* for intra-composite precondition checks, never to external readers. ASN-0134's "batches not atomic" refers to a sequence of *separate* operations (`retract_stale`, a multi-step (`m ≥ 2`) rule firing) whose partial visibility is intended (a single-step `m = 1` fire is one atomic `transact` — §Purpose). **M2 cannot bundle caller-separate operations** — it offers only the per-`transact` atomic unit; a store honors A5's intended partial visibility by issuing an `m ≥ 2` batch as *separate* `transact`s. Whether committing it as *one* `transact` is a sound over-satisfaction depends on whether a *modeled read witnesses the interior*: for an **unwitnessed** batch — the **content run** (m × K.α), whose mid-batch states A5 itself notes are witnessed by no modeled read — committing-as-one is harmless and is precisely how W2 is delivered; for a **witnessed** batch — a link-store `retract_stale`, whose every interior `Nullify_Binary` *is* visible to an `Observe_K` over the active slice `A_K` (A5) — committing-as-one *suppresses* that intended partial visibility, an observable-behavior change, so the recommended default stays *separate* `transact`s and one-`transact` is **not** a free over-satisfaction. M2 neither forces nor forbids the granularity; the store chooses by that witnessed/unwitnessed criterion (paraphrasing A5: multi-step batch atomicity is the caller's, to be built above the substrate). The **content run** (one `K.α` per atom) is the boundary case ASN-0134 A5 explicitly classes as a non-atomic batch — and in v1 M2 commits it as **one atomic `transact([key(d,s_C)], …)`** (under the single applier the serialized atomic install delivers W2 via the run's confinement to one step and over-satisfies clause 5 — no reader lands mid-run). The reader-visible-mid-run flavor of clause 5 (a run committed as separate inner commits) is not realizable under the single applier, which serializes every write; it belongs to the deferred per-key realization (§8). So: M2 delivers transaction (composite) atomicity; multi-transaction batch atomicity is the caller's, "above the substrate"; and the content run is, in v1, one atomic unit (over-satisfying clause 5).

**2. Single global writer (ASN-0047) vs per-home serialization suffices (ASN-0134 G1).** The **contract** is the weaker one — per-key serialization (clause 2). The **v1 implementation** is a single applier (ASN-0047), which over-satisfies it: every write is serialized through one lock, so same-key serialization holds trivially and the `keys` are the documented seam M3/M7 code against rather than a live lock table (§4). The per-home-concurrent realization ASN-0134 G1 ultimately blesses for throughput is **deferred** (§8, Open build decisions); because `transact(keys, …)` and the `LockKey` seam are invariant across realizations, it slots in later as a pure internal change without altering any caller's call shape. ASN-0047's single-writer is thus one conservative realization of ASN-0134's contract, not a competing requirement.

**3. Visible-after-durable (ASN-0047) vs durability-orthogonal (ASN-0134).** ASN-0047 says make a composite visible only after its batch is durably committed — natural in its single-threaded model, where *visible* == *acked*. ASN-0134 treats durability as orthogonal (not a MIC clause; an in-memory mode is faithful) and takes *visible* == *committed*. M2 resolves this by making **durable-before-visible the single applier's one ordering** (§1/§3): per-commit, install follows the single records+marker barrier, so every installed root is durable, an external M10-acked read never reflects a state a crash can roll back, and a woken write's effect is already in `root` (the read-your-writes A7 requires). The commit-ack mechanism that makes this work — **a committed marker *is* the ack** (no second ack fsync), with `TxnError::Durability` a true no-op on barrier failure and a kernel poison (`TxnError::Poisoned`) only when the un-acked-tail truncation itself fails — is the §1 canonical discipline, cross-referenced here rather than restated (the deferred `FsyncBatch` group-commit reintroduces a separate durable `Clean` watermark, where one batched fsync acks many markers — §1). The **in-memory mode** (`Durability::InMemory`) takes ASN-0134's weaker stance that durability is not a MIC clause — atomicity/isolation intact, no journal, no recovery. (A visible-before-durable ordering would be *forced* by the deferred per-key/CAS realizations, whose install-before-barrier shape leaves no room for durable-before-visible; it is deferred with those realizations — §8.)

**Boundary clarifications (territory that *looks* like M2's but is a neighbor's, resolved by the decomposition's dependency inversion):** the frontier discipline ASN-0134 reasons about (H0) is M3's *allocator*; M2 owns only its *serialization*. The request/response path and pipelining-vs-sequential client model (G0) are re-homed to M10; M2 keeps only the commit-gate mechanism. Neither is a conflict — both are M2 honoring its seam by *not* doing the neighbor's job.

## Open build decisions

- **Per-key-concurrent (merge-at-install) and optimistic-CAS write concurrency** — **deferred to implementation**, developed against a `loom`/linearizability harness; out of scope for the v1 design, which is **single-applier**. The `transact`/`snapshot` API and the `LockKey` seam are invariant across concurrency realizations, so they slot in later as a pure internal change.
- **Burned-Seq policy on durability failure** (carried on `Durability::Fsync`, whose barrier-failure path truncates + rolls back per §1) — `Rollback` (keeps the order gap-free; recommended) vs `TolerateGap` (relaxes the invariant to monotone-only; recovery tolerates the gap — §7). Under `TolerateGap` a trailing burned-`Seq` gap can make §7's corrupt-run classifier *over*-estimate a run's max and conservatively halt a recoverable kernel — the deliberate cost of never-silently-dropping; under `Rollback` the classifier is exact (§7). The failed-truncation **poison** (`Poisoned` rather than a no-op) applies under either policy — the §1 discipline, cross-referenced not restated.
- **Durability mode** — per-commit `Fsync` (`Durability::Fsync` — one barrier fsync of records+marker per commit, durable-before-visible — §1) vs **in-memory** (`Durability::InMemory`; MIC-faithful, for tests/embedding; `checkpoint()` then a no-op returning `current_seq()`, `flush()` a no-op `Ok` — §6/§Public interface).
- **Group-commit (`FsyncBatch`) durability batching** — **deferred to implementation**, developed against a `loom`/linearizability harness that can exhaustively check the leader/follower/watermark interleavings; out of scope for the v1 design, which is per-commit `Fsync`. `FsyncBatch` is where the separate durable `Clean{through}` watermark record (folded out of v1 per the marker-as-ack model — §1) earns its keep: one batched fsync acks many markers, so marker-presence no longer implies durability and recovery must again bound trust by the highest durable `Clean{through}` = `W`. The `transact`/`snapshot` API is invariant across durability modes, so it slots in later as a pure internal change (the retained no-op `flush()` is its slot-in point, where it would flush the pending batch and advance the watermark).
- **Checkpoint cadence, retention & representation** — every-N-commits / time / journal-size (the *cadence policy* — which `CheckpointPolicy` variant and threshold — is the knob; the *trigger mechanism* is **fixed**, an on-commit evaluation inside `transact`'s post-install step with `Manual` disabling it and no background timer, the trigger counters living in `transact`'s applier-locked state and reset there by the triggering `transact`, never by `checkpoint()`, whose auto-triggered errors are logged and dropped — §3/§6); **`retain_checkpoints` (N ≥ 1)** most-recent checkpoints kept, journal reclaimed only below the **oldest** retained one so `BadCheckpoint` can fall back to an older retained base (N = 1 ⇒ newest is the sole base, no fallback, so verify/duplicate the write) — §6; full-`World` serialize vs per-store/incremental; serialize hints vs `#[serde(skip)]` + `rebuild_derived` (checkpoint size vs recovery recompute — and an overriding `rebuild_derived` must match the `apply`-fold of `Seq ≤ S_load`, §7). The recovery-time-vs-overhead knob ASN-0047/0134 leave open. (The `≤ S_load` / `(S_load, W]` checkpoint-vs-replay boundary against the *loaded* checkpoint and the derived `W` is *fixed*, not a knob — §6/§7; journal truncation is segment-granular space reclamation, never a correctness mechanism — recovery's `Seq > S_load` filter handles any `≤ S_load` frames a straddling segment leaves behind, and a corrupt run whose inferred max is `≤ S_load` is non-fatal, §7.)
- **Journal framing** — CRC algorithm (the frame `crc` covering **both `len` and payload**) **plus a fixed per-frame `magic` sync word** so the recovery scan can resynchronize past an interior bad frame to find later markers and tell an un-acked tail from committed-prefix corruption (§1/§7); the per-frame **`txn` id — a transaction's *first* `Seq`, not a separate counter** (so it is unique across sessions and recovered for free with the single `Seq` high-water, §1/§7) — that groups a transaction's frames so its `records_checksum` validates after a `magic`-resync skipped a corrupt frame (file-contiguity untrustworthy there); the marker's `records_checksum` over the txn's record frames (distinct from the frame `crc`); (the `Clean{ through }` watermark record is **`FsyncBatch`-only** — v1 has no separate ack record, the committed marker being the ack — §1); **per-segment `[firstSeq, lastSeq]` range metadata** (segment named by its `firstSeq`, or a small segment header) so recovery skips and §6's reclamation drops whole segments by `Seq` range without opening them — the representation (name-by-first-Seq vs header) is the open choice, the *requirement* is fixed (§1/§6/§7); **segment-rotation discipline — rotate at txn boundaries (so a txn's frames never span a segment) *or* fsync the old segment before appending the new one: the marker-as-ack property (a committed marker implies a durable prefix — §1) holds *within* a segment but *across* a rotation requires the old segment durable before the new one is appended, which a fixed-byte-offset rotation mid-txn would break, defeating the no-second-watermark simplification v1 rests on**; max frame size; fsync-of-dir on rotate.
- **Record/key encoding** — `Record` (the trait's `W::Record`) as one serde enum (recommended for a single binary, compile-time dispatch) vs a runtime type-id registry of boxed appliers; `LockKey` as `Vec<u8>` vs `SmallVec`/`Box<[u8]>` vs a fixed-width digest (its 1-byte space tag always drawn from **`skep-kernel`'s** central tag enum — below every store, never the engine crate — and built by the shared base-crate `key(...)` constructor — §Dependencies).
