# Revision list

1. **[SHARPENING] State the recovery corrupt-run classification criterion precisely, and note its `TolerateGap` over-conservatism (§7).** A corrupt run's own Seqs are unreadable, so the run is provably `≤ S_load` (harmless) iff the next *intact* resync Seq `q ≤ S_load + 1` (the run's max `< q`); a run reaching into `(S_load, W]` always has `q ≥ S_load + 2`, so it correctly halts. Make the `+1` explicit so a builder doesn't naively use `q ≤ S_load` and false-halt a corrupt frame sitting exactly at the `S_load` boundary. Add one line that under `TolerateGap` (non-default) a corrupt run adjacent to a burned-Seq gap can be *over-counted* (the resync spans the absent burned frames), yielding a conservative false halt — **safe** (never silent corruption) but worth flagging; under the default `Rollback` the inference is exact.

2. **[SHARPENING] Align the `Seq` doc-comment with the gap-free-only-under-`Rollback` invariant.** The `Seq` struct comment asserts "monotone, gap-free" unconditionally, while the Invariants section and §1 correctly scope gap-freeness to `BurnedSeqPolicy::Rollback` (relaxing to monotone-only under `TolerateGap`). Change the struct comment to "monotone; gap-free under `Rollback` (default), monotone-only under `TolerateGap`" so a builder doesn't code a contiguity assumption the chosen policy doesn't hold (the §7 "do not add a contiguity check" warning then matches the type's own doc).

3. **[SHARPENING] Give `LockKey` the derives its documented contract needs.** The comment says "M2 only `Eq`/`Hash`/`Ord`-s the bytes," but `pub struct LockKey(pub Vec<u8>);` derives nothing. Add `#[derive(Clone, PartialEq, Eq, Hash, PartialOrd, Ord, Debug)]`. Not load-bearing in v1 (the global applier subsumes the keys, so they are received and dropped), but it makes the type match the seam contract the deferred per-key realization will rely on.

4. **[SHARPENING] Specify how recovery locates "the first segment containing a `Seq > S_load`" (§7).** Either name segments by their first `Seq` (or keep a small segment index), or note explicitly that a builder may scan all retained segments and rely on the `Seq > S_load` replay filter for correctness — the segment-skip is purely a perf optimization, and correctness does not depend on it. As written, "skip earlier whole segments" presumes segment-range metadata that the data model doesn't yet pin.

5. **[SHARPENING] Tighten the `K.λ` vs `K.λ_sh` attribution in the `Seq` comment.** The comment lists `K.λ` (ASN-0047 link allocation) among "the further ASN-0047 records the `→_sh` trio does not enumerate," while the trio it names includes `K.λ_sh` (ASN-0128/0134 gated emission). A reader may take these as the same primitive and see double-counting. A clause clarifying that `K.λ_sh` is the gated/typed view and raw `K.λ` is the transition-model view (and that M2 branches on neither) removes the ambiguity. Immaterial to M2's behavior — the load-bearing point ("M2 journals more record kinds than the trio, so `Seq` refines `𝔼`") stands regardless, since `K.μ⁺/K.μ⁻/K.ρ/K.μ⁺_L/K.δ`-for-nodes are unambiguously non-trio.
