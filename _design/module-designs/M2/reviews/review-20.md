Reviewed M2's detailed design against ASN-0047, ASN-0134, the decomposition, and the Engine Composition Contract. The module is close to buildable — the transaction flow, WAL discipline, keyed-serialization seam, and MIC-clause mapping are concrete and faithful — but recovery's corrupt-run classifier has a genuine under-specification with a demonstrable corner-case inconsistency, which is load-bearing for the design's own "never silently drop committed data" posture.

**1. Revision list**

1. **[DEFECT] — Define the corrupt-run classifier's Seq inference at marker frames and at end-of-journal; the current arithmetic is off by one there and breaks §7's own claims.** §7 computes a corrupt run's inferred max as `next_intact − 1`, where `next_intact` is "the Seq of the next intact frame" — but a `Marker` frame carries no `seq` field (only `txn` and `last_seq`), so the value is undefined when the resync lands on a marker, and the natural reading (`next_intact := last_seq`) under-estimates the run's true max by one, because a marker shares `last_seq` with its final record rather than consuming the next Seq. Two concrete consequences: (a) an interior committed txn whose *last* record frame rots (resync lands on that txn's own intact marker) with that record at `Seq = S_load + 1` gets inferred max `= S_load` → classified **harmless** → recovery proceeds, the txn fails its `records_checksum`, is not replayed, and an *acked* txn's effect is silently lost while later txns replay — exactly the silent wrong recovery §7 claims is impossible ("a genuinely-replayed corrupt frame is never under-classified down to harmless"); (b) in the acknowledged post-commit-rot blind spot (last committed txn, single record), the same reading gives inferred max `= demoted W` → classified **fatal** (`∈ (S_load, W]`), contradicting the blind-spot paragraph's stated behavior ("discarded as a torn tail, silently"). Fix: specify that a marker frame contributes `last_seq + 1` as `next_intact` (equivalently, a run ending at a marker has inferred max `= last_seq`), and that a corrupt run reaching EOF with no next intact frame classifies as the tail (`> W`). Under that definition both §7 claims become true — verify and state that the safe-side/never-under-classify argument and the blind-spot classification both hold under the corrected arithmetic. Also note the same rule feeds `Corruption{ at }`'s payload when `at` would be a marker.

2. **[SHARPENING] — Add the checkpoint checksum to §6's write path.** `OpenError::BadCheckpoint` and §7's "latest *valid* retained checkpoint" both presume each checkpoint carries a checksum that load validates ("each unreadable / failed its checksum"), but §6's write procedure (serialize → tmp → fsync → rename → fsync dir) never writes one. Serde deserialization alone will not reliably detect bit-rot, and a silently-wrong checkpoint base defeats the fallback chain. One sentence in §6 (checksum over the serialized `W`, stored in the file or its header) closes the write/read asymmetry.

3. **[SHARPENING] — State the disposition of a failed auto-triggered `checkpoint()` inside `transact`.** The §3 flow runs `checkpoint()` after release and then returns `Ok((v, last_seq))`; a `CheckpointError` there cannot surface through `TxnError` and must not fail an already-committed transaction. Say explicitly that the error is logged/dropped and why that is safe (a failed checkpoint leaves an ignored `.tmp` and an unreclaimed journal — §6's own argument).

4. **[SHARPENING] — Qualify the `Seq` doc comment.** The interface comment says "monotone, gap-free" flatly, while the Invariants section correctly makes gap-freeness conditional on `BurnedSeqPolicy::Rollback` (monotone-only under `TolerateGap`). Align the comment.

5. **[SHARPENING] — Flag the migration cost of §8's "may freely read state outside its `keys`."** The design simultaneously promises the deferred per-key realization slots in as "a pure internal change" and blesses v1 stores reading outside their declared keys — a store that exercises that freedom is exactly the store the per-key realization would break. Add one sentence: reading outside declared keys is safe only under the single applier; stores that want the migration guarantee must declare every slice they read as a key (which is already the stated intent of the seam).

6. **[SHARPENING] — Verify or soften the "ASN-0134-recommended persistent-immutable representation" attribution.** ASN-0134's extracted statements establish the single-state/snapshot obligations (A3, V0, V2, MIC-4/6) and the global-exclusion cost the persistent root dissolves, but do not themselves recommend a persistent-immutable data-structure realization. If the note's prose does, cite it; otherwise attribute the `im`/`ArcSwap` choice as the design's own mechanism for discharging those clauses.

7. **[SHARPENING] — Spell out how recovery decides genesis is "still reachable" on the `BadCheckpoint` fallback.** §6/§7 say fall back to genesis "only while nothing below it has been reclaimed"; the concrete test (the earliest surviving segment's range covers the first assigned Seq, i.e. `firstSeq` = 1) is inferable from the segment metadata but worth one clause, since getting it wrong folds deltas onto a base missing a reclaimed prefix.

**2. Verdict**

The design's owned capabilities are all present and concrete, its conflict resolutions (composite-vs-batch atomicity, single-writer-vs-per-home, durable-before-visible) are stated and sound, and the composition-contract discipline is honored — but item 1 is a material under-specification in the recovery algorithm that contradicts the design's own stated guarantees in a reachable corner case, and a builder cannot resolve it from the document alone.

VERDICT: REVISE
