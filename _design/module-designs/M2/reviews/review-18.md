## Revision list

1. **[SHARPENING] §2: disambiguate `K.λ` (ASN-0047) vs `K.λ_sh` (ASN-0134) as one step at two layers, not two journaled records.** §2 lists `K.λ_sh` in the `→_sh` trio *and* "K.λ link allocation" among "the further ASN-0047 records the trio does not enumerate" — but `K.λ_sh` (ASN-0128's gated emission) *is* gate-check-then-`K.λ`-allocation, so the trio does enumerate the link step (as `K.λ_sh`); only the journaled deposit is `K.λ`. State the layering explicitly (gated *operation* `K.λ_sh` ⇒ allocation *record* `K.λ`/`LinkRec::Emit`) so no builder infers two distinct link-allocation records. The conclusion §2 draws (Seq refines, not equals, `idx(σ)`) is unaffected; this is purely the taxonomy.

2. **[SHARPENING] Pin the `key(home, …) -> LockKey` *constructor* to the shared base crate, distinct from the tag *enum* in `skep-kernel`.** The design correctly places the central space-tag **enum** in `skep-kernel`, but the seam examples freely call `key(d, s_C)` / `key(home, s_L)` without naming the constructor's home. Per the Engine Composition Contract that constructor names *both* `Address` (M1) and `LockKey` (M2), so it **cannot** live in `skep-kernel` (no M2→M1 edge) and must sit in the shared base crate over `skep-address`+`skep-kernel`. Add one line where the seams first use `key(...)` so a builder doesn't try to export it from `skep-kernel`.

3. **[SHARPENING] Mark the A5 attribution "atomicity must be built above the substrate" as a paraphrase, or pin it to ASN-0134's prose.** It is quoted verbatim (twice) and carries weight in Conflict #1 and the "not M2's" list, but it does not appear in the provided A5 (`NoBatchIsolation`) statement digest. The *substance* (an `m≥2` batch's atomicity is the caller's, above the substrate) is faithful to A5; only the quote marks overclaim. Soften to a paraphrase so the witnessed/unwitnessed criterion isn't read as a literal A5 clause.

4. **[SHARPENING] §3: re-attribute the intra-composite example from "S3★ after K.α but before K.μ⁺" to K.μ⁺'s own precondition.** S3★ is a per-state invariant that holds *vacuously* at the post-`K.α`/pre-`K.μ⁺` intermediate (no V-position yet binds the new content); the thing actually checked at `working()` is `K.μ⁺`'s precondition `a ∈ dom(C)` (which the prior `K.α` satisfies). Attribute the example to that precondition — the mechanism (`working()` reflects staged records for ordered intra-composite checks) is right, the invariant label is loose.
