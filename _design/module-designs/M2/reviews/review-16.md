## Review: M2 — Transaction, Journal & Concurrency Kernel

I scrutinized this against buildability, fidelity to ASN-0047 / ASN-0134, boundary discipline, the three stated conflicts, altitude, internal consistency, and the Engine Composition Contract. I could not find a material defect. The public API typechecks against the composition contract (`apply` fold, `transact<T,E> -> Result<(T,Seq), TxnError<E>>`, `Snapshot` newtype, `Staging::push(W::Record)`); all seven MIC clauses are discharged (1/4/6 by the immutable `ArcSwap` root + one-`Snapshot` threading, 2/5/7 by the single applier subsuming the keys, 3 by post-install return); A5/A7 and the ASN-0047 composite boundary are faithful (composites = one closure, J-couplings left to M5, durable-before-visible reconciles Conflict #3); and the boundary is clean — no address/frontier/coverage math, no request lifecycle, no J-enforcement. The recovery core (two-pass, marker-as-ack, `Seq > S_load` filter against a non-idempotent `apply`) is concrete and sound, and the design pre-empts its own blind spot (post-commit rot) honestly. The deferral of per-key concurrency behind an invariant `transact`/`LockKey` seam is a legitimate Lampson-style v1 (over-satisfying ASN-0134 G1's weaker contract), not a dropped capability.

The remaining items are non-load-bearing.

1. **[SHARPENING] Tighten the recovery corruption-classifier so the harmless and fatal regions don't both claim the boundary frame.** §7 defines the harmless region as "the *whole corrupt run* at or below `S_load`" but defines the fatal region by the run's *inferred upper bound* `at` = the next intact frame's `Seq`, and sets `Corruption{at}` halt for `at ∈ (S_load, W]`. These collide at `at = S_load + 1`: the corrupt frames are then all `≤ S_load` (harmless, already embodied in the checkpoint), yet `at > S_load` trips the halt — a safe-side but spurious refuse-to-open. Make the *classifier* the run's inferred **max** (≈ `next_intact − 1`, i.e. "any corrupt frame has inferred `Seq > S_load`"), and keep `at` = next-intact-`Seq` only as the error *payload*. State explicitly how a run straddling `S_load` (some frames `≤ S_load`, some in `(S_load, W]`) classifies (fatal — it has a needed frame).

2. **[SHARPENING] Make the downstream seam sketches obey the Engine Composition Contract they cite.** The M5/M7 sketches write `stg.push(Record::ContentAlloc{…})` (naming the engine's central `Record`) and `recompute_max_under(stg.working(), …)` (passing `&W` where the contract's pure step takes `&XState`). A store crate cannot name `Record::Variant`, and the contract mandates `stg.push(content_rec.into())` plus reaching the slice via the accessor (`stg.working().ns()`). The compiler will catch a literal copy (the cycle is compile-enforced), but the example contradicts contract (3) / the reviewer checklist in M2's own document — rewrite the sketches to push the store's own `XRec` via `.into()` and read upstream slices through `HasX::x()`.

3. **[SHARPENING] State the `Seq`-vs-`idx(σ)` correspondence once and reference it.** The same multi-sentence explanation (refines 𝔼 / →_sh subsequence isomorphic to the finest 𝔼 / install-order for over-satisfied runs / no caller derives `idx(σ)`) appears verbatim three times — the `Seq` doc-comment, §2, and the Invariants section. Consolidate to §2 and cross-reference, so the three copies can't drift.

4. **[SHARPENING] Add the documented derives to `LockKey`.** The prose says "M2 only Eq/Hash/Ord-s the bytes," but `pub struct LockKey(pub Vec<u8>);` derives nothing. Add `#[derive(Clone, PartialEq, Eq, PartialOrd, Ord, Hash)]` (or note they land with the deferred per-key lock table, since v1's global applier never compares them).

5. **[SHARPENING] Align the M7 dedup seam with the "uniform `working()`" rule.** The M5 seam mandates reading `stg.working()` "NOT `base()`," but the M7 idem=⊤ sketch reads `m7_active_in_class(stg.base(), …)`. They're equal at that point (nothing pushed before the dedup read), so it's correct — but use `working()` for consistency, or add a one-line note that the dedup read precedes any push so `base()` suffices.

VERDICT: CONVERGED
