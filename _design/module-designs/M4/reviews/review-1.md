One material hole and several sharpenings.

## Revision list

1. **[DEFECT] `Val` is unusable across module boundaries — add a constructor and a read accessor.** `pub struct Val(Arc<[u8]>)` has a *private* tuple field and the only `impl` block is on `ContentStore`. So (a) M5 cannot construct a `Val` to pass into `stage_write`/`store` (which take `val: Val` by value), and (b) M6's RETRIEVEV and M9's def read-back cannot extract bytes from the `&Val` that `value_at` returns. This breaks the module's headline job — moving bytes in and out — and directly contradicts the stated seams ("the K.α step M5 folds," "`value_at` → M6/M9"). It is also the one internal-consistency break: the public interface names a type (`Val`) the producers can't build and the consumers can't read. Add `Val::new(bytes: impl Into<Arc<[u8]>>) -> Val` (or `From<Vec<u8>>`/`From<&[u8]>`) and `fn as_bytes(&self) -> &[u8]` (or `impl AsRef<[u8]>`/`Deref<Target=[u8]>`), keeping it free of identity `Hash`/`Eq` per S4. Since `value_at` is per-atom, state explicitly that M6/M9 reassemble a multi-atom object (text run, predicate-def body) by iterating `value_at` over `shift(start,k)` for `k = 0..m-1` (mirroring RETRIEVEV), not by a single `value_at` at the start-address.

2. **[SHARPENING] Make the shape-gate pseudo-code real Rust.** `addr.element_field().len() ≥ 2` does not typecheck — `element_field()` is `Option<&[Nat]>`. Step 1 already guarantees `addr.level()==Element` (⇒ `element_field()` is `Some`), so write `addr.element_field().is_some_and(|e| e.len() >= 2)`. Define `s_C` as an explicit constant (`= 1`, ASN-0093 `SubspaceConventionAxiom`; M1 `subspace`: 1=text) and build the comparison value as a `Nat`, rather than referencing `s_C` bare.

3. **[SHARPENING] Repair the out-of-line `Val` recovery story (Open 1).** "journal-by-offset … rebuilt by journal scan" contradicts M2's reclamation contract: M2 reclaims journal segments *wholly below the oldest retained checkpoint*, so pre-checkpoint `ContentWrite` records are gone and a journal scan cannot rebuild the handle-map — and permanent content cannot live in the reclaimable journal at all. Qualify the alternative: out-of-line storage requires a *separate durable blob store*, with the `Address→Handle` map either checkpointed normally or rebuilt from that blob store (M2's `rebuild_derived` seeds from *authoritative state*, not a journal scan).

4. **[SHARPENING] Soften the S3-timing claim.** The ASN-0036 digest presents S3 as a post-state invariant, not an "open timing question." What makes S3 hold at *every committed snapshot* is the **atomicity** of M5's composite, not "pushing the `ContentWrite` before the arrangement reference within the closure" — intra-closure push order is invisible to committed snapshots and matters only for M5's own `working()` check (M5's concern). Reword to attribute the guarantee to atomic co-commit and drop the "resolves ASN-0036's open question … for free" framing.

5. **[SHARPENING] State the serialization assumptions.** `#[derive(Serialize, Deserialize)] ContentStore { map: im::HashMap<Tumbler, Val> }` compiles only if `Tumbler: Serialize + DeserializeOwned` (M1's published derives show only `Clone/PartialEq/Eq/Hash` — confirm M1 supplies serde or wrap the key), `im` is built with its `serde` feature, and serde's `rc` feature is enabled for `Arc<[u8]>` in `Val`. Make these explicit so the `WorldState` slice actually serializes.

6. **[SHARPENING] Show the engine-glue seams M4 contributes but elides.** Spell out the `World::apply` arm (`Record::ContentWrite { addr, val } => World { content: self.content.apply_write(addr, val), ..self.clone() }`) and the `store` `LockKey` build (central 1-byte space-tag + `document_of(addr)` + `s_C`, matching M5's `(d, s_C)` key so they serialize together). In the test-only `store`, handle `document_of(addr) == None` (a non-document-scoped address) with a clean reject rather than an `unwrap` panic.
