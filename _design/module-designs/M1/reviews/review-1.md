Reviewing M1 against ASN-0034 (tumbler algebra), ASN-0045 (classification), ASN-0053 (span algebra), and the decomposition. M1 is a foundation (no upstream to check fidelity against), so the weight falls on buildability, faithfulness to the three notes, and internal consistency. The boundary discipline is genuinely good — the allocator/frontier→M3, spanfilade→M7, byte-map→M4/M5, and ω→M3 splits are all clean and explicitly stated. The defects below are mostly local but several are load-bearing.

## Revision list

1. **[DEFECT] `pub fn zeros(t: &Tumbler) -> u8` cannot meet its contract and breaks two invariants the design claims "by construction."** `zeros` is defined over the *whole carrier* (`classify` is total and must handle garbage), and T0(b) makes length — hence zero-count — unbounded. A tumbler like `[1,0,1,0,…]` with 259 zeros (admissible carrier input arriving at admission) overflows `u8`: with wrapping arithmetic `259 → 3`, so it classifies as **Element** instead of **Invalid** (silently violating *Partition*); with checked arithmetic it **panics** (violating *never-faults / Off-Domain Vacuity*). Change the return to `usize` (or specify saturating-at-4 semantics and make the scan early-exit once `zeros > 3`).

2. **[DEFECT] The "Address is always T4-valid" invariant has unguarded mint sites — `elem_addr` can mint an invalid `Address`, and the `// Minted only by validate` comment is false.** `Address` is produced by `validate`, `parent`, `checked_inc`, **and** `elem_addr`/`shift_ordinal`. `parent` and `checked_inc` preserve validity; but `elem_addr(p) -> Address` constructs `doc·0·subspace·ordinal` directly, bypassing `validate`, and mints an invalid address whenever `subspace == 0` (adjacent zeros) or `ordinal == 0` (trailing zero) — both admitted by `Nat = BigUint`. Either enforce `subspace ≥ 1 ∧ ordinal ≥ 1` (return `Result`) or route the constructed tumbler through `validate`; and correct the doc-comment to state the real invariant (every `Address` is T4-valid, with the validity discharged at each mint site) rather than "minted only by validate."

3. **[DEFECT] The T6 "field-absence ⇒ NO" contract is not relayed; the natural `Option`-equality implementation of the containment predicates silently violates it.** T6(b)/(c)/(d) explicitly return **NO** under asymmetric *and symmetric* absence, but the design only says "truncate-and-compare on parsed fields (T6 a–d)." A builder implementing `same_account` as `a.account_field() == b.account_field() && same_node(a,b)` gets `None == None ⇒ true`, so two **Node** addresses report "same account." State the rule for `same_account`/`same_document`/`under_document`: if either operand lacks the required field (`account_field`/`document_field` is `None`, equivalently `zeros < 1`/`< 2`), the answer is `false`.

4. **[DEFECT] `hull` is under-specified relative to the document's own altitude — its construction is left "somehow."** Every sibling operation states its formula (`intersect = (max start, min reach)`, `merge = (min start, max reach)`, the S11d dispatch table), but `hull(points) -> Option<Span>` gives only "a covering span (convexity, S0)." A builder cannot implement it without re-deriving from S7: the exclusive upper bound (`reach = inc(max(P),0)`, which is `> max` and length-preserving by TA5(a)/(c)), the level-uniformity requirement of the single-span hull (`#min = #max`, else WF can't fire), and the empty/`None` and non-uniform cases. Pin the construction — e.g. `if P.is_empty() || #min ≠ #max { None } else { Some(from_endpoints(min(P), inc(max(P),0))) }` — and state whether the general `|Σ|=|P|` unit-span cover (which S7 also offers, and which works for non-uniform P) is in scope or deliberately omitted.

5. **[SHARPENING] `shift(v, n: &Nat) -> Tumbler` drops the `n ≥ 1` precondition from OrdinalShift/OrdinalDisplacement and is typed total, but `v ⊕ δ(0,#v)` is undefined (`δ(0,·)` is Zero, failing `Pos(w)`).** State the `n ≥ 1` precondition (debug-assert), define `shift(v,0) = v` as the total extension, or return `Result`. (`shift_ordinal` is unaffected — `ordinal += 0` is harmless.)

6. **[SHARPENING] `canonical_key`/`equiv` are typed total but depend on the fallible `normalize`, and `CanonicalForm` is undefined.** `normalize -> Result<_, LevelMismatch>`, so `canonical_key(&SpanSet) -> CanonicalForm` and `equiv(_) -> bool` need either a `Result` return or a documented level-uniform precondition. Also define `CanonicalForm` (it must be `Hash + Eq` to serve M7's dedup key) and derive `Hash` on `Span`/`SpanSet` — currently `Span` is `PartialEq/Eq` only and `SpanSet` is `Clone` only, so the "content-addressed key" cannot be hashed as written.

7. **[SHARPENING] The subtree-capture (1-position) convention (ASN-0034) is not relayed, though T5 contiguity is claimed as a by-construction invariant.** ASN-0034 lists subtree-capture as a required span capability. It is reachable via the provided primitives (`subtree_of(p) = from_endpoints(p, inc(p,0))`), but a consumer can't derive it from this document. Add a one-line helper or note so the T5 guarantee is exploitable without the source note.

8. **[SHARPENING] `union`'s interface comment `// concat (+ normalize)` contradicts its body ("union is concatenation") and its total `-> SpanSet` return.** If `union` normalized, it would need `Result` (level mismatch). Clarify that `union` is concat-only and never normalizes/fails; normalization is the caller's separate (eager/lazy) step.

9. **[SHARPENING] Raw public `shift` re-opens the TA7a hazard the `ElemPos` wrapper exists to close.** ASN-0034's commitment is that the strip/reattach API make the text→link mis-shift *un-violable by callers*; exposing raw `shift` (which advances a subspace-base `doc·0·subspace` from text to link) lets a caller violate it. Consider making `shift` crate-private behind `shift_ordinal`, or annotate it as an unsafe-for-element-bases primitive. (The design surfaces this as an open decision, which is acceptable, but the "un-violable" wording in the invariant is then overstated.)

10. **[SHARPENING] Reconcile "coverage-class computed in M1" (decomposition, M7's seam) with the design's split (M1 computes the canonical form, M7 derives the class).** The design's boundary (canonical normalization in M1, class *policy* in M7) is sound and preferable, but it diverges from the decomposition's literal wording; state plainly that `canonical_key` *is* the dedup primitive and M7 owns the coverage-class policy, so the apparent contradiction with the decomposition is a deliberate refinement, not a gap. (Likewise note `validate`/`T4Error` commits to "carries the violated clause(s)" while the Open decision lists bare-vs-clause as undecided — pick one.)

VERDICT: REVISE
