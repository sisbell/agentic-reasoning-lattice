# Review: M1 — Address & Span Algebra (detailed design)

Mostly faithful and buildable — the arithmetic, the span engine's collapse to "one comparator + one constructor + min/max," the self-guarding `intersect`, the single-comparison `merge` guard, the `(start,width)`-authoritative/`reach`-derived split, and the level-gate placement all check out against ASN-0034/0045/0053. Two owned primitives are specified incorrectly, and several types/contracts need tightening.

## Revision list

**1. [DEFECT] `parent` is internally contradictory and un-buildable as written.** The stated algorithm — "drop the last component; if that exposes a trailing separator (0), drop it too" — does **not** produce the stated results. For a full content element `[1,0,2,0,5,0,1,9]` (document `[1,0,2,0,5]`, element field `[subspace=1, ordinal=9]`), dropping `9` gives `[1,0,2,0,5,0,1]` (the coarser *subspace-base element*), whose last component is `1`, not a separator — so the function stops there. The result is **not** the document; reaching the document takes a *second* `parent` call. So the example "element→document" is false for the normal I-stream element. Worse, the examples are mutually inconsistent: "version→document" is a same-zeros-level component peel, while "element→document" would have to be a level-coarsening — one rule cannot yield both. A builder cannot determine `parent`'s semantics. **Fix:** pick one precise contract — recommend single-component peel, defined as "the longest T4-valid proper prefix" — and rewrite the examples to match (full-element→subspace-base→document; versioned-document→base-document; document→account; account→node; node→`None`). **And** confirm a clean *I-address → origin-Document `Address`* projection exists for M6's SHOWORIGIN pointwise origin projector, which the decomposition explicitly assigns to M1: `document_field() -> Option<&[Nat]>` returns raw components, not a Document `Address`, forcing M6 to reassemble the address (address-construction logic that belongs in M1). Provide a `document_of(&Address) -> Option<Address>` or a documented parent-chain.

**2. [DEFECT] `subtree_of` over-captures, contradicting its own contract and the T5 invariant.** It is `from_endpoints(p, inc(p,0))`, but `inc(p,0)` advances `sig(p)` (TA5), whereas the subtree-capture 1-position convention advances position `#p` (width `δ(1,#p)`). These coincide only when `sig(p)=#p` — i.e. p has a nonzero last component (every T4-valid address). For a prefix with a **trailing zero**, `inc(p,0)` advances the wrong position: `subtree_of([2,0]) = [[2,0], inc([2,0],0)=[3,0])` admits `[2,1]`, which is *not* an extension of `[2,0]`. This directly contradicts the §6 claim "the span denoting exactly p's subtree" **and** the Invariants' credit that "T5 … holds for any prefix whether or not well-formed, so spans capture subtrees for free (`subtree_of`)." Note `shift` correctly uses `δ` (position `#v`) while `subtree_of` uses `inc(·,0)` (position `sig`) — the two are conflated. **Fix:** use `from_endpoints(p, p ⊕ δ(1,#p))` (advance position `#p`), or restrict the parameter to `&Address` and drop the any-prefix claim. (`hull`'s use of `inc(max,0)` is fine — it only needs a cover, and `inc(max,0) > max` always holds.)

**3. [SHARPENING] Declare the error types named in signatures.** `EmptySequence`, `T4Error`, `AddPrecond`, `SubPrecond`, `GateViolation`, `LevelMismatch`, `WfError`, and `SplitError` are referenced in return types but never declared (only `T4Clause`, `T12Clause`, `ElemError` are). All are inferable, but a build-spec should show them — in particular `T4Error` carrying `T4Clause`(s) (its first-failure-vs-full-set granularity is correctly left as an Open decision; its declaration is not).

**4. [SHARPENING] Add `impl PartialOrd for Tumbler`.** Rust requires `Ord: PartialOrd + Eq`; the interface impls `Ord` and derives `Eq` but omits `PartialOrd`. State it delegates to `cmp` (consistency required).

**5. [SHARPENING] The `&[Nat]`-returning field projections pin tumbler storage to a sliceable form.** `node_field/account_field/document_field/element_field -> (Option<)&[Nat]` cannot be implemented over an `im::Vector<Nat>` backing — which is offered as a tumbler-storage option under Open decisions. The recommended inline default works; either state the constraint explicitly or return an iterator/view so the open storage choice stays genuinely open.

**6. [SHARPENING] Tighten the S10 attribution.** §7 and the Invariants cite "(S10)" for union being "commutative, associative, **and idempotent**." Per S10's formal statement (and the ASN-0053 digest's own note), S10 states *only* commutativity and associativity; idempotence — which the join-semilattice/CRDT claim relies on — is a *derived* corollary. The claim is true; the citation is loose.

**7. [SHARPENING] State the input contract of `intersect_sets`/`difference_sets`.** §7 describes "a sweep-line over two **already-normalized** inputs," but the functions take raw `&SpanSet` and return `Result<_, LevelMismatch>`. Clarify whether they normalize internally (consistent with the error type) or require pre-normalized inputs as an unenforced precondition.

**8. [SHARPENING] Two prose imprecisions.** (a) `inc(t,k>0)` "descend k levels" conflates component-depth with hierarchy-level — `k=1` is a *same-zeros-level* version, `k=2` descends one zeros-level (the operation itself, append `k-1` zeros + `1`, and the gate predicate are correct). (b) `hull`'s "level-uniform point set" precondition is really the weaker `#min = #max`: by convexity the hull covers a mixed-length P whenever min and max share a length, and the operative `None` check is already `#min ≠ #max`.

VERDICT: REVISE
