## Revision list

**1. [DEFECT] — Implementation approaches §1: the full scan is *not* "effectively Green's behavior."** The digest says the full scan of `Σ.L` ("for each address evaluate `sat`") "is effectively Green's behavior — it runs the full enumeration and walks the result," and then in §2 says the per-slot index "is exactly Green's spanfilade." These contradict each other, and the §1 attribution is the wrong one. Per Q11/Q12, Green's count calls `findlinksfromtothreesp`, which does V→I translation + **spanfilade (indexed) search per endset** + intersection, then walks the result list — Green never evaluates `sat` against every link in the store. Green is the indexed path of §2, not the linear scan of §1. Fix: present the full scan as the builder's *simplest contract-faithful baseline* (which Green does **not** use); move the Green attribution, the cost-equivalence ("counting costs exactly as much as enumerating," Q11), and "exploits no asymmetry" to the indexed §2 path. The "build the scan first, add the index later" advice can stay as builder guidance, but must not imply Green = scan with the index as a later add-on — Green's spanfilade was there from the start.

**2. [SHARPENING] — Guarantees / "What must be built": surface the reverse-orphan trap explicitly.** The digest states home is "a membership test on the address projection `home(a)`," which is correct, but never names the dramatic instance the note and Q17 dwell on: a link whose *own* entry in its home document's arrangement has been deleted still contributes to a **home-bounded** count, because `home(a)` is read off the permanent address and never recomputed from `Σ.M`. Add a one-line warning — *do not implement the home filter as an arrangement-presence test* — since that is the one way a builder would silently violate both CN-LOC and CN-STAB here.

**3. [SHARPENING] — Persistence and recovery: the in-memory link store is not a "hint."** The digest lumps "the in-memory link store, the `nullified` set, the per-slot indexes, and any count cache" together as "hints rebuilt by replay." All four are rebuilt by replay, but only three are *hints* in the Lampson sense (derived, discardable, recomputable). The in-memory link store is authoritative working state materialized from the durable append-only log — calling it a hint blurs precisely the state-vs-hint distinction the digest leans on everywhere else. Separate them: the log is durable, the link store is its working materialization, and `nullified`/indexes/cache are the discardable accelerators.

**4. [SHARPENING] — Implementation approaches §4: `q*` returns the *active-view* size, not the "store size."** The bullet correctly opens with "counts the whole active view, `|addressable|`," then closes by calling `q*` "the trivial store-size boundary case." `dom(Σ.L)` includes nullified links; `|addressable|` excludes them — the very distinction CN-RETRACT is built on. Tighten "store-size" to "active-view-size" so the boundary case isn't conflated with the full store.
