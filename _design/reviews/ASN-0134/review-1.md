**Revision list**

1. **[DEFECT] Approach 5 (contiguous runs): "pre-reserve a block of `m` frontier slots … and then fill them, shortening the exclusive window" is unsound on this substrate — and the digest's own (correct) scope note proves it.** The frontier *is* the population count (H0: `φ_S = |P_S|`), and contiguity (W3 / ChainMembershipForOrigin) requires the populated slots to be a **gapless** prefix. If you reserve `[φ, φ+m)` but let a foreign same-`(d,s_C)` writer advance — the only writer the digest rightly says can threaten the run — it either collides on slot `φ` (the count hasn't moved) or, if your serializer skips it to `φ+m`, leaves `φ..φ+m−1` empty while `φ+m` is filled: a gap, i.e. a non-canonical state (violates W3 *and* A6). The only gap-free option is to keep that writer out for the whole run — which *is* holding the lock, so nothing is shortened. Pre-reservation can save the `m−1` redundant frontier reads (per-step overhead) but cannot shrink the exclusion span below the run's duration; doing *that* would require batch read-atomicity, which is strictly stronger than clause 5 and is explicitly Open Question 5. Fix: drop "shortening the exclusive window"; reframe pre-reserve as a per-step-overhead optimization that still holds the run-length exclusion, or as OQ5 over-satisfaction — not as a cheaper realization of clause 5.

2. **[SHARPENING] "What must be built" / "How it fits" / SAFE(c): state the note's explicit `K.σ` scoping boundary.** The note is emphatic that MIC has *no* document-registration clause: document-address freshness (distinct agents proposing distinct fresh `d`) is an **assumed upstream precondition** (the excluded entity-allocation layer's job), not a MIC obligation, and a same-`d` registration race is resolved by **cleanly rejecting the loser** (there is no frontier to advance), structurally like the nullify rejection. Add this to the "excludes / someone else's job" list and name the reject-loser semantics, so a builder neither over-engineers a registration serializer nor mishandles the collision. (Your `(d,S)`/sub-allocator framing already *implicitly* excludes `K.σ`, but the note draws this boundary on purpose — say it.)

3. **[SHARPENING] "Guarantees → Explicitly given up": add the residual idem=⊤ order-dependence.** The list cites SC/program-order, batch atomicity, durability, and idem=⊥ duplication, but omits the note's load-bearing point that an idem=⊤ emit's *outcome* stays order-dependent even under full MIC. Instance (ii) — a lone idem=⊤ emit racing a `Nullify` of its coverage-equal active incumbent — reaches different committed states (`∅` vs `{A'}`) by order, and is reduced by **neither** clause 8 (it governs racing *emits*, of which (ii) has one) **nor** emit-before-retract (vacuous, the incumbent is already emitted). Clause 8 removes only the *duplicate* (instance i); this which-survivor/present-vs-absent non-confluence is benign for uniqueness but persists. State it so a consumer does not over-rely on idempotent determinism.

4. **[SHARPENING] Approach 6 / nullification: "target isn't yet present → reject" is too coarse — it drops P-tgt's second disjunct.** `P-tgt = a ∈ A_rel^Σ ∨ a = a_emit(Σ, d_retr)` (W5). A nullify of the retractor's *own* next frontier slot (target absent from the store yet equal to `a_emit`) **fires** — depositing its R-tuple on that slot and self-nullifying (W5 case 2) — it does not reject. The authoritative instruction ("check P-tgt at the nullify's own linearization state") is right; spell out the disjunction so the rejection rule reads "absent **and** not the retractor's own emit slot → reject," not "absent → reject."

5. **[SHARPENING] "Guarantees → Hold by construction": echo the note's A6/W3 boundary.** A6 (full canonicity) is listed as held-by-construction, but the note carefully isolates A6's *chain-contiguity conjuncts* (ChainMembershipForOrigin / L-ContiguousPrefix) as exactly W3 — serialization-borne, not model-intrinsic — which you (correctly) also list under "require active enforcement." Both are true under your conditioning, but make the split explicit: A6 is fully canonical *on a valid `𝔼`*; producing a gapless `𝔼` under per-home concurrency rides on clause 2, and only A6's *non*-contiguity conjuncts hold from A0 alone.
