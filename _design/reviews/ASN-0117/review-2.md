## Revision list (most important first)

**1. "Decisions for the builder → Within-document sharing": stop presenting a settled model fact as an open decision.** The item says "decide whether the model allows one document to arrange the same I-address at multiple V-positions." The note settles this: the arrangement model **permits** it (S5/M13), and the note's semantics *depend* on it — the worked example sets `a_2 = a_5`, and `A_del^{excl}`/the wp exist precisely to handle it. Reframe: state that within-document sharing is permitted by the underlying model, so it is not a "whether" but a "given"; the real builder obligation is that **removal-verification and discovery/index-retraction must reason by count and last-witness (`A_del^{excl}`), never by per-pair removal** — a shifted survivor can reoccupy a deleted slot *label*, so "is this V→I pair gone?" is the wrong test (this is the note's count-and-label form of DEL-REMOVE, which the digest currently never surfaces).

**2. "Implementation approaches §1 (relative-displacement option) and §7": fix the run-representation mechanics for no-zero-width and for what gets shifted vs. split.** Two coupled problems. (a) In approach 2, "the shift is applied to boundary crums" is imprecise — Green left-*shifts* the **suffix** entries (`tumblersub`, case 2; Q13) and *splits* only the entries that straddle a cut, and only on **strictly-interior** cuts (`slicecbcpm` fires iff `THRUME`; Q11/Q12). (b) §7's no-zero-width advice — "preserve that by only ever cutting at existing boundaries (boundary-aligned cuts need no splitting at all)" — holds only for the one-position-per-unit map (approach 1). The enfilade you recommend *at scale* coalesces content into multi-unit runs, so a delete endpoint can land interior to a run, and the guarantee then comes from **splitting that run into two positive-width halves (the strict-interior guard), not from boundary-only cutting** — which is exactly the "cut/slice at boundaries" machinery approach 2 already lists. As written, §7 contradicts approach 2's own cost line. State the split-into-positive-width guard as the no-zero-width mechanism for the run representation.

**3. "How it fits" / "Decisions → Concurrency unit": ASN-0134 is an ungrounded citation.** "Hands concurrency to the consistency/isolation model (ASN-0134)" names a specific note that appears in **neither the source note nor the evidence** — the note raises concurrency only as an Open Question and names no target. Either confirm ASN-0134 exists and is the right target (the note is dated six days before this review, so a higher-numbered note may not yet exist), or soften to "a concurrency/consistency layer (note TBD)." Don't assert a dependency the source doesn't.

**4. "Design commitments → Two layers" / state model: name the link store as a second, disjoint codomain of the arrangement.** The compact model — content store `C : I-address ⇀ Value` plus arrangement `M(d) : V-position ⇀ I-address` — glosses that `M(d)` ranges into **two disjoint stores**: the content store (text-subspace positions → `dom C`) and the **link store** (link-subspace positions → `dom L`), disjoint by SD. This is precisely what makes the "links survive by construction" guarantee true (a text delete touches neither link positions nor the link store, DEL-FSUB) — the digest asserts that guarantee but never gives it a model basis. Add the link store to the headline state. (Minor adjunct: the note also stresses V-positions are a *shared vocabulary* — the same tumbler `q_1` means different content in `d` vs `d'`; document identity lives in `M`, not in the position — worth one clause where you discuss document isolation.)

**5. "What this is": scope "the exact symmetric inverse of INSERT" to the arrangement layer.** The symmetry is only the V-shift (left vs. right). At the content layer the two are *not* inverses — INSERT of new content appends to the store, DELETE "writes nothing… not even an append" — and that asymmetry is one of the note's headline insights. The digest corrects this later ("arrangement-expansion operation"); carry the scoping up to the intro so the content-layer asymmetry isn't blurred at first read.

**6. Surface the S8★ run fusion/split (completeness, minor).** Closing the gap can fuse or split the maximal V→I correspondence runs (the note's S8★ re-cut): adjacency in V after a delete does not imply adjacency in I. A builder maintaining any run-structured view of the arrangement (or naming span regions over it) must recompute the decomposition post-delete. One line, likely in §3 or Guarantees.

**7. Backtrack: flag that you are answering OQ4, not restating a commitment (minor).** "What must be built → Backtrack support" presents the retained-old-mapping requirement as flat fact. The note commits to backtrack as a *presumed capability* but leaves the exact mechanism and required-retained-state **open** (Open Question 4). Your inference (the bytes persist, the mapping does not, so the old mapping is what must be retained elsewhere) is the right answer — just mark it as the digest's proposed resolution of OQ4 rather than a note guarantee.
