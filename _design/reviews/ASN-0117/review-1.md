This is a strong, evidence-dense digest: it reads ASN-0117's core (de-arrange ≠ destroy, content-store-in-frame, gap-closure, subspace/document confinement, link-by-I-address) accurately and at the right altitude, and it puts the verified Green evidence (Q4, Q11–Q20) to excellent use — especially the principled-vs-accidental subspace nuance, the "acknowledge-before-work is silent corruption" cautionary, and NonDestruction-by-construction. The improvements below are mostly about grounding precision and one dropped note element, not about the spine of the design.

**Revision list (most important first)**

1. **Open Questions / Decisions — restore the note's fifth open question (orphan-link cross-document *obligations*); it is dropped.** ASN-0117 lists five open questions; the digest surfaces four (totalization, concurrency→ASN-0134, discovery-index, backtrack) but omits *"what relationship must hold between a deletion that orphans a link from one document and the obligations of the documents that continue to arrange the same content."* The "Link survival" guarantee answers only the *mechanical* half (the link persists; other arrangers are unaffected) and thereby silently treats as settled what the note explicitly leaves open — the *policy* of whether still-arranging documents incur any lifecycle/notification/ownership obligation when `d` orphans a link. Add it as a deferred decision, kept distinct from the mechanical survival guarantee.

2. **Implementation approaches §1 (journal-native option) — the `links.jsonl` + `paths.json` reference is ungrounded; cite it or genericize.** "exactly the repo's `links.jsonl` + `paths.json`-recovered-by-replay model" names specific storage artifacts and a recovery model present in *neither* ASN-0117 *nor* the verified evidence (which is entirely udanax-green C: `fns.c`/`edit.c`/`orglinks.c`/…) *nor* documented Green structure, and carries no checkable citation — yet it asserts an existing reference model the builder can mirror. Either add the concrete repo path if those files exist, or restate generically: "an append-only operation journal (DELETE = one record `(d,p,w)`, no content record) with the live arrangement recomputed by replay." The design point (journal-of-edits + materialized view) stands on its own; only the false-specific grounding needs removing.

3. **Approaches §1 (relative-displacement tree) and §4 — stop crediting Green with efficiency mechanisms the evidence doesn't support.** Two over-attributions: (a) "Green realizes exactly this … giving O(log N) work" — but Q4/Q13 show Green's intersection-finder (`newfindintersectionnd`) is *stubbed* to always return the root, so Green never performs the O(log N) descent the claim assumes; and Q20 shows Green mutates in place with level-collapse disabled, so it is *not* persistent. (b) "retained persistent-map roots … *This is why version comparison works in Green*" — Q15 supports only that Green retains the prior version's POOM mapping (so it still resolves those addresses); it does *not* establish structural-sharing/persistent roots. Reword so Green supplies the relative-displacement *representation*, the boundary-shift idea, and retained prior arrangements — while the O(log N) cost, persistence, and structural sharing are properties of the *recommended* implementation, not demonstrated Green behavior.

4. **Guarantees / Decisions — promote the wp result; the note's main analytical output is buried and disconnected from the index strategy.** ASN-0117 derives exactly when discoverability-from-`d` is preserved: precisely when the deleted span removes *no link's last witness in `d`* (`A_del^{excl}`). The digest mentions "last witness" only inside the within-document-sharing decision and elsewhere says merely that discoverability "is a derived read-time fact." Surface it as one named, actionable predicate and connect it to Approach §3: the *same* `A_del^{excl}`/last-witness test that governs within-document-sharing index retraction also tells the discovery-index reconciliation exactly which links' `d`-discoverability could change, and could drive a user signal ("this delete orphans link X from this document"). Right now the digest states this insight twice, partially, without naming it the wp.

5. **"What must be built" — separate the note-forced backtrack requirement from the digest-recommended recovery/journaling mechanism.** "A durable record of the operation and a recovery path that replays arrangement edits" is listed as a must-build, but ASN-0117 says nothing about crash-recovery or journaling — its only related content is the backtrack open question ("what state beyond the content store must persist for backtrack to be exact"). What the note *forces* is retained arrangement state sufficient for exact backtrack; journaling-with-replay is one digest-recommended realization. State the must-build as the note frames it (retained arrangement history beyond the content store) and demote the "recovery path" specifics to the approaches section.

6. *(Minor, altitude)* Approaches §1 — "`im::OrdMap`-style" leans on a specific library; "persistent ordered map with absolute keys" already carries the idea. Keep the library name only as an explicit optional illustration, not as the description.

Sections that are genuinely solid and need no change: **Design commitments** (forced/conventional labeling is correct, including the principled-vs-accidental subspace distinction), **Approach §2** (content-store-frame-by-construction, well-grounded in Q15's two-primitive architecture), and **Approach §5** (validation/acknowledgment-ordering, tightly grounded in Q4/Q13/Q14).
