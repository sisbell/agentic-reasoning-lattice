## Revision list

**1. [DEFECT] — Implementation approaches §5 (and the matching line in *Decisions → Totalization policy*): "a span lying *entirely* before the arranged run is a silent **no-op**" is false for the specified text deletion, contradicts the note, and has the no-op/corruption assignment backwards.**

The digest attributes the no-op to "no positions fall in range, and the displacement-subtraction's exponent guard leaves survivors untouched." Both halves fail for the operation being specified:
- "No positions fall in range" only kills the *deletion* (case-1); for a span entirely before the run, **every** surviving position is classified *after* the cut (case-2) and is shifted left — so "no deletions" is not "no effect."
- The exponent guard that would suppress that shift fires only **cross-subspace** (width `exp=−1` vs. link position `exp=0`, Q18). The specified operation is a *text* delete, whose width shares the text positions' ordinal granularity (`exp=−1` on both), so the guard does **not** fire. The survivors shift left by the spurious out-of-range width into invalid/non-positive positions — i.e. corruption. This is exactly Q4's same-exponent Code Exploration (crum 5 → 3), the abstract `OrdinalExceedsDisplacement` failure, and the note's own blanket verdict: "Outside containment the implementation exhibits not an alternative semantics but a silent corruption."

The genuine out-of-extent no-op is a span lying **entirely past the run's end** (`J > N`): all positions are classified *before* the cut (case-0), untouched — no shift, no guard needed. Fix: swap the example — entirely-after is the no-op; entirely-before *corrupts* for a text delete; note that the exponent-guard no-op is a cross-subspace artifact out of scope here. The fail-closed conclusion ("the caller cannot tell which it got → reject all containment failures, validate before mutating, never ack before durable") is correct and should stand — but as written this paragraph also contradicts the *Guarantees* section ("an out-of-range span produces ... negative/unreachable positions"), so reconciling them is required.

**2. [SHARPENING] — §5: "shifts in-range survivors left ... into negative, unreachable positions" overstates one corruption mode.** Straddling the document's start can also produce *positive-but-wrong* (overlapping/misplaced) positions — Q4's straddling example moves a crum from V=7 to V=1, not negative; the negative-and-unreachable case (Q13/Q14) is one mode, not the only one. Say "invalid positions (negative-and-unreachable, or positive-but-misplaced)."

**3. [SHARPENING] — P4 / *Decisions → Orphan-link obligations*: distinguish per-document undiscoverability from global orphanhood.** The digest consistently frames discoverability loss as "from this one document," which is right for the common case, but never names the case where `d` was the link's **sole** arranger — there the link becomes *globally* undiscoverable (a ghost, LP17 GhostProjection) yet still persists and is recoverable on re-arrangement. The persistence is covered; the global-ghost outcome and its boundary (sole-arranger) are worth a clause so a builder doesn't assume a link is always findable from *some* document after a delete.

Everything else checks out — including the points most at risk in a digest like this: it does **not** propose value-based dedup (it correctly keeps identity-by-origin and routes re-discovery through identity-preserving copy, not insert, per Q19), it keeps the content-store frame structural rather than a discipline (Q15), and it treats the discovery index as a monotone hint with read-time post-filter (Q16) rather than maintaining it on the write path.
