This is a strong, committal digest: the forced/conventional split is accurate, the default approaches are sound, and every Green source-level claim it makes is grounded in the evidence answers (no fabricated function names). The items below are mostly precision fixes; the first three are real accuracy/soundness issues on recommended approaches.

**1. Registry/index and Provenance sections — "cross-owner version discovery" overstates what the provenance/content index can do.** Both sections claim the address→document reverse index makes "cross-owner version discovery computable." Per V9w/VD the shared-content witness is *symmetric* (does not orient derivation) and *not version-specific*: a COPY or transclusion sharer produces the same dual-provenance rows — the evidence is explicit that a shared I-address appears in the spanfilade "once per document that has ever placed content at those addresses via INSERT, COPY, or CREATENEWVERSION" (Q17). So the index recovers content-*sharers*, of which cross-owner versions are a state-indistinguishable subset; for A=∅ there is no state trace at all, and in every case the fact "v is a *version* of d_src" survives only as the out-of-state `derives` event. Fix: in both sections, say the index recovers content-*sharing* (necessary, not sufficient, for being a version) and that distinguishing version-from-copy and orienting derivation are *not* state-computable across owner boundaries — aligning the index language with the honesty already correctly stated in the "Derivation orientation" decision. Otherwise a builder ships a "find cross-owner versions" query that silently returns copies too.

**2. Implementation approaches (Registry, Snapshot) — the default recommendation (C, structural sharing) hinges on an engine premise the note doesn't establish, and names a library type.** The italic aside asserts a committed "Rust + `im` crate" target (citing `notes/rust-implementation.md`); the snapshot default ("Pick C") and the registry ("`OrdMap`") ride on it, but the note is engine-neutral and neither it nor the evidence establishes this target. (Flag for the reviser: verify that citation — prior project direction in this repo was Dafny-based, so the Rust/`im` claim may be stale or mis-attributed.) Fix: (a) keep the *default* engine-neutral — structural-sharing/COW is the default *only* on a persistent-immutable engine; otherwise re-derive-and-reblock (B, exactly what udanax-green does) is the default; (b) if the target is genuinely committed, cite it once as an explicit external dependency, not as the digest's silent premise; (c) lift `OrdMap` → "persistent ordered map" to hold design altitude.

**3. Atomicity approaches — orphan-closure is mis-attributed to the journal.** "Pick A … run B's journal underneath … removes the orphan case" contradicts the evidence: udanax-green leaves the orphan *under exactly* single-threaded run-to-completion (A), because the orgl is already allocated in memory when population fails (Q8) — "no other request can run during this window," yet the orphan persists. Orphan-closure comes from the *commit-or-discard / publish-new-immutable-value* half of B (an aborted fork never publishes), not from durability journaling. Fix: attribute orphan-closure to publish-on-commit, state plainly that A alone does not close it (Green is the cautionary case), and note that on the persistent-value model in-memory commit and journal commit coincide — which is why the orphan vanishes there but not on an in-place-mutation engine.

**4. Provenance recording — flag that an R row asserts *once-contained*, not *currently-contains* (OQ7), which bears on the reverse-index use.** Because R is append-only (P2), a row (a, v) survives the version later contracting a off its arrangement; an R-by-address correspondence/discovery query can therefore return a document that no longer arranges the shared address. Add one line: downstream "currently shares" queries must filter reverse-index hits against current arrangement — the row is historical-containment evidence, not a live-membership assertion. This is OQ7 and it compounds item 1's version-vs-sharer point.

One line.
