Below is the revision list. The digest is strong — well-grounded, correctly altitude'd, and it gets the genuinely hard part (the three-way split between empty-recorded, invalid, and resolution-shrinkage) exactly right. The items below are the improvements worth making, defects first.

---

**1. Guarantees (F6) / Design commitments — restore the "confinement is not confidentiality" correction; it is load-bearing and currently missing.** The note builds its entire F6 framing on Nelson's Q5 correction: Xanadu makes *no* secrecy promise about a link's other ends — "bidirectional discoverability is the whole point," the siblings are *deliberately* reachable through other operations, and the property is therefore *operational confinement* ("this op computes only slot i"), not confidentiality. The digest extracts F6's coverage-vs-representation structure but drops this foundation, and its bare "Nothing of the other ends" reads like a privacy guarantee. A builder could mis-design on that: add access controls around FOLLOWLINK, or treat representation-level sibling-leakage (which the digest correctly says is a *non-guarantee*) as a security vulnerability rather than a free choice. Add a sentence to the F6 entry: SlotConfinement is scope, not secrecy; the other ends are intentionally discoverable elsewhere; F6 is not an access-control boundary.

**2. Implementation approaches → Link lookup (and Guarantees F4) — "lock-free reads concurrent with the appending writer, which is exactly F4" misstates F4.** F4 is a non-mutation frame condition evaluated against a *single* state Σ; it says nothing about concurrency or what a reader observes during a concurrent write, and it is satisfied by *any* read that doesn't write — no persistent map required. As written, the digest equates a concurrency-consistency property with the pure-read frame, which could lead a builder to believe F4 mandates lock-free concurrency. Reframe: F4 holds by construction for any read touching only immutable/snapshot state; the persistent (structurally-shared) map's actual payoff is *consistent point reads under concurrent appends* — a concern the note never raises. Apply the same fix to "A persistent link map gives this [F4] for free" in the Guarantees section (F4 is free for any non-mutating read; the map buys concurrency-consistency, not F4).

**3. How it fits — RETRIEVEENDSETS is conflated with the by-content link-*finding* operation.** The digest asserts "finding links by their endset content is a different operation… Green's RETRIEVEENDSETS is *that* by-content operation." But the evidence's link-finding-by-content operation is `find_links` (`dofindlinksfromtothree`, Q19); RETRIEVEENDSETS (Q17/Q18) is a distinct spanfilade operation that *retrieves endsets partitioned by from/to/type*, not one that finds links — its own description in the same sentence ("partitioning by from/to/type") is endset retrieval, not link finding. Keep the load-bearing contrast (RETRIEVEENDSETS is spanfilade/by-content and shares only the endset→span-set conversion; it is *not* a by-address all-slots FOLLOWLINK), but stop equating it with "the find-links-by-content operation" — attribute link-finding to `find_links`, or drop the equation.

**4. Endset→span-set emitter / Guarantees (F2) — tighten "F2 is a read-side duty."** The note is explicit that F2 "is not an independent requirement — it follows from F1," and "coverage exactness alone enforces it." There is no separate F2 to enforce: merging across a gap is itself an F1 violation (over-coverage), not an F2 violation. Calling F2 a "duty… discharged by verbatim emission" risks implying it needs its own check. Reframe: F2 holds automatically for any F1-satisfying result; the only genuinely separable piece is the upstream assumption that CREATELINK stored the discontiguity unflattened — which the digest already states cleanly and should keep. Drop "duty," keep the upstream-assumption split.

**5. Implementation approaches → Link lookup — trim the store-durability design to FOLLOWLINK's actual need.** The journal-as-authority + recovery-by-replay + address-registry machinery is the *link store's* concern (ASN-0093), not FOLLOWLINK's; FOLLOWLINK needs only a consistent by-address point read over an immutable (monotone) map. As written, the paragraph designs store durability at length and implies this read operation owns recovery. Either mark the journal/recovery design as inherited and assumed from the store spec, or cut it, so the approach stays at FOLLOWLINK's altitude (the persistent-map recommendation for the *read* is fine and can stay).

What's solid and should be left alone: the design-commitments treatment of the resolution-bundling divergence — correctly distinguished from the F7 empty-*recorded*-endset bug, correctly grounded in Q11/Q15/Q19, and correctly argued as the architectural reason not to reuse the reference path. The F7 domain-guard approach (boundary check first, empty-decision in the core against the endset, "copy RETRIEVEENDSETS's empty-handling not followlink's") is accurate and well-cited. The coverage-vs-representation commitment, the Q13 "verbatim chain is the *exceptional* path, not evidence the reference emits verbatim" reading, the T4-valid disclosure slice, the n-set arity point, and the L3-derived type-slot invariant are all accurate and grounded. Altitude is right throughout — "sum type"/"variant-typed result" lean toward implementation vocabulary but stay at design-pattern level, not signatures.
