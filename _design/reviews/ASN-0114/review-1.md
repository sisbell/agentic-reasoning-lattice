Reviewed the digest against ASN-0114, its claim statements, and the Q11–Q20 evidence. The digest is strong on its central move (de-bundling resolution from the recorded-end read) and on the F7 engineering. The defects below are real; ordered most-important first.

## Revision list

**1. Emitter approach — the Q13 citation presents Green's *exceptional* path as its behavior, contradicting the digest's own de-bundling claim.**
"Green's evidence shows raw endset spans returned by a pure copy chain, exponents preserved, no arithmetic (Q13)" is only half of Q13, and the wrong half to lean on. Per Q13, the pure copy chain applies *only* to pure-I-span endsets (`sporgladdress = 0`), which Q13 itself calls "not the normal operational case." Green's *normal* path (V-spec endsets) recomputes the result by `tumblersub` in V-space — i.e. it **resolves**, the exact behavior commitment #2 (correctly) says "the reference implementation bundled… this spec de-bundles." The note kept both halves ("raw address spans… copy chain, *whereas*… recomputed by tumbler subtraction"); the digest dropped the second. Fix: ground the verbatim-emission recommendation in the note's "the recorded endset is its own witness" (that is what actually licenses copy), and if Q13 is cited, cite it whole, in service of F3/representation-freedom — not as evidence that Green emits verbatim.

**2. "How it fits" / domain guard — RETRIEVEENDSETS is mischaracterized, and the framing is internally inconsistent.**
The digest calls FOLLOWLINK "the single-slot sibling of RETRIEVEENDSETS (all slots), sharing the slot/store machinery" and says "model FOLLOWLINK on that sibling." But per Q17/Q18, RETRIEVEENDSETS takes a *content region* (a specset) and queries the **spanfilade** — the by-content index the digest itself (rightly) says "do not consult here" — partitioning by from/to/three. It is not a by-address all-slots reader. FOLLOWLINK and RETRIEVEENDSETS share only the `sporglset→specset` conversion (`linksporglset2specset`, Q14/Q16), not the by-address path. So "sibling (all slots)" is inaccurate and collides with the digest's own "by-content is a different operation served by the spanfilade." Fix: keep only the valid lesson — RETRIEVEENDSETS handles the empty case correctly (always succeeds, lets an empty end flow out, Q17), so copy *that* empty-handling pattern — and drop the "by-address all-slots sibling / shares store machinery" framing.

**3. Confinement — the digest drops the note's "what the result discloses" half and the multi-document builder decision (OQ5).**
The digest reproduces F6 (coverage-level confinement; representation-level non-leakage is not a contract guarantee) but omits the note's disclosure analysis, which is load-bearing and appears in the synthesis: the result reveals exactly `coverage(eᵢ)`; home-document identity is recoverable only over the **T4-valid document-bearing slice** (`zeros(t) ≥ 2`), because coverage may include node-level (`zeros=0`), user-level (`zeros=1`), ghost (L9), or non-T4-valid interior tumblers that name no document; and success at selector `i` reveals `|link| ≥ i`. The digest's "spans over tumbler space" correctly implies the arbitrary-tumbler generality, but it never states the *partial* document-recoverability, and it omits OQ5 (multi-document coverage reported as one set, document identity recoverable only by parsing each address, and only for document-bearing ones — sufficient?). Add a short "what the result discloses" line and surface OQ5 as a builder decision.

**4. Link-lookup approach — built on an unverified repo substrate and a language/library presupposition.**
The section asserts "this repo's working substrate is… `links.jsonl`… `paths.json`" and recommends the Rust `im` crate "for snapshot consistency." None of this is in the note or the evidence. Naming `im` presupposes a Rust implementation the note never establishes — an altitude slip; name the *approach* (a persistent/structurally-shared map), not a crate. And "snapshot consistency" is over-spec for data the digest itself calls monotone and immutable: FOLLOWLINK does one point lookup, so what it needs is lock-free reads concurrent with the appending writer (that *is* F4), not MVCC snapshots. Fix: verify the `links.jsonl`/`paths.json` substrate against the actual repo before resting an approach on it; pitch the persistent-map idea language-neutrally and justify it by F4 + lock-free concurrent reads.

**5. F2 — the anti-flattening duty is mis-relocated to the writer.**
"The obligation not to flatten a discontiguous end is the writer's (CREATELINK's)… the deeper anti-flattening duty for F2 sits on the writer." But F2 as stated in the note is a **read-side** guarantee: any F1-result over a disconnected recorded end has `≥2` spans ("coverage exactness alone enforces it"). The legitimate observation — verbatim copy is only as faithful as what was stored — is fine, but that is a separate CREATELINK concern (out of ASN-0114's scope), not a relocation of F2. Keep F2 as FOLLOWLINK's read-side duty (don't merge across a gap → no over-coverage); present storage-faithfulness as an upstream *assumption*, not as "where F2 really lands."

**6. Sharpening — make the de-bundling payoff concrete; surface OQ4.**
The de-bundling case is argued well but abstractly. Add the observable divergence: for an orphaned/ghost link, the abstract FOLLOWLINK returns the recorded (non-empty) end, while Green's bundled path returns **empty** (all addresses dropped in I→V, Q15/Q19) and varies by queried document (Q11) — same link, different answers. That is the single sharpest argument for de-bundling and for not reusing Green's followlink, and it is distinct from the F7 empty-*recorded*-endset bug. Minor: OQ4 (must a non-existent higher slot be observationally distinct from an existing-but-empty slot, beyond error-vs-success?) is a real builder question the digest omits.
