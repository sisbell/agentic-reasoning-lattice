The digest is unusually disciplined — the proven/conjectured split (PC6 theorem vs C‑reach/C‑emit conjectures) is handled correctly, the Green evidence is used accurately rather than decoratively, and the footprint‑indexed re‑evaluation built on FP/PD0/PD2 is a faithful, high‑value extraction. The defects below are mostly localized inaccuracies and a few load‑bearing mechanisms left under‑surfaced.

## Revision list (most important first)

**1. Implementation approaches ("Keep span arithmetic inside the leaf") and How it fits: self‑emit is *not* agent‑time — and the digest contradicts itself.** The note assigns self‑emit to the *emit surface*: "the self‑emit check belongs to the emitting surface, which performs it (S3)" (C‑emit, QD‑audit) — the substrate already evaluates it inside `Nullify_Binary`'s P‑tgt at transition time. Only reachability is the agent‑time‑unrolling case. The Design‑commitments section gets this right ("self‑emit is checked on the emitting surface"), but two later passages contradict it: "self‑emit and home‑grouping are agent‑time questions" and "Reachability and self‑emit are likewise *handed out* to agent‑time computation (unroll `succs`, recompute the frontier)." Fix both to match the commitments section — reach → agent‑time; self‑emit → emit surface (substrate emit‑side, not PL, not an agent; "recompute the frontier" is the *emit* surface's FrontierUnification, not a caller's loop). Drop "home‑grouping is an agent‑time question": the note only says no atom regroups by home (inexpressible), not that anyone computes it at agent time. While there, tighten even the correct sentence "neither is handed to the substrate" — self‑emit *is* done by the substrate; the precise claim is "neither is a PL term / handed to the predicate layer."

**2. What must be built / Implementation approaches: surface the `targets_keyed` → `·[K]` path and the `Reg` route.** The digest names the `targets_keyed` producer but never its only consumer — the per‑class map lookup `·[K]` (V‑PRIM), the sole eliminator of the `Map_fin` codomain and, per V‑IDX, the *designed* route to per‑class BH3 verdicts under a `Reg` binder (`targets_keyed(s)[K]` reads the bound class's verdict without applying an atom that class may lack). Relatedly, the Reg‑expander's "reject instances that apply an absent behavior atom" undersells V‑IDX: a class‑indexed behavior atom under `Reg` is *never* well‑formed at any constructible registry (R‑C1 plus `R`'s empty‑behavior record guarantee every registry contains a class lacking every family), so `·[K]` over `targets_keyed` is the *only* way to read per‑class behavior data under `Reg`. Add `·[K]` as a build item and name this route; without it a builder ships `targets_keyed` whose results nothing consumes.

**3. Vocabulary generator / Explicit‑partiality guarantee: make atom totality an atom‑construction rule, not just a composition fact.** The digest attributes totality to "PC5 with PC2's guard discipline," but the guard is the *composition*‑side mechanism. The note's load‑bearing point is *atom*‑side: every ⊥‑adjoined atom is re‑typed total and returns ⊥ *as a value* (`age(a)=⊥` exactly off the active K‑tuples, doubling as an activeness test), because state‑dependent definedness — a retraction turning a defined term undefined — would "poison PC4/PC5's universal claims and the dynamics classification with them." Give the builder the rule: implement every atom as total over its ⊥‑adjoined codomain, never as a partial function; that is *what makes* the guard discipline apply uniformly.

**4. Design commitments: "One view per term" is mismarked forced — the note calls it a convention.** PC3 states the absence of a per‑constituent view parameter "is a convention about atom‑name binding, not an expressiveness fence," with cross‑view readings reconstructible inside any term — which the digest's own view‑machinery section correctly flags as an OQ1 deferral. Reconcile the commitments list with that section: the *forced* part is "three views are three distinct questions over the same Σ"; the *conventional* part is "one top‑level tag, no per‑constituent parameter (OQ1)." As written (unmarked, i.e. forced) it directly trips review criterion 1.

**5. Guarantees to uphold ("expressive ceiling"): distinguish the fold axis from the node‑combinator axis.** PC6's "what the relativization costs" separates restrictions that fail *differently* when dropped. The digest names the two dangerous ones (granularity = span arithmetic, control = feedback) but omits the note's calibration: adding a node combinator is *benign* (V‑PRIM‑style admission, ceiling untouched), whereas adding a *fold* "admits a computation class, not a combinator" (closable only fold‑by‑fold — the parity candidate is exactly such a fold). For a builder tempted to extend the aggregate set, this is the line that decides whether the change is safe; add it.

**6. What must be built (read‑base adapter): split V‑TUP's two per‑tuple regimes.** "Per‑tuple value reads" collapses two regimes the note keeps deliberately independent: the denotation projections (`addr`/`addrs_F`/`addrs_G`) and the coverage‑*membership* tests (`coverage_F`/`coverage_G`). The note is explicit that neither derives from the other — coverage fixes the denoted set only up to its ≼‑minimal elements (PrefixSpanCoverage / I0a's separating pair) — which is *why* both are V‑TUP primitives and why the PC6 converse needs the coverage tests as their own leaves. State that the adapter must expose both; "value reads" alone invites a builder to ship only the projections.

**7. Guarantees to uphold ("grow‑only/immutable"): fix the non‑monotonicity illustration.** "Active membership is not monotone (resurrection re‑deposits at a fresh address)" cites the wrong cause. The direct ⊤→⊥ flip is *retraction* removing the tuple from the active slice (`Nullify_Binary` drops it from `A_K` while `L_K` keeps it — PD1); resurrection is the secondary subtlety (re‑deposit at a *fresh* address, so not even value‑identity is stable). Lead with retraction, keep resurrection as the "and value‑identity isn't stable either" rider.

Items 5–7 are genuine but minor; 1–4 are where the digest is actually wrong or incomplete. The append‑only‑journal‑plus‑hints architecture, the symmetric span‑intersection index grounded decisively in the Green evidence, and the footprint‑dispatch section's insistence on honoring FP's cross‑type footprints ("name these exceptions or be surprised by them") are solid — leave them.
