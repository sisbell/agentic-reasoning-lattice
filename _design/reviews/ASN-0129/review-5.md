# Revision list

**1. [DEFECT] — "How it fits" (sibling-boundary) and the ceiling bullet: the self-emit design stance is mis-grounded in PC6a.** The digest says the reach/self-emit stance is "a settled design stance resting on the grammar fact (PC6a) alone," and frames "(C-reach, C-emit) … *implies* the grammar fact (any fixpoint former would compute reach) and additionally rules out every indirect counting/order encoding." This is right *for C-reach* — its baseline is PC6a, it implies PC6a (a fixpoint former computes reach), and its indirect routes are counting/order encodings. It is wrong for **C-emit**. The note grounds self-emit's design conclusion in a *different* grammar fact — "read off V: the vocabulary supplies no term spelling the test" (no frontier atom, no home-grouping atom, `inc(·,0)` excluded) — not PC6a; self-emit is frontier arithmetic, not closure, so no-fixpoint has no bearing on it, and its indirect routes are `age`/reflected-`L_dom`, not counting/order encodings. Fix: give C-emit its own grammar baseline (V supplies no self-emit spelling) wherever the digest currently collapses both conjectures onto PC6a/the fixpoint argument; confine "fixpoint former → reach / implies PC6a / rules out counting-order encodings" to C-reach.

**2. [DEFECT] — "Make the common case fast": "an ⊥-stable termination condition won't un-fire" attaches the ST property to the SF class.** ST (⊤-stable) is *once true, stays true*, so an ST trigger "won't un-fire." SF (⊥-stable) is *once **false**, stays **false***; it guarantees nothing about true persisting, so an SF condition *can* flip true→false — the digest's own canonical SF term `count(L_K) ≤ 3` un-fires on the 4th deposit. PD1's entire warning is that a fire-until-Q stop-condition un-terminates *unless Q ∈ ST*; pairing "termination condition" with SF inverts that and would steer a builder into the exact un-termination bug. Fix: ST → "once fired, won't un-fire (stays true)"; SF → "once false, won't fire (stays false)." Both are droppable from re-evaluation once at their stable value (ST-true, SF-false) — that is the actual pruning point.

**3. [SHARPENING] — read-base adapter: the rationale for admitting the V-TUP coverage tests overstates.** "admitted as primitives only to keep span arithmetic inside the leaf" doesn't hold: the digest itself notes coverage is derivable from `addrs + ≼` (PrefixSpanCoverage), and that route uses only the prefix test — *no* span-add — so non-admission would not expose span arithmetic either. The genuinely load-bearing point is the one the digest already states correctly (the projections are irreducible because coverage pins the denoted set only to its ≼-minimal elements); coverage's admission is a regime-parity convenience, and PC6's converse needs a *per-tuple* test (coverage or its `addrs+≼` equivalent), not span-arithmetic-hiding specifically. Drop or soften the "only to keep span arithmetic inside the leaf" clause.

**4. [SHARPENING] — "Leans on": the reachable-state class is credited to ASN-0126, but it is ASN-0128's.** The state class `S` every PL term is indexed over is ASN-0128's `→_sh*`-reachable **extended-record** states (R-TR), built on ASN-0126's gated transition relation. The digest folds "and the reachable-state class" under ASN-0126; split it so the extended-record reachable class is credited to ASN-0128 (0126 supplies the transition relation/frames and the home-chain frontier).
