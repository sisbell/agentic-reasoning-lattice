I checked the digest against the note (ASN-0129), its claim statements, and the verified Green evidence. It is, on the whole, an unusually strong digest: the forced/conventional split is accurate, the "structural-reads-only is a wiring discipline, not a theorem" framing is exactly right, the snapshot/multi-read/version-pinning treatment faithfully tracks PC4's "access count, not atom count" and correctly says PL discharges nothing there, the "build one symmetric reverse index unconditionally, let BH3 gate only the atom name" recommendation is well-grounded in both the note and the Green evidence, and the "no feedback primitive or it silently decides `reach`" point is correct. ## Revision list

**1. [DEFECT] — Design commitments → Forced → "no fixpoint/recursion": self-emit is misplaced at "agent time."** The digest says reach, self-emit detection, and dependency-chain walking "are outside the language… and belong to agent time." Reach and dependency-walking are agent-time (the note: "computed at agent time — iterate `succs`, unroll the recursion"). **Self-emit is not.** C-emit's design conclusion is explicit: "the self-emit check belongs to the *emitting surface*, which performs it (S3)" — i.e., ASN-0128's `Nullify_Binary` P-tgt, a substrate *write-path* responsibility, not an application/agent operation. Misattributing it inverts the layering (a builder could omit it from Nullify, or expect agents to compute it). Fix: split the three — reach/dependency-walking are agent-time; self-emit is inexpressible in PL (correct) but already performed by the emit surface (S3). Worth adding the note's companion fact: PL *can* state the **residence** disjunct of that same P-tgt gate (via `is_doc`/reflected `L_dom`); only the self-emit disjunct is the surface's alone.

**2. [SHARPENING] — Guarantees / Conventional: "set-semantics counting (dedup before counting)" risks a value-identity error.** The parenthetical is loose. Domain interpretations are already sets; the only dedup in the algebra is set-union over *addresses* in `⋃`-folds. Per PC2a, I0-equal tuples at *distinct addresses are distinct elements and are counted separately* (idem=⊥ audit count = deposit count; resurrection re-deposits the same pair at a fresh address *by design*). State that `count` is the cardinality of the distinct-tuple/address set in the selected view — never a content/I0-class dedup — so a builder does not collapse resurrection duplicates.

**3. [SHARPENING] — Implementation approaches → atom backing → BH4: the age recommendation omits the live frontier.** "Store the home and chain index with the tuple and read them out" captures only the *static* inputs. Per FP, `age(a) = f_d − 1 − j` also needs the *live* home frontier `f_d` (the home-wide, all-types deposit count that moves on every deposit at the home — this is precisely *why* the footprint is "home-wide," which the digest correctly flags one clause earlier). Make the combination explicit: age = stored per-tuple index `j` against a fresh per-home frontier read; storing `j` alone — or caching age with the tuple — is wrong because age grows as the home fills.

**4. [SHARPENING] — Implementation approaches → atom backing → membership: two distinct mechanisms are conflated under one Green citation.** The digest recommends a prefix-ordered index over `≼`-minimal elements for `is_K` (the denotation-side PrefixSpanCoverage form — comparison-only), then cites Green's "add-then-compare" as confirming "the mechanism." Those are *different* (equivalent) regimes: `is_K` via denotation is a prefix test; Green's add-then-compare is the *coverage/span* test — exactly the note's V-TUP "an add-then-compare, *never comparison alone*." Attach the Green evidence to the V-TUP coverage test and the "arithmetic-stays-inside-atoms" point (where it grounds), and present the prefix-over-minimal index as the denotation-side alternative; don't claim Green confirms it.

**5. [SHARPENING] — "What must be built" vs "Dynamics analyzer": the pass count is inconsistent.** "Three separate static passes must walk it" (term-representation rationale) conflicts with "A second static pass" (dynamics analyzer), which implies two. Reconcile by naming the three *analyses* (WT well-typing, FP footprint, PD0–PD2 stability) and noting they realize as two traversals (type-check; then footprint+stability fused). The "reify, don't closure-encode" conclusion is unaffected.

**6. [SHARPENING] — Dynamics analyzer: "(ST / SF / neither)" drops the ST∩SF case.** PD0 puts step-constants (V-PRIM constants, V-TUP reads of bound tuples) in *both* ST and SF. The classifier output is a 4-point lattice (both / ST-only / SF-only / neither); the digest's own "stability lattice element" phrasing already implies it — just list the fourth point.

**7. [SHARPENING] — State substrate: "active slice… (audit minus the retraction entries)" is imprecise.** Active = audit-K-tuples minus `nullified(Σ)` (the *addresses* retractions cover), not minus the retraction tuples (which sit in `L_R`, a different slice). The correct form — "audit minus nullified" — already appears in the evaluator paragraph; align this one to it.
