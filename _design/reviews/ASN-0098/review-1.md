This is a strong, well-organized digest: the forced/conventional discipline in *Design commitments* is handled with real care (it correctly refuses to call tightness or the subspace partition "forced"), the recompute-default-then-add-index-when-hot staging is good Lampson hygiene, and the coverage-keyed-reverse-index-as-hint is a genuinely sound design judgment well-grounded in the green evidence. The build list is appropriately delegated to the upstream ASNs. The improvements below are real defects first, then sharpenings.

**1. *What must be built* / pre-edit survival check — the "break N links" payoff overclaims; LP12a is per-document, not global orphaning.** The digest says the check decides "which links it will *orphan*" and pitches "this delete will break N links." LP12a's wp is `discoverable_from(a, d, Σ')` — discoverability *from d specifically*. A link whose projection through `d` fails to meet the retained set loses reach **through d**, but may stay discoverable from other documents; "orphaned" in the note (LP17) means discoverable from *no* document. As written a builder will report links as broken that survive elsewhere. Fix: reframe as "which links lose their reach through this document (become undiscoverable from `d`)"; note that true orphaning requires additionally confirming the link is discoverable from no other document.

**2. *Arrangement + edits* / Decisions #4–#5 — the insertion recommendation is over-constrained and internally inconsistent; surface the dense-address option that drops the reorder.** The approaches section recommends mid-document insertion = extend-at-frontier + reorder, treating the reorder as necessary. But LP9 requires only E1 (strict domain growth) + E2 (prior-domain agreement) — *not* frontier placement. With the stable-dense-address choice the digest itself offers in decision #5, a mid-document insert is a single clean LP9 extension (add a V-position *between* two existing ones; downstream positions never move, E2 holds literally) with no reorder at all — strictly cleaner than both green's shift and the note's extend+reorder. The reorder is forced only by contiguous integer V-positions (ASN-0047's D-SEQ★/D-CTG★, which the digest invokes for contraction), and that contiguity is a shape convention, not a requirement of LP9–LP21. Fix: connect #4 and #5 explicitly; present dense/stable V-positions as the option that eliminates the reorder while preserving every displacement law; flag that adopting it relaxes ASN-0047's D-CTG★ arrangement shape (a tradeoff against other ASN-0047 reasoning, not against this note).

**3. *Design commitments* / "Survival of reach" — "anything is left at each end" re-arms a confusion the note explicitly defuses.** The note sharpens that colloquialism to an **existential** condition: `(E i : coverage(eᵢ) ∩ ran(M(d)) ≠ ∅)` — *at least one* slot, not *each* end (LP12, and the note's own gloss "for at least one slot i"). Stating it as "anything left at each end ... is precisely coverage ∩ ran ≠ ∅" risks a builder implementing an AND-over-endsets check — and the digest's own capability text correctly says "any slot," so the digest contradicts itself. Fix: state the commitment as "at least one endset's coverage still meets the arrangement range"; drop or annotate "each end." (Worth distinguishing for the builder: this is existential *discoverability*, not universal *followability*.)

**4. Missing commitment — discovery independence of origin, which is what justifies the coverage-keyed reverse index.** The note dedicates a result to it: discoverability of `a` from `d` turns solely on `coverage(eᵢ) ∩ ran(M(d))`, independent of the link's home document `home(a)` and of the origin documents of covered content. This is load-bearing: the reverse index must **not** be scoped by home document. Green's home-doc filter being a no-op accidentally conforms; a maintained index that scoped by origin would be wrong. Fix: add this as a commitment and cite it where you recommend coverage-keyed reverse discovery (it is *why* ignoring `home(a)` is correct, not just convenient).

**5. *Guarantees to uphold* — referential integrity is S3★ (ASN-0047), not "LP20 corollary."** "Every arranged I-address must be allocated" is the GeneralizedReferentialIntegrity invariant S3★; LP20's corollary *consumes* S3★ to confine the projection's range into the stores. The builder's obligation is to uphold S3★ (an arrangement-layer invariant); LP20's store-confinement only follows once it holds. Fix: cite S3★ as the obligation and present LP20's corollary as its consequence. (The substance — green gets it free via the V→I path; re-impose it if you let arrangements name raw I-addresses — is correct.)

**6. *Coverage* / Decision #2 — normalization "discarding the user's original span decomposition" sits in tension with the immutability commitment.** Equal coverage gives equal projection (LP21), but two endsets with equal coverage and different span *sets* are different link values (L5 set-semantics); discarding the user's spans changes the stored object, against "the spans within each endset never change" (LP2). Fix: distinguish "derive a normalized-coverage representation as a separate hint for indexing/comparison" (clean) from "replace the stored link's spans" (lossy, irreversible, and against LP2); recommend the former — keep the stored link immutable, normalize only the derived coverage view.

**7. Minor citation/precision.** (a) "Coverage is stateless ... (LP3)" — statelessness is the *coverage definition* ("does not consult any state component"); LP3 is invariance-across-transitions. Cite the definition (and LP21) for statelessness. (b) "Projection = coverage ∩ live range (LP20)" conflates V-positions with I-addresses — LP20 equates the *image* of the projection with `coverage ∩ ran`; the projection itself is the V-position set. (c) The link-store approach asserts it "maps directly onto the repo's own working substrate" and assumes a Rust/`im` stack — neither is grounded in the note; state these as assumptions or make the substrate claim conditional.
