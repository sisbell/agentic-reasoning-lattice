Overall this digest is accurate and unusually well-grounded — the forced/conventional split is mostly right, the Green-derived claims (stateless query-and-increment, no `Σ.next`, per-document orgl embedding, `CREATELINK`'s three-write fusion, no withdrawal) are all supported by the evidence, and it holds design altitude without slipping into code. The improvements below are real but localized.

## Revision list

**1. Guarantees / Design commitments — surface that the `K.σ` document-shape gate is the foundation of *cross-document* isolation, not local well-formedness.** The "Uniqueness / freshness — by construction when you mint via the cursor" bullet justifies freshness only with "first emission is fresh; subsequent strictly advances past the max sibling" — that is the *within-document* pillar only. The note's freshness rests on **three** independent pillars: within-document (cursor advance / ChainEnumerationInjectivity), **cross-document** (Cross-document disjointness via prefix-incomparable anchors), and cross-subspace (T7/SD). The cross-document pillar holds *only because* every document is `T4-valid ∧ zeros(d)=2` (M0) — that shape is what makes distinct documents' anchors provably prefix-incomparable, hence their whole address spaces disjoint. The digest currently presents `zeros(d)=2`/`T4-valid` as merely "discharges M0 at the new key." Do: state that the `K.σ` shape-gate underwrites inter-document address-space disjointness and is therefore part of the isolation TCB (a builder must not relax it), and rewrite the freshness-by-construction claim to name all three pillars rather than only cursor-advance.

**2. Implementation approaches → Address allocation: the "Pick: cached hint over recompute-always" default is under-justified and inconsistent with the digest's own discipline.** For indexing the digest correctly defaults to the simple thing and defers optimization ("add a hash index only if point-lookup latency demands it"); for the cursor it does the opposite — defaults to the cache. Recompute-always is the simpler mechanism, is exactly what Green does (the evidence: deliberately *stateless*, no cached cursor), and the predecessor query is already O(log n), so the cache buys only O(log n)→O(1). The cache is defensible on common-case-fast grounds, but as a *default* it contradicts both Lampson's "cheapest mechanism that meets the contract" and the digest's own stance two paragraphs later. Do: default to recompute-always and present the cached hint as the measured optimization (mirroring the index decision), or explicitly justify why the cursor hot-path warrants caching where the index does not.

**3. Guarantees — "The link value shape (L3) is the one value check you must actively enforce" drops the content value precondition.** `K.α`'s precondition includes `v ∈ Val`, and the digest's own clean summary lists both ("`v ∈ Val` for content, L3 for links"). The "one value check" phrasing in the well-formedness bullet is therefore internally inconsistent. Do: reconcile — either treat `v ∈ Val` as a real precondition (then L3 is the link-side value check, not "the one"), or, if `Val` is pure typing with no structural predicate, say that explicitly and drop it from the summary so the two passages agree.

**4. Design commitments → Conventional: refile the subspace numbers as forced, not conventional.** The bullet files `s_C=1, s_L=2` under "Conventional (committed but replaceable)" and then spends a paragraph arguing they are *not* freely relabelable — which is self-undermining. Your own derivation shows the numbers are forced: C1c/L1c mandate `k₁=2`, a depth-2 increment off a `zeros=2` document necessarily introduces digit 1 (so `s_C=1`), and `inc(b_C,0)` necessarily gives 2 (so `s_L=2`). The only genuinely conventional choices are (a) exactly two subspaces and (b) content-as-lower-sibling / link-as-next — and from those the numbers follow. Do: lead with that distinction (cardinality + ordering = conventional; the digits = forced-given-that) and cut the "Conventional but not relabelable" tension; this also shortens the longest block in the digest.

**5. How it fits / Decisions — surface that the per-document partition gives the note's open concurrency question a structural answer.** The digest collapses ordering to "single-writer journal append," which is correct but stricter than the structure requires. Because the per-document chains are provably disjoint (DisjointSubAllocatorChains, Cross-document disjointness), allocations under *different* documents cannot collide and can proceed concurrently; only commit-order assignment / journal append needs a single serialization point. The note explicitly lists "what discipline governs concurrent emission across multiple allocators?" as open — the partition is the latent answer worth handing the builder. Do: add a line noting the partition enables safe per-document parallelism, so "single-writer" is a choice, not a necessity.

**6. Implementation approaches → persistence: note that journal+replay departs from Green.** The digest contrasts with Green on the cursor, embedding, coupling, and withdrawal, but proposes "journal-as-truth + replay" for persistence without noting Green did something different — a paged enfilade B-tree with in-core caching and disk flush (`orglincore`, `writeenfilades`, `leftbroorfather` for eviction; evidence Q8). It's a fine design and correctly flagged "deployment-prudent, not note-mandated," but for consistency add one line that journal+replay is a deliberate design choice for an append-only model, *not* a port of Green's mechanism.
