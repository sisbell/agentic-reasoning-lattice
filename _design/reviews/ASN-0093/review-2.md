Reviewed the digest against ASN-0093 and its claim statements, with the evidence answers in hand. The digest is unusually committal and mostly well-grounded — the cursor-as-recomputable-hint, the mint-vs-validate split, the enfilade-YAGNI call, and the indexing argument are all sound. The defects below are real, and several are internal self-contradictions.

## Revision list (most important first)

**1. "Forced" commitments — the bullet "the home is never stored beside the element, only recomputed" is miscast as forced.** The note forces only *recoverability*: `origin(·)` is a pure projection (C2/L1a), so the home *need not* be stored as authoritative state. The note nowhere forbids denormalizing it as a cache — and the digest's own "Home document: recompute vs. denormalize" section, plus Green's `homedoc` denormalization (Q6 evidence), treat denormalization as a legitimate option. Fix: state the forced part as "home is recoverable from the address ⟹ never needed as authoritative state," and let the recompute-vs-denormalize *choice* live only in the builder-decisions section.

**2. "Decisions → Value storage": "Links are small (fixed endset arity)" contradicts L3.** L3 admits arbitrary `N ≥ 3`, and the note's own Open Questions flag *bounding* arity as unsettled — i.e., unbounded is the current commitment. Endsets are sets, not scalars, so even a triple need not be small. The inline-vs-out-of-line decision therefore applies to links too; the "links are small" default is unsafe. Fix: acknowledge the common case (StandardTriple) is small but L3 permits unbounded arity, so don't hard-assume it.

**3. "Guarantees → clean summary": "the only two active gates" undercounts.** The "addresses are correct by construction" clause covers only the *minted* K.α/K.λ addresses; K.σ's address is caller-supplied and *validated*, so its gate (fresh `∉ dom(M)` + T4-valid + `zeros=2`) is a third active gate — and the digest itself calls it "mandatory" twice elsewhere. The content value check (`v ∈ Val`) is also dropped (the precondition-gates section lists it; the summary says only "link value"). Fix: reconcile the summary — active gates are (a) home-registered + value-well-formed for K.α/K.λ, and (b) K.σ's mandatory document-address gate.

**4. "Conventional": `s_C=1, s_L=2` are not freely "replaceable" Green-compat labels.** They are pinned by the inherited inc-algebra: `b_C(d)=inc(d,2)=[d.0.1]` *forces* `s_C=1` (it is the digit a depth-2 increment introduces), and `b_L=inc(b_C,0)` forces `s_L=2`. The Green-compat convention is the *decision to have exactly these two subspaces*; the *numbers* fall out of "content = first subspace, link = its sibling, anchors built by minimal inc-steps." The digest's "distinctness + fixedness + consecutiveness" criterion misses this — a builder can't renumber without rebuilding the anchor construction and the C1c/L1c witnesses. Fix: say the values are *derived from the algebra*, not Green-relabelable.

**5. "How it fits" / "What must be built": missing layer boundary — the substrate builds no link-discovery index (Green's spanfilade).** Green's `CREATELINK`/`docreatelink` writes *three* layers — I-space link orgl, spanfilade endpoint-index, POOM (Q6 evidence) — whereas `K.λ` writes only the link-value store and holds `M` in frame. The digest's porting warning catches the M-fusion but not the spanfilade. A Green-porting builder will expect and prematurely build an endpoint index that the note does not model. Fix: extend the CREATELINK warning (and the deferred-concerns list) to state that link *discovery/indexing* is also absent here — the substrate's `L` is value-only, with no from/to/type index.

**6. "Implementation approaches": naming the `im` crate presumes a Rust stack that isn't established.** The repo (markdown + Python tooling, JSON-shaped store) gives no evidence of Rust; naming a specific library is below design altitude. Fix: state the design-level requirement — "persistent / structurally-shared immutable maps" — and drop the library unless the stack is fixed.

**7. (Sharpening) Persistence is framed as note-mandated; it is a deployment need.** The note's permanence (C0/L12/M1) constrains the *transition relation* (no transition deletes or overwrites) — not crash-durability; a purely in-memory implementation satisfies every invariant. The persistence approaches are good, but "must build … so the stores survive restart" misattributes durability to the note. Fix: mark durability as deployment-prudent, distinct from the note's transition-relational permanence.

**8. (Sharpening) The "exactly this repo's `links.jsonl` + `paths.json` pattern" reference is unverifiable from the materials.** If the repo genuinely uses that pattern it is a strong anchor; if not, it is fabricated grounding stated twice. Verify it; otherwise generalize to "an append-only event log + replayed maps."

**9. (Sharpening) "Decisions → Mint vs. validate": "supports idempotent re-presentation on replay" overclaims.** The note's preconditions compute the *next* address; re-presenting an already-allocated `(d,a,v)` would compute `inc(max,0) ≠ a` and *fail* validation, not no-op. The real benefit is *deterministic replay self-check* (re-derive and compare) — which the digest already states correctly under "replay safety." Fix: drop "idempotent re-presentation" or rename it to the self-check it actually is.

**10. (Minor) Note that C-fin/L-fin are what make the cursor's `max{a':origin=d}` well-defined.** The subsequent-emit branch takes a `max` over the same-origin set; the note proves finiteness precisely to license it. One line in the allocation-approach would close the gap.

## Solid as-is
The cursor section (recomputable, no global `Σ.next`, cached-hint-recomputed-on-miss) is accurate and well-grounded in the Green evidence; the indexing argument (ordered tumbler map answers max-under-prefix and prefix-range scans via ChainPrefixExtension/ChainMembershipForOrigin) is correct; the enfilade-deferral call is good restraint; and the identity-by-address treatment correctly forbids value-identity while permitting blob-level content-addressing *underneath* — exactly the right side of that trap. No changes needed there beyond the items above.
