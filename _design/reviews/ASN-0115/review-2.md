This is a strong digest — accurate on the great majority of commitments, disciplined about forced-vs-chosen, and genuinely good at flagging *unsound* approaches (the hash-addressing/S4 trap, global-sort/R5, dedup/R3-R8, coalesce-across-gap/R6, and cache-by-byte-identity/R7 are all caught correctly and should be left intact). It stays at design altitude — no signatures, Green functions referenced descriptively as grounding rather than named as behavior. The improvements below are mostly localized.

## Revision list

**1. "Implementation approaches → Repeatability" (and "Decisions → Live vs snapshot"): the version/snapshot conflation misstates the note's version model.** The digest writes *"a 'version's arrangement' is an immutable map value"* — but in the note a *version* is a distinct document tumbler with its **own mutable** arrangement Σ.M(d′) (S7d; P3 ArrangementMutabilityOnly). The digest itself says correctly two paragraphs up that "naming a document does not freeze it," so this is internally inconsistent. An immutable persistent-map *value* is a **snapshot**, not a version; conflating them invites a builder to implement versions as copy-on-write snapshots of one document's arrangement instead of as independent documents. Two further consequences: (a) the note's own repeatability mechanism is caller-discipline against the cited *mutable* arrangement ("a caller obtains it by citing a version whose arrangement it does not subsequently edit"), not system-level freezing; (b) R4 pins resolution to the **current** Σ.M(dⱼ), so delivering against a pinned snapshot is an *extension beyond* RETRIEVEV's contract, not RETRIEVEV. Fix: keep the sound insight (persistent maps make R7's hypothesis trivially satisfiable; key any delivery cache on the consulted arrangement *value*), but call the immutable thing a snapshot, state that the note's repeatability is current-arrangement + caller-discipline, and label snapshot-delivery explicitly as beyond the current-only guarantee.

**2. "Guarantees to uphold" omits R4 (ArrangementRelativity / per-document isolation), a real active-enforcement obligation.** The list maps R2,R3,R5,R6,R7,R8,R9,R10,R11 but not R4 — yet R4 ("resolved through Σ.M(dⱼ) alone") is precisely a guarantee a builder can silently break: a single global V→address index resolves a spec against the wrong document unless per-document scoping is enforced. The evidence makes this concrete (Q17): Green honors isolation *structurally* — each document is its own POOM, and the crum-level homedoc filter is **dormant** during retrieval — so a builder who replaces per-document arrangements with one shared index must re-add the isolation R4 demands. Add R4 as an active-enforcement guarantee (the digest's recommended per-document architecture already secures it; the warning matters for the enfilade/global-index variants it also offers).

**3. "Forced → Span width is a tumbler boundary, not a count": the divergence is mis-attributed.** The bullet ends *"(Green's boundary clip makes the two diverge)"*, but the note's load-bearing mechanism is the **nominal-extent corollary**: delivered quantity = |act|, which falls below the nominal extent (the width's deepest component) exactly when named positions are unbound (gaps) or the spec is depth-incompatible — and that ties directly to R6. Green's boundary clip (Q14) is the *realization* detail, not the cause. Also distinguish the note-level statement (delivered *position-count* = |act|) from the Green-level one (delivered *byte-length*, position=byte per Q18); the bullet blurs them. Cite the note's gap/depth mechanism first, with the clip as the Green realization.

**4. Missing boundary case: the empty spec-set.** The note explicitly settles `p = 0`: "the empty spec-set is a valid request whose delivery succeeds and returns nothing." The digest's "never fail" framing implies it but never states it. Add to the request-gate/assembler obligations — the empty request is the limiting case of partial delivery and must succeed returning nothing, not error.

**5. "Byte-opacity and boundary clipping": make the bindable-slice scope of the no-interior-hole guarantee explicit.** The coalescing-safety argument leans on "R6 keeps every gap at a run's end … so the gap is always a run boundary," but R6's no-interior-hole guarantee is scoped to the *bindable slice* (depth-#s, subspace-S) — the note stresses it is "not about every named tumbler in the interval." The argument is sound for runs of same-depth bound positions; state that scope, and keep it distinct from the I-address-gap segmentation (Q13), which forces run boundaries even when every position is bound. The conclusions (never coalesce across a gap; keep segments gap-aligned) are correct — just anchor them to the slice-scoped guarantee rather than to "every gap."

## Genuinely solid — leave alone

- The forced-vs-chosen split is accurate throughout (ordinal-level confinement and the force-empty override are correctly classed as *chosen*; the subspace identifiers as conventional).
- The "iterate sparse bound positions, never enumerate the interval" point and the m_S(d)-as-hint treatment are exactly the right Lampson moves and correctly grounded.
- The hash-addressing/S4 warning, the global-sort/dedup prohibitions, and "be stricter than the reference at the gate" (Q19/Q1 footgun) are the most valuable soundness calls in the digest and are all correct.
- R8 vacuity (CL-OWN + CL-UNIQ), the kind-asymmetric provenance (R9), permanence-by-construction (R11/Q20), and the failure-only-on-unallocated boundary with Green's open-check correctly externalized are all faithful.

One minor note, not worth a revision item: the "torn reads of a registry under concurrent writers" caution is about the store-*build* side, not delivery (a pure read) — fine to keep, but it reads as a generic aside in a content-delivery digest.
