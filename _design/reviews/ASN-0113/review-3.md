## Revision list

**1. "Guarantees to uphold" / W4 inherited bullet (and the contiguity-trust stance throughout): the central risk is under-grounded — bring the contiguity evidence to bear the way the confinement bullet brings Q18/Q20.** The digest tells the builder to "trust D-CTG★ (it is enforced on the write path)" and treats contiguity as a safely inherited invariant. But the evidence shows the *reference implementation did not enforce contiguity*: mid-subspace deletion / sparse insert leaves real gaps (Q11: "if such gaps exist… a bounding span that overstates"; Q13: "the span is a bounding box, not a dense occupancy descriptor — it freely spans internal unoccupied gaps"), and contiguity holds only under "normal sequential use," not by construction. This is exactly the input on which the note's count-based span fails catastrophically (the digest's own "does not degrade gracefully"). So two things are missing: (a) "enforced on the write path" is optimism — make contiguity enforcement an explicit, *non-inherited* obligation the builder must actively meet, symmetric with how the digest correctly grounds confinement in Green's stubbed `acceptablevsa`; (b) note the consequence — the note's count-based span is *strictly less robust than the reference's bounding box* on the one failure both share (gap → Green overshoots conservatively, the note's span silently omits a real position and invents an absent one). That asymmetry is the real reason the note's open question #1 matters, and it is grounded in Q11/Q13 sitting unused.

**2. "Implementation approaches" / recommendation paragraph: the faithfulness-asymmetry summary contradicts Option 3's own analysis.** The closing line says "Options 3/4 read an extent whose last component equals the count only under D-CTG★," but Option 3's body foregrounds a *count-hint* `(n_{s_C}, n_{s_L}, …)` that is "robust, faithful to the count even if a write-path gap ever opened" — i.e., not an extent. Reframe the asymmetry around *what is stored*, not the option number: Options 1/2 **and** Option 3-as-count count actual occupancy and stay faithful under a write-path gap; only Option 3-as-extent and Option 4 (Green's bounding box) read an extent whose last component is the count solely under D-CTG★. As written, the recommendation wrongly tars a faithful design (maintained count) with the fragility of a different one (maintained/free-ridden extent).

**3. "Decisions for the builder" / contiguity verification, and the W4 bullet's "assert it cheaply": the defensive assert must verify the full run shape (D-SEQ★), not just contiguity (D-CTG★).** The synthesizer trusts three bundled foundation facts, not one: the start `[S,1,…,1]` (D-MIN★ — the basis for the digest's own "you never need to *find* a minimum" shortcut), contiguity (D-CTG★), and the common depth `m_S` (S8-depth). A contiguity-only assert passes on `V_S = {[S,2],[S,3]}` (a perfectly contiguous run) while the synthesizer still emits `start = [S,1]` and covers `{[S,1],[S,2]}` — wrong. State the cheap *complete* check: `V_S(d) == {[S,1,…,1,k] : 1 ≤ k ≤ n_S}`, which is the same scan cost and backstops exactly the "never find a minimum" / "read `m_S` off any key" bets. Reword "trust D-CTG★" to "trust D-SEQ★" wherever it stands in for the bundle.

**4. "Guarantees to uphold": W16 (Partition) is not surfaced.** Its constituents (W4 exactness, W9 exhaustiveness, W11 disjointness) are all covered, so this is derivative — but it is a named claim in the note's table and the "no orphan, no phantom across the whole report" coherence property is a one-line guarantee worth stating explicitly as the conjunction the builder gets for free once the three constituents hold.

**5. "Implementation approaches" / Recovery: don't import an unstated substrate model.** The note specifies no journal; "an append-only arrangement journal plus a separately-kept document registry, recovered by replay on load" is a Lampson default the digest presents as "the standard substrate." The load-bearing point is sound and should stay — *registration must be recorded apart from content writes so allocated-empty (`⟨⟩`) is distinguishable from never-allocated (fail)* — but decouple it from the specific journal/replay framing (or label that framing as one substrate assumption among several), so the requirement reads as a constraint on the registry, not a mandate for a particular durability mechanism.
