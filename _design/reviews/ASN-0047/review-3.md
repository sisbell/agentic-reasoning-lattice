This is a strong, faithful digest — the state factoring, the P3 headline, the origin-not-value identity, the transclusion asymmetry, the orphan-link/coupling story, and the forced/conventional/divergence calls are all accurate and well-grounded, and several moves are genuinely sharp (the fork *map-not-set* catch, "R is authoritative, not a hint," and the content-only recovery contract). I found no outright inaccuracy, ungrounded source claim, or altitude slip. The improvements below are sharpenings and two real completeness gaps, ordered by value.

**1. Implementation approaches → "Arrangements M(d)" / Decisions → "Arrangement representation": the depth-rebasing caveat overgeneralizes a representation artifact, and the default representation is sub-optimal.** The parenthetical "*J4's depth-rebasing freedom m_new ≠ m_old is not a pure structural share*" is true only for the recommended **tumbler-keyed** ordered map. D-SEQ★ collapses each non-empty subspace to exactly `(depth m_S, count n_S, k↦I-address for k∈1..n_S)` — the only varying data is `k↦I-address`, and V-positions are never durable handles (links and R both key on I-addresses, not V-positions). So a per-subspace **k-indexed vector + a depth scalar** is the exact fit: suffix-removal = truncate, reorder = permute, extend = append, and depth-rebasing becomes free metadata — fork is O(1)-shareable at *any* depth, dissolving the caveat. Do W: scope the depth-rebasing remark to the tumbler-keyed map, and promote the vector (the digest's own listed "exact fit to D-SEQ★") to recommended default or co-equal. The tumbler-keyed map stores the full `[S,1,…,1,k]` when only `k` varies and pays an avoidable fork cost for that redundancy.

**2. Design commitments / Implementation approaches (fork): the digest omits J4's source-selection rule (a load-bearing version semantic).** It describes fork's *copy fidelity* well (φ, multiplicity-preserving, map-not-range) but never says *which* document fork copies *from*. J4's operand-tracking is a real note commitment: a first version (k=1) copies the base `d_src`, but a subsequent version (k=0) copies the chain frontier `prev_version` — so a version-of-a-version inherits the latest edits, not the base. The note spends two worked examples on exactly this. Add it; a builder composing the version command will copy the wrong content without the "fork from the frontier, not the base" rule.

**3. Guarantees / What must be built: the pervasive "target document already exists in E_doc" precondition is missing.** The guarantee list surfaces P8 (parent-exists at *entity creation*) but not the distinct, more pervasive check: six of seven primitives (K.α, K.λ, K.μ⁺, K.μ⁺_L, K.μ⁻, K.ρ) require their target/home `d ∈ E_doc`, and K.α/K.λ additionally require `origin(a)`/`origin(ℓ) ∈ E_doc` (P6, L1a). "Mints fresh addresses under a parent prefix" implies it but never states it as a checked precondition. Add it as an explicit active obligation — it is not the same as P8 and it gates every allocation and placement.

**4. Composite atomicity / Decisions → Concurrency: mis-attributes the source of prefix disjointness.** "per-home-document writers… you must arrange node baptism to guarantee prefix disjointness" is wrong about the mechanism *within a node*: per-document disjointness comes from the document/account allocator (the note's CrossDocDisjoint / CrossDocEntityDisjoint), not node baptism. Node baptism governs *cross-node/federation* disjointness — relevant only if you parallelize across nodes (and evidence flags Green has no federation mechanism at all). Re-attribute: per-home-document parallelism rests on CrossDocDisjoint; node baptism is the federation-level boundary.

**5. Querying: "current containment… a cheap recomputable hint" is cheap in only one direction.** Deriving "what does `d` display now" from `M(d)` is cheap; "which documents currently contain `a`" is a full scan of all arrangements without a dedicated index. Scope the "cheap" claim to the per-document query (the dominant one), and note that the cross-document direction is what R is for (and R answers *ever*-contained, not *currently*).

Minor, optional: the link-transclusion asymmetry is labeled "forced" alongside P3, but it is forced by the *adopted ownership semantics* (Nelson LM 4/12), not by structural necessity like P3 — a one-clause distinction would tighten the forced/conventional taxonomy. Not worth a structural change.
