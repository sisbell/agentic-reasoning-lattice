This is a strong, carefully-disciplined digest — it gets the hard things right (origin-addressing with no value dedup, the multiplicity-preserving fork that a range copy would break, orphan links carrying no coupling, R as authoritative non-recomputable state, the crash-atomicity gap to close, and the per-state-vs-composite-boundary scoping). The grounding to evidence is honest and the forced/conventional calls are accurate. The items below are what it can still sharpen, most-important first.

---

**1. Implementation approaches (Arrangements/fork) + Design commitments: Fork is characterized only by its copy *mechanics*, never by its *source selection* — a load-bearing semantic omission.** The digest nails the φ-bijection (order/multiplicity preservation, "copy the map not the range") but drops J4's operand-tracking rule: *which* document supplies the copied content. The note commits (Definition Fork + the dedicated k=0 worked example) that a first version (k=1) copies from `d_src`, but a **subsequent version (k=0) copies from the chain frontier `prev_version`**, so a new version inherits the prior version's edits, not the base's. The evidence confirms Green copies "the immediate source's current content, including all edits." A builder composing the `version` command from these primitives must know to source from the version-chain frontier, not the root — add this; it is observable version semantics, not a detail.

**2. What must be built (registry / arrangements): surface that `M(d) = ∅` does NOT mean "document unallocated."** The note explicitly warns (default-value convention + Bridging lemma `dom(M) = E_doc`) that a freshly created or just-forked document has empty `M` yet exists, and that the allocation discriminator is **E_doc-membership, never the test `M(d) = ∅`**. This is a real footgun precisely for the digest's recommended unified-tree design (and for separate stores): a builder who keys "document exists" off "has a non-empty arrangement" mishandles every empty/new/forked document. State that existence lives in the entity registry, not in M's emptiness.

**3. Implementation approaches (Provenance R): the header "authoritative *duplicate* state" contradicts the body.** The body correctly argues R is "the *only* surviving record" once K.μ⁻ strips content from M — i.e., it is authoritative *primary* state, not a duplicate of anything. "Duplicate" undercuts the (correct, central) Lampson point that R is the one place the cache-don't-duplicate rule is overridden. Reword the header to "the one index that is authoritative primary state, not a recomputable hint."

**4. What must be built (per-document arrangements): "must let the caller pick insertion depth and must not bake in a single global depth" is over-strict — the depth is semantically inert.** Under D-SEQ★ contiguity, the depth `m` only prepends fixed leading 1's to every V-position (`[S,1,…,1,k]`); it yields no subdivision/insertion room and no semantic distinction. The note's own depth-rebasing example says rebasing "changes only the numeric V-values, never the order, multiplicity, or range," and Green hardcodes `m=2`. Recast caller-chosen depth as a semantically-inert degree of freedom: a builder may safely fix `m=2` (matching Green) — move this from "must build" to a builder decision, noting the freedom is unexercised in practice.

**5. Implementation approaches (Composite atomicity): the "J-couplings double as your recovery contract / signal a torn composite to discard" framing overstates them.** With the commit-marker / fsync-before-acknowledge discipline the digest (rightly) makes primary, a torn composite never becomes visible and never replays — so the content-scoped J0/J1★ replay check can never actually fire; it is a belt-and-suspenders integrity assertion, not the discard mechanism. Reframe: the commit marker *is* the recovery contract; the content-scoped J-checks are an optional consistency assertion over already-committed state. (The accompanying "don't apply J-checks to links — orphans are valid" point is excellent; keep it.)

**6. Guarantees: add store disjointness (L14, `dom(C) ∩ dom(L) = ∅`).** Currently only implied via "distinct subspace prefixes." It is by-construction in the subspace-partitioned allocator, but it is load-bearing exactly for the recommended *unified* tree, where content and link addresses share one structure and must provably never collide — a builder choosing unified-vs-separate stores should see it stated.

**7. Decisions (interior arrangement deletion): the "Green compacts-and-renumbers" claim is faithful to the note but contested in the source evidence.** The note's open question asserts Green's `DELETEVSPAN` compacts-and-renumbers, and the digest faithfully relays it (grounded). But the source-level evidence is genuinely split: one path attributes a left-behind *gap* to the `strongsub` exponent guard (deletion width at a lower exponent than the link displacements), while the other shows compaction via the case-2 `tumblersub` shift. Add a half-line so the builder choosing an interior-deletion discipline does not over-rely on "Green already does compaction" — it is not a settled reference point.

Everything else — the five-component factoring, P3 as headline, the transclusion asymmetry, the seven-primitive composition, the unified-tree/stateless-allocator/single-writer recommendations, and the L3-vs-empty-F/G validation split — is accurate and at the right altitude; no change needed there.
