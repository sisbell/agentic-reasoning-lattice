## Review

The digest is, on the whole, unusually strong: the Design Commitments are accurate, the forced/conventional tagging is right (five-component state, P3 mutability hierarchy, origin-not-value identity, transclusion asymmetry, orphan links, suffix-only K.μ⁻), and every Green source-level claim (permascroll/Istream, spanfilade DOCISPAN-vs-link-endpoint split, stateless query-and-increment, single-writer run-to-completion, no-fsync gap, fixed arity-3, empty-Θ/phantom-link acceptance, immediate-source fork copy, the contested DELETEVSPAN behavior) traces to the evidence. The Implementation Approaches are at the right altitude and the fork-is-φ-bijection-not-range-equality and R-is-authoritative-not-a-hint points are exactly the load-bearing traps a builder would otherwise hit. The depth-`m`-is-semantically-inert synthesis is correct and well-defended by the note's own depth-rebasing proof. I found one material problem.

### Revision list

1. **[DEFECT] "What this is" — the thesis sentence misstates the primitive set and contradicts the digest's own body.** It lists "the complete, minimal set of primitive state changes (allocate content, allocate link, create entity, extend/contract/**reorder** an arrangement, record provenance)." Two errors: (a) **reorder (K.μ~) is not primitive** — the note is explicit ("a named composite of K.μ⁻ + K.μ⁺ … *not a primitive transition*"), and the digest's own Design Commitments and Decisions correctly call it a composite, so the opening is both false against the note and internally inconsistent; (b) **"extend" is collapsed into one item**, but the note has *two* distinct extension primitives — K.μ⁺ (content, permits `origin(a)≠d`) and K.μ⁺_L (link, requires `origin(ℓ)=d`) — which is precisely the transclusion asymmetry the digest itself flags as forced. The note's primitive set is the **seven elementary transitions** (K.α, K.δ, K.λ, K.μ⁺, K.μ⁺_L, K.μ⁻, K.ρ). *Do W:* reword the opening to enumerate the seven elementary transitions (keeping content-extend distinct from link-extend) and present reorder and fork as composites built from them — or describe the operations without asserting the parenthetical list *is* the primitive set. The primitive/composite line is load-bearing in the note (it underwrites "seven elementary transitions suffice" and P3's case analysis), so a digest should not ship reorder as a primitive.

2. **[SHARPENING] Design commitments — the interior-link-withdrawal sentence leads with one side of contested evidence.** "the reference implementation … is reported to additionally support interior link withdrawal by compacting and renumbering" states the compact-renumber reading as the behavior, with the contest only signalled by the inline "(contested … see Decisions)" and fully surfaced later. Since the evidence genuinely splits (gap-leaving via the `strongsub` exponent guard vs. compact-renumber via the case-2 `tumblersub` shift), surface both readings at first mention so a reader does not anchor on compact-renumber as settled. The note's open question and the Decisions section already do this correctly; align the commitment sentence with them.

3. **[SHARPENING] "What must be built / Guarantees" — make the content-side parent-exists check explicit.** The digest calls out P8 (parent exists) as the active check for entity creation, but the analogous content precondition — K.α requires the origin document to already exist in E_doc (P6 / S7a: content is minted under an existing document's prefix) — is only implicit in "allocate under a parent prefix." Name it alongside P8; it is the content-layer counterpart and a real precondition a builder must enforce.

4. **[SHARPENING] Trivial: "an allocated-but-unplaced link is a *orphan link*" → "an orphan link."**

VERDICT: REVISE
