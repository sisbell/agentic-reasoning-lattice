## Revision list

**1. [DEFECT] "Implementation approaches → Genesis," "Decisions → Genesis," and the "Design commitments" empty-start bullet: the empty-start option is described with udanax-green's "all-zeros root … never stored," but that root is not T4-valid, so it collides with the digest's own B6(i) gate.** B6(i) requires *every* baptism's parent — baptized or not — to satisfy T4 (nonzero final component). The note is explicit that the *only* prerequisite it waives is parent-baptized-ness ("no parent-baptized prerequisite is imposed"); it does **not** waive T4-validity of the parent. An all-zeros root has a zero final component, fails T4, and the digest's own recommended "validate T4 on parents (B6(i))" gate would reject the very first baptism — the system cannot bootstrap. The note sidesteps this precisely by seeding the *nonzero* root `[1]` (the trace verifies "[1] satisfies T4"); udanax's zero root works only because the reference implementation performs no B6-style structural check on parents (cf. the note's first open question, "Gregory's implementation does not check at structural levels"). **Fix:** state that a note-conforming empty-start baptizes the first child under a *T4-valid* virtual parent (e.g. `[1]`, giving first address `[1,0,1]`), not the all-zeros root; flag udanax's literal zero root as non-conforming to B6; and amend the "no parent-baptized precondition" commitment to note that B6(i)'s T4 requirement on the (virtual) parent still applies. The downstream claim — that under empty-start the auxiliary set stays empty because every baptized address is a namespace child — is itself correct and survives the fix.

**2. [SHARPENING] "Registry representation": "'decomposition alone suffices' holds *precisely* under empty-start genesis" over-narrows and sits in mild tension with the digest's own later genesis paragraph.** The actual condition is "no baptized address is a non-child length-1 root" — which empty-start guarantees, but which a seed containing *only* namespace-children also satisfies (exactly what the later "if any seed root belongs to no sibling stream, the auxiliary set must carry it" implies). Replace "precisely under empty-start" with "under empty-start — and, more generally, any seed with no length-1 roots."

**3. [SHARPENING] "Registry representation": the granfilade is invoked as the model for *both* the explicit-set option and the counter-bearing hierarchical-tree option, but per the evidence it is only the former.** The evidence is explicit that udanax keeps "no session-local counter and no cached 'next available' pointer" — the granfilade is the *counter-less* hierarchical store that derives max by `findpreviousisagr` navigation. So the "hierarchical tree … each parent carrying up to two child-counters … essentially the granfilade shape" overstates: the granfilade supplies the hierarchy and child-links but *not* the per-node counters, which are an addition over what Green does. Say the counter-bearing tree is "the granfilade's hierarchy plus per-node counters the granfilade does not itself keep."
