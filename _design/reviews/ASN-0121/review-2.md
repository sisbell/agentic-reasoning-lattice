This is a strong, carefully-grounded digest — it repeatedly flags the traps that would *violate* a note commitment (value-based dedup, GC-ing nullified retractors, deciding addressability once at creation) rather than falling into them, and it keeps Green source claims tied to the evidence channel. The improvements below are real but none overturn its core reading.

**Revision list (most important first):**

1. **"Guarantees to uphold" (FL-REACH) + "Implementation approaches" (the index): the orphan strict-superset and its build constraint are missing.** The digest captures FL-REACH's *global* and *found-once* but drops FL-REACH(d): `findlinks_FTT` is a **strict** superset of any document-by-document enumeration because it still finds *satisfying orphans* — links whose endpoint content has left every arrangement. The load-bearing builder consequence is absent: the I-address index must **not** garbage-collect entries when content departs all arrangements; the orphaned link stays findable by content identity (grounded in Q18 — write-only spanfilade, no `deletespanf` — and S0/LP17-LP18, content never destroyed). This is also exactly the boundary between this query (stable, finds orphans) and `findlinks_V` (fragile, loses them); the digest states that boundary under "How it fits" but not the build rule. Add a guarantee/decision: index entries for content-departed links persist and remain findable, with an explicit warning against incremental index GC.

2. **"What must be built": promote the request representation to a first-class component.** The listed combination engine must "short-circuit to ∅ on any empty constrained slot, return all-addressable when every slot is wildcard" — but it can only do that if the *upstream request representation* distinguishes three states per slot (`∗` / empty-constrained `∅` / populated). That representation is precisely the one thing the reference got wrong (Q2/Q7: wire format and parser collapse NOSPECS and empty-specset to NULL, so `Θ = ∅` is inexpressible and FL-WILD/FL-EMP are only half-realizable). The digest demotes this to "repair (c)." Add a build component — a request decoder/grammar carrying the per-slot wildcard-vs-empty-vs-populated trichotomy — since FL-WILD and FL-EMP are unrealizable without it.

3. **"Design commitments" (wildcard/empty bullet) and "What must be built" (per-slot finder): the empty-endset exclusion is overstated.** "excluded from any constrained from/to slot" and "a constrained from/to request never returns it" read as *any* constrained slot. Per FL-EMP's link-side rule and Trace 5, an `e₁ = ∅` link is excluded only on the **from** axis; it remains a perfectly normal **to**-match — a constrained to-request matching `e₂` returns it. Emptiness on one endset suppresses constrained matching *on that axis only*; the link stays discoverable via its other, non-empty endset. Restate per-axis, and note that "admitted under that axis's wildcard" undersells it: the *other* axis matches normally, not just under wildcard.

4. **"Design commitments" (address-overlap bullet) / "Decisions for the builder": surface type-hierarchy-by-containment (FL-TYP(c)).** The digest covers ghost-types and address-only matching but drops the named consequence: a prefix-rooted type request covers a whole subtree, so subtype/supertype search falls out of the *same* coverage-overlap test — "without any registry." This is a "don't build it" point in the Lampson spirit: do not build a separate type-hierarchy/ontology registry; address structure plus the prefix-span fast path give subtype search for free. Flag the matching open question (when the containment reading is *exact*).

5. **"Implementation approaches" (spanfilade): "each link contributes one entry per slot" undercounts.** An endset whose coverage is *k* contiguous I-regions contributes *k* entries in that slot's subspace (Q13: one sporgl per contiguous region; Q19/Q20: `insertspanf` inserts per-sporgl). State "one entry per contiguous coverage region per slot," and connect it to dedup: this is *why* a per-slot lookup can return the same link-address several times *within a single query*, making dedup-by-address intrinsic — not merely a cross-document/transclusion artifact (the digest currently motivates dedup only from the multi-document case).

6. **"Guarantees to uphold" (FL-JUNK): clarify or soften the "logarithmically" target.** As written it reads oddly beside the recommended nested-loop intersection (O(n·m·p)). The reconciling mechanism is unstated: junk that matches nothing never enters any per-slot result set, so it costs only index-lookup *depth* (≈ log of store size), while the intersection's polynomial cost is in the *matching* result sizes — independent of junk. Either ground "logarithmic" explicitly as the lookup-depth term or soften to "junk that matches nothing costs nothing in the intersection." (You already correctly separate FL-JUNK-the-answer-invariance-lemma from this complexity goal — keep that.)

7. **"Guarantees to uphold" (FL-STB), low priority:** stability is *unconditional* from FL-LOC (the operation never reads Σ.M), not contingent on keying. I-address keying preserves the *index's faithfulness* to an already-stable answer (a V-position-keyed index would drift, not change the true answer). The "iff keyed by I-address" is right as an index-realization rule; just don't locate the *source* of the abstract guarantee in the keying choice.
