## Revision list (most important first)

**1. Implementation approaches → "Link store & allocation": operationalize the serialization assumption; the "no contention" line is misleading for allocation.** The recommended allocator ("next address is the home chain's current max + one," "per-home last-allocated hint recomputable by scanning the journal") is sound *only* under serialized allocation. Two concurrent `editlink`/`assert_sup` calls can both read the same per-home max and append colliding keys, violating freshness/GlobalUniqueness. The note's whole model rests on ASN-0047's *atomic, totally-ordered* transitions, and the evidence is explicit that Green's correctness here depends on it (Q18: run-to-completion serialization is what prevents the collision; the allocator otherwise would not). The digest names "atomic, totally-ordered transitions" once in "How it fits" but never carries it into the allocator, and the sentence "the store is only ever extended at fresh keys, so there is no contention on existing entries" elides that *next-key allocation* is exactly where contention lives. **Do:** state that address allocation must be funneled through a single serialization point (make the journal append the atomic commit, or a per-home lock), preserving ASN-0047 atomicity; qualify "no contention" to "no contention on *reads of existing (immutable) entries*; allocation of the next key must be serialized."

**2. Design commitments + "Choose the reader's default currency policy": don't foreclose OQ6 — cross-home "latest" is unrecoverable *from state*, not flatly impossible.** The digest discusses temporal ordering in three places and lands on "a cross-home or per-principal 'latest' is available to none of them, being unrecoverable from state (EL13)." That is true of Σ, but the note explicitly leaves open (OQ6) *what temporal witness, if any, the system must attach beyond per-home order* — i.e., global ordering is achievable by attaching an out-of-state witness, and its design is unsettled. A builder will need cross-home ordering and must know it's an open avenue with tradeoffs, not a closed door. **Do:** qualify the claim to "unrecoverable from state *alone*; attaining it requires a temporal witness outside the current unit-depth claim schema — what witness, if any, is OQ6," and add OQ6 to the "Mark the scope" list.

**3. Design commitments → "Supersession and retirement are independent acts. [forced]": scope the [forced] and flag OQ2.** Independence is forced *for the `editlink` operation as specified* (EL6iv/EL9: it moves none of the three axes). Whether independence is *mandatory under every admissible layer discipline* is OQ2 — the note lists it open, and EL9 itself says "supersede and retire is available [as a composite]; it is never implied." As written, a downstream commitment "locked in for everything downstream" reads as forbidding a coupled gesture, which contradicts the digest's own later builder decision permitting a *visible* bundled "supersede-and-retire." **Do:** scope the bullet to "the `editlink` operation moves none of the three axes," note that mandatory independence across disciplines is OQ2, and cross-reference the bundling decision (bundling is allowed if visible/separately-attributed).

**4. Implementation approaches → "Link store & allocation": tighten the Green attribution.** "Use an append-only log recovered by replay (e.g. a JSONL journal) — the proven shape of udanax-green's granfilade" overclaims. What the evidence proves is *append-only / write-once / no-overwrite path / monotonically-advancing fresh address* (Q11, Q13). The granfilade is an enfilade (B-tree-like, disk-loaf structured, recovered by structural descent — Q17), **not** a replay log. **Do:** attribute only the append-only/no-overwrite/monotonic-fresh-address properties to Green, and present "log + replay + checkpoint" as the digest's own realization of those properties (a fine one) rather than Green's shape.

**5. "Mark the scope the substrate leaves open": add OQ5 and OQ8 (substance is covered, but they aren't flagged as open).** The digest handles the standoff (`current = ∅`) as a legitimate disclosed outcome and tells the builder bundling must stay visible — but the note flags as open (OQ5) *whether any assertion discipline can guarantee a non-empty currency answer and whether that is compatible with open authorship* (directly relevant to the fork/standoff workflow decision), and (OQ8) *what coupling invariant, if any, should bind an edit to the home registry's listing* (directly relevant to the "what the edit gesture bundles" decision). **Do:** add both as scope-markers so the builder knows these are unsettled, not free-for-all.
