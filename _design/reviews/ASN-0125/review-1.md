Orientation: this is a strong digest — the forced/chosen markings are all defensible (I checked each against EL0–EL16 and found none miscoded), every udanax-green claim is grounded in the Q11/Q13/Q15/Q16/Q17/Q19 evidence, and the read-model approach is Lampson-faithful (hints over authoritative state; `succ_o` derived by filtering claim addresses, correctly sidestepping the EL14(e) endpoint trap). The improvements below are real but mostly localized.

**1. "What must be built" / "Require active enforcement" (editlink): the DC precondition is missing — add it, with its hazard.**
The digest specifies editlink as "allocate the successor, then assert; exactly two allocations; nothing else touched," but omits editlink's value-level precondition `DC(ℓ')` (EDITop; EL7(vi)). This is load-bearing, not cosmetic. DC (a) bars a retraction-class successor and (b) forces a `[K_sup]`-classed successor to satisfy the claim schema. Without (a), an "edit" whose `ℓ'` has slot-3 coverage `= coverage(R)` deposits a retraction tuple in step 1 and *silently nullifies whatever `ℓ'.e₂` points at* — violating EL7(iv)'s "nullifies nothing." DC is precisely what makes editlink discipline-preserving (EL7(vi)) and therefore chainable. The digest's "Schema conformance enforced at assertion time" covers `assert_sup` but not editlink's successor-value constraint. Add: editlink must validate `ℓ'` (reject retraction-class successors; schema-conform a claim-class successor) — it is not a blind allocate+assert.

**2. "Implementation approaches → Link store & allocation": drop the false-precise "this repo's links.jsonl" and the bare crate name (altitude/grounding).**
"Use an append-only journal recovered by replay — exactly this repo's `links.jsonl` + replay model" asserts a specific implementation artifact that appears in neither the note nor the evidence and is not visible in this (spec) repo. The recommendation stands entirely on its grounded leg — Green's append-only granfilade with no in-place endset mutation (Q11) — so keep that and state the journal at design altitude ("an append-only log, e.g. JSONL, recovered by replay"). Same fix for "the `im` crate's HAMT" → "a persistent / structurally-shared map." These are the digest's only altitude slips.

**3. "Implementation approaches → claim store" / "Decisions → class-comparison": the enum-tag shortcut understates its cost and risks a forced commitment.**
The note forces the kind to be the *coverage class of the type slot* (EL3), and a tuple is in `S^Σ` only if its stored slot-3 coverage equals `coverage(K_sup)` (Df-CLS). So the stored kind must remain a coverage-class endset; an enum can at most be a local comparison cache decoded from it. Storing an enum *as* the kind makes the tuple not a `[K_sup]` claim at all, and — per Q19, where the type is an opaque I-span that clients coordinate on by convention — defeats independent cross-client minting/recognition of subtypes, which is the entire reason the kind is a coverage class. Recast the tradeoff: the cost of a true enum is not merely "lose refinement" but "lose substrate membership and cross-client agreement"; the enum is admissible only as an in-memory index over a stored coverage class.

**4. "Design commitments" / "Decisions → currency policy": surface that per-home 'latest' *is* state-recoverable.**
"There is no canonical 'latest'" is correct cross-home, but the digest never states the other half of EL13: within one home (one document chain) claims are totally ordered by address, so per-home / per-document-chain "latest" is well-defined and state-computable. This is exactly what legitimizes the "follow per-home latest" reader policy the digest itself lists — without it, that policy reads as if it contradicts "no latest." State which temporal ordering is recoverable (per-home) and which is not (cross-home, per-principal).

**5. "Guarantees" / "How it fits": elevate reference survival from a by-product to the stated criterion.**
The note makes reference-survival (Q10, EL16) the explicit test separating a permanence-preserving edit from a mutating one, with two named failure modes: mutation silently re-points every existing citation/comment/dispute; silent re-creation strands them with no road forward. The digest mentions it only as a consequence of endpoint frame. Promote it — it is *the* reason "allocate + assert" is the unique correct regime, and the two failure modes are the concrete justification for rejecting both in-place update and delete-and-recreate.

**6. "Decisions for the builder": flag the note's open questions as scope markers — especially wholesale-vs-span-level edits.**
The note opens with "an endpoint widened, a target corrected, a type refined," yet the model offers only *wholesale* replacement: even widening one endpoint means allocating a complete new link value and asserting supersession, and whether the record must carry span-level correspondence between old and new endsets is explicitly open (OQ7). A builder may otherwise expect a fine-grained endpoint-edit op the note doesn't provide. Add a one-line scope marker (wholesale replacement only; span-level correspondence unresolved), and similarly flag third-party-retraction authority (OQ1) and meta-claims-on-claims (EL8(d)/OQ4 stratification) as policies the builder must define rather than things the substrate settles.

Genuinely solid and needing no change: the EL0/EL1/EL2–EL3 commitment chain; the NonInjectivity "do not content-address links for identity" trap (correctly grounded in L11b); the "address freshness even after de-listing" allocation obligation (correctly handles the Q12 V-position-reuse trap by sourcing the max from the journal, not the live listing); and the unit-depth-discipline ⇒ no-range-queries insight for the endpoint index.
