Reviewing the digest against ASN-0111, its formal claims, and the verified evidence. The digest is strong overall — the layering thesis is the right organizing idea and the permanence/caching machinery is handled well. The defects below are concentrated in a few load-bearing claims.

---

**1. "Implementation approaches → Organizing decision": the anomaly attribution is ungrounded and self-contradicting — replace it.** The digest states the read/resolve fusion "is what produced Green's unexplained 'type endset comes back empty when both endpoints are deleted' anomaly." The evidence (Q14, Q19) explicitly says this anomaly's mechanism "is not explained by any KB entry" ("either a bug or an undocumented dependency"), so asserting a definite cause is ungrounded. Worse, the mechanism the digest *names* — "silently dropping unmapped addresses" — cannot produce this anomaly: the type endset points into the bootstrap document, which the evidence stresses is *unmodified* when the endpoints are deleted, so its addresses are not unmapped and would not be dropped. Do this instead: motivate "factor the raw read as its own layer" with the *explained* orphaned-link case (Q15/Q17) — the raw read (`link2sporglset`) returns the endset I-address spans unchanged, while Green's fused `FOLLOWLINK` returns empty V-spans because resolution drops unmapped addresses, so the intact recorded relationship is invisible at the only operation Green exposed. That is exactly RL6's territory and is precisely the note's **open question 2** (a legitimately-empty endset must stay distinguishable from one whose spans merely reference unwitnessed content). Name that open question as the principled reason to keep the layers separate. If you keep the type anomaly at all, cite it only as "an effect Green never explained," not as a consequence of the fusion.

**2. "Design commitments" / "Guarantees to uphold": the mandatory-non-empty-type asymmetry (L3) is missing, and Green's divergence from it is unflagged.** The note commits to the "mandatory-type / permissive-direction split": a successful read always yields arity ≥ 3 with a *non-empty, usable* type endset (`e₃ ≠ ∅`), while the from- and to-slots may each be `∅` (RL1 corollary; worked-read structural corollary). The digest states "arity ≥ 3" and "ghost-typed links read completely" but never states that the type slot is guaranteed non-empty while connectives are permissively empty — and ghost-typing is a *different* property (a non-empty type whose spans point at unallocated addresses). State this commitment and note that readlink *inherits* it by verbatim disclosure rather than enforcing it. Then extend the "Conventional" arity discussion: Green diverges on the *lower* bound too — it permits 2-endset links and an absent/empty type (Q19, Q14), not just caps the upper bound at 3 — so honoring the note's mandatory non-empty type is a conscious model-fidelity choice, not a given.

**3. "Permanence classification and caching" (and "Decisions for the builder → Cache footprint"): "do not cache negatives" overstates the note.** RL5's caching discipline clause (ii) explicitly *permits* caching `⊥` permanently wherever an address-computable permanence proof applies; the flat "Negative results: do not cache — recompute" (echoed by "keep no negative cache") contradicts that stated option. The underlying engineering call is sound — recomputing the classifier (a few field projections) is cheaper than a store probe, so permanent-`⊥` addresses need no probe — but frame it as "caching permanent `⊥` is permitted but usually redundant," not as a prohibition. Keep verbatim the one hard rule the note does impose and the digest gets right: residual-class `⊥` must *never* be cached.

**4. "What this is": search is mis-placed as something readlink "sits below."** The intro says readlink "sits below all resolution and search," but search (FINDLINKS/COUNT) does not sit on top of readlink — it reaches links through the content-region index (the spanfilade), a separate path, as the digest's own "How it fits" correctly calls a *sibling*. Reword: readlink sits below *resolution* (FOLLOWLINK) and *beside* search.

**5. Minor altitude / sourcing.** "(the `im` crate)" names a specific library — return to design altitude by stating the property ("a persistent, structurally-shared map") and leaving the crate as an aside at most. The "`links.jsonl` + `paths.json` … replayed on load" substrate claim is a repo fact (not a udanax-green claim, and not in the note or evidence); fine if the repo actually has it, but it carries no basis here, so don't lean on it as evidence for the "append-only journal" pattern — the immutability/append-only argument (L12/LP13) already carries that on its own.
