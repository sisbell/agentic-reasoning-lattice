## Revision list

**1. Decisions for the builder / Design commitments — surface the result's self-identification (open question 3 is unaddressed).** The digest establishes "identity is by address, don't dedup" and that `home(a)` is derivable from the key, but never draws the load-bearing dual: the returned *value* is address-free. The note is explicit (L2/RL1: `home(a)` "is no part of this returned value"; RL4 makes readlink a function of `(a, Σ.L(a))` whose *output* is just `Σ.L(a)`). So two structurally-identical links return **equal values**, distinguishable only by the caller-retained query address — which is precisely the note's open question 3. Add a builder decision: does readlink return a bare value (caller owns identity/home via the key) or a self-identifying `(address, value)` pair? The note implies the former. State the consequence so a builder doesn't denormalize the address into the value and let downstream value-equality masquerade as identity.

**2. Design commitments (Forced, "Disclosure is verbatim") — "a fragment of a stored link is itself a valid link" over-generalizes.** RL1 says `Link` is closed only under *shrinking a connective slot* (`(F',G,Θ)` with `F'⊊F`). A fragment that empties/drops the *type* slot is **not** a valid `Link` (L3: `e₃≠∅`), and an arity-`<3` return is rejected by the `Link` definition. So the type does catch two classes of incompleteness — empty type and arity below 3 — while span-level fidelity, connective-slot completeness, exact arity for `N>3`, and slot order are the behavioral obligations. Fix the parenthetical and carry the precision into *Guarantees → Completeness*, so the builder targets tests at span/connective fidelity (and `N>3` arity preservation) rather than assuming the type enforces nothing.

**3. Implementation approaches (Organizing decision) — fix the arity of the Green correspondence.** "READLINK is exactly the raw structural read … (`link2sporglset`)" and "FOLLOWLINK be *readlink ∘ resolve*" mis-state the shape. Per Q11–Q13, `link2sporglset` is *per-endset* (selected by `whichend ∈ {1,2,3}`); it returns one slot's raw spans, not the whole link. READLINK discloses *all* slots in one read (preserving arity, including `N>3`); FOLLOWLINK first *selects* one endset, then resolves it — so it is `resolve ∘ select ∘ readlink`. Keep the (correct, valuable) layering point, but say READLINK corresponds to *assembling* `link2sporglset` across all slots and that FOLLOWLINK additionally selects one. Otherwise a builder may copy Green's per-endset signature and miss that readlink must return the whole link at once.

**4. Design commitments (Conventional, arity bullet) — re-anchor "Green doesn't enforce a non-empty type."** The claim is right but leans on the weaker, internal-only `domakelink` 2-endset path, which the exposed FEBE `createlink` never takes (all protocol-created links go through `docreatelink` with three slots). The stronger, protocol-reachable evidence is Q14: even the three-slot path stores *no* type when the type VSpec resolves to nothing (the type endset is silently omitted at insert; the golden read returns `type: []`). So Green holds and reads back links with an empty/absent type, directly contradicting L3's `e₃≠∅`. Cite that. Optionally note the model reason — Green captures *resolved* I-addresses at creation, whereas the note stores address-spans abstractly — which is why mandatory non-empty type is a store-side enforcement the reference doesn't give you.

**5. Solid, with one small label.** The organizing decision, the permanence/caching discipline (correctly fencing the residual class — the one real correctness landmine), and the forced/conventional split are all sound and faithful; leave them. Label it as such, so all three open questions are visibly accounted for: Q2 handled, Q1 answered-in-substance, Q3 the real gap from item 1.
