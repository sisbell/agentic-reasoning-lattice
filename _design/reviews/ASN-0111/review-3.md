The core of this digest is genuinely strong and I won't manufacture problems against it: the organizing decision (readlink is the *raw* read Green computed in `link2sporglset` but never exposed; FOLLOWLINK = `resolve ∘ select ∘ readlink`; the orphaned-link cost made visible) is the best engineering insight here and is well-grounded in the evidence; the RL4/RL6 layering rule, the caching/hints discipline (with the residual-class landmine correctly fenced), and the identity-by-address / bare-value handling are all accurate and committal. The forced/conventional split is correctly assigned. Below are the improvements worth applying, real defects first.

---

**1. Design commitments (Disclosure) and Guarantees (Completeness): "the type rejects an empty type slot" is inaccurate and self-contradictory.** The codomain `Link = {(e₁..eₙ) : N≥3, each eᵢ∈Endset}` *permits* e₃ = ∅, since ∅ is a valid Endset. The empty-type-slot prohibition is invariant **L3** (a link-store invariant from ASN-0043), which readlink inherits *by verbatim disclosure* — not by the type. The digest's own later lines say exactly this ("the store enforces it, the read does not"; "inherited, not enforced"), so as written it contradicts itself and misallocates the mechanism in two places. Fix both: the type rejects only **arity < 3**; list "non-empty type slot (e₃≠∅)" with the store-enforced/inherited guarantees. This matters to the builder's modeling decision — a `Link` newtype constrains arity but will *not* stop e₃=∅; that invariant must be separately enforced or trusted.

**2. What must be built (address-analysis module) / structural screen: the field projections are partial, and guarding their domain is a well-definedness requirement, not just the screen's optimization.** `subspace_I`, `#E`, node-lineage head, and user-field width are defined only on T4-valid tumblers with zeros=3 (on `[1,0,0,2,0,3]` they have no value — the note spends a paragraph on this). The digest lists them as if total and attaches "left-to-right, short-circuiting" only to the *optional* screen. But the **permanence classifier** is a must-build, non-optional component (it gates caching) that runs the *same* projections on *arbitrary* addresses; it too must establish T4-valid ∧ zeros=3 (screen-failure → permanent ⊥) *before* projecting #E/N/#U. State that these projections are partial and conformance-before-projection is a correctness requirement for both consumers — distinct from the genuinely optional choice of *whether* to screen on read.

**3. Implementation approaches (Concurrency): the "matches Green … lockless" citation grounds the wrong property.** The lock-free/MVCC claim is sound, but it follows from the note's *immutability + persistent sharing* alone — ground it there. Green's evidence (Q20: link orgl readable by ISA with `NOBERTREQUIRED`, no document-open precondition) is about *access control / global addressability*, not concurrency; BERT is an open-handle/permission table, not a thread lock. Re-ground the concurrency claim in immutability, and relocate the Green "ungated, globally addressable" point to where it belongs — the *first-class addressable object* commitment — rather than presenting it as confirmation of MVCC.

**4. Implementation approaches (organizing decision): you claim to "answer open question 2," but you relocate it.** OQ2 asks what *FOLLOWLINK* must guarantee so a legitimately-empty endset stays distinguishable from one whose spans are merely currently-unwitnessed. Keeping readlink as a separate raw layer lets a *consumer* recover that distinction (call readlink, not just follow) — but it does not tell FOLLOWLINK itself how to keep them distinct; resolution still collapses both to empty at the follow operation. Sharpen: readlink's separate existence *preserves the information needed* to answer OQ2; FOLLOWLINK's own guarantee (signalling empty-recorded vs. empty-after-resolution) remains the open question. (OQ1 and OQ3 are answered well — leave those.)

**5. Conventional divergence / arity-> 3 decision: Green diverges on the *lower* arity bound too, at the store level — add it for symmetry.** The digest flags only the e₃≠∅ divergence and presents arity≥3 as cleanly type-enforced with "fixed-triple matches Green." But Green's internal `domakelink` path stores genuine 2-endset links (Q19/Q2), so neither arity≥3 nor e₃≠∅ is a store-level invariant Green upholds. One line: honoring **both** mandatory arity≥3 and mandatory non-empty type is a conscious model-fidelity choice; Green's FEBE path yields three slots but its store admits 2-slot links, so "fixed-triple matches Green" holds for the protocol surface, not the store.

**6. Design commitments / Guarantees: make the reachable-state trust assumption explicit — it is the unstated premise under "the store enforces it, the read does not."** readlink is specified only over →*-reachable, invariant-satisfying states, so every value the store can hold already satisfies L0–L13 (arity, non-empty type, well-formed spans). That is *why* verbatim disclosure is safe without re-validation. State it once: the read trusts stored values because allocation is the only writer and only reachable states occur — and a builder who can introduce values by any path other than the allocator must re-establish the invariants. This also tells the boundary-validation decision (last builder item) precisely when it bites.
