**Revision list (most important first):**

1. **[DEFECT] Guarantees ("Reaching quiescence") + Forced-commitment #7 package (i): H-RF is not free under "bounded input + fairness," and an idle environment does not supply it.** The digest states "The engine *always* guarantees the registry-side half — finitely many real fires, inert past the last — under bounded input + fairness," and lists package (i) as "environment idles (any registry)" with no H-RF. Both are false for a non-SF registry. The note makes H-RF an *independent* hypothesis ("drop H-RF and rules can re-arm each other forever… genuinely separable"): under bounded — even *zero* — external input, Q4 mutual re-arm and Q5a's "stays ⊤ on a fixed argument forever" both produce unbounded real fires, each fire depositing and growing the substrate. H-RF is structural *only* for an all-SF+extinction registry under bounded growth (Q5a); otherwise it is a standalone assumption. Fix: scope the registry-side guarantee to "H-FAIR + H-RF, with H-RF structural via Q5a or separately assumed — bounded input does not supply it," and add H-RF to package (i) (an idle environment does not stop internal re-arm).

2. **[DEFECT] Registration analysis, "reusable design pattern to certify": "type-isolate rule domains (no rule's emission enlarges another's domain)" is false for the cmt/res registry it cites.** ρ_P's `cmt` emission *does* enlarge ρ_R's domain `L_cmt` — a builder certifying against this rule would reject the very exemplar. The note's type isolation is asymmetric: ρ_R's `res` does not feed ρ_P's domain (no back-edge), *and* ρ_P's domain is fed only by the environment (the crux — no rule writes `attn`/`tgt`); ρ_P→ρ_R is an intended, *bounded* one-way edge. Fix: state the pattern as an **acyclic** rule-emission dependency graph (no rule's output re-arms an upstream rule) with each root domain environment-bounded — not "no emission enlarges another's domain."

3. **[DEFECT] Forced #7 / Guarantees, regime (ii): "no environment hypothesis" is wrong.** Regime (ii) requires bounded growth, which the note explicitly classifies as "a bound on external input." The note's precise wording is "no environment-**idle** hypothesis" (the environment need not stop, only stay bounded). As written the gloss is internally inconsistent with the digest's own listed "bounded growth" and with its scheduler claim that "termination needs bounded external input." Fix: "no environment-*idle* hypothesis (bounded input still required)," and soften the "structural (ii) vs. environmental otherwise" dichotomy — bounded input is environmental in *every* route; regime (ii)'s only structural advantage is needing no idle.
