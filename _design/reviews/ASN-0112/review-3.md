## Revision list (most important first)

**1. Guarantees → positive-extent/non-negative-width: complete the Q18 citation and surface Open Question 5 — the root *origin* can go negative, not just the width.** The digest cites Q18 only for "root width stays non-negative," and phrases it as a clean contrast ("intermediate tree nodes can hold negative displacements … yet the root width stays non-negative"), which nudges the reader to assume the root is fine. But Q18 also establishes that the root *displacement* (the reported origin/start) can be driven negative by same-subspace deletes that produce negative intermediate displacements — "setwispupwards absorbs them into the root's cdsp (shifting the document's reported origin)," yielding a start that violates S8a (zero-free, positive). The note flags exactly this as **Open Question 5** ("origin and extent when content occupies V-positions whose addressing arithmetic has been driven outside the well-formed range by prior editing"). This is a real soundness hazard *specific to approach 2* (the confluent relative-displacement summary the digest endorses); approaches 1 and 3 sidestep it because they read `min` as an actual stored key. Add a sentence to approach 2's tradeoff and to the guarantee: the non-negative-width discipline does *not* protect the origin, the spec leaves repair open (OQ5), and an enfilade builder must guard against (or accept) negative root displacements that the ordered-map/hint approaches cannot produce.

**2. Decisions → tumbler in-memory form: "leading-zero-permitting" is too narrow for the general case the digest itself claims to handle.** The digest cites `[1,2,0]` as a width but describes the width type as "leading-zero-permitting" and claims component-vectors suffice "independent of any depth policy." `[1,2,0]` carries a *trailing* zero, and trailing/interior-zero widths arise *only* under depth divergence. So the claim is internally inconsistent: under the recommended equidepth policy widths never carry trailing zeros (`[0,n]` or `[1,2]`), so "leading-zero" is fine — but for the depth-divergent case it explicitly says it covers, the type must permit zeros in *any* position. Fix one side: either scope the type statement to "under equidepth, widths need only leading zeros," or broaden it to "widths/displacements permit zeros anywhere (the cited `[1,2,0]`), unlike zero-free positions (S8a)."

**3. Approach 3: cut or genericize the "links.jsonl-style log" detail — it is grounded in neither the note nor the evidence.** It is hedged ("if this repo's substrate is in fact…"), so it is not a fabrication, but the specific artifact name is unverifiable repo-speculation that adds nothing the generic "append-only journal recovered by replay" doesn't already carry. Drop the parenthetical example or replace with the generic mechanism; the Lampson hint-with-replay-recovery point stands on its own.

**4. Design commitments → composition insensitivity: the summary sentence "Only clearing content entirely, or moving the max, moves the span" omits the symmetric V18 case.** First-content insertion into a link-only document moves the *min* downward (origin migrates to the content anchor, V18) — a composition change that moves the span but is neither "clearing content" nor "moving the max." You capture V18 correctly in commitment 8, so this is a local incompleteness; make the summary symmetric: "clearing content, adding first content, or moving the link max."

**5. Open Questions: surface OQ2 (and note OQ3/OQ4), because the digest takes a firm position the note leaves partially open.** The digest repeatedly instructs "read `min O(d)`, never hardcode the content anchor" — but OQ2 explicitly asks "under what conditions must the reported origin be the document's *permanent tumbler identity* (`d`) rather than the minimum occupied V-position." The digest's firm `min O(d)` stance is defensible (V1/V8 are firm), but it should acknowledge the spec leaves open whether origin should ever be the document identity instead. OQ3 (historical-version faithfulness — connects to your version-creation discussion) and OQ4 (whole-span vs correspondence-run spans composing global from local — connects to the span-set sibling) are also unsurfaced; one line each would complete the "what the spec leaves unresolved" picture for a builder.
