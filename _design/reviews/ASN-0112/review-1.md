**1. "Implementation approaches → Discriminators" (and the opener / commitment 1): surface V12's count-derivability — the most builder-relevant omission.** The digest insists "never a count / never a cardinality" and lists exactly two width-readable facts: V9b (first component `= 0` ⟺ exact) and V9a (last component `> 0` ⟺ tight reach). But the note's V12 establishes a *third* fact riding the same slot: in the single-subspace regime the width is `[0,…,0,n_s]`, so its **final component equals `|O(d)|` exactly** — the occupied count is recoverable for free from the returned width, even though the result *type* is not a count. Add this, scoped to single-subspace, and state the nuance directly: the result is not *typed* as a cardinality yet *determines* the cardinality in the common case. Note that the cross-subspace case does **not** (it is the note's first Open Question), so a builder doesn't assume the count is always free.

The evidence contradicts this: Green's version creation uses a *separate content-only* primitive (`doretrievedocvspanfoo` / `retrievedocumentpartofvspanpm`, Q14/Q17), precisely because RETRIEVEDOCVSPAN's bounding box bridges subspaces and would not yield the content-only extent. Fix the attribution — and note it concretely demonstrates the digest's own "redirect fragmentation-sensitive callers" thesis.

**4. "Design commitments" #10: "half-open reach … conventional" conflates a forced denotation with a genuine design choice.** The half-open *denotation* is forced (inherited from ASN-0053 T12). Reclassify: half-open denotation forced; the same-depth one-step reach a *justified construction* (tight among same-depth tumblers, provably well-formed by V2), with `w.0` an open alternative — not a bare convention.
