**1. "What must be built" (placement) + "Guarantees to uphold": surface destination-`p` validity as a precondition, and stop attributing "no holes" to key-vacating.** The placement invariant — *"vacating the old keys (no double-binding, no holes)"* — conflates two independent guarantees. Vacating pre-shift keys (CP3c) prevents **double-binding**; it does nothing about **holes**. No-holes (the note's D-CTG/D-SEQ/D-MIN "prior arrangement preserved" section) holds only because the note requires `p` to be a *valid insertion position* — `p ∈ [min, max+1]`, inside the existing run or at its boundary — placing a contiguous `W`-block. An out-of-range `p` leaves a gap no matter how carefully you vacate. The note makes `p`-validity load-bearing (it's in `enabled(COPY)`); udanax does **not** check it (`acceptablevsa` is an unconditional stub — depth/VSA evidence answers). So this is also a missing builder decision: enforce the note's valid-`p` (preserve contiguity) or accept-any like udanax (tolerate holes). Add `p`-validity to the precondition list and split the invariant (vacate ⇒ no double-binding; valid-`p` + contiguous block ⇒ no holes). *(Related: the empty-destination case `V_{s_C}(d)=∅` forces the builder to choose the new subspace depth `m ≥ 2`, per ValidFirstInsertionPosition — surface this for any tumbler-keyed representation.)*

**2. "Implementation approaches → Resolution": carry the note's central immunity result — resolve by reading the bound image, never by offset arithmetic from the span start.** The digest captures relaxed admissibility ("intersect with bound positions, no depth/shape validation — pure order intersection") but drops the punchline the note's longest argument exists to establish: the abstract resolution is *immune* to a real udanax bug **because** it reads each address as the actual image `M(d_s)(v)` of a bound position, rather than clipping the span boundary to an integer offset. udanax's `context2span`/`tumblerintdiff` discards sub-depth structure, so a cross-depth boundary is silently mis-read as a content offset and the wrong I-spans returned (the depth-mismatch and clipping-stage evidence answers) — this is exactly the note's open question 2. "Reuse ASN-0058's `resolve`, don't reinvent" implies the right thing but doesn't warn against the wrong thing. State it: derive each resolved address by reading the arrangement at the bound position; offset arithmetic from the span start is the cross-depth bug to avoid.

Σ.R is **recoverable from the journal**, not recomputable from current state. As written, the sentence contradicts the distinction the section is built on.
