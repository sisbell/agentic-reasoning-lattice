The digest is faithful and well-pitched — the sum-type / by-construction spine is exactly the right reading, and several Green caveats are sharp. The defects below sit mostly in the *justifications* and a few Green attributions, not the core recommendations. Ordered most-important-first.

**1. Implementation approaches (and every "≤7 / tiny / bounded" instance): the length bound is false.** The spec bounds the zero-*count* (`zeros(t) ≤ 3`), not the address *length*. Fields between separators can be multi-component — Green's own `defaultaccount` is `1.1.0.1`, whose node field "1.1" is two components — and a Node (zeros=0) is *any* zero-free sequence, hence unbounded. The element example is 7 components only because its fields are single-component; that's the *minimal* element, not a maximum. The recommendations (don't build machinery, single scan, no `im`, recompute-on-demand) all survive, but re-ground them: classification is a single left-to-right **O(#t)** pass with O(1) carried state — cheap because it is a *scan, not a parse*, not because the input is small. Fix "a valid address is ≤ 7 components," "bounded ≤7-component address," "pure, total, and **bounded**," and "fine at this size."

**2. How it fits → ownership: don't call `tumbleraccounteq` "the account predicate."** ASN-0045's `Account(t)` is a one-place *level* predicate ("is t account-shaped," zeros=1). `tumbleraccounteq` is a two-place *containment* relation ("is document d under account a") — which the digest itself defers to "Adjacent but not here." The "structural ≠ ownership" hazard is real, but it lives at the *containment* layer (Green pairs `tumbleraccounteq` with `isthisusersdocument`), not at this note's level predicate. Reattribute: ASN-0045 supplies only the pure level fact; containment and ownership both sit above it. As written, containment is simultaneously "the account predicate here" and "adjacent, not here" — an internal contradiction.

**3. Guarantees → Depth ceiling: "five-separator" is off by one.** The first over-depth address is `zeros=4` = **four** separators (a fifth field) — exactly the note's counter-example `[1,0,1,0,1,0,1,0,1]` (four zeros). "Five-separator" is zeros=5. Fix to "four-separator (zeros=4)" and cite that counter-example row; the substance — this is the one clause that must be *actively checked* — is correct and worth keeping.

**4. Design commitments → naming: "user appears only in ownership predicates" overstates the evidence.** The code-exploration evidence shows `user` is *also* (and primarily) an integer session-slot index (`userid`, `player[user]`) — not a tumbler concept at all. Tighten: structural/addressing code uniformly says *account*; *user* survives as a session-slot index and in ownership predicates, but never as the level name. The note's point (account is the structural term) is unaffected.

**5. (Sharpening) Make the load-bearing "exclusivity needs no name table" explicit.** The note labors to show Partition rests on counting zeros + ℕ-discreteness, *not* on T4c's level-name bijection (reading it off the bijection domain would be circular — "T4c is **not** a premise"). The builder payoff is concrete: the classifier guarantees exactly-one-level by comparing zero-counts *alone* — it needs no level-name lookup/table for correctness or mutual exclusion; the name↔level correspondence (T4c) is a separable derived fact used only for *reporting*. The digest gestures at this ("reduces to 'the scan implements zeros correctly'") but should state it outright so the builder knows the classifier core is name-free.

**6. (Sharpening) "spanfilade" is the wrong Green structure for address/containment indexing.** The evidence ties address allocation/containment to the **granfilade** ("allocates a new node or account in the granfilade"); the spanfilade indexes spans/links, not address-prefix containment. Name the granfilade, or drop to the generic "enfilade."

**7. (Sharpening) Parse-once option: "level becomes the count of populated fields" is off by one.** A valid address populates 1–4 named fields; the level is the *last populated* field — populated-count − 1 = zeros. As written, a Node populates 1 field but is the zeros=0 level. Restate to avoid baking in an off-by-one.

**8. Leave alone (solid):** the five-way-sum / by-construction framing of Partition + Off-Domain Vacuity; the fused single-pass validate-and-classify; the admission-gate placement (validate once at the front door, downstream never re-checks); the Green-encoding caveat (double-zero terminator + header words ≠ the spec's single-zero-separator model — a correctly-grounded catch); and the Invalid-carries-the-failing-clause decision keyed to the four counter-example rows. These are faithful and at altitude; don't churn them.
