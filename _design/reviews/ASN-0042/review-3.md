## Revision list

1. **Implementation approaches / Principal registry: `[SHARPENING]`** — The two-layer structure of Option A is sound but reads as a near-contradiction. You say "account creation inserts the prefix into the granfilade" and endorse storing prefixes there (the durable log), then say "Do not reach for the granfilade/enfilade machinery here" (the resolver). Both are right but they are *different layers*. Make explicit: the granfilade/journal is the durable append-only **log**; the resolver operates over a **derived in-memory principal index** recovered by replay — the prohibition is on using the enfilade query path for longest-match, not on storing prefixes in the granfilade. One clause prevents a builder from thinking the advice conflicts.

2. **What must be built / Bootstrap: `[SHARPENING]`** — The bootstrap checklist enumerates O14.1–.8 (nonempty, finite, account-tier, injective, valid, non-nesting, covers, every-prefix-baptized) but drops O14.9: `Σ₀.B` must itself be an ASN-0040-reachable, B₀-conformant registry. It is a cross-layer precondition inherited from baptism, but it belongs on the seed-state checklist for completeness; without it the "every prefix is baptized in Σ₀.B" clause has nothing well-formed to land in.

3. **Guarantees / Uniqueness: `[SHARPENING]`** — "Enforce (v) and (ii); uniqueness then needs no runtime check" is *true* (the set is sufficient), but the attribution is loose. The operative clause for injectivity (O1b, hence uniqueness) is **(v)** freshness — given PrefixBaptismCoupling, `pfx(π') ∉ Σ.B` forbids collision with any existing principal's (baptized) prefix. The note *also* derives O1b from **(i)+(ii)** via the length contradiction. Either route works and the gate enforces all five anyway; just name (v) as the clause that carries uniqueness so a reader doesn't infer (ii) alone secures it (it does not — it needs (i)).

4. **Delegation gate: `[SHARPENING]`** — "condition (iv) is a subtree-emptiness query … O(1)-ish in a trie" overstates. Walking to the `pfx(π')` node is O(prefix-length) and the emptiness test is O(1) *only with augmentation* (a maintained has-principal-descendant flag or subtree count); without it the test is O(subtree). The honest claim is "independent of |Π| with subtree augmentation," which is still the right reason to prefer the trie here.
