## Revision list

**1. [DEFECT] "Recovery and durability" mis-classifies the arrangement (`Σ.M` / per-document POOMs) as derived state, and names only the link journal as source of truth.** The note's state is `Σ = (C, L, E, M, R)` with `M` an *independent authoritative component*, moved by `K.μ⁺/μ⁻/μ~` and read by Phase 1 — and the digest itself lists "two distinct state-dependencies (M for resolution, L for matching)" as a **forced** commitment. The POOM *is* `M(d)`: editorial state encoding which content is arranged where, not derivable from the content or link allocations. So listing "per-document POOMs" among "derived state rebuilt by replay" of "the append-only link journal" is wrong on two counts — it contradicts the digest's own forced commitment #5, and it contradicts the digest's *own* "What must be built / Recovery" line, which correctly scopes "derived" to indexes and caches. A builder could fail to durably persist arrangement edits and lose all arrangement state on recovery (replaying the link journal reconstructs links, never arrangements). Fix: name the authoritative state as the per-component append-only logs — content (`K.α`), links (`K.λ`), arrangement edits (`K.μ*`) — with the POOM the *materialized arrangement* whose source of truth is its own edit log; only the spanfilade (from `L`), the granfilade-as-index (from `C`), the per-document I-footprint hint, and the result caches are derived/rebuildable.

**2. [SHARPENING] "The link matcher": make explicit that this note's disjunctive primitive does *not* require per-slot index tagging.** `findlinks(I)` is fully served by a *slot-collapsed* coverage index — index each link by `⋃ᵢ coverage(eᵢ)` and test that union against `I`, since `(⋃ᵢ coverage(eᵢ)) ∩ I ≠ ∅ ⟺ ∃i coverage(eᵢ) ∩ I ≠ ∅`. Per-slot tagging (Green's `LINKFROMSPAN/TO/THREE`) is a forward-investment for the conjunctive Q2 query, not a requirement here. The "even though this note's primitive is slot-disjunctive" hedge is there; sharpen it to "not required by this note, but build it anyway to serve Q2" so a builder doesn't read slot-aware indexing as forced.

**3. [SHARPENING] "Caching … μ~ clause": name the loss-side recheck target.** The μ~ maintenance borrows "the Δ-bounded drop recheck of the μ⁻ clause," but the correct recheck set for a loss candidate is the *retained-core* image `image(W,Σ) ∩ image(W,Σ')` (the un-moved part), not the μ⁻ clause's `I_R`. After dropping loss candidates that miss the retained core, the `findlinks(Δ_gain)` union re-admits any link re-witnessed by a gained address, giving the order-independent `(old ∖ failed-loss) ∪ findlinks(Δ_gain)`. The takeaway (localized incremental maintenance, no full recompute) is right; just state the retained-core target so the μ⁻ analogy isn't applied verbatim.

**4. [SHARPENING] "Region resolver": present the cross-subspace decomposition as the resolver's consequence, not a note result.** C1a is stated in the note only for a contiguous `W` *within a single subspace*; "a `W` straddling content and link subspaces decomposes per subspace (one run set each)" is a sound extrapolation (subspaces are disjoint `s_C`/`s_L` address lanes) but not a note lemma. Keep it — just frame it as inferred from subspace disjointness rather than as C1a.
