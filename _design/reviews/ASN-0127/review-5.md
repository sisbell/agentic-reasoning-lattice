## Revision list

**1. [DEFECT] — Implementation approaches → Caching → Discovery ("If you key invalidation instead of maintaining…"); echoed in Guarantees → "Discovery present-tense semantics" and Decisions → "image-keyed conservative invalidation."** The claim *"triggering invalidation on image-motion over-invalidates but never under-invalidates"* is false once `K.λ` is in scope. D-ABSORB's necessity direction (image-motion necessary for discovery-set motion) is stated by the note **only across `Σ.L`-preserving transitions**; under `K.λ` the discovery result gains a newly-matching link with the image *fixed* (F-LAMBDA; cf. D-NONMONO's off-`d_q` clause). So a discovery-result cache keyed *solely* on image-motion **under-invalidates** — it serves a stale result missing the new link, the exact correctness bug D-NONMONO warns of. Fix: the trigger is image-motion **OR** a `K.λ` whose new link matches the cached image; scope "never under-invalidates" to store-fixed (arrangement) transitions. (The maintenance route's `K.λ` bullet already handles this; only the invalidation alternative and the "across an arrangement edit" guarantee drop it — so the digest contradicts itself between the two routes.)

**2. [DEFECT] — Implementation approaches → Caching → Discovery → μ⁻ bullet (the D-CWP front-end sentence).** Internal contradiction. The bullet says the Δ-bounded maintenance (`candidates = findlinks(Δ)`, per-link `matches(a, I_R)` recheck) is *"far cheaper than re-querying the (large) retained set,"* then says checking `findlinks(Δ) ⊆ findlinks(I_R)` *"in general costs the same `findlinks(I_R)` you'd otherwise recompute."* But that subset check **is** the Δ-bounded recheck — decide it by testing each `a ∈ findlinks(Δ)` for `matches(a, I_R)`, costing `O(|findlinks(Δ)|)` per-link tests, never a full `findlinks(I_R)` recompute (the new result is the cached old result minus the failed candidates). Both sentences cannot hold of the same computation. Fix: state that the D-CWP predicate is decided by the same Δ-bounded recheck — *not* as costly as recomputing `findlinks(I_R)`; "not a free skip" means you still pay `|findlinks(Δ)|` rechecks, and the genuinely zero-work case is `findlinks(Δ) = ∅`. (Decisions → "Discovery-cache policy" already states the `∅` case correctly; align the prose to it.)

**3. [SHARPENING] — What must be built → region resolver ("contiguous V-spans resolving to a union of contiguous I-runs").** The note's run-decomposition (C1a) yields contiguous I-runs only for a contiguous `W` *in a single subspace*; a `W` straddling content and link subspaces decomposes per subspace. State that scope, so the builder doesn't expect one clean run map across a cross-subspace region — which is exactly the link-document case the digest elsewhere (rightly) makes first-class.

**4. [SHARPENING] — Coverage evaluator ("so at root this is a prefix-containment test").** "at root" reads as "when `x` is the tree root"; the intended sense is "fundamentally." Reword (e.g., "this is fundamentally a prefix-containment test"), especially since the trie discussion later keys off "generating address is an ancestor on the trie path."
