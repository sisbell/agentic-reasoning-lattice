Reviewing ASN-0127's Design Digest against the note, its claims, and the evidence. This is a strong digest — accurate on the forced/conventional split, the regime taxonomy, and the Green divergences. The improvements below are concentrated in the caching plan (the digest's largest load-bearing section), plus a missing precondition and some minor grounding/terminology fixes.

---

## Revision list

**1. Caching across evolution (μ⁻ and μ~ clauses): the "drop" maintenance is framed too pessimistically — bound it by the *dropped* addresses, not the retained region. This corrects two claims at once and recasts D-CWP's cost.**

- The μ⁻ clause says the post-result is "`findlinks(I_R)`, a region-bounded spanfilade query over the **retained** in-region addresses." The μ~-incomparable clause says it is "the only case forcing a **genuine region recompute** … so there is **no incremental shortcut**." Both overstate the cost.
- The change under a drop is bounded by `Δ` (the addresses leaving the region), not by `I_R` (retained) or `W` (region). The only links that can leave the result are those in `findlinks(Δ)`: any link not reaching `Δ` reached `image_old = I_R ∪ Δ` via `I_R` and therefore survives (F-IMONO). So maintenance is: *candidates = `findlinks(Δ)`* (bounded by the small dropped region), *remove each that no longer matches `I_R`* (a per-link `matches(a, I_R)` recheck). For a local edit this is far cheaper than re-querying over the (large) retained set.
- This *is* the incremental shortcut the μ~ clause says doesn't exist. The digest conflates "no **monotone-transfer** shortcut" (true — F-IMONO is not order-reflecting, so you can't read the new result off the old by inclusion) with "no incremental maintenance" (false). For an incomparable reorder, F-IMG-SWING localizes the image change to the positions `π` moves across the `W`-boundary: gain `Δ_gain` (incremental union `findlinks(Δ_gain)`, as in μ⁺) plus loss `Δ_loss` (the μ⁻/Δ-bounded drop above). Rewrite "genuine region recompute, no incremental shortcut" as "gain-union plus a `Δ_loss`-bounded drop recheck — the same shape as μ⁻, localized to the moved positions."
- Recast D-CWP accordingly: it is not a free skip (checking `findlinks(Δ) ⊆ findlinks(I_R)` in general costs the same `findlinks(I_R)` you'd otherwise recompute). It is the *fast front-end* of the Δ-bounded maintenance: when `findlinks(Δ) = ∅` (dropped region reaches no link — the common case for a small edit), the result is provably unchanged with no retained-region work at all. State the win-condition explicitly (cheap iff `Δ` is small/link-poor and the prior result is cached) instead of the vague "weigh the check's cost."
- One closing sentence ties in F-IMG-TAX (currently captured only abstractly): an *injective* arrangement (no content sharing) admits **only** incomparable reorder motion, so both the gain and loss sides always run; content sharing (M13/M14) is exactly what makes pure-gain/pure-loss *containment* motion reachable, letting one side be skipped. So whether a reorder is cheap to maintain is a function of whether the queried document shares content.

**2. "What must be built" / "Design commitments": surface that `findlinks_V` is a *partial* function — undefined for `d ∉ dom(Σ.M)` — distinct from the empty-image (∅) case.** The note states this twice (F-IMG, F-V: "undefined when `d ∉ dom(Σ.M)`"). The digest's resolver only covers "unarranged positions (drop silently)," which is the *within-a-registered-document* case. Querying an *unregistered* document is a precondition violation, not a `∅` result. Call this out so a builder errors on a bad document reference rather than silently returning "no links" for a typo'd `d` — a real correctness boundary the note draws and the digest currently blurs.

**3. "Coverage evaluation": fix the "prefix-closure" terminology.** The digest repeatedly calls `subtree(x) = {t : x ≼ t}` "the prefix-closure of `x`." Conventionally *prefix-closure* means the set of **prefixes** of `x` (downward) — the opposite of this set of `x`'s extensions/descendants (upward). The parenthetical "every address having `x` as a prefix" is correct, but the label inverts the standard reading and could mislead. Use the note's own term `subtree(x)` (or "descendant set" / "prefix-extension set").

**4. "Decisions for the builder" (concurrency): drop or relabel the unverifiable repo-history claim.** "The repo's history of multi-worker torn-read races" is grounded in neither the note, the evidence, nor documented Green structure — it is an uncheckable assertion of fact used to motivate a decision. The snapshot-isolation recommendation is already fully earned by the two-phase coherence argument you make under "Recovery and durability" (a query straddling independent `L` and `M` updates corresponds to no single coherent `Σ`). Either delete the aside or mark it explicitly as local repo context, not a derived requirement. (The `links.jsonl`/`paths.json` substrate mappings elsewhere are fine — they read as deployment analogies, not factual claims.)

**5. (Minor) "Implementation approaches" (whole-document footprint): the per-document `ran M(d)` hint is not trivially incremental under contraction.** The digest says the footprint "moves only under μ⁺/μ⁻," implying simple maintenance. But under content sharing an I-address leaves `ran M(d)` only when its *last* arranging V-position is removed, so incremental μ⁻ maintenance needs refcounting (or footprint recompute). Note this so the hint isn't assumed free to maintain — it's consistent with the same many-V→one-I fact the digest (rightly) leans on for set-dedup elsewhere.

## Solid — leave as-is

- The **`slotmatch` factoring** (this note's `⋃ᵢ slotmatch` vs Q2/Green's `⋂ slotmatch`, neither composing from the other) is a genuine architectural insight and correctly grounded in F-MATCH + the evidence.
- The **empty-*input* vs empty-*conjunct* short-circuit** distinction (don't import Green's AND-collapse into this disjunctive primitive) is exactly right and subtle.
- The **THREE-slot divergence** ("index it, don't replicate Green's broken filter") and the **homedocids coincidence** ("disabled in Green, but `findlinks` is global *by definition* here, so this is not a bug to repair") are both precisely handled — the kind of evidence-vs-contract reasoning the digest is supposed to do.
- The **forced/conventional split**, the **regime split keyed on F-CIL's predicate-reads-which-component** framing (including the correct, F-CIL-grounded observation that a fixed-filter conjunctive query inherits existence-stability for free), and the **index-as-hint / rebuild-by-replay** Lampson framing are all sound.
