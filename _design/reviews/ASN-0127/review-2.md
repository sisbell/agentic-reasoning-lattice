This digest is accurate and unusually careful — its disjunctive-vs-conjunctive (`slotmatch` union vs intersection) analysis, its empty-input-vs-empty-conjunct short-circuit distinction, its "many-V→one-I ⟹ deduped set-union" extraction from the unrestricted union laws, and the torn-(L,M)-read snapshot argument are all genuinely sharp and correctly grounded. I found no hard inaccuracy, ungrounded claim, or altitude slip. The items below are improvements, ordered by value.

**1. Implementation approaches → Caching → Discovery-anchored: "recompute by default" forgoes the per-transition monotone maintenance the note is built to supply.** The digest grants existence caches monotone incremental-add (K.λ) but collapses discovery to "recompute by default; invalidate conservatively." But D-NONMONO is a *per-K-transition* analysis, and per single step the discovery set is monotone except under µ~-incomparable motion. So the discovery cache admits the same incremental maintenance: under **µ⁺/µ⁺_L** on `d_q`, union in `findlinks(Δ⁺)` for the newly-arranged in-region I-addresses (F-IMG-MONO + F-UDIST + F-INERT) — no re-query of the unchanged part; under **K.λ**, test the new link against the *current image* and add the singleton if it matches (F-LAMBDA) — identical to the existence move; under **µ⁻**, the post-result is `findlinks(I_R)`, a region-bounded spanfilade query, or skipped entirely when D-CWP holds (which the digest already cites); only under **µ~ incomparable motion** is a genuine region recompute forced. Replace "recompute by default" with this discipline. Add the cleanest special case explicitly: **whole-document / F-FULL discovery is reorder-immune** — `image = ran M(d)`, preserved under µ~ by LP11 — so the F-FULL result and the `ran M(d)` footprint hint update only on µ⁺/µ⁻ and K.λ, never on a reorder. This is the note's central operational payload for the discovery regime; the digest leaves most of it unused.

**2. Implementation approaches → Divergences from Green: home-scoping is misframed as a faithfulness requirement.** `findlinks(I, Σ) = {a ∈ dom(Σ.L) : matches(a, I, Σ)}` is **global** over the whole link store — ASN-0127 has no home-document filter anywhere. So Green's disabled `homedocids` (the `TRUE||` guard → global) *coincidentally matches* this note's contract; it is not a "Green limitation to not replicate" relative to ASN-0127, and "a faithful build … home-document scoping should actually filter" mis-attributes an enhancement to the note. Keep "index the type slot" as the one genuine faithful-build divergence (F-MATCH's existential *does* range over slot 3, so Green's broken THREE filter diverges from this note's primitive). Recast home-scoping as out of scope here — an enhancement for the Q2 / full `find-links-from-to-three` layer, not a fidelity obligation. (Per-home-document *partitioning* stays fine as an index-locality choice in "Decisions for the builder"; just don't sell it as "restoring a contract feature.")

**3. Implementation approaches → Coverage / link matcher: the interval-index default rests on an order-contiguity claim the note never makes.** The digest asserts `subtree(x)` is "an order-contiguous set" and makes that the basis of the stabbing/interval default. The note establishes only *prefix* structure (prefix-incomparability T10a.2; subtree as prefix-closure), never that subtrees are contiguous intervals in the T1 order. Order-contiguity is true in Green — it is exactly what the spanfilade (a range structure over the address space) relies on — so the claim is grounded, but present it as *the enabling assumption the interval index inherits from the tumbler order / spanfilade*, not as self-evident. Then note that the **radix/prefix-trie** alternative rests directly on the prefix structure the note *does* establish, making it the safer default if subtree-contiguity under T1 isn't separately confirmed. As written, the digest picks as default the option needing the extra assumption and states that assumption as if given.

**4. Design commitments / Caching: surface F-CIL as the meta-lemma behind the two regimes, not just "the hinge coverage turns on."** The regime split is a *consequence* of F-CIL: any comprehension whose predicate reads only `Σ.L` is `Σ.L`-stable. Naming it tells the builder the split is principled on *which state component the predicate consults* — and, usefully, that the conjunctive Q2 query under *fixed* filters inherits the same existence-stability (still a `Σ.L`-only predicate), so no separate stability machinery is needed for it. One or two lines; F-CIL is currently mentioned only obliquely.

**5. What must be built → region resolver / Commitment #7: reinforce that the *image itself* can contain link addresses, not only the coverage index.** Commitment #7 correctly notes endsets may *cover* link addresses (L4) and bundles in S3★, but doesn't carry S3★ to the resolver. S3★ / K.µ⁺_L means a document can *arrange link-subspace positions*, so the resolver's output image — and hence the query I-set — can itself contain link addresses. State this in the resolver/composite build items: link-document queries are first-class on *both* sides (resolver maps V→link-address; matcher queries link-address against endsets), not just in the index.

**6. Recovery and durability: the link-journal ↔ permascroll analogy miscasts the Green structure (minor).** The permascroll is Green's permanent *content* scroll; the link store's append-only permanence is L12 (ASN-0043), a separate guarantee. Either hook the link journal to L12 or call it "a permascroll-*style* append-only permanent store" rather than "the analog of the permascroll."

Genuinely solid and not to be touched: the Forced/Conventional split (two-phase *factoring* conventional, the two *state-dependencies* forced); the existence-cache monotone-maintenance derivation from E-MONO/F-LAMBDA; the D-ABSORB "image-motion trigger over-invalidates but never under-invalidates" safe-direction argument; and the `slotmatch` substrate-sharing observation for Q2. Those carry the digest.
