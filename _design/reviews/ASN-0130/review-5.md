## Revision list

**1. [DEFECT] — "Guarantees to uphold," *Frontier-ghost closure* bullet: the soundness argument is wrong and inverts the note's own currency/soundness split.** The bullet claims that checking (iv) by content-residence "silently reintroduces the hazard: … an as-yet-unallocated frontier slot could come to mean something by a later allocation," and that "the slice lookup is load-bearing for soundness, not just currency." Both are false. A residence check *rejects* an unallocated frontier slot — it is not resident; the note's own Adversary check says the frontier "is not even resident" — so residence does **not** reintroduce the later-allocation hazard. Per PR0's "the two are distinct" and PR1, ever-registration (iii, via `sig`, the **audit** slice) is what makes a referent a validated, already-allocated definition and closes the later-allocation hazard; the **active**-slice check (iv) adds only reference *currency* — rejecting a host that references a *de-registered* definition — which the note frames as a deposit-time *endorsement*, explicitly **not** an evaluation-soundness requirement (evaluation keys on ever-registration). This also contradicts the digest's own correct text in "What must be built → Registration operation," which says typing keys on ever-registration and the active check's distinctive job is rejecting de-registered referents. Do W: keep the instruction ("(iv) tests the active pdef slice; a resident, parse-valid, *unregistered* run must still fail (iv)"), but re-base the *why* on currency — residence is insufficient because it admits references to resident-but-de-registered/unvalidated runs; the unallocated-frontier/later-allocation hazard is closed by the registration requirement (ever-registration at (iii)/`sig`), which residence would also reject for the unallocated case.

**2. [DEFECT] — "Implementation approaches → Evaluation": "The active slice is consulted only at registration/certification" is false and self-contradictory.** The digest's own "Catalog wiring" and PS2 text say `is_pd_stable(t)` is "true iff an active certificate covers t" and the universal lint is "evaluated over the active slice" — both consumer-facing status queries reading the active slices (`A_pd_stable`, and `M_pdef` at view `active` = `A_pdef`), and neither is the register/certify operation. The intended, correct point is narrower. Do W: scope it to evaluation — e.g., "*Evaluation* does not consult the active slice (it keys on ever-registration via the audit slice); the active slice is read at registration/certification to gate new endorsements and by the `is_pd_stable`/lint status queries — but never by `evaluate`."
