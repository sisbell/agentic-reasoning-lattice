Reviewed against the note, its claim statements, and the Q2/Q5 evidence. The digest is accurate on the load-bearing commitments and unusually disciplined about the one trap that matters most (identity-by-address ⇒ no value-dedup / no canonical-encode). The defects are concentrated in the caching story and one mis-grounded Green aside.

## Revision list (most-important first)

**1. Implementation approaches → Evaluation, and Decisions for the builder → What to cache: "evaluation results are cacheable as hard hints" is unsound — strike it.** This appears twice and directly contradicts PR3 ("the value varies only as `(args, view, Σ)` vary, exactly as for any PL term") and the digest's own *What must be built → evaluation binding* ("at the caller-supplied `(args, view, state)`"). The denotation reads the **mutable** structural state (PC4: `dom(Σ.M)`, `Σ.L`, `Σ.registry`); it is *not* "derived from immutable content and the permanent audit slice." The clean read/write split is real but narrower than stated: evaluation reads (a) the audit slice for the ever-registration precondition — permanent, (b) immutable content to resolve+expand — permanent, **and (c) the live structural state Σ for the denotation — mutable.** Fix: the hard-hint-cacheable set is exactly *{resolved term, expanded term, ever-registration fact}*; the **evaluation result** is state-dependent — at most a memo keyed on the structural state it read, invalidated as that state grows. A builder who caches results as permanent will serve stale verdicts. This is the headline defect: an approach that violates a stated guarantee.

**2. Implementation approaches → Storing the artifact: the Green contiguity hazard's mechanism is incoherent and mis-grounded — fix the mechanism, keep the recommendation.** "link atoms land in a different subspace **and advance the frontier**" → "splits the run" is supported by no single source. The note's basis (worked-comp step 1) and the Q5 *KB Synthesis* are *same-subspace* link allocation sharing the content frontier — that is what splits a run *across separate insertions*; the Q5 *Code Exploration* says the opposite ("LINKATOM → `[D.0.2,D.0.3)`, a different subspace … the next text insert finds the last text address … **No gap**"). The digest welded "different subspace" (from the half that says *no split*) onto "splits the run" (from the half that says *same subspace*). Fix: state the note's same-subspace/shared-frontier mechanism (and note the evidence is split on whether Green actually splits), and foreground the one **unanimous, load-bearing** fact — a *single* insertion is always one contiguous run (Q5) — so the recommended atomic-batch write makes condition (i) hold by construction regardless. The practical advice ("keep term-writing off the link-allocation path") is sound; only the causal story needs repair.

**3. Guarantees → "Evaluation determinism": relabel to "Expansion determinism."** What immutable content + the fixed renaming order make invariant across states is the expanded **term** (same *concrete* term, not merely α-equivalent — PR3's determinacy), not the evaluation **result**, which varies with Σ. The current label invites exactly the misreading that feeds item 1. Rename and state it names the term, not the value.

**4. Design commitments / Guarantees: the surface seal is *forced* and the linchpin, not "Forced/conventional."** The note is explicit that the seal "is what discharges the registration discipline (PR-DISC)," and every permanence/uniqueness/`sig`-well-definedness result is scoped to PR-DISC. Without the seal those guarantees don't hold — it is not optional hygiene. Sharpen the commitment to say the seal *establishes* PR-DISC, on which the rest of the by-construction guarantees rest.

**5. Decisions for the builder → lint scope: add *why* the global lint can't be narrowed in PL.** The digest names the right mechanism (protocol-scoped membership filter) but omits the load-bearing reason from PR5: you cannot restrict `M_pdef` to Boolean predicates *within PL*, because result sort is `sig`/content-derived and outside PL's read surface — which is precisely why scoping must go through a separate membership classifier, not a sort filter. State this; it forecloses the tempting non-fix ("just write a better PL lint that skips non-Boolean defs").

**6. Implementation approaches → Expansion: "agree … bit-for-bit" overstates the contract.** Two implementations must produce the same *concrete term* (identical down to the chosen expansion names) — but not the same *bytes*, since the digest itself (correctly) says canonical encoding is not required. Reword to "the same term, identical down to the chosen expansion names." (Minor adjacent point: naming the `im` crate twice presumes a language/library the note doesn't fix; present structural-sharing as the design idea and the crate as one realization.)

**7. (Minor/optional) Registration / Guarantees: note that validation-success ≠ referenceability off the disciplined path.** PR0's born-nullified case (a prior *range* retraction covering the frontier slot) passes validation and deposits into the audit slice yet never lands active/referenceable; it's excluded on surface-disciplined derivations (DR), but a one-line caveat keeps a builder from assuming emit ⟹ referenceable unconditionally. Similarly, the versioning facility should note `tip` returns ⊥ on competing successors (consumer must handle it) — the digest mentions register-then-supersede but not the ⊥/branch path the consumer faces.

## What's solid (no change)
The design-commitments list is accurate and its forced/conventional calls are defensible (modulo item 4). The "canonicalization is **not** required" reasoning is exactly right and correctly avoids the value-identity trap the note forbids. The `sig`-as-recomputable-hint, expansion memoization, and replay-rebuild-indexes treatment are textbook Lampson and sound by the note's determinism/permanence. The diamond-blowup cost analysis, the (iv)-as-exact-point-lookup observation, the view-independence scoping (required only at certification), and the never-forwarded-filter cautionary parallel (apt use of Q2) are all on target.
