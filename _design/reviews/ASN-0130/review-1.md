**Revision list**

1. **[DEFECT]** *"Implementation approaches → Resolution and expansion"* and *"Decisions for the builder → How to represent the expanded term"*: the blowup mitigation is unsound as stated. PR3 renames each inlined referent's parameters **and binders** to per-site fresh expansion names, so two inlinings of one referent are α-equivalent but **textually distinct** (different ν-indices — and your own recommended "counter bump" makes them more distinct, not less). `im`'s structural sharing shares structure only between a value and versions *derived* from it; it does **not** intern two independently-built equal values, let alone two differently-named ones. So "a referent inlined at many sites is physically shared [via im's structural sharing]" is false — a builder who implements named-term expansion + `im` gets *no* sharing and still hits the exponential blowup. Do instead: (a) preferably don't materialize `expand(a)` at all — evaluate and ST⁺-classify over the reference DAG with per-node memoization, since denotation, typing, and ST⁺ are compositional and α-invariant (the materialized concrete term is a spec *determinacy device*, not an implementation obligation); (b) if you do cache it, use an α-canonical (de Bruijn / locally-nameless) representation with explicit hash-consing. State that this same α-invariance is what licenses the "counter, not a scan" scheme: a monotonic counter diverges from the note's least-index-not-occurring naming and yields a *different* concrete term, harmless only because nothing downstream (typing, denotation, ST⁺, view-independence, caching-by-address) depends on the concrete names — say that, rather than implying the counter reproduces the note's term.

2. **[SHARPENING]** *"Guarantees to uphold → Hold by construction"*: add the boundary the note stresses — **content dereferencing is confined to the operation surface (validate / resolve / expand); the PL evaluator only ever sees the pure expanded term and never reads content**, so ASN-0129's structural-reads-only surface is preserved. The expand-before-evaluate architecture already enforces this, but it is *why* self-hosting doesn't re-open PL's read surface, and a builder who "optimizes" by resolving references lazily during evaluation would silently break it. Name it as a guarantee.

ST⁺ widens PD0's count-threshold from "ℕ literal" to "ℕ literal *or* environment-bound ℕ parameter"; a checker built to literal PD0 would silently *refuse* a certifiable term (e.g. view-independent `count(L_W) ≥ x`, `x : ℕ` a parameter).
