## Revision list

1. **[DEFECT] Certification ("the one place with real algorithmic latitude") — the k=0 test-oracle claim contradicts the conservative-classifier allowance one sentence later.** The digest says "on closed-term (k=0) inputs the ST⁺ pass *must agree* with PD0's literal ST verdict," then immediately: "a **conservative** classifier (certifying less) is fully legal and sound." These conflict: a conservative classifier *under-certifies* closed terms, so it does **not** agree with literal ST. A builder shipping a conservative classifier and using "must agree" as the oracle would chase false failures on every closed term their classifier correctly leaves *unknown* but literal-ST accepts. Restate the oracle **directionally**: for *any* sound classifier, every closed (k=0) term it certifies must be literal-ST (the safety check — no false positives); two-way *agreement* at k=0 is required only of a classifier that aims to be *complete* for ST⁺. The core insight (ST⁺ ≡ literal-ST at k=0, so closed terms are your reference set) is correct and worth keeping — only "must agree" is wrong.

2. **[SHARPENING] Implementation/certification — "The view-independence scanner is the same finite scan as the type pass; share it" is imprecise and, read literally, points at an unsound check.** The registration-time type pass (WT+WT-ref) runs over the *body-with-references*; view-independence (and ST⁺) run over the *expanded* term `expand(a)` at certification. A body that references a view-sensitive definition is syntactically view-clean until expanded — scanning the body would falsely certify it. Your build list already says "view-independent *expansion*"; make this line agree: reuse the finite-walk *infrastructure*, but run it over `expand(a)`, and note view-independence is a *distinct property-check*, not a by-product of well-typing.

3. **[SHARPENING] "Guarantees to uphold" omits the adversary-check guarantee the note dedicates a section to.** Add: condition (iv) checks *active registration*, not mere residence, which closes the frontier-ghost hazard — "no definition can come to mean something by a later allocation." The digest correctly says references must be "actively registered," but doesn't flag that the tempting optimization of testing (iv) against the *content store* (residence — cheap, no slice lookup) instead of the active `pdef` slice silently reintroduces the hazard. The slice lookup is load-bearing for *soundness*, not just currency.

4. **[SHARPENING] Registration validation, reference-active (iv) — wrong lemma cited for "plain keyed-map hit."** The digest justifies (iv) being a point lookup via "the note proves coverage at distinct starts is exact." But (iv) tests `r ∈ addrs(F)` with `addrs(F) = {a}` recovered exactly by AD (unit-depth span) — it is a point check *by construction*, no exactness argument needed. The coverage-exactness lemma is what collapses the *is_pd_stable lint's* coverage-based test (which uses `subtree`, not `addrs`) to a point lookup. Attribute each to its own check; the practical conclusion (index by start, flat map) is unaffected.

5. **[SHARPENING] (optional) The worked-composition's central lesson is underplayed.** The note's authoring takeaway — "a terminator that *tests live state* can un-terminate; one that *tests for a recorded event* cannot" — is the idiom that makes a predicate ST⁺-certifiable: phrase stability predicates over grow-only audit-slice bases (`L_Done`), never active-slice tests (which flip). Worth a line in the certification section as guidance to whoever authors the stored predicates, even though the subsystem builder inherits the rule from ASN-0129.
