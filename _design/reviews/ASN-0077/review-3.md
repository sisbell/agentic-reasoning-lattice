Reviewed the digest against ASN-0077 and the evidence answers. This is a strong, well-grounded digest — the forced/conventional discipline is careful, the Green structures are cited correctly, and the engineering judgement (especially around caching) is mostly sound. The defects below are concentrated in two proposed approaches and a few groundings; the rest are sharpenings.

## Revision list (most important first)

**1. Implementation approaches (I-span) + Decisions for the builder — the single-origin fast path is unsound on empty spans, and the digest asserts it is sound.** The proposal "*do the span's endpoints share a document prefix? → short-circuits to a singleton {d} without enumeration… That test is sound…*" is sound only for the *same-origin* half. It returns `{d}` even when the span contains **no allocated content** — and Q14 makes that a real case (fragmented allocation leaves gaps *inside* a document's contiguous range). The correct answer there is `∅`. The note's `wp(SHOWORIGIN_I, |result|=1)` carries non-emptiness as a *separate conjunct* (`⟦σ⟧ ∩ dom(C) ≠ ∅`), and the digest's own "What must be built" insists "empty… legitimate result." Fix: gate the fast path on a cheap existence check (any allocated content in `[s, s⊕ℓ)`?) — return `{d}` only if non-empty, else `∅`; fall back to enumerate/boundary-walk when endpoints differ. Also drop the "*works because of scale-invariance (O8)*" justification: the test rests on contiguous, disjoint document ranges (which the digest already states), not on O8.

**2. Implementation approaches (I-span boundary-walk) — the recommended wide-span path must restrict to the content subspace, or it over-reports.** The granfilade holds *both* content and link allocations (K.λ allocates links there too). A boundary-walk that "collect[s] distinct boundaries crossed" over an I-interval that crosses into the link subspace will surface documents whose *link* allocations fall in range — but the I-span lift is defined as content-only (`⟦σ⟧ ∩ dom(C)`, the note's cross-subspace edge case). State that the walk must filter to `dom(C)`. Secondary: "*cost ∝ number of distinct origins*" silently assumes the tree can skip an entire document's contiguous block in ~one step (true for an enfilade like the granfilade); make that assumption explicit so a builder doesn't pick a flat map that forces a per-address walk.

**3. Implementation approaches (Permanence) — reconcile the addressing layer.** The permanence argument cites "*Q19's `2.1.0.x.x.x` permascroll addresses*" as the content addresses, but the entire origin *projection* truncates **document-scoped** I-addresses (Q12/Q14: `…doc.0.3.N`). If content addresses were literally permascroll `2.1.0.…` (node 2), prefix-truncation would name the permascroll, not the home document — directly at odds with the projector the digest builds two sections earlier. The permanence point doesn't need the permascroll example: append-only / no-reuse holds for the same document-scoped granfilade allocation (P0/P3). Drop the second layer, or note the layering explicitly. As written it risks confusing a builder about what `origin` actually consumes.

**4. What must be built — surface the I-span well-formedness precondition.** The build list includes a "V-span admissibility check" component but nothing for the I-span arity, implying its input needs no validation. The note's `SHOWORIGIN_I` has preconditions (T12 (i)–(iv): `s,ℓ ∈ T`, `Pos(ℓ)`, `actionPoint(ℓ) ≤ #s`). Add that the I-span resolver enforces span well-formedness, so the asymmetry the digest draws reads correctly as "I-span: well-formed span, empty result legitimate" vs "V-span: full `WF_V`, empty document inadmissible" — not "no check vs check."

**5. Cross-section — the three-way edit contract (O11/O13/O14) is restated three times** (V-span resolver build item, result-set cache, V-span edit-stability guarantee). Consolidate to one authoritative statement and cross-reference; the triple repetition pads three sections without adding distinctions.
