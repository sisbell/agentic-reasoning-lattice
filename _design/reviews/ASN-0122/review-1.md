This is a strong digest: it reads the note's commitments accurately, correctly elevates the matcher/fan-out problem to "the heart," grounds every Green source-level claim in the evidence (no fabricated function names), and the caching-as-hint and join-vs-merge analyses are exactly right. The improvements below are mostly tightenings, but the first two are real defects in the build guidance.

## Revision list

**1. (What this is / Implementation approaches–region rep / Snapshot / How it fits) The operational sections quietly collapse "two regions" into "two documents," which is wrong for multi-document spec-sets.** The note's X12 lists the multi-document case first ("Each names one document — the two-version case — or several") and a region "simply unions their windows" across documents. The digest gets this right in the commitments ("two *regions'* resolution maps") but then says "it reads two documents' arrangements," "consistent view of two arrangements," and "read only the two arrangements," and its block tuple `(V-start, address-start, width)` carries no document tag. Fixes: (a) the snapshot/access scope is *all documents named across both spec-sets*, not two — reword accordingly; (b) add the document to the block tuple → `(document, V-start, address-start, width)`, because one region's blocks can belong to different documents and the output record needs `(document, start)` per side; (c) state that the join is on address *across* documents, so a single report can pair a left foot in one document with a right foot in another. Keep the access-discipline point (read only the regions' arrangements, never a membership/spanfilade index) — that is correct and well-grounded (evidence Q19); only the count is wrong.

**2. (What must be built — precondition gate) "Strip/reject link-subspace spans" blurs a distinction the note is careful to draw, and could lead a builder to reject legal spans.** The binding precondition (X12) is on the span's *start* subspace only (`subspace(start)=s_C`). A content-start span that *denotes* link positions — the note's `σ=([1,5],[3])`, which is T12-well-formed — is **legal** and is handled by the region resolver's `∩ V_{s_C}` clip, not by the gate. Spell this out so the gate doesn't reject such spans. Separately, whether a link-*start* span is a hard precondition violation (reject/error) or is leniently filtered (strip, as the reference's added front-filter does, which "implements X12's precondition exactly") is a genuine builder decision — surface it in "Decisions for the builder."

**3. (Implementation approaches — Matching) Strengthen the "one corrected step" claim with the evidence that makes it true.** The digest says to keep the reference's interval intersection and bounded traversal and fix only the pairing. The evidence (Q15) confirms this precisely: the V→I/I→V machinery *already faithfully enumerates every fan-out occurrence* ("incontextlistnd is faithful — it enumerates all V-occurrences"); the loss is solely the final pairing step's per-interval width budget (`iwidth`), which exhausts after one occurrence. Say this — it demonstrates the enumeration is reusable wholesale and that exactly one step (the budget-bounded merge) is replaced, raising the grounding of your default recommendation.

**4. (Matching / Completeness) Name the sharpest test for the exact bug being fixed: equal-window self-comparison, not just the disjoint-window detector.** The digest frames self-comparison via X8(c) (disjoint windows → sharing detector). But the failure mode you're correcting is caught most directly by X8(a/b): the note's worked example self-compares d₁'s whole extent and must return **6** elements (4 diagonal + 2 off-diagonal from the repeated `b`), where the reference returns only 4. Recommend equal-window self-comparison with internal repetition as the canonical fan-out completeness test, and note the off-diagonal symmetry (both `(p,q)` and `(q,p)`, X8b).

**5. (How it fits) "the content store's POOMs" undercuts the digest's own central invariant.** POOMs implement the per-document arrangement `M`, not the content store `C`; the operation reads POOMs (addresses) and never opens `C` (values). As written, "resolution … over the content store's POOMs" contradicts the commitment "it never opens the content store." Reword to "the documents' POOMs (arrangement indexes into, but not part of, the content store `C`)."

**6. (Design commitments — soundness+completeness / Guarantees) Soften "the whole weight of this falls on one place: fan-out."** Window-exactness (the in-window part of a boundary-crossing run must not be dropped, X4) is also a completeness obligation; it is by-construction only if you clip-then-join, which the digest correctly assumes elsewhere. Reframe as "the hard case the reference gets wrong is fan-out" rather than implying completeness has a single failure mode.

**7. (Implementation approaches — Resolving a region) Surface the "Rust/`im`" target as an assumption.** The note and evidence establish neither the target stack nor its "O(1), lock-free snapshots." The persistent-structure properties are sound general CS, but the digest presents the target as given; tie it to whatever project context actually fixes it, or phrase it conditionally ("if the target is Rust/`im`…").
