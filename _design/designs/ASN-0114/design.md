## What this is

FOLLOWLINK is the link store's single-endset read accessor: given a link address and a slot selector, it returns the recorded endset at that slot — a set of spans over tumbler space, measured by coverage — or a distinguished error if the link or slot does not exist. It is the narrowest read primitive over the link store, and deliberately *only* that: it reads what the link records, not what that record resolves to in any document.

## Design commitments

These are locked in for the whole system; downstream design cannot violate them.

- **The contract is bound at *coverage*, not representation.** Two results that denote the same set of positions are equal answers (F1/F3), regardless of how the spans are decomposed, split, or ordered. This is the deepest commitment: callers may not depend on a span count, a splitting point, or an emission order. You buy implementation freedom by leaving representation out of the contract — so do not promise or document any emission order, and expect callers to form Hyrum's-Law dependencies on whatever order you do emit. The discipline is non-promotion of order, not non-determinism.
- **FOLLOWLINK reads the *recorded* end, not its *resolution*.** Projecting the recorded endset into a particular document's live arrangement, and dropping addresses absent from that view, is a **separate operation** this note excludes by name. This is a placement decision with teeth: FOLLOWLINK needs no document handle, no arrangement, no content lookup, no lock. The reference implementation bundled resolution in; this spec de-bundles it, and the payoff is observable: for an orphaned or ghost link the abstract FOLLOWLINK returns the recorded (non-empty) end, whereas the bundled path drops every address in I→V conversion and returns **empty** (Q15, Q19), and resolves the *same* recorded end differently against different queried documents (Q11) — one link, many answers. That divergence — distinct from the F7 empty-*recorded*-endset bug — is the sharpest reason not to reuse the reference followlink path. Honor the de-bundling — a faithful FOLLOWLINK returns tumbler-space spans, full stop.
- **Pure read, zero mutation (F4).** No state component changes — not content, links, entities, arrangements, or provenance. This forbids read-tracking, access stamping, and any "normalize on read and write back."
- **Empty is a first-class success, distinct from invalid (F7).** `⟨⟩` (a valid slot that presently holds nothing) and `⊥` (no such link or slot) are different return categories and must remain distinguishable, in-process and on the wire. This is the one obligation the reference implementation *failed*, so treat it as forced, not free.
- **The precondition is at its true minimum: link exists ∧ slot exists (F0/F8).** No requirement that any covered address currently holds content. Orphaned and ghost links are answerable; content existence is a separate question this operation never asks.
- **Selector arity is not frozen at three.** Valid selectors are `1..arity(link)`. The from/to/type triple is the floor, not the ceiling; derive bounds from the stored link, don't hard-wire `3`.

What is forced: coverage-exactness, pure-read, empty≠invalid, the minimal precondition, and confinement *at the coverage level*. What is merely conventional (left free by F3/F6): the span decomposition, span ordering, any normal form, and representation-level non-leakage of sibling slots.

## What must be built

Described functionally — what each must do.

- **A by-address link lookup** that maps a link address to its recorded link value, or reports absence.
- **A slot accessor with arity** that indexes the link's endset sequence by selector and knows the link's slot count for bounds-checking.
- **A three-way domain guard** that separates *link absent* and *slot out of range* (both → `⊥`) from *valid slot* (proceed) — and that decides "this end is empty" from the endset itself, never by inferring it from a downstream "nothing found."
- **An endset→span-set emitter** that produces a result whose coverage equals the stored endset's. The stored spans are their own witness, so the cheapest correct emitter copies them.
- **A result-category encoding** that keeps `⟨⟩` (success, empty) and `⊥` (error) distinct end-to-end, including across any serialization boundary.

What must *not* be built for this operation: any arrangement projection, content fetch, reachability/orphan check, document-open or locking gate, or by-content link index. Those belong to other operations.

## Implementation approaches

**Link lookup (by address).**
FOLLOWLINK needs only a by-address *point read* over ASN-0093's link store; the store's durable shape is ASN-0093's concern, inherited and assumed here, not designed by FOLLOWLINK. Because links are immutable (LP13), the address→link map is *monotone* — entries are only ever added, never overwritten — so the read stays trivial: a pure point lookup, needing no overwrite, versioning, or snapshot machinery of its own. Monotonicity makes lock-free reads *available* but does not by itself secure them: a mutable structure mid-resize can tear even with no entry overwritten, so lock-free reads further require ASN-0093's representation to *publish* entries atomically (an immutable/persistent structure) — a property the link's immutability invites but that belongs to the store's representation choice, not a logical consequence of monotonicity. Green's granfilade *link orgl*, reached by address, is the proven analogue, and the evidence confirms the follow path needs **no open-document gate** (it runs without the home document open, Q19) — corroborating the "no lock, no handle" placement; do likewise.

**Slot accessor + selector.**
A link is a finite ordered sequence of endsets, so the selector is a direct positional index and arity is read off the link value. Green's verified design uses the literal integer `1/2/3` *both* as the storage coordinate and the query coordinate — proof that a positional selector is sufficient and cheap. The one thing to *not* copy: Green froze the range with a `==1||==2||==3` whitelist (Q12). Derive bounds from the actual arity instead, so n-set links work unchanged.

**The domain guard — the load-bearing engineering choice (F7).**
The order is: look the link up — *absent* ⟹ `⊥`; then check the selector against the link's *actual arity*, post-lookup — *out of range* ⟹ `⊥`; then read the slot — *empty endset* ⟹ `⟨⟩` as success. Only the selector's lower bound (`i ≥ 1`) and address syntax are checkable at the boundary before the lookup; the upper bound `i ≤ |Σ.L(a)|` is known only *after* the lookup, since arity is read off the looked-up link (F0). Green can whitelist `==1||==2||==3` at the input boundary (Q12) only because it freezes arity at 3 — the very freeze this spec rejects; with arity unfrozen, the upper-bound check must move post-lookup. This ordering is the whole game. The verified anti-pattern is precisely instructive: Green's follow path treats "retrieval found nothing" as failure and emits a protocol error (`sporgl.c:93` → `putrequestfailed`, Q17), conflating an empty-but-valid end with an invalid request — the exact collapse F7 forbids. The fix is structural: never derive emptiness from a downstream null; derive it from "slot is valid **and** its endset is empty," a decision made in the core against the endset, not at the retrieval layer. The correct empty-handling already exists in the same codebase — Green's RETRIEVEENDSETS always succeeds and lets an empty end flow out as an empty result (Q17). Copy *that* empty-handling pattern, not the followlink path's.

**Endset→span-set emitter.**
Emit the stored spans verbatim. The license is that **the recorded endset is its own witness** — it is *already* a finite set of well-formed spans, so any sequencing of its members is a span-set whose coverage equals the recorded end's. F1 then holds by construction: coverage is a pure function of the spans you emit, and you emit exactly the recorded ones, with no arithmetic on the read path. F2 needs no enforcement of its own: it *follows from* F1, so any F1-satisfying result has it automatically. Verbatim emission satisfies F1 — emitting the recorded spans without merging across a gap introduces no over-coverage — so a disconnected recorded end stays `≥2` spans, with no separate check to run, because merging across a gap would itself be an F1 over-coverage violation, not an independent F2 one. (Verbatim copy is only as faithful as what was stored; storing a discontiguous end without flattening it is CREATELINK's concern — upstream and out of scope here — so it is an *assumption* FOLLOWLINK leans on, not something it can relocate.) Q13, read whole, belongs at the representation level F3 leaves free: a raw-address endset is returned by a pure copy chain with exponents preserved, *whereas* an arrangement-relative endset is **recomputed** by tumbler subtraction to a denotationally-equal but representationally-distinct result — two legitimate decompositions of one coverage, which is F3's point. It is *not* evidence that the reference emits verbatim: that copy chain is its exceptional (raw-I-span) path, and its normal (V-spec) path resolves. Multi-region ends are kept as separate spans with coalescing explicitly disabled (`orglinks.c:412–413`, Q14). F3 *permits* coalescing adjacent (gap-free) spans or imposing a normal form, but doing so spends work on the read path for no contractual gain. I would emit verbatim and, if a normal form is ever wanted, establish it once at write time so reads stay cheap and stay deterministic-by-permanence (F5).

**Result-category encoding.**
In-process, make success-vs-error a sum/result distinction with the empty span-set living *inside* success — then `⟨⟩ ≠ ⊥` holds by construction and cannot be accidentally collapsed. Across a protocol boundary (the note's open question), carry an explicit status discriminant, not just a payload: an empty list alone is ambiguous with an error that sent nothing. Encode empty-success as an explicit *ok-with-empty* and invalid as an explicit *error*. This is just the remote form of the in-process sum type — and the standing rule "don't overload absence to mean two things."

## Guarantees to uphold

- **Exactness (F1)** and **discontiguity faithfulness (F2):** by construction under verbatim copy of a faithfully-stored end. F2 is not a separate obligation — it follows from F1, so any F1-satisfying result has it automatically; merging across a gap would itself be F1 over-coverage, not an independent F2 failure. The only genuinely separable piece is the upstream assumption that the disconnected end was stored faithfully in the first place (CREATELINK's concern, out of scope here).
- **Representation invariance (F3):** upheld by *under-*promising — guarantee only coverage, and keep any emission order out of the contract rather than promising it (callers may still latch onto whatever order you emit). The risk is over-promising, not under-delivering. Concretely for the builder: conformance tests and golden fixtures must assert coverage-equality (`⟦R⟧ = coverage(eᵢ)`), never a span count, split point, or emission order.
- **Pure read (F4):** by construction if the read path touches only immutable/snapshot state and adds no read-tracking.
- **Temporal determinism (F5):** free, inherited from link permanence (LP13). The only way to break it is to break immutability upstream; FOLLOWLINK enforces nothing itself.
- **Slot confinement (F6):** coverage-level confinement holds by construction since you read only slot `i`. Representation-level non-leakage is *not* a contract guarantee — but it is cheap to provide here (compute the result solely from slot `i`'s spans, never consulting siblings to choose split points), and I would provide it as hardening. *What the result discloses* is exactly `coverage(eᵢ)`, and derivable from it only two further facts: the home document, but **only over the T4-valid, document-bearing slice** of the coverage (`zeros(t) ≥ 2`) — node-level (`zeros=0`), user-level (`zeros=1`), and non-T4-valid interior tumblers in the coverage name no document; ghost-ness is orthogonal and must not be conflated with this — a ghost target sitting at a document-bearing address still discloses its home document, since the field projections read off the *address*, not the content, so content-absence (L9 ghosts) is an F8 matter, not a disclosure one — and that the link has at least `i` slots (`|link| ≥ i`). Nothing of the other ends. But this is *scope, not secrecy*: F6 says only that this operation, given selector `i`, computes from slot `i` alone — not that the other ends are hidden. Xanadu makes no confidentiality promise about a link's siblings; they are *deliberately* discoverable through other operations (bidirectional discoverability is the point). F6 is therefore not an access-control boundary, and the representation-level sibling-leakage the contract leaves free is a free implementation choice, not a security defect.
- **Empty≠invalid (F7):** the one guarantee needing *active* design — the variant-typed result plus the boundary-ordered domain guard above.
- **Content independence (F8):** by construction, because the read path never consults content, arrangements, or reachability.
- **Derived invariant:** since the writer enforces a non-empty type slot (L3), `followlink(·, ·, type-slot)` never returns `⟨⟩` — a useful assertion, but one that holds only because the *writer* upholds L3.

## How it fits

FOLLOWLINK sits *above* the raw link store and *below* arrangement/resolution. It leans on the **state model** (ASN-0047) for the five-component frame `(Σ.C, Σ.L, Σ.E, Σ.M, Σ.R)` that F4 ranges over, on the **link store** (ASN-0093) for address→link, on **link permanence** (ASN-0043 L12, ASN-0098 LP13) for F5, on the **endset/span model** (ASN-0043, ASN-0034) for what a slot is, and on **coverage and span-set semantics** (ASN-0098/0043, ASN-0053 — convexity S0, non-empty denotation S2) for the measurement and the empty-collapses. It hands the job of projecting a recorded end against a document's live arrangement, and filtering unreferenced addresses, to a **separate resolution operation** that is explicitly out of scope — that is where shrinkage and document-dependence live, not here. The two access paths of the link store are worth keeping distinct: FOLLOWLINK uses the **by-address** path only; finding links by their endset *content* is a different operation — Green's `find_links` (`dofindlinksfromtothree`, Q19) — served by the by-content index (Green's spanfilade), and you do not consult it here. Green's **RETRIEVEENDSETS** is yet another spanfilade (by-content) operation, *not* a by-address all-slots reader: it takes a content region and queries the spanfilade, partitioning by from/to/type, and shares with FOLLOWLINK only the endset→span-set conversion, not the by-address lookup.

## Decisions for the builder

- **Resident map vs on-demand index.** Whether the address→link map is fully resident or loaded on demand belongs to ASN-0093's link store, inherited here rather than designed by FOLLOWLINK; FOLLOWLINK requires only a by-address point read over it, however the store is shaped.
- **Verbatim vs normalized emission.** F3 lets you return stored spans as-is or impose a normal form. Pick verbatim on the read path; if you want a normal form, decide *where* it is established (recommended: at write time) — the spec leaves both the form and its placement to you.
- **Result shape and wire discriminant for `⟨⟩` vs `⊥`.** F7 forces *some* explicit-tag scheme; the exact in-process type and the exact wire status encoding are yours to choose.
- **Whether to provide representation-level confinement (beyond F6's coverage guarantee).** Not required by the contract, cheap to provide here; decide whether to commit to it as a hardening property.
- **Selector form and arity discovery.** Positional integer (Green-style, doubling as a storage coordinate) vs symbolic slot name mapped to a position; and whether arity is stored with the link or derived. Do not hard-wire three.
- **Where the bounds check lives.** Only the selector's lower bound (`i ≥ 1`) and address syntax are boundary-checkable for a fast `⊥` on malformed input; the upper bound `i ≤ |Σ.L(a)|` is known only after the by-address lookup, so it must be checked post-lookup once arity is unfrozen (Green's boundary whitelist works only because it freezes arity at 3). Make the empty-vs-present decision in the core against the actual endset, never inferred from a downstream "nothing found." That post-lookup split is what keeps F7 intact.
- **Multi-document coverage (OQ5, open).** When the selected end's coverage spans more than one document, is reporting it as one span-set — document identity recoverable only by parsing each address, and only for the document-bearing ones — sufficient, or must the result group or tag by document? The contract guarantees only the coverage; the spec leaves this to you.
- **Observability of non-existent-higher vs existing-empty slots (OQ4, open).** Beyond `⊥` vs `⟨⟩`, must a selector naming a non-existent higher slot be observationally distinct from one naming an existing-but-empty slot? The spec leaves this open.
