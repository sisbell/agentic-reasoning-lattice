# Design Digest — ASN-0127: Content-Region Link Query

## What this is
The read-side query algebra for **link discovery**: given a region of a document in reader (V) coordinates, which stored links reach it — and what stays stable as the substrate evolves. It defines a pure lookup capability (no mutation) plus its invariance taxonomy; it sits beneath any reader-facing "show me the links here" operation, not as one itself.

## Design commitments

**Forced — downstream cannot violate these:**

- **V→I resolution runs only through the document's live arrangement, and invents nothing.** The path from a reader's region to addresses is `image(W, d)` over `Σ.M(d)`; the `W ∩ dom(M(d))` intersection is load-bearing — positions a document doesn't currently arrange contribute no I-address. No query may manufacture reachability for unarranged positions.
- **The single-filter match is per-link *disjunctive across slots*.** A link reaches an I-set if *any one* endset slot's coverage meets it (F-MATCH). This is a different operation from the multi-slot *conjunctive* query (from ∩ to ∩ type) that Green's `find-links-from-to-three` implements — that is Q2, left open.
- **Coverage is a deterministic, total function of an endset's spans.** Same endset ⟹ same coverage, always (ASN-0043). This is the hinge F-CIL turns on, and it means coverage is *derivable* — never authoritative stored state.
- **`K.λ` (link creation) is the sole mutator of the link store; every other transition preserves `Σ.L` exactly** (F-PRES, from ASN-0047). Change-tracking for the **link store** — and hence for **fixed-I existence** queries — therefore reduces to "observe link creations"; discovery-anchored results, by contrast, additionally change under arrangement edits to `Σ.M` with no link created (D-PRES).
- **Two query regimes with different contracts, decided solely by how the I-argument is obtained.** A *fixed* I in the permanent address space (existence anchoring) rides only on `Σ.L`: stable, monotone, changes only under `K.λ`. An I read off a live arrangement (discovery anchoring) rides on `Σ.M` too: non-monotone, moves under arrangement edits with the store frozen. These are distinct cacheability/consistency regimes and must be treated as such. The split is principled, not incidental: **F-CIL** (the meta-lemma) says any comprehension whose predicate consults only `Σ.L` is `Σ.L`-stable, so a query's regime is fixed by *which state component its predicate reads*. (The conjunctive Q2 query under *fixed* filters is still a `Σ.L`-only predicate, so it inherits existence-stability for free — no separate stability machinery is needed for it.)
- **Permanence and address identity.** Links, content, and their tumbler addresses are permanent (L12/S0/P0); what changes is *reachability through an arrangement*, never existence. A query result dropping a link asserts present unreachability, never deletion.
- **Link-addresses appear on *both* sides of the query.** Endsets may target any address, including link addresses (L4) — so the matcher's index must accept links-about-links as coverage targets, not just content targets. And documents may *arrange* link-subspace positions: S3★ routes a link-subspace V-position to an address in `dom(Σ.L)`, so the resolver's image can itself contain link addresses. Link-document queries are therefore first-class on resolution as well as on matching.

**Conventional — this note's framing, not forced:** the explicit two-phase combinator (`findlinks ∘ image`) and the "existence/discovery" naming. An engine may fuse the stages internally — but the *two distinct state-dependencies* (M for resolution, L for matching) and their separate stability properties are forced, so the phases must stay distinguishable even if fused.

## What must be built

- **A region resolver (image):** given `(document d, V-region W)`, return the I-addresses the region currently covers via `M(d)`, restricted to the arranged domain. Must handle empty region, unarranged positions (drop silently), and contiguous V-spans resolving to a union of contiguous I-runs — but that clean run structure is a note result (C1a) *only* for a contiguous `W` within a **single** subspace. A `W` straddling content and link subspaces decomposes *per subspace* (one run set each) — this is not C1a but an inference from subspace disjointness (the `s_C` and `s_L` lanes are disjoint address spaces), so don't expect one clean run map across a cross-subspace region — exactly the link-document case this resolver must also serve, made first-class just below. Distinguish two zero-ish cases the note keeps separate: *unarranged positions within a registered document* drop silently (possibly yielding an empty image, a legitimate `∅` result), but an *unregistered document* `d ∉ dom(Σ.M)` leaves `image` — and hence `findlinks_V` — *undefined* (both are partial functions, F-IMG/F-V). That is a precondition violation to signal as an error, not a silent `∅`, so a typo'd or stale `d` surfaces rather than masquerading as "no links here." Because a link-subspace V-position resolves to a *link* address (S3★), the returned image — and thus the I-set handed to the matcher — can itself contain link addresses; link-document queries are first-class here, not only in the index.
- **A coverage evaluator:** from an endset's spans, decide `coverage(e) ∩ I ≠ ∅` *without materializing the covered set* (subtrees are large/unbounded). Coverage of a unit-depth span is `subtree(x) = {t : x ≼ t}` — the *descendant set* of `x` (every address having `x` as a prefix) — so this is fundamentally a prefix-containment test; it sharpens to an interval test only if subtrees are additionally order-contiguous under T1 (see Implementation approaches).
- **A link matcher (findlinks):** given an I-set, return all links with some slot meeting it — backed by an index so it is not a full store scan.
- **The composite query** chaining resolver into matcher, with the empty-image short-circuit.
- **Derived indexes maintained across evolution:** a global coverage index over the link store (the spanfilade's job); optionally a per-document I-footprint (`ran M(d)`) for whole-document queries (the F-FULL case).
- **Result-caching machinery honoring the two regimes:** monotone incremental maintenance for existence queries; recompute-or-invalidate discipline for discovery queries.
- **Recovery:** rebuild every index and cache from the append-only stores; none of the derived state is itself a source of truth.

## Implementation approaches

**Coverage evaluation — intensional, never materialized.** Represent an endset by its spans and test intersection against I by prefix comparison: an I-address meets a unit-depth coverage iff the span's generating address is a prefix of it — `subtree(x)` is the *descendant set* (prefix-extension set) of `x`, which is the structure the note actually establishes (prefix-incomparability T10a.2, subtree-as-prefix-extension), not contiguity. *If* subtrees are also order-contiguous in the T1 order — which the note does not prove, but which holds in Green and is exactly what the spanfilade relies on — then `coverage ∩ I ≠ ∅` sharpens to an *interval-overlap (stabbing) test*, with a multi-span endset a union of such intervals. Either way this is a pure function (Lampson: cache the cheap thing — here, don't cache at all; recompute). Materialize coverage only for a hot link as a transient optimization.

**The link matcher — index, don't scan.**
- *Full scan of `dom(Σ.L)`* is correct and simple; keep it as the cold-start / recovery / verification path. It is also the honest fallback when an index is suspected stale.
- *The spanfilade* is the proven structure: an enfilade keyed on the I-address space that endsets cover, returning the links touching a queried span. This note's *disjunctive* primitive does **not** require per-slot index tagging: `findlinks(I)` is fully served by a **slot-collapsed** coverage index — index each link by the union `⋃ᵢ coverage(eᵢ)` and test that union against `I`, since `(⋃ᵢ coverage(eᵢ)) ∩ I ≠ ∅ ⟺ ∃i : coverage(eᵢ) ∩ I ≠ ∅` is exactly F-MATCH's existential. Per-slot tagging (Green tags storage `LINKFROMSPAN`/`LINKTOSPAN`/`LINKTHREESPAN`) is therefore a **forward-investment for the conjunctive Q2 query, not a requirement here** — build it anyway, because the substrate the two queries share is a **per-slot matcher** `slotmatch(a, i, J) ≡ coverage(Σ.L(a).eᵢ) ∩ J ≠ ∅`: this note's `findlinks(I) = ⋃ᵢ slotmatch(·, i, I)` *unions* the per-slot result sets (OR across slots), while Q2 (and Green's `intersectlinksets`) `= ⋂_{specified i} slotmatch(·, i, Jᵢ)` *intersects* them (AND across slots) — neither composes from the other, both compose from `slotmatch`, and the per-slot result sets feed both the union and the intersection. Realize it as either:
  - a **radix/prefix trie** over tumbler digits — it rests directly on the prefix-subtree structure the note establishes (an I-address matches an endset iff the endset's generating address is an ancestor on the trie path), so it is the safer default unless subtree-contiguity under T1 is separately confirmed; or
  - a **range/interval index** over the tumbler order (coverage = union of intervals; match = overlap query) — cleaner for multi-span endsets, but it *inherits the order-contiguity assumption* above, so prefer it once that assumption is confirmed (as it is in Green's spanfilade).
  Either way, maintenance is *append-only*: `K.λ` is the only writer and links are never retracted, so the index only grows — no deletion, no rebalancing for removal. **The index is a hint** (Lampson): fully rebuildable by replaying the link journal, so it is never journaled itself and a suspected miss is recoverable by recomputation.

**The region resolver — a run map, versioned.** Model `M(d)` as a run/interval map V→I (POOM-style), so a contiguous `W` resolves by walking its run decomposition and unioning I-extents — `O(runs in W)`, not `O(|W|)`. Arrangements are per-document, numerous, and frequently edited (μ⁺/μ⁻/μ~), so favor a **persistent ordered map with structural sharing**: an edit is `O(log n)`, the prior version survives for free (giving MVCC snapshots to concurrent queries), and reorder/contract/extend become cheap structural operations. Contrast the asymmetry with the link side: many small versioned per-document maps vs. one large append-only global link index.

**Caching across evolution — exploit F-CIL/F-LAMBDA and the regime split.**
- *Existence-anchored (fixed I):* cache freely and **maintain monotonically**. The result only grows (E-MONO) and changes only under `K.λ` (F-LAMBDA), so maintenance is: on each new link, test it against the fixed I and union the singleton if it matches. Never invalidate — only append. This is the ideal incremental-view situation.
- *Discovery-anchored (live arrangement):* **maintain incrementally per transition** — do not blanket-recompute. The result is non-monotone *across a path* (D-NONMONO), but D-NONMONO is a per-transition analysis, and at each single step the discovery set moves monotonically except in one case, so the cache admits the same kind of step-by-step maintenance as the existence cache:
  - *μ⁺/μ⁺_L on `d_q`:* union in `findlinks(Δ⁺)` for the newly-arranged in-region I-addresses (F-IMG-MONO + F-UDIST + F-INERT) — the unchanged part is never re-queried.
  - *K.λ:* test the new link against the *current image* and union the singleton if it matches (F-LAMBDA) — identical to the existence move.
  - *μ⁻ on `d_q`:* the change is bounded by `Δ` (the dropped in-region addresses), **not** by the retained `I_R` or the region `W`. The old result splits as `findlinks(I_R) ∪ findlinks(Δ)` (F-UDIST) while the post-result is exactly `findlinks(I_R)` (D-CWP's bridge `image(W, d_q, Σ') = I_R`), so the only links that can leave are those in `findlinks(Δ)`: any link not reaching `Δ` already reaches the retained `I_R` and survives (F-IMONO). Maintenance is therefore *candidates = `findlinks(Δ)`* (bounded by the small dropped region), each dropped iff it no longer matches `I_R` (a per-link `matches(a, I_R)` recheck) — far cheaper than re-querying the (large) retained set. **D-CWP** is the fast *front-end* of this Δ-bounded maintenance, not a free skip: its predicate `findlinks(Δ) ⊆ findlinks(I_R)` is decided by the *same* Δ-bounded recheck — test each `a ∈ findlinks(Δ)` for `matches(a, I_R)` — costing `O(|findlinks(Δ)|)` per-link tests, never a full `findlinks(I_R)` recompute (the new result is the cached old result minus the failed candidates). "Not a free skip" means you still pay those `|findlinks(Δ)|` rechecks; the genuinely zero-work case is `findlinks(Δ) = ∅` (the dropped region reaches no link — the common case for a small edit), where the result is provably unchanged with no recheck at all. So the contraction is cheap to maintain exactly when `Δ` is small/link-poor and the prior result is cached.
  - *μ~ on `d_q`:* no *monotone-transfer* shortcut exists for incomparable motion — F-IMONO is monotone but not order-reflecting, so the new result can't be read off the old by inclusion — yet incremental maintenance still applies, contrary to a "full recompute." F-IMG-SWING localizes the image change to the positions `π` moves across the `W`-boundary, splitting it into a gain side `Δ_gain` (incremental union `findlinks(Δ_gain)`, as in μ⁺) and a loss side `Δ_loss`. The loss recheck has the same *shape* as μ⁻ — the candidates are the links `findlinks(Δ_loss)` reaching a departed address — but **not the same target**: each is retested against the **retained-core** image `image(W, d_q, Σ) ∩ image(W, d_q, Σ')` (the un-moved part of the region's image), *not* the μ⁻ clause's `I_R`. After dropping the loss candidates that miss the retained core, the `findlinks(Δ_gain)` union re-admits any link a gained address re-witnesses, giving the order-independent result `(old ∖ failed-loss) ∪ findlinks(Δ_gain)`. Whether a reorder is cheap is itself a content-sharing question (F-IMG-TAX): an *injective* arrangement admits **only** incomparable motion, so both sides always run, while content sharing (M13/M14) is exactly what makes pure-gain or pure-loss *containment* motion reachable — letting one side be skipped.
  - *Off-`d_q` transitions:* the image is unchanged, so only `K.λ` can move the result, handled as above.

  If you key invalidation instead of maintaining — a stale discovery result is a correctness bug, not a staleness annoyance (D-NONMONO) — then the trigger must combine two events. D-ABSORB says image-motion is *necessary but not sufficient* for the result to move, but its necessity direction holds **only across `Σ.L`-preserving transitions**; under `K.λ` the result gains a newly-matching link with the image *fixed* (F-LAMBDA, the off-`d_q` clause of D-NONMONO). So triggering invalidation on image-motion *alone* under-invalidates — it serves a stale result missing the new link, the exact correctness bug D-NONMONO warns of. The safe trigger is image-motion **or** a `K.λ` whose new link matches the cached image: on that combined trigger, invalidation *over-invalidates but never under-invalidates* — the image-motion disjunct is conservative-safe across the store-fixed transitions where image-motion is the only mover, and the `K.λ` disjunct covers the one case image-motion misses.
- *Whole-document queries* (`W ⊇ dom M(d)`, F-FULL) equal ASN-0098's discovery set; maintain a per-document I-footprint (`ran M(d)`) as a hint to answer them without re-resolving the whole arrangement. This regime is **reorder-immune**: the image is `ran M(d)`, which μ~ preserves (LP11), so the footprint hint moves only under μ⁺/μ⁻ and the F-FULL result only under μ⁺/μ⁻ and `K.λ` — never on a reorder, and never a full recompute. One caveat on the μ⁻ side keeps the hint from being free: under content sharing an I-address leaves `ran M(d)` only when its *last* arranging V-position is removed (the same many-V→one-I fact the dedup argument leans on), so incremental contraction maintenance of the footprint needs per-address refcounting — or a footprint recompute — not a blind drop.

**Query planning from the algebra.** F-UDIST / F-VDIST (union distributivity, no disjointness needed) license decomposing a region into runs, querying the spanfilade per run, and unioning — a natural pipeline and parallelization plan. The union laws hold *without* a disjointness side-condition for a load-bearing reason: under content sharing (M13/M14) distinct V-positions can resolve to a *single* I-address, so the images of even disjoint regions can overlap — a disjointness-restricted union would not close the composition. The consequence is a real resolver/index constraint, not just an algebra footnote: resolution is genuinely many-V→one-I, so the resolver's image must be a deduped *set* and per-run results must be *set*-unioned, never concatenated or counted. The empty-image short-circuit (F-V/F-FIND) returns ∅ without touching the link index — this is an empty-*input* short-circuit (`I = ∅ ⟹ ∅`). Green's short-circuit on the first empty per-slot result is a *different* mechanism: an empty-*conjunct* collapsing an AND, which belongs to the conjunctive Q2 query, not to this disjunctive primitive. They share only the "detect empty early" lesson; don't import Green's conjunctive short-circuit here.

**Recovery and durability.** This maps onto the repo's working substrate, but the authoritative state is *three independent append-only logs*, not one: a content log (`K.α`), a link log (`K.λ`, `links.jsonl`-style), and a per-document arrangement-edit log (`K.μ⁺/μ⁻/μ~`). Each is permanent in its own right — the link log's permanence is L12 (ASN-0043), making it a permascroll-*style* store (the permascroll proper is Green's *content* scroll, a separate guarantee). Crucially the arrangement log is **not** reconstructible from the content or link logs: `Σ.M` is independent authoritative editorial state (the forced "M for resolution" dependency), so its edits must be durably journaled on their own — a builder that treats the POOM as rebuildable from the link journal loses all arrangement on recovery (replaying the link journal reconstructs links, never arrangements). The **per-document POOM is the *materialized* arrangement**, rebuildable only by replaying *its own* arrangement-edit log. What *is* genuinely derived-and-rebuildable from the other stores is the index/cache layer: the **spanfilade** (from `L`), the **granfilade-as-index** (from `C`), the per-document I-footprint hint (`ran M(d)`), and both result caches (the `paths.json`-registry pattern). For large stores, **checkpoint the materialized arrangements and derived indexes, and replay only each log's tail** (standard WAL + checkpoint). For concurrent queries against an evolving state, serve each query a **consistent (L, M) snapshot** — MVCC falls out for free from the persistent structures, which matters here because the two phases read two different stores: a query straddling independent L/M updates would otherwise produce a result corresponding to *no single coherent state* — an `image` read at one `Σ.M` matched against a later `Σ.L`.

**Divergences from Green to *not* replicate.** The evidence shows Green's type (THREE) slot filter is non-functional. F-MATCH's existential ranges over *all* slots — slot 3 included — so a faithful build of *this note's* primitive indexes the type slot too; the broken THREE filter is the one genuine divergence from the ASN-0127 contract. Green's `homedocids` scoping is *also* disabled (a `TRUE||` guard makes `find-links` global over the link store), but here that **coincidentally matches** ASN-0127 rather than contradicting it: `findlinks(I, Σ) = {a ∈ dom(Σ.L) : matches(a, I, Σ)}` is global by definition — there is no home-document filter anywhere in this note. So Green's disabled home-scoping is *not* a limitation to repair relative to this primitive; home-document scoping is out of scope here, an enhancement belonging to the Q2 / full `find-links-from-to-three` layer, not a fidelity obligation.

## Guarantees to uphold

**Hold by construction** (given faithful implementation + append-only stores):
- Permanence of links/content/addresses, and "result drop = present unreachability, not deletion."
- Coverage determinism; result determinism given a fixed state.
- Union distributivity and I-monotonicity (algebraic; free if `findlinks` is a faithful comprehension) — and result-as-set, so order/idempotence are non-issues.
- Existence-anchored monotonicity and "existence zero ⟹ historical absence" — because the append-only store *is* the complete history.

**Require active enforcement:**
- **Index/cache consistency with the journal.** Indexes are hints; on `K.λ` they must be updated (or marked rebuildable) or the matcher silently under-reports.
- **Discovery present-tense semantics.** Never serve a stale discovery result — neither across an arrangement edit nor across a `K.λ` whose new link matches the cached image; the per-transition maintenance discipline above (with conservative invalidation, triggered on image-motion *or* a matching `K.λ`, as the fallback) is the enforcement.
- **Monotone maintenance of existence caches.** If you cache, never drop a member — the only-grows promise is now yours to keep.
- **Snapshot consistency** so a query sees one coherent (L, M) pair.

## How it fits

Leans on: **ASN-0034** (tumblers: total order, prefix/subtree); **ASN-0036** (content store: immutable, finite domain); **ASN-0043** (link store: endsets, coverage as deterministic span function, append-only permanence); **ASN-0047** (state Σ, the K-transition vocabulary, effect frames, and `K.λ` uniqueness); **ASN-0058** (arrangement, restriction/run decomposition, content sharing M13/M14); **ASN-0093** (allocation freshness/injectivity that the worked witnesses rest on); **ASN-0098** (the discovery predicate F-FULL bridges to, plus link persistence and store monotonicity that the existence lemmas inherit).

Hands to: reader-facing link-following operations; the conjunctive multi-slot retrieval (Q2 / Green's `find-links-from-to-three`); a content-keyed variant via `Σ.C` (Q1); and composition with ASN-0098 link-projection displacement (Q4). It sits as **read-side foundation algebra** — above the stores and arrangement, below reader operations.

## Decisions for the builder

- **Link-index structure:** radix/prefix trie vs. range/interval index over the tumbler order vs. a sorted base + small mutable overlay merged on read (LSM-style). Default to the prefix trie — it rests only on the prefix structure the note establishes; switch to the interval form once subtree-contiguity under T1 is confirmed (it holds in Green's spanfilade).
- **Index granularity:** one global spanfilade vs. per-home-document partitioning — purely an index-locality/sharding choice here, since home-scoping is not part of this note's query contract (see Q2); don't treat partitioning as restoring a contract feature.
- **Discovery-cache policy:** per-transition incremental maintenance vs. conservative invalidation keyed on image-motion *or* a matching `K.λ` vs. recompute-always — and, within maintenance, whether to run the D-CWP front-end check (`findlinks(Δ) = ∅` proves a contraction leaves the result unchanged, skipping its maintenance entirely), and at what granularity (per-region, per-document, or global on `K.λ`).
- **Arrangement representation:** persistent ordered run-map (versioned, MVCC-friendly) vs. flat mutable map (cheaper per-op, no free history). Decide whether you need to evaluate `image` at past states; if yes, persistence is effectively forced.
- **Coverage strategy:** purely intensional vs. transient materialization for hot links.
- **Recovery cadence:** pure replay vs. checkpoint + tail replay, and snapshot frequency.
- **Concurrency model:** whether queries run against MVCC snapshots concurrent with `K.λ`/arrangement edits, or under a simpler serialized regime. Snapshot isolation is already earned by the two-phase coherence argument under *Recovery and durability* — a query straddling independent `L` and `M` updates would correspond to no single coherent `Σ` — so weigh that requirement against a serialized regime's simplicity.
