## What this is

RETRIEVEENDSETS (`RE(W, d, Σ)`) is the read-only query that, given a content region of a document, returns the `(role, endset)` pairs for the *touching endsets* of every *live* link that reaches that region — reporting **that** and **how** content is bound without revealing **which** links bind it. It is the "anchoring without names" sibling of the link-discovery query (`findlinks`): same region, narrower selection (`sel = findlinks_V ∩ addressable` — only the live links), and a *different* deliverable, not a poorer one. `findlinks` hands back identities and hides the anchoring structure; `RE` hands back the anchoring structure — the spans where links attach — and hides the identities. The two axes are orthogonal (RE-EXST): `RE` is *discovery* on the foundation's query-mode axis (region resolved through the present arrangement) but *existence-of-anchoring* on the deliverable axis (structure surfaced, not made followable). Build it as a structure-revealing, non-followable query, not as a lossy `findlinks`.

## Design commitments

These are locked in for everything downstream; I mark what is *forced* versus *conventional*.

- **Identity is withheld; the answer is non-followable.** *(Forced — this is the operation's whole reason for being.)* The link address never reaches the answer, so a surfaced from-endset cannot be paired with its link's to-endset. *(Committed, though questioned by Open Question 2 — not "provisional" the way RE-WHOLE is:)* the adopted answer further *deduplicates* — two distinct links bearing the same endset value in the same slot collapse to one `(role, endset)` pair (baked into RE-DEF as a *set*; RE-UNIT is introduced, not provisional), which makes link multiplicity unrecoverable. OQ2 reopens whether collapsing is *faithful*, not whether it is the committed behavior; the incremental-refcount tension noted below is contingent on this dedup and dissolves if multiplicity is instead preserved.
- **The key is content identity (I-addresses), never position or document.** *(Forced.)* Both the anchoring (endsets cover I-addresses) and the region (its image is I-addresses) live in content-identity space, so transclusion-blindness falls out for free. Coverage-*permanence* is a separate gift — it comes from link immutability (L12) plus LP3★, not from content-keying: content-keying makes the answer a content-identity answer; immutability makes that answer permanent.
- **The region must lie in the content subspace (`∀ v ∈ W : subspace(v) = s_C`).** *(Forced — a caller obligation, **not** a check the operation performs.)* It places the image in content (`I ⊆ dom(Σ.C)`, S3★). The retraction emitter's from-set (∅, content-disjoint because `coverage(∅) = ∅`) and unit-depth to-set (content-disjoint by RE-NCD — a unit-depth span at a non-content `s_L` start) are content-disjoint *unconditionally*; what `I ⊆ dom(Σ.C)` buys is only that they *do not touch the region*. Net-removal-only (below) needs more still — the Θ-discipline `coverage(Θ) ∩ dom(Σ.C) = ∅` (Open Question 6) — not merely a content image. Link-subspace regions (`W ⊆ s_L`) are **out of scope (Open Question 7)**; green accepts them but returns an *empty* result rather than crashing, so a builder must either trust the caller or document the empty/undefined behavior.
- **Overlap, not containment; single shared address suffices; existential within an endset; tested per-endset.** *(Forced.)* A straddling endset is surfaced on one shared address and is *not* clipped to the region.
- **No clipping — every span is reported at full recorded extent.** *(Forced, load-bearing.)* Clipping would lie about the link's grip. This holds under either extent reading.
- **Discovery-anchored / present-tense.** *(Forced by resolving through `Σ.M(d)`.)* A zero answer means "nothing is reachable through this region as it now stands," never "nothing was ever anchored." The answer is non-monotone under editing.
- **Pure read over the *addressable* (live, non-nullified) population.** *(Purity is forced; ranging over the addressable population rather than the full permanent store is the note's settled design decision — a withdrawn link's anchoring should not be reported as live.)* `Σ' = Σ`; reads only `Σ.M(d)` and `Σ.L`; never `Σ.C` values, `Σ.E`, or `Σ.R`.
- **Whole-endset surfacing — all spans, including those pointing outside the region.** *(CONVENTIONAL — provisional, Open Question 1.)* A touching-spans-only implementation still honors no-clipping. This is the one place the note explicitly leaves the payload shape open.

## What must be built

Functionally, an implementation must provide:

- **A region resolver** — turn `(W, d)` into the content-image `I` by reading the *current* arrangement `Σ.M(d)`. Shared verbatim with `findlinks` and content retrieval.
- **A coverage/touch oracle** — decide `coverage(e) ∩ I ≠ ∅` exactly, over the totally-ordered address space, returning the endset *unclipped*.
- **A live-link endset enumerator** — given `I`, produce every `(slot, endset)` of an addressable link whose coverage meets `I`.
- **An addressability determination** — distinguish live links from nullified ones (`addressable = dom(Σ.L) ∖ nullified`).
- **A deduplicating, identity-stripping collector** — assemble `(role, endset)` pairs into a set, discarding link addresses and collapsing duplicates.
- **(Optional) a renderer** — project surfaced endset I-spans into the querying document's V-order, for consumers that want a positioned answer rather than a content-identity one.

## Implementation approaches

This is the heart. The note's deepest engineering gift is that `RE` is *thin*: it is a join over three mechanisms that belong to other subsystems, plus a dedup. Build it that way.

### Resolving the region (V→I)
The image is `{Σ.M(d)(v) : v ∈ W ∩ dom(Σ.M(d))}`. Two realizations:
- **Ordered map from V-position to I-address** (a persistent ordered map). Image = collect over `W`. This is the simplest thing that honors the spec; start here.
- **Run-compressed / interval representation** (the udanax-green POOM/enfilade approach). Because the arrangement is a canonical *contiguous* prefix of the content subspace (D-CTG/D-SEQ), the common case is a handful of contiguous runs, and an interval map stores one entry per run, not per position, and answers V-ranges directly.

I'd ship the ordered map first and move to interval/run-compression only when arrangement size demands it — but note the contiguity invariant makes the interval form natural, so this migration is a known, bounded one, not a rewrite.

### The anchoring index — and "one index, two readers"
The query must, given `I`, find every `(link, slot, endset)` whose coverage meets `I`. Options:

- **Option A — scan the live links.** For each addressable link, for each endset, run the touch test. This is *literally* RE-DEF; the note proves the answer finite *unconditionally*, and computable under one hypothesis — that `W` is *finitely presented* (region membership `v ∈ W` decidable, e.g. `W` given as finitely many spans), always met in practice since the region arrives as a specset of spans (RE-FIN). No index to build, maintain, or recover; nothing can go stale. For a small corpus or a cold path, this is the correct, cheapest thing — pick it first.
- **Option B — a content-keyed coverage index (the spanfilade).** Index every endset span by its I-address range, carrying `(link, slot)` as payload; the query intersects `I` against it. This is udanax-green's spanfilade, proven at scale: a two-dimensional range structure with the I-address on one axis (`SPANRANGE`) and link-identity-plus-role on the other (`ORGLRANGE`), role as a prefix so you can query one slot or all. Since `RE` tests every slot of every link (no per-slot request differentiation), you query all role-bands. One caution: green fixes exactly three role-bands (from/to/three), but RE-DEF is arity-general — `1 ≤ i ≤ |Σ.L(a)|`, and L3 admits *more* than three endsets — so the role dimension must carry an arbitrary slot index; a three-band index silently drops a link's fourth-and-beyond endsets and violates completeness (RE-CMP).

  A second caution, on extent: an index keyed by endset span and intersected against `I` returns only the *touching* spans — one per matching crum — which is the **touching-spans** reading, *not* the whole endset that RE-DEF/RE-WHOLE adopt (`e = Σ.L(a).eᵢ`, all of its spans). Once the intersection has identified a touching `(link, slot)`, honoring whole-endset surfacing requires an *additional* gather of that slot's remaining spans — read directly from the link's endset value. The index finds the touch; the whole endset is fetched separately.

  The verified green pipeline shows `findlinks` and RETRIEVEENDSETS run the *same* V→I→spanfilade search and diverge only in **which axis of the hit they read**: `findlinks` reads the link-identity axis; RETRIEVEENDSETS reads the endset-span axis and strips identity. So **build one link-endset index and give it two readers** — do not build a separate endset index. This is the cleanest "put the function where it belongs" move available here.

The decisive simplification: links are permanent and immutable (L12) and emission is append-only, so the coverage index is a **pure monotone function of the link journal** — append-only, never updated, never deleted. That makes it a *hint* in Lampson's sense: recomputable by replay on a miss or after a crash, never authoritative, never transactionally coupled to anything. Realize it as a persistent ordered interval map keyed by I-address; each emission yields a structurally-shared new version cheaply.

When to pick which: scan for small/cold; the shared index for the hot path at scale. They are not exclusive — the scan is also your recovery-time oracle and your correctness reference for the index.

### Coverage and the touch test
Represent coverage as ranges over the ordered address space and answer touch by range-overlap. A wide span is a half-open interval `[start, start⊕width)`; a unit-depth span is the prefix-closed set `{t : start ≼ t}`, which is just the range `[start, next-sibling)`. One mechanism — interval overlap on an ordered structure — serves both, and it is exactly what makes the note's disjointness arguments (type endsets vs content, retraction to-sets vs content) computable as prefix/field comparisons.

The degenerate cases fall straight out of this test (RE-BND): an empty image — `W ∩ dom(Σ.M(d)) = ∅`, as for a freshly-registered document whose arrangement is still empty — makes `touch_W` false for every endset, so `RE = ∅`; no addressable links gives `∅` the same way; and an *empty* from- or to-endset slot is never surfaced, since `coverage(∅) = ∅` fails the test (only the type slot is required non-empty, L3). That last is a real builder gotcha — the collector must never emit a `(role, ∅)` pair.

### Addressability as a separate live-set filter
Green's spanfilade is write-only and monotone — it never removes an endset entry, even after the content is gone. The note's `addressable = dom(Σ.L) ∖ nullified` is an *additional* live-set filter that green did not need (green has no retraction; links are permanent). Keep this decomposition clean:
- **Filter nullified at query time.** The index returns candidate `(link, slot, endset)`; drop those whose link is nullified. This keeps the index append-only (a pure hint) and puts the retraction logic where it belongs — a separate, cheap set-membership test.
- *Reject* maintaining a live-only index (removing on nullify): it breaks append-only and couples the index to retraction for no benefit.

`nullified` itself is a hint: derived by replaying retraction links (each `Nullify` appends a retraction-typed link whose unit-depth to-set names its target). Materialize it as a persistent set updated incrementally on each retraction emission, recoverable by replay.

On the growth side, RE-ADDR settles emission cleanly: a freshly-emitted *non-retraction* link is immediately addressable in its post-state (`ℓ_new ∉ nullified(Σ')`), so ordinary emission can only *add* `(role, endset)` pairs — the answer is monotone under non-retraction emission. Among link-store (`K.λ`) changes, only retraction removes a pair, and it does so *via the addressable population*; image-side movers (content-subspace contraction, reorder, shift-delete) remove pairs through the image instead (see caching).

A caveat the builder must honor before treating retraction as *removal-only*: a retraction is itself a link emission, and while its from-set (∅) and unit-depth to-set are content-disjoint *unconditionally*, its retraction *type* endset Θ is not. `coverage(Θ) ∩ dom(Σ.C) = ∅` is an **imposed discipline, not a theorem** (Open Question 6); if Θ meets a content image, the retraction surfaces the fresh pair `(3, Θ)` and *adds* anchoring rather than only removing it — breaking net-removal-only (RE-RET) and the refcount-decrement model below. Discharge it structurally by seating Θ in a content-disjoint subspace (see Decisions); do not assume it.

### Recovery: journal + replay, indices as hints
This subsystem reads only `Σ.M` and `Σ.L`, and `Σ.L` is naturally an **append-only journal** — a link log recovered by replay, exactly green's permascroll discipline. So: one authoritative append-only log; the coverage index, the `nullified` set, and the `addressable` set are all hints rebuilt by replay. No duplicate authoritative state, no recovery protocol beyond "replay the journal."

### Assembling the answer — and a real subtlety
Collect into a persistent set keyed by `(slot, endset-value)`; endset equality is set-equality on spans; duplicates collapse. The slot component must be an *arbitrary index*, not a three-valued from/to/type tag — same arity reason as the index above. For *stateless recompute*, that is all.

But if you want to **incrementally maintain** a cached `RE` answer (attractive, because RE-EDIT/RE-RET/RE-CWP tell you exactly how the answer moves), retraction forces a wrinkle: under the adopted dedup (OQ2) and the net-removal-only discipline (OQ6, above), RE-RET says a pair drops *iff the retracted link was its sole addressable bearer*. To maintain the deduplicated set incrementally you must then keep an **internal per-pair bearer refcount**, incremented when an emission adds an addressable bearer of the pair and decremented when a retraction removes one (the pair enters the answer as its count rises above 0 and leaves as it falls back to 0) — even though the answer deliberately hides that very multiplicity (RE-UNIT). The answer hides counts; incremental maintenance needs them privately. (If OQ2 resolves toward *preserving* multiplicity, the dedup — and this whole tension — dissolves.) Decide up front: stateless recompute (simple, no refcounts) versus incremental-with-refcounts (cheap updates, internal bookkeeping). I'd default to stateless recompute and add refcounts only if query latency on a churning store demands it.

### Content-identity vs rendered answer
The note's primitive is a **content-identity** answer: endsets as spans over I-addresses, arrangement-independent and permanent (RE-IDENT). Green actually returns a **rendered** answer: it converts endset I-spans back to the *querying* document's V-positions and **silently drops** any I-address that document does not currently arrange — so an endset can come back empty or partial, and a reorder/pivot can fragment one contiguous endset into several V-spans. That rendered behavior is Open Question 3, not the note's answer.

Build the content-identity answer as the stable primitive and offer rendering as an *optional projection on top*. Put the permanent, arrangement-independent thing underneath; put the lossy, present-tense view where its losses are visible and expected.

### Caching by region cover
Union-distributivity (RE-UDIST) is a gift — *but a reading-dependent one: it holds only under the adopted whole-endset payload, and fails under a touching-spans payload (the note gives an explicit counterexample), where composing cached region answers by union is therefore **unsound**.* Under whole-endset surfacing: cache atomic-unit answers (per V-position, per line) and compose larger regions by **union**. Do **not** compose by intersection — RE-UDIST-∩ fails in general, and the note proves no *injectivity-style* restriction recovers `⊇` (the split-witness obstruction defeats it even under a perfectly injective arrangement; the obstruction is *injectivity-proof, not restriction-proof* — only a degenerately impoverished arrangement, too poor to admit two disjoint regions with distinct nonempty images, forces `⊇`, and then only vacuously). So a cache that answers `W₁ ∩ W₂` by intersecting cached `RE(W₁)`, `RE(W₂)` is unsound; compose only upward, by union. (The weakest *structurally-restricted sufficient* condition for intersection-equality is Open Question 4.)

And RE-EDIT/RE-CWP are the cache's **invalidation rules** — they tell you, *before* recomputing, whether an edit can move the answer at all. RE-EDIT classifies every transition. One set leaves `RE` *fixed* — skip the recompute outright: edits to other documents, content allocation `K.α`, entity creation `K.δ`, provenance writes `K.ρ`, and link-subspace-confined edits on `d` (`K.μ⁺_L` and content-retaining `K.μ⁻`). The complementary set *can* move the answer and forces a recompute: the content-subspace arrangement movers on `d` — extension `K.μ⁺` (image grows, may add pairs), reorder `K.μ~` (image swings, membership may move either way), content-subspace contraction `K.μ⁻`, and the shift-based insert/delete (image-only *under the note's conservative-lift modelling assumption* — that ASN-0082 shift touches no store but `Σ.M(d)`; a builder must ensure their own insert/delete primitives genuinely frame `Σ.L`, `Σ.E`, `Σ.R`, or RE's stability under them does not hold) — together with `K.λ` emission/retraction. RE-CWP handles the one hard case in that set, a contraction, with a *checkable, pre-edit* precondition: `∀ available (i,e): coverage(e) ∩ Δ ≠ ∅ ⟹ coverage(e) ∩ I_R ≠ ∅` (with `Δ` the dropped I-addresses and `I_R` the retained image) — when it holds, the deletion provably leaves `RE` unchanged and the recompute can be skipped without touching the post-state.

## Guarantees to uphold

- **Soundness** *(by construction — never fabricate; the index payload must witness a real link/slot)*. **Completeness** *(active enforcement — every emitted endset span must be indexed; a missed insert silently violates RE-CMP)*.
- **No clipping** *(active — always use the full-extent extraction path; never the intersect-and-truncate path used for content retrieval; green proves these are two different routines and only the full-extent one is correct here)*.
- **Anchoring without names** *(active — the link address is an internal lookup key only; ensure it never reaches the answer; dedup on `(slot, endset)`)*.
- **Content-identity invariance / coverage permanence** *(by construction, given link immutability and content-keying — holds as long as endsets are never rewritten and the key is the I-address)*.
- **Determinism** *(by construction — pure read of current state)*.
- **Present-tense correctness** *(active — resolve through the *current* arrangement; even atop a monotone index, gate the *selection* on what `Σ.M(d)` arranges now, exactly as green's POOM gates its input. Gate only selection, never the returned endset values — those are permanent and arrangement-independent (RE-IDENT); green's *output*-gating, silently dropping unarranged I-addresses, is the rendered mode (OQ3), and applying it to the content-identity answer would violate RE-IDENT)*.
- **Union-distributivity** *(by construction — but **only under the adopted whole-endset reading**; it is forfeit under a touching-spans payload, see Decisions)* — with the standing caution that intersection-distributivity does not hold.

## How it fits

`RE` sits at the query layer and leans on four subsystems, re-deriving none:

- **Arrangement** (`Σ.M`, ASN-0036/0047) for the image — the same `F-IMG` primitive `findlinks` and content retrieval use.
- **Link store** (`Σ.L`, ASN-0043) for endsets — append-only, immutable, non-injective.
- **Span/coverage algebra** (ASN-0098, ASN-0043, ASN-0034) for `coverage(e)` and the half-open/prefix touch test.
- **Retraction discipline** (ASN-0086) for `nullified` / addressability — a standing assumption (every retraction is a `Nullify` with empty from-set and unit-depth to-set); the retraction *type* endset's content-disjointness is itself an *imposed* discipline, not a theorem (Open Question 6).

It is the **sibling of `findlinks`** (ASN-0127): the same discovery selection narrowed to the addressable (`sel = findlinks_V ∩ addressable`), a different deliverable — share the index, project differently. It is **distinct from FINDLINKSFROMTOTHREE** (per-slot-differentiated, identity-returning) and **FOLLOWLINK** (identity-in, endsets-out). It **hands its answer to anchoring-aware consumers** — UI that shades bound regions, "is this linked?" indicators, anchoring-coverage views (*how much* of a region is bound, not how many links bind it — RE-UNIT hides counts) — anything that needs to know content is gripped without needing to follow the grip. It touches neither content values, entities, nor provenance.

## Decisions for the builder

Genuinely open implementation choices (distinct from the note's spec-level Open Questions):

- **Scan vs index.** Brute-force scan over live links for small/cold corpora (proven correct, zero maintenance); the shared content-keyed index for the hot path at scale. Keep the scan as your recovery oracle and correctness reference regardless.
- **Index representation.** Persistent ordered interval map keyed by I-address with role as a dimension and `(link, slot)` as payload, versus the run-compressed enfilade. Choose on corpus size and how contiguous endset coverage tends to be.
- **Addressability placement.** Filter nullified at query time (recommended — keeps the index a pure append-only hint) versus a live-only index (rejected).
- **`nullified` materialization.** Incrementally-updated persistent set versus replay-on-demand; both are valid hints, recoverable from the journal.
- **Where to seat the retraction type.** Net-removal-only under retraction (RE-RET) holds *only if* `coverage(Θ) ∩ dom(Σ.C) = ∅`, which is imposed discipline, not a theorem (OQ6). Seat the retraction type Θ at a dedicated, content-disjoint, *unit-depth element-level* subspace so the field-agreement argument transfers and the disjointness becomes structural. Caution: green's type-address disjointness from content is convention/allocation-enforced, *not* type-system-structural — `acceptablevsa()` is a no-op and the backend never rejects a type endset pointing at content — so a build that mimics green's type placement, *if that convention is ever violated*, can let a retraction surface `(3, Θ)` and *add* anchoring, breaking RE-RET.
- **Content-identity vs rendered answer at the API.** Return I-address spans (stable primitive), V-rendered spans (green's lossy, present-tense view), or both. If you render, decide how to surface the silent-drop of unarranged I-addresses and the pivot-induced fragmentation (Open Question 3 territory). Recommended: content-identity underneath, rendering as an opt-in projection.
- **Whole-endset vs touching-spans payload.** The note adopts whole-endset provisionally — it is baked into RE-DEF (`e = Σ.L(a).eᵢ`, the whole slot endset) and reopened as Open Question 1. Green's RETRIEVEENDSETS does *not* match it: reading the spanfilade SPANRANGE-restricted, it surfaces only the endset spans that intersect the region (one crum per contiguous span, each at full stored extent), so a discontiguous endset's non-touching spans are never found — the *touching-spans economy*, which diverges from RE-DEF. Green diverges *further* still: it returns three flat per-role specsets (one from-, one to-, one three-endset), a *union of touching spans per role* that preserves neither endsets as units nor grouping by link/slot — even more destructured than RE-DEF's `(i, e)` pairs (and than RE-UNIT's per-`(slot, endset)` dedup), so do not mistake green's answer shape for a reference implementation of RE-DEF's deliverable. (Green's whole-endset fetch lives in FOLLOWLINK, which reads the link's own POOM, not in RETRIEVEENDSETS.) So green is evidence in OQ1 *for* the economy, not confirmation of the adopted convention — verify against a discontiguous endset before committing either way. Both readings honor no-clipping (RE-CLIP); but the choice is **not** merely a wire-payload-size decision: per the note it *also decides whether the composition laws hold* — whole-endset surfacing uniquely affords union-distributivity (RE-UDIST) and the unconditional `⊆` half of RE-UDIST-∩, both forfeit under `RE_clip` — and the note calls this algebraic consequence its *strongest* argument for the adopted reading, more decisive than the faithfulness appeal.
- **Stateless recompute vs incremental maintenance.** If you cache `RE` and want incremental updates, retraction forces internal per-pair bearer refcounts (even though the answer hides multiplicity) — but only under the adopted OQ2 dedup; if multiplicity is preserved instead, that tension dissolves. Default to stateless recompute; add refcounts only under measured query pressure.
- **Cache composition.** Exploit union-distributivity to compose region answers from atomic units; never compose by intersection. Use RE-EDIT/RE-CWP as invalidation rules to skip recomputation when an edit provably cannot move the answer.
- **Index scope: global vs per-document.** A global, content-keyed index makes transclusion-blindness (RE-TRANS) and cross-store completeness (RE-CMP, Open Question 5) fall out, as green's global spanfilade demonstrates. If you partition the link store per document, you must union across all co-transcluders at query time to avoid silently dropping anchoring reached through borrowed content.
