# Design Digest — ASN-0112: RETRIEVEDOCVSPAN (Document V-Stream Extent Query)

## What this is

RETRIEVEDOCVSPAN is the cheapest whole-document probe in the operation set: hand it a document identity and nothing else, and it returns a *single span* — an origin and an extent — bounding everything currently arranged in that document's V-stream, or a distinguished *empty result* if the document holds nothing. It is a boundary query, not a content read: it answers "where does this begin and how far does it reach," never "what is in it." Its result is not *typed* as a count either — though in the common single-subspace case the returned width does *determine* the occupied count (below).

## Design commitments

These are the constraints the rest of the system inherits. I mark each forced (the spec or the algebra leaves no choice) vs. conventional (locally chosen, could differ).

- **The result is a boundary description, not data or a count** — two tumblers, "from here, this far," with everything between implicit. Never a content sequence, never a cardinality *as a type*. *Forced* (Nelson 4/68, 4/24). Nuance: though untyped as a count, the returned width *determines* the count in the single-subspace case — its final component is exactly `|O(d)|` (V12); across subspaces it does not (the note's first Open Question), so don't assume the count is always free.
- **The measure is the V-stream (the current arrangement), not the I-stream (the content store).** Content removed from the arrangement but still permanent in the store contributes *nothing* to the extent; the answer is a function of `dom(M(d))` alone. *Forced* — this is the load-bearing distinction of the whole note. Conflating them would report permanence instead of the present arrangement.
- **The query is pure and the result is a snapshot.** No state component changes (V-frame); the returned span is a value fixed at query time, not a live view into mutable state. *Forced.*
- **The span is a function of the extremes only** — `min O(d)` and `max O(d)` — never the interior positions and never the mapped I-addresses. This forces *rearrangement invariance*: permuting what sits where, without changing which positions are occupied, returns the identical span. It also forces *composition insensitivity* in the cross-subspace regime: adding or removing content positions while content stays present (and below the link max) moves neither extreme, so the reported bounding span is *unchanged* — a coarse bound that ignores mid-document content edits. Only clearing content entirely, adding *first* content to a link-only document (the symmetric V18 case, which moves the min down to the content anchor), or moving the link max, moves the span. This is distinct from — and more surprising than — rearrangement invariance. *Forced.*
- **A single span denotes one convex region.** A document occupying both subspaces (content + links) cannot be exactly decomposed by one span — only *enclosed* as a bounding box that bridges the unoccupied inter-subspace void. Fragmentation is unrepresentable in a single span. *Forced by the span algebra* (convexity), not a choice.
- **The origin is an occupied position** — the actual first V-address (e.g. `1.1`), never a fictitious or padded lower bound (`1.0`). *Forced* (it is `min` of the occupied set).
- **Within a single subspace the span is an exact cover; across subspaces it degrades to a bounding box.** The exact-cover half is *forced given the arrangement invariants* (the occupied run is dense and gap-free — ASN-0047 D-SEQ); the degradation is forced by convexity above.
- **Origin permanence:** while content is present, the origin is pinned to the content anchor `[s_C,1,…,1]` and does not move under editing. *Forced given D-MIN*; it migrates only when content occupancy toggles on/off. In the reachable link-only state (all content deleted, links surviving), the origin is instead the link minimum `[s_L,1,…,1]` (V18) — so a builder must read `min O(d)`, never hardcode the content anchor (the `min`-based approaches handle this automatically). One thing the note leaves open here (OQ2): under what conditions the reported origin should be the document's *permanent tumbler identity* `d` rather than `min O(d)`. V1/V8 fix it firmly to `min`, but whether a report should ever name the identity instead is unresolved.
- **The empty document is answerable** via a distinguished empty result; the implementation's zeros are a *sentinel* meaning "no origin, no extent," not a legal tumbler address. *Conventional encoding* of a forced totality requirement.
- Subspace identifiers (`s_C=1`, `s_L=2`, content-before-link) are *conventional*.
- **The half-open denotation is forced** (inherited from ASN-0053 T12); but `reach = shift(max, 1)` — one ordinal step past the max — is a *justified construction*, not a bare convention: V3 makes it the least strict upper bound *at `max`'s depth* and V2 proves it well-formed. It is **not** least over all of `T` — the deeper zero-extension `w.0` is a strictly smaller valid reach, and whether a well-formed span can attain it is an Open Question. *Forced denotation; constructed (not arbitrary) reach.*

## What must be built

- **Identity resolution**: given a document identity, locate its arrangement (the V→I map `M(d)`), gated only by *allocation* — an unallocated identity has nothing to report.
- **Extreme-finding**: obtain the least and greatest occupied V-position of that arrangement. This is the only real work.
- **Span construction**: from `(min, max)` produce `origin = min`, `reach = shift(max, 1)`, `extent = reach ⊖ origin` — i.e. ordinal *shift*, *displacement/subtraction*, and *comparison* over tumblers.
- **Emptiness handling**: detect `O(d) = ∅` and emit the distinguished empty result rather than a degenerate span.
- **Result packaging**: deliver a span-set (a singleton for non-empty, the empty collection for empty) — not a bare span, so the empty and populated cases are denotationally distinguishable.

## Implementation approaches

**The core question is how to get `min` and `max` of the occupied set cheaply.** Everything else (the tumbler arithmetic, the packaging) is trivial once you have the two endpoints.

**1. Read the ends of an ordered arrangement (simplest; my default).**
If `M(d)` is held as a persistent/immutable balanced ordered map keyed by V-position (a B-tree or HAMT), then `min` is the first key and `max` is the last — `O(log n)`, or `O(1)` if you cache the two ends. No auxiliary structure, no summary to keep coherent. *Pick this unless other operations force more.* The whole point of the note is that this query is cheap on *any* ordered representation; do not build special machinery for it.

**2. Maintain a confluent extent summary at a tree root (proven, but earns its keep elsewhere).**
Hold the arrangement in a widative tree — Green's POOM enfilade is the proven instance — where each node carries its subtree's (min-displacement, max-reach) and the root's summary *is* `(origin, reach)`. The query becomes an `O(1)` root read; in Green it is literally a raw copy of the root's V-displacement and V-width, maintained after every edit. The decisive property is **confluence**: the root summary depends only on the *logical* arrangement, not on insertion order or how the tree was balanced — which is exactly what underwrites determinism (V16). The cost lands on the *edit* path (`O(log n)` summary maintenance up the spine), not the query. **Tradeoff:** this is the right place to spend only if positional reads, range queries, or offset arithmetic (RETRIEVECONTENTS, append-point computation) already justify the widative tree. Building an enfilade *solely* for RETRIEVEDOCVSPAN is putting the function in the wrong place. **A second, sharper tradeoff:** the relative-displacement summary can be driven *negative at the root* — same-subspace deletes produce negative intermediate displacements that `setwispupwards` absorbs into the root's displacement (Q18), so the reported origin/start can go negative, violating S8a (zero-free, all-positive). The non-negative-width discipline (below) does *not* cover this; the note leaves repair of the out-of-range case open (Open Question 5). You must guard against or accept a negative root origin — a hazard approaches 1 and 3 cannot produce, since they read `min` as an actual stored key.

**3. Treat the summary as a recomputable hint, authoritative state elsewhere (recovery story).**
Whatever the persistent representation, hold the per-document `(min, reach)` as a *derived index* — a hint in Lampson's sense — with authoritative state in the arrangement (or whatever store/log underlies it). Keep the hint in memory for `O(1)` reads, never treat it as authoritative, and on a miss or after a crash recompute from the arrangement. This keeps the cache honest and gives crash-recovery for free. If the substrate is an append-only journal recovered by replay, the mapping is direct: rebuild the hint by replaying the journal on load. Approaches 1 and 2 are *how you compute the hint*; this is *how you persist and recover it*.

**Span construction.** Once you hold `(min, max)`: `reach = shift(max, 1)` (advance the last ordinal component by one), `extent = reach ⊖ origin` (i.e. `reach ⊖ min`) via tumbler displacement. One representation caution: occupied *positions* are zero-free vectors of positive components (S8a), but *widths/displacements* legitimately carry leading zeros (e.g. `[0,3]` for a three-position content-only document). Do not reuse the position type for widths — the displacement type must permit leading zeros.

**Empty result.** Prefer an explicit empty collection over an in-band zero "span." The zero tumbler is precisely the value the algebra forbids as an address, so letting a zero-span flow into the value layer invites "is this a real address or an empty marker?" confusion. If wire-compatibility with Green matters, Green emits zeros for both displacement and width on an empty document — decode those to the empty result *at the boundary*, not inside the value semantics.

**Cross-subspace bounding box and its discriminators.** When a document holds both content and links, the single span is a bounding box bridging the unoccupied void (Green reports the misleading "1.1 for 1.2" here). Two responses, not exclusive:
- Return the raw bounding box, faithful to the spec, and steer fragmentation-sensitive callers to the per-subspace span-set operation (Green's RETRIEVEDOCVSPANSET is the proven sibling for exact decomposition).
- *Additionally* surface the facts the note hands you, all readable off the returned width with no second query: **first component `= 0` ⟺ exact cover** (V9b), **last component `> 0` ⟺ tight reach** (V9a), and — in the single-subspace regime, where the width is `[0,…,0,n_s]` — **the final component is exactly the occupied count `|O(d)|`** (V12). The count rides the same final slot as the tightness flag, so the result, though not *typed* as a cardinality, *determines* the cardinality in the common single-subspace case; across subspaces it does not (the note's first Open Question), so do not assume the count is always free. Preserve all three — do not normalize the width in a way that destroys positional information. Green's span-set path zeroes mantissa digits to separate subspaces; that is a cautionary example of a normalization that throws away the very positions a caller might want.

**Depth policy (a large simplification).** Keep both subspaces at the *same* depth — Green places content and links both at depth 2, distinguished only by the leading component (`1` vs `2`), never by depth. Then origin and reach are always equidepth, the reach is *always* tight, the span is *always* level-uniform, and the entire depth-divergence apparatus (the negative branches of V-ReachTight / V-LevelUniform, the cross-depth subtraction cases) never fires. The only surviving subtlety is exact-cover vs bounding-box, which turns on subspace *value*, not depth. Allow depth divergence only if some other requirement forces it; otherwise this is the simplest thing that honors the spec.

## Guarantees to uphold

- **Permanence/immutability of what the span denotes** — *by construction*, inherited from content-store (S0/P0) and link-store (L12) immutability. The query never touches it.
- **No mutation; snapshot semantics (V-frame, V16)** — *by construction* if the query path is read-only and returns a value (not a reference into mutable state). With persistent data structures this is free: structural sharing + immutability means a later edit cannot retroactively alter a handed-out result. *Active obligation:* ensure no read-time rebalancing changes logical state (hint recomputation that preserves the logical value is fine).
- **Coverage and well-formedness (V1, V2)** — `O(d) ⊆ ⟦σ_d⟧` and a legal span — *by construction* from `min`/`max` plus the half-open reach.
- **Positive extent (value semantics) / non-negative width (implementation conformance)** — the abstract extent is strictly *positive* by construction (V2 `Pos(extent_d)`), since `reach > origin` always. The weaker *non-negative* property is the implementation-conformance concern: *active obligation if you cache a summary* — the root extent must be recomputed as `max-reach − min`, not a stale transient. Green confirms intermediate tree nodes can hold negative displacements after deletes, yet the root width stays non-negative precisely because it is recomputed as max-minus-min (Q18) — replicate that discipline. **But that discipline protects only the width, not the origin:** the same Q18 mechanism absorbs those negative intermediate displacements *into the root's displacement*, so a confluent summary (approach 2) can report a *negative* origin/start — a value that violates S8a (zero-free, all-positive). The note leaves repair of this out-of-range case open (Open Question 5). Approaches 1 and 3 cannot produce it, since they read `min` as an actual stored key; an enfilade builder must guard against it or accept it.
- **Total answerability (V11)** — *requires active enforcement*: handle empty deliberately. Do not rely on zeros "falling out" of an unguarded path; decide the empty encoding explicitly.
- **Per-document independence (V13)** — *by construction* if each document's query reads only its own arrangement, even when content is shared/transcluded.
- **Confluence / shape-independence (V16)** — *by construction* with approach 1; *an active maintenance invariant on the edit path* with approach 2 (the summary must depend only on logical content, never on tree shape).

## How it fits

- **Leans on:** the strand/arrangement state model (`M, C, L, E, R`); the tumbler algebra (ASN-0034) for shift/displacement/ordering; the span algebra (ASN-0053) for the span-set type and half-open denotation; the subspace and referential-integrity invariants (ASN-0047: dense-run shape, content anchor, depth re-pinning) that make exact cover possible and origin permanence hold; content/link permanence (S0/P0; ASN-0043 L12) for what the span ultimately denotes.
- **Sits at:** the operations layer, as the minimal whole-document boundary query. It is the sibling of the per-subspace span-set operation (which exists precisely to recover exact extents for fragmented documents; the note leaves open, OQ4, what invariant must relate the whole-document span to the bounding spans of the document's individual correspondence runs, so the global extent composes from local ones) and a primitive other operations build on — but *which* operations build on it, and how, turns on the bounding-box/content-only split. **Link append** builds directly on the bounding-box reach: the next link write position is `stream ⊕ width`, sound because a new link sits past the document max, in link space — exactly where the bounding box reaches (Green's `findnextlinkvsa`, with a floor at the link minimum `[s_L,1,…,1]` for a document that has no links yet, where `stream ⊕ width` would still land in content space). **Content append into a mixed document** must *not* use `stream ⊕ width`: that reach lands in *link* space, not at the content end, so content append reads the content-only extent through a separate content-only primitive (Green's `findvsatoappend`, the text-subspace reach — not this op). **Version creation** needs the same content-only extent, and for the same reason reads it through a *separate content-only primitive* — a concrete instance of the redirect-fragmentation-sensitive-callers thesis. (The note leaves open, OQ3, what faithfulness a report of a designated *historical* version must preserve relative to a report of the present arrangement.)
- **Hands to:** callers who then issue content reads over sub-ranges or compute append points. Fragmentation-sensitive callers are explicitly redirected to the span-set operation rather than trusting a single bounding span.

## Decisions for the builder

- **Arrangement representation:** persistent ordered map (read the ends; `O(log n)` or `O(1)`-cached, no summary to maintain) vs. widative summary tree (`O(1)` query, summary maintained on every edit). Pick the map unless the broader operation set already needs the tree.
- **Whether to cache the extent at all:** recompute per query (always correct, trivially cheap on an ordered map) vs. keep `(min, reach)` as an in-memory hint rebuilt on load (by journal replay, if the substrate is journal-based). The hint is recoverable, so caching is safe — but only worth it under query pressure.
- **Empty-result encoding:** explicit empty span-set (recommended) vs. in-band zero sentinel (only for Green wire-compatibility, decoded at the boundary).
- **Discriminator exposure:** keep RETRIEVEDOCVSPAN a bare bounding box and route fragmentation-aware callers to the span-set op, vs. also returning the value-readable exact/tight discriminators so callers classify the answer without a second query.
- **Depth policy:** fix both subspaces equidepth (recommended — collapses level-uniformity and reach-tightness to "always") vs. permit depth divergence and carry the general cross-depth arithmetic.
- **Tumbler in-memory form:** plain component-vectors (positive-integer vectors for positions, with a distinct width/displacement type permitting zeros *in any position*) vs. mirroring Green's mantissa+exponent representation. Component-vectors suffice because the abstract model is purely *positional* — it carries no exponent at all, using integer vectors whose zeros may fall anywhere (`[0,3]` = Green's `0.3`; the depth-3 width `[1,2,0]` carries a *trailing* zero), unlike zero-free positions (S8a). The depth policy is *orthogonal* and governs *where* width zeros can land: fixing both subspaces equidepth fixes vector *length*, so fixed-size vectors and plain lexicographic comparison suffice and widths carry only *leading* zeros (`[0,n]` or `[1,2]`); allowing depth divergence forces *variable-length* vectors, zeros in any position (the trailing-zero `[1,2,0]`), and the prefix-comparison convention (T1 case (ii)) — but still not mantissa+exponent. Reach for mantissa+exponent only if you must inter-operate with Green's wire form.
- **Access model:** session open-document gating (Green gates on the caller's open list) vs. open read access. The note scopes authorization out of the value semantics entirely, so this is a free deployment-level choice that does not affect any guarantee above.
