## What this is

This note defines the **read-side link-resolution layer**: how a stored link's reach into any document is computed against that document's *current* arrangement, and exactly how that reach moves — grows, shrinks, or rebinds — as documents are edited. It is the semantics underneath "follow this link" and "what links reach here," and it draws the system's sharpest line between *permanent stored state* (the link, its coverage) and a *live, recomputed query result* (the projection).

## Design commitments

These are locked in; downstream design cannot violate them.

- **Projection is computed, never stored (the central commitment).** `project(e, d, Σ)` is a pure function of exactly two inputs — `coverage(e)` (static) and the document's current arrangement `M(d)` (live) — and consults nothing else (LP4). *Forced.* No projection cache can ever be authoritative; any stored projection is a hint, correct only insofar as it can be recomputed.
- **The stored link is immutable and permanent.** Address, endset sequence, and the spans within each endset never change and the link is never deleted — regardless of whether anything currently reaches it (LP2, LP13, LP17). *Forced* by L12 (ASN-0043).
- **Coverage is a stateless combinatorial function of the endset's spans.** It does not consult `C`, `L`, `M`, or anything else (by the coverage definition itself, which is purely combinatorial over the spans), and endsets with equal coverage are interchangeable for every projection (LP21). *Forced.* This licenses re-representing, splitting, merging, or normalizing endset spans freely *in derived views* as long as coverage is preserved — while the stored link's own spans stay immutable (LP2).
- **Discoverability is derived, per-document, and arrangement-conditional — not a property of the link.** A link reaches document `d` iff some endset's coverage still intersects `d`'s arrangement range (LP12); this can be lost and regained (orphan/resurrect, LP17/LP18) without the link object changing. *Forced.*
- **Discoverability is independent of origin.** Whether link `a` is discoverable from `d` turns *solely* on `coverage(eᵢ) ∩ ran(M(d))` (LP12's form), hence is independent of the link's home document `home(a)` and of the origin documents of the covered content; a document that merely transcludes covered content thereby becomes a discovery site, with no notification (LP16). *Forced.* This is what licenses a reverse-discovery index that ignores `home(a)` — scoping discovery by home or origin document would be wrong.
- **Projection is per-document.** Editing document `d'` cannot affect the projection through any `d ≠ d'` (LP5). *Forced* by the single-document frame of every edit operation. This is the locality guarantee that licenses per-document indexing and per-document recomputation.
- **Each edit class moves projection in exactly one way.** Extension only grows it (LP9); contraction only shrinks it (LP10); reordering rigidly rebinds it through a bijection that preserves both the I-addresses reached and the cardinality (LP11); allocation, link-allocation, document-registration, provenance-recording, and node/account creation never move it (LP6–LP8, LP14, plus K.δ's Node/Account cases under the same arrangement-fixing template). *Forced.* This is the complete catalog of displacement.
- **Survival of *reach* is conditional; survival of the *object* is not.** A link is discoverable from `d` iff *at least one* endset's coverage still meets `d`'s arrangement range — existentially, `(E i : coverage(eᵢ) ∩ ran(M(d)) ≠ ∅)` (LP12), *not* a condition on each end; the link's mere existence requires nothing (LP13). *Forced.* (This is existential *discoverability*, distinct from universal *followability* of every endpoint.)
- **Identity is by I-address, and content I-addresses are permanent.** Deletion removes arrangement entries, not content; orphaned coverage addresses persist and remain re-arrangeable (LP10, LP17, LP18). *Forced* by S0 / store monotonicity.
- **Tightness is a construction discipline, not an enforced invariant.** Build endsets canonically against currently-allocated addresses and fresh allocations provably fall outside coverage (LP19/LP19a) — but the substrate does *not* check this. *Conventional / builder-owned.*
- **The content/link subspace partition of the arrangement range is load-bearing for projection.** Content-subspace V-positions resolve into the content store, link-subspace into the link store, and the two are disjoint (LP20, LP12b). The partition is what makes per-subspace contraction reasoning sound — but it rests on a *convention* the arrangement layer must uphold (see green below).

## What must be built

- A **projection capability**: given an endset (or a link slot) and a document, return the V-positions in that document's current arrangement whose I-addresses lie in the endset's coverage; undefined when the document doesn't exist. Decide the **return shape** — unordered set, sorted V-list, or union of contiguous V-ranges — noting that contiguity is *not* preserved across reordering (K.μ~ can fragment a formerly contiguous projection, per the worked trace), and that whether a projection is expressible as a finite union of contiguous V-ranges, and whether projected V-order reflects the I-order of the underlying addresses, are both left open by the note. A caller must not rely on order or contiguity unless the arrangement-shape conditions that would guarantee them are separately established.
- A **coverage capability**: from an endset's spans, produce the denoted I-address set as a union of half-open tumbler intervals — pure, stateless, memoizable.
- A **discoverability test**: does any slot's projection through a document hit — equivalently, does coverage intersect the document's arrangement range. The existential here ranges over *every* slot `1..|L(a)|`, and L3 (ASN-0043) forces the type endset at slot 3 to be non-empty as a *set of spans* — so a link is discoverable from any document that arranges its *type* endset's coverage, not only its from/to content. This type-coverage property holds only if the type endset has non-empty *coverage*, which needs positive-width spans, not merely a non-empty span set: enforce non-empty, positive-coverage type endsets at construction, because the substrate does not give it for free — per Green, the creation path accepts empty endsets silently and crashes on zero-width. Decide whether reverse-discovery and the survival count (below) should weight, isolate, or exclude the type slot: a coverage-keyed reverse index returns links by type-coverage too, and "this delete will break N links here" counts type-slot reach unless told otherwise.
- A **pre-edit survival check**: given a proposed contraction on document `d`, decide which links lose their reach *through `d`* — i.e. become undiscoverable from `d` (LP12a's weakest precondition: a link stays discoverable from `d` iff some slot's projection meets the retained set). This is the practical payoff for offering "this delete will break N links *here*" before committing; *true* orphaning (LP17 — discoverable from no document) additionally requires confirming each such link is reachable from no other document.
- A **link store** that is append-only and value-preserving (no mutate, no delete path).
- An **arrangement family** (per-document V→I maps) supporting extend / contract / reorder with their frame and monotonicity behaviors, and never naming an unallocated I-address.
- A **reverse-discovery index** ("which links reach this content/V-position") — the substrate needs this even though the note leaves its invariants open.
- Optionally, a **tight-endset constructor** at link-creation time, if the builder adopts the no-future-capture discipline.

## Implementation approaches

**Projection.** The proven approach (udanax-green) is a *single dimension-parametric routine* (`permute`) that walks a 2-D-indexed arrangement (the POOM enfilade) and returns entries whose (I, V) rectangle intersects the query — one algorithm serving V→I and I→V, with endset/span/address distinctions living only in thin wrappers above it. This is exactly LP21 made structural: the engine sees only `(start, width)` spans, never the endset's decomposition, so equal-coverage endsets are automatically interchangeable. For a Rust/`im` build, model `M(d)` as a persistent ordered map V→I and realize projection two ways:
- *Forward filter* — scan `dom(M(d))`, test each I-address for coverage membership. Simplest, always correct, honors the spec literally. Pick this first; it is the right default for small/medium documents or cold projection.
- *Coverage-range query via an inverse-arrangement index* — keep an I→V index (the arrangement's range side). Because the V→I arrangement is not injective — one I-address can sit at several V-positions within a single document (green's POOM is a multimap, and `project` returns a *set* that may hold several `v` mapping to one covered address) — this index must be a **multimap**, and projection through it can return several V-positions per coverage address. Projection then becomes: intersect coverage's half-open intervals with the document's I-range to get the *reached I-addresses* (this is LP20's image, `coverage(e) ∩ ran(M(d))`), then look those back up through the I→V multimap to recover the V-positions. Termination is immediate because `ran(M(d))` is finite — that holds at every state, independent of LP-Fin. What LP-Fin adds — when the span start is substrate-emittable (`s ∈ F`, true for tight or allocated-rooted spans but not arbitrary endsets) — is that any canonical span's reach contains at most `n` substrate-emittable addresses (LP-Fin Corollary), hence at most `n` allocated ones, so the per-span result is small: the lookup is cheap, not merely finite. This is the enfilade's rectangle walk generalized. Faster for large documents, but the inverse index is a **hint**: derive it from `M(d)`, never treat it as authoritative, and rebuild on suspected staleness. Add it only when profiling says projection is hot.

**Coverage.** Represent an endset's coverage as a union of half-open tumbler intervals `[s, s⊕ℓ)`; membership is interval containment. Because LP21 says only coverage matters, you may *derive* a canonical normalized interval-union — buying fast equality/dedup. Keep that as a separate derived hint; do *not* overwrite the stored link's spans with it, since two endsets with equal coverage but different span sets are different link values (L5 set-semantics) and the stored spans are immutable (LP2). Normalize the derived coverage view if you index or compare coverages; keep the raw spans intact for display and as the authoritative link value. Coverage is pure, so cache it freely (Lampson: cache answers that are cheap to recompute on a miss).

**Link store.** An **append-only journal of link-creation records, recovered by replay on load**, with a registry for address→offset lookup. It fits because links never mutate or vanish — there is no overwrite or delete path to reconcile, so replay is unconditional and LP13 (unconditional persistence) holds *by construction*. If the target substrate is already an append-only journal of this shape, build on it directly. In memory — given a persistent-collection stack (e.g. a Rust/`im`-style one) — a persistent map from link address to value gives O(1) per-state snapshots via structural sharing, which is what makes "project at Σ vs Σ′" cheap across the branch points the note traces; absent such a structure, fall back to per-state copies or to recomputing from the journal. Snapshots on top of the journal are a cold-start optimization, not a correctness requirement.

**Arrangement + edits.** Per-document persistent ordered map V→I, snapshotted per state. The note's operations partition cleanly: contraction = remove a D-SEQ prefix's complement (under contiguous V-positions — qualified in the dense-V-position note below); reordering = re-key by a permutation (I-addresses reached are invariant, so it is pure rebinding); extension = add new V-positions with existing mappings fixed (LP9's E1 + E2). **Decision point with green:** green's INSERT *shifts* all downstream V-positions (the two-blade knife / `makegappm`), so a mid-document insert both adds and moves entries in one primitive — neither a clean LP9 grow nor a clean LP11 permute. But LP9 requires only E1 (strict domain growth) and E2 (prior-domain agreement), *not* frontier placement, so how you recover clean displacement laws is tied to how you choose V-position identity (decision #5):
- *Dense, stable V-positions* — if V-positions are structured addresses dense enough to name a point *between* two existing ones, a mid-document insert is a single clean LP9 extension: add the new V-position, downstream positions never move (E2 holds literally), no reorder at all. Strictly cleaner than both green's shift and extend+reorder. The cost: it relaxes ASN-0047's D-CTG★/D-SEQ★ contiguous-arrangement shape. That shape is *no requirement* of LP9–LP11, LP20, or LP21 — their proofs use only E1/E2, subset+agreement, the bijection, and coverage — so for *those* laws the relaxation is free, a tradeoff against *other* ASN-0047 reasoning rather than against this note's displacement laws. It is *not* free, however, for this note's contraction-survival reasoning: LP12a's retention set `R` is exactly the per-subspace D-SEQ★ prefix union, so dense V-positions reshape `R` away from a prefix — contradicting the "contraction = remove a D-SEQ prefix's complement" framing above. The pre-edit survival check (built on LP12a) must therefore be **re-derived** over the new arrangement shape rather than inherited verbatim; the core identity `project(e, d, Σ′) = project(e, d, Σ) ∩ R` survives for *any* `R`, only the prefix structure is lost. The note's other survival-side lemmas are untouched by V-position identity: LP19/LP19a constrain *coverage* against the allocation frontier — a tight endset plus strict-monotone allocation puts every fresh address outside `coverage(e)`, a statement that never mentions V-positions — and LP12b's subspace argument (`project(a, i, d, Σ) ⊆ V_{s_C}(d)`, `R ⊆ V_{s_L}(d)`, disjoint ⇒ wp false) needs only the subspace *partition*, holding for any retained `R` inside the link subspace, prefix or not.
- *Extend-at-frontier + reorder* — under contiguous-integer V-positions, treat insertion as the note does (a composite of allocate + arrange): append at the frontier, then permute into place. Keeps LP9 and LP11 each exact, at the cost of a reorder on every mid-document insert.
- *Green-style shift primitive* — simplest to implement, but adds *and* moves in one step, forfeiting the per-operation displacement laws (and thus the exactness of the pre-edit survival check).

I'd take dense/stable V-positions where you can afford to relax D-CTG★, otherwise extend + reorder; both keep the displacement laws exact.

**Discoverability + reverse index.** Discoverability is `coverage ∩ ran(M(d)) ≠ ∅` — cheap if you keep `ran(M(d))` or the inverse index. For reverse discovery the proven approach is the **spanfilade: a reverse index from content I-address to link addresses.** Because coverage is a *dense interval set*, not a set of points, this is not a point map — it must be a spatial/interval index over the coverage spans, supporting **stabbing** queries (given an I-address, which links' coverage covers it; a *V-position* query first maps V→I through the document's arrangement, after which the answer is which links' *projection* contains that position — the note's reverse-discovery open question) and **overlap** queries (given a range about to be removed, which links reach into it). Green's spanfilade is exactly this. The pre-edit survival check is built on the same structure: it enumerates the candidate links for a proposed contraction by overlap-querying the soon-to-be-removed positions, then confirms each via live projection against the retained set. The decisive design choice is *what you key it on*:
- Key on **coverage** (permanent, LP3) and **filter on read** through live projection. The index can then never go stale — it over-approximates (false positives only), and the authoritative answer is always the recomputed projection. This is a textbook hint: benign over-approximation, corrected by recomputation. It also makes orphan→resurrect cycles free, because the coverage-keyed entry was never wrong — only the current reach changed. Green's spanfilade is exactly this shape: write-only, returning a stale *superset* after deletion that callers post-filter. Critically, the index must *not* be scoped by home document: discoverability is independent of origin (LP16), so a home-scoped index would miss legitimate discovery sites — green's home-doc filter being a no-op accidentally conforms.
- Key on **current reach** (precise, maintained) — then every contraction must update the index, you duplicate information already in `M`+`L`, and you fight LP17/LP18 (you'd delete entries you'll want back on resurrection).

I'd key on coverage and filter live, every time. (Green also shows the contrast cleanly: link discovery there admits only *content* addresses as queries; link addresses are outputs, not query keys — so a link-to-link reverse capability, flagged open by the note, is genuinely new work, not a reuse of this index.)

**Tight-endset construction.** Build canonical spans (`ℓ = δ(n, #s)`) whose reach contains only currently-allocated addresses, and rely on strictly-monotone allocation so future allocations land above the captured range (LP19a). Green achieves this *emergently* — endsets are captured exactly from arrangement-resident content, and the append-only allocator places new addresses strictly higher — with no invariant asserting it. The single-component difference between `δ(3,m)` (tight) and `δ(4,m)` (reaches one slot past the frontier) is the whole difference between "future content cannot enter this link" and "the next allocation resurrects into it." Choose per link semantics.

## Guarantees to uphold

*Hold by construction* if you follow the approaches above:
- **Link permanence** (LP13) — from an append-only/journaled store with no delete path.
- **Coverage invariance** (LP3) — from deriving coverage purely from immutable spans.
- **Projection's image = coverage ∩ live range** (LP20) — LP20 equates the I-addresses the projection *reaches* with `coverage(e) ∩ ran(M(d))`; the projection itself stays a set of V-positions. Holds from always recomputing, never serving an unvalidated cache.
- **Per-document independence** (LP5) — from per-document arrangement storage with single-document edits.
- **Monotone/rigid displacement** (LP9/LP10/LP11) — from not implementing any primitive that adds *and* removes in one step (decompose insert-with-shift).
- **Orphan persistence + resurrection** (LP17/LP18) — from link permanence + live recomputation; requires that you never GC orphaned links or their coverage addresses.
- **Passive discoverability through transclusion** (LP16) — falls out free: a document that transcludes covered content becomes a discovery site with no notification path to build.

*Require active enforcement:*
- **No spurious future capture** (LP19) — the tightness discipline at construction; the substrate won't do it for you.
- **Subspace integrity** (LP12b, LP20 partition) — content-subspace V-positions must resolve to content, link-subspace to links. Green's placement guard is a stub that always accepts, so nothing structural prevents cross-subspace corruption; for a fresh build a cheap write-time check is worthwhile insurance, because LP12b shows projection is sensitive to the subspace *partition* of a deletion, not just its size. The mechanism is worth stating, since it shapes the index: by the LP-Fin Corollary, a canonical *content*-subspace span's coverage is subspace-*pure* — disjoint from the link store entirely. That is what lets you index content-reaching and link-reaching discovery as separate structures, and it is why emptying a document's content subspace (retaining link positions) orphans a content-canonical link *from that document* regardless of how many link-subspace positions are retained — LP12b's wp goes false. That is the *proven* case. The note's open question (Q7) concerns the link-canonical endset under the **same** contraction (empty content, retain link): here the link's reach sits in the *retained* link subspace, so it tends to be **preserved**, not orphaned — but the precise preservation guarantee is open, because the LP-Fin Corollary at `X = s_L` gives coverage ⊆ link-subspace addresses while `dom(L)` inhabits the link subspace too, so `coverage ∩ dom(L)` need not be empty; LP12b's "coverage disjoint from the link store" step inverts and the case entangles with link-to-link discovery (open Q4). The truly *symmetric* deletion — emptying the **link** subspace and retaining content — is by contrast a clean orphan of a link-canonical link, provable by the mirror argument (its coverage is disjoint from the content store, so `project ⊆ V_{s_L}(d)` while `R ⊆ V_{s_C}(d)`, disjoint ⇒ wp false); that is not the open case.
- **Referential integrity of the arrangement** (S3★, ASN-0047) — every arranged I-address must be allocated; this is the GeneralizedReferentialIntegrity invariant the arrangement layer owns, and LP20's store-confinement corollary only follows once it holds. Green gets it for free because its V→arrangement→I path can only name already-resolved addresses; if you let arrangements name raw I-addresses, you must re-impose it.

## How it fits

- **ASN-0047** provides the extended state `Σ = (C, L, E, M, R)`, the edit operations and their single-document frames, document registration, and generalized referential integrity (S3★) — this note is a pure consumer of those transitions.
- **ASN-0043** provides the stored link/endset structure, the coverage definition, and link immutability (L12) — the permanent half of the permanent/live split.
- **ASN-0093** provides substrate addressing: sub-allocator chains, contiguous emission, the subspace convention, and store disjointness/monotonicity — the ground for LP-Sub/LP-Fin and the tightness argument.
- **ASN-0034** provides the tumbler algebra (spans, `⊕`, half-open intervals, ordinal displacement `δ`) that coverage is built from.
- This layer **hands to** the user-facing link-following / endset-retrieval / link-finding operations, which are expressed directly in terms of `project` and `discoverable_from`. Transclusion and version-comparison rest on the same V↔I projection *machinery* — and transclusion additionally on the displacement laws (LP9, LP16) — but not on the endset-taking `project` or on `discoverable_from` themselves; version-comparison in particular has no endset and no link.

## Decisions for the builder

1. **Recompute-always vs cached hint.** Default to recompute; add the per-document inverse-arrangement index as a recoverable hint only when projection is hot. Never let it be authoritative.
2. **Coverage representation.** Derive a normalized interval-union as a separate hint for indexing/comparison (fast equality/dedup, LP21-licensed) while keeping the stored link's raw spans immutable (LP2) — do not overwrite spans with the normalized form. Worth deriving only if you index/compare coverages.
3. **Reverse-index keying.** Coverage-keyed + live filter (never stale, free resurrection — recommended) vs reach-keyed + maintained (precise but fights LP17/LP18 and duplicates state).
4. **Insertion model.** Tied to #5. *Dense/stable V-positions* make a mid-document insert a single clean LP9 extension with no reorder (relaxes ASN-0047's D-CTG★). *Extend + reorder* keeps LP9/LP11 and the pre-edit survival check exact under contiguous V-positions. A *green-style shift primitive* is simpler but muddier — it adds and moves in one step.
5. **V-position identity.** Stable structured addresses dense enough to name a point *between* two existing ones (LP9's prior-domain agreement holds literally; eliminates the insertion reorder, but reshapes LP12a's retention set away from a prefix, so the survival check must be re-derived — see Arrangement+edits) vs contiguous-integer/positional offsets that shift (you must re-derive agreement, and mid-document insert needs a reorder). Drives #4.
6. **Tightness.** Enforce canonical, frontier-bounded endsets at construction, or allow loose spans that admit future capture. Substrate won't decide for you.
7. **Subspace-convention enforcement.** Structural write-time check vs trust callers (green's choice). For a new build, check.
8. **Durability.** Journal-and-replay (natural for an immutable store) vs periodic snapshot vs both.
9. **Recomputation timing.** Per-document independence (LP5) lets you recompute only the edited document — eagerly on edit or lazily on next query. Lazy is simpler and the live-recomputation model fully supports it.
