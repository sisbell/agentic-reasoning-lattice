# Design Digest — ASN-0133: Substrate Quiescence

## What this is

This note defines the **quiescence theory for the substrate's reactive rule layer** — a coordination/automation system in which a *registry* of trigger-action rules watches the substrate and emits writes. It pins down what it means for such a system to be *done*, how "done" is recognized from inside the predicate language, and under exactly which named hypotheses the system reaches and holds that done-state. It is termination/fixpoint theory for a rule engine, not a new substrate operation or structure.

## Design commitments

- **The rule layer is strictly weaker than the full substrate surface (forced).** Rules sense only through reads (`Observe_K` — never an emission) and act only through `Emit_K`/`Nullify_Binary`. A fire can neither register a home nor allocate raw content (`K.σ`/`K.α` are excluded). Homes and content are provisioned by the *environment*, and every emission targets a pre-existing home (H-HOME). The engine decorates a namespace it does not own; downstream cannot grant rules home- or content-creation power without breaking H-HOME's discharge.
- **Done-ness is a pure, decidable verdict written in the rule language itself (forced, Q0).** `quiescent_R` is one PL term — pure, terminating, observer-uniform — so the system detects its own termination using the same language its rules are written in, with no external oracle. This is the enabling commitment for self-monitoring and for exposing "done?" as a query any party can run from state plus registry alone.
- **Recognizability and absorption are unconditional; *reaching* quiescence is not (forced).** Once quiescent, firing is inert (Q1). But reaching quiescence is a conditional theorem with *every* hypothesis named — extinction discipline, bounded work, fair scheduling. Because the substrate is shared, the environment can re-arm a trigger after detection (*re-entry*); the engine may promise "I will go inert," never "the system settles." No unconditional termination guarantee exists to lean on.
- **Where a trigger reads decides whether it terminates (the asymmetry is forced; the discipline is conventional).** A *negated-existential* trigger over the grow-only audit slice is ⊥-stable (SF) — once extinguished it stays false; combined with **extinction discipline** (the rule emits its own falsifier) this gives at-most-once firing per argument (Q-EXT). SF alone does not. A trigger over the active slice (history minus retractions) is re-armable by any retraction or active-slice deposit (Q-FLIP). The forced fact is the audit/active asymmetry; the stance "*triggers in SF, termination conditions in ST*" is the recommended discipline that makes termination certifiable — not a constraint the substrate imposes.
- **The done-verdict is a single-state property but a multi-read in practice (forced, ASN-0134).** Evaluating `quiescent_R` against a live shared substrate must pin every constituent read to one committed index, or the verdict straddles two states across an interleaved write. A registry whose verdict is a single bounded access escapes this for free.
- **A common evaluation view always exists (forced, Q0 heterogeneous case).** Mixed-view registries pay a fixed-view-base rewrite — a change of spelling, not of value — to become one PL term; top-level *audit* always serves, the walk included (audit reads it natively). The transitive-closure walk (`chain`) is the lone exception not to *audit serving* but to *fixed-view-base reconstruction*: it is rebuildable from no fixed-view base and must be read directly, and the rendering that fails it is top-level *default* for a registry consuming an unfiltered walk.
- **Termination depends on emissions, not rule bodies (forced, Q2).** Extinction discipline is decided by trigger values before/after a fire — public facts — so bodies may be black-box or nondeterministic; only their emitted call sets are judged.

## What must be built

- A **rule registry** holding `(domain, trigger, contract)` rules, carried inline or as pdef-references (registry-as-content).
- A **domain enumerator** that materializes the finite argument set `[D_ρ]_Σ` (QD-fin) — a query over typed relations/slices, with coverage handled as a membership test, never enumeration.
- A **trigger evaluator** computing the Boolean PL verdict per argument at a chosen view; for pdef triggers, expansion-by-reference.
- A **quiescence detector** evaluating `quiescent_R` across all rules × domains × triggers (short-circuiting), at a pinned snapshot, applying the view-rewrite for heterogeneous registries.
- A **scoped quiescence detector** evaluating `quiescent_{R,S}` — the same machinery plus a scope filter `{x ∈ [D_ρ]_Σ : β_ρ^S(x)}` on each rule's domain (per-target `(∃ y ∈ addrs_G(x) :: S(y))` for tuple rules, `S(x)` for address rules), the scope body constrained to be *S-monotone* (`S` occurring only positively — SC's one standing constraint) — answering "is *this* document/region done?", often the operationally relevant query (Q7).
- A **view-derivation layer** yielding audit/active/default readings from the grow-only history plus the retraction set and filter predicates, with direct reads for the transitive-closure walk.
- A **snapshot/version mechanism** pinning all reads to one committed index.
- A **fire executor** applying emission contracts atomically (H-ATOM) and finitely (H-FIN) into a registered home (H-HOME).
- A **scheduler** selecting the next enabled `(ρ, x)` to fire, fair (weak or strong).
- A **registration checker/lint** (recommended) certifying SF + extinction (the Marker pattern) and flagging cyclic couplings.
- A **divergence/livelock monitor** (optional backstop) catching spinning and mutual re-arm.

## Implementation approaches

**Quiescence detection — poll vs. incremental agenda.** Two realizations. (1) *Poll*: periodically evaluate `quiescent_R` by scanning every domain and testing each trigger, short-circuiting on the first true. Dead simple, always correct, no derived state to corrupt; cost is O(total domain size) per poll, wasteful when mostly idle. (2) *Incremental agenda* (production-system / RETE-style match): maintain the set of currently-enabled occurrences — quiescence ≡ empty agenda — and after each write flip only the affected occurrences, using ASN-0129's falsifier inventory (Q-FLIP) as the delta rules and a precomputed *armer graph* (which rule reads which type/view; which emission can arm which trigger) to know what to re-check. The common case (sparse local change) is cheap; the cost is delta-logic correctness — a buggy delta yields *false quiescence*, the dangerous failure. **Pick:** treat the agenda as a *hint* over the append-only journal — the authoritative answer is always recomputable by re-evaluating the pure trigger term or a full Q0 scan. Run the incremental agenda for the everyday "anything enabled?" check; reconcile against a periodic full Q0 scan and on recovery. The agenda is a cache; Q0 is the authority. This is the journal + derived-registry split this repo already runs (`links.jsonl` recovered by replay into `paths.json`).

**Evaluation against the grow-only history — views and snapshots.** The substrate is append-only at the history level — deposits append tuples; retraction is realized as an *appended nullification record* rather than a delete (the note's `A_K = L_K ∖ nullified`). Only the append-only *base* is verified Green-side: the granfilade and spanfilade are write-only and stale entries persist. The active-view-*by-subtraction* is the note's own model — a design choice, not a Green inheritance; Green realizes its active document view as a *mutable* POOM (DELETE removes V→I mappings), not as a log-minus-nullified — so adopt the appended-nullification model deliberately, not as something inherited. So the *audit* reading is the raw log; *active* is audit-minus-nullified; *default* is active-minus-filtered. Build active/default as **layered filters over the audit base**, not as separately stored slices — they are hints recomputable from the log. Evaluate the whole verdict at top-level audit (always admissible), reconstructing active/default from the audit base per Q0's rewrite. Pin all reads with **MVCC over the journal** — "read as of position N" is reading a log prefix, the cheapest mechanism meeting ASN-0134's snapshot obligation and a natural fit for an append-only store; reserve reader critical sections for single-writer deployments. The transitive-closure walk (`chain`) is the exception: not reconstructable from filters (PL can't express the closure, C-reach), so read the substrate-provided walk atom directly — and prefer registries that never consume an unfiltered walk, since top-level default is unsafe for them.

**Domain enumeration and coverage queries.** A domain is a finite query (QD-fin) over typed relations. For Marker-pattern triggers the hot question is "does any tuple in slice `L_K` cover address `a`?" Coverage is the infinite downward closure — membership-testable, never enumerable — as distinct from the finite denoted endset (verified: `coverage_G` vs `addrs_G`). So answer it as a **membership test per finite denoted address**, never by materializing the closure, and index it with a **spanfilade-style span enfilade** — Green's proven index for "which spans cover this point." The domain source is the grow-only log, scanned or indexed by type and then *view-filtered*: an audit-slice domain is the raw log, while an active-slice domain (e.g. the worked-example producer's `{t ∈ M_tgt : is_attn(t)}`, read at the active view) shrinks under nullification and is *not* grow-only. This same discipline binds the per-target scope: scope a tuple by `(∃ y ∈ addrs_G(x) :: S(y))` over its finite targets, with coverage only ever a membership predicate *inside* `S`.

**Fire execution — atomicity and recovery.** A fire is a finite, atomic step run (H-FIN, H-ATOM). Model it as a **journal transaction**: append all of a fire's emissions as one atomic record, so recovery replays it whole and no environment step interleaves within it (a log used for atomicity). Marker-pattern fires emit a single tuple — trivially atomic. Enforce H-FIN at the executor: a contract that would emit unboundedly is rejected. Check the target home is registered before firing (H-HOME), or the fire has no admissible emission. For an **idem=⊤** Marker rule the extinction guarantee survives `Emit_K`'s dedup no-op (ASN-0128 I1): because the trigger reads the *audit* slice, a true trigger certifies no covering tuple in `L_K`, so the fire cannot be a dedup hit — the emit is necessarily a miss that grows `L_K`, and even a born-nullified deposit joins `L_K` and flips the audit-read trigger.

**Scheduler — fairness, deferred by the note.** The note constructs no scheduler; this is the largest open lever. Weak fairness (round-robin or FIFO over the agenda, deduplicating re-armed occurrences) suffices for the structural route — for an all-SF, extinction-disciplined registry over **grow-only** domains, weak (not strong) fairness suffices to reach *and hold* quiescence; bounded input is still required (Q6, regime ii grow-only, on Q5a's full package: all-SF, extinction-disciplined, *and* bounded growth). Strong fairness — needed only for *non-grow-only* domains facing an environment that cycles arguments out of phase — requires turn-fairness machinery the note flags as nontrivial (eventually leaving each recurring argument in-domain-and-true at some turn). **Design lever: keep domains grow-only and you never need strong fairness.** Default to round-robin/FIFO weak fairness; reach for strong-fairness scheduling only where a registry genuinely needs non-grow-only domains under an adversarial environment.

**Registration-time certification (lint).** Make "this registry terminates on bounded input" a static lint. Two syntactic checks per rule: (a) the trigger is an SF spelling — a negated existential over a grow-only audit slice (PD0's quantifier rule); (b) the contract is the Marker pattern — deposits exactly the witness the trigger's existential quantifies over (Q3's decidable match). Both passing on every rule, with grow-only domains, certifies termination structurally. The check is **sound but incomplete**: rules outside the Marker/SF pattern can't be certified and must be flagged uncertified (the note's Open Question 1 — whether to ship a `pd_extinct` SF certificate alongside ASN-0130's existing `pd_stable`). Build the **armer graph** here too and flag cyclic couplings: the note's cyclic-pair counterexample shows local extinction discipline alone diverges, and SF immunity is what breaks the cycle — so a cycle of non-SF rules is a divergence risk worth a warning.

**Divergence monitoring (runtime backstop).** The full work bound is meta-level — reachability-quantified, PL-inexpressible (Open Question 2). A cheap backstop: for SF/Marker rules, any `(ρ, x)` firing more than once is impossible by Q-EXT (which bounds each argument at one fire unconditionally — domain growth adds *new* arguments, it never re-fires an existing one), so a per-argument fire counter exceeding one *certifies* a misbehaving rule — a livelock watchdog. Pair it with the static armer-graph cycle check for the common mutual-re-arm pattern.

**Recovery and persistence.** Everything derived — agenda, active/default views, span indexes, armer graph — is recomputable from the append-only journal, so none needs durable storage; rebuild by replay on restart (the repo's recovered-by-replay pattern). For large histories, checkpoint the derived state periodically so recovery is replay-from-checkpoint, not from genesis — the standard log + snapshot split.

## Guarantees to uphold

- **Recognizability** — `quiescent_R` is always a decidable verdict. *By construction* (Q0) for inline triggers; for a pdef-trigger registry the PL-membership is *conditional on PR-DISC* (the standing premise that lets `expand` terminate). The engine must only evaluate it correctly *and actively* honor the snapshot pinning and the heterogeneous-view rewrite.
- **Scope recognizability** — `quiescent_{R,S}` is likewise always a decidable verdict for any PL scope predicate `S`. *By construction* (Q7); same snapshot and view-rewrite duties as Q0. **Hazard:** scope quiescence absorbs only *in-scope* firing — an *out-of-scope* fire (the registry's own activity, playing the environment's role for the in-scope sub-registry) can re-arm an in-scope trigger and silently un-quiesce a scope just reported done (Q8), itself detectable per-state by re-evaluating Q7.
- **Scope anti-monotonicity** — quiescence is anti-monotone in scope: where `S' ⟹ S` (`S'` the tighter scope), `quiescent_S ⟹ quiescent_{S'}`, so *global* done implies *every* scoped done (the converse fails — a looser scope can hold work no tighter scope sees). *By construction* (Q9), but **only for an *S-monotone* scope body** (`S` occurring only positively, SC's standing constraint); a custom non-monotone body inverts the nesting and voids the global⟹scope inference, so the engine must reject non-monotone scope-body declarations or accept that the inference no longer holds.
- **Absorption** — a quiescent state is a firing fixed point. *By construction* (Q1, RG's no-op clause); honored by simply not firing on a false trigger.
- **Fire atomicity & finiteness** — H-ATOM, H-FIN. *Active*: serialize each fire (journal transaction / critical section) and bound its emissions.
- **Home dischargeability** — emissions land in a registered home. *Active / precondition* (H-HOME): the environment supplies homes; the executor checks before firing.
- **At-most-once firing per argument** — *by construction* for SF-spelling + extinction-disciplined rules (Q-EXT); **not guaranteed otherwise** — for non-SF rules it is an obligation the builder must monitor or accept.
- **Termination (reaching and holding quiescence)** — *conditional only*. The engine enforces fairness (scheduler) and can secure finite real fires for certified SF/Marker registries on bounded input; general H-RF and the environment hypotheses (regime (i) footprint-settling, bounded external input) are workload/protocol assumptions the substrate cannot enforce. State this boundary explicitly to callers.

## How it fits

- Sits on **ASN-0129** for PL, query domains QD, the dynamics classes (PD0–PD2, ST/SF), the falsifier inventory FP, and the view machinery — the language and dynamics its triggers and view-rewrite are written in.
- Sits on **ASN-0128/0126** for the operation surface (`Emit_K`/`Nullify_Binary`/`Observe_K`), idempotency, the gated `→_sh` step and home gate — the act primitives a fire is built from.
- Sits on **ASN-0086** for typed relations and the audit/active slices with `A_K ⊆ L_K` — the grow-only-history vs active-view distinction the SF/Marker reasoning rests on.
- Sits on **ASN-0130** for predicate-definitions-as-content — the option to make the registry itself substrate content via pdef triggers (with PR-DISC as the standing premise).
- Hands its concurrency obligation to **ASN-0134** — the reader-snapshot duty (clause 6), multi-read decomposition, and the single-bounded-access shortcut.
- Hands *upward* to the protocol/coordination layer everything it deliberately omits: who may register rules (the activation binding), which workloads supply bounded input, the scheduler/violation policy, and stochastic rule bodies (probabilistic-flip evaluators, which meet the deterministic contracts only operationally — retry / N-consecutive-clean stopping rules — evaluator-reliability engineering, not substrate semantics).

## Decisions for the builder

- **Scheduler discipline.** Weak (round-robin/FIFO) vs strong fairness; the turn/serialization model strong fairness needs; violation policy (log, halt, escalate). Default to weak fairness and grow-only domains; reach for strong fairness only under non-grow-only + adversarial environments.
- **Quiescence detection strategy.** Full-scan poll vs incremental agenda-as-hint. Pick incremental for large domains with sparse change; keep a periodic full Q0 scan as the authority either way.
- **Scope body.** Per-emitter (`S(addr(x))`), per-target (`(∃ y ∈ addrs_G(x) :: S(y))`), or per-source for a tuple rule; `S(x)` for an address rule; or a custom body. Whichever you pick must be *S-monotone* (`S` positive) to keep the global⟹scope inference (Q9); a non-monotone body is admissible but forfeits it.
- **Snapshot mechanism.** MVCC-over-journal (multi-writer friendly) vs reader critical section (single-writer simple) vs exploiting single-bounded-access registries that need no snapshot at all.
- **Trigger carrier.** Inline PL terms (self-contained, no PR-DISC premise) vs pdef-references (registry-as-content: addressable, versioned, governable, survives de-registration — but needs PR-DISC and an expansion step). Default to pdef when the registry must be governed as substrate content; inline for embedded or ephemeral rule sets.
- **Handling uncertifiable rules.** Reject non-SF / non-Marker rules at registration, or admit them with runtime divergence monitoring. The lint is sound-but-incomplete; you choose the strictness.
- **Checkpoint cadence** for derived-state recovery, traded against journal length.
- **Single- vs multi-writer deployment**, which determines how much of the snapshot and atomicity machinery you actually need.
