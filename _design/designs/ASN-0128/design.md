## What this is

ASN-0128 defines the **type-registry and operation-surface layer** of the substrate — the operational/API ceiling that sits directly above ASN-0126's static shape gate. It pins down what each type registration carries (shape + an idempotence flag + a set of attached behaviors), what de-duplication means at emit time, the catalog of optional query behaviors and the default queries a registered type exposes, and the three types every substrate ships pre-registered (lifecycle retirement, supersession, retraction).

## Design commitments

These are locked for the whole system; downstream design cannot violate them.

- **De-duplication is a *computed equivalence at the operation surface*, never stored identity — the substrate beneath stays pluralistic.** When a type is idempotent and an emit matches an active tuple, the surface returns the incumbent's address and takes *no step*; nothing is merged, no canonical record is rewritten, every distinct deposit survives underneath. This is the thesis of the note and the most load-bearing decision in it: the idem flag enters no transition precondition or effect. (Forced by I1. This is the Nelson architecture — links are never merged; equivalence is computed, not recorded.)
- **Sameness is coverage equality, not value or decomposition equality.** Two emits are "the same" iff they *assert* the same thing — equal source-coverage and equal target-coverage — regardless of span decomposition, proposer, emission time, source app, or home document. A hit can fire on a call whose denoted address set differs from the incumbent's; the suppressed decomposition is then simply never stored, and the returned address bears the *incumbent's* `(F', G')`, not the call's — so a caller that emits `[a, a.x]` and reads the address back may find `[a]`. The only guarantee is coverage-equality, never value- or decomposition-equality (I6's POST is coverage-typed). (Forced by I0; the finer denoted-set criterion is explicitly rejected because no query argument could ever select between coverage-equal tuples.) *Consequence for type designers:* under idem=⊤ on a non-R type, identical assertions from *different proposers* collapse to the first — the second emit is a no-op returning the first's address, so per-author claims do not accumulate. This bites a shipped type: `supersedes` is idem=⊤, and its dedup key is the full coverage pair `(coverage(old), coverage(new))` — crucially its F carries *content* (the old version), not the proposer, unlike R, whose from-fill folds the proposer into F. So two parties asserting the *same* old→new edge share both F and G and collapse to one record — in slight tension with the note's own framing of supersession claims as owned links that accumulate. (Same-old/*different*-new is not a dedup at all but the *branch* case — `succs = {v3, v3'}` — that the determinate walk reports.) The escape, which R demonstrates and which generalizes: to preserve who-asserted-what, fold the author into F — R's per-document from-fill makes `coverage(F)` document-specific, so cross-document retractions are *not* I0-equal — or register idem=⊥. idem=⊤ is identity-of-assertion, not identity-of-claimant.
- **The registry is immutable and validated once, all-or-nothing, at construction.** A declaration set that fails any check yields *no substrate at all* — there is no partially-registered state and no runtime re-validation path. Idem and shape are constant at every reachable state. (Forced: every invariance and stability proof rests on this. A "register a type at runtime" path is not a feature you can bolt on later without dismantling the foundation.)
- **The surface speaks whole-address sets; the substrate speaks coverage (subtrees).** The API emits and returns addresses via a canonical encoding — one unit-depth span per address — but every such address asserts its entire subtree. Membership queries test subtree containment; enumeration queries return exact denoted addresses. (Forced by AD; this address↔coverage bridge is what the whole note is built on.)
- **Query-argument matching is deliberately asymmetric.** Forward / source-vertex arguments match by *exact address*; the one reverse lookup matches by *coverage*. This is chosen, not incidental: the determinate walk's cycle detection and termination need exact vertex identity, while the substrate's native query is coverage overlap. (Forced by AM.)
- **Time is ordinal, not wall-clock, and recoverable only within a home.** The state holds no clock. Age and staleness are measured by position in a home's append chain, and that order exists only *within* a single home — there is no global counter and no cross-home total order. Calendar semantics must be carried as tuple content by the app. (Forced by the four-component state + R1; corroborated exactly by udanax-green, which records no wall-clock timestamp anywhere in persistent state and supports only structural ordering.)
- **Retraction is the single privileged write-path, and target-validity is an *enforced, rejecting* precondition.** All nullification routes through one unit-depth wrapper; the general emit surface rejects every retraction-class call; the wrapper rejects any call whose target is neither already-resident nor self-emitted. This promotion of P-tgt from "conditions the postcondition" to "rejects the call" is what makes whole-document sterilization unreachable through the surface. (The note's central safety decision — it is *not* free and must be coded as rejection.) R is registered **Binary deliberately**: among ASN-0126's four `[R]` configurations it is the one where retraction is expressible *and* the static gate confines *every* R-tuple — wrapper-routed or raw-bypass — to a single-span to-endset (ASN-0126's P6). That confinement bounds even an off-surface raw retraction to a single (at worst range-valued) span rather than a multi-subtree set, which is exactly what lets the nullification index stay cheap.
- **Resurrection after nullification is intended.** Re-emitting a nullified tuple is not a no-op — dedup consults only the active view, so a fresh tuple lands at a fresh address; the audit trail keeps both. (Forced by I2.)

*Conventional, not forced:* *that* the three lifecycle/supersession/retraction universals ship pre-registered, and *with* the registrations S1–S3 fix (shapes, idem flags, behaviors), is forced — the note's resolution of ASN-0126 OQ4, which left open whether *anything* ships pre-registered; what the substrate parameterizes is only *which addresses* the three occupy (reserved type-addresses, in the manner of the subspace identifiers `s_C`/`s_L`). Genuinely conventional: the names `retired`/`supersedes`/`R`; and the `supersedes` slot direction (old→new — the note chooses the converse of Nelson's LM diagram to align the determinate walk with the canonical "version-in-hand → current head" query). This last generalizes to an obligation on *any* directional Binary type (L7): the substrate's F→G ordering carries no inherent direction, so a shipped or app-registered relation whose walk has a meaning must pin its slot convention in its registration contract, or two conforming implementations will walk it opposite ways — *that* you must fix a direction is forced; *which* direction you pick is the convention.

## What must be built

- **A registry builder/validator** that takes a declaration set, checks each record well-formed (shape in its enumeration, idem boolean, every behavior compatible with shape and idem per the compatibility table — read-filter requires Unary; determinate-walk and typed-reverse-lookup require Binary; age-staleness requires idem=⊥, with no shape clause) and the set globally consistent (coverage-class keys pairwise distinct, representatives admissible), pre-seeds the three standard registrations — `retired` = Unary / idem=⊤ / {read-filter}, `supersedes` = Binary / idem=⊤ / {determinate-walk}, `R` = Binary / idem=⊤ / {} — and either yields the frozen registry or fails the entire construction. All checks are finite and decidable (key-uniqueness is O(n²) coverage-equality over representatives). The builder is specified over a *single* declaration set; how several apps sharing one substrate merge their declarations — and what resolves an app-vs-app or app-vs-substrate key collision — is left unspecified (OQ8).
- **The emit operation surface**: accept `(home, source-address, target-address-set)`. The signature's source slot is nominally a finite address set, but the shape gate enforces `|F| = 1` on *every* admitted call across all three shapes — so the source is **always a single address**, and only the target set's cardinality varies (Unary `G = ∅`, Binary one address, Multi finite). Canonically encode, run the gate (registered + shape-conformant), enforce retraction-exclusion, then — under idem — perform the de-dup check against the *active* view, returning the incumbent on a hit (no write) or depositing on a miss; under non-idem, always deposit. Validate `home` only on the branch that reads it (the miss branch) — but since that makes invalid-`home` admission *state-dependent* (it turns on whether a hit exists, which the caller cannot evaluate), the portable caller-facing contract is to supply `home ∈ dom(Σ.M)` unconditionally. The surface is *partial*: a rejected call is undefined — no step, no address — a deliberate choice over a total surface that returns an error value. The single-address source is not cosmetic: it is the precondition that makes the dedup key (`source-address`, minimal-target-antichain) sound, so a builder who reads "set" and admits multi-span sources breaks that key. This whole layer is fixed at the **F=1 / N=3 envelope**; loosening it — multi-span sources, richer arity — is a future note (ASN-0126 OQ6), not something to design in here.
- **The de-duplication check**: given a presented coverage pair and a type, decide whether an active tuple of that type asserts the same coverage; if several match (possible only off the disciplined path), return a *deterministic* one (address-least). Reads the active view only, never the audit slice.
- **Active-/audit-/default-view derivation**: per type, the audit slice (every deposit), the active subset (audit minus nullified), and the default view (active minus read-filtered) — all *derived* over the journal and the retraction relation, not new authoritative state. Only `members` and `targets_of` carry the `active`/`default` view selector (defaulting to `default`); every other enumeration and all membership predicates have a single committed reading (active). The two escape hatches are asymmetric: filtering is undone by selecting `active`, but nullification is undone by nothing — it resurfaces only in the audit view.
- **The retraction wrapper**: the sole nullification entry point — build the unit-depth retraction tuple, check the three preconditions as *rejecting* gates, dedup as any idempotent binary type, deposit on a miss.
- **The default predicates**: source membership, the subtree-membership test, and source→target projection, plus the derived assertion-level forward composition.
- **The behavior-conditional surfaces**, each unlocked only when the registration carries the behavior: read-filter (*Unary only*: a coverage-membership test + a result-side rewrite of the two default enumerations); determinate-walk (*Binary only*: one-step successors, the maximal determinate walk halting at sink/branch/cycle, tip, and in-walk membership — the last *enumeration-derived*, an exact-vertex test on the walk's result list, not a coverage test, so an extension of a chain element does not satisfy it); typed-reverse-lookup (*Binary only*: reverse lookup by target-coverage, typed forward lookup, multi-type forward join); age-staleness (*idem=⊥ only, any shape*: per-tuple ordinal age, the stale set above a horizon, batch retraction of it). These four are the *committed* set of a deliberately growing catalog — the note considers and defers two further behaviors (cascade-with, single-source-restriction) pending a forcing case, so build the behavior set as extensible, not closed. Read-filter's rewrite is pinned to `members`/`targets_of` *only*: whether filtering also rewrites `sources_to` (BH3) or a `chain`/`tip` walk that passes through a filtered mid-chain element (BH2) is deliberately uncommitted in the note (OQ1) — and since `retired` and `supersedes` both ship, the BH1×BH2 case is the canonical lifecycle scenario, not a corner. Ship the active-view reading on those behavior surfaces and treat filter-dominance as an explicit, deferred policy decision, not a default.
- **A serializing authority** that orders concurrent emits into the sequential step relation before either becomes a step, so frontier allocation is first-to-commit.

## Implementation approaches

The substrate underneath should be **an append-only journal of tuple deposits**: the note's link store `L` is append-only and immutable (L12), and udanax-green's permascroll/granfilade is the proven precedent for append-only, monotonic addressing. Recover the derived state by **replay on load** — this is the recommendation here, not an inherited mechanism: udanax persists by session-shutdown enfilade snapshot, not by journal replay, so it grounds the append-only/monotonic-addressing decision, not the recovery method. Build everything else as *derived hints* over that journal. The recurring Lampson move here is that almost nothing in this note is authoritative state: the dedup index, the active/nullified sets, every behavior index, and the per-home frontier are all recomputable from the journal, so they may be lost and rebuilt without ever being wrong.

**The registry.** It is small, frozen after build, and read on every emit. Keep the *validated* registry as an in-memory immutable map for the hot path, but treat the **declaration manifest as the source of truth** and recover by re-validation (deterministic — same input, same registry). Immutability is a gift: no locking, no invalidation, wait-free reads. The alternative is to **reserve conventional addresses in a bootstrap document and store types as content references, with subtyping by address containment** — but this is a *design option, not a proven precedent*: the note cites it per the KB synthesis, yet Q8's code exploration finds no protected backend type registry at all: the named-type constants (QUOTE_TYPE, MARGIN_TYPE) exist only as type-reference VSpecs in the Python *client*, while the backend treats all links identically and enforces no type registry. So the pattern is a *client-side convention with no backend enforcement* — and the registry-subspace isolation it needs (below) is this digest's invention, not inherited from Green. If you take it, the registry subspace **must stay outside the reach of the operation surface** — reserved, never an `Emit`/`Nullify` target — or `Emit`/`Nullify` could mutate a registration and **R1** (the registry constant at every reachable state) falls, dismantling the immutability every invariance and stability proof rests on. This approach unifies registry storage with content storage and offers a provenance answer relevant to OQ4 (substrate-type attribution), at the cost of folding registry lookups into the content query path. *Pick the in-memory map when emit latency dominates; pick the bootstrap-document approach only when you want types to be first-class, queryable, attributable content under one storage mechanism and can isolate the registry subspace from the surface.*

**The de-duplication index (the idem hot path).** The check is "does an active tuple of type K assert this coverage pair?" Coverage equality is *not* span-set equality, so do not key the index on raw endsets. The note hands you the exact canonicalization: for an address-denoting endset, coverage is determined by its ≼-minimal denoted addresses (I0a). So normalize each endset to its minimal-address antichain (drop any address that extends another) and key the index on `(source-address, minimal-target-antichain, type)`. Because the surface emits only canonical encodings, this is a *perfect* key on the disciplined path — O(1) dedup. Keep ASN-0086's coverage-equality decision procedure as the fallback for the rare off-surface tuple that carries non-denoting spans. *Build the antichain index; scan only on the cold path.* This is "make the common case fast, the rare case correct" applied directly.

**Nullification / active-view tracking.** `nullified(a)` holds iff some retraction's target-coverage contains `a`. Two facts make this cheap. First, retraction coverages are *subtrees rooted at a single address* (the unit-depth wrapper), so the test is prefix containment: *is any retraction-root a prefix of `a`?* Second, nullification is **monotone and permanent** — once covered, always covered (resurrection re-emits elsewhere, never un-nullifies the address), so the set of retraction-roots is *append-only and never needs deletion*. Maintain a growing **prefix/radix index over retraction-roots** (built from the audit slice of retractions — every retraction ever deposited, since `nullified` reads the audit slice, not the active one). The active view is then "audit slice minus prefix-covered addresses." Because R ships Binary, the gate confines *every* R-tuple — wrapper-routed or raw-bypass — to a single-span to-endset (ASN-0126's P6), so even an off-surface raw retraction is at worst *one* range-valued span, never a multi-subtree set: the prefix-trie-for-unit-depth / spanfilade-for-range split below is exactly sized to that bound. The proven structure for the subtree-intersection version of this query is udanax's **spanfilade** — a content-keyed index answering overlap/containment in a single pass. *Use a prefix trie for the unit-depth (substrate-surface) case; reach for a spanfilade-shaped index only if you admit range-valued retractions off-surface.* Either way, the index is a hint: lose it, replay, rebuild.

A sharp simplification falls out of the note's own theorem — but a narrower one than "no born-nullified tuples." DR makes only the **C3** conjunct vacuous on surface-disciplined derivations (no *pre-existing* retraction can cover a later fresh address); born-nullified tuples still arise through **C2's self-nullification**. The accurate statement: on a surface-only deployment **no *non-R* deposit is ever born-nullified** — C2 is free for non-R types (the `K ≁ R` precondition) and C3 is vacuous (DR) — so the active view of a non-R type never loses a just-deposited tuple to a pre-existing retraction. The one residual surface case is a wrapper **self-emit** retraction (P-tgt's `a = a_emit(Σ, d_retr)` disjunct), which self-nullifies and is therefore born-nullified — *not* a special case to gate, because in a replay-derived design there is no standalone born-nullified check to write: born-nullified-ness simply falls out of `A_K = L_K \ nullified`, computed identically on every path. So don't build a *separate* sterilization-avoidance gate the discipline makes dead — but don't imply self-emit retractions land active either; the ordinary `nullified` derivation keeps them out of the active view.

**Read-filter (BH1).** `is_filtered(addr)` is the same prefix-containment test as nullification, over the filter type's active roots. The rewrite of the two default enumerations subtracts filtered results at assembly time. Because filter marks are coverage-scoped subtrees, *test each finite result element against the filter-root trie lazily* — never materialize the (infinite) filtered subtree. The active and default views differ only by this subtraction, so expose both behind a view selector rather than storing two sets.

**Determinate-walk (BH2).** Build the active denoted graph as a **forward adjacency index** (source-address → target-addresses) over the active binary slice, maintained incrementally and rebuilt on load; or, when walk queries are cold, just scan the active slice for successors on demand. Critically: **ship one-step successors only, never transitive closure.** Both authorities are emphatic and verified here — udanax answers every link query in a single set-intersection pass and never traverses the graph (which is exactly why its tested cyclic and fan-out topologies never loop), and chains are walked by the *client* issuing repeated single-step queries. So implement `chain` as a bounded iterative walk over `succs` with a visited-set, halting at sink, branch (≥2 successors), or repeat; the finite vertex set is your termination bound. The graph is a *general finite digraph* — fan-out and cycles are first-class (verified: udanax permits and tests cyclic link structures; version cycles are separately impossible by prefix arithmetic) — so the walk's branch/cycle verdicts (`tip = ⊥`) are load-bearing, not decoration. *Do not add a reachability index; closure is the app's job until a forcing case appears.* One further scope caveat is left open: the walk reads the *active* view, so a nullified mid-chain tuple is simply not an edge and the walk halts early — whether an *audit-view* `chain()`/`tip()` recovering historical chains from the audit slice is a substrate obligation or app-side reconstruction is deferred (OQ6).

**Typed-reverse-lookup (BH3).** This is the *reverse* of the adjacency, matched by coverage, and it is precisely what the **spanfilade was built for**: index endsets by content so "which sources' target-coverage contains this address" is one pass. The two directions need two index *shapes*, dictated by AM: forward keyed by exact source address, reverse by target subtree. That asymmetry is the **note's surface-layer choice, not something inherited from the substrate** — udanax matches the from-side and the to-side *symmetrically* by content/I-address intersection (Q4: "no asymmetry between from and to in the matching rule"); AM departs from that, exact-keying the forward side. This is precisely why the **forward adjacency index has to be built deliberately and does not come for free**: the substrate's native query is the symmetric coverage one (so the reverse index falls out of the spanfilade), while the exact-keyed forward side is the note's own addition. *Build the reverse index via the spanfilade when target-side queryability matters operationally.*

**Age-staleness (BH4).** Age is the home chain's frontier minus the tuple's chain index — read straight off the per-home append order already in the journal. The behavior's idem=⊥ requirement is *forced*, not a stylistic constraint: age is per-address, and under idem=⊤ an assertion's address is pinned to its first emission — re-emitting an I0-equal tuple is a dedup hit that returns the incumbent and allocates no fresh chain slot — so `age` would keep counting from the original deposit however often the assertion is renewed, `stale` would classify by first utterance, and `retract_stale` would retract assertions the caller just re-asserted (re-emission being exactly the renewal gesture a lease uses). Under idem=⊥ every admitted emit deposits at the frontier, so renewal *is* re-emission and the renewed assertion's age restarts at zero. **Add no global counter and no clock**: the note and udanax (no persistent timestamp anywhere; no recoverable cross-document order) both forbid it, and a global denominator would silently break the home-relative semantics the spec promises. `stale(h)` scans active tuples computing age; `retract_stale` is batch tooling — a *sequence* of wrapper steps, not an atomic op — over the stale set snapshotted at batch entry. A target already nullified — by interleaving, or earlier in the same batch — is handled by case split, not blanket dedup, and that split is what makes the batch's net postcondition hold under interleaving: R's I0 identity is (retracting-document, target-coverage), so re-retracting the same target *from the same document* is an idempotent hit (dedups to the existing tuple and takes no step), while re-retracting *from a different document*, or after the prior retraction was itself nullified, is not I0-equal and deposits a fresh retraction — redundant (the target is already nullified) but harmless, since an admitted unit-depth wrapper call on an existing link address has single-tuple scope and cannot sterilize. If an app wants seconds, it carries timestamps as content.

**Concurrency and recovery.** `→_sh` is sequential; frontier allocation is first-to-commit per home. The simplest serializing authority is a **single append point** — one writer ordering all deposits — which matches udanax's single-threaded run-to-completion loop and gives a clean total order. That total order exists only to sequence `→_sh` steps; **never expose it as a cross-home age/staleness denominator** — doing so would silently replace BH4's home-relative semantics with the global clock the note (and udanax) forbid. You may shard *frontier allocation, journaling, and non-idempotent emits* per home (those are genuinely home-local — independent frontiers, no shared counter), realized by a per-home buffer-then-flush pattern. But the **idem-⊤ de-duplication check-and-deposit cannot be sharded *by home*** — it is a cross-home synchronization point; if you need dedup throughput, partition it **by I0-class** instead (same I0-class → same shard → serialized), never by home. Cross-home de-duplication is a note commitment: I0's identity is `(coverage(F), coverage(G))` within `[K]` with home explicitly excluded; I1 makes it deliberate; and I4 requires the serializing authority to order two same-`(F,G,K)`-different-home calls so the loser, evaluated against the winner's post-state, finds the now-active tuple and returns its address. Shard the dedup check per home and both same-I0-class calls miss in their own shards and both deposit — two active tuples in one I0-class across homes, violating idem-uniqueness (I1a). Home-locality holds for allocation and staleness denomination, never for dedup. For durability, prefer **per-operation journaling** (crash-safe) over udanax's session-shutdown snapshot; add periodic **checkpoints of the derived indexes** purely to shorten replay — a missing or stale checkpoint just costs more replay, never a wrong answer.

**Storage generality.** Keep the store **span/range-capable** and confine address-denotation to the surface. The substrate is range-valued end-to-end in udanax (verified: CREATELINK carries extents throughout), and the note explicitly defers a range-aware predicate layer; narrowing to addresses at the API is cheap insurance that doesn't repaint storage later.

**State representation.** Persistent, structurally-shared immutable structures align with the spec's functional, immutable-value model and give you free state snapshots and trivial rollback at a constant-factor cost — worth it for the state value and any index you want to expose or reason about *as a value at Σ*. Use plain mutable indexes for the purely-derived hot-path hints you rebuild on load.

## Guarantees to uphold

- **Permanence / immutability of deposits** — by construction, given an append-only journal with no in-place mutation.
- **Address freshness and a flat (prefix-antichain) link domain** — by construction, via monotonic per-home frontier allocation (udanax gets this free from tumbler arithmetic).
- **Registry & idem stability** — by construction *iff you build no mutation path*; actively violated the instant runtime registration exists.
- **Dedup identity = coverage** — *active enforcement*: the check and its index must compare coverage (canonical antichain), not value; a value-keyed index would wrongly split coverage-equal/decomposition-different emits.
- **At most one active tuple per I0-class (idempotent types)** — holds by construction *iff* two conditions both hold: every `L_K`-growing step for that type goes through the surface (*K-surface-emitted*, I1a's per-type hypothesis) **and** the idem-⊤ dedup check-and-deposit is sequentially ordered per I0-class (a global, or I0-class-partitioned, atomic critical section). Surface-routing alone is necessary but not sufficient: concurrent same-I0-class emits from different homes can both miss without that ordering. Off either condition the surface must tolerate multiple matches and resolve deterministically (address-least).
- **No sterilization through the surface** — *active enforcement*: P-tgt as a rejecting precondition + wrapper-only retraction, which makes C3 vacuous on *surface-disciplined* derivations (SD — every `L_R`-growing step is a wrapper call). This is the safety property and it is not free.
- **Attribution / ownership** — home is recorded at deposit and a tuple's home is independent of its endsets; retraction attribution is observable from the from-fill. By construction, with retraction *fully* attributable only under SD (every retraction wrapper-routed; no raw R-deposit whose from-span lies elsewhere).
- **Ordering** — only within-home arrival order is promised; by construction, *and* an active "don't" — building a global counter would over-promise and break home-relative staleness.
- **Resurrection** and **crash-determinism of queries** — by construction, given dedup reads active-only and every query index is pure-replay-derivable.

## How it fits

It sits at the top of the formal stack, the last layer before an app-facing query language. It **leans on**: ASN-0086 (the Emit/Observe/Nullify primitives, the endset/coverage model, coverage-equality decidability, the active/audit slices, frontier allocation, the flat link domain, retraction semantics); ASN-0126 (the static shape gate and shape registry, shape-conformance, the born-nullified/wp analysis, frontier unification, and the projection-bridge proof technique this note mirrors); and ASN-0043 (addresses/spans/endsets/coverage, the unit-depth-span-covers-a-subtree fact, and the canonical-span convention the address-denotation bridge is built on). It **hands to**: the app/query layer (registration and querying through these predicates) and a future predicate-composition note (connectives, nesting, multi-behavior closure — all deferred here). In the production engine, its registry is foundation, its behaviors and operation surface are ops, and its append-only substrate is the engine's journal.

## Decisions for the builder

These are engineering picks the note leaves to you (distinct from its spec-level open questions).

- **Expose a raw deposit path, or surface-only?** This is the biggest fork. Surface-only gives the two disciplines (K-surface-emitted per type, and the `[R]`-specific SD), hence — *with* the dedup ordering below — idem-uniqueness, plus no sterilization and full retraction attribution by construction; and it guarantees no non-R deposit is born-nullified (so the active view never loses a just-deposited non-R tuple to a pre-existing retraction). Admitting raw deposits (for import/migration) forces you to handle multiple dedup matches, born-nullified tuples, non-denoting spans, and audit/active divergence. On non-denoting spans specifically, implement AD's verdict: a non-unit-depth span names no address, so such a tuple is **omitted from address-typed enumerations** yet stays **fully visible to membership predicates and raw `Observe_K`** (both read coverage). *Default to surface-only; gate any raw path behind an explicit import mode.*
- **Where the registry lives** — in-memory frozen map (+ persisted manifest) vs reserved-address bootstrap document; default the map, bootstrap-doc only for types-as-content + OQ4 provenance. Full fork in *Implementation approaches → The registry*.
- **Derive vs index, per query family** — scan-on-demand vs a maintained derived index, chosen independently for nullification, read-filter, forward adjacency, reverse lookup, and age. *Index reverse-lookup first (the classic win); scan the rest until a profile says otherwise.* Idem dedup is **not** in this independent set: indexing it commits you to an atomic check-insert that is a cross-home synchronization point (coupled to Concurrency granularity below) — partitionable only by I0-class, never by home.
- **Dedup key** — canonical minimal-antichain with a coverage-equality fallback; no real reason not to take it. Full fork in *Implementation approaches → The de-duplication index*.
- **Concurrency granularity** — global serialization (default) vs per-home sharding of the home-local parts (frontier allocation, journaling, non-idem emits); idem-⊤ dedup partitioned by I0-class if at all, **never by home** (I1/I4). Full fork in *Implementation approaches → Concurrency and recovery*.
