## What this is

ASN-0128 defines the **type-registry and operation-surface layer** of the substrate — the operational/API ceiling that sits directly above ASN-0126's static shape gate. It pins down what each type registration carries (shape + an idempotence flag + a set of attached behaviors), what de-duplication means at emit time, the catalog of optional query behaviors and the default queries a registered type exposes, and the three types every substrate ships pre-registered (lifecycle retirement, supersession, retraction).

## Design commitments

These are locked for the whole system; downstream design cannot violate them.

- **De-duplication is a *computed equivalence at the operation surface*, never stored identity — the substrate beneath stays pluralistic.** When a type is idempotent and an emit matches an active tuple, the surface returns the incumbent's address and takes *no step*; nothing is merged, no canonical record is rewritten, every distinct deposit survives underneath. This is the thesis of the note and the most load-bearing decision in it: the idem flag enters no transition precondition or effect. (Forced by I1. This is the Nelson architecture — links are never merged; equivalence is computed, not recorded.)
- **Sameness is coverage equality, not value or decomposition equality.** Two emits are "the same" iff they *assert* the same thing — equal source-coverage and equal target-coverage — regardless of span decomposition, proposer, emission time, source app, or home document. A hit can fire on a call whose denoted address set differs from the incumbent's; the suppressed decomposition is then simply never stored. (Forced by I0; the finer denoted-set criterion is explicitly rejected because no query argument could ever select between coverage-equal tuples.)
- **The registry is immutable and validated once, all-or-nothing, at construction.** A declaration set that fails any check yields *no substrate at all* — there is no partially-registered state and no runtime re-validation path. Idem and shape are constant at every reachable state. (Forced: every invariance and stability proof rests on this. A "register a type at runtime" path is not a feature you can bolt on later without dismantling the foundation.)
- **The surface speaks whole-address sets; the substrate speaks coverage (subtrees).** The API emits and returns addresses via a canonical encoding — one unit-depth span per address — but every such address asserts its entire subtree. Membership queries test subtree containment; enumeration queries return exact denoted addresses. (Forced by AD; this address↔coverage bridge is what the whole note is built on.)
- **Query-argument matching is deliberately asymmetric.** Forward / source-vertex arguments match by *exact address*; the one reverse lookup matches by *coverage*. This is chosen, not incidental: the determinate walk's cycle detection and termination need exact vertex identity, while the substrate's native query is coverage overlap. (Forced by AM.)
- **Time is ordinal, not wall-clock, and recoverable only within a home.** The state holds no clock. Age and staleness are measured by position in a home's append chain, and that order exists only *within* a single home — there is no global counter and no cross-home total order. Calendar semantics must be carried as tuple content by the app. (Forced by the four-component state + R1; corroborated exactly by udanax-green, which records no wall-clock timestamp anywhere in persistent state and supports only structural ordering.)
- **Retraction is the single privileged write-path, and target-validity is an *enforced, rejecting* precondition.** All nullification routes through one unit-depth wrapper; the general emit surface rejects every retraction-class call; the wrapper rejects any call whose target is neither already-resident nor self-emitted. This promotion of P-tgt from "conditions the postcondition" to "rejects the call" is what makes whole-document sterilization unreachable through the surface. (The note's central safety decision — it is *not* free and must be coded as rejection.)
- **Resurrection after nullification is intended.** Re-emitting a nullified tuple is not a no-op — dedup consults only the active view, so a fresh tuple lands at a fresh address; the audit trail keeps both. (Forced by I2.)

*Conventional, not forced:* which three types ship (a substrate parameter, like a reserved subspace identifier); the names `retired`/`supersedes`/`R`; and the `supersedes` slot direction (old→new — the note chooses the converse of Nelson's LM diagram to align the determinate walk with the canonical "version-in-hand → current head" query).

## What must be built

- **A registry builder/validator** that takes a declaration set, checks each record well-formed (shape in its enumeration, idem boolean, every behavior compatible with shape and idem per the table) and the set globally consistent (coverage-class keys pairwise distinct, representatives admissible), pre-seeds the three standard registrations, and either yields the frozen registry or fails the entire construction. All checks are finite and decidable (key-uniqueness is O(n²) coverage-equality over representatives).
- **The emit operation surface**: accept `(home, source-address-set, target-address-set)`, canonically encode the sets, run the gate (registered + shape-conformant), enforce retraction-exclusion, then — under idem — perform the de-dup check against the *active* view, returning the incumbent on a hit (no write) or depositing on a miss; under non-idem, always deposit. Validate `home` only on the branch that reads it.
- **The de-duplication check**: given a presented coverage pair and a type, decide whether an active tuple of that type asserts the same coverage; if several match (possible only off the disciplined path), return a *deterministic* one (address-least). Reads the active view only, never the audit slice.
- **Active-/audit-/default-view derivation**: per type, the audit slice (every deposit), the active subset (audit minus nullified), and the default view (active minus read-filtered) — all *derived* over the journal and the retraction relation, not new authoritative state.
- **The retraction wrapper**: the sole nullification entry point — build the unit-depth retraction tuple, check the three preconditions as *rejecting* gates, dedup as any idempotent binary type, deposit on a miss.
- **The default predicates**: source membership, the subtree-membership test, and source→target projection, plus the derived assertion-level forward composition.
- **The behavior-conditional surfaces**, each unlocked only when the registration carries the behavior: read-filter (a coverage-membership test + a result-side rewrite of the two default enumerations); determinate-walk (one-step successors, the maximal determinate walk halting at sink/branch/cycle, tip, in-walk membership); typed-reverse-lookup (reverse lookup by target-coverage, typed forward lookup, multi-type forward join); age-staleness (per-tuple ordinal age, the stale set above a horizon, batch retraction of it).
- **A serializing authority** that orders concurrent emits into the sequential step relation before either becomes a step, so frontier allocation is first-to-commit.

## Implementation approaches

The substrate underneath is the proven one and you already have it: **an append-only journal of tuple deposits, recovered by replay on load** — this repo's `links.jsonl` + `paths.json` registry, and udanax-green's permascroll/granfilade. Build everything else as *derived hints* over that journal. The recurring Lampson move here is that almost nothing in this note is authoritative state: the dedup index, the active/nullified sets, every behavior index, and the per-home frontier are all recomputable from the journal, so they may be lost and rebuilt without ever being wrong.

**The registry.** It is small, frozen after build, and read on every emit. Keep the *validated* registry as an in-memory immutable map for the hot path, but treat the **declaration manifest as the source of truth** and recover by re-validation (deterministic — same input, same registry). Immutability is a gift: no locking, no invalidation, wait-free reads. The alternative, proven in udanax-green, is to **reserve conventional addresses in a bootstrap document and store types as content references, with subtyping by address containment** — this unifies registry storage with content storage and gives substrate-type provenance for free (settling the note's open attribution question), at the cost of folding registry lookups into the content query path. *Pick the in-memory map when emit latency dominates; pick the bootstrap-document approach when you want types to be first-class, queryable, attributable content under one storage mechanism.*

**The de-duplication index (the idem hot path).** The check is "does an active tuple of type K assert this coverage pair?" Coverage equality is *not* span-set equality, so do not key the index on raw endsets. The note hands you the exact canonicalization: for an address-denoting endset, coverage is determined by its ≼-minimal denoted addresses (I0a). So normalize each endset to its minimal-address antichain (drop any address that extends another) and key the index on `(source-address, minimal-target-antichain, type)`. Because the surface emits only canonical encodings, this is a *perfect* key on the disciplined path — O(1) dedup. Keep ASN-0086's coverage-equality decision procedure as the fallback for the rare off-surface tuple that carries non-denoting spans. *Build the antichain index; scan only on the cold path.* This is "make the common case fast, the rare case correct" applied directly.

**Nullification / active-view tracking.** `nullified(a)` holds iff some retraction's target-coverage contains `a`. Two facts make this cheap. First, retraction coverages are *subtrees rooted at a single address* (the unit-depth wrapper), so the test is prefix containment: *is any retraction-root a prefix of `a`?* Second, nullification is **monotone and permanent** — once covered, always covered (resurrection re-emits elsewhere, never un-nullifies the address), so the set of retraction-roots is *append-only and never needs deletion*. Maintain a growing **prefix/radix index over retraction-roots** (built from the audit slice of retractions — every retraction ever deposited, since `nullified` reads the audit slice, not the active one). The active view is then "audit slice minus prefix-covered addresses." The proven structure for the subtree-intersection version of this query is udanax's **spanfilade** — a content-keyed index answering overlap/containment in a single pass. *Use a prefix trie for the unit-depth (substrate-surface) case; reach for a spanfilade-shaped index only if you admit range-valued retractions off-surface.* Either way, the index is a hint: lose it, replay, rebuild.

A sharp simplification falls out of the note's own theorem: on a surface-only deployment, *every* retraction goes through the wrapper, and the proof shows no retraction can ever cover a later fresh address (the C3 conjunct is vacuous). So the **born-nullified / sterilization-avoidance check is provably unnecessary when the only write path is the surface** — you can omit it entirely, and reintroduce it only if you expose a raw deposit path or import pre-policy history. Don't build machinery the discipline makes dead.

**Read-filter (BH1).** `is_filtered(addr)` is the same prefix-containment test as nullification, over the filter type's active roots. The rewrite of the two default enumerations subtracts filtered results at assembly time. Because filter marks are coverage-scoped subtrees, *test each finite result element against the filter-root trie lazily* — never materialize the (infinite) filtered subtree. The active and default views differ only by this subtraction, so expose both behind a view selector rather than storing two sets.

**Determinate-walk (BH2).** Build the active denoted graph as a **forward adjacency index** (source-address → target-addresses) over the active binary slice, maintained incrementally and rebuilt on load; or, when walk queries are cold, just scan the active slice for successors on demand. Critically: **ship one-step successors only, never transitive closure.** Both authorities are emphatic and verified here — udanax answers every link query in a single set-intersection pass and never traverses the graph (which is exactly why its tested cyclic and fan-out topologies never loop), and chains are walked by the *client* issuing repeated single-step queries. So implement `chain` as a bounded iterative walk over `succs` with a visited-set, halting at sink, branch (≥2 successors), or repeat; the finite vertex set is your termination bound. The graph is a *general finite digraph* — fan-out and cycles are first-class (verified: udanax permits and tests cyclic link structures; version cycles are separately impossible by prefix arithmetic) — so the walk's branch/cycle verdicts (`tip = ⊥`) are load-bearing, not decoration. *Do not add a reachability index; closure is the app's job until a forcing case appears.*

**Typed-reverse-lookup (BH3).** This is the *reverse* of the adjacency, matched by coverage, and it is precisely what the **spanfilade was built for**: index endsets by content so "which sources' target-coverage contains this address" is one pass. Note the two directions need two index *shapes*, dictated by AM: forward is keyed by exact source address, reverse by target subtree. udanax's split is the same — a content-keyed reverse index plus per-link forward-by-position. *Build the reverse index when target-side queryability matters operationally; it does not come for free from the forward adjacency.*

**Age-staleness (BH4).** Age is the home chain's frontier minus the tuple's chain index — read straight off the per-home append order already in the journal. **Add no global counter and no clock**: the note and udanax (no persistent timestamp anywhere; no recoverable cross-document order) both forbid it, and a global denominator would silently break the home-relative semantics the spec promises. `stale(h)` scans active tuples computing age; `retract_stale` is batch tooling — a *sequence* of wrapper steps, not an atomic op — over the stale set snapshotted at batch entry. If an app wants seconds, it carries timestamps as content.

**Concurrency and recovery.** `→_sh` is sequential; frontier allocation is first-to-commit per home. The simplest serializing authority is a **single append point** — one writer ordering all deposits — which matches udanax's single-threaded run-to-completion loop and gives a clean total order; relax to **per-home serialization** only under throughput pressure, which is sound precisely because ordering is home-local (independent frontiers, no shared counter). This repo's worker-buffer-then-orchestrator-flush pattern is the per-home-ish realization of the same idea. For durability, prefer **per-operation journaling** (crash-safe, the repo's substrate) over udanax's session-shutdown snapshot; add periodic **checkpoints of the derived indexes** purely to shorten replay — a missing or stale checkpoint just costs more replay, never a wrong answer.

**Storage generality.** Keep the store **span/range-capable** and confine address-denotation to the surface. The substrate is range-valued end-to-end in udanax (verified: CREATELINK carries extents throughout), and the note explicitly defers a range-aware predicate layer; narrowing to addresses at the API is cheap insurance that doesn't repaint storage later.

**State representation.** Persistent, structurally-shared structures (the `im` crate) align with the spec's functional, immutable-value model and give you free state snapshots and trivial rollback at a constant-factor cost — worth it for the state value and any index you want to expose or reason about *as a value at Σ*. Use plain mutable indexes for the purely-derived hot-path hints you rebuild on load.

## Guarantees to uphold

- **Permanence / immutability of deposits** — by construction, given an append-only journal with no in-place mutation.
- **Address freshness and a flat (prefix-antichain) link domain** — by construction, via monotonic per-home frontier allocation (udanax gets this free from tumbler arithmetic).
- **Registry & idem stability** — by construction *iff you build no mutation path*; actively violated the instant runtime registration exists.
- **Dedup identity = coverage** — *active enforcement*: the check and its index must compare coverage (canonical antichain), not value; a value-keyed index would wrongly split coverage-equal/decomposition-different emits.
- **At most one active tuple per coverage class (idempotent types)** — holds by construction *iff every store-growing step goes through the surface* (surface discipline); otherwise the surface must tolerate multiple matches and resolve deterministically (address-least). Enforce surface discipline to get it free.
- **No sterilization through the surface** — *active enforcement*: P-tgt as a rejecting precondition + wrapper-only retraction. This is the safety property and it is not free.
- **Attribution / ownership** — home is recorded at deposit and a tuple's home is independent of its endsets; retraction attribution is observable from the from-fill. By construction, and *fully* attributable only under surface discipline (no raw retractions whose from-span lies elsewhere).
- **Ordering** — only within-home arrival order is promised; by construction, *and* an active "don't" — building a global counter would over-promise and break home-relative staleness.
- **Resurrection** and **crash-determinism of queries** — by construction, given dedup reads active-only and every query index is pure-replay-derivable.

## How it fits

It sits at the top of the formal stack, the last layer before an app-facing query language. It **leans on**: ASN-0086 (the Emit/Observe/Nullify primitives, the endset/coverage model, coverage-equality decidability, the active/audit slices, frontier allocation, the flat link domain, retraction semantics); ASN-0126 (the static shape gate and shape registry, shape-conformance, the born-nullified/wp analysis, frontier unification, and the projection-bridge proof technique this note mirrors); and ASN-0043 (addresses/spans/endsets/coverage, the unit-depth-span-covers-a-subtree fact, and the canonical-span convention the address-denotation bridge is built on). It **hands to**: the app/query layer (registration and querying through these predicates) and a future predicate-composition note (connectives, nesting, multi-behavior closure — all deferred here). In the production engine, its registry is foundation, its behaviors and operation surface are ops, and its append-only substrate is the engine's journal.

## Decisions for the builder

These are engineering picks the note leaves to you (distinct from its spec-level open questions).

- **Expose a raw deposit path, or surface-only?** This is the biggest fork. Surface-only buys surface discipline, idem-uniqueness, no sterilization, and full attribution *by construction* — and lets you omit the born-nullified check entirely. Admitting raw deposits (for import/migration) forces you to handle multiple dedup matches, born-nullified tuples, non-denoting spans, and audit/active divergence. *Default to surface-only; gate any raw path behind an explicit import mode.*
- **Where the registry lives** — in-memory frozen map (+ persisted manifest) vs reserved-address bootstrap document. Default to the map for emit latency; choose the bootstrap document if you want types-as-content and free provenance.
- **Derive vs index, per query family** — scan-on-demand vs a maintained derived index, chosen independently for dedup, nullification, read-filter, forward adjacency, reverse lookup, and age. *Index dedup and reverse-lookup first (the two classic wins); scan the rest until a profile says otherwise.*
- **Dedup key** — canonical minimal-antichain (perfect and O(1) on the disciplined path) with a coverage-equality fallback. There is no real reason not to take this.
- **Concurrency granularity** — single global serialization (simplest, matches the proven single-threaded model) vs per-home sharding (more parallel, sound because ordering is home-local). Default global; shard under pressure.
- **Durability** — per-operation journal (recommended) vs session/checkpoint snapshot; and how often to checkpoint derived indexes as a replay shortcut.
- **State representation** — persistent immutable structures where you want snapshots/rollback and spec-faithful value reasoning; mutable rebuilt-on-load hints elsewhere.
- **Branch/cycle reporting** — the determinate walk returns ⊥ at a branch or cycle; decide whether the client gets bare ⊥ or ⊥-plus-the-candidate-set so the reader can adjudicate (the note assigns adjudication to readers, which argues for surfacing the candidates).
