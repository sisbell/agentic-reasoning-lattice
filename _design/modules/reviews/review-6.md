**Revision list (all sharpenings, most useful first):**

1. **M6 → M5 (content-containment reverse index placement).** `[SHARPENING]` The same "co-locate the index with its writer" logic that correctly put the spanfilade in M7 argues the content-containment reverse index belongs in **M5** (where R is written, maintained at placement time), not in M6 (a reader maintaining a derived index it must track across another module's writes). Either makes M6 *truly* read-only (matching M8's "owns no index") and removes the lone asymmetry where a read module holds a maintained hint. 2. **M7/M8 matcher duplication.** `[SHARPENING]` (Producer-flagged.) The per-slot-match + AND-of-ORs combiner is implemented twice — inside `Observe` (M7) and inside `findlinks` (M8). Factor that combiner into M7 alongside the spanfilade it already owns, leaving M8 as pure discovery presentation (windowing/cursors, count, pagination, projection, RETRIEVEENDSETS). Ownership stays unambiguous either way; this just removes the DRY seam the producer already named as the softest in the design.

3. **M7 — pdef/pd_stable type-declaration seeding.** `[SHARPENING]` M7's registry is immutable and built at construction, yet must contain the `pdef`/`pd_stable` type-shape declarations, which are *specified in ASN-0130* (an M9 source M7 does not cite). The constraint is noted in M9's seam; the ownership of the declarations is just left fuzzy.

4. **M5/M7 — link-arrangement API is add-only as described.** `[SHARPENING]` The M7→M5 channel is described only as a "semantics-blind link-*seating* API," but ASN-0125's listing axis is mutable both ways (de-listing is a real, if optional, part of the edit/supersession workflow), and link-subspace contraction (K.μ⁻ on `s_L`, remove-and-tombstone — distinct from ASN-0117's text-only DELETE) is an M5 capability invoked through this same channel. Describe the API as seat **and** de-list so the capability isn't implied away. (The mechanism exists in M5's general contract primitive and the M7→M5 edge exists; this is description, not a missing component.)

5. **M8 — currency/tip query not named.** `[SHARPENING]` `in(y)`/`out(x)` are listed in M8 as operations composing M7's BH3 reverse index, but their BH2 sibling — ASN-0125's set-valued *currency* (`tip` over the `supersedes` graph) — is left unnamed. 6. **Producer-flagged heft (M3, M7).** `[SHARPENING]` M3 (allocation+registry+ownership) and M7 (raw store + typed relations + behaviors + supersession + index) are the heaviest modules, each with a live split the producer flagged (an Authority module out of M3; a Typed-Relations module out of M7).
