Reviewing against the corpus, the decomposition is largely sound: every ASN's "what-must-be-built" lands somewhere, the five state components map cleanly (C→M4, L→M7, E→M3, M→M5, R→M5), the DAG is acyclic, the cycle-breaks (M7→M5 link-seating, M5→M3 lazy-arrangement, M8→M7 Observe-internal) are real and correctly directed, and sources are faithful. One material edge is missing, plus several worthwhile sharpenings.

## Revision list

**1. [DEFECT] M8 cannot satisfy the document-existence precondition its resolution operations require — add `M8 → M3` (or move the check into M5's image/resolve).** ASN-0127's `findlinks_V`, ASN-0098's `project`, ASN-0108's windowed search, and ASN-0131's resolver all resolve a V-region through a named document's arrangement and must distinguish a *registered-but-empty* document (defined → ∅) from an *unregistered* one (undefined → error). ASN-0127 makes this load-bearing and explicit: the unregistered case "leaves `findlinks_V` undefined ... a precondition violation to signal as an error, not a silent ∅, so a typo'd or stale `d` surfaces rather than masquerading as 'no links here.'" The manifest's own (sound, flagged) lazy-arrangement choice means a registered document may have **no POOM yet**, so M5's POOM-presence cannot make this distinction — the authoritative answer is M3's entity registry (`dom Σ.M = E_doc`, per ASN-0093, which the manifest itself cites for the registered-empty/unallocated split). The manifest wires `M6 → M3` and `M7 → M3` for *exactly* this existence-check pattern (RETRIEVEDOCVSPANSET's allocated-vs-unallocated gate; MAKELINK's home/source-existence gate) — but **M8 has no M3 edge**, and `M5 → M3` is explicitly scoped "*only* ... as an edit precondition," which forecloses routing M8's read-path check transitively through M5's resolve. A builder following the DAG would ship `findlinks_V` returning ∅ for unregistered documents — the precise bug ASN-0127 warns against. Fix: add `M8 → M3` (mirroring `M6 → M3`), **or** make M5's image/resolve own the existence error (consulting M3) and broaden the `M5 → M3` seam past edit preconditions. The same fix clears up the imprecise "V→I image primitive (via M5)" listing in M8: the resolve is M5's, the content-subspace restriction is per-caller, and the existence error must live with whichever owns `image`.

**2. [SHARPENING] Relocate the spanfilade from M8 to M7 so `Observe` and discovery share one index.** The producer flagged this (Open question 3) and, I think, took the weaker side. The spanfilade has *two* consumers: M8's discovery and M7's `Observe` (ASN-0086 names the spanfilade as Observe's index). `M8 → M7` already exists, so placing the index in M7 costs **no new edge**, lets M8 read it, and restores the indexed Observe that the current placement forecloses on the PL/quiescence hot path (ASN-0129/0133 poll Observe; unindexed it is O(|L_K|) per poll). M7 is also the better maintenance site — it is co-located with the only writer of links (Emit/MAKELINK), so the index can be pushed-updated on write, whereas in M8 it can only be a pull/replay-rebuilt hint disconnected from the write path. M7 already carries derived hints (nullified set, dedup index), so this matches its shape. Sound either way; I'd flip it.

**3. [SHARPENING] M9's seam under-states its *writes* into M7.** The seam describes only reading M7, but ASN-0130's `register_pred`/`certify_pd_stable` *emit* `pdef`/`pd_stable` classifier tuples into M7, and ASN-0133's reactive fires emit via `Emit_K` (M7). The `M9 → M7` edge is present, so this is a description gap, not a missing edge — but state the write path, and note `pdef`/`pd_stable` must be registered in M7's (immutable, construction-time) type registry.

**4. [SHARPENING] Name the version-frontier-vs-document-frontier separation in M3's allocator.** ASN-0123 *forces* the allocator to separate the version chain (child of the source document) from the document chain (child of an account): "the allocator is forced to separate the document frontier from the version frontier." M3's "frontier allocator (inc-modes ...)" subsumes this but doesn't surface it, even though M5's CREATENEWVERSION calls M3 for version-identity allocation (`M5 → M3`). Make the level-aware mode an explicit M3 obligation.

**5. [SHARPENING] Make the R-in-M5 justification (and its permanence-layer distinction) explicit, not merely flagged.** Co-locating append-only authoritative R with mutable presentational M puts two permanence layers (ASN-0047) in one module. It is sound — write-locality (every placement appends R atomically with the M edit) and the requirement that SHOWDELETIONS/COMPARE read a *single consistent (M, R) snapshot* (ASN-0075's atomic root-swap of M-edit + R-append) both argue for co-location — but the responsibility line should say so, so the boundary isn't read as a grab-bag.
