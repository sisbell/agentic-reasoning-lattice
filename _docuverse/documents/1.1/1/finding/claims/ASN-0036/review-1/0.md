### D-MIN carries a circular derivation; it is a design axiom, not a theorem
**Class**: REVISE
**Foundation**: T1 (LexicographicOrder), and the sibling design constraints D-CTG / S8-fin / S8a within this ASN
**ASN**: D-MIN per-claim contract, Step 3: *"By the contiguity constraint, V_1(d) is a single block with no internal gaps, and a document's text is laid down starting at the origin of its subspace... the smallest position the subspace admits is [1, 1, ..., 1], and that is where the block begins. A non-empty block contains its starting position, so [1, 1, ..., 1] ∈ V_1(d)."*
**Issue**: The Properties table and main body classify D-MIN as a "design requirement / design constraint," but the per-claim contract attaches a 4-step proof ending in ∎ that purports to *derive* `min(V_1(d)) = [1,…,1]` from contiguity plus positivity. Step 2 only establishes that `[1,…,1]` is a universal *lower bound* (`[1,…,1] ≤ v` for all `v`); Step 3 then asserts membership `[1,…,1] ∈ V_1(d)` by claiming "that is where the block begins" — which is exactly the conclusion D-MIN states. The step "a document's text is laid down starting at the origin of its subspace" smuggles in the thesis. The derivation is in fact impossible from the cited premises: the set `V_1(d) = {[1,5],[1,6],[1,7]}` satisfies D-CTG (contiguous — `[1,6]` is the only intermediate and it is present), S8a (all components positive, depth 2), S8-fin (finite), and S8-depth (common depth 2), yet `min = [1,5] ≠ [1,1]`. So D-MIN is logically independent of D-CTG/S8a/S8-fin and cannot be a theorem over them. Separately, the Depends list names only S8-depth, while the proof body invokes the contiguity constraint (D-CTG) and the finiteness constraint (S8-fin).
**What needs resolving**: Drop the 4-step derivation and present D-MIN purely as a design requirement (consistent with the table and the main-body treatment, and with how D-SEQ/ValidInsertionPosition already consume it as a premise). If D-MIN is instead to remain derived, it must cite the actual left-anchoring premise that forces the least element to the all-ones tuple (a strand- or operations-layer "block starts at origin" invariant) — and acknowledge that D-CTG + S8a + S8-fin alone do not entail it, exhibiting why the contiguous/positive/finite witness `{[1,5],[1,6],[1,7]}` is excluded. Either way, fix the Depends list to match whatever premises the final text uses.
