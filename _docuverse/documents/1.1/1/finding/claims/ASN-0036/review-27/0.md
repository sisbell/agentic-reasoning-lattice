### S7d models each document as a distinct child-spawn node, inconsistent with T10a's sibling structure
**Class**: REVISE
**Foundation**: T10a (AllocatorDiscipline) — child-spawn rule `base = inc(spawnPt, k')`, `k' ∈ {1,2}`, at-most-once on `(t,k')`; TA5(d) (HierarchicalIncrement) — `inc(·,1)` appends `[1]`, `inc(·,2)` appends `[0,1]`, so every child-spawn base ends in component value `1`; T10a.7 (EnumerationInjectivity); GlobalUniqueness.
**ASN**: S7d (DocumentAllocationDiscipline): *"Every document is realized as a distinct node of the global allocator tree 𝒯 at document level — its address being the document-level tumbler N.0.U.0.D (zeros = 2) carried as that node's base, established by exactly one child-spawning event… Hence the map `ev` taking each document to its spawning triple `(parent, spawnPt, spawnParam)` is total and single-valued… and injective: were `ev(d₁) = ev(d₂) = (P, t, k')`, T10a's at-most-once constraint… would coincide the two children, hence the two documents `d₁ = d₂`."*
**Issue**: Under T10a, a non-root node's base is `inc(spawnPt, k')` with `k' ∈ {1,2}`, and by TA5(d) every such base ends in component value exactly `1`. A document address `N.0.U.0.D` whose document field's last component exceeds `1` — i.e. **every co-user document after the first** — therefore cannot be any node's base. Concretely, `[1,0,1,0,2] = inc([1,0,1,0,1], 0)` is a *sibling* of document 1, produced by `inc(·,0)`; T10a places it in document 1's allocator domain as an address, not as a distinct allocator. (S5's own witness set `dᵢ = [1,0,1,0,i]` is exactly such a co-node/co-user family.) Consequently S7d's premise fails for those documents on two counts: (i) they are not distinct nodes, and (ii) they carry no spawning triple, so the map `ev` is undefined on them and the at-most-once-on-`(t,k')` injectivity argument — which is about *child-spawning* events — does not apply. The argument as written only discriminates the single child-spawn document per allocator; it does not establish event-distinctness for the sibling documents, which are distinct *sibling-increment* (`inc(·,0)`) events. The downstream **conclusion** S7 consumes (distinct documents ⇒ distinct document-level tumblers) is still true — sibling-increment events are distinct allocation events, and GlobalUniqueness covers all event types — so S7's uniqueness postcondition survives; but it is established by a different route than the one S7d gives, and S7 currently feeds on S7d's broken derivation.
**What needs resolving**: Replace S7d's "every document is a distinct child-spawn node" model with one consistent with T10a: co-user documents are distinct sibling addresses within a single document-allocator's domain (one node), distinct by T10a.7 / distinct `inc(·,0)` events, while documents under different users or nodes lie in disjoint allocators. Establish "distinct documents ⇒ distinct allocation events" across both regimes (so `ev` ranges over allocation *events*, not child-spawn triples only), then lift to address-distinctness via GlobalUniqueness as before; remove or restrict the at-most-once-on-`(t,k')` injectivity step to the single child-spawn document per allocator. While reconciling, check that S7a's parallel phrase *"spawned under the document's own allocator"* is read as the shared (per-user) document allocator with the document address as spawn point — not as a per-document node — since S7a's used memberships `A_element ∈ 𝒯`, `a ∈ dom(A_element)` are themselves sound.

VERDICT: REVISE
