### S7a mis-scopes the element-allocator quantifier
**Class**: REVISE
**Foundation**: T10a.6 (DomainDisjointness) — for distinct allocators `X ≠ Y`, `dom(X) ∩ dom(Y) = ∅`.
**ASN**: S7a: *"Consequently, for a T10a-conforming element allocator `A_element`, every `a ∈ dom(Σ.C)` satisfies two memberships of distinct types — `A_element ∈ 𝒯` … and `a ∈ dom(A_element)`, the address lying in that node's domain …"*
**Issue**: The quantifier order as written binds `A_element` before `∀a`, i.e. `∃A_element ∀a : a ∈ dom(A_element)` — one element allocator whose domain contains every stored address. This is false: when content is allocated under more than one document, `dom(A_element)` (one document's element addresses) cannot contain all of `dom(Σ.C)`, and by T10a.6 distinct documents' element allocators have disjoint domains, so no single `A_element` holds two documents' addresses. The intended statement is `∀a ∃A_element` — for each `a`, the element allocator of `a`'s home document. S7's own Precondition states it correctly per-address ("for the document owner's T10a-conforming element allocator"), so the defect is confined to S7a's prose, but S7a is an exported claim and its statement is unsound as written.
**What needs resolving**: Re-scope so the element allocator is bound per address: for every `a ∈ dom(Σ.C)` there exists a T10a-conforming element allocator `A_element` (the allocator of `a`'s home document) with `A_element ∈ 𝒯` and `a ∈ dom(A_element)`.
