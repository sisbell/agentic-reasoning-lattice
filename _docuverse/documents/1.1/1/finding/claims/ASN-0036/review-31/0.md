### S7d's single-valuedness clause reintroduces the T10a.7/T10a.6 dependence the reroute disavows, and is unconsumed
**Class**: REVISE
**Effective class**: OBSERVE (classifier override)
**Classifier rationale**: The single-valuedness clause is unconsumed by S7 (whose lift uses only totality + injectivity) and is an axiomatically-posited trace citing T10a — itself a declared dependency — so the artifact is correct as it stands and dropping the residue only tightens prose rather than repairing a defect.
**Foundation**: T10a.6 (DomainDisjointness), T10a.7 (EnumerationInjectivity) — neither in S7d's Depends (which lists T4, T10a, TA5)
**ASN**: S7d (DocumentAllocationDiscipline). Body: *"The map `ev` is total and single-valued: each document's document-level address is produced by exactly one event of the discipline — every address of `𝒯` is either an allocator's base, established by one child-spawning event, or the `n`-th output of one allocator, produced by one `inc(·, 0)` step (T10a)."* Axiom: *"the map `ev` ... is total and single-valued — every address of `𝒯` is produced by exactly one event ... (T10a) — and injective ..."* Reroute disavowal, same claim: *"T10a.7 (EnumerationInjectivity)'s output-injectivity `n ↦ tₙ` ... we have no need of it — index-distinctness alone separates the two events."*
**Issue**: The single-valuedness clause "every address of 𝒯 is produced by **exactly one** event" is not one of the two facts S7 consumes — S7's Uniqueness step takes only (i) each document's tumbler arises from an allocation event, and (ii) distinct documents arise from distinct events (the injectivity). For the lift to GlobalUniqueness, ev needs only totality + injectivity; single-valuedness is never used. Worse, validating "exactly one event" requires precisely the uniqueness facts the reroute set out to avoid: within an allocator, no address appears at two indices (T10a.7's output-injectivity — the very `tₘ ≠ tₙ` the prose says it has "no need of"); across allocators, no address lies in two domains (T10a.6). The bare "(T10a)" citation papers over this — and S7a's precedent (which lists T10a *and* T10a.4 separately) shows this ASN's convention is to cite the specific T10a.* sub-claim used. So the clause is either a gratuitous "trace" of a posited property (essay-prose justifying why the posit holds) or an under-cited derivation; the reroute fixed the load-bearing injectivity path but this residue still leans on the avoided lemma. This is reviser drift: an adjacent assertion left standing after the path it shared was rerouted.
**What needs resolving**: Drop the unconsumed single-valuedness "trace" ("every address produced by exactly one event ... (T10a)") so the claim asserts only what S7 consumes (totality + injectivity), keeping the reroute's "no need of T10a.7" honest; or, if ev's single-valuedness is to be claimed, cite T10a.6 and T10a.7 in Depends and remove the disavowal of T10a.7.
