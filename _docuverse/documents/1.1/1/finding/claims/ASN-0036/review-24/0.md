### subspace claim defines the v₁ projection without grounding it in T0
**Class**: REVISE
**Foundation**: T0 (CarrierSetDefinition, ASN-0034) — component projection `i ↦ aᵢ` and length operator `#·`
**ASN**: subspace (VPositionSubspaceIdentifier) — the entire claim: *"For any tumbler `v` of depth `#v ≥ 1`, define: `subspace(v) = v₁` extracting the subspace identifier as the first component of a V-position."* There is no *Formal Contract*, *Definition*, or *Depends* block.
**Issue**: subspace is a **derived** definition — `subspace(v) = v₁` consumes T0's component projection (`v₁` for `v ∈ T`) and T0's length operator (`#v ≥ 1`) — yet it cites no foundation at all. It is referenced as a first-class dependency by V-sub, S8-depth, D-CTG, D-CTG-depth, D-SEQ, OrdShiftHom, and ValidInsertionPosition, each writing "subspace (VPositionSubspaceIdentifier) — supplies the projection `subspace(v) = v₁`" to ground *their* use of `v₁`. The grounding chain therefore terminates at subspace, where `v₁` is introduced with no edge to T0. A consumer (formalization tool included) tracing where `v₁` is defined hits an unsupported symbol. This is unlike the sibling signature definitions: Σ.C names "`T` is the set of tumblers (ASN-0034)" in prose, and Strand uses only this-ASN symbols (`Σ.C`, `Σ.M`); subspace alone consumes a foundation symbol while citing nothing. Every other claim in the ASN that reads a component cites T0 for the projection.
**What needs resolving**: Give subspace a *Depends* entry citing T0 (CarrierSetDefinition) for the component projection `v₁` and the length operator `#·` its definition consumes, so the `v₁` symbol is grounded at its definition site rather than left dangling for the seven downstream consumers that ground their `v₁` usage on it.
