### D-SEQ Step 3 cites NAT-card's empty-set biconditional as a packaged export, contradicting the ASN's own established convention
**Class**: REVISE
**Foundation**: NAT-card (NatFiniteSetCardinality)
**ASN**: D-SEQ (SequentialPositions), Step 3: `"By NAT-card's empty-set characterization \`|S| = 0 ⟺ S = ∅\` (NatFiniteSetCardinality, ASN-0034), this guard holds exactly when the zero-filter ... is empty"`; and the parallel Depends entry: `"supplies the cardinality operator \`|·|\` through its empty-set characterization \`|S| = 0 ⟺ S = ∅\` (the \`k = 0\` case of \`|·|\`)"`.
**Issue**: NAT-card's Formal Contract exports only the "unique-k" value-clause axiom; it has no Consequence bullet stating `|S| = 0 ⟺ S = ∅`. This ASN's own sibling claims are explicit and emphatic that this biconditional is *not* a packaged NAT-card export and must be derived inline each time it is needed: S8a states "its contract exports this only as the `k = 0` instance of that axiom, not as a packaged consequence, so we derive the biconditional here rather than cite it by name," and D-CTG-depth — proving literally the same fact (`zeros(w) = 0` for a constructed intermediate witness `w`, in the same "insert a witness between two positions" argument shape as D-SEQ's Step 3) — goes further, explicitly performing the inline derivation and explicitly refusing to "attribute it to NAT-card as an already-exported characterization... on S8a's own stated terms for the identical fact." D-SEQ instead asserts the biconditional directly, under the label "NAT-card's empty-set characterization," with no inline derivation — the exact citation pattern its sibling claims name and reject. This is a real inconsistency in a document that otherwise polices this distinction (direct vs. transitive grounding, packaged vs. derived facts) with unusual rigor; a downstream formalizer reading D-SEQ's Depends entry would look for a Consequence bullet in NAT-card that does not exist.
**What needs resolving**: Either (a) perform the inline derivation of `|S| = 0 ⟺ S = ∅` at the `k = 0` instance of NAT-card's axiom in D-SEQ's Step 3, mirroring D-CTG-depth's and S8a's treatment, and drop the "empty-set characterization" phrasing that implies a packaged export; or (b) if the two-line derivation is judged unnecessary overhead here, at minimum align the phrasing with the ASN's established discipline (e.g., "the `k = 0` case of NAT-card's axiom, from which `|S| = 0 ⟺ S = ∅` follows as shown in S8a/D-CTG-depth") rather than presenting it as a directly-citable NAT-card characterization.
