### S7a/S7 conflate the allocator tree 𝒯 with the address domain dom(A_element)
**Class**: REVISE
**Foundation**: T10a (defines `𝒯` = *the set of allocators*); T10a.4 (instantiation requires `A ∈ 𝒯` and `t ∈ dom(A)`); AllocatedSet/GlobalUniqueness use `A ∈ 𝒯` for allocators, `a ∈ dom(A)` for tumblers
**ASN**: S7a — "every `a ∈ dom(Σ.C)` satisfies `a ∈ dom(A_element) ⊆ 𝒯`"; and S7 Well-definedness — "instantiating it at `A := A_element` and `t := a` — legitimate precisely because S7a places `a ∈ dom(A_element) ⊆ 𝒯`"
**Issue**: `𝒯` is the set of *allocators* (T10a: "the set of allocators induced by T10a"); `dom(A_element)` is a set of *tumbler addresses*. The written `dom(A_element) ⊆ 𝒯` therefore asserts *tumblers ⊆ allocators*, a type mismatch. What T10a.4's instantiation actually needs are two distinct memberships of distinct types: `A_element ∈ 𝒯` (the element allocator is a node of the tree) and `a ∈ dom(A_element)` (the address lies in its domain). Both hold — S7a's own prose establishes them ("A_element — a node of the global allocator tree 𝒯" and `a ∈ dom(A_element)`) — but the compressed chain `a ∈ dom(A_element) ⊆ 𝒯` mis-encodes the allocator-membership as a subset relation on the address domain, violating the definitions in scope at the exact point the proof claims to be "legitimate."
**What needs resolving**: State the licensing premise type-correctly as the conjunction `A_element ∈ 𝒯 ∧ a ∈ dom(A_element)` (not `dom(A_element) ⊆ 𝒯`) at both S7a and S7's Well-definedness step, so the T10a.4 instantiation `A := A_element, t := a` is discharged by memberships of the right types.
