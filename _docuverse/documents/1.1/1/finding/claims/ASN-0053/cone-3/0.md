### SC — `start`, `reach`, and the span type are ungrounded in the depends section
**Class**: REVISE
**Foundation**: SC's *Depends* cites only T1 (LexicographicOrder, ASN-0034)
**ASN**: SC (SpanClassification) — *Preconditions*: "α and β are spans whose starts and reaches lie in the domain of the total order T1"; *Definition*: "The denotation of a span γ is the half-open position set ⟦γ⟧ = { p : start(γ) ≤ p < reach(γ) }"
**Issue**: The accessor functions `start(α)`, `reach(α)`, `width(α)` and the type "span" are introduced in SC's preconditions and definition slot with no grounding citation. The Span definition — which fixes `span(s, ℓ) = {t ∈ T : s ≤ t < s ⊕ ℓ}` and establishes the `start`, `width`, `reach` projections — is explicitly cited in T12's depends section from ASN-0034 as the source of these symbols. SC omits it entirely. As a result, `reach(α) = start(α) ⊕ width(α)` is never grounded, and the claim that reach(α) ∈ T (asserted as a precondition) has no traceable source — TumblerAdd's carrier postcondition `a ⊕ w ∈ T`, which would ground it, is also uncited. The denotation definition `⟦γ⟧ = { p : start(γ) ≤ p < reach(γ) }` that SC introduces locally is therefore circular: it defines the set by reach(γ) while reach(γ) itself is undefined in SC's scope.
**What needs resolving**: SC must add the Span definition to its depends section (grounding `start`, `width`, `reach` as projections from the pair representation and establishing the denotation `⟦σ⟧ = span(start(σ), width(σ))`). TumblerAdd must also appear to ground reach(α) ∈ T via its carrier postcondition, or T12 must be cited as the source of that membership fact for well-formed spans. The choice between citing Span + TumblerAdd directly versus citing T12 is a design decision, but at least one grounding path must be present.
