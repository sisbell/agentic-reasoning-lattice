### Issue 3: R3 conflates determinism with canonicity, and the conformance clause then retracts R3
**ASN-0122, "The Operation," X12**: "(R3) *determinism* — pairs are maximal and listed in canonical lexicographic order, first-operand-major" versus, one paragraph later, "it may emit finer pairs than the maximal ones — granularity is free — so long as the denotation equals `corr`. Completeness, soundness, confinement, and the determinism of whatever presentation it fixes are non-negotiable."
**Problem**: Two defects. (a) Mislabeling: maximality plus canonical order is *canonicity* — a particular output; determinism (same inputs, same output) is already X5's consequence and holds for any fixed presentation. (b) Normative inconsistency: an implementation emitting finer-than-maximal pairs violates R3 as written yet is declared conformant by the very next paragraph — and the ASN's own udanax-green adjudication ("one pair per arrangement-index leaf … the particular count is implementation granularity") applies the denotational standard, not R3. The same ambiguity touches R4, which the implementation section also relaxes ("The packing is representation, not content"). As a contract, X12 mixes binding postconditions (R1, R2) with reference-presentation properties (R3, R4) under one heading and equal force.
**Required**: Separate the contract into (i) binding conformance requirements — soundness, completeness, confinement, deterministic presentation — and (ii) the canonical reference presentation `CANON` (maximal pairs, lexicographic order, minimal record), stating explicitly that (ii) defines the reference result and is not required of conforming implementations. Rename R3 accordingly.
