### Issue 1: `subspace(start) = s_C` does not entail "span confined to the content subspace," and is not the mechanism that makes the result content-only
**ASN-0122, X12 (precondition) and "State, Instances, and Spec-Sets":** "every span confined to the content subspace (subspace(start) = s_C) — a restriction that loses no correspondence information (X9)" — and, in the region section, "the restriction to the content subspace V_{s_C} is a precondition we adopt now and justify below (X9)."

**Problem:** The parenthetical equates two non-equivalent properties. `subspace(start) = s_C` constrains only the first component of the start tumbler; it does not confine the span's denotation to the content subspace. A T12-well-formed span whose width acts below `#s` crosses subspaces. Concretely, `σ = ([1,5], [3])` is T12-well-formed — `Pos([3])`, `actionPoint([3]) = 1 ≤ #[1,5] = 2` — with `subspace(start) = 1 = s_C`, yet `reach(σ) = [1,5] ⊕ [3] = [4]`, so `⟦σ⟧ = {t : [1,5] ≤ t < [4]}` contains `[2,7]`, whose `subspace = 2 = s_L`. A span passing the precondition can therefore denote link-subspace positions; "subspace(start) = s_C" is strictly weaker than "confined to the content subspace," and the equation as written is false for general T12 operands.

This is not merely cosmetic, because the operation's content-only correctness does not actually rest on the precondition. It rests on the region definition's unconditional clip `⟦S_i⟧ ∩ V_{s_C}(d_i)`, which removes every non-content denoted position regardless of the start's subspace (above, `[2,7] ∉ V_{s_C}(d)`, so it is dropped). The ASN presents the precondition *as* the content-subspace restriction, and X9's losslessness is argued about that restriction — while the load-bearing mechanism is elsewhere (the `∩ V_{s_C}` in `R_Σ(ρ)`). An implementer who trusts the gloss "subspace(start) = s_C ⟹ confined to s_C" and consequently treats the V_{s_C} clip as redundant would wrongly admit arranged link-subspace positions for any low-action-point content-rooted span — a real correctness defect the prose invites, and one that flatly contradicts X9's conclusion.

**Required:** Reconcile the two mechanisms. Either (a) strengthen the precondition to ordinal-/level-uniform content spans (`#ℓ = #s` with `actionPoint(ℓ) = #s`, matching the report's own `(u, δ(n, m))` feet and ASN-0058's content references) — under which `subspace(start) = s_C` *does* entail full confinement (the prefix copy keeps `(s⊕ℓ)₁ = s₁ = s_C`, and T5 contiguity confines `⟦σ⟧`), so the gloss becomes correct; or (b) keep the weaker predicate but state explicitly that content-only results are guaranteed by the unconditional `∩ V_{s_C}(d_i)` clip, demote `subspace(start) = s_C` to operand hygiene, and correct the "confined to the content subspace" wording. In both cases X9's "lossless restriction" should be pinned to the V_{s_C} clip, not to the start-component predicate.
