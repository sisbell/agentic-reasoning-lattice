### Issue 1: Case (ii) "forced" inconsistency for V_{s_L}(d) = ∅
**ASN-0100, "The Operation: Formal Contract" → Substrate Decomposition (case ii)**: The ASN states K.μ⁻ omission in case (ii) is "Canonical-decomposition choice when V_{s_L}(d) ≠ ∅; forced when V_{s_L}(d) = ∅".
**Problem**: For V_{s_L}(d) ≠ ∅, the ASN explicitly identifies an alternative decomposition: "an alternative decomposition could fire K.μ⁻ with n'_{s_C} < N (admissible since s_C is non-empty here) and follow with a K.μ⁺ that re-adds the discarded s_C positions before adding Insertion, reaching the same Σ'." The same alternative is available when V_{s_L}(d) = ∅: with n'_{s_C} < N (admissible since case (ii) requires N ≥ 1 and V_{s_C}(d) is non-empty) and n'_{s_L} = 0 = n_{s_L}, K.μ⁻'s strict-shrinkage clause `(E S :: n'_S < n_S)` is satisfied via s_C alone. K.μ⁻ fires; K.μ⁺ then re-adds the discarded s_C positions plus Insertion, reaching the same Σ'. This alternative uses only K.μ⁻ + K.μ⁺ (the ASN's stated vocabulary scope), requires no K.μ⁺_L, and is admissible. Under the ASN's own definition of "forced" — "no admissible K.μ⁻ firing exists under the canonical retention parameters and INSERT's frame" combined with the alternative-decomposition treatment of V_{s_L}(d) ≠ ∅ — case (ii) with V_{s_L}(d) = ∅ should be classified as "canonical-decomposition choice", not "forced".
**Required**: Either (a) reclassify case (ii) V_{s_L}(d) = ∅ as "canonical-decomposition choice" (consistent with the V_{s_L}(d) ≠ ∅ treatment), or (b) explain why the alternative decomposition with n'_{s_C} < N that the ASN admits for V_{s_L}(d) ≠ ∅ is not considered for V_{s_L}(d) = ∅. As written, the two subcases of case (ii) receive inconsistent treatment for the same available alternative.
