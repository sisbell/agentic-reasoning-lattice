### Issue 1: The worked example asserts D(d) is both unchanged and changed for the same scenario
**ASN-0116, "A worked insertion" → Links over the insertion (the "IP6 trap" and "genuine resurrection" paragraphs)**

The example explicitly equips `d` with **two coexisting links**: "Equip `d` with two links to drive the link claims against this concrete shift." — `ℓ` with `coverage(e) = {a_3, [d.0.s_C.8]}` and `ℓ'` orphaned with `coverage(e') = {[d.0.s_C.7]}`.

The IP6 trap paragraph (about `ℓ`) concludes:
> "This is precisely the pre-state the *sufficient* emptiness form would reject and the *weakest* containment form accepts: `ℓ ∈ Added ⊆ D(d, Σ)` leaves `D(d)` unchanged. ✓ IP6 (containment, not emptiness)."

Two sentences later, the genuine-resurrection paragraph (about `ℓ'`) concludes:
> "Here `ℓ' ∈ Added ∖ D(d, Σ)`, so `D(d, Σ') ⊋ D(d, Σ)` — a real change to the discoverable set... ✓"

**Problem**: Both `ℓ` and `ℓ'` inhabit the *same* post-state, so `Added = {ℓ, ℓ'}`. Since `ℓ' ∈ Added ∖ D(d, Σ)`, we have `Added ⊄ D(d, Σ)` and `D(d, Σ') = D(d, Σ) ∪ {ℓ'} ⊋ D(d, Σ)`. Therefore the IP6-trap chain `ℓ ∈ Added ⊆ D(d, Σ)` asserts a containment (`Added ⊆ D(d, Σ)`) that is **false** for this scenario, and "leaves `D(d)` unchanged" is **directly contradicted** by the very next paragraph's `D(d, Σ') ⊋ D(d, Σ)`. Two adjacent ✓-marked conclusions ("D unchanged" / "D changed") about the same pre-state cannot both stand. The defect is a silent promotion of a per-link observation (`ℓ` is already discoverable, so it adds nothing) into a global claim about `D(d)` and into the set-containment `Added ⊆ D(d, Σ)`, both of which fail once `ℓ'` is in scope.

Note this is a defect in the *example*, not in IP6 itself: the wp statement `wp(INSERT, D(d,Σ')=D(d,Σ)) ≡ INSERT-pre ∧ Added ⊆ D(d,Σ)` is correct, and its emptiness-vs-containment commentary is correct. The example simply illustrates it inconsistently.

**Required**: Either (a) present `ℓ` and `ℓ'` in **separate** scenarios, so that in the `ℓ`-only pre-state `Added = {ℓ} ⊆ D(d,Σ)` genuinely holds and `D(d)` is genuinely unchanged; or (b) rescope the IP6-trap prose to a statement about `ℓ` alone — e.g. "`ℓ ∈ Added ∩ D(d,Σ)`, so `ℓ` contributes no *new* discoverable link; `D(d)` changes only through `ℓ'` (below)" — and drop the false "`Added ⊆ D(d,Σ)` / leaves `D(d)` unchanged". The containment-over-emptiness point (that the emptiness form over-rejects pre-states where `Added` is non-empty but contained in `D`) is correctly witnessed by `ℓ`; it must not be phrased as "the containment form accepts / `D(d)` unchanged" for a scenario in which `ℓ'` makes the containment fail.
