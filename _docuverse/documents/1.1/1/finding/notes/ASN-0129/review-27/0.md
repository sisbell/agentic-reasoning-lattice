### Issue 1: PD0's aggregate clause contradicts itself on which class `count(D) ≤ c` inhabits
**ASN-0129, Predicate dynamics, PD0 (AuditMonotonicity), Aggregates bullet**: "Equality and wrong-polarity bounds are in *neither* class: `count(L_K) ≤ 3` is the canonical non-member of `ST` — true while the slice is small, flipped ⊤→⊥ for good by the fourth K-deposit; it lives in `SF`, where that flip is the licensed direction — and `count(D) = c` lives nowhere"
**Problem**: The headline asserts that wrong-polarity bounds are in *neither* class. This is contradicted twice within its own context: the rule one sentence earlier grants `count(D) ≤ c ∈ SF` outright, and the example's own continuation says `count(L_K) ≤ 3` "lives in `SF`". Only equality is in neither class; each inequality is in exactly one. In a section whose entire content is a membership classification — and which PD2 and Open Question 5 treat as the mechanical input to protocol checking — a reader applying the headline literally concludes `count(D) ≤ c ∉ SF` and loses the ⊥-stability the rule just granted. The intended meaning (an inequality read at the *wrong* polarity is not in *that* class) is recoverable only by discarding the sentence's literal claim.
**Required**: Split the classification so the headline matches the rules: equality is in neither class; each inequality bound belongs to exactly one class — `count(D) ≥ c` to `ST` only (its ⊤→⊥ flip is unlicensed there is false; its ⊥→⊤ flip is the licensed direction), `count(D) ≤ c` to `SF` only. Keep the `count(L_K) ≤ 3` example as the illustration of why the `ST` reading fails.
