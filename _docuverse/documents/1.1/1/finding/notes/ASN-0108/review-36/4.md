### Issue 5: Open Question 4 is substantially answered in the body
**ASN-0108, Open Questions**: "When the cursor link has been orphaned between calls, what must distinguish a genuinely empty successor set from an irrecoverable cursor, so that exhaustion and cursor-invalidation are not conflated?"
**Problem**: W8 and W9 already answer this: under a *computable* key (either permanent key supplies it) `κ(c)` survives orphaning, so an empty window certifies `After(next-cursor,Σ)=∅` (genuine exhaustion); only the content-position key makes the empty window "indistinguishable from cursor-invalidation." Listing the question as open, when the body resolves it by adopting a permanent key, is accretion (deferring forward something already settled).
**Required**: Remove OQ4, or sharpen it to state the genuine residue beyond "use a key whose value survives orphaning" (e.g., a guarantee independent of key choice, if one is intended).
