### Issue 1: V-ReachTight's "common depth" gloss contradicts its own iff
**ASN-0112, "The bounding span and its two endpoints" (V-ReachTight) and the Claims table**: "`reach(σ_d) = reach_d ⟺ #origin_d ≤ #reach_d` ... so the reach attains the constructed endpoint exactly when the occupied subspaces share a common depth" (table: "equivalently the reach is tight whenever the occupied subspaces share a common depth").

**Problem**: The iff `reach(σ_d) = reach_d ⟺ #origin_d ≤ #reach_d` is correct, but the "common depth" restatement is false as an equivalence. Take the cross-subspace case with content shallower than the maximal link, `m_C < m_L` — a state the note explicitly admits abstractly (V-LevelUniform: "strictly non-level-uniform only when `m_C < m_L`"; V2 covering case 1 handles `#origin_d ≤ #reach_d` with strict `<`). There `#origin_d = m_C < m_L = #reach_d`, so V2 case 1 / D1 closes the round-trip to `r⋆ = reach_d` — the reach **is** tight — yet `m_C ≠ m_L`, so the subspaces do **not** share a common depth. The precise condition `#origin_d ≤ #reach_d` is strictly weaker than `#origin_d = #reach_d` (common depth); the gloss conflates `≤` with `=`. The note even uses the correct condition `#origin_d ≤ #reach_d` in `wp(…, Tight)`, so this is an internal inconsistency between V-ReachTight's gloss and the wp derivation.

**Required**: Drop or correct the "common depth" restatement in both the prose and the table. The accurate gloss is: tight whenever the origin is no deeper than the reach (`m_C ≤ m_L` in the cross-subspace case, automatically satisfied single-subspace) — which includes the `m_C < m_L` case, not only `m_C = m_L`.
