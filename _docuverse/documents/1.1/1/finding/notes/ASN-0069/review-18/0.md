### Issue 1: Worked example's K.μ⁻ deletes a middle position
**ASN-0069, "Worked Example" section, "Subsequent edits" subsection**: "Suppose `d_src`'s owner later deletes `[s_C, 2]` from `d_src`'s arrangement (K.μ⁻ contraction). By V5a, `M(d_new)` is unaffected — `a₂` remains in `d_new`'s arrangement."

**Problem**: K.μ⁻ per ASN-0047 supports only per-subspace *suffix-prefix retention* — the caller selects a retention count `n'_S` and the contracted arrangement retains `{[S, 1, ..., 1, k] : 1 ≤ k ≤ n'_S}`. Removing `[s_C, 2]` alone while keeping `[s_C, 3]` is not expressible as a single K.μ⁻; the post-state would violate D-CTG★ (contiguity within the content subspace). The example's stated transition does not match the K.μ⁻ semantics it cites, which may mislead readers about what arrangement modifications the abstract spec actually admits.

**Required**: Either (a) revise to delete `[s_C, 3]` (a valid K.μ⁻ with `n'_{s_C} = 2`), (b) revise to delete `[s_C, 2]` *and* `[s_C, 3]` together (`n'_{s_C} = 1`), or (c) generalise to "contracts `d_src`'s arrangement via K.μ⁻" without naming a specific middle deletion. The abstract bidirectional-independence point (V5a, V12) holds under any valid transition; only the example needs adjusting.
