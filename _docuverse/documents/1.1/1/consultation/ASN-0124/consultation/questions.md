# Sub-Questions — FINDDOCSCONTAINING Operation

**Inquiry:** What happens when the system is asked which documents contain any portion of the material named by a vspec-set? What is returned and what reach must the search have — must it cross document boundaries to find documents that contain the material through transclusion regardless of where the native copies were authored, what relationship must each returned document bear to the queried vspec-set — full containment, partial overlap, or shared origin — and must the source document of the queried material itself appear in the result, what does asking by a vspec-set covering multiple non-contiguous regions reveal about content sharing across documents that asking about a single span would not, and what invariants must the operation maintain about completeness across the entire docuverse, soundness against ghost or deleted I-addresses, stability of the result under content edits in any document, and the cross-document reach of containment through chains of transclusion?

1. [theory] When the system is asked which documents contain any portion of a named set of content regions, what exactly must be returned — bare document identities, or identities paired with an indication of which queried material each document contains?
2. [theory] Must the search reach every document in the docuverse that holds the queried material through transclusion, regardless of where the material was originally authored or which document the asker started from?
3. [theory] What relationship must a returned document bear to the queried material — is partial overlap with even one fragment sufficient for inclusion, or must the document contain the queried regions in full?
4. [theory] Must the document in which the queried material natively originates itself appear in the result, or is the operation defined only over documents that share the material from elsewhere?
5. [theory] When the query names multiple non-contiguous regions of content, what does the result reveal about the pattern of sharing across documents that a query about a single contiguous span could not?
6. [theory] What completeness guarantee does the design make — is it an invariant that no document anywhere in the docuverse containing any queried portion may be silently omitted from the answer?
7. [theory] What soundness guarantee constrains the result — must every returned document verifiably contain the queried material at the moment of asking, with no document admitted on the basis of content it once held but has since deleted?
8. [theory] How must the result behave under editing — if material is removed from one document or new copies appear in another, which parts of the answer may change and which must remain stable?
9. [theory] When material is transcluded from one document into a second, and from the second into a third, must containment carry through the entire chain so that every document in the chain appears in the result?
10. [theory] Does containment rest on the permanent identity of the content itself rather than on resemblance — so that two documents holding coincidentally identical text are not reported as sharing, while documents holding the same identified material always are?
11. [evidence] When FINDDOCSCONTAINING returns its result, does each entry consist solely of a document address, or does it also report the specific I-address span (or V-span within the returned document) that overlaps the queried material?
12. [evidence] Is the spanfilade search in FINDDOCSCONTAINING genuinely global across all documents in the docuverse, or does the 2D index's document-origin dimension restrict the traversal to some subtree of the document address space?
13. [evidence] Does the document whose V-spans were named in the query vspec-set always appear in its own FINDDOCSCONTAINING result, given that INSERT created a DOCISPAN entry for it — and is there any path (e.g., content added via APPEND, whose `insertspanf` call is commented out) by which a document containing the material is silently absent?
14. [evidence] Is partial overlap sufficient for a document to be returned — that is, if a document's DOCISPAN entry shares even a single I-address position with the queried sporgl set, is it included, or must the document contain the full queried I-span?
15. [evidence] After DELETE removes a V-span from a document's POOM, the DOCISPAN entry persists in the write-only spanfilade — does FINDDOCSCONTAINING verify candidates against the current POOM (the way FOLLOWLINK filters during I→V conversion), or does it return ghost documents that no longer contain the material?
16. [evidence] When the queried vspec-set covers a single contiguous V-span that maps to non-contiguous I-addresses (e.g., due to a CREATELINK allocation gap), does `vspanset2sporglset` split it into multiple sporgls, and is the result the union of documents matching ANY fragment or only those matching ALL fragments?
17. [evidence] For a multi-span vspec-set covering regions in different documents, are the per-span results merged into a single deduplicated document set, or does the answer preserve which queried span each returned document overlaps?
18. [evidence] In a transclusion chain where doc A's content is copied to B and B's copy is copied to C, do A, B, and C all carry DOCISPAN entries pointing at the same I-addresses, so that querying A's span returns C directly without any iterative chain-following?
19. [evidence] Is the FINDDOCSCONTAINING result stable under INSERT in a returned document — since DOCISPAN entries are keyed by I-address rather than V-position, do V-shifts from edits in any document leave the membership of the result set unchanged?
20. [evidence] Does CREATENEWVERSION's copying of SPAN metadata create DOCISPAN entries for the new version document, so that querying the original's text immediately returns every version sharing those I-addresses — and conversely, does FINDDOCSCONTAINING require the returned documents (or the queried document) to be open under a BERT, or does the spanfilade search bypass `findorgl` entirely?
