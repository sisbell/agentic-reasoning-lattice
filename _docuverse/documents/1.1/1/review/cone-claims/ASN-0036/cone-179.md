### D-CTG's outer quantifier leaves `d` untyped, unlike its sibling posits
**Class**: REVISE
**Foundation**: T0 (CarrierSetDefinition, ASN-0034) — supplies `T`, the carrier `d` must range over for `Σ.M(d)` to be a defined object
**ASN**: D-CTG (VContiguity) Axiom: `(A d, u, q : u ∈ V_1(d) ∧ q ∈ V_1(d) ∧ u < q : (A v ∈ T : subspace(v) = 1 ∧ #v = #u ∧ zeros(v) = 0 ∧ u < v < q : v ∈ V_1(d)))`
**Issue**: The formal quantifier binds `d` with no type constraint at all — contrast S8a's `(A d ∈ T :: ...)`, AX-1's `(A d ∈ T :: ...)`, and S8-depth's `(A d ∈ T :: ...)`, all of which explicitly type `d`. D-CTG's own prose claims the opposite of what the notation says: "the outer universal binds `d` over the tumbler carrier `T`... admitting no `d ∉ T` for which `Σ.M(d)` would be undefined" — but the formal statement `(A d, u, q : ...)` admits exactly such `d`. Since `u ∈ V_1(d)` unfolds to `u ∈ dom(Σ.M(d)) ∧ subspace(u) = 1`, and `Σ.M(d)` is only defined for `d ∈ T` (per Σ.M(d)'s own declaration), the guard is ill-typed/undefined for `d ∉ T`. This is precisely the untyped-`d` defect that cone-178 flagged in D-CTG, AX-1, and S8a together (per the git history: "review(asn-36): cone-178 finds untyped `d` quantifier in D-CTG, AX-1, S8a"); only AX-1 received a dedicated fix commit, and S8a shows the fix in the current (uncommitted) working tree, but D-CTG's Axiom text still shows the original untyped form and D-CTG.md is absent from git status — the fix was never applied here.
