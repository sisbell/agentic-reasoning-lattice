### D-CTG-depth asserts an infinite witness sequence requiring dependent choice
**Class**: REVISE
**Foundation**: T0(a) (UnboundedComponentValues, ASN-0034)
**ASN**: D-CTG-depth body: *"continuing, we obtain a strictly increasing sequence n₁ < n₂ < n₃ < … of natural numbers, all exceeding uⱼ₊₁. The sequence is infinite and pairwise distinct … The sequence n₁ < n₂ < … being infinite has at least N + 1 terms, so we keep the first N + 1 witnesses."* The same claim appears in D-CTG-depth's Depends entry for T0(a): *"the extracted natural n = t′ⱼ₊₁ drives the strictly increasing sequence n₁ < n₂ < … of admissible intermediates that contradicts S8-fin."*
**Issue**: Building the infinite sequence n₁ < n₂ < n₃ < … requires ω-many applications of T0(a), each depending on the previous output — formally the Axiom of Dependent Choice (DC): from `(∀M ∈ ℕ)(∃n ∈ ℕ)(n > M)`, concluding `∃f : ℕ → ℕ` strictly increasing. DC is not among the foundations; NAT-wellorder (the least-element principle) does not imply it. The contradiction uses only N+1 witnesses for the specific N furnished by S8-fin for document d. Those N+1 values are constructible by exactly N+1 finite applications of T0(a) — apply it at M=uⱼ₊₁ to get n₁, at M=n₁ to get n₂, …, at M=n_N to get n_{N+1} — a finite iterated existential instantiation requiring no choice axiom. The "infinite" framing over-commits: it asserts the existence of an infinite object where the proof needs only a finite prefix of fixed length.
**What needs resolving**: Replace the infinite-sequence argument with a direct finite construction tied to the N from S8-fin. After instantiating S8-fin at d to obtain N, invoke T0(a) exactly N+1 times to produce n₁ < n₂ < … < n_{N+1}, all exceeding uⱼ₊₁. Remove the claim that the sequence is infinite; remove the "being infinite has at least N+1 terms" intermediary. The Depends entry for T0(a) should describe T0(a) as supplying N+1 witnesses by N+1 applications (not as "driving the strictly increasing sequence n₁ < n₂ < …").

### D-INJ above-k₀ surjectivity sub-case claims predecessor existence without grounding
**Class**: REVISE
**Foundation**: NAT-cancel (NatAdditionCancellation, ASN-0034); NAT-discrete (NatDiscreteness, ASN-0034)
**ASN**: D-INJ surjectivity proof, above-k₀ sub-case: *"The index i is the predecessor of j — the natural with i + 1 = j, which exists because j, lying strictly above k₀ ≥ 1, is a successor; this is the backward reading of the very successor step the renumbering already trades on when it ranges i + 1 over k₀ ≤ i ≤ P."*
**Issue**: The claim `∃i ∈ ℕ: i + 1 = j` is asserted and justified only by the informal observation that j > k₀ ≥ 1 makes j "a successor." Predecessor existence — `(∀j ∈ ℕ : j > 0 : (∃i ∈ ℕ :: i + 1 = j))` — is not among the listed foundations and is not derivable from NAT-carrier, NAT-order, NAT-wellorder, NAT-zero, NAT-closure, NAT-addcompat, NAT-cancel, or NAT-discrete alone. (NAT-wellorder gives a minimum of any non-empty subset, but applying it to `{i : i + 1 = j}` to get existence is circular — the set may be empty without predecessor existence.) The parenthetical appeal to "the backward reading of the successor step the renumbering already trades on" does not constitute a derivation: the forward map i ↦ i+1 is defined, but its pointwise inverse at j is not supplied by any listed axiom. The subsequent bounds derivation (k₀ ≤ i ≤ P from NAT-discrete and NAT-cancel, by rewriting j as i+1) is sound given i, but the existence is ungrounded. A formalization tool working from the listed foundations would need to discharge this gap.
**What needs resolving**: Add a predecessor lemma, either as a new named foundation item (`(∀j ∈ ℕ : j > 0 : (∃i ∈ ℕ :: i + 1 = j))`) grounded by the system's accepted induction-from-NAT-wellorder convention (induction at base j=1: take i=0, 0+1=1 by NAT-closure's left identity; at j=k+1: take i=k), and cite it in the above-k₀ sub-case; or reformulate the surjectivity argument to avoid needing predecessor (e.g., observe that the identity branch and successor branch of ρ together cover all of {1,…,P+1}\{k₀} via a combined cardinality argument once D-INJ's own result is available — though this must avoid circularity). The current "because j is a successor" phrasing is not a proof step and must be replaced with a grounded derivation.

VERDICT: REVISE
