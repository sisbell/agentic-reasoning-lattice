**Class**: REVISE
**Foundation**: S8-depth (FixedDepthVPositions); S8-fin (FiniteArrangement); AX-1 (InitialEmpty) — all three state their Axiom clauses in `(A ... :: ...)` bracket notation
**ASN**: D-MIN (VMinimumPosition), *Formal Contract* → *Design Requirement*: "For every reachable state Σ and each document d with V_1(d) ≠ ∅, min(V_1(d)) = [1, 1, ..., 1] — the length-m tuple (m the common V-position depth fixed by S8-depth) with every component 1; at depth 2, min(V_1(d)) = [1, 1]."
**Issue**: Every other Axiom/Design-Requirement clause in this ASN (S8-depth, S8-fin, AX-1, NAT-induction, and the foundation claims NAT-addcompat, T1, NAT-closure, NAT-zero, NAT-discrete, NAT-order, T0) states its content as an explicit bounded-quantifier formula — `(A d ∈ T :: ...)`, `(A d ∈ T :: (E n : n ∈ ℕ : ...))`, etc. D-MIN's Design Requirement is the one Axiom-level clause in the ASN given only as prose ("For every reachable state Σ and each document d with V_1(d) ≠ ∅, ..."), with no bracketed binder for `d`, no explicit guard notation for `V_1(d) ≠ ∅`, and no binder for `Σ` (consistent with the rest of the ASN, which leaves Σ ambient — not itself a new gap). Left as prose, the clause is ambiguous exactly where it most needs to be precise: whether it is `(A d ∈ T : V_1(d) ≠ ∅ :: min(V_1(d)) = [1,...,1])` or some weaker material-conditional reading, and how the length-`m` tuple constant is quantified relative to `d`. A formalization pass (Dafny or otherwise) has nothing to translate directly here, unlike every other Axiom in the document.
**What needs resolving**: State the Design Requirement in the same bracket-quantifier form used throughout the rest of the ASN — explicitly binding `d` over `T`, the guard `V_1(d) ≠ ∅`, and the equation `min(V_1(d)) = [1,1,...,1]` — consistent with how S8-depth and S8-fin bind `d ∈ T` and phrase their guarded conclusions.
