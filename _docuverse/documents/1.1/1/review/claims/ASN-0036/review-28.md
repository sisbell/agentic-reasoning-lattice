### S7d's "one document-allocator per (node, user)" is false for multi-component document fields
**Class**: REVISE
**Foundation**: T10a (AllocatorDiscipline), TA5(d), T10a.7 (EnumerationInjectivity); the conclusion is consumed by S7's Uniqueness step
**ASN**: S7d *Axiom*: "Documents sharing a node and user are realized, in allocation order, as the successive outputs of one document-allocator (a single node) — the first at its child-spawn base `inc(spawnPt, k')` with `k' ∈ {1, 2}` ... and each later co-user document at the next `inc(·, 0)` sibling-increment in that node's domain ... while documents under different users or nodes are realized in disjoint document-allocators." Proof headers: "*Co-user, co-node documents.* Let `d₁ ≠ d₂` be realized in a common document-allocator A" and "*Documents under different users or nodes.* ... events drawn from disjoint allocators `A₁ ≠ A₂` are distinct."
**Issue**: The axiom admits *every* document-level address `N.0.U.0.D` with `zeros = 2`, including a multi-component document field — e.g. a version/sub-document `N.0.U.0.5.3` (`D = [5, 3]`, still `zeros = 2`; Nelson's "the version, or subdocument number is only an accidental extension of the document number"). T10a allocates `N.0.U.0.5.3` by child-spawning `inc(N.0.U.0.5, 1)` from `N.0.U.0.5`, which is itself a *sibling output* of the per-(node, user) document-allocator `A = {N.0.U.0.k}`. So `N.0.U.0.5.3` lies in a *distinct child allocator* `V`, not as a sibling output of `A` — yet it shares node `N` and user `U` with `A`'s documents. The axiom's "documents sharing a node and user are the successive outputs of one document-allocator (a single node)" is therefore false in the very address space it admits, and structurally inconsistent with T10a's tree (deeper document fields are children, not siblings). The proof's case *conditions* ("common document-allocator A" vs "disjoint allocators `A₁ ≠ A₂`") are exhaustive over any pair and both are discharged, so the conclusion S7 actually consumes ("distinct documents arise from distinct allocation events") survives — a co-user version pair falls into the disjoint-allocator case. But the case *headers* mislabel it (a co-user/co-node version pair satisfies the "disjoint" condition despite the "co-user, co-node" header), and a downstream consumer treating the axiom's structural claim as ground truth would wrongly enumerate co-user documents as one allocator's sibling stream, missing version allocators. S7a carries the parallel over-claim: "the document's address ... being one output of the (per-user) document allocator in whose domain it lies" is wrong for a version document (whose address is an output of a version allocator, not the per-user document allocator) — though S7a's element-allocator *existential* survives regardless.
**What needs resolving**: Either (a) restrict the document-allocation model to single-component document fields, so co-(node, user) documents genuinely are one allocator's sibling stream and the headers match; or (b) recast the axiom to admit version/sub-document documents — child-spawned from a parent document's address into a distinct allocator — and key the injectivity case split on allocator-sameness (common allocator vs disjoint allocators), aligning the case headers with the conditions actually used. Apply the same correction to S7a's "(per-user) document allocator in whose domain it lies" gloss.
