# Review of ASN-0112

## REVISE

### Issue 1: V9's converse direction is false — composition changes need not move the extent
**ASN-0112, "The origin is permanent; the extent tracks quantity, not order"**: "changing how content is arranged leaves the extent unchanged, while changing how much content there is changes it"
**Problem**: Only the first half is proven, and only the first half is true. The second half — composition changes move the extent — is refuted by a counterexample constructible from the ASN's own worked example. Take `M(d) = {[1,1]↦a, [1,2]↦b, [1,3]↦a, [2,1]↦ℓ}` and apply a `K.μ⁻` with retention counts `n'_{s_C} = 2`, `n'_{s_L} = 1`. The content position `[1,3]` is removed — composition changes — but `min O(d) = [1,1]` and `max O(d) = [2,1]` are both untouched, so `origin_d`, `reach_d`, and `extent_d` are all identical before and after. The same holds for content *extension* into a both-subspace document: the new position `[1, n_C+1]` is still below the link maximum, so the span does not move. The ASN's own golden cases already display this: ten characters plus one link and three characters plus one link both report extent `[1,2]`. What the span actually tracks is the pair `(min O(d), max O(d))` — nothing else. The quantity-tracking direction holds only in the single-subspace regime (where any change to `n_s` moves `max O(d)` and hence the extent's final component). The section heading ("the extent tracks quantity, not order") and the claim's parenthetical name ("extent tracks composition, not arrangement") both encode the false direction.
**Required**: Restate the prose and the V9 gloss to claim only what is proven: the span is a function of the extremes of `O(d)`, hence invariant under rearrangement; composition changes move the span iff they move an extreme; in the single-subspace regime every composition change does so (final component of `extent_d` equals `n_s`), while in the cross-subspace regime content-side composition changes that keep `n'_C ≥ 1` leave the span fixed. The heading and claim name must be corrected to match.

### Issue 2: The V5/V6-dichotomy defense is stated three times
**ASN-0112, V6 paragraph and "Preconditions and well-definedness"**: V6's body argues "The bare strict inclusion `O(d) ⊊ ⟦σ_d⟧` follows as a corollary, but it cannot carry the dichotomy … `Exact` is depth-scoped and `⊊` is not; only the occupied-depth witness separates V6 from V5"; the claims table repeats "the genuine negation of V5"; and the wp(Exact) derivation repeats it a third time: "the depth-scoped `Exact` is refuted by the witness, which the corollary `O(d) ⊊ ⟦σ_d⟧` alone could not provide."
**Problem**: This is the same defensive point — evidently a prior finding's resolution — restated in three locations. The wp derivation needs only one fact: V6 supplies an occupied-depth witness `w⋆ ∈ ⟦σ_d⟧ \ O(d)`, hence `¬Exact`. The trailing relative clause re-litigates a formulation choice already settled at V6 and advances nothing in the backward reasoning. The "genuine negation" qualifier in the recording line and table is the same defense compressed. This is exactly the accretion pattern flagged for this note: duplicate paragraphs saying the same thing in different words.
**Required**: State the dichotomy defense once, in the V6 paragraph where the `origin_d.0` argument lives. Delete the "which the corollary … alone could not provide" clause from the wp derivation and drop the "genuine" qualifier from the recording line and table row.

### Issue 3: V2 case 2 attributes a TumblerSub + TumblerAdd composite to TumblerAdd alone
**ASN-0112, "The span covers every occupied position", second case**: "With `k = 1`, TumblerAdd gives `r⋆` agreeing with `reach_d` (zero-padded to length `#origin_d`) on every position `1 ≤ i ≤ #reach_d` and carrying trailing zeros beyond"
**Problem**: The agreement at position 1 is not a TumblerAdd fact. It requires TumblerSub's action-point component (`extent_d₁ = reach_d₁ − origin_d₁` at `zpd = 1`) followed by ℕ cancellation (`r⋆₁ = origin_d₁ + extent_d₁ = reach_d₁`); the agreement at positions `i > 1` requires TumblerSub's tail copy (`extent_dᵢ = reach_dᵢ` zero-padded) before TumblerAdd's tail copy can deliver `r⋆ᵢ = extent_dᵢ`; and the length `#r⋆ = #origin_d` routes through TA2's `#extent_d = max(#origin_d, #reach_d)`. The sentence compresses a multi-step, two-operation derivation into "TumblerAdd gives," and TumblerSub is never cited at this step. The depth-divergent variant at the end shows one concrete instance but does not substitute for the general component computation.
**Required**: Display `extent_d`'s components from TumblerSub at `zpd = 1`, then compute `r⋆` componentwise from TumblerAdd at `k = 1`, with the position-1 cancellation made explicit, before concluding `reach_d ≺ r⋆` via T1 case (ii).

### Issue 4: V12's count-recovery chain stops one step short of the returned value
**ASN-0112, "What the caller learns beyond the name"**: "its span `σ_d` fixes the occupied count exactly: `|O(d)| = n_s` is the final component of `max O(d)`, recoverable from `reach_d` (V5, D-SEQ★)"
**Problem**: The caller holds `σ_d = (origin_d, extent_d)`, not `reach_d`. The bridge from the returned value to `reach_d` is `reach(σ_d) = origin_d ⊕ extent_d = reach_d`, which holds in this regime by V-ReachTight (single-subspace endpoints are equidepth) — but V-ReachTight is not cited, so the information-gain claim, which is precisely about what the *returned value* determines, leaves its last link implicit. There is also a shorter route the ASN never states: in the single-subspace regime TumblerSub at `zpd = m_s` gives `extent_d = [0,…,0,n_s]`, so `n_s` is directly the final component of the returned width (visible in the worked example's "0.3" but nowhere recorded as the general identity).
**Required**: Complete the chain — either cite V-ReachTight to license computing `reach_d` from `σ_d`, or state the identity `n_s = ` final component of `extent_d` and recover the count from the width directly.
