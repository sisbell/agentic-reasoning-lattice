# Review of ASN-0108

The windowing machinery here is rigorously built — I checked the W2 weakest-precondition derivation (`wp(resume_offset, R) ≡ j'=j ∨ (j≥m' ∧ j'≥m')` is correct, and the three-way nesting membership-identity ⟹ frozen-prefix ⟹ wp holds), the W4 partition induction, the W8/W9 computability split, and the W9b multiplicity-bound and W9c necessity walk. All survive scrutiny. The findings below are clarity, an overstated exhaustiveness claim, and accreted meta-prose flagged under the anti-bloat classifier.

## REVISE

### Issue 1: "matched-content key" and "content-position key" conflated in W6
**ASN-0108, "What κ is" intro vs W6 (body and claims table)**: The taxonomy is introduced as three *coordinate, distinctly-named* candidates — "We call this the **matched-content key**" (Gregory's, permanent least I-address) and "The third candidate is **mutable**: the **content-position key**, keyed on the matched content's *current V-position*." But W6 then writes: "The consequence under *either* matched-content key — Gregory's I-address key as much as the V-position foil — is the *blind spot*," and the claims table: "a matched-content key (least covered I-address, or V-position) is not allocation-monotone."
**Problem**: W6 stretches "matched-content key" to subsume the *content-position key*, which the intro defined as a separate, third, mutable candidate. This collides with the note's central three-key distinction exactly where W6 is asserting that "the two *permanent* keys part" — the content-position key is *not* one of the two permanent keys, yet W6 files it under "matched-content key." A reader tracking the flat three-name taxonomy must silently re-interpret it as a family. W6a, by contrast, uses the umbrella "matched-content boundary" while keeping "matched-content I-address key" and "content-position key" distinct — so the note is inconsistent with itself.
**Required**: Pick one scheme. Either establish "matched-content key" up front as a *family* with two variants (permanent I-address; mutable V-position = content-position) and state it once, or keep the three flat names and have W6 say "either content-drawn key (matched-content I-address or content-position)" rather than "either matched-content key."

### Issue 2: "sole abstract respect in which the two identity keys differ" overstates, and is duplicated
**ASN-0108, W6 body and claims table**: "Allocation-monotonicity is therefore the **sole** abstract respect in which the two identity keys differ"; table: "for the matched-content key this is the **sole** abstract respect in which it differs from the link-address key (the comparison's home)."
**Problem**: (a) The note's own composite-key caution contradicts "sole": "the bare content key is **not injective on `Match`** ... it must be composed with a permanent tiebreaker — `κ(a) = (endpoint-boundary, a)`." The address key satisfies W0/W1 unaided; the matched-content key requires an appended address tiebreaker to order `Match` at all. That augmentation requirement is a *second* abstract respect in which the two keys differ, so "sole" is overstated. (b) The exhaustiveness claim is stated in the body and re-stated in the table — duplication. (c) The table parenthetical "(the comparison's home)" is meta-commentary about argument location occupying a structural slot.
**Required**: Either narrow the claim (e.g., "their only *behavioral* divergence on W5/W8/W6 is allocation-monotonicity; the matched-content key additionally requires the address tiebreaker to satisfy W0/W1") or reconcile it explicitly with the tiebreaker requirement. State it once; drop "(the comparison's home)" from the table.

### Issue 3: accreted "allocation is orthogonal" defensive prose (W5/W8)
**ASN-0108, W5**: "and the reason is definitional, not an allocation consequence ... Allocation axioms enter only orthogonally — that the cursor `c` stays an allocated, uniquely-identifying address is T8 ... with LP13 ... and that no distinct allocation event ever reproduces `c`'s address is GlobalUniqueness — but none of these is what freezes the key; the freezing is the state-independence of `κ` itself." **W8**: "Allocation enters only *orthogonally* here, exactly as set out under W5," plus walk parentheticals "(... an orthogonal fact the resume step never consults)" and "with no appeal to membership or to `a_2`'s persistence as an allocated entity."
**Problem**: The W5 passage spends most of its words *rebutting an allocation-based explanation* of key-freezing rather than advancing the positive fact (one sentence: κ is a state-independent function of the held value, hence frozen and computable by construction). This is defensive justification — the anti-bloat pattern — and reads as a relocated response to a prior conflation finding. W8 then back-defers to it ("exactly as set out under W5") and repeats the orthogonality point a third and fourth time. The W8 *computability-vs-value-totality-vs-allocation* distinction is load-bearing and should stay; the repeated rebuttal of the allocation explanation is what should be trimmed.
**Required**: State the positive fact once (address key = state-independent function of the held value ⟹ frozen comparisons and held-value computability). Remove the W5 rebuttal-of-allocation passage and the W8 backward deferral/restatement; keep only W8's substantive computability-vs-value-totality point.

### Issue 4: "No per-cursor local condition characterizes coherence" asserted beyond its support
**ASN-0108, W5**: "No per-cursor local condition characterizes coherence; only the whole-pass property does, since clause-1 failures at different cursors can offset one another."
**Problem**: The "since" clause (the cancellation walk) establishes that clause 1 *specifically* is not necessary — failures cancel. It does not establish the universal negative that *no* per-cursor local condition is necessary-and-sufficient. The stronger claim is asserted, not derived (standard 6). The load-bearing content — clause 1 is sufficient but not necessary — is fully supported; the universal "no local condition characterizes" is not.
**Required**: Either supply the meta-argument (any predicate evaluated independently per transition cannot witness cross-cursor cancellation, so coherence — a whole-pass outcome — is not characterizable per-cursor) or soften to "clause 1, the natural per-cursor condition, is not necessary; coherence is a whole-pass property, as the cancellation walk shows."

### Issue 5: Open Question 4 is substantially answered in the body
**ASN-0108, Open Questions**: "When the cursor link has been orphaned between calls, what must distinguish a genuinely empty successor set from an irrecoverable cursor, so that exhaustion and cursor-invalidation are not conflated?"
**Problem**: W8 and W9 already answer this: under a *computable* key (either permanent key supplies it) `κ(c)` survives orphaning, so an empty window certifies `After(next-cursor,Σ)=∅` (genuine exhaustion); only the content-position key makes the empty window "indistinguishable from cursor-invalidation." Listing the question as open, when the body resolves it by adopting a permanent key, is accretion (deferring forward something already settled).
**Required**: Remove OQ4, or sharpen it to state the genuine residue beyond "use a key whose value survives orphaning" (e.g., a guarantee independent of key choice, if one is intended).

## OUT_OF_SCOPE

None. The note correctly imports the satisfaction predicate from ASN-0127 (`findlinks_V`, F-V/F-FULL) rather than re-deriving it, stays within windowed delivery, and defers count-only retrieval, full-set retrieval, MAKELINK, FOLLOWLINK, and BEBE. The genuinely-open multi-document ordering (OQ1) and non-allocation-monotone eventual delivery (OQ2) are appropriately left to future work.
