# Review of ASN-0071

## REVISE

### Issue 1: Symbol `v_A` overloaded in worked example

**ASN-0071, "A worked scenario"**: Step 2 introduces `v_A` as a content value — "`Σ.C(a₁) = v_A` for some value `v_A`" — while step 3 reuses the same symbol for the V-position — "`v_A = [s_C, 1]` is the minimum content-subspace V-position". The state summary then carries both senses in adjacent clauses: "`Σ.C ⊇ {a₁ ↦ v_A}`,   `Σ.M(d_A) = {v_A ↦ a₁}`".

**Problem**: The content value lives in `Val`; the V-position lives in `T`. These are distinct mathematical objects under one symbol. The summary line places both senses in the same paragraph, with `v_A` appearing on both sides of `↦` with different types. The reader must disambiguate by context on each occurrence, which obscures an example whose entire purpose is to show the operation working step-by-step on concrete data.

**Required**: Rename the content value (e.g., `val_A`, or even just `c_A`), keeping `v_A` for the V-position. Apply consistently to step 2, the state summary, and any later mention. Do the same for any analogous reuse if `v_B`-as-value were to appear (it does not, but worth checking under the rename).

### Issue 2: "By trichotomy" — which trichotomy?

**ASN-0071, "Resolution" — subspace confinement argument**: "So `t₁ = u₁ = s_C` by trichotomy, hence `subspace(t) = s_C`."

**Problem**: The argument has just eliminated `t₁ < u₁` and `t₁ > u₁` for natural numbers `t₁, u₁ ∈ ℕ` (T0). The conclusion `t₁ = u₁` follows from trichotomy of `<` on ℕ — NAT-order's axiom `(A m, n ∈ ℕ :: exactly one of m < n, m = n, n < m)`. The ASN, however, has spent the surrounding sentences invoking T1 case (i) (trichotomy on tumblers). Saying "by trichotomy" without naming the carrier leaves the reader to guess whether the appeal is to T1 trichotomy on tumblers (irrelevant here — both `t₁` and `u₁` are components, not tumblers) or NAT-order trichotomy on ℕ (the correct one).

**Required**: State explicitly: "by NAT-order trichotomy on ℕ applied to the components `t₁` and `u₁`" (or equivalent). The remainder of the proof is careful about citing T1 case (i) at specific positions; the final step deserves the same precision.

### Issue 3: `iaddrs` codomain notation hides state dependence

**ASN-0071, Claims table**: "`iaddrs : VSpecSet × Σ → P(dom(C))`"

**Problem**: `dom(C)` is state-dependent — it is `dom(Σ.C)`, which changes with the second input. The signature as written suggests `dom(C)` is a fixed set independent of `Σ`. The prose around the table is careful (it writes `Σ.M(d_s)` and `dom(Σ.M(d_s))`), so the relaxation in the table is jarring. A reader checking the claim from the table alone would not know whether the codomain is meant to be `dom(Σ.C)` (the input state) or `dom(Σ'.C)` for some related state.

**Required**: Write the codomain as a per-input subset claim. For instance: "`iaddrs(Q)(Σ) ⊆ dom(Σ.C)` for every `Q` and `Σ`" — or include the basis cell's parenthetical clarification that the codomain is read with Σ implicit. The other state-dependent operators (`Σ.M`, `Σ.E_doc`) are written with explicit `Σ`-projection; `Σ.C` should be too.

### Issue 4: F-FIN's appeal to "the sequential-transition discipline" is too loose

**ASN-0071, "Finiteness" — step (c)**: "A reachable state is reached by finitely many transitions. By the sequential-transition discipline (SequentialTransitionAxiom, ASN-0047), the state space is generated by finite sequences `Σ₀ → Σ₁ → ... → Σ_n` of atomic transitions; the count `n` is a finite natural number for any reachable `Σ`."

**Problem**: SequentialTransitionAxiom only says transitions are atomic, uninterruptible, and totally ordered. It does not, on its own, say that reachable states have finite ancestry — that property comes from defining "reachable" as "reached by a finite sequence of valid composite transitions" (which is how ASN-0047's ExtendedReachableStateInvariants theorem characterises it, and is the implicit reachability semantics throughout). The citation as written attributes the finite-ancestry property to a different axiom than the one that actually provides it.

**Required**: Either cite ExtendedReachableStateInvariants directly (it begins "Every state reachable from Σ₀ by a finite sequence of valid composite transitions ..."), or note that "reachable" is taken to mean "reached by a finite sequence", with SequentialTransitionAxiom supplying only the atomicity that makes individual transitions countable.

## OUT_OF_SCOPE

### Topic 1: Resolution equivalence to ASN-0058's `resolve` is asserted but not proved

The ASN states in prose: "when a vspec `(d_s, σ)` is also a well-formed ContentReference, `iaddrs_one(d_s, σ)(Σ)` equals the set-flattening of `resolve(d_s, σ)` — concretely, `{ a + k : (a, n) ∈ resolve(d_s, σ) ∧ 0 ≤ k < n }`."

**Why out of scope**: The relationship is not load-bearing for any F-claim — it is an explanatory bridge to a prior ASN. Proving it formally is a worthwhile follow-up (it ties the relaxed vspec definition to ContentReference's stricter well-formedness), but the present ASN's claims stand without it. A future ASN on resolution equivalence — or a small lemma appendix here — would be the natural home.

VERDICT: REVISE
