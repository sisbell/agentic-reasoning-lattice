# Review of ASN-0040

## REVISE

### Issue 1: State space and transition system never formally defined

**ASN-0040, throughout**: References to "states Σ, Σ'", "transitions Σ → Σ'", "reachable from Σ", and "transition sequence" pervade the ASN. B0's axiom quantifies "(A Σ, Σ' : Σ → Σ' : Σ.B ⊆ Σ'.B)". B1, B10, and B8 proofs induct on transition sequences.

**Problem**: What is a state? What constitutes an admissible transition? What does "reachable" mean? AllocatedSet (foundation) defines `𝒮` as the state space, `Σ` as the transition vocabulary, `s → s'` as `(s, op(s))` for `op ∈ Σ`. ASN-0040 introduces Σ.B as "a state component" without ever defining the state space Σ or the transition relation. The Σ.B justification claims "the type invariant is preserved across all transitions" without specifying what the transition relation is — meaning every preservation proof induces over an undefined object.

**Required**: At the ASN's start, define the state Σ as a tuple containing Σ.B (and noting future components may be added). Define the transition relation as generated by the operations specified here (currently Bop only). Define reachability from B₀ as the reflexive-transitive closure. Without this framework, every "transition sequence" induction is hand-wavy — one cannot induct over an unspecified set.

### Issue 2: B4 uses undefined temporal vocabulary

**ASN-0040, B4 (Namespace Serialization)**: "`(A β₁, β₂ : ns(β₁) = ns(β₂) : commit(β₁) ≺ read(β₂) ∨ commit(β₂) ≺ read(β₁))` where ≺ denotes temporal precedence."

**Problem**: `≺`, `commit(β)`, `read(β)`, and the notion of a "baptismal act β" are introduced informally and never grounded. B4 is a precondition for every Bop, a key step in the freshness argument ("B4 ensures the state observation is current"), a load-bearing premise in B1 preservation ("By B4, this baptism observes the complete state left by any prior same-namespace baptism — no interleaving has occurred"), and central to B8's same-namespace case. Without formal grounding for the event model, the wp analysis "B4 ensures the state observation is current" is unverifiable.

**Required**: Either (a) define the event model precisely — what is a baptismal act, what are commit and read events, what is the precedence relation — or (b) recast B4 as a transition-level constraint (e.g., "Bop is treated as an atomic state transition; B4 is the assertion that two same-namespace Bop transitions are linearly ordered in any execution"). The latter would let B4 fit cleanly into the transition framework requested in Issue 1.

### Issue 3: B0a "produced by baptism" predicate informally defined

**ASN-0040, B0a (Baptismal Closure)**: "`(A t : t ∈ Σ'.B \ Σ.B : t was produced by baptism(p, d) for some (p, d) satisfying B6)`".

**Problem**: The predicate "t was produced by baptism(p, d)" is not formally defined. It refers to provenance — which operation produced an element — but the state Σ does not track provenance, so this predicate has no state-level interpretation. In a closed transition system where Bop is the only operation that modifies Σ.B, B0a is automatic; if the system admits other operations, B0a constrains them. The ASN doesn't make this distinction.

**Required**: Recast B0a as a constraint on the operation vocabulary: "The only state transition that increases Σ.B is Bop, and Bop's preconditions require B6(p, d)." This converts a meta-level predicate into an operation-set axiom that future ASNs can verify when adding operations. Or define provenance explicitly as a state component.

### Issue 4: B3 "occupied" predicate undefined; forbidden case is a forward requirement, not current invariant

**ASN-0040, B3 (Ghost Validity)**: The trivalent table uses "t occupied" as a dimension; the case "t ∉ Σ.B ∧ t occupied" is marked **forbidden**.

**Problem**: The predicate "occupied" is never defined here — content storage is correctly noted as out of scope. But B3 is presented as if it states a current system invariant, when in fact the forbidden case is a precondition that future content operations must enforce. The narrative ("The fourth case is a *requirement on content operations*") admits this, but B3's table presents all four cases as if they have current truth values.

**Required**: Either (a) reframe B3 as a forward requirement on future ASNs ("any operation that populates a position must take t ∈ Σ.B as a precondition") without the trivalent table, or (b) parameterize the table over a future predicate `Occupied(t, σ_content)` with explicit notation that this predicate is defined elsewhere.

### Issue 5: T5 cited under non-canonical name

**ASN-0040, "The sibling stream"**: "lies within the set {t ∈ T : p ≼ t}, which forms a contiguous interval under T1 by T5 (PrefixContiguity)."

**Problem**: The foundation lists T5 as `ContiguousSubtrees`. The ASN cites it as `PrefixContiguity`. This is a naming inconsistency with the foundation registry.

**Required**: Use the canonical name `T5 (ContiguousSubtrees)` per the foundation, or — if `PrefixContiguity` is intended as a clearer alias — note this explicitly at first use.

### Issue 6: Relationship between Σ.B and ASN-0034's `allocated(s)` not specified

**ASN-0040, Bop and B0 narrative**: "B0 is the state-level reading of T8 (AllocationPermanence)." T8 is stated in terms of `allocated(s)` from AllocatedSet.

**Problem**: AllocatedSet defines `allocated(s) = ⋃ { domₛ(A) : activated(A, s) }`. ASN-0040 introduces Σ.B as "the set of baptized tumblers". The conceptual relationship — are they the same set viewed from different angles, or genuinely distinct components? — is left implicit. If Σ.B = allocated(s) under a suitable identification of namespaces (p, d) with allocators, then B0 should be derivable from T8 rather than stipulated. If they're distinct, the distinction needs articulation.

**Required**: State the relationship explicitly. If Σ.B = allocated(s), justify B0 as a corollary of T8 (and explain what additional content B0 carries — perhaps that B0 quantifies over all transitions in the registry framework, while T8 is stated for the algebraic transition vocabulary). If Σ.B ≠ allocated(s), explain what each captures and why both are needed.
