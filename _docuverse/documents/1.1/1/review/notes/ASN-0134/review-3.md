# Review of ASN-0134

The per-home conflict theory (H0–H2, G1) is the spine of this note and it is sound: H0's framing lemma is proved by the right case split, G1's confluence-by-adjacent-transposition argument is correct, and the §4 step-vs-operation seam (raw-`K.λ_sh` confluence vs. operation-level idem non-confluence) is handled with unusual honesty. The two issues below are not in that machinery. They are both in the *reader-side* half of the contract, which the note specifies far more loosely than the writer-side half: it nails down writer exclusion (per-home serialization, run critical sections) but leaves reader atomicity (composing a multi-type verdict; a reader's view of a partial batch) asserted rather than established.

## REVISE

### Issue 1: A multi-type quiescence verdict is not realizable as "one atomic snapshot Observe"

**ASN-0134, §8 / V0 / MIC clause 4**: V0 reads "A verdict obtained by a single Observe is `Q(Σ_r)` for one index `r` ... it is a sound statement about the one state `Σ_r`." §8's soundness condition is "all of the verdict's reads must occur at one index, i.e. the verdict must be one atomic snapshot Observe." MIC clause 4 promises "Each Observe — including each quiescence verdict — is evaluated against a single committed state."

**Problem**: The note's own A1 says "an Observe ... is realized as zero steps; it reads a state and returns" — one read, one index. The inherited operation surface supplies only the *per-type* `Observe_K` (ASN-0086, ASN-0128 D1–D4/BH1–BH4): each call reads one type's active view at its own read index. A quiescence predicate over more than one type or home (the realistic case — `targets_keyed` already joins across Binary types) is therefore *several* zero-step reads at *several* indices. V0's soundness premise ("all reads at one index") is then exactly what is not delivered: by A1, the constituent reads land at distinct indices, and §8's own counterexample ("quantified over a collection of states that never coexisted") applies to the verdict's own evaluation.

MIC clause 4 does not close this. Read against the per-type surface, "each Observe ... against a single committed state" is the *per-call* guarantee A3 already gives for free (every `Observe_K` is a function of its own `Σ_k`); it does not force two `Observe_K` reads of *one verdict* to share an index. The genuine requirement — pin all of a verdict's per-type reads to one committed index — is a *reader-side* atomicity obligation, distinct in kind from clause 2's *writer-side* per-home serialization, and it appears nowhere: no whole-state `Observe` primitive is provided, no composition lemma is proved, no clause imposes it. So V0/M1(a) establish snapshot soundness only for the single-`Observe_K` (single-type) verdict; the multi-type verdict — the one a real quiescence recognizer needs — is asserted ("must be one atomic snapshot Observe") without being shown realizable from the surface the note depends on. This is the §8 headline ("the snapshot is the only honest referent for a verdict"), so the gap sits in the note's core, not in deferred territory.

**Required**: Either (a) add a MIC clause requiring all per-type reads composing one verdict to be evaluated against a single committed index — a reader-side snapshot obligation stated as carefully as clause 2 states writer serialization — and connect it to the inherited `Observe_K` surface; or (b) establish that such a composition is constructible from the surface (e.g., that a reader can pin all sub-reads to one `Σ_r`); or (c) restrict V0's soundness claim to predicates evaluable by a *single* `Observe_K`, and state explicitly that multi-type verdicts require the added reader-snapshot contract. As written, the §4 step/operation seam is mirrored by an unaddressed per-call-read / per-verdict-snapshot seam.

### Issue 2: §1 equates batch *contiguity* with batch *atomicity*; this is false and contradicts the note's own Open Question

**ASN-0134, §1**: "Batch atomicity, where a layer needs it, is something the layer must construct — by making the batch contiguous, which is a critical section, which is a discipline the substrate neither provides nor forbids."

**Problem**: Making a batch contiguous is, by the note's own W4, a *writer-side* exclusion: a run "occupies a contiguous block of `A_{s_C}(d)` iff no foreign allocation into `(d, s_C)` is interleaved between the run's first and last step." That prevents foreign *steps* from wedging in. It does nothing about *readers*. A reader can `Observe` at any index (A0/A3), including an interior index of a perfectly contiguous run; at `Σ_{i₁+2}` of a 3-atom contiguous run it sees a two-atom prefix. Every `m ≥ 2` batch — contiguous or split — has observable partial states. Contiguity ≠ atomicity; a critical section on `(d, s_C)` (W4) excludes writers, not readers, so it cannot deliver all-or-nothing reader visibility.

This is not a stray imprecision: it contradicts the note's own Open Question, which treats the *same* example — "a definition's content run seen whole" — as needing "the minimal additional contract that makes a multi-step batch appear atomic," i.e. as **unsolved beyond W4**. §1 says W4-style contiguity *constructs* the atomicity; the Open Question says the run's atomicity needs a further contract W4 does not supply. Both sentences are about the content run. They cannot both be right. (§6 is on the correct side — it says the corpus needs "batch *contiguity*," carefully avoiding "atomicity" — which isolates the error to §1.) A5 compounds the confusion by tying partial-effect visibility to *splitting* ("If a batch is split, then ... an Observe ... witnesses a strict, non-empty subset"), which leaves the false impression that a *non-split* (contiguous) batch is not partially observable.

**Required**: Correct §1 to state that a critical section yields *contiguity* (no foreign step interleaves the run), not *atomicity* (no reader observes a partial run); atomicity is strictly stronger and is — correctly — deferred to Open Question 3. The deferral itself is fine; only the §1 claim that contiguity already constructs atomicity must go. While there, sharpen A5: partial-batch visibility holds for *any* multi-step batch independent of splitting (an `Observe` at any interior index suffices); splitting *additionally* interleaves foreign effects.
