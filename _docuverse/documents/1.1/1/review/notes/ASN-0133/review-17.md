# Review of ASN-0133

This is an unusually careful note. The termination machinery — H-RF as the operative hypothesis with H-W demoted to a *foil*, the open/closed split, Q5a's domain-growth route, Q6's three obstruction cases, the H-SFAIR satisfiability caveat — I checked the load-bearing proofs (Q-EXT, Q5, Q5a, Q6 regimes (i)/(ii), the case-(3) cycling counterexample, the worked Σ₀→Σ₂ trace) and they hold. One genuine gap remains, in the pillar the note advertises as *unconditional*.

## REVISE

### Issue 1: Q0's exhaustiveness argument omits the collection behavior atoms, so the "for every registry" claim is unproven for the general heterogeneous-view case

**ASN-0133, Q0 (Recognizability)**: "PC3 names *exactly four* view-parameterized constituents — `members`, `targets_of`, `is_K`, `M_K` — and each rebuilds as above; everything else a Boolean trigger or a QD domain can read (the verdict/Boolean atoms `is_in_chain`, `tip`, `age`, `targets_keyed`, and the fixed-view slices `A_K`/`L_K` themselves) is never UV-rewritten and already reads one fixed slice." And the backstop: "A genuinely non-unifiable trigger would require a view-parameterized read with *no* fixed-view-base rewrite; the vocabulary of ASN-0129 has none — the four atoms above exhaust the view-parameterized forms, and each rebuilds."

**Problem**: The case analysis is non-exhaustive, and the quoted universal is false. ASN-0129's UV lists *six* collection atoms rewritten under the default view — "`members`, `targets_of`, `succs`, `sources_to`, the sequence `chain` returns, and `stale`." The latter four (`succs`, `sources_to`, `chain`, `stale`, the BH2/BH3/BH4 collection atoms) are *fixed-view* in PC3's sense — they read the active slice — yet under `v = default` their *results* are filtered, so their default-view value differs from their active value. A Boolean trigger reading `succs(x) = ∅`, `t ∈ elems(chain(x))`, or `t ∈ sources_to(x)` *at the default view* therefore does **not** "already read one fixed slice" in the value sense the merge needs; it needs the same rebuild the four view-parameterized atoms get. The note's dichotomy conflates "not view-parameterized" with "never UV-rewritten," and these four atoms are the counterexample — they fall through both branches (not in the four, not in the verdict/Boolean/slice list). The robustness backstop inherits the error: "the four atoms exhaust the view-parameterized forms" is true but insufficient, because view-unification must also discharge the default-view collection behavior atoms.

This is not fatal to the conclusion — those atoms *do* rebuild — but the proof as written does not show it, and one of them is subtle. The `chain` case in particular: there is no PL former that filters a `Seq_fin(T)` to a `Seq_fin(T)`, so the rebuild has to route through `elems(chain)` (a filterable `℘_fin(T)` by QD's set-valued closure) or through the non-rewritten `is_in_chain`; the note addresses neither.

**Required**: Extend Q0's exhaustiveness to `succs`/`sources_to`/`chain`/`stale` at the default view, showing each rebuilds over the active fixed-view bases — for the set-valued ones as `{x ∈ ⟨active reading⟩ : ¬(∃ J ∈ Φ :: is_filtered_J(x))}`, and for `chain` via `elems(chain)` (or `is_in_chain`, which UV does not rewrite). Correct the false universal ("everything else … is never UV-rewritten"). With this, `quiescent_R ∈ PL` for every registry stands; without it the unconditional recognizability claim is established only for registries whose triggers and domains avoid these atoms at the default view. Q7 (scope quiescence "carries Q0's status exactly") and Q9 inherit the same gap, since a scoping body `β_ρ^S` may read these atoms — note that the same fix covers them.
