# Review of ASN-0043

## REVISE

### Issue 1: L8 prose says "addresses" but formal definition uses spans
**ASN-0043, L8 (TypeByAddress)**: "Whether two links share the same type is determined by whether their type endsets reference the same addresses, not by what is stored at those addresses: `same_type(a₁, a₂) ⟺ Σ.L(a₁).type = Σ.L(a₂).type`"
**Problem**: The prose "reference the same addresses" naturally reads as coverage equality, but the formal definition is endset (span-set) equality under L5. The ASN itself notes that "coverage is a lossy projection: two endsets with different span decompositions may have identical coverage." Under the formalization, `{(g, δ(1, #g))}` and an endset that covers the same addresses via a different decomposition are *not* the same type — even though they "reference the same addresses." Nelson's "merely considers the type's address" gives no guidance between the two readings. A reader applying L8 to determine type equivalence cannot tell which notion is binding.
**Required**: Either (a) tighten the prose: "two type endsets are the same iff they are equal as sets of spans (different decompositions, even with identical coverage, are distinct types)"; or (b) generalize the formal definition: `same_type(a₁, a₂) ⟺ coverage(Σ.L(a₁).type) = coverage(Σ.L(a₂).type)`. State which design choice is intended and why.

### Issue 2: L9 witness `d'` is not anchored to a T10a allocation event
**ASN-0043, L9 proof, "Construction of `d'`"**: "Build the tumbler `d' = 1.0.1.0.1` from carrier axioms: by T0(b), tumblers of length ≥ 5 exist; the literal sequence `[1, 0, 1, 0, 1]` is in `T`. T4-validity holds: ... So `d'` is a T4-valid document-level tumbler. ... otherwise extend the arrangement store with the fresh entry `d' ↦ ∅` (a freshly allocated document with empty initial arrangement)."
**Problem**: S7d (DocumentAllocationDiscipline, ASN-0036) requires every `d ∈ dom(Σ.M)` to be the result of a T10a allocation event under the system's allocator tree 𝒯. The proof builds `d'` from T0(b) (carrier existence) and inserts it into `dom(Σ'.M)` without exhibiting a T10a-conforming allocator chain producing `d'`. T4-validity is necessary but not sufficient — S7d demands a specific allocation history, not just structural well-formedness. The phrase "freshly allocated document" presupposes an allocation event that the proof never constructs.
**Required**: Either (a) exhibit an explicit T10a allocator chain from the system root to `d'` (e.g., root `1` → `inc(1, 2) = 1.0.1` → `inc(1.0.1, 2) = 1.0.1.0.1`), discharging TA5a at each `k' > 0` step; or (b) parametrize the proof to pick an existing `d ∈ dom(Σ.M)` from `Σ` (well-defined since the operations layer is OUT OF SCOPE here and any conforming `Σ` must contain at least one such `d` for the L9 construction to be meaningful — or note explicitly that L9 fails vacuously when no documents exist).

### Issue 3: L0 cites a chain that does not establish T4-validity for content addresses
**ASN-0043, L0 (SubspacePartition) proof**: "T4-validity is discharged on each side: ... for `b ∈ dom(Σ.C)`, by T10a.4 applied to the content allocation framework of ASN-0036 (where the chain S7a/S7b/S7d + T10a + T10a.4 establishes the analogous structural well-formedness)."
**Problem**: ASN-0036's S7d establishes T10a conformance only for document tumblers (zeros = 2). T10a.4 preserves T4-validity through the document allocator chain but does *not* automatically extend to content allocators emanating from documents — ASN-0036 has no explicit analog of L1c for content allocation. The cited chain "S7a/S7b/S7d + T10a + T10a.4" therefore does not deliver T4-validity of content addresses. T7's precondition fails to discharge through the stated route, leaving the L0 disjointness conclusion improperly supported even though it happens to be true.
**Required**: Replace the citation with the correct route: S7b's postcondition asserts that T4b's projections `N(b)`, `U(b)`, `D(b)`, `E(b)` are well-defined for `b ∈ dom(Σ.C)`; by T4b's definition (UniqueParse, ASN-0034), `dom(N) = `T4-valid subset of T, so `b` is T4-valid. Alternatively, introduce an explicit content-allocator T10a conformance axiom (analog of L1c) and use it.

### Issue 4: L9 allocator chain case split misses the middle case
**ASN-0043, L9 proof, "L1c (LinkAllocatorConformance)" verification**: "When `dom(Σ.L) = ∅` (no prior link allocations under `d'`), the full child-spawning chain from `d'` to the first link address ... When `d'` already has link allocations ... the next link address is `inc(·, 0)` from the allocator's current frontier ..."
**Problem**: The two branches are: (i) `dom(Σ.L) = ∅` globally, and (ii) `d'` already has link allocations. The middle case — `dom(Σ.L) ≠ ∅` globally (links exist under other documents) but no prior link allocations under `d'` — is not addressed. In this case the full child-spawning chain (steps i–iii) is still required to set up `d'`'s element-level allocator before any sibling advance applies; treating it as a simple sibling step under branch (ii) silently skips the required `inc(·, k')` with `k' ∈ {1, 2}` initialization.
**Required**: Reorganize the case split per-`d'`: case A — `d'` has no prior link allocations (use steps i–iii); case B — `d'` has prior link allocations (extend the existing allocator via `inc(·, 0)`). The global emptiness of `dom(Σ.L)` is not the right discriminator.

### Issue 5: L9 and L11b verify only a subset of conformance invariants
**ASN-0043, L9 statement**: "for any conforming state `Σ` satisfying L0–L14, L-fin, and S0–S3..." **L9 / L11b proofs**: enumerate L0–L14, L-fin, S0–S3 but do not address ASN-0036's S7a, S7b, S7c, S7d, S8-fin, S8a, S8-depth, D-CTG, D-MIN, D-SEQ.
**Problem**: ASN-0036 establishes substantially more invariants than S0–S3. If "conforming" means satisfying all ASN-0036 invariants, the proofs are incomplete — they do not verify S7d preservation for the freshly added `d'`, S8a/S8-depth for the new arrangement entry, or D-CTG/D-MIN/D-SEQ for `V_1(d')`. If "conforming" means only L0–L14 + L-fin + S0–S3, then the proof's appeal to `dom(Σ.M)` and the per-document arrangement structure (which require S7d, S8a, etc. to be meaningful) is unsupported. The statement equivocates on the scope of conformance.
**Required**: Either (a) widen the L9/L11b preconditions to "Σ satisfies all ASN-0036 invariants" and explicitly verify each in the extended state (most are vacuous on `d' ↦ ∅` or trivial when `Σ'.C = Σ.C`, `Σ'.M ⊇ Σ.M`); or (b) state the minimum invariant set actually required by the proof and explain why the remainder are not load-bearing.

### Issue 6: L11b construction of fresh `a'` is informal
**ASN-0043, L11b proof**: "By L-fin, only finitely many are occupied. Therefore unoccupied addresses exist; allocate `a'` by a fresh T10a-conforming allocation event within the same document's link subspace ..." and later: "L1c — `a'` is the next sibling output of the allocator via `inc(·, 0)` from its current frontier within the same document's link subspace ..."
**Problem**: The construction asserts existence of an unoccupied address and asserts a sibling step yields `a'`, but does not establish that the sibling step is *guaranteed* to land in an unoccupied position. Multiple allocators may exist in `home(a)`'s link subspace (different `inc(·, k')` spawning chains), so `inc(frontier, 0)` from one allocator could in principle collide with an already-allocated address from a parallel chain. The proof needs to either show such collisions cannot occur (which requires invoking GlobalUniqueness on the specific allocator pair) or describe an explicit fresh-finding procedure (continue sibling advances past the maximum allocated address in the chain).
**Required**: Make the construction precise: "Let the allocator that produced `a` continue advancing siblings via `inc(·, 0)` until reaching an address outside `dom(Σ.L)`. By L-fin (finite occupation) and T0(a) (unbounded sibling stream), this terminates in finitely many steps. By GlobalUniqueness applied to the new event against all prior allocation events, the resulting `a'` is fresh."

### Issue 7: `dom(Σ.M)` is used as if defined but ASN-0036 does not introduce it
**ASN-0043, L1a (LinkScopedAllocation)**: "(A a ∈ dom(Σ.L) :: (E d :: ... ∧ d ∈ dom(Σ.M) ∧ home(a) = d ∧ ...))"; also used in the worked example, L9 proof, and L11b proof.
**Problem**: ASN-0036 introduces `Σ.M(d) : T ⇀ T` per-document but does not formally introduce `Σ.M` as a function with its own domain `dom(Σ.M) ⊆ T` (the set of allocated documents). ASN-0043 uses `dom(Σ.M)` ubiquitously — including in load-bearing precondition clauses of L1a — without definition. The reader can infer the meaning, but a formal statement should not rely on an undeclared symbol.
**Required**: Add an inline definition in the "Link Store" section or in a preliminary "Notation from ASN-0036" remark: `dom(Σ.M) = {d ∈ T : Σ.M(d) is defined}` — the set of documents allocated in state Σ. If this is what S7d implicitly assumes, state it once and reuse.

## OUT_OF_SCOPE

No items raised here belong in a future ASN — the issues above are all in-ASN deficiencies. The "Open Questions" section already acknowledges deferred topics (cross-component invariants, compound link well-formedness, allocation ordering), and the explicit Scope section is comprehensive.
