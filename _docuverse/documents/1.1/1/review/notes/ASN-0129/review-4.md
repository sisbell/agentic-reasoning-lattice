# Review of ASN-0129

## REVISE

### Issue 1: V-IDX's universal-attachment condition is wrong for `targets_keyed`, and its shape rider is wrong for `age`

**ASN-0129, V-IDX (IndexedFamilies)**: "a body applying a behavior-family atom (`succs`, `tip`, `age`, `targets_keyed`, …) at the bound class is well-formed only when the behavior — and with it, by R-C0's compatibility, the shape — is attached at *every* registered class"

**Problem**: Two defects in one sentence.

(a) `targets_keyed` cannot be "applied at the bound class." The note's own FP says it is "indexed by no single K," and ASN-0128's BH3 defines it as the join across *every* BH3-attached Binary type — it takes no class parameter. Its occurrence in a Reg-quantified body is therefore the same closed atom in every expansion instance, and each instance is a PL term iff `targets_keyed ∈ V_atom`, i.e. iff *some* registered class attaches BH3 — not iff every class does. The stated condition ("attached at every registered class") is false for this entry. The charitable alternative reading — the V-PRIM lookup `targets_keyed(s)[K]` with bound `K` — fares no better: V-PRIM defines the lookup per registered class with absent keys reading ⊥, so it is total over registered indices and again needs no universal attachment.

(b) For `age`, the rider "and with it, by R-C0's compatibility, the shape" is false: R-C0 states that BH4 "requires `idem = ⊥`, with no shape clause." Universal BH4 attachment forces `idem = ⊥` at every class, not any shape. The rider is correct only for the BH1/BH2/BH3 entries.

**Required**: Remove `targets_keyed` from the list (or treat it separately: well-formed in any instance iff at least one registered class attaches BH3), and replace the uniform "the shape" rider with what each behavior's R-C0 compatibility actually forces — shape for BH1/BH2/BH3, `idem` for BH4.

### Issue 2: Whether `Reg` admits QD filtering and PC2a folds is left undefined

**ASN-0129, QD / V-IDX / PC2a**: QD's filtering clause — "if `D ∈ QD` and `P : D × S → Bool` is a Boolean PL predicate, then `{x ∈ D : P(x, ·)} ∈ QD`" — is stated uniformly over `D ∈ QD`, and `Reg ∈ QD`; PC2a's `count(D)` and `⋃(D, f)` are likewise stated for all `D ∈ QD`. But V-IDX defines class-variable bodies ("a term former that would otherwise be undefined") *only* for PC1 quantification over `Reg`.

**Problem**: The closure rules and the class-variable semantics do not line up, and the note never says which reading governs. Reading (i): filtered-Reg domains and Reg-folds are formable — then `count({K ∈ Reg : (∃ x ∈ M_K :: ⊤)})` ("how many classes have non-empty member sets") and `⋃(Reg, λK. M_K)` are grammatically generated by QD + PC2a, yet have no semantics: V-IDX's static expansion and instance-wise well-formedness condition are scoped to ∀/∃ binders only. Reading (ii): class-variable bodies simply don't exist outside V-IDX (note that V-PRIM supplies *no* class-valued operations, not even class equality), so non-trivial filters and folds over `Reg` are unformable — but then QD's and PC2a's uniform statements over-generate, and the restriction is stated nowhere. Tuple-valued domains got their body vocabulary rule explicitly (V-TUP, introduced precisely because "a filter over `L_K` has no expressible body" without it); the class-valued base has the analogous rule only in one binding position. A language-definition note cannot leave the formability of a syntactically generated term class undecidable from the text — PC6's leaf/node enumeration depends on the grammar being exactly pinned.

**Required**: One of: (a) extend V-IDX's static expansion and instance-wise well-formedness to every Reg-binding position (QD filters, PC2a's `count` over filtered Reg, `⋃` over Reg), or (b) state in QD and PC2a that `Reg` and class-variable bodies occur only under PC1 quantification, so filters and folds over `Reg` (beyond the trivial `count(Reg)`) are not in the grammar.

### Issue 3: PC2a's "set semantics, settled" clauses omit their view qualifiers, and one is false as stated

**ASN-0129, PC2a (AggregationClosure)**: "under `idem = ⊤` on surface-emitted derivations a per-class count is 0 or 1 (I1a, ASN-0128), under `idem = ⊥` the count is the deposit count because the *substrate* holds the duplicates as distinct tuples"

**Problem**: Both clauses are view-dependent and neither names its view, in a paragraph that opens by saying counts are taken "in the selected view." I1a's 0-or-1 bound is a property of the *active* subset; the *audit* slice under `idem = ⊤` can hold arbitrarily many I0-equal tuples — resurrection-after-nullification re-deposits the same pair at a fresh address by design (I2, R6c, ASN-0128) — so "a per-class count is 0 or 1" is false at view `audit`. Symmetrically, "the count is the deposit count" under `idem = ⊥` holds at the *audit* view only; at the *active* view it overcounts whenever a duplicate has been retracted or born nullified (I3): deposit three duplicates, nullify one, and the active class count is 2 against a deposit count of 3. Since this paragraph is presented as *settling* ASN-0128's Open Question 2, its two illustrative clauses must be exactly right.

**Required**: Qualify both clauses: active-view per-class count ≤ 1 under `idem = ⊤` on surface-emitted derivations; audit-view per-class count = deposit count under `idem = ⊥`, with the active count being deposits minus nullified (including born-nullified) members.

### Issue 4: PC6's statement equates a set of predicates with a class containing non-predicates

**ASN-0129, PC6 (ExpressiveClosure)**: "*Statement: the predicates computable by syntax-directed evaluation over the base are exactly `PL`.*" (repeated in the opening commitments: "predicates computable by *syntax-directed evaluation* … are exactly PL")

**Problem**: `PL` as defined is the closure of `V_atom` under PC0–PC2a and QD-refl, and contains non-Boolean terms — `count(L_dom) : ℕ`, `members : ℘_fin(T)`, `chain : Seq_fin(T)`. A set of predicates cannot equal `PL`. The forward and converse arguments in fact operate over all COD-valued computations (the converse normalizes set-valued and ℕ-valued intermediate results), so the mismatch is in the statement, not the proof. In a note this fastidious about typing — COD is given a realizer and a consumer per entry — the headline theorem's statement should type-check.

**Required**: Restate at the term level ("the COD-valued functions computable by syntax-directed evaluation over the base are exactly the PL terms"), or restrict both sides to Boolean codomain and note the general-term version separately.

## OUT_OF_SCOPE

### Topic 1: Tumbler-field projections as PL vocabulary

V-PRIM admits address comparisons (`=`, `≼`, T1) but no field projections — no `home`, `N`/`U`/`D`/`E`. Consequently home-scoped predicates ("the active K-tuples homed at `d`") are not expressible: `d ≼ a` does not pin `home(a) = d`, since document-level prefixes can properly extend one another at equal zero count. **Why out of scope**: the note never claims field access — BH4 uses `home` only atom-internally, behind its own definition — and admitting projections would be a V-PRIM-style vocabulary extension for a successor note, not a defect in this one.

### Topic 2: Sum-aggregation over state-dependent domains

PC2a deliberately ships `count`, T1-extrema, and `⋃`; there is no Σ-fold (sum of `g(x)` over a domain). Cross-type totals survive via static hand-expansion over the constant `Reg`, but sums over state-dependent domains — e.g. total target multiplicity of a Multi type, `Σ_{x ∈ A_K} |addrs_G(x)|` — are not PL terms. **Why out of scope**: PC2a's suite is a deliberate selection ("aggregation raises no expressiveness beyond the closure"), and a Σ-fold is a new former with its own PC5/PD0 obligations — a conscious extension, like the bounded-fixpoint successor of Open Question 4.

VERDICT: REVISE
