# Review of ASN-0129

## REVISE

### Issue 1: V's inheritance claim for default-view semantics contradicts UV
**ASN-0129, The atomic vocabulary (V)**: "each template atom's active- and default-view semantics is exactly its ASN-0128 specification."
**Problem**: This sentence cannot coexist with UV. UV's own premise is: "ASN-0128 committed the collection rule for `members` and `targets_of` and left the behavior surfaces open (its Open Question 1); UV closes the question." So for `succs`, `chain`, `sources_to`, and `stale`, the default-view semantics is **this note's** rule (UV's Collections clause), not an ASN-0128 specification — V asserts an inheritance UV says does not exist. The dilemma is closed both ways: if ASN-0128 *did* fix the behavior atoms' default readings (reading BH1's "Nothing else is rewritten" universally, i.e. unrewritten), then UV's rewrite of `succs`/`chain`/`sources_to`/`stale` contradicts both ASN-0128 and V's sentence; if it did not (OQ1 open, as UV claims), V's sentence asserts a specification that doesn't exist. Either horn requires amending V. Relatedly, the additions inventory — "This note's own additions are five" — omits the behavior-surface default readings, which by UV's own account this note defines; the audit readings (V-AUD) are counted as an owned addition while the structurally parallel default readings are not.
**Required**: Scope V's sentence to what is actually inherited — active-view semantics for all template atoms, plus the core family's default reading per BH1 — and point the behavior atoms' default-view semantics explicitly at UV. Either add UV's default readings to the additions inventory or restate the inventory as covering vocabulary symbols only.

### Issue 2: `targets_keyed` mistyped as a class-indexed template atom
**ASN-0129, V (BH3 family)**: "*BH3 family* (when typed-reverse-lookup is attached): `sources_to : T → ℘_fin(T)`, `target_of : T → T ∪ {⊥}`, and the join `targets_keyed : T → Map_fin`."
**Problem**: `Tpl(record(K))` is defined as the generator of K's atoms, and every other member of every family is K-indexed. But `targets_keyed` is not K's atom: FP states its footprint "is cross-type by construction: it joins `target_of` across *every* BH3-attached Binary type … indexed by no single K," and V-IDX must specially exempt it ("the class-*unindexed* `targets_keyed` … occurring as the same closed atom in every expansion instance, well-formed iff … *some* registered class attaches BH3"). As written, V generates one "copy" of a global atom per BH3-attached class, and a reader of V reasonably concludes it is class-indexed like `sources_to`; the correction arrives two sections later, at V-IDX and FP. The well-formedness condition V-IDX needs ("some class attaches BH3") is currently only recoverable by noticing that the union over K happens to produce it.
**Required**: State the class-unindexed character at the definition site — either hoist `targets_keyed` out of the per-K family into a registry-level admission conditioned on "some registered class attaches BH3," or annotate it inside the BH3 family as a single global atom that every BH3-attached class's family contributes identically.

### Issue 3: `is_doc`'s upstream grounding misstates the foundation contracts it cites
**ASN-0129, PC5**: "`is_doc` is a single membership check — the residence test the emit surface itself performs at every gated call (I1/I5, ASN-0128)." **ASN-0129, QD-audit**: "the emit surface's own gating clause (I1/I5, ASN-0128) — the one store-domain test the upstream contracts themselves perform."
**Problem**: Two precision failures against the cited foundation. (a) I1 makes home validation *branch-local*: "On a hit, `d` is not read at all: the call is admitted and answered with the existing address whatever `d` holds." An `idem = ⊤` hit is a gate-passing call (the gate is evaluated first, per I1's Order clause) on which the residence test is never performed — so "at every gated call" is false; the correct statement is "on every miss (I1) and on every `idem = ⊥` call (I5)" (and on every `Nullify_Binary` call, where S3 evaluates P0 on both branches). (b) "The one store-domain test the upstream contracts themselves perform" is falsified by `Nullify_Binary`'s P-tgt — `a ∈ A_rel^Σ`, i.e. membership in `dom(Σ.L)`, "enforced as rejecting preconditions at this surface" (S3) — a checked store-domain test on the link store. The claim survives only if silently scoped to the arrangement store.
**Required**: Reword PC5's parenthetical to match I1/I5's branch structure, and scope QD-audit's clause to "the one *arrangement-store*-domain test" (or otherwise acknowledge P-tgt's `dom(Σ.L)` membership check).

### Issue 4: Forward-reference accretion — duplicated interpretive prose and repeated deferrals
**ASN-0129, UV (closing paragraph) and intro**: "The reading adopted: *the walk* is the traversal and its verdicts — … and UV preserves exactly that: traversal is never filtered (the retired mid-chain element is walked through), `tip` and `is_in_chain` answer from the unrewritten walk…"
**Problem**: This restates, in different words, commitments already made three paragraphs earlier in UV's own clauses (*Booleans*: `is_in_chain` "evaluated against the unrewritten walk"; *Arguments and traversal*: "`chain` walks the active denoted graph; a retired mid-chain element is traversed but not shown") — the same-content-twice pattern. The non-duplicative parts of the interpretive paragraphs (the colon-scoping of BH1's "Nothing else is rewritten," the OQ1 citation) are load-bearing and should stay; the restatement of UV's own bullet content should not. Separately, the intro defers to PC6 twice in consecutive paragraphs ("the language is *exactly* that closure (PC6)"; "the closed-algebra commitment, made formal at PC6"), and "protocol constructions are fenced at the end" pre-states what the "What this note doesn't cover" section's first bullet says again.
**Required**: Trim the UV interpretive paragraphs to the scoping facts not already committed in UV's clauses; keep one intro pointer to PC6 and drop the duplicate fence sentence.

## OUT_OF_SCOPE

### Topic 1: Cross-state evaluation coherence for agent-time iteration
PC4/PC5 deliberately govern one evaluation at one state, and C-reach correctly pushes closure computation to agent-time loops over `succs`. But an agent iterating across `→_sh` steps evaluates each round against a *different* Σ, and nothing specifies what coherence (if any) the substrate owes such multi-state computations — e.g., whether an agent-time reach computation interleaved with retractions has any meaningful result.
**Why out of scope**: This is application/protocol-layer contract territory (the fenced "protocol constructions" zone), not an error in the single-state predicate foundation.

### Topic 2: Evaluation cost model
The note proves purity and termination but says nothing about cost — base-read counts per term, fold-size bounds as functions of `|dom(Σ.L)|`. A scheduler or trigger-dispatch layer evaluating many PL terms per step will eventually need a cost discipline (e.g., which PD2 non-interference facts license skipping re-evaluation).
**Why out of scope**: Purity and termination are the guarantees this layer owes; cost budgeting is new territory for the runner/middleware layer.
