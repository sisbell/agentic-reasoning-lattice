# ASN-0130: Predicate Definitions as Substrate Content

*Terms as artifacts — storing, validating, referencing, versioning, and certifying PL predicates in the docuverse itself.*

ASN-0129 defines the predicate language: what terms exist, what they mean, what they cannot express, and how their truth moves. Its terms, however, are meta-level objects — the note says well-typing is decidable but gives terms no existence inside the system. This note closes that gap the Xanadu way: a predicate definition is *content* — an immutable run of I-addresses holding a serialized PL term — registered by a classifier tuple, referenced by address, versioned by supersession, and certified by further tuples. The predicate system becomes self-hosting on the links it queries: a builder's protocol definitions are themselves linkable, citable, supersedable documents, and the platform's validation guarantees attach to them once, permanently.

The design rests on three foundation facts. Content is immutable and permanent — the strand model's S0/S1 guarantee, re-derived per step of the gated substrate in PR1 — so a validated definition can never drift: validation at registration is validation forever. Identity is by origin, not value (S4, ASN-0036), so definitions are identified by address, dissolving the naming and equality problems a name-keyed registry would import. And registration events are totally ordered along any derivation, so definitional references — required to name *already-registered* definitions — can only point backward in first-registration order, making the reference graph a DAG by construction, definitional expansion terminating without any cycle check, and the typing of reference-bearing bodies well-grounded (PR-SIG's stratification).

**Depends:** ASN-0034 (Tumbler Arithmetic), ASN-0036 (Strand Model), ASN-0043 (Link Ontology), ASN-0086 (Typed Relations on Address Sets), ASN-0093 (Allocation Substrate), ASN-0126 (Substrate Shape Framework), ASN-0128 (Substrate Type Operational Semantics), ASN-0129 (Substrate Predicate Composition).

## What this note commits

- **The definition artifact** (PR-ENC): a predicate definition is a contiguous content run holding an encoded *signed* PL term — a recorded parameter signature plus a body — identified by the run's start address. Parse-validity, the run's extent, and the recorded signature context are *content-intrinsic*; typing is decidable by ASN-0129's WT extended with one rule for applied definitional references (WT-ref).
- **Registration as a validated emit** (PR0): the operation surface validates the encoded term — parse, well-type, *registered references only* — and on success deposits the `pdef` classifier through the emit it wraps; on failure it rejects, no tuple. The exposed `Emit_K` rejects `pdef`- and `pd_stable`-class calls outright (the entry-point seal, PR-DISC), so the validated surfaces are the only surface routes into either slice. The success postcondition is stated against the born-nullified boundary, with the weakest precondition for referenceability supplied.
- **Validation permanence** (PR1): a `pdef` tuple's existence is a permanent proof that its run validated — validation at registration is validation forever. No runtime re-validation path exists or is needed.
- **Acyclic reference by construction** (PR2): definitions reference other definitions by address; registration requires referenced definitions to be already registered, so references point strictly backward in *first-registration* order — the reference graph is a DAG, and expansion terminates, preserving ASN-0129's PC6a under definitional reference without a cycle check.
- **Evaluation by reference** (PR3): `evaluate(a, args, view, Σ)` — precondition: `a` ever-registered; `args` a signature-respecting environment — resolves content to a term by the self-delimiting parse, expands through the reference DAG into a pure term well-typed at the recorded signature (PR3a), and evaluates per ASN-0129 at the caller's view — references are *view-transparent* (PR-VIEW) — inheriting purity, termination, and the ceiling unchanged.
- **Versioning by supersession** (PR4): definitions are immutable; updating one is registering a successor and emitting the shipped `supersedes` relation (S2, ASN-0128) — `tip()` resolves the current version, a branch is a ⊥ verdict surfaced to readers, exactly the shipped semantics with no new machinery.
- **Dynamics certification** (PR5, operation contract PR5a): a second validated surface, `certify_pd_stable`, certifies a registered definition's PD class (ASN-0129, PD0–PD2) by emitting a certification classifier — making "is this termination predicate certified ST⁺ (PR5)" itself a one-atom PL query. The certified object is the definition's *expansion* (PR3); certification is restricted to *view-independent* expansions (PR-VIEW) and reads parameters as bound constants of their declared sorts (PR5's *Parameters* qualification) — the certificate binds at every call view and asserts ⊤-stability of every `Γ_D`-instantiation.

## The definition artifact

**PR-ENC (EncodingDiscipline).** An *encoding* is an injective map from *signed syntactic terms* — a pair of an ordered, sorted parameter context `Γ_D = ⟨x₁ : C₁, …, x_k : C_k⟩` (each `Cᵢ ∈ Codom`, COD of ASN-0129; `k = 0` for closed terms) and a body in ASN-0129's grammar extended with *applied definitional references* (PR-SIG), and no view component (deliberately: definitions are view-polymorphic, the view bound per evaluation, PR-VIEW) — to finite content-value sequences, with a decidable parse and one further discipline the rest of the note leans on: **prefix-freeness** — no parse-valid sequence is a proper prefix of another; equivalently, the parse is *self-delimiting*, determining its own extent from its start. The domain is deliberately *syntax only* — grammatical well-formedness, no typing requirement, typing being stratified onto registration order instead (PR-SIG). What the syntactic domain buys is that *parse-validity, the run's extent, the recorded `Γ_D` and body — hence the body's reference addresses — and prefix-freeness are all content-intrinsic*: properties of the value sequence alone, fixed at allocation, the same against every store and at every state. The discipline also reserves a countable supply of *expansion names* `ν₁, ν₂, …`, which no recorded parameter name and no body binder may inhabit. A *definition artifact* is a contiguous run `A_def = {shift(a, k) : 0 ≤ k < n}` (`n ≥ 1`) of content addresses holding a parse-valid encoding, identified by its start `a` — *the definition's address*. The run is one segment of `a`'s origin K.α chain (ASN-0093), because on T4-valid content addresses (StoreT4Validity, ASN-0093) `shift(x, 1) = inc(x, 0)`: `inc(x, 0)` rewrites exactly the sig position (TA5(c), ASN-0034), which for a T4-valid tumbler is the terminal position `#x` (TA5-SigValid), while `shift(x, 1) = x ⊕ δ(1, #x)` (OrdinalShift, ASN-0034) agrees with `x` everywhere except adding one at that same terminal position — the same tumbler. Identification by start is well-defined exactly because of prefix-freeness:

**PR-ENC-uniq.** At most one parse-valid run starts at any address: were `{shift(a, k) : 0 ≤ k < n}` and `{shift(a, k) : 0 ≤ k < n'}` both parse-valid with `n < n'`, the shorter's value sequence would be a proper prefix of the longer's — both parse-valid encodings — contradicting prefix-freeness.

By S0/S1 (ASN-0036) the run's values are fixed and permanent from allocation; by S4, two registrations of byte-identical terms at different runs are distinct definitions — identity is by origin, and term-equality questions are extensional questions ASN-0129 already classifies as open theory, not identity.

**PR-DISC (RegistrationDiscipline).** Call a derivation *registration-disciplined* iff every `L_pdef`-growing step along it is the deposit branch of a `register_pred` call (PR0) and every `L_pd_stable`-growing step the deposit branch of a `certify_pd_stable` call (PR5a) — the per-class surface-discipline shape of ASN-0128 (SD, I1a). On such a derivation every active `pdef` tuple is the trace of a validated registration, and every active `pd_stable` tuple the trace of a validated certification. This is the note's central scoping hypothesis; the entry-point seal (Standard registrations) discharges it for the shipped surfaces.

**PR-SIG (SignaturesAndReferences).** A signature has two components of different epistemic standing, and the definition layer is stratified accordingly. The *parse layer* is content-intrinsic: wherever a parse-valid run starts, the self-delimiting parse returns the recorded parameter context `Γ_D` and the body — functions of the immutable values (S0, PR-ENC), defined at every state alike. The syntax PL gains is the *applied reference*: for an address `r` and terms `e₁, …, e_k`, the form `r(e₁, …, e_k)`, bare `r` when `k = 0` — a grammatical form, parsed with no store consulted. The *type layer* cannot be content-intrinsic: typing a reference needs the referent's parameter sorts and result sort, so a reference-bearing body's well-typing is not a property of its own run's values — and a definition that demanded it would not be well-founded. Allocate two runs, each referencing the other's start, neither registered: whether either well-types needs the other's signature first — a loop with no ground, where a least-fixed-point reading calls both invalid, a greatest calls both valid, and content decides nothing. Registration order is what grounds the type layer:

**sig.** `sig(a) = (Γ_D, C_D)`: the parse layer's recorded context, paired with the result sort the WT + WT-ref pass derives for `a`'s body *at `a`'s first registration*. A *registration event*, here and throughout, is a deposit through `register_pred` (PR0); and the induction below — with every claim that consumes `sig` — is scoped to the *registration-disciplined* derivations (PR-DISC). `sig` is defined exactly on the *ever-registered* addresses, by induction on first-registration order — well-founded, registration events being totally ordered along the derivation (PR2). At `a`'s first registration, PR0 (iv) has every referenced address `r` carrying an active tuple at the pre-state — under the discipline, a tuple that entered at a `register_pred` deposit for the definition at `r` — so `r`'s first registration is strictly earlier (PR2(a)) and `sig(r)` is already defined by the induction: every signature WT-ref consults is grounded, the pass is a terminating syntax-directed walk, and `C_D` is determined — unique, WT being syntax-directed. Once defined, `sig(a)` never changes, and it re-derives identically at every later deposit event for `a`: the body is content-fixed (S0), each consulted `sig(r)` was fixed at its own earlier first registration, and the pass is deterministic. The parse component is permanent by content immutability; the sort component by this induction.

**WT-ref.** For a context `Γ`, an address `r` with `sig(r)` *defined* and `sig(r) = (⟨x₁ : C₁, …, x_k : C_k⟩, C_r)`, and `Γ ⊢ eᵢ : Cᵢ` for each `1 ≤ i ≤ k`: `Γ ⊢ r(e₁, …, e_k) : C_r`. Definedness of `sig(r)` is the rule's domain condition — a reference to a never-registered address has no typing judgment, not a false one, exactly as a partial function applied outside its domain has no value.

WT-ref makes the typing judgment relative to registration history — the one read ASN-0129's state-free typing pass acquires — but a grounded one where PR0 invokes it: condition (iv) requires each referenced `r` actively registered, so — on the registration-disciplined derivations (PR-DISC) — `sig(r)` is defined and immutable. The pass remains a syntax-directed finite tree walk with one finite signature lookup per reference node — decidable, its verdict permanent once the referents are registered. A body well-types under its own `Γ_D` alone, so its free variables are among its parameters; the binders *inside* a body are ASN-0129's own (PC1/PC2a domains, PC2's binder guard), and any name coincidence between a referent's parameters or binders and the host's variables is an expansion concern, resolved there by canonical renaming (PR3) — typing never confronts it.

## Registration

**PR0 (DefinitionRegistration).** The operation surface exposes `register_pred(d, A_def)`: *validate, then emit through the `pdef`-class emit it wraps*, returning the classifier tuple's address. *Validation* runs in full on every call — hit or miss, I1's gate-first order (ASN-0128) extended to the surface's own precondition — at the call state Σ: (0) `A_def` is a non-empty finite address set (`A_def ≠ ∅`, `|A_def| < ∞`) — failing which the call rejects like any other, the abbreviations below being undefined on `∅`; then, writing `a := min(A_def)` (T1) and `n := |A_def|`, (i) the run is resident and chain-contiguous — `A_def ⊆ dom(Σ.C)` and `A_def = {shift(a, k) : 0 ≤ k < n}`, one segment of one origin's K.α chain (PR-ENC); (ii) the run's values are exactly one parse-valid encoding — the self-delimiting parse from `a` succeeds and consumes precisely the presented extent, and by PR-ENC-uniq no other extent could; (iii) the decoded signed term well-types, `Γ_D ⊢ body : C_D`, under WT plus WT-ref (PR-SIG) — each reference node's `sig(r)` defined exactly because (iv) holds — an entailment registration discipline supplies (PR-SIG, PR-DISC) — PR-SIG having fixed a registered referent's signature at its first registration, the surface checking (iii) and (iv) jointly; (iv) every definitional reference names an *already-registered* definition: for each referenced address `r`, some `(b, F, G) ∈ A_pdef^Σ` (the active slice of the `pdef` class, ASN-0086's typed-relation machinery as surfaced by ASN-0128) with `r ∈ addrs(F)`. On any validation failure the call is rejected — no step, no tuple, no address, *even when an I0-equal active tuple exists*: rejection of a call asserts nothing about a standing registration. This is the enforce-by-rejection stance ASN-0128's S3 takes for P-tgt, and for the same reason: the static gate cannot read content, but the operational layer can, and admitting an invalid registration would mint a durable classifier whose meaning (PR1) would be a lie.

On success the surface invokes the `pdef`-class emit it wraps — I1/I6's idem-⊤ contract (ASN-0128), reachable only through this wrapper by the entry-point seal (PR-DISC) —

`Emit_pdef(Σ, d, {a}, A_def)`

whose deposited endsets are the canonical encodings `F = enc({a})` — one unit-depth span denoting the definition's address — and `G = enc(A_def)`, the run; both are recoverable by denotation, `addrs(F) = {a}` and `addrs(G) = A_def` (AD, ASN-0128). Shape conformance (Sh-conf, ASN-0126) holds by construction — `pdef` is Multi (PS1): `|F| = 1`, `|G| = n < ∞` — and `pdef ≁ R` by the construction-time non-collision check, so the gate admits every validated call, and I1's `idem = ⊤` contract supplies the branch: a *hit* (some I0-equal tuple in `A_pdef^Σ`) returns the incumbent's address, no step taken, `d` unread; a *miss* with `d ∈ dom(Σ.M)` deposits `(enc({a}), enc(A_def), pdef)` at the frontier address `a_emit(Σ, d)`; a miss with `d ∉ dom(Σ.M)` is rejected.

*Uniqueness.* Every `register_pred` deposit is an `Emit_pdef` deposit branch, so a registration-disciplined derivation (PR-DISC) is pdef-surface-emitted in I1a's sense — discharging I1a's premise, so I1a applies: at most one active `pdef` tuple per I0 class at every state reached. Prefix-freeness sharpens the unit to the one references use: all validated runs at one start coincide (PR-ENC-uniq), so all validated tuples at one start are I0-equal — *at most one active registration per definition address*.

*Success, precisely — the born-nullified boundary and the wp.* "Registered" in this note means *active* membership — condition (iv) reads `A_pdef^Σ`. A gate-clearing miss deposits into `L_pdef^{Σ'}` unconditionally but lands in `A_pdef^{Σ'}` only if C3 holds — no pre-existing retraction tuple's to-coverage contains `a_emit(Σ, d)` (I3, ASN-0128). Under a prior *range* retraction covering that frontier slot, the deposit is *born nullified* (RangeSterilization, ASN-0126): validation passed, tuple deposited, definition never referenceable. On surface-disciplined derivations this cannot happen — DR (ASN-0128) empties C3's existential — so there success and referenceability coincide. The weakest precondition, in I6's form, for the postcondition that the registration is *referenceable*,

`POST-ref ≡ (E (b, F', G') ∈ A_pdef^{Σ'} :: addrs(F') = {a})`

is — *on registration-disciplined derivations (PR-DISC); the equivalence is not unscoped, both directions drawing on the discipline at the two points flagged below* —

`wp(register_pred(d, A_def), POST-ref) ≡ (E (b, F', G') ∈ A_pdef^Σ :: addrs(F') = {a}) ∨ (VALID(Σ, A_def) ∧ d ∈ dom(Σ.M) ∧ C3(Σ, d))`

with `VALID` conditions (0)–(iv). The two disjuncts partition on whether `a` is *already* actively registered at Σ — POST-ref being a state predicate over `Σ'` that a *standing* tuple can satisfy, not a claim about what this call returns, so a rejecting call (a skip, `Σ' = Σ`) inherits whatever registration stood. *First disjunct — an active tuple denotes `a` at Σ.* Then POST-ref holds at `Σ'` whatever the call does, and the disjunct is wp-true: a `VALID`-passing call hits (I1's branch at the `pdef` class) — the incumbent is I0-equal and, *first use of the discipline*, canonically shaped, every tuple at one start having entered as a `register_pred` deposit, so `F' = enc({a'})` with `subtree(a') = coverage(F') = subtree(a)` forcing `a' = a` — and returns it at `Σ' = Σ`; a `VALID`-failing call is rejected at `Σ' = Σ`, the incumbent still standing. This is the branch the unlifted `VALID ∧ (…)` form wrongly excluded — a call may fail validation (a referent since de-registered, condition (iv)) yet leave `a`'s own standing registration untouched, POST-ref true while `VALID` is false. *Second disjunct — no active tuple denotes `a` at Σ.* Then canonical shaping makes every `VALID`-passing call a *miss*, and POST-ref at `Σ'` demands a fresh deposit that lands active: `VALID` must hold (a `VALID`-failing call is a skip, no tuple — wp false under I6's attainability convention), `d ∈ dom(Σ.M)` must hold (an admitted miss with `d ∉ dom(Σ.M)` is rejected), and the deposit must clear C2 ∧ C3 (I3) — C2 outright (`pdef ≁ R`), leaving C3, whose *necessity* is the second use of the discipline: a born-nullified deposit (¬C3) leaves no active tuple denoting `a`, POST-ref false. On derivations additionally surface-disciplined, C3 vanishes (DR) and the wp reduces to

`wp(register_pred(d, A_def), POST-ref) ≡ (E (b, F', G') ∈ A_pdef^Σ :: addrs(F') = {a}) ∨ (VALID(Σ, A_def) ∧ d ∈ dom(Σ.M))`

Validation reads content values — `Σ.C(a)` dereferences, which PL itself is forbidden (ASN-0129, Structural reads only) — but only at the operation surface: at registration to validate, and at resolution and expansion (PR3) to read terms whose validity the standing tuple already proves; never inside PL evaluation itself, where the structural-reads-only boundary holds untouched.

**PR1 (ValidationPermanence).** At any state Σ reached by a registration-disciplined derivation (PR-DISC), if `(b, F, G) ∈ L_pdef^Σ`, then the run `addrs(G)`, with start `addrs(F) = {a}`, passed PR0's validation at its deposit's pre-state — parse-valid (ii), well-typed (iii), every reference registered (iv) — and holds the same values at Σ and at every `→_sh*`-successor. Deposit-state validity is the discipline itself: the tuple entered at a `register_pred` deposit, whose validation (0)–(iv) had just passed. Permanence is per-step plus induction, not a single transfer. Each step of the substrate relation either frames the content store outright — K.σ and K.λ_sh carry `Σ'.C = Σ.C` in their frames (GatedTransitionRelation, ASN-0126; R-TR, ASN-0128) — or is a K.α step, whose content effect is `C' = C ∪ {a' ↦ v}` at a key fresh against `dom(Σ.C)` (K.α's binding precondition with emission freshness, ASN-0093), leaving every existing binding intact: these are C0's per-step clauses (ASN-0093) read against `→_sh`. So every single step preserves the residence and value of every already-stored content address, and induction along the derivation from the registering state carries the run — resident, values fixed — to Σ and to every successor. The tuple itself persists with its value fixed the same way: L12 is a transition invariant, crossing each genuine `→_sh` step by B2's transition-invariant clause with RP-b (ASN-0128), inducted along the derivation. A `pdef` tuple is therefore a *permanent proof of validation*: no re-validation path exists at runtime because none is needed — staleness would require the content to change, and the substrate has no operation that changes content. (Contrast every system whose code artifacts are mutable: there, validation is a cache; here it is a fact.)

**PR2 (AcyclicReference).** Under the registration discipline (PR-DISC), deposits into the `pdef` class are `→_sh` steps, totally ordered along any derivation (SequentialAtomicTransitions, ASN-0093). One definition may carry *several* deposit events: de-registration re-opens registration — after a `Nullify_Binary` on a run's tuple, the dedup sees an empty class (I2, ASN-0128) and a later `register_pred` for the same run deposits afresh — so "registration order" is an order on *events*, not a function of definitions, and the acyclicity argument must be run event-wise. For an ever-registered definition D — a start address carrying at least one `pdef` deposit along the derivation — write `e₁(D)` for its *earliest* deposit event; D's term, hence D's reference set, is the same at every one of D's deposit events (the run is content-immutable, and the prefix-free parse returns the same term every time). Two observations close the argument:

(a) *Every deposit event sees each referent registered strictly earlier.* A deposit is the miss branch of a `register_pred` whose validation (iv) had just passed at the pre-state: each referenced address `r` carries an active tuple there, which entered `L_pdef` at some strictly earlier deposit event — a deposit event *for the definition at* `r`, since that tuple's F denotes `r` and so its run starts at `r`. Hence `e₁(r) <` the current event; instantiating at D's earliest event, `e₁(r) < e₁(D)`.

(b) *Self-reference fails at every deposit event.* Deposits occur only on a dedup miss, and all validated tuples at one start are I0-equal (PR-ENC-uniq), so at a deposit event for D every existing tuple denoting D's start is inactive — and the depositing tuple does not yet exist during its own validation. Condition (iv) therefore has no witness for a reference to D's own start: a self-referencing term is rejected at every would-be deposit event, and by induction along the derivation it is never deposited at all — nor can such a call ever be answered by a hit, since a hit requires an active incumbent whose own deposit the same argument excludes.

The reference relation on ever-registered definitions thus embeds in the strict order `e₁(r) < e₁(D)` — irreflexive, acyclic, a DAG with no cycle check ever run. (Note the order is *registration* order, not allocation order: a run may be allocated long before it is registered, so the runs' allocation order constrains nothing.) *Consequently definitional expansion terminates*: expansion (PR3) descends reference edges, `e₁` strictly decreasing among the finitely many deposit events (L-fin bounds them), each term finite; the expanded result is a pure PL term (no references), and ASN-0129's PC6a is preserved — mutual recursion among definitions is not merely banned, it is *unconstructible*: the would-be second member of a cycle cannot validate before the first is deposited, and the first refers only to definitions first-registered earlier than itself. (Ghost references — L4/L9 endset generality, ASN-0043 — are exactly what condition (iv) excludes for *references inside terms*; the endsets of the `pdef` tuple itself remain ordinary endsets with ordinary semantics.)

**PR3 (EvaluationByReference).** Three layers, each pinned. *Resolution* — address to signed term: read content values from `a` along its origin chain — successive addresses `shift(a, k)`, the chain's `inc(·, 0)` siblings (PR-ENC) — feeding the self-delimiting parse, which determines the run's extent from content alone and yields `(Γ_D, body)`. Resolution consults no slice and no tuple: the extent comes from the parse, not from any endset, and is unique per start (PR-ENC-uniq); overlapping runs are harmless because resolution is start-anchored — a decodable suffix is a different definition at a different start. *Expansion* — `expand(a)`: in `body`, replace each applied reference by the referent's expansion with the expanded arguments substituted for its parameters — defined so that `expand` is a *function*, every choice a rule. References are processed bottom-up, siblings left to right (arguments fully expanded before the node they feed). At a node `r(·)` with expanded arguments `E₁, …, E_k`: take `expand(r)` — the recursion is well-founded because descent strictly decreases first-registration rank (PR2) — rename its parameters *and* every binding site in it (PC1/PC2a domains, PC2 binder guards) to expansion names from PR-ENC's reserved supply, the least-indexed names occurring nowhere in the term under construction, the `Eⱼ`, or `expand(r)` itself, assigned in a fixed order (parameters first in signature order, then binding sites depth-first, left to right); then substitute `Eⱼ` simultaneously for the renamed `j`-th parameter. The renaming is total — a referent's free variables are among its parameters (PR-SIG), and all parameters are renamed, so every free variable is — and capture-free by construction: every introduced name is fresh for everything in scope, and no author-written name inhabits the supply (PR-ENC). The parameters are renamed *along with* the binders, deliberately: a referent's parameter may share its name with a host variable (the worked composition's `gate` does exactly this), and the rename is what keeps the two from ever meeting in one scope. Expansion terminates (PR2) in a pure PL term whose free variables are among the top level's own parameters `Γ_D` — a *well-typed* one at the recorded signature, `Γ_D ⊢ expand(a) : C_D` with `expand(a) ∈ PL` (PR3a below) — and it is *determinate*: the parses are content (S0), the reference DAG is fixed by the parses, and every processing order and name choice above is fixed, so `expand` is a function of immutable content — two evaluators expanding the same address at any two states obtain the same concrete term, not merely α-equivalent ones. *Evaluation* — `evaluate(a, args, view, Σ)`. Its precondition: `a` is *ever-registered* at Σ — a registration event for `a` precedes Σ along the derivation — spelled as the audit-slice fact: some `(b, F, G) ∈ L_pdef^Σ` with `addrs(F) = {a}` (in PL: `(E x ∈ L_pdef :: a ∈ addrs_F(x))`; equivalently `a ∈ M_pdef` at view `audit`, V-AUD). Spelling and meaning coincide exactly on registration-disciplined derivations (PR-DISC): there every audit tuple denoting `a` is some `register_pred` deposit's trace, and `evaluate` is specified only on the disciplined domain. Active registration is *not* required, of `a` or of any referent: under the precondition the top run validated at its deposit (PR1); each referent was deposited strictly earlier (PR2(a)) and so is ever-registered at Σ by audit monotonicity (L12a per step, via RP-b); so `sig` is defined at every node of the reference DAG (PR-SIG's induction), and induction down the DAG carries deposit-state validity — parse and typing both — to every leaf. A de-registered definition therefore still evaluates — resolution reads immutable content whose validity the deposit-state validation already proved; what de-registration withdraws is the *endorsement* (condition (iv) for new registrations), not the artifact or its standing proof in the audit slice. `args` is a `Γ_D`-*environment*: one value of sort `Cᵢ` per parameter `xᵢ`, per `sig(a) = (Γ_D, C_D)` (PR-SIG). Then `evaluate(a, args, view, Σ)` is the ASN-0129 denotation of `expand(a)` at `(args, view, Σ)` — a denotation that exists at the signature's result sort because `expand(a)` is a PL term with `Γ_D ⊢ expand(a) : C_D` (PR3a), the view fixed at the top level per PC3, with what that fixing means for referents stated at PR-VIEW. Purity (PC4), termination (PC5), decidability, and the ceiling (PC6) hold verbatim — the expansion is a pure PL term fixed by immutable content before evaluation begins — the same concrete term at every state (S0 for the values read, determinacy of `expand` for the spelling); the *value* varies only as `(args, view, Σ)` vary, exactly as for any PL term.

**PR3a (ExpansionWellTyping).** On registration-disciplined derivations (PR-DISC): for every ever-registered `a` with `sig(a) = (Γ_D, C_D)`, `expand(a)` is a pure PL term with `Γ_D ⊢ expand(a) : C_D`. PR2 gives termination; this lemma supplies what PR3's evaluation clause actually consumes — that the terminating result is a *term*, of the signature's sort — and its proof is the substitution induction. Two facts about WT + WT-ref carry it; we state them once, each a syntax-directed induction, each conditioned on exactly the freshness PR3's renaming arranges. WT touches variable names at two points only — the variable rule's context lookup and the context extension at each binder (PC1, PC2a's `⋃`, PC2's guard, QD filters) — and WT-ref adds no third: its signature lookup reads an address, not a variable.

*WT-α (renaming).* If `Γ ⊢ u : C` and `ρ` renames variables sort-preservingly and injectively — acting on `dom(Γ)` and on `u`'s binding sites, its image names pairwise distinct and occurring nowhere in `u` — then `ρΓ ⊢ ρu : C`. Both name-touching points commute with an injective, fresh renaming — lookups find the renamed entry, extensions extend at the renamed binder — so the derivation maps rule for rule.

*WT-W (weakening).* If `Γ ⊢ u : C`, `y ∉ dom(Γ)`, and `y` occurs nowhere in `u` as a binder, then `Γ, y : C′ ⊢ u : C` for any sort `C′`. Lookups at `u`'s variables are unchanged — contexts are functions and `y` is new — and every context extension at a binder of `u` remains a function, the binder differing from `y` by the proviso. Iterated, WT-W adjoins any finite set of variables each satisfying both provisos.

We induct on first-registration rank (well-founded by PR2; every referent's rank strictly lower, PR2(a)), with a nested structural induction on the body, whose registration-state judgment `Γ_D ⊢ body : C_D` under WT + WT-ref is supplied by PR0 (iii) and permanent (PR1; the consulted signatures fixed once defined, PR-SIG). Expansion rewrites reference nodes only, so every other node's WT rule is preserved as the structural induction passes through it. Consider a reference node `r(e₁, …, e_k)`, typed in the host derivation at a context `Γ` — `Γ_D` extended with the host binders in scope, all author names (replacements are pure, so every surviving reference node sits under the body's original binders) — by WT-ref's premises `Γ ⊢ eᵢ : Cᵢ` and `sig(r) = (⟨x₁ : C₁, …, x_k : C_k⟩, C_r)`, conclusion `Γ ⊢ r(e₁, …, e_k) : C_r`. Write `E₁, …, E_k` for the expanded arguments and `y₁, …, y_k` for the expansion names PR3 assigns to `r`'s parameters; PR3's freshness gives the `yⱼ` and the renamed binders pairwise distinct, outside `dom(Γ)` (expansion names never collide with author names, PR-ENC), and occurring nowhere in any `Eⱼ` or in `expand(r)`.

- *Arguments.* The structural induction gives `Γ ⊢ Eᵢ : Cᵢ` for each `i`.
- *Referent.* The rank induction gives `expand(r) ∈ PL` with `⟨x₁ : C₁, …, x_k : C_k⟩ ⊢ expand(r) : C_r`. WT-α — at the parameter-and-binder renaming, legitimate by the freshness just listed — yields `⟨y₁ : C₁, …, y_k : C_k⟩ ⊢ u : C_r`, where `u` is the renamed term, whose free variables are among the `yⱼ` and whose binders are fresh expansion names.
- *Weaken.* Iterated WT-W adjoins `dom(Γ)`: each variable of `Γ` is new to `⟨y₁ : C₁, …, y_k : C_k⟩` (the `yⱼ` lie outside `dom(Γ)`) and is no binder of `u` (`u`'s binders are expansion names, `dom(Γ)`'s are author names). Contexts being functions, the result is `Γ, y₁ : C₁, …, y_k : C_k ⊢ u : C_r`.
- *Substitute.* The replacement node is `u[y₁ ↦ E₁, …, y_k ↦ E_k]`; since no `yⱼ` occurs in any `Eᵢ`, the simultaneous substitution equals the sequential `[y_k := E_k]`, …, `[y₁ := E₁]`. Discharge by `k` applications of WT's PC2 plain-composition rule, last parameter first: at step `j = k, …, 1`, write `Γⱼ := Γ ∪ {y₁ : C₁, …, yⱼ : Cⱼ}`; iterated WT-W lifts `Γ ⊢ Eⱼ : Cⱼ` to `Γ_{j−1} ⊢ Eⱼ : Cⱼ` — the weakened-in `y₁, …, y_{j−1}` are fresh for `Eⱼ`, neither free in it nor binders of it — and PC2 (`Γ_{j−1} ⊢ g[yⱼ := Eⱼ] : C_r` from `Γ_{j−1} ⊢ Eⱼ : Cⱼ` and `Γ_{j−1}, yⱼ : Cⱼ ⊢ g : C_r`, ASN-0129) lowers the judgment one context at a time. No step captures — the term being substituted into has only expansion-name binders, chosen fresh for every `Eⱼ` — and no step interferes — a later target `yᵢ` occurs in no inserted `Eⱼ`, every `Eⱼ`'s free variables lying in `dom(Γ)`. After step `1`: `Γ ⊢ u[y₁ ↦ E₁, …, y_k ↦ E_k] : C_r`.

The replacement node thus carries exactly the sort WT-ref gave the node it replaces, the host derivation re-types unchanged above it, and the structural induction closes with `Γ_D ⊢ expand(a) : C_D`. Membership in PL rides the same induction: renaming preserves PL membership (the renamed term is formed by the same formers), each replacement is built from PL constituents — `expand(r)` by the rank hypothesis, the `Eⱼ` by the structural one — under PC2 composition, and PL is closed under PC2 (PC6's least-class definition); no reference node survives, so `expand(a)` is pure. ∎

**PR-VIEW (ViewTransparency).** A signed term records no view (PR-ENC) and `evaluate` takes one (PR3). PC3 (ASN-0129) gives every PL term exactly one view, fixed at the top level; expansion yields one pure term; so the view binding every view-parameterized constituent (`members`, `targets_of`, `is_K`, `M_K` — PC3's list) in every inlined referent is the evaluating *caller's*, not anything the referent's author chose. References are *view-transparent*: a referent contributes spelling, never scope — the artifact fixes the term, the reader fixes which state the term's parameterized reads see. (Motivating precedent, not load-bearing — the derivation rests on PC3 alone: Xanadu's read side already puts scope in the reader's hands, in udanax-green every link query carrying its own scope, each specset naming its own document or version per call, historical versions queryable on the same footing as current ones, with no backend-held "current" substituted for the caller's choice, and link filtering likewise front-end work, the reader's sieve; the definition layer inherits that published-artifact semantics.) An author who needs a read pinned to a slice *regardless of caller* pins it in the spelling: PC3's fixed-view constituents (`A_K`, `L_K`, `L_dom`) denote their slices at every term view, and its derivable cross-view readings (PC3, ASN-0129) respell every parameterized read through them. Call a term *view-independent* iff it contains no view-parameterized constituent and no collection-valued behavior atom on UV's rewrite list (`succs`, `sources_to`, `chain`, `stale`; the verdict-valued behavior atoms UV never rewrites are admissible): a syntactic condition, decided by the same finite scan that decides well-typing. A view-independent term's denotation is invariant in the view argument — by structural induction, PC3 and UV locate all view-sensitivity in exactly the excluded constituents — so for such a term the `view` argument is inert.

## Versioning and certification

**PR4 (VersioningBySupersession).** Definitions are never edited; they are *succeeded*. To update a predicate: register the successor (PR0), then emit `supersedes` (the shipped S2 class, ASN-0128) from the old definition's address to the new. The shipped semantics carry over without addition: `tip(a)` resolves the current version of the lineage rooted at `a`; competing successors make a branch and `tip` returns ⊥ — the multiplicity is *reported*, and adjudicating among competing updates belongs to readers (BH2's stance). A consumer wanting a stable binding pins the address; one wanting the lineage's head follows `tip` and handles ⊥.

**PR5 (DynamicsCertification).** A second validated surface — `certify_pd_stable`, its operation contract at PR5a below — classifies a registered definition against ASN-0129's PD criteria and emits a certification classifier — `pd_stable` (PS2 below). The asserted property is not literal membership in PD0's closed-term **ST** class but a parametric lift of it, written **ST⁺** and named so uniformly throughout: *per-instantiation ⊤-stability established by PD0's rules under the parameter reading* fixed in the *Parameters* qualification below — every parameter read as a bound constant of its declared sort, PD0's aggregate-threshold side condition correspondingly extended from "ℕ literal" to any bound ℕ value. ST⁺ is a *sound superset* of PD0's literal closed-term ST: every literal-ST closed term is ST⁺, ST⁺ additionally admits the parametrized terms whose every `Γ_D`-instantiation is ⊤-stable, and the two coincide exactly at `k = 0`, where the parameter reading degenerates to PD0's own statement. Three qualifications are load-bearing. *Purity*: PD0's classes are defined on *pure* PL terms, and a reference-bearing body is not one — *the certified object is the definition's expansion* (PR3, well-typed by PR3a), the pure term `expand(a)`, not the artifact's literal reference-bearing spelling. *View*: PD0's classes are view-relative — `is_K(addr)` is ST at view `audit` and flips at `active` (PD1), `M_K` is grow-only only in an audit-view term — while a definition records no view and is evaluated at the caller's (PR-VIEW), so "`expand(a) ∈ ST`" has a truth value only once a view is fixed. The surface therefore certifies only *view-independent* expansions (PR-VIEW's syntactic class, decided by the same scan that validates): such a term denotes identically at every view, and the PD0 rules open to it are the view-neutral ones — step-constants, residence, reflected-set tests, quantifiers and aggregates over the fixed-view grow-only bases `L_K` and `L_dom` and their filters — so ST⁺ membership is well-posed absolutely, and the certificate binds at every `evaluate` call whatever view the caller passes; no view index on the certificate, because the certified spelling has nothing for a view to vary. A view-parameterized spelling is refused not as unstable but as *ill-posed for certification*; its respelling through the fixed-view slices is always available (PC3's cross-view readings), and that is where an audit pin belongs anyway — in the spelling, which is the certified object. *Parameters*: PD0's classes are stated for Boolean state-predicates — terms with a truth value at each reachable Σ — while for `k ≥ 1` the expansion is in general *open*: its free variables are among the parameters `Γ_D` (PR3), and an open expansion has no truth value until an environment binds them, so "`expand(a) ∈ ST`" needs a reading on this axis just as it did on the view axis. ST⁺'s parameter reading is per-instantiation, in one move: the checker runs PD0's rules with each parameter treated as a bound constant of its declared sort — the reading PD0's side conditions give bound variables for all but one rule ("argument a literal or bound address"; step-constants "reading no state beyond already-bound values"), a parameter counting as one more already-bound value — and the certificate asserts that *every* `Γ_D`-instantiation of `expand(a)` is ⊤-stable: once true at a reachable Σ for given `args`, true at every `→_sh*`-successor for the same `args`. The lone exception is PD0's aggregate rule, whose side condition reads "ℕ literals" — strictly narrower than "bound value": it classifies `count(D) ≥ c` as ST and `count(D) ≤ c` as SF only against a literal `c`, and an ℕ-sorted parameter is no literal. The parameter reading extends that threshold position from "ℕ literal" to any *bound* ℕ value, the parameter included — without which check (iii) would silently refuse a term it ought to certify, e.g. a view-independent `count(L_W) ≥ x` with `x : ℕ` a parameter, ⊤-stable at every instantiation yet never fired by the rule run against literals alone. Soundness — of the bound-constant reading at large and of this aggregate extension alike — is PD0's own ground, which consumes only the *fixity* of bound values across a step: a bound address names the same address at both states, a bound tuple's stored value persists (L12), and a count's threshold stays put whether literal or parameter, so "a count over a growing set never decreases, so satisfied lower bounds persist and violated upper bounds stay violated" (PD0). An environment-bound parameter is exactly as fixed, the same `args` on both sides of every transition; at `k = 0` the convention degenerates to PD0's statement itself. Permanence is unimpaired: `expand(a)` is determined by immutable content alone — PR3's resolution reads nothing else, and expansion makes no free choice (PR3's determinacy) — so the certified object is one fixed pure spelling, frozen exactly as the artifact is — the certified object and the classified object coincide, at the expansion. Certification is sound-but-incomplete by design: PD0's rules are spelling-level and certify a subclass of the extensionally stable terms (ASN-0129, Open Question 5); an uncertified term is *unknown*, not unstable. What certification buys is structural checkability downstream. With both classes' from-endsets denoting definition addresses (PS1, PS2), "every registered definition carries `pd_stable`" is the one-quantifier PL term

`(A t ∈ M_pdef :: is_pd_stable(t))` — one term, view `active`

— PC1 over the QD base `M_pdef`, whose active reading is `⋃ addrs(F)` over `A_pdef^Σ` (D1): under the registration discipline (PR-DISC), exactly the registered definition addresses. The body is the `pd_stable` class's core membership atom (D2), true at `t` iff some active certificate's F covers `t` — and the coverage test is *exact* at starts: a certificate's F-coverage is `subtree(t')` (PrefixSpanCoverage, ASN-0043), and distinct content-run starts are prefix-incomparable — same-origin starts lie on one content sub-allocator chain (ChainMembershipForOrigin, ChainDiscipline, ASN-0093), distinct outputs of a single allocator, prefix-incomparable by T10a.2 (NonNestingSiblingPrefixes, ASN-0034); cross-origin starts extend prefix-incomparable anchors (ChainPrefixExtension, CrossDocumentDisjointness, ASN-0093), and a nesting `t' ≼ t` would chain both anchors onto the one tumbler `t`, two prefixes of one tumbler being ≼-comparable (Prefix, ASN-0034) — so `t ∈ subtree(t')` between starts forces `t' = t`. The exact win is the per-definition atom `is_pd_stable(t)` itself; the *universal* form needs one caveat. `M_pdef` holds every registered definition of *any* result sort — `register_pred` stores signed terms of any `C_D ∈ Codom` (PR0, PR-ENC), and a `℘_fin(T)`- or `ℕ`-valued definition, though registrable and referenceable, is rejected by certification check (0) (PR5a) *as a non-predicate* and so can never carry `pd_stable`. On every such `t ∈ M_pdef`, `is_pd_stable(t)` is permanently false, and the universal lint is *vacuously* violated the moment one is registered — for a legitimate reason (a referenced `℘_fin(T)` helper, say), not a missing certificate. PL cannot narrow the domain to repair this: restricting `M_pdef` to Boolean predicates would read each definition's result sort, which is `sig`/content-derived and outside PL's read surface (ASN-0129, Structural reads only; PC4 reads only `dom(Σ.M), Σ.L, Σ.registry`). The universal form is therefore a *definition*-level certification check, conflating "uncertified predicate" with "legitimately non-predicate" — sound as a predicate-coverage lint only where the domain is known to hold predicates alone. Scoping the lint to a protocol is a QD filter over `M_pdef` (the protocol's own membership classifier); either way it is one quantifier, decidable at every reachable state (PC5), evaluable by anyone. Permanence for the certificate slice is stated and proved at PR5a: the certified expansion can never change, so a certificate never expires.

**PR5a (CertificationSurface).** The operation, to PR0's standard. The surface exposes `certify_pd_stable(d, a)`: *validate, then emit through the `pd_stable`-class emit it wraps*, returning the certificate tuple's address. It is a separate call, not a mode of `register_pred`: registering and certifying a definition is two calls in sequence, each validated on its own, so a failed certification leaves the registration it follows standing — rejection scope is the certificate alone. *Validation* runs in full on every call — hit or miss, I1's gate-first order — at the call state Σ, in this order:

(0) *Predicate sort*: `sig(a)` is defined with Boolean result sort — `sig(a) = (Γ_D, Bool)`. This presupposes `a` ever-registered, `sig`'s domain (PR-SIG); a never-registered run fails here, `sig(a)` undefined — for a reference-bearing run not even a contentual reading could supply it. The check fixes what *predicate* means for certification: `register_pred` stores signed terms of *any* result sort `C_D ∈ Codom` (PR0, PR-ENC), but only the Boolean-sorted ones are predicates carrying a PD class — ST is a class of Boolean terms (PD0, ASN-0129) — so a `℘_fin(T)`- or `ℕ`-valued definition, though a well-formed, registrable, referenceable artifact, has no stability to assert. Failure here is rejection *as a non-predicate* — a term that was never a predicate at all, a third category distinct from both (ii)'s ill-posed (view-dependent) and (iii)'s unknown (Boolean but not provably ST).

(i) *Target status*: `a` is *actively* registered — some `(b, F, G) ∈ A_pdef^Σ` with `addrs(F) = {a}`. (0) already made the certified object well-defined — ever-registration is all `sig(a)` and `expand(a)` need (PR-SIG, PR3) — but the surface demands the *active* slice for the same reason PR0 (iv) does: a certificate is a new endorsement, and new endorsements are not issued against withdrawn registrations. A de-registered definition fails (i); to certify it, re-register it first.

(ii) *Well-posedness*: `expand(a)` — well-defined under (i) — is view-independent: PR-VIEW's syntactic scan, no view-parameterized constituent and no UV-rewritten collection atom. Failure is rejection *as ill-posed*, not as unstable (PR5's distinction): a view-dependent spelling has no absolute PD class to certify.

(iii) *Class membership*: the checker's verdict `expand(a) ∈ ST⁺` (PR5) by PD0's rules — parameters read as bound constants of their declared sorts, the verdict asserting ⊤-stability of every `Γ_D`-instantiation (PR5's *Parameters* qualification). By (0) the term reaching (iii) is genuinely Boolean, so the verdict turns on *stability*, never sort. Failure is rejection; the definition stays registered, merely uncertified — *unknown*, not unstable: a genuine Boolean predicate whose ST membership is merely unproven, the category (0) is at pains to separate from a non-predicate.

Checks run in the stated order; the first failure rejects — no step, no tuple, no address — and rejection asserts nothing about the definition or any standing certificate (the enforce-by-rejection stance, PR0's). The four checks carry four distinct verdicts: (0) non-predicate, (i) not-actively-registered, (ii) ill-posed, (iii) unknown — only (iii) a claim about stability, and only it leaving a genuine predicate merely uncertified. On success the surface invokes the wrapped `Emit_pd_stable(Σ, d, {a}, ∅)` — Unary shape conformant by construction (`|F| = 1`, `G = ∅` — Sh-conf, ASN-0126), `pd_stable ≁ R` by the construction-time non-collision check, so the gate admits — under I1's idem-⊤ contract: all certificates for one definition are I0-equal (slot-F coverage `subtree(a)`, slot-G coverage empty), so a *hit* — an active certificate already denoting `a` — returns the incumbent's address, no step taken, `d` unread; a *miss* with `d ∈ dom(Σ.M)` deposits `(enc({a}), ∅, pd_stable)` at the frontier address `a_emit(Σ, d)`; a miss with `d ∉ dom(Σ.M)` is rejected. After a certificate's retraction the dedup sees an empty class (I2) and re-certification — re-validated in full — deposits afresh at a new address. The wp mirrors PR0's, the already-certified disjunct likewise lifted clear of `CVALID`: for `POST-cert ≡ (E (b, F', G') ∈ A_pd_stable^{Σ'} :: addrs(F') = {a})`, on registration-disciplined derivations (PR-DISC) `wp(certify_pd_stable(d, a), POST-cert) ≡ (E (b, F', G') ∈ A_pd_stable^Σ :: addrs(F') = {a}) ∨ (CVALID(Σ, a) ∧ d ∈ dom(Σ.M) ∧ C3(Σ, d))`, with `CVALID` the conjunction (0)–(iii). The partition is PR0's: an already-active certificate denoting `a` makes POST-cert hold at `Σ'` whether a re-certifying call hits (`Σ' = Σ`, incumbent returned) or is rejected (`Σ' = Σ`, incumbent standing) — the case a later de-registration of `a`'s `pdef` tuple realizes, `CVALID` failing at (i) while the standing certificate persists; absent such a certificate, POST-cert demands a fresh deposit landing active, hence `CVALID ∧ d ∈ dom(Σ.M) ∧ C3`. The discipline supplies canonical shaping at the hit (every `pd_stable` tuple entered through this surface, its F the canonical encoding of one start) and C3's necessity at the miss, exactly as at PR0, and C3 vanishes on surface-disciplined derivations (DR).

*Permanence for the slice* — PR1's analogue, same proof shape. At any state Σ reached by a registration-disciplined derivation (PR-DISC), if `(b, F, G) ∈ L_pd_stable^Σ` with `addrs(F) = {a}`, then at the deposit's pre-state `a` was actively registered — with `sig(a)` Boolean, condition (0) — `expand(a)` was view-independent, and `expand(a) ∈ ST⁺` held, and these facts are permanent. The runs under `a`'s reference DAG never drift (PR1's per-step content induction), so `expand(a)` is the same concrete term at every state (PR3's determinacy); view-independence is a syntactic property of that fixed term; the ST⁺ verdict is PD0's classification of that fixed spelling under PR5's parameter reading; and the Boolean sort is fixed at `a`'s first registration (`sig`, PR-SIG) — none of these reads anything that can change. A certificate is a permanent proof of certification, exactly as a `pdef` tuple is of validation. (What is *not* permanent is the target's active registration: a later de-registration leaves the certificate active while the condition-(i) fact recedes into history — harmless to the lint, whose quantification domain `M_pdef` at view `active` drops de-registered definitions.)

## Standard registrations

This note extends the substrate's shipped classes (ASN-0128, Standard registrations) with two designated coverage classes, under the same parameterization and the same R-C1-style pairwise non-collision checks at construction:

**PS1 (PredicateDefinition).** `pdef` — Multi, idem=⊤, behaviors=∅. Slot convention: F = `enc({a})` denotes the definition's address — identity by start — and G = `enc(A_def)` denotes its run. Marks a content run as a validated predicate definition. The Multi shape is what makes both facts recoverable *by denotation* — `addrs(F) = {a}` and `addrs(G) = A_def` — where a single merged span over the run would denote nothing, AD collecting unit-depth spans only. Idempotent (idem=⊤): dedup is by I0 coverage identity on both slots — same start, same run — with the hit, validation-first rejection, and post-de-registration re-deposit dynamics PR0's contract (and PR-DISC), not restated here. No read-filter: a definition is not presentation-layer state.

**PS2 (StabilityCertificate).** `pd_stable` — Unary, idem=⊤, behaviors=∅. Slot convention: F = `enc({a})`, the certified definition's address; G = ∅ (Unary). Asserts **ST⁺** certification of the *expansion* — view-independent, per PR5 — of the definition at `a`: per-instantiation ⊤-stability under PD0's rules (ASN-0129) with PR5's parameter reading, a *sound superset* of literal PD0-ST (not literal ST-class membership), the two coinciding only at `k = 0`. Emitted only by `certify_pd_stable` (PR5a), through the wrapped `Emit_pd_stable(Σ, d, {a}, ∅)` — a monopoly the entry-point seal below *enforces* rather than assumes; the assertion discipline is thereby the surface's mechanically, the tuple merely durable.

*Entry points — the seal.* Both classes are surface-sealed, S3's pattern (ASN-0128): the exposed `Emit_K` rejects every `pdef`-class and every `pd_stable`-class call by the same uniform class-exclusion mechanism that rejects R-class calls — the uniform precondition extends from `K ≁ R` to `K ≁ R ∧ K ≁ pdef ∧ K ≁ pd_stable`, fixed at construction with the designations themselves — so `register_pred` is the one surface route into the `pdef` slice and `certify_pd_stable` (PR5a) the one into `pd_stable`, exactly as `Nullify_Binary` is the one retraction entry point. The seal is what makes the registration discipline (PR-DISC) a fact about the shipped surfaces rather than an assumption: without it, a direct `Emit_pdef` call — admissible at the bare Multi gate, which reads span counts, never content — could mint an unvalidated classifier through a shipped surface. ASN-0128 closed the identical hole for [R] structurally; this note closes its two the same way.

Retraction interacts with both classes through the shipped machinery and nothing else: a `Nullify_Binary` aimed at a `pdef` tuple's address *de-registers* the definition — the tuple leaves `A_pdef^Σ`, every "is this registered" query flips, and PR0's condition (iv) thereafter refuses new references to it — while the audit slice keeps the full history (a de-registered definition is recoverable evidence, not erased content; the run itself is untouched and untouchable). De-registration does not cascade: previously registered referencing definitions validated against their own deposit pre-states, and PR1's proof concerns those states; evaluation likewise survives, PR3's precondition being an audit-slice fact. Whether dangling *live* references (a registered definition referencing a since-de-registered one) should be surfaced, tolerated, or blocked is genuinely open (Open question 3).

## Worked composition

A builder registers a base predicate and a successor, certifies the successor, and a consumer evaluates by lineage head.

1. *Author.* The builder appends the encoded term of `quiescent_v1` — signature `⟨t : T⟩ → Bool`, body `¬(E x ∈ A_W :: t ∈ coverage_F(x))`, "no active assignment of the builder's work class covers `t`" (`W` a Binary class registered at construction); the one state read is the fixed-view active-slice base `A_W` (PC3), so the term is view-independent (PR-VIEW) — to the builder's document `d_b` as a sequence of `n₁` K.α steps scoped to `d_b`, one content value per step. Each subsequent step lands at `inc(·, 0)` of its predecessor on `d_b`'s content sub-allocator chain (K.α's subsequent-emission clause, ASN-0093), so with no other K.α scoped to `d_b` interleaved, the keys form one chain segment — the run `A₁ = {shift(a₁, k) : 0 ≤ k < n₁}` starting `a₁`, by PR-ENC's identity `shift(·, 1) = inc(·, 0)`; steps scoped to other documents, and `d_b`'s own link-chain deposits, land on disjoint chains (CrossDocumentDisjointness, DisjointSubAllocatorChains, ASN-0093) and cannot split the segment. (The implementation grounds the picture: udanax-green mints a single insertion's I-addresses as one uninterrupted run — the start located once, a cursor advanced linearly — with cross-document traffic allocating in disjoint subspaces; the abstract substrate is cleaner still, its link chain disjoint from its content chain, where the implementation's same-subspace link allocation can split runs across *separate* insertions.) `register_pred(d_b, A₁)` validates — parses, well-types, no references — and the wrapped `Emit_pdef(d_b, {a₁}, A₁)` deposits the tuple `(enc({a₁}), enc(A₁), pdef)`.
2. *Reference.* A second term `gate` — signature `⟨t : T⟩ → Bool`, body `a₁(t) ∧ count({x ∈ A_H : t ∈ coverage_F(x)}) ≤ 3`, "quiescent and holding at most three active leases" (`H` the builder's lease class, Binary, registered at construction) — carries the first conjunct as an *applied reference*, typed `Bool` by WT-ref against `sig(a₁)`; the second conjunct is genuine inline PL — a QD filter over the fixed-view tuple base `A_H` with V-TUP's coverage test, `count` by PC2a, the comparison V-PRIM's `≤` against the literal `3` — so the body well-types with one reference node and no vocabulary beyond ASN-0129's. The name coincidence — `gate`'s parameter is `t`, and so is `quiescent_v1`'s recorded parameter — is exactly the collision PR3's renaming discipline absorbs: at expansion the referent's `t` is renamed to a fresh expansion name before the argument, the host's `t`, is substituted for it, so the two `t`s never meet in one scope. Registration validates condition (iv) against `A_pdef^Σ` — `a₁ ∈ addrs(F)` of the standing tuple — and succeeds. The reference points backward in first-registration order necessarily (PR2).
3. *Update.* The builder registers `quiescent_v2` at run `A₂` starting `a₂` and emits `supersedes` from `a₁` to `a₂`. Now `tip(a₁) = a₂`; `gate` still references `a₁` — pinned semantics, by address — while a lineage-following consumer evaluates `tip(a₁)` and gets v2. Both behaviors are correct; the choice is the consumer's, visible in their own term.
4. *Certify.* `certify_pd_stable(d_b, a₁)` clears PR5a (0)–(ii) — `a₁` is Boolean-sorted (a predicate, `sig` result sort `Bool`), actively registered, and `expand(a₁)`, here the body itself (reference-free), is view-independent, its one state read the fixed-view `A_W` base — so v1's PD class is well-posed, and the call is rejected at (iii): the term is not ST, the active slice not being grow-only — an active-slice test can flip back (PD1, ASN-0129) — so certification is correctly *refused*, the standing registration untouched (PR5a's rejection scope). The builder's v2 respells the terminator the Marker way: body `(E x ∈ L_M :: t ∈ coverage_F(x))`, true once a completion marker of the builder's marker class `M` has been emitted for `t` — an existential over the grow-only audit-slice base `L_M` whose V-TUP body is step-constant precisely under PR5's parameter reading, the free `t` entering as a bound constant of sort `T` — one more of PD0's already-bound values — fixed-view hence again view-independent, in **ST⁺** by the quantifier rule, the certificate asserting ⊤-stability per instantiation of `t`. `certify_pd_stable(d_b, a₂)` clears all four checks — classifying `expand(a₂)`, again the body itself — and the wrapped `Emit_pd_stable(d_b, {a₂}, ∅)` deposits the certificate. The contrast is the lesson the certificate teaches: a terminator that *tests live state* can un-terminate; a terminator that *tests for a recorded event* cannot — and the lint distinguishes them structurally, before anything runs.
5. *Adversary check.* A registration whose term references the unallocated `a₃ = shift(a₂, n₂)` (the frontier) is rejected at condition (iv) — no active tuple denotes `a₃`; here the address is not even resident, and (iv) asks for strictly more than residence: a registered referent is resident (its own deposit's condition (i), carried forward by C0), but a resident, parse-valid, *unregistered* run still fails (iv). The registration check (iv) closes the frontier-ghost hazard for definitional references: no definition can come to mean something by a *later* allocation.

## What this note doesn't cover

- **The concrete encoding.** PR-ENC fixes the discipline (injective, prefix-free, decidable self-delimiting parse, recorded signature contexts, a reserved expansion-name supply); the byte format is a substrate parameter for the implementation to fix, as with subspace identifiers. Typing decidability is not an encoding property — it belongs to WT + WT-ref (PR-SIG).
- **Activation.** Binding predicates to emissions ("when P, emit E") — the trigger primitive — remains protocol-layer territory outside the corpus (ASN-0129's fence), now with one improvement available to it: the P it binds can be a `pdef` address rather than an inline term.
- **The certifier's internals.** PR5 and PR5a commit the certificate's meaning, operation contract, and permanence, not the checking algorithm; soundness of the syntactic check is ASN-0129's Open Question 5, inherited.

## Open questions

1. **Name relations.** Identity is by address; human-facing naming (a Binary `pname` from name-content to definition) was considered and deferred — names introduce collision politics (who owns "quiescent"?) that addresses dissolve. Should a shipped naming class exist at all, or is naming app-side convention as type labels are (ASN-0126)?

2. **Cross-substrate portability.** A definition's references are addresses in *this* docuverse. Republishing a predicate library on another substrate re-allocates every run and rewrites every reference — a deep-copy with address translation. Is there a portable identity layer (content-hash manifests as un-registered metadata?), or is portability an application concern?

3. **Dangling live references.** De-registration (retraction of `pdef`) can leave registered definitions referencing de-registered ones. Evaluation still works (the content persists; PR3 reads content, not registration), but the reference now crosses a revoked endorsement. Should evaluation-by-reference check registration *transitively* at evaluation time, only at registration (status quo), or should a `pdef` retraction be rejected while live referents exist?

4. **Certificate classes beyond ST.** `pd_stable` ships; certificates for SF (the ⊥-stable spellings), frame-stability footprints (FP, ASN-0129), or view independence as a standalone class (PR-VIEW's scan, currently PR5a's check (ii)) could follow. Each is a new designated class — the catalog-growth question (ASN-0128, Open Question 5) instantiated at the certification layer.
