# ASN-0130: Predicate Definitions as Substrate Content

*Terms as artifacts — storing, validating, referencing, versioning, and certifying PL predicates in the docuverse itself.*

ASN-0129 defines the predicate language: what terms exist, what they mean, what they cannot express, and how their truth moves. Its terms, however, are meta-level objects — the note says well-typing is decidable but gives terms no existence inside the system. This note closes that gap the Xanadu way: a predicate definition is *content* — an immutable run of I-addresses holding a serialized PL term — registered by a classifier tuple, referenced by address, versioned by supersession, and certified by further tuples. The predicate system becomes self-hosting on the links it queries: a builder's protocol definitions are themselves linkable, citable, supersedable documents, and the platform's validation guarantees attach to them once, permanently.

Three foundation facts make the design nearly free, and the note's work is mostly to compose them. Content is immutable and permanent — the strand model's S0/S1 guarantee, re-derived per step of the gated substrate in PR1 — so a validated definition can never drift: validation at registration is validation forever. Identity is by origin, not value (S4, ASN-0036), so definitions are identified by address, dissolving the naming and equality problems a name-keyed registry would import. And registration events are totally ordered along any derivation, so definitional references — required to name *already-registered* definitions — can only point backward in first-registration order, making the reference graph a DAG by construction and definitional expansion terminating without any cycle check.

**Depends:** ASN-0034 (Tumbler Arithmetic), ASN-0036 (Strand Model), ASN-0043 (Link Ontology), ASN-0086 (Typed Relations on Address Sets), ASN-0093 (Allocation Substrate), ASN-0126 (Substrate Shape Framework), ASN-0128 (Substrate Type Operational Semantics), ASN-0129 (Substrate Predicate Composition).

## What this note commits

- **The definition artifact.** A predicate definition is a contiguous content run holding an encoded *signed* PL term — a recorded parameter signature plus a body — identified by the run's start address, an identification well-defined because the encoding discipline is *prefix-free* (PR-ENC). The encoding is otherwise treated abstractly; what is fixed is that the parse is self-delimiting and that parsing and well-typing are decidable — the latter by ASN-0129's WT extended with one rule for applied definitional references (PR-SIG).
- **Registration as a validated emit** (PR0): the operation surface validates the encoded term — parse, well-type, *registered references only* — and on success deposits the `pdef` classifier through the emit it wraps; on failure it rejects, no tuple — exactly the R-VAL/P-tgt pattern of validating where the operational layer can and the static gate cannot. The exposed `Emit_K` rejects `pdef`- and `pd_stable`-class calls outright (the entry-point seal, S3's pattern), so the validated surfaces are the only surface routes into either slice. The success postcondition is stated against the born-nullified boundary, with the weakest precondition for referenceability supplied — scoped to disciplined derivations — and on them success and referenceability coincide.
- **Validation permanence** (PR1): a `pdef` tuple's existence is a permanent proof that its run validated — the content store is framed or fresh-extended at every step of the substrate relation, so by induction along any derivation the run's values never drift and the validation can never go stale. No runtime re-validation path exists or is needed.
- **Acyclic reference by construction** (PR2): definitions reference other definitions by address; registration requires referenced definitions to be already registered, so references point strictly backward in *first-registration* order — stated event-wise, robust to de-registration and re-registration — the reference graph is a DAG, and expansion terminates, preserving ASN-0129's PC6a under definitional reference without a cycle check.
- **Evaluation by reference** (PR3): `evaluate(a, args, view, Σ)` — precondition: `a` ever-registered (an audit-slice fact); `args` a signature-respecting environment — resolves content to a term by the self-delimiting parse, expands through the reference DAG with capture-avoiding substitution into a pure term well-typed at the recorded signature (PR3a), and evaluates per ASN-0129 at the caller's view — references are *view-transparent*, the artifact fixing the term and the reader the scope (PR-VIEW) — inheriting purity, termination, and the ceiling unchanged.
- **Versioning by supersession** (PR4): definitions are immutable; updating one is registering a successor and emitting the shipped `supersedes` relation (S2, ASN-0128) — `tip()` resolves the current version, a branch is a ⊥ verdict surfaced to readers, exactly the shipped semantics with no new machinery.
- **Dynamics certification** (PR5): the registration surface may additionally certify a definition's PD class (ASN-0129, PD0–PD2) by emitting a certification classifier — making "is this termination predicate certified ST" itself a one-atom PL query, the check ASN-0129's Open Question 5 anticipates, recorded as substrate fact. The certified object is the definition's *expansion* — PD0's classes are defined on pure terms — itself a frozen, content-determined spelling (S0), so the certificate attaches to a fixed object, permanently; and certification is restricted to *view-independent* expansions (PR-VIEW), so the asserted class is well-posed and binds at every call view.

## The definition artifact

**PR-ENC (EncodingDiscipline).** An *encoding* is an injective map from *signed* PL terms — a pair of an ordered, sorted parameter context `Γ_D = ⟨x₁ : C₁, …, x_k : C_k⟩` (each `Cᵢ ∈ Codom`, COD of ASN-0129; `k = 0` for closed terms) and a body in ASN-0129's syntax extended with *definitional references* (PR-SIG), well-typed as `Γ_D ⊢ body : C_D`, and no view component (deliberately: definitions are view-polymorphic, the view bound per evaluation, PR-VIEW) — to finite content-value sequences, with a decidable parse, decidable well-typing of the decoded term, and one further discipline the rest of the note leans on: **prefix-freeness** — no valid encoding sequence is a proper prefix of another; equivalently, the parse is *self-delimiting*, determining its own extent from its start. The concrete encoding is a substrate parameter, like the subspace identifiers and the designated standard classes (ASN-0128, Standard registrations); this note fixes the discipline, not the bytes. A *definition artifact* is a contiguous run `A_def = {shift(a, k) : 0 ≤ k < n}` (`n ≥ 1`) of content addresses holding a valid encoding, identified by its start `a` — *the definition's address*. The run is one segment of `a`'s origin K.α chain (ASN-0093), because on T4-valid content addresses `shift(x, 1) = inc(x, 0)`: `inc(x, 0)` rewrites exactly the sig position (TA5(c), ASN-0034), which for a T4-valid tumbler is the terminal position `#x` (TA5-SigValid), while `shift(x, 1) = x ⊕ δ(1, #x)` (OrdinalShift, ASN-0034) agrees with `x` everywhere except adding one at that same terminal position — the same tumbler. Identification by start is well-defined exactly because of prefix-freeness:

**PR-ENC-uniq.** At most one valid run starts at any address: were `{shift(a, k) : 0 ≤ k < n}` and `{shift(a, k) : 0 ≤ k < n'}` both valid with `n < n'`, the shorter's value sequence would be a proper prefix of the longer's — both valid encodings — contradicting prefix-freeness. (Runs may still *overlap*: a suffix of a run may itself decode. That is harmless — identity and resolution are start-anchored (PR3), so a definition starting mid-run is a different definition at a different start, never confused with the containing one.)

By S0/S1 (ASN-0036) the run's values are fixed and permanent from allocation; by S4, two registrations of byte-identical terms at different runs are distinct definitions — identity is by origin, and term-equality questions are extensional questions ASN-0129 already classifies as open theory, not identity.

**PR-SIG (SignaturesAndReferences).** The *signature* of the definition at `a` is `sig(a) = (Γ_D, C_D)`: the parameter context the artifact records and the result sort WT derives for its body — unique, WT being syntax-directed. `sig` is a function of immutable content (S0), defined wherever a valid run starts. The syntax PL gains is the *applied reference*: for an address `a` and terms `e₁, …, e_k`, the form `a(e₁, …, e_k)`, bare `a` when `k = 0`. Its typing rule, extending WT (ASN-0129):

**WT-ref.** For a context `Γ`, an address `a` with `sig(a) = (⟨x₁ : C₁, …, x_k : C_k⟩, C_D)`, and `Γ ⊢ eᵢ : Cᵢ` for each `1 ≤ i ≤ k`: `Γ ⊢ a(e₁, …, e_k) : C_D`.

WT-ref makes the typing judgment relative to the artifact store — the one read ASN-0129's state-free typing pass acquires — but a harmless one where PR0 invokes it: condition (iv) requires each referenced `a` already registered, so the consulted `sig(a)` exists (a registered run parses, PR1), is read off by the terminating self-delimiting parse, and never changes (S0). The pass remains a syntax-directed finite tree walk with one finite signature lookup per reference node — decidable, its verdict state-stable once the referents exist. A body well-types under its own `Γ_D` alone, so its free variables are among its parameters; the binders *inside* a body are ASN-0129's own (PC1/PC2a domains, PC2's binder guard), and any collision between a referent's binders and an argument's free variables is an expansion concern, resolved there by renaming (PR3) — typing never confronts it.

## Registration

**PR0 (DefinitionRegistration).** The operation surface exposes `register_pred(d, A_def)`: *validate, then emit through the `pdef`-class emit it wraps*, returning the classifier tuple's address. *Validation* runs in full on every call — hit or miss, I1's gate-first order (ASN-0128) extended to the surface's own precondition — at the call state Σ, writing `a := min(A_def)` (T1) and `n := |A_def|`: (i) the run is resident and chain-contiguous — `A_def ⊆ dom(Σ.C)` and `A_def = {shift(a, k) : 0 ≤ k < n}`, one segment of one origin's K.α chain (PR-ENC); (ii) the run's values are exactly one valid encoding — the self-delimiting parse from `a` succeeds and consumes precisely the presented extent, and by PR-ENC-uniq no other extent could; (iii) the decoded signed term well-types, `Γ_D ⊢ body : C_D`, under WT plus WT-ref (PR-SIG) — each reference node's signature read from its referent's artifact, well-defined whenever (iv) holds, the surface checking (iii) and (iv) jointly; (iv) every definitional reference names an *already-registered* definition: for each referenced address `r`, some `(b, F, G) ∈ A_pdef^Σ` (the active slice of the `pdef` class, ASN-0086's typed-relation machinery as surfaced by ASN-0128) with `r ∈ addrs(F)`. On any validation failure the call is rejected — no step, no tuple, no address, *even when an I0-equal active tuple exists*: rejection of a call asserts nothing about a standing registration. This is the enforce-by-rejection stance ASN-0128's S3 takes for P-tgt, and for the same reason: the static gate cannot read content, but the operational layer can, and admitting an invalid registration would mint a durable classifier whose meaning (PR1) would be a lie.

On success the surface invokes the `pdef`-class emit it wraps — I1/I6's idem-⊤ contract (ASN-0128), reachable only through this wrapper by the entry-point seal (Standard registrations below) —

`Emit_pdef(Σ, d, {a}, A_def)`

whose deposited endsets are the canonical encodings `F = enc({a})` — one unit-depth span denoting the definition's address — and `G = enc(A_def)`, the run; both are recoverable by denotation, `addrs(F) = {a}` and `addrs(G) = A_def` (AD, ASN-0128). Shape conformance holds by construction — `pdef` is Multi (PS1): `|F| = 1`, `|G| = n < ∞` — and `pdef ≁ R` by the construction-time non-collision check, so the gate admits every validated call, and I1's `idem = ⊤` contract supplies the branch: a *hit* (some I0-equal tuple in `A_pdef^Σ`) returns the incumbent's address, no step taken, `d` unread; a *miss* with `d ∈ dom(Σ.M)` deposits `(enc({a}), enc(A_def), pdef)` at the frontier address `a_emit(Σ, d)`; a miss with `d ∉ dom(Σ.M)` is rejected.

*Discipline and uniqueness.* Call a derivation *registration-disciplined* iff every `L_pdef`-growing step along it is the deposit branch of a `register_pred` call and every `L_pd_stable`-growing step the certification branch of PR5 — the per-class surface-discipline shape of ASN-0128 (SD, I1a). Every `register_pred` deposit is an `Emit_pdef` deposit branch, so a registration-disciplined derivation is pdef-surface-emitted in I1a's sense — discharging I1a's premise, so I1a applies: at most one active `pdef` tuple per I0 class at every state reached. Prefix-freeness sharpens the unit to the one references use: all validated runs at one start coincide (PR-ENC-uniq), so all validated tuples at one start are I0-equal — *at most one active registration per definition address*. The note's downstream claims — PR0's wp equivalence (its C3 form needs registration discipline, its reduced form surface discipline besides; both uses are flagged where they occur), PR1, PR2, PR5's lint reading, PS1's dedup reading — are scoped to derivations that are registration-disciplined and surface-disciplined (SD, ASN-0128); a derivation driven entirely through the shipped surfaces is both, and *enforcedly* so: the entry-point seal (Standard registrations) extends the exposed `Emit_K`'s uniform class exclusion to `pdef` and `pd_stable` — S3's pattern (ASN-0128), the same move that makes `Nullify_Binary` the one retraction entry point and licenses SD's reading there — so `register_pred` and PR5's certification path are the only surface routes into those slices, and every surface-driven `L_R`-growing step remains a `Nullify_Binary`.

*Success, precisely — the born-nullified boundary and the wp.* "Registered" in this note means *active* membership — condition (iv) reads `A_pdef^Σ`. A gate-clearing miss deposits into `L_pdef^{Σ'}` unconditionally but lands in `A_pdef^{Σ'}` only if C3 holds — no pre-existing retraction tuple's to-coverage contains `a_emit(Σ, d)` (I3, ASN-0128). Under a prior *range* retraction covering that frontier slot, the deposit is *born nullified* (RangeSterilization, ASN-0126): validation passed, tuple deposited, definition never referenceable. On surface-disciplined derivations this cannot happen — DR (ASN-0128) empties C3's existential — so there success and referenceability coincide. The weakest precondition, in I6's form, for the postcondition that the registration is *referenceable*,

`POST-ref ≡ (E (b, F', G') ∈ A_pdef^{Σ'} :: addrs(F') = {a})`

is — *on registration-disciplined derivations; the equivalence is not unscoped, both directions drawing on the discipline at the two points flagged below* —

`wp(register_pred(d, A_def), POST-ref) ≡ VALID(Σ, A_def) ∧ (hit(Σ, a) ∨ (d ∈ dom(Σ.M) ∧ C3(Σ, d)))`

with `VALID` conditions (i)–(iv) and `hit` I1's branch condition at the `pdef` class. Reading the branches: a `VALID`-failing call, and an admitted miss with `d ∉ dom(Σ.M)`, are rejections — wp false under I6's attainability convention. A hit satisfies POST-ref at `Σ' = Σ` from the incumbent — I0-equal and, *first use of the discipline*, canonically shaped: every tuple at one start entered as a `register_pred` deposit, so `F' = enc({a'})` for its own start with `subtree(a') = coverage(F') = subtree(a)` forcing `a' = a`. Off-discipline this direction fails: an I0-equal incumbent may carry `F'` with unit spans at `a` and at an extension `a.x` — `coverage(F') = subtree(a)` by subtree absorption, yet `addrs(F') = {a, a.x} ≠ {a}` (I0a's separating pair, ASN-0128) — so `VALID ∧ hit` would hold while POST-ref fails. An admitted miss deposits and lands active iff C2 ∧ C3 (I3), where C2 holds outright (`pdef ≁ R`), leaving C3 — whose *necessity* is the second use: at a miss no active I0-equal incumbent exists, and canonical shaping turns that into *no active tuple denoting `a` at all*, so a born-nullified deposit (¬C3) leaves POST-ref false. Off-discipline this direction fails too: a pre-existing raw tuple with `F'' = enc({a})` and an unrelated `G''` is no hit — not I0-equal — yet satisfies POST-ref at `Σ'` while the formula reads false. On derivations additionally surface-disciplined, C3 vanishes (DR) and the wp reduces to

`wp(register_pred(d, A_def), POST-ref) ≡ VALID(Σ, A_def) ∧ (hit(Σ, a) ∨ d ∈ dom(Σ.M))`

Validation reads content values — `Σ.C(a)` dereferences — which PL itself is forbidden (ASN-0129, Structural reads only). There is no contradiction: validation is an *operation*, surface-level work whose product is a structural fact (the tuple) that PL *can* read. The division of labor is the note's central move: content is dereferenced only at the operation surface — at registration to validate, and at resolution and expansion (PR3) to read terms whose validity the standing tuple already proves — and never inside PL evaluation itself, where the structural-reads-only boundary (ASN-0129) holds untouched.

**PR1 (ValidationPermanence).** At any state Σ reached by a registration-disciplined derivation, if `(b, F, G) ∈ L_pdef^Σ`, then the run `addrs(G)`, with start `addrs(F) = {a}`, held a valid encoding at its deposit's pre-state — and holds the same values at Σ and at every `→_sh*`-successor. Deposit-state validity is the discipline itself: the tuple entered at a `register_pred` deposit, whose validation (i)–(iv) had just passed. Permanence is per-step plus induction, not a single transfer. Each step of the substrate relation either frames the content store outright — K.σ and K.λ_sh carry `Σ'.C = Σ.C` in their frames (GatedTransitionRelation, ASN-0126; R-TR, ASN-0128) — or is a K.α step, whose content effect is `C' = C ∪ {a' ↦ v}` at a key fresh against `dom(Σ.C)` (K.α's binding precondition with emission freshness, ASN-0093), leaving every existing binding intact: these are C0's per-step clauses (ASN-0093) read against `→_sh`. So every single step preserves the residence and value of every already-stored content address, and induction along the derivation from the registering state carries the run — resident, values fixed — to Σ and to every successor. The tuple itself persists with its value fixed the same way: L12 is a transition invariant, crossing each genuine `→_sh` step by B2's transition-invariant clause with RP-b (ASN-0128), inducted along the derivation. A `pdef` tuple is therefore a *permanent proof of validation*: no re-validation path exists at runtime because none is needed — staleness would require the content to change, and the substrate has no operation that changes content. (Contrast every system whose code artifacts are mutable: there, validation is a cache; here it is a fact.)

**PR2 (AcyclicReference).** Under PR0's discipline, deposits into the `pdef` class are `→_sh` steps, totally ordered along any derivation (SequentialAtomicTransitions, ASN-0093). One definition may carry *several* deposit events: de-registration re-opens registration — after a `Nullify_Binary` on a run's tuple, the dedup sees an empty class (I2, ASN-0128) and a later `register_pred` for the same run deposits afresh — so "registration order" is an order on *events*, not a function of definitions, and the acyclicity argument must be run event-wise. For an ever-registered definition D — a start address carrying at least one `pdef` deposit along the derivation — write `e₁(D)` for its *earliest* deposit event; D's term, hence D's reference set, is the same at every one of D's deposit events (the run is content-immutable, and the prefix-free parse returns the same term every time). Two observations close the argument:

(a) *Every deposit event sees each referent registered strictly earlier.* A deposit is the miss branch of a `register_pred` whose validation (iv) had just passed at the pre-state: each referenced address `r` carries an active tuple there, which entered `L_pdef` at some strictly earlier deposit event — a deposit event *for the definition at* `r`, since that tuple's F denotes `r` and so its run starts at `r`. Hence `e₁(r) <` the current event; instantiating at D's earliest event, `e₁(r) < e₁(D)`.

(b) *Self-reference fails at every deposit event.* Deposits occur only on a dedup miss, and all validated tuples at one start are I0-equal (PR-ENC-uniq), so at a deposit event for D every existing tuple denoting D's start is inactive — and the depositing tuple does not yet exist during its own validation. Condition (iv) therefore has no witness for a reference to D's own start: a self-referencing term is rejected at every would-be deposit event, and by induction along the derivation it is never deposited at all — nor can such a call ever be answered by a hit, since a hit requires an active incumbent whose own deposit the same argument excludes.

The reference relation on ever-registered definitions thus embeds in the strict order `e₁(r) < e₁(D)` — irreflexive, acyclic, a DAG with no cycle check ever run. (Note the order is *registration* order, not allocation order: a run may be allocated long before it is registered, so the runs' allocation order constrains nothing.) *Consequently definitional expansion terminates*: expansion (PR3) descends reference edges, `e₁` strictly decreasing among the finitely many deposit events (L-fin bounds them), each term finite; the expanded result is a pure PL term (no references), and ASN-0129's PC6a is preserved — mutual recursion among definitions is not merely banned, it is *unconstructible*: the would-be second member of a cycle cannot validate before the first is deposited, and the first refers only to definitions first-registered earlier than itself. (Ghost references — L4/L9 endset generality, ASN-0043 — are exactly what condition (iv) excludes for *references inside terms*; the endsets of the `pdef` tuple itself remain ordinary endsets with ordinary semantics.)

**PR3 (EvaluationByReference).** Three layers, each pinned. *Resolution* — address to signed term: read content values from `a` along its origin chain — successive addresses `shift(a, k)`, the chain's `inc(·, 0)` siblings (PR-ENC) — feeding the self-delimiting parse, which determines the run's extent from content alone and yields `(Γ_D, body)`. Resolution consults no slice and no tuple: the extent comes from the parse, not from any endset, and is unique per start (PR-ENC-uniq); overlapping runs are harmless because resolution is start-anchored — a decodable suffix is a different definition at a different start. *Expansion* — `expand(a)`: in `body`, replace each applied reference `r(e₁, …, e_k)` by `expand(r)` with the expanded arguments substituted for `r`'s parameters, *capture-avoidingly* — the referent's binders (PC1/PC2a domains, PC2 binder guards) are renamed away from the arguments' free variables; the substitution is total because a referent's free variables are exactly its parameters (PR-SIG). Descent strictly decreases first-registration rank (PR2), so expansion terminates in a pure PL term whose free variables are the top level's own parameters `Γ_D` — and a *well-typed* one at the recorded signature, `Γ_D ⊢ expand(a) : C_D` with `expand(a) ∈ PL` (PR3a below). *Evaluation* — `evaluate(a, args, view, Σ)`. Its precondition: `a` is *ever-registered* at Σ — some `(b, F, G) ∈ L_pdef^Σ` with `addrs(F) = {a}`, an audit-slice fact (in PL: `(E x ∈ L_pdef :: a ∈ addrs_F(x))`; equivalently `a ∈ M_pdef` at view `audit`, V-AUD). Active registration is *not* required, of `a` or of any referent: under the precondition the top run validated at its deposit (PR1); each referent was deposited strictly earlier (PR2(a)) and so is ever-registered at Σ by audit monotonicity (L12a per step, via RP-b); and induction down the DAG carries parse- and type-validity to every leaf. A de-registered definition therefore still evaluates — resolution reads immutable content whose validity the deposit-state validation already proved; what de-registration withdraws is the *endorsement* (condition (iv) for new registrations), not the artifact or its standing proof in the audit slice. `args` is a `Γ_D`-*environment*: one value of sort `Cᵢ` per parameter `xᵢ`, per `sig(a) = (Γ_D, C_D)` (PR-SIG). Then `evaluate(a, args, view, Σ)` is the ASN-0129 denotation of `expand(a)` at `(args, view, Σ)` — a denotation that exists at the signature's result sort because `expand(a)` is a PL term with `Γ_D ⊢ expand(a) : C_D` (PR3a), the view fixed at the top level per PC3, with what that fixing means for referents stated at PR-VIEW. Purity (PC4), termination (PC5), decidability, and the ceiling (PC6) hold verbatim — the expansion is a pure PL term fixed by immutable content before evaluation begins: two evaluators expanding the same address at any two states obtain the same term (S0); the *value* varies only as `(args, view, Σ)` vary, exactly as for any PL term.

**PR3a (ExpansionWellTyping).** For every ever-registered `a` with `sig(a) = (Γ_D, C_D)`: `expand(a)` is a pure PL term with `Γ_D ⊢ expand(a) : C_D`. PR2 gives termination; this lemma supplies what PR3's evaluation clause actually consumes — that the terminating result is a *term*, of the signature's sort — and its proof is the substitution induction. We induct on first-registration rank (well-founded by PR2; every referent's rank strictly lower, PR2(a)), with a nested structural induction on the body, whose deposit-state judgment `Γ_D ⊢ body : C_D` under WT + WT-ref is supplied by PR0 (iii) and permanent (PR1, S0). Expansion rewrites reference nodes only, so every other node's WT rule is preserved as the structural induction passes through it. At a reference node `r(e₁, …, e_k)`, typed in the host derivation at a context `Γ` — `Γ_D` extended with the binders in scope — by WT-ref's premises `Γ ⊢ eᵢ : Cᵢ` and `sig(r) = (⟨x₁ : C₁, …, x_k : C_k⟩, C_r)` with conclusion `Γ ⊢ r(e₁, …, e_k) : C_r`: the structural induction gives `Γ ⊢ expand(eᵢ) : Cᵢ` for each expanded argument; the rank induction gives `expand(r) ∈ PL` with `⟨x₁ : C₁, …, x_k : C_k⟩ ⊢ expand(r) : C_r`. That judgment weakens to `Γ, x₁ : C₁, …, x_k : C_k ⊢ expand(r) : C_r` — WT is syntax-directed and a derivation consults only the variables its term mentions, which after the capture-avoiding renaming of `expand(r)`'s binders away from `Γ` (PR3) are the parameters and the renamed binders, none clashing with `Γ` — and then `k` applications of WT's PC2 plain-composition rule (`Γ ⊢ g[x := f] : C₂` from `Γ ⊢ f : C₁` and `Γ, x : C₁ ⊢ g : C₂`, ASN-0129) discharge the parameters in turn: the arguments' free variables lie in `Γ`, never among the `xⱼ`, so the sequential substitutions neither capture nor interfere, and `Γ ⊢ expand(r)[x₁ := expand(e₁)] … [x_k := expand(e_k)] : C_r`. The replacement node thus carries exactly the sort WT-ref gave the node it replaces, the host derivation re-types unchanged above it, and the structural induction closes with `Γ_D ⊢ expand(a) : C_D`. Membership in PL rides the same induction: each replacement is built from PL constituents — `expand(r)` by the rank hypothesis, the expanded arguments by the structural one — under PC2 composition, and PL is closed under PC2 (PC6's least-class definition); no reference node survives, so `expand(a)` is pure. ∎

**PR-VIEW (ViewTransparency).** A signed term records no view (PR-ENC) and `evaluate` takes one (PR3) — a deliberate pair, and a semantic commitment this paragraph states rather than leaves implicit. PC3 (ASN-0129) gives every PL term exactly one view, fixed at the top level; expansion yields one pure term; so the view binding every view-parameterized constituent (`members`, `targets_of`, `is_K`, `M_K` — PC3's list) in every inlined referent is the evaluating *caller's*, not anything the referent's author chose. References are *view-transparent*: a referent contributes spelling, never scope — the artifact fixes the term, the reader fixes which state the term's parameterized reads see. This is the published-artifact semantics Xanadu's read side already exhibits: which state a query sees is the reader's per-use choice, never the publisher's — in udanax-green every link query carries its own scope, each specset naming its own document or version per call, historical versions queryable on the same footing as current ones, with no backend-held "current" substituted for the caller's choice — and link filtering is likewise front-end work, the reader's sieve. An author who needs a read pinned to a slice *regardless of caller* pins it in the spelling: PC3's fixed-view constituents (`A_K`, `L_K`, `L_dom`) denote their slices at every term view, and its derivable cross-view readings — `⋃(L_K, addrs_F)` for audit `members`, `(E x ∈ L_K :: t ∈ coverage_F(x))` for audit `is_K` — respell every parameterized read through them. Call a term *view-independent* iff it contains no view-parameterized constituent and no collection-valued behavior atom on UV's rewrite list (`succs`, `sources_to`, `chain`, `stale`; the verdict-valued behavior atoms UV never rewrites are admissible): a syntactic condition, decided by the same finite scan that decides well-typing. A view-independent term's denotation is invariant in the view argument — by structural induction, PC3 and UV locate all view-sensitivity in exactly the excluded constituents — so for such a term the `view` argument is inert. PR5 leans on this class.

## Versioning and certification

**PR4 (VersioningBySupersession).** Definitions are never edited; they are *succeeded*. To update a predicate: register the successor (PR0), then emit `supersedes` (the shipped S2 class, ASN-0128) from the old definition's address to the new. The shipped semantics carry over without addition: `tip(a)` resolves the current version of the lineage rooted at `a`; competing successors make a branch and `tip` returns ⊥ — the multiplicity is *reported*, and adjudicating among competing updates belongs to readers (BH2's stance), which for protocol definitions is precisely the right politics: the substrate records who claims to supersede what; choosing whose protocol update to follow is the consumer's act. A consumer wanting a stable binding pins the address; one wanting the lineage's head follows `tip` and handles ⊥.

**PR5 (DynamicsCertification).** The registration surface may, on request, classify a validated definition against ASN-0129's PD criteria and emit a certification classifier — `pd_stable` (PS2 below), asserting membership in PD0's **ST** class, the ⊤-stable spellings (further certificate classes may ship as the checker matures; the conservative one is the protocol-critical one). Two qualifications are load-bearing. *Purity*: PD0's classes are defined on *pure* PL terms, and a reference-bearing body is not one — *the certified object is the definition's expansion* (PR3, well-typed by PR3a), the pure term `expand(a)`, not the artifact's literal reference-bearing spelling. *View*: PD0's classes are view-relative — `is_K(addr)` is ST at view `audit` and flips at `active` (PD1), `M_K` is grow-only only in an audit-view term — while a definition records no view and is evaluated at the caller's (PR-VIEW), so "`expand(a) ∈ ST`" has a truth value only once a view is fixed. The surface therefore certifies only *view-independent* expansions (PR-VIEW's syntactic class, decided by the same scan that validates): such a term denotes identically at every view, and the PD0 rules open to it are the view-neutral ones — step-constants, residence, reflected-set tests, quantifiers and aggregates over the fixed-view grow-only bases `L_K` and `L_dom` and their filters — so membership in ST is well-posed absolutely, and the certificate binds at every `evaluate` call whatever view the caller passes; no view index on the certificate, because the certified spelling has nothing for a view to vary. A view-parameterized spelling is refused not as unstable but as *ill-posed for certification*; its respelling through the fixed-view slices is always available (PC3's cross-view readings), and that is where an audit pin belongs anyway — in the spelling, which is the certified object. Permanence is unimpaired: `expand(a)` is determined by immutable content alone (PR3's resolution reads nothing else), so the certified object is itself a fixed pure spelling, frozen exactly as the artifact is — the certified object and the classified object coincide, at the expansion. Certification is sound-but-incomplete by design: PD0's rules are spelling-level and certify a subclass of the extensionally stable terms (ASN-0129, Open Question 5); an uncertified term is *unknown*, not unstable. What certification buys is structural checkability downstream. With both classes' from-endsets denoting definition addresses (PS1, PS2), "every registered definition carries `pd_stable`" is the one-quantifier PL term

`(A t ∈ M_pdef :: is_pd_stable(t))` — one term, view `active`

— PC1 over the QD base `M_pdef`, whose active reading is `⋃ addrs(F)` over `A_pdef^Σ` (D1): under PR0's discipline, exactly the registered definition addresses. The body is the `pd_stable` class's core membership atom (D2), true at `t` iff some active certificate's F covers `t` — and the coverage test is *exact* at starts: a certificate's F-coverage is `subtree(t')` (PrefixSpanCoverage, ASN-0043), and distinct content-run starts are prefix-incomparable — same-origin K.α chain addresses share their length, `inc(·, 0)` rewriting only the terminal sig position (TA5(c), TA5-SigValid, ASN-0034), while cross-origin addresses extend prefix-incomparable anchors (CrossDocumentDisjointness, ASN-0093) and two prefixes of one tumbler are length-ordered — so `t ∈ subtree(t')` between starts forces `t' = t`. Scoping the lint to a protocol is a QD filter over `M_pdef` (the protocol's own membership classifier); either way it is one quantifier, decidable at every reachable state (PC5), evaluable by anyone. PR1's permanence applies to certificates identically: the certified expansion can never change, so the certificate never expires.

## Standard registrations

This note extends the substrate's shipped classes (ASN-0128, Standard registrations) with two designated coverage classes, under the same parameterization and the same R-C1-style pairwise non-collision checks at construction:

**PS1 (PredicateDefinition).** `pdef` — Multi, idem=⊤, behaviors=∅. Slot convention: F = `enc({a})` denotes the definition's address — identity by start — and G = `enc(A_def)` denotes its run. Marks a content run as a validated predicate definition. The Multi shape is what makes both facts recoverable *by denotation*: `addrs(F) = {a}` and `addrs(G) = A_def`, so condition (iv) tests `r ∈ addrs(F)`, `targets_of(a, active)` enumerates the run (D3), and `M_pdef` enumerates the registered definitions (D1) — where a single merged span over the run would denote nothing, AD collecting unit-depth spans only. Idempotent: re-registering the same run *while its tuple is active and the presentation still validates* dedups to the existing tuple (I0's coverage identity on both slots — same start, same run); validation runs first on every call (PR0), so a re-presentation whose referents have since been de-registered fails (iv) and is *rejected*, the incumbent untouched — rejection of the call asserts nothing about the standing registration. After de-registration the dedup sees an empty class (I2) and a re-registration deposits afresh at a new address. No read-filter: a definition is not presentation-layer state.

**PS2 (StabilityCertificate).** `pd_stable` — Unary, idem=⊤, behaviors=∅. Slot convention: F = `enc({a})`, the certified definition's address; G = ∅ (Unary). Asserts ST-class certification (PD0, ASN-0129) of the *expansion* — view-independent, per PR5 — of the definition at `a`. Emitted only by the certification path of the registration surface, through the wrapped `Emit_pd_stable(Σ, d, {a}, ∅)` — a monopoly the entry-point seal below *enforces* rather than assumes; the assertion discipline is thereby the surface's mechanically, the tuple merely durable.

*Entry points — the seal.* Both classes are surface-sealed, S3's pattern (ASN-0128): the exposed `Emit_K` rejects every `pdef`-class and every `pd_stable`-class call by the same uniform class-exclusion mechanism that rejects R-class calls — the uniform precondition extends from `K ≁ R` to `K ≁ R ∧ K ≁ pdef ∧ K ≁ pd_stable`, fixed at construction with the designations themselves — so `register_pred` is the one surface route into the `pdef` slice and PR5's certification path the one into `pd_stable`, exactly as `Nullify_Binary` is the one retraction entry point. The seal is what makes PR0's discipline scoping a fact about the shipped surfaces rather than an assumption: without it, a direct `Emit_pdef` call — admissible at the bare Multi gate, which reads span counts, never content — could mint an unvalidated classifier through a shipped surface. ASN-0128 closed the identical hole for [R] structurally; this note closes its two the same way.

Retraction interacts with both classes through the shipped machinery and nothing else: a `Nullify_Binary` aimed at a `pdef` tuple's address *de-registers* the definition — the tuple leaves `A_pdef^Σ`, every "is this registered" query flips, and PR0's condition (iv) thereafter refuses new references to it — while the audit slice keeps the full history (a de-registered definition is recoverable evidence, not erased content; the run itself is untouched and untouchable). De-registration does not cascade: previously registered referencing definitions validated against their own deposit pre-states, and PR1's proof concerns those states; evaluation likewise survives, PR3's precondition being an audit-slice fact. Whether dangling *live* references (a registered definition referencing a since-de-registered one) should be surfaced, tolerated, or blocked is genuinely open (Open question 3).

## Worked composition

A builder registers a base predicate and a successor, certifies the successor, and a consumer evaluates by lineage head.

1. *Author.* INSERT the encoded term of `quiescent_v1` — signature `⟨t : T⟩ → Bool`, body an emptiness test over `t`'s pending work read through the fixed-view active-slice base `A_K` (PC3), so the term is view-independent (PR-VIEW) — into the builder's document `d_b`; the content lands at run `A₁` starting `a₁` (K.α chain, ASN-0093). `register_pred(d_b, A₁)` validates — parses, well-types, no references — and the wrapped `Emit_pdef(d_b, {a₁}, A₁)` deposits the tuple `(enc({a₁}), enc(A₁), pdef)`.
2. *Reference.* A second term `gate` — signature `⟨t : T⟩ → Bool`, body `a₁(t) ∧ under_cap(t, 3)` — carries the first conjunct as an *applied reference*, typed `Bool` by WT-ref against `sig(a₁)`. Its registration validates condition (iv) against `A_pdef^Σ` — `a₁ ∈ addrs(F)` of the standing tuple — and succeeds. The reference points backward in first-registration order necessarily (PR2).
3. *Update.* The builder registers `quiescent_v2` at run `A₂` starting `a₂` and emits `supersedes` from `a₁` to `a₂`. Now `tip(a₁) = a₂`; `gate` still references `a₁` — pinned semantics, by address — while a lineage-following consumer evaluates `tip(a₁)` and gets v2. Both behaviors are correct; the choice is the consumer's, visible in their own term.
4. *Certify.* `quiescent_v1`'s expansion is view-independent (its one state read is the fixed-view `A_K` base), so its PD class is well-posed (PR5) — and it is not ST: the active slice is not grow-only, and an active-slice test can flip back (PD1, ASN-0129), so certification is correctly *refused*. The builder's v2 respells the terminator the Marker way: true once a completion marker of the builder's marker class has been emitted for `t` — an existential over the grow-only audit-slice base `L_K`, fixed-view hence again view-independent, in PD0's ST class by the quantifier rule. The surface certifies v2 — classifying `expand(a₂)`, here reference-free, so the expansion is the body itself — and the wrapped `Emit_pd_stable(d_b, {a₂}, ∅)` deposits the certificate. The contrast is the lesson the certificate teaches: a terminator that *tests live state* can un-terminate; a terminator that *tests for a recorded event* cannot — and the lint distinguishes them structurally, before anything runs.
5. *Adversary check.* A registration whose term references the unallocated `a₃ = shift(a₂, n₂)` (the frontier) is rejected at condition (iv) — no active tuple denotes `a₃`; here the address is not even resident, and (iv) asks for strictly more than residence: a registered referent is resident (its own deposit's condition (i), carried forward by C0), but a resident, valid, *unregistered* run still fails (iv). The registration check (iv) closes the frontier-ghost hazard for definitional references: no definition can come to mean something by a *later* allocation.

## What this note doesn't cover

- **The concrete encoding.** PR-ENC fixes the discipline (injective, prefix-free, decidable self-delimiting parse, decidable typing, recorded signatures); the byte format is a substrate parameter for the implementation to fix, as with subspace identifiers.
- **Activation.** Binding predicates to emissions ("when P, emit E") — the trigger primitive — remains protocol-layer territory outside the corpus (ASN-0129's fence), now with one improvement available to it: the P it binds can be a `pdef` address rather than an inline term.
- **The certifier's internals.** PR5 commits the certificate's meaning and permanence, not the checking algorithm; soundness of the syntactic check is ASN-0129's Open Question 5, inherited.

## Open questions

1. **Name relations.** Identity is by address; human-facing naming (a Binary `pname` from name-content to definition) was considered and deferred — names introduce collision politics (who owns "quiescent"?) that addresses dissolve. Should a shipped naming class exist at all, or is naming app-side convention as type labels are (ASN-0126)?

2. **Cross-substrate portability.** A definition's references are addresses in *this* docuverse. Republishing a predicate library on another substrate re-allocates every run and rewrites every reference — a deep-copy with address translation. Is there a portable identity layer (content-hash manifests as un-registered metadata?), or is portability an application concern?

3. **Dangling live references.** De-registration (retraction of `pdef`) can leave registered definitions referencing de-registered ones. Evaluation still works (the content persists; PR3 reads content, not registration), but the reference now crosses a revoked endorsement. Should evaluation-by-reference check registration *transitively* at evaluation time, only at registration (status quo), or should a `pdef` retraction be rejected while live referents exist?

4. **Certificate classes beyond ST.** `pd_stable` ships; certificates for SF (the ⊥-stable spellings), frame-stability footprints (FP, ASN-0129), or view independence as a standalone class (PR-VIEW's scan, currently folded into `pd_stable` as a precondition) could follow. Each is a new designated class — the catalog-growth question (ASN-0128, Open Question 5) instantiated at the certification layer.
