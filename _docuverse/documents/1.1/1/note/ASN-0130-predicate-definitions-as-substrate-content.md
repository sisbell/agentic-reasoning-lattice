# ASN-0130: Predicate Definitions as Substrate Content

*Terms as artifacts — storing, validating, referencing, versioning, and certifying PL predicates in the docuverse itself.*

ASN-0129 defines the predicate language: what terms exist, what they mean, what they cannot express, and how their truth moves. Its terms, however, are meta-level objects — the note says well-typing is decidable but gives terms no existence inside the system. This note closes that gap the Xanadu way: a predicate definition is *content* — an immutable run of I-addresses holding a serialized PL term — registered by a classifier tuple, referenced by address, versioned by supersession, and certified by further tuples. The predicate system becomes self-hosting on the links it queries: a builder's protocol definitions are themselves linkable, citable, supersedable documents, and the platform's validation guarantees attach to them once, permanently.

Three foundation facts make the design nearly free, and the note's work is mostly to compose them. Content is immutable and permanent (S0/S1, ASN-0036), so a validated definition can never drift — validation at registration is validation forever. Identity is by origin, not value (S4, ASN-0036), so definitions are identified by address, dissolving the naming and equality problems a name-keyed registry would import. And registrations are totally ordered along any derivation, so definitional references — required to name *already-registered* definitions — can only point backward in registration order, making the reference graph a DAG by construction and definitional expansion terminating without any cycle check.

**Depends:** ASN-0036 (Strand Model), ASN-0043 (Link Ontology), ASN-0086 (Typed Relations on Address Sets), ASN-0093 (Allocation Substrate), ASN-0126 (Substrate Shape Framework), ASN-0128 (Substrate Type Operational Semantics), ASN-0129 (Substrate Predicate Composition).

## What this note commits

- **The definition artifact.** A predicate definition is a contiguous content run holding an encoded PL term, identified by the run's start address; the encoding is treated abstractly (PR-ENC) — what is fixed is that parsing and well-typing are decidable on it, which ASN-0129 already supplies for the term it encodes.
- **Registration as a validated emit** (PR0): the operation surface validates the encoded term — parse, well-type, *resident references only* — and on success emits the `pdef` classifier; on failure it rejects, no tuple, exactly the R-VAL/P-tgt pattern of validating where the operational layer can and the static gate cannot.
- **Validation permanence** (PR1): a `pdef` tuple's existence is a permanent proof that its run validated — because the run is immutable (S0), the validation can never go stale. No runtime re-validation path exists or is needed.
- **Acyclic reference by construction** (PR2): definitions reference other definitions by address; registration requires referenced definitions to be already registered, so references point strictly backward in registration order, the reference graph is a DAG, and expansion terminates — preserving ASN-0129's PC6a (no fixpoints) under definitional reference without a cycle check.
- **Evaluation by reference** (PR3): `evaluate(a, args, view, Σ)` expands the definition at `a` through its DAG and evaluates per ASN-0129, inheriting purity, termination, and the ceiling unchanged.
- **Versioning by supersession** (PR4): definitions are immutable; updating one is registering a successor and emitting the shipped `supersedes` relation (S2, ASN-0128) — `tip()` resolves the current version, a branch is a ⊥ verdict surfaced to readers, exactly the shipped semantics with no new machinery.
- **Dynamics certification** (PR5): the registration surface may additionally certify a definition's PD class (ASN-0129, PD0–PD2) by emitting a certification classifier — making "is this termination predicate certified ST" itself a one-atom PL query, the check ASN-0129's Open Question 5 anticipates, recorded as substrate fact. The fit is exact, not approximate: ASN-0129's classes are *spelling-level* — the rules read a term's syntax, not its denotation — and a definition artifact is precisely a frozen spelling (S0), so the certificate attaches to the very object the classification is defined on.

## The definition artifact

**PR-ENC (EncodingDiscipline).** An *encoding* is an injective map from PL terms (ASN-0129's syntax: the vocabulary V/V-AUD/V-TUP/V-PRIM/V-DOC, the PC0–PC2a constructors over QD, and *definitional references* — I-addresses standing for the terms registered at them) to finite content-value sequences, with a decidable parse and the property that well-typing of the decoded term is decidable — ASN-0129's WT supplies the typing judgment and its decision for pure terms, and a definitional reference types as its referent's registered signature, available at validation because registration (PR0) requires referents already registered. The concrete encoding is a substrate parameter, like the subspace identifiers and the designated standard classes (ASN-0128, Standard registrations); this note fixes the discipline, not the bytes. A *definition artifact* is a contiguous run `A_def = {shift(a, k) : 0 ≤ k < n}` of content addresses (one K.α chain run, ASN-0093) holding an encoding, identified by its start `a` — *the definition's address*. By S0/S1 (ASN-0036) the run's values are fixed and permanent from allocation; by S4, two registrations of byte-identical terms at different runs are distinct definitions — identity is by origin, and term-equality questions are extensional questions ASN-0129 already classifies as open theory, not identity.

## Registration

**PR0 (DefinitionRegistration).** The operation surface exposes `register_pred(d, A_def)`: validate, then classify. *Validation*, at the registration state Σ: (i) the run `A_def ⊆ dom(Σ.C)` is resident and contiguous on one origin chain; (ii) its values decode to a PL term (PR-ENC's parse); (iii) the term well-types under WT (ASN-0129), each definitional reference carrying its referent's registered signature; (iv) every definitional reference in the term is the address of an *already-registered* definition — some `(b, F, ∅) ∈ A_pdef^Σ` (the active slice of the `pdef` class, ASN-0086's typed-relation machinery as surfaced by ASN-0128) with the referenced address in `addrs(F)`. On success, the surface emits the `pdef` classifier (PS1 below) — a Unary tuple whose F is the merged canonical span over the run, `{(a, δ(n, #a))}` — homed at the registering document `d`. On any failure the call is rejected: no step, no tuple — the same enforce-by-rejection stance ASN-0128's S3 takes for P-tgt, and for the same reason: the static gate cannot read content, but the operational layer can, and admitting an invalid registration would mint a durable classifier whose meaning (PR1) would be a lie.

Validation reads content values — `Σ.C(a)` dereferences — which PL itself is forbidden (ASN-0129, Structural reads only). There is no contradiction: validation is an *operation*, surface-level work whose product is a structural fact (the tuple) that PL *can* read. The division of labor is the note's central move: content is dereferenced only at the operation surface — once at registration to validate, and at expansion (PR3) to read terms whose validity the standing tuple already proves — and never inside PL evaluation itself, where the structural-reads-only boundary (ASN-0129) holds untouched.

**PR1 (ValidationPermanence).** If `(b, F, ∅) ∈ L_pdef^Σ` for any reachable Σ, then the run under `addrs(F)` held a valid encoding at the registering state — and holds it at Σ and every successor: the run's values are immutable (S0) and permanent (S1), both carried to the gated layer's states by ASN-0126's bridge (B2) and onward by RP (ASN-0128). A `pdef` tuple is therefore a *permanent proof of validation*: no re-validation path exists at runtime because none is needed — staleness would require the content to change, and the substrate has no operation that changes content. (Contrast every system whose code artifacts are mutable: there, validation is a cache; here it is a fact.)

**PR2 (AcyclicReference).** Registration events — `pdef` emissions — are totally ordered along any derivation, and condition (iv) forces every definitional reference to name a definition whose registration *strictly precedes* the referencing one: the referent's tuple must be active at the referencing validation, and the referencing definition's own tuple does not yet exist during that validation — which excludes self-reference outright. (Note the order is *registration* order, not allocation order: a run may be allocated long before it is registered, so the runs' allocation order constrains nothing.) The reference relation on definitions is therefore a subrelation of strict registration order — irreflexive, acyclic, a DAG with no cycle check ever run. *Consequently definitional expansion terminates*: expanding a definition replaces each reference by its referent's term, descending a finite DAG of finite terms; the expanded result is a pure PL term (no references), and ASN-0129's PC6a is preserved — mutual recursion among definitions is not merely banned, it is *unconstructible*: the would-be second member of a cycle cannot validate before the first exists, and the first already refers to nothing later than itself. (Ghost references — L4/L9 endset generality, ASN-0043 — are exactly what condition (iv) excludes for *references inside terms*; the endsets of the `pdef` tuple itself remain ordinary endsets with ordinary semantics.)

**PR3 (EvaluationByReference).** For a registered definition at `a`, `evaluate(a, args, view, Σ)` is: expand (PR2, terminating), then evaluate the expansion per ASN-0129. Purity (PC4), termination (PC5), decidability, and the ceiling (PC6) hold verbatim — the expansion is a PL term, and expansion itself reads only registered, immutable content fixed before evaluation begins. Two evaluators expanding the same address at any two states obtain the same term (S0); the *value* varies only as Σ varies, exactly as for any PL term.

## Versioning and certification

**PR4 (VersioningBySupersession).** Definitions are never edited; they are *succeeded*. To update a predicate: register the successor (PR0), then emit `supersedes` (the shipped S2 class, ASN-0128) from the old definition's address to the new. The shipped semantics carry over without addition: `tip(a)` resolves the current version of the lineage rooted at `a`; competing successors make a branch and `tip` returns ⊥ — the multiplicity is *reported*, and adjudicating among competing updates belongs to readers (BH2's stance), which for protocol definitions is precisely the right politics: the substrate records who claims to supersede what; choosing whose protocol update to follow is the consumer's act. A consumer wanting a stable binding pins the address; one wanting the lineage's head follows `tip` and handles ⊥.

**PR5 (DynamicsCertification).** The registration surface may, on request, classify the validated term against ASN-0129's PD criteria and emit a certification classifier — `pd_stable` (PS2 below), a Unary tuple over the definition's run, asserting membership in PD0's **ST** class, the ⊤-stable spellings (further certificate classes may ship as the checker matures; the conservative one is the protocol-critical one). Certification is sound-but-incomplete by design: PD0's rules are spelling-level and certify a subclass of the extensionally stable terms (ASN-0129, Open Question 5), and an uncertified term is *unknown*, not unstable. The spelling-level character is what makes the certificate well-posed here: the artifact *is* a spelling, frozen by S0, so the certified object and the classified object coincide exactly. What certification buys is structural checkability downstream: "every termination condition this protocol relies on carries `pd_stable`" is a one-quantifier PL term over `A_pdef^Σ` and `A_pd_stable^Σ` — the platform lint, expressed in the platform's own language, evaluable by anyone. PR1's permanence applies to certificates identically: the certified term can never change, so the certificate never expires.

## Standard registrations

This note extends the substrate's shipped classes (ASN-0128, Standard registrations) with two designated coverage classes, under the same parameterization and the same R-C1-style pairwise non-collision checks at construction:

**PS1 (PredicateDefinition).** `pdef` — Unary, idem=⊤, behaviors=∅. Marks a content run as a validated predicate definition. Idempotent: re-registering the same run dedups to the existing tuple (I0's coverage identity — the same run is the same definition). No read-filter: a definition is not presentation-layer state.

**PS2 (StabilityCertificate).** `pd_stable` — Unary, idem=⊤, behaviors=∅. Asserts ST-class certification (PD0, ASN-0129) of the definition whose run its F covers. Emitted only by the certification path of the registration surface (PR5); like all classifier meaning, the *assertion discipline* is the surface's, the tuple merely durable.

Retraction interacts with both classes through the shipped machinery and nothing else: a `Nullify_Binary` aimed at a `pdef` tuple's address *de-registers* the definition — it leaves `A_pdef^Σ`, every "is this registered" query flips, and PR2's condition (iv) thereafter refuses new references to it — while the audit slice keeps the full history (a de-registered definition is recoverable evidence, not erased content; the run itself is untouched and untouchable). De-registration does not cascade: previously registered referents validated against the pre-state, and PR1's proof concerns the registration state. Whether dangling *live* references (a registered definition referencing a since-de-registered one) should be surfaced, tolerated, or blocked is genuinely open (Open question 3).

## Worked composition

A builder registers a base predicate and a successor, certifies the successor, and a consumer evaluates by lineage head.

1. *Author.* INSERT the encoded term of `quiescent_v1` into the builder's document `d_b`; the content lands at run `A₁` starting `a₁` (K.α chain, ASN-0093). `register_pred(d_b, A₁)` validates — parses, well-types, no references — and emits `pdef` over `A₁`.
2. *Reference.* A second term `gate ≡ quiescent_v1(t) ∧ under_cap(t, 3)` encodes the first conjunct as the definitional reference `a₁`. Its registration validates condition (iv) against `A_pdef^Σ` — `a₁` is registered — and succeeds. The reference points backward in registration order necessarily (PR2).
3. *Update.* The builder registers `quiescent_v2` at run `A₂` and emits `supersedes` from `a₁` to `a₂`. Now `tip(a₁) = a₂`; `gate` still references `a₁` — pinned semantics, by address — while a lineage-following consumer evaluates `tip(a₁)` and gets v2. Both behaviors are correct; the choice is the consumer's, visible in their own term.
4. *Certify.* `quiescent_v1` is an active-view emptiness test — sound semantics, but not a stable spelling: an active-view term can flip back (PD1, ASN-0129), so certification is correctly *refused*. The builder's v2 respells the terminator the Marker way: true once a completion marker of the builder's marker class has been emitted for `t` — an existential over a grow-only audit slice, in PD0's ST class by the quantifier rule. The surface certifies v2 and emits `pd_stable` over `A₂`. The contrast is the lesson the certificate teaches: a terminator that *tests live state* can un-terminate; a terminator that *tests for a recorded event* cannot — and the lint distinguishes them structurally, before anything runs.
5. *Adversary check.* A registration whose term references the unallocated `a₃ = shift(a₂, n₂)` (the frontier) is rejected at condition (iv) — not registered, indeed not resident. The residence check closes the frontier-ghost hazard for definitional references: no definition can come to mean something by a *later* allocation.

## What this note doesn't cover

- **The concrete encoding.** PR-ENC fixes the discipline (injective, decidable parse, decidable typing); the byte format is a substrate parameter for the implementation to fix, as with subspace identifiers.
- **Activation.** Binding predicates to emissions ("when P, emit E") — the trigger primitive — remains protocol-layer territory outside the corpus (ASN-0129's fence), now with one improvement available to it: the P it binds can be a `pdef` address rather than an inline term.
- **The certifier's internals.** PR5 commits the certificate's meaning and permanence, not the checking algorithm; soundness of the syntactic check is ASN-0129's Open Question 5, inherited.

## Open questions

1. **Name relations.** Identity is by address; human-facing naming (a Binary `pname` from name-content to definition) was considered and deferred — names introduce collision politics (who owns "quiescent"?) that addresses dissolve. Should a shipped naming class exist at all, or is naming app-side convention as type labels are (ASN-0126)?

2. **Cross-substrate portability.** A definition's references are addresses in *this* docuverse. Republishing a predicate library on another substrate re-allocates every run and rewrites every reference — a deep-copy with address translation. Is there a portable identity layer (content-hash manifests as un-registered metadata?), or is portability an application concern?

3. **Dangling live references.** De-registration (retraction of `pdef`) can leave registered definitions referencing de-registered ones. Evaluation still works (the content persists; PR3 reads content, not registration), but the reference now crosses a revoked endorsement. Should evaluation-by-reference check registration *transitively* at evaluation time, only at registration (status quo), or should a `pdef` retraction be rejected while live referents exist?

4. **Certificate classes beyond ST.** `pd_stable` ships; certificates for SF (the ⊥-stable spellings), frame-stability footprints (FP, ASN-0129), or view discipline could follow. Each is a new designated class — the catalog-growth question (ASN-0128, Open Question 5) instantiated at the certification layer.
