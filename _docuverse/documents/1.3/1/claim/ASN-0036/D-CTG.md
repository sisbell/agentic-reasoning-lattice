**D-CTG (VContiguity).** For each document d, the text-subspace projection V_1(d) — the active text V-positions `{v ∈ dom(Σ.M(d)) : subspace(v) = 1}` of d, as defined in V-sub (SubspaceProjection) — is either empty or occupies every intermediate position between its extremes:

`(A d, u, q : u ∈ V_1(d) ∧ q ∈ V_1(d) ∧ u < q : (A v ∈ T : subspace(v) = 1 ∧ #v = #u ∧ zeros(v) = 0 ∧ u < v < q : v ∈ V_1(d)))`

The candidate position v ranges over the tumbler carrier set T (T0, CarrierSetDefinition, ASN-0034); this domain is what makes the inner guards well-typed, since the component projection `subspace(v) = v₁`, the length `#v`, and the strict order `<` in `u < v < q` (the last from T1, LexicographicOrder) are all defined only on T. The guards then restrict v to the same-depth, zero-free text-subspace positions strictly between u and q.

In words: within the text subspace, V-positions form a contiguous ordinal range with no gaps. If positions [1, 3] and [1, 7] are occupied, then every position [1, k] with 3 < k < 7 must also be occupied.

For the text subspace at depth m = 2, this is a finite condition: the intermediates between [1, a] and [1, b] are the finitely many [1, i] with a < i < b. This betweenness statement is all that D-CTG asserts; the stronger reading — that V_1(d) occupies a *single unbroken block* of ordinals — is not a consequence of contiguity alone but of contiguity combined with the arrangement's finiteness, and is derived in D-SEQ, the claim that brings both ingredients together.

What we have not done is *derive* this contiguity, and the Depends list below makes the reason visible: D-CTG cites only definitional foundations — V-sub for the projection `V_1(d)`, and subspace, T0, T1, T4 for the position algebra — and no state-transition axiom. A statement about *which* V-positions inhabit `dom(Σ.M(d))` at a reachable state cannot follow from those purely mathematical foundations alone; deriving it would require the transition axioms AX-1, AX-2 and the content-stream invariants S0–S3, none of which appears here, and none of which in fact constrains the betweenness of arrangement keys — AX-1 fixes only the empty base arrangement, AX-2 constrains the *targets* of newly established V-mappings rather than which keys are admitted, and S0, S1, S2, S3 govern the evolution of the content stream `C` alone. We therefore adopt D-CTG as a *design constraint* on the class of permitted arrangements, asserted by fiat — a protocol posit, accepted within this ASN without proof. We posit it rather than derive it; the point of naming it is methodological. D-CTG-depth and D-SEQ read D-CTG as a load-bearing premise — D-CTG-depth calls it *the contiguity axiom* and drives its negation to a contradiction with the finiteness of `dom(M(d))` (S8-fin) — and so need an explicit, citable source rather than a result they must themselves discharge. Knowing D-CTG is a posit and not a theorem is exactly what tells such a consumer — a formalization tool included — that gap-freeness is an implementation obligation on permitted arrangements, to be met by the protocol's allocation discipline, rather than a consequence automatically inherited from the existing axioms.

*Formal Contract:*

- *Axiom:* For every reachable state `Σ` and every document `d` — the formal statement's shorthand `V_1(d)` carries this suppressed `Σ`, standing for `{v ∈ dom(Σ.M(d)) : subspace(v) = 1}` (V-sub) read at that state — the active text V-positions of `d` occupy every intermediate position between their extremes:
  `(A d, u, q : u ∈ V_1(d) ∧ q ∈ V_1(d) ∧ u < q : (A v ∈ T : subspace(v) = 1 ∧ #v = #u ∧ zeros(v) = 0 ∧ u < v < q : v ∈ V_1(d)))`
  — the inner candidate `v` ranging over the tumbler carrier `T` (T0), the guards `subspace(v) = 1`, `#v = #u`, `zeros(v) = 0`, and `u < v < q` restricting it to the same-depth, zero-free text-subspace positions strictly between `u` and `q` — holding at every state reachable from the base state `Σ₀` by the transition relation. This is a protocol design posit on the class of permitted arrangements, accepted within this ASN without proof; it constrains which arrangements an implementation may produce, admitting no reachable arrangement whose text subspace `V_1(d)` has an internal gap. It is not derived from any other claim — in particular not from the content-stream invariants S0, S1, S2, S3, which govern the evolution of `C` alone, nor from the transition axioms AX-1 (which fixes only the empty base arrangement) and AX-2 (which constrains the targets of newly established V-mappings, never the betweenness of the keys); none of these constrains the contiguity of `dom(Σ.M(d))`. D-CTG-depth and D-SEQ consume it as the contiguity axiom — a load-bearing posit whose negation the D-CTG-depth proof drives to a contradiction with S8-fin — so a consumer, a formalization tool included, must treat it as an implementation obligation on permitted arrangements rather than as a theorem to discharge.

- *Depends:*
  - V-sub (SubspaceProjection) — supplies the definition of the text-subspace projection `V_1(d) = {v ∈ dom(Σ.M(d)) : subspace(v) = 1}` over which the contiguity statement quantifies; the extreme guards `u ∈ V_1(d)`, `q ∈ V_1(d)` and the consequent `v ∈ V_1(d)` are membership tests against this set, each unfolding to `· ∈ dom(Σ.M(d)) ∧ subspace(·) = 1`
  - subspace (VPositionSubspaceIdentifier) — supplies the projection `subspace(v) = v₁`, the function whose value the inner-quantifier guard `subspace(v) = 1` constrains, restricting each intermediate position v to the text subspace (subspace identifier 1)
  - T4 (HierarchicalParsing, ASN-0034) — supplies the zero-count `zeros`, grounding the inner-quantifier guard `zeros(v) = 0` that restricts the intermediate position v to a zero-free V-position
  - T1 (LexicographicOrder, ASN-0034) — supplies the strict order `<` on tumblers used in the extremes guard `u < q` and the betweenness guard `u < v < q` that delimit the intermediate positions
  - T0 (CarrierSetDefinition, ASN-0034) — supplies the tumbler carrier set `T`, the domain of the inner quantifier's candidate v (without which the guard terms `subspace(v)`, `#v`, and `u < v < q` are ill-typed); and the tumbler length `#`, giving meaning to the same-depth selector `#v = #u`
