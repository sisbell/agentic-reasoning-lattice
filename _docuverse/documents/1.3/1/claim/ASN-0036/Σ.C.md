**Σ.C (ContentStore).** The first component of the strand state is the object an edit never mutates. The *content store* `Σ.C : T ⇀ Val` is a partial function mapping Istream addresses to content values. `T` is the carrier set of tumblers (CarrierSetDefinition, ASN-0034) — the same carrier at whose addresses the arrangement `Σ.M(d) : T ⇀ T` lays out content — and it types the domain of `Σ.C`, whose elements are the I-addresses. Its codomain `Val` is an unspecified nonempty set of content values, opaque at this level of abstraction: we introduce it here as a primitive, uninterpreted set, fixing no structure on it, so that the model stays independent of any particular content representation. This codomain annotation `Σ.C : T ⇀ Val` is the content-side counterpart of the arrangement declaration `Σ.M(d) : T ⇀ T` fixed at Σ.M(d) (Arrangement), and it is the sole grounding site for every later use of `Val` — in particular the witnesses of S5, which draw an arbitrary `w ∈ Val`. The domain `dom(Σ.C)` is the set of I-addresses at which content has been stored.

We fix the type and name its two factors, and nothing more. This claim posits the content store as a `T ⇀ Val` partial function — its domain carrier `T` grounded in T0, its codomain `Val` introduced here as an opaque primitive — and names its domain `dom(Σ.C)`; it imposes no constraint on *which* content stores may arise. Those constraints are the work of the claims downstream, each of which grounds the content symbol it speaks of here, at this defining claim: S0 holds content immutable across transitions, S1 makes `dom(Σ.C)` monotone, AX-2 requires every newly established mapping to target a stored address, S3 resolves every reference into `dom(Σ.C)`, S4 reads `dom(Σ.C)` and the value application `Σ.C(a)`, S5 draws its witnesses' values `w ∈ Val` from this codomain, and the structural-attribution results S7/S7a/S7b/S8 range their quantifiers over `dom(Σ.C)`. Each speaks of `Σ.C`, `dom(Σ.C)`, or `Val`; each is grounded at the type this claim supplies.
