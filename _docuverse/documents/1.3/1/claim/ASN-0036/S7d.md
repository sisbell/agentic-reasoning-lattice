**S7d (DocumentAllocationDiscipline).** Every document is realized at a document-level address `N.0.U.0.D` (`zeros = 2`) of the global allocator tree `𝒯` (ASN-0034), allocated by exactly one event of T10a's discipline. Each document is one output of a single document-allocator — a node of `𝒯` — emitted either at that allocator's child-spawn base `inc(spawnPt, k')` with `k' ∈ {1, 2}` (its first document) or at a later `inc(·, 0)` sibling-increment within that one allocator's domain (each subsequent document). The discipline sorts any pair of documents into two regimes keyed not on shared `(node, user)` but on `same_allocator` — T10a's predicate `∃A ∈ 𝒯 : · ∈ dom(A) ∧ · ∈ dom(A)`: documents realized in a *common* allocator are its successive sibling outputs; documents realized in *disjoint* allocators are held apart by the allocators themselves. A single `(node, user)`'s base documents `N.0.U.0.k` do form one allocator's sibling stream, but a version or sub-document — a multi-component document field `N.0.U.0.k.…` (Nelson: "the version, or subdocument number is only an accidental extension of the document number") — is *child-spawned* from its parent document's address into a *distinct* allocator that shares the node and user yet is a sibling of nothing in the parent's allocator. In both regimes *distinct documents arise from distinct allocation events*.

We make precise the bridge on which S7's Uniqueness step turns, taking care not to over-identify. *Document* is a notion of this ASN's model; *allocation event* a notion of ASN-0034's T10a. It is tempting to fuse a document with an allocator *node* — to read each document as the node `𝒯` spawns for it — but T10a forbids this for all but the *first* document of each allocator. By TA5(d) a child-spawn base `inc(spawnPt, k')`, `k' ∈ {1, 2}`, appends `[1]` (at `k' = 1`) or `[0, 1]` (at `k' = 2`); *every* base therefore ends in the component value `1`, and an address whose document field ends in a component exceeding `1` is no allocator's base but an `inc(·, 0)` sibling-increment within some one allocator's domain. It is equally tempting — and this is the over-identification we must refuse — to fuse "shares a node and user" with "shares an allocator." Under one `(node, user)` the *base* documents `N.0.U.0.1, N.0.U.0.2, N.0.U.0.3, …` are indeed one allocator `A`'s successive outputs: its base `N.0.U.0.1` followed by the `inc(·, 0)` siblings, each a shallow increment at the document field's last position, an address in the *one* node `A`'s domain rather than a node of its own. But a version or sub-document does *not* join this stream. Its address `N.0.U.0.5.3` (`D = [5, 3]`, still `zeros = 2`) is, by T10a, the `inc(·, 0)` output at index `2` of a *version-allocator* `V` whose base `N.0.U.0.5.1 = inc(N.0.U.0.5, 1)` was child-spawned (`k' = 1`, appending `[1]` by TA5(d)) from `N.0.U.0.5` — itself but one sibling output of `A`. So `N.0.U.0.5.3` lies in `V`, a node of `𝒯` distinct from `A`, sharing node `N` and user `U` with every document of `A` yet a sibling of none of them. The regime split S7d's injectivity turns on is therefore `same_allocator` — a common allocator against disjoint allocators — not co-residence under a `(node, user)`: co-user documents may sit in one allocator or in two. What S7d posits, then, is not a per-document node but how the model's documents are laid into `𝒯`'s *event stream*: each document is created by exactly one allocation event of the discipline — a child-spawn for an allocator's first document, an `inc(·, 0)` sibling-increment for each later one — and the map `ev` taking each document to that event records the lay-in. Like S7a it is not derived within this ASN; once posited, it makes the event-distinctness S7 needs immediate.

That immediacy is the whole point of naming the identification, so we trace it. The map `ev` is total and single-valued: each document's document-level address is produced by exactly one event of the discipline — every address of `𝒯` is either an allocator's base, established by one child-spawning event, or the `n`-th output of one allocator, produced by one `inc(·, 0)` step (T10a). It is moreover injective, which we establish across the two regimes the lay-in distinguishes.

*Documents in a common allocator.* Let `d₁ ≠ d₂` be realized in a common document-allocator `A` (`same_allocator` of their addresses), with domain `dom(A) = {tₙ : n ≥ 0}`, `t₀` the base and `tₙ₊₁ = inc(tₙ, 0)` — `A` being a per-(node, user) base-document allocator or a version-allocator indifferently, the argument turning only on its being one allocator. Successive allocation places the two distinct documents at distinct enumeration indices `m ≠ n`. Now `A`'s enumeration is generated event by event — index `0` is the base's child-spawn, index `i ≥ 1` the `i`-th `inc(·, 0)` sibling-increment — so the passage from index to allocating event is itself injective: distinct indices `m ≠ n` *are* distinct events, with no detour through the distinctness of their outputs `tₘ, tₙ`. Hence `d₁` and `d₂` arise from distinct allocation events. We stop deliberately at the events: T10a.7 (EnumerationInjectivity)'s output-injectivity `n ↦ tₙ` would carry us on to `tₘ ≠ tₙ`, an address-level fact S7d leaves to GlobalUniqueness, and we have no need of it — index-distinctness alone separates the two events. Nor does the at-most-once-on-`(t, k')` constraint enter this regime: it discriminates child-spawns, of which one allocator's sibling stream holds exactly one.

*Documents in disjoint allocators.* This regime is the exact complement of the last — any two documents not sharing an allocator, whether or not they share a node and user: a base document of `A` and a version document of a `V` child-spawned from one of `A`'s outputs fall here despite sharing both node and user, `V ≠ A` being distinct nodes of `𝒯`. An allocation event occurs within a single allocator, so events drawn from disjoint allocators `A₁ ≠ A₂` are distinct, and with them the documents they realize. One boundary sub-case calls on T10a's at-most-once constraint: when `d₁` and `d₂` are the *first* (base) documents of their allocators, each is produced by a child-spawn `inc(spawnPt, k')`; were these two child-spawning events to share parent, spawn point, and spawn parameter `(P, t, k')`, T10a's at-most-once constraint — each `(t, k')` yields at most one child — would coincide the two base nodes, hence the two allocators, hence the two documents `d₁ = d₂`. Base documents under *different* parents are separated already, their events differing in the parent component.

In either regime `ev(d₁) = ev(d₂)` forces `d₁ = d₂`; contrapositively, distinct documents have distinct allocation events — exactly the second fact S7 feeds to GlobalUniqueness. We mark the boundary of the claim: S7d separates documents at the level of *events*, not yet of *addresses* — two distinct events could, for all S7d says, still emit one tumbler value — and lifting event-distinctness to address-distinctness is GlobalUniqueness's step (ASN-0034), not S7d's; S7d's office is precisely to hand GlobalUniqueness two distinct events to discriminate.

*Formal Contract:*
- *Axiom:* Every document is realized at a document-level address `N.0.U.0.D` (`zeros = 2`, by T4's zero count) of the allocator tree `𝒯` (ASN-0034), allocated by exactly one event of T10a's discipline. Each document is one output of a single document-allocator (a node of `𝒯`) — at that allocator's child-spawn base `inc(spawnPt, k')` with `k' ∈ {1, 2}`, which by TA5(d) ends in component value `1`, if it is the allocator's first document, else at the next `inc(·, 0)` sibling-increment in that node's domain (document field ending in `2, 3, …`). The discipline sorts any pair of documents by `same_allocator` (T10a's `∃A ∈ 𝒯 : · ∈ dom(A) ∧ · ∈ dom(A)`), not by shared `(node, user)`: a single `(node, user)`'s base documents `N.0.U.0.k` are one allocator's sibling stream, but a version or sub-document `N.0.U.0.k.…` (multi-component document field, still `zeros = 2`) is child-spawned from its parent document's address into a *distinct* allocator sharing that node and user — so documents may share node and user yet lie in disjoint allocators. Hence the map `ev` taking each document to its allocating event is total and single-valued — every address of `𝒯` is produced by exactly one event, a child-spawn or an `inc(·, 0)` step (T10a) — and injective by a case split on `same_allocator`: documents in a *common* allocator are laid in at distinct enumeration indices `m ≠ n`, and each index is the work of its own event (the base's child-spawn at index `0`, the `i`-th `inc(·, 0)` sibling-increment at index `i ≥ 1`), so distinct indices are distinct events outright — no appeal to the output-distinctness of `tₘ, tₙ`; documents in *disjoint* allocators arise from events of distinct allocators, T10a's at-most-once-on-`(t, k')` constraint discriminating only the boundary sub-case of two first/base documents sharing a parent. Therefore **distinct documents arise from distinct allocation events**. The lay-in of the model's documents into `𝒯`'s event stream is a design posit (the document-level counterpart of S7a), not derived within this ASN; given it, the event-distinctness conclusion follows from T10a's per-index event structure and its at-most-once constraint as derived in the prose above. S7d yields event-distinctness only — it does not establish the address-distinctness `tₘ ≠ tₙ`, not even in the common-allocator regime — lifting event-distinctness to address-distinctness is GlobalUniqueness's step, consumed by S7's Uniqueness argument.

- *Depends:*
  - T4 (HierarchicalParsing, ASN-0034) — sole definition site of the zero count `zeros(t) = |{i : 1 ≤ i ≤ #t ∧ tᵢ = 0}|`, the function S7d's statement invokes in the parenthetical `zeros = 2` that characterises each document's address as a document-level tumbler (the `N.0.U.0.D` prefix, exactly two field separators present)
  - T10a (AllocatorDiscipline, ASN-0034) — supplies the allocator tree `𝒯` and its discipline: each allocator's domain `dom(A) = {tₙ : n ≥ 0}` with `tₙ₊₁ = inc(tₙ, 0)`, child-spawning by one `inc(·, k')`, `k' ∈ {1, 2}` (whose result is the child's base, a node distinct from the parent), and the `same_allocator` predicate on which S7d's two regimes are keyed — so that a single `(node, user)`'s base documents are the successive outputs of one allocator (first the base, the rest `inc(·, 0)` siblings) while a version/sub-document is child-spawned into a distinct allocator sharing that node and user, and any two documents not sharing an allocator are held apart by the allocators themselves; and supplies the per-index event structure of an allocator's enumeration — index `0` the base's child-spawn, index `i ≥ 1` the `i`-th `inc(·, 0)` sibling-increment — by which distinct enumeration indices are distinct events, grounding the common-allocator regime with no recourse to output-distinctness; and supplies the at-most-once constraint — each `(t, k')` yields at most one child-spawning event — which discriminates the boundary sub-case of two first/base documents sharing a parent in the disjoint-allocator regime; together these ground the conclusion that distinct documents arise from distinct allocation events, the event-level separation S7's Uniqueness step feeds to GlobalUniqueness
  - TA5 (HierarchicalIncrement, ASN-0034) — postcondition (d): a child-spawn `inc(t, k')` with `k' ∈ {1, 2}` appends `k' − 1` zero separators and a final component `1`, so every allocator base ends in component value `1`; this distinguishes an allocator's `inc(·, 0)` sibling-increment outputs (document field ending in `2, 3, …`, shallow increments within that one node's domain) from its child-spawn bases (ending in `1`) — the latter including both the per-(node, user) document-allocator's base `N.0.U.0.1` and a version-allocator's base `N.0.U.0.k.1` child-spawned from a parent document — fixing the `same_allocator` regime split on which S7d's corrected model rests
