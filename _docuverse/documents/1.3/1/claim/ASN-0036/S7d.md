**S7d (DocumentAllocationDiscipline).** Every document is realized at a document-level address `N.0.U.0.D` (`zeros = 2`) of the global allocator tree `𝒯` (ASN-0034), allocated by exactly one event of T10a's discipline. The discipline lays these addresses down in two regimes. Documents sharing a node and user are realized, in allocation order, as the successive outputs of *one* document-allocator — a single node of `𝒯`: the first document at that allocator's child-spawn base `inc(spawnPt, k')` with `k' ∈ {1, 2}`, each later co-user document at the next `inc(·, 0)` sibling-increment within that one allocator's domain. Documents under different users or nodes are realized in *disjoint* document-allocators. In both regimes *distinct documents arise from distinct allocation events*.

We make precise the bridge on which S7's Uniqueness step turns, taking care not to over-identify. *Document* is a notion of this ASN's model; *allocation event* a notion of ASN-0034's T10a. It is tempting to fuse a document with an allocator *node* — to read each document as the node `𝒯` spawns for it — but T10a forbids this for all but the first document under each user. By TA5(d) a child-spawn base `inc(spawnPt, k')`, `k' ∈ {1, 2}`, appends `[1]` (at `k' = 1`) or `[0, 1]` (at `k' = 2`); *every* base therefore ends in the component value `1`, and an address whose document field ends in a component exceeding `1` is no allocator's base. These are exactly the co-user documents after the first: the document-allocator's base `N.0.U.0.1` is followed by its siblings `N.0.U.0.2, N.0.U.0.3, …`, each a shallow `inc(·, 0)` at the document field's last position — an address in the *one* base node's domain, not a node of its own. (The family `[1, 0, 1, 0, 1], [1, 0, 1, 0, 2], …`, a single document-allocator's successive outputs under user `[1, 0, 1]`, is exactly the shape of a co-node/co-user document family — only the first is a child-spawn base, the rest sibling-increments of that one allocator.) What S7d posits, then, is not a per-document node but how the model's documents are laid into `𝒯`'s *event stream*: each document is created by exactly one allocation event of the discipline — a child-spawn for the first document under a user, an `inc(·, 0)` sibling-increment for each later one — and the map `ev` taking each document to that event records the lay-in. Like S7a it is not derived within this ASN; once posited, it makes the event-distinctness S7 needs immediate.

That immediacy is the whole point of naming the identification, so we trace it. The map `ev` is total and single-valued: each document's document-level address is produced by exactly one event of the discipline — every address of `𝒯` is either an allocator's base, established by one child-spawning event, or the `n`-th output of one allocator, produced by one `inc(·, 0)` step (T10a). It is moreover injective, which we establish across the two regimes the lay-in distinguishes.

*Co-user, co-node documents.* Let `d₁ ≠ d₂` be realized in a common document-allocator `A`, with domain `dom(A) = {tₙ : n ≥ 0}`, `t₀` the base and `tₙ₊₁ = inc(tₙ, 0)`. Successive allocation places the two distinct documents at distinct enumeration indices `m ≠ n`; by T10a.7 (EnumerationInjectivity) the indexing `n ↦ tₙ` is injective, so `tₘ ≠ tₙ` are distinct outputs of `A`, each emitted by its own event — the base's child-spawn at index `0`, the `i`-th `inc(·, 0)` sibling-increment at index `i ≥ 1`. Hence `d₁` and `d₂` arise from distinct allocation events. The at-most-once-on-`(t, k')` constraint plays no part in this regime — these are sibling-increment events, not child-spawns, and it is T10a.7, not at-most-once, that discriminates them.

*Documents under different users or nodes.* An allocation event occurs within a single allocator, so events drawn from disjoint allocators `A₁ ≠ A₂` are distinct, and with them the documents they realize. One boundary sub-case calls on T10a's at-most-once constraint: when `d₁` and `d₂` are the *first* (base) documents of their allocators, each is produced by a child-spawn `inc(spawnPt, k')`; were these two child-spawning events to share parent, spawn point, and spawn parameter `(P, t, k')`, T10a's at-most-once constraint — each `(t, k')` yields at most one child — would coincide the two base nodes, hence the two allocators, hence the two documents `d₁ = d₂`. Base documents under *different* parents are separated already, their events differing in the parent component.

In either regime `ev(d₁) = ev(d₂)` forces `d₁ = d₂`; contrapositively, distinct documents have distinct allocation events — exactly the second fact S7 feeds to GlobalUniqueness. We mark the boundary of the claim: S7d separates documents at the level of *events*, not yet of *addresses* — two distinct events could, for all S7d says, still emit one tumbler value — and lifting event-distinctness to address-distinctness is GlobalUniqueness's step (ASN-0034), not S7d's; S7d's office is precisely to hand GlobalUniqueness two distinct events to discriminate.

*Formal Contract:*
- *Axiom:* Every document is realized at a document-level address `N.0.U.0.D` (`zeros = 2`, by T4's zero count) of the allocator tree `𝒯` (ASN-0034), allocated by exactly one event of T10a's discipline. Documents sharing a node and user are realized, in allocation order, as the successive outputs of one document-allocator (a single node) — the first at its child-spawn base `inc(spawnPt, k')` with `k' ∈ {1, 2}`, which by TA5(d) ends in component value `1`, and each later co-user document at the next `inc(·, 0)` sibling-increment in that node's domain (document field ending in `2, 3, …`) — while documents under different users or nodes are realized in disjoint document-allocators. Hence the map `ev` taking each document to its allocating event is total and single-valued — every address of `𝒯` is produced by exactly one event, a child-spawn or an `inc(·, 0)` step (T10a) — and injective across both regimes: co-user documents sit at distinct outputs of one allocator's enumeration, pairwise distinct by T10a.7 (EnumerationInjectivity) and so emitted by distinct `inc(·, 0)` events; documents in disjoint allocators arise from events of distinct allocators, T10a's at-most-once-on-`(t, k')` constraint discriminating only the boundary sub-case of two first/base documents sharing a parent. Therefore **distinct documents arise from distinct allocation events**. The lay-in of the model's documents into `𝒯`'s event stream is a design posit (the document-level counterpart of S7a), not derived within this ASN; given it, the event-distinctness conclusion follows from T10a.7 and T10a's at-most-once constraint as derived in the prose above. S7d yields event-distinctness only — lifting it to address-distinctness is GlobalUniqueness's step, consumed by S7's Uniqueness argument.

- *Depends:*
  - T4 (HierarchicalParsing, ASN-0034) — sole definition site of the zero count `zeros(t) = |{i : 1 ≤ i ≤ #t ∧ tᵢ = 0}|`, the function S7d's statement invokes in the parenthetical `zeros = 2` that characterises each document's address as a document-level tumbler (the `N.0.U.0.D` prefix, exactly two field separators present)
  - T10a (AllocatorDiscipline, ASN-0034) — supplies the allocator tree `𝒯` and its discipline: each allocator's domain `dom(A) = {tₙ : n ≥ 0}` with `tₙ₊₁ = inc(tₙ, 0)`, and child-spawning by one `inc(·, k')`, `k' ∈ {1, 2}`, so that documents under one user are the successive outputs of one allocator (first the base, the rest `inc(·, 0)` siblings) and documents under different users/nodes lie in disjoint allocators; and supplies the at-most-once constraint — each `(t, k')` yields at most one child-spawning event — which discriminates the boundary sub-case of two first/base documents sharing a parent, grounding (with T10a.7) the conclusion that distinct documents arise from distinct allocation events, the event-level separation S7's Uniqueness step feeds to GlobalUniqueness
  - T10a.7 (EnumerationInjectivity, ASN-0034) — supplies the injectivity of an allocator's enumeration `n ↦ tₙ` (`tₙ₊₁ = inc(tₙ, 0)`); applied to a document-allocator it makes the successive co-user document outputs pairwise distinct addresses emitted by distinct `inc(·, 0)` events, discharging the within-allocator regime of S7d's injectivity argument — the regime T10a's at-most-once constraint, being about child-spawns only, does not reach
  - TA5 (HierarchicalIncrement, ASN-0034) — postcondition (d): a child-spawn `inc(t, k')` with `k' ∈ {1, 2}` appends `k' − 1` zero separators and a final component `1`, so every document-allocator base ends in component value `1`; this is what marks the co-user documents after the first (document field ending in `2, 3, …`) as sibling-increments within one node's domain rather than distinct child-spawn nodes, fixing the two-regime split on which S7d's corrected model rests
